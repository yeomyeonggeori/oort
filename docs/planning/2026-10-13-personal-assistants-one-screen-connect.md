# 개인 비서 연결을 한 화면·한 번에 (#3773 설계 메모)

- 날짜: 2026-10-13 · 트랙: UXUI · 이슈: #3773
- 계기: 성재(2026-10-13) 「어사이드에서 이런 업데이트가 있었는데, 우리도 저 UI 기반으로 온보딩과 에이전트 연동 부분을 개선해보면 어떨까. 지금은 몇 단계에 걸쳐서 그록봇을 데려오는 과정과 그 UXUI가 좋진 않았다」
- 레퍼런스: Aside Settings › Channels › Personal Assistants. 한 줄에 아이콘·이름·제공사·행동 하나(Copy 또는 +).
- 경계: ADR-0162(다이얼인·pairing·사람 confirm·D4 비밀 규율), ADR-0184 D2(도어벨 값은 벤더 Info 화면), ADR-0200(생존 라벨). 이 메모는 이 경계를 **지키면서** 줄인 결과다. 경계 자체를 바꾸자는 제안은 없다.

## 1. 현행 단계 측정 (그록봇, 코드에서 센 값)

세는 기준: 화면(oort 쪽 화면 전환), 클릭(oort 쪽 버튼·체크), 복사해서 붙이는 값, 사람이 다른 앱(그록봇)에서 하는 일. 입력칸 타이핑은 따로 센다. 근거는 `HostedAgentWizard.tsx`, `wizard.ts`(`HOSTED_WIZARD_STEPS`), `presets.ts`(`HOSTED_PRESETS.grok.steps`), `CreateAgentFlow.tsx`, `GrokBotInvite.tsx`, `FirstAgentStage.tsx`, `DoorbellSection.tsx`, `docs/SELF_HOST_AGENT.md` §3.3.17.

### 1.1 웹에서 전체 길 (핸들이 비어 있을 때)

| # | 화면 | oort 쪽 클릭 | 복사·붙이기 | 그록봇에서 사람이 하는 일 |
|---|---|---|---|---|
| 1 | 허브 → 에이전트 만들기 | 1 | | |
| 2 | 종류 고르기 (다른 곳에서 도는 에이전트) | 1 | | |
| 3 | 프리셋 고르기 (그록봇) | 1 | | |
| 4 | 위저드 1 이름 정하기 | 1 (연결 만들기) + 입력 2칸 | | |
| 5 | 위저드 2 연결 값 발급 | 4 (주소·routine 이름·연결 값 복사, 저장했어요) | 복사 3 | 말로 전하거나 직접 붙이기: 커넥터 추가, 주소·헤더 값 붙이기, routine 만들기(이름·지시문 붙이기), 수동 실행 |
| 6 | 위저드 3 감지 기다리기 | 0 (자동 되묻기) | | |

| 8 | 위저드 5 자격증명 교체 | 4 (자격증명 복사, 저장했어요, 교체 표시, 실행 표시) | 복사 1 | 커넥터 값 교체, routine 다시 실행 |

- 합계: **화면 8** (위저드 진행 표시는 5), **클릭 14 + 입력 2칸**, 복사 4, 그록봇 쪽 붙여 넣기 약 5 (주소·routine 이름·연결 값·routine 지시문·자격증명), 그록봇 쪽 작업 5 (커넥터, routine 만들기, 수동 실행, 값 교체, 재실행).
- 도어벨은 별도다(설정 `DoorbellSection`): webhook routine 만들기, 그록봇 Info 화면에서 https 주소와 sender key 복사 2, oort에 붙여 넣기 2, 15분 sweep routine 하나 더. 필수 경로에는 들어가지 않는 가속기다(SELF_HOST_AGENT §3.3.17).

### 1.2 데스크탑에서 앱이 감지될 때의 지름길 (`GrokBotInvite`)

초대 줄 클릭 1로 이름·발급이 자동 진행돼 화면 4번을 건너뛴다: 화면 5(허브 줄 포함), 클릭 약 11, 입력 0. 지름길이 있다는 사실 자체가 단계 수가 사람마다 다르다는 뜻이다.

### 1.3 온보딩 (`FirstAgentStage`)

그록봇 줄 선택(1) → 계속(1) → 위저드 2~3(복사·저장) → 온보딩이 감지를 이어받음 → 승인은 온보딩 밖에서 「채널 승인 대기」로 남는다. 온보딩만으로는 활성에 닿지 않는다.

### 1.4 사람이 줄일 수 없는 것 (바닥)

| 바닥 | 근거 | 이 설계의 처리 |
|---|---|---|
| detected → active 사이 **사람 확인** | ADR-0162 D6-4 | 단계로 남긴다. 승인은 홀로 서는 2번 단계다. 채널 사전 체크도 하지 않는다. |
| 정적 bearer의 **두 번째 값 교체** | ADR-0162 D4·D6 「정직한 setup 단계」 | 교체도 프롬프트 한 덩어리로 줄인다. 없애는 길은 OAuth 프리셋 #3524다(중복 이슈를 열지 않고 링크한다). |
| 도어벨 URL·sender key | ADR-0184 D2: 벤더 Info 화면에만 있고 에이전트가 읽지 못한다 | 「도어벨 자동 등록」은 불가능하다. 필수 경로에서 빼고 활성 뒤 선택 단계로 둔다. 서버 켜짐을 읽는 길은 #3775. |
| 그록봇이 프롬프트를 실제로 따르는가 | `presets.ts` `verified: false`, ADR-0162 D8 | `runtime-unverified`. 직접 붙여 넣는 순서를 접어서 남긴다. |

## 2. 목표 단계

핵심 아이디어는 셋이다.

1. **한 행 = 한 행동.** 설정(AI 허브 › 외부 연결 머리)에 「개인 비서」 목록을 세우고, 그록봇 행의 「연결」 한 번이 이름 입력·종류 고르기·프리셋 고르기를 모두 대신한다(`HostedWizardLaunch.autoAdvance: "create"`). 이름·핸들은 서명 레지스트리(`HOSTED_AGENT_SIGNATURES`)의 값이다.
2. **프롬프트 한 덩어리.** 주소·routine 이름·routine 지시문·연결 값을 `buildConnectPrompt`가 한 번에 만든다. 사람은 복사 한 번, 붙여 넣기 한 번이다. 교체도 `buildSwapPrompt` 한 덩어리다.
3. **진행 표시 5 → 3.** 서버 상태 기계(`hostedWizardStep`)는 그대로 두고, 그록봇의 번호만 묶는다(`HOSTED_COMPACT_STEPS`): ① 프롬프트 붙여 넣기(이름·발급·기다리기·만료 막힘) ② 채널과 권한 승인 ③ 값 교체하고 확인. `wizard.ts` 머리말이 금지한 「로컬 진행 카운터」는 만들지 않는다. 번호는 서버 단계의 함수다.

| # | 화면 | oort 쪽 클릭 | 복사·붙이기 | 그록봇에서 사람이 하는 일 |
|---|---|---|---|---|
| 1 | 개인 비서 목록: 그록봇 행 | 1 (연결) | | |
| 2 | ① 프롬프트 붙여 넣기 | 2 (프롬프트 복사, 붙여 넣었어요) | 복사 1 | 대화에 붙여 넣기 1 (커넥터·routine·수동 실행은 그록봇이 한다) |
| 3 | ② 채널과 권한 승인 | 2 (채널 선택, 승인) | | |
| 4 | ③ 값 교체하고 확인 | 2 (교체 프롬프트 복사, 붙여 넣었어요), 실행 표시는 선택 | 복사 1 | 대화에 붙여 넣기 1 |

- 합계: **화면 4** (전 8), **클릭 7** (전 14), **입력 0** (전 2칸), 복사 2 (전 4), 그록봇 쪽 붙여 넣기 **2** (전 약 5), 그록봇 쪽 사람 작업 **2번의 말하기** (전 5가지 작업).
- 「붙여 넣었어요」는 교체 표시(`replace`)를 대신 채운다. 실행 표시는 사람의 몫으로 남는다(서버가 채우는 증명 줄과 구분).
- 도어벨은 활성 뒤 선택 단계로 남는다. 한 화면에 세우는 것은 후속이다(#3775가 서버 켜짐을 읽는 길을 연 뒤).

## 3. 화면 와이어

```
개인 비서
이미 쓰고 있는 AI 비서를 팀의 멤버로 불러와요. 한 줄에서 한 번만 누르면 돼요.

 [G]  그록봇                                    연결 안 됨      [ 연결 ]
      프롬프트 하나를 붙여 넣으면 연결돼요.
 ----------------------------------------------------------------------
 [d]  dots                                         곧
      연결 방식을 확인하는 중이라 아직 연결할 수 없어요.
 ----------------------------------------------------------------------
 [M]  Muse  Meta                                   곧
      연결 방식을 확인하는 중이라 아직 연결할 수 없어요.

 연결 값은 한 번만 보이고, 승인은 항상 사람이 해요. 승인 전에는 어떤 대화도 읽지 못해요.
```

- 행 구조: 이니셜 마크 · 이름(+제공사, 근거 있을 때만) · 한 줄 설명 · 상태 배지 · 주 행동 하나. 행당 버튼은 최대 하나다(시험이 센다).
- 상태 배지와 행동은 `personalAssistantRows`가 정한다.

| 연결 상태 | 배지 | 주 행동 |
|---|---|---|
| 연결 없음·해제 완료 | 연결 안 됨 | 연결 (이름 자동, 첫 발급 자동) |
| `pairing_pending`·`expired` | 연결 대기·만료됨 | 프롬프트 다시 받기 |
| `detected` (승인 전) | 감지됨 | 승인하기 |
| `detected` (증명 대기) | 감지됨 | 이어서 확인 |
| `active` | **ADR-0200 생존 라벨** (응답함 n분 전 등), 라벨이 없으면 연결됨 | 관리 (외부 에이전트 연결로 이동) |
| `cleanup_pending` | 정리 중 | 없음 |
| dots·Muse | 곧 | 없음 |

- 이름과 제공사는 근거가 있을 때만 쓴다. Muse의 Meta는 ADR-0186 L8·ADR-0198 L101에 근거가 있다. 그록봇과 dots의 제공사는 레포에 근거가 없어 비웠다(스크린샷은 Aside의 표기이지 근거가 아니다). 브랜드 로고는 쓰지 않고 이니셜 타일만 쓴다.
- 네 상태: 로딩(높이를 지키는 막대) · 오류(인라인 배너와 다시 시도) · 오프라인(행은 그대로, 행동만 잠금과 사유) · 권한 없음(소유자·관리자 아니면 행동 없음과 사유).
- 위저드 ① 화면: 마스크한 프롬프트 미리보기, 주 행동 「연결 프롬프트 복사」 하나(잉크), 「그록봇에 붙여 넣었어요」(보조). 연결 값만 따로 붙이는 길과 직접 붙여 넣는 순서는 접힌 보조 구획이다. 검증되지 않은 프리셋이라는 경고는 접지 않고 항상 보인다.

## 4. 연결 프롬프트의 경계 (시험이 고정)

- 연결 값은 **커넥터 구획에 정확히 한 번**, routine 구획에는 없다. ADR-0162 D4가 static bearer를 routine prompt·URL·질의·일반 평문 설정에 넣지 못하게 했다. `connectPrompt.test.ts`가 구획을 잘라 확인한다. 「간단히 하려고 routine에 값을 같이 넣는」 변경은 이 시험에서 깨진다.
- 첫 연결 값(pairing)과 active 자격증명은 서로 다른 비밀이다. 교체 프롬프트는 처음 값을 되풀이하지 않는다.
- 미리보기는 마스크본이고 클립보드에는 비밀 포함본이 간다. 화면 문서에 비밀은 보조 구획에 한 번만 있다(기존 `FirstAgentStage.wizard.integration.test.tsx`의 「정확히 한 번」 시험이 그대로 통과한다).
- 채팅에 연결 값이 남는 것은 기존 「말로 전하기」 경로와 같은 위험이다. 값은 짧은 만료, 1회 소비, 감지 즉시 무효이고 대화 권한으로 승격되지 않는다(ADR-0162 D6).

## 5. 온보딩 재사용

- 온보딩의 AI 연결 목록(`AiConnectList`)은 라디오 선택 + 하단 「계속」이라는 온보딩 문법(시안 D4)을 갖는다. 설정 목록의 「행당 버튼 하나」와 상호작용이 다르다. 그래서 **컴포넌트를 억지로 하나로 합치지 않고, 같은 카탈로그와 같은 위저드를 쓰게 했다.**
  - 「곧」 줄(dots, Muse)과 이름·제공사·설명은 `PERSONAL_ASSISTANTS` 한 곳에서 온다. 두 표면이 어긋나지 않는다(`AiConnectList.soon.test.tsx`).
  - 그록봇 행은 온보딩에서도 같은 위저드를 `autoAdvance: "create"`로 연다. 그래서 프롬프트 한 덩어리와 진행 표시 3단계가 온보딩에도 그대로 적용된다.
- #3716(내 도구 = 개인 에이전트 켜기)과 #3712(O3)의 줄·문구·순서는 건드리지 않았다. 「곧」 줄은 에이전트 묶음(그록봇 바로 뒤)에 들어가고 「내 도구」 묶음 앞이다.
- 한계: 온보딩은 승인까지 가지 않고 감지에서 멈추는 기존 구조를 유지한다(승인은 채널 승인 대기 안내로 이어진다). 온보딩 안에서 승인까지 닫는 것은 사람 확인 경계와 온보딩 흐름의 결정이라 이 PR 범위 밖이다.

## 6. 서버 변경이 필요한 것

- **#3775 [engine]** 도어벨·호스티드 전달이 켜져 있는지 읽는 길. 지금은 꺼진 서버가 저장 때 본문 없는 404로만 답한다.
- 비밀 교체를 없애는 OAuth 프리셋은 기존 **#3524**.
- 에이전트가 다른 에이전트를 초대하는 길(그록봇·Muse·dots 포함)은 **#3772**에서 ADR로 설계 중이다. 이 PR은 거기와 겹치지 않는다: 이 PR의 「연결」은 사람이 소유자·관리자 세션에서 누르는 길이고, #3772는 에이전트가 자기 권한으로 초대하는 길이다.

## 7. 미검증과 남은 위험

- `runtime-unverified`: 실제 그록봇이 프롬프트의 두 구획(커넥터 추가, routine 생성과 수동 실행)을 그대로 수행하는지. `HOSTED_PRESETS.grok.verified`가 거짓이라는 기존 사실이 그대로이고 경고도 그대로 보인다. 실패하면 접힌 직접 붙여 넣기 순서가 남아 있다.
- dots와 Muse는 연동 경로가 없어 「곧」만 있다. 경로가 확인되면 카탈로그의 `state`와 `presetId`를 뒤집는다.
- 활성 행의 「관리」는 외부 에이전트 연결 목록으로 보낸다. 행 안에서 해제까지 하지 않는다(해제는 정리 목록이 필요한 별도 흐름).
- 폰(`clients/mobile`)은 이 PR에서 바꾸지 않았다. 폰의 호스티드 표면은 관전 전용이다(`status.ts` 머리말).
