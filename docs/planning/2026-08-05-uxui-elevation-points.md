# UXUI 고도화 포인트 — 성재 발제 4축 (2026-08-05 초안)

> 발단: 성재 — *"모드 변경이나, 채팅 UI가 지금 너무 구린 포인트, 원격 클라우드 연동 UX 및 온보딩 UI 개선 같은 포인트."*
> 표기: **[실측]** = 코드/화면에서 확인 · **[후보]** = 정밀 진단 배치에서 확정할 것. 우선순위·배치 편성은 §5.

## 1. 모드 변경 (라이트/다크)

- **[실측]** 웹 `tokens.css`는 `prefers-color-scheme` 대응(시스템 추종) — 그러나 **설정에 전환 토글이 없다**(settings 표면 grep 0). 사용자는 OS를 바꿔야만 모드가 바뀐다.
- **[실측]** 모바일 `tokens.ts`는 단일 스킴(다크 고정) — 라이트 모드 자체가 없다.
- 고도화: ①웹 설정 「테마」(시스템/라이트/다크 3값, `data-theme` 루트 스탬프 — tokens.css가 이미 그 문법을 앎) ②모바일 라이트 팔레트 신설+시스템 추종(여명 팔레트의 라이트 변주 — 디자인 토큰 작업이 선행) ③두 클라 저장 위치(웹 localStorage·모바일 MMKV)와 기본값=시스템.

## 2. 채팅 UI — "구린 포인트" 정밀 목록

성재 스크린샷 3장 + 코드 실측에서 이미 보이는 것:
- **[실측]** 시스템 라인·실행 결과 카드·일반 메시지의 **시각 위계가 평평**하다 — 실패 카드가 본문과 같은 톤의 상자라 경중이 안 읽힌다.
- **[실측]** 아바타 없음(이름 텍스트뿐) — 발화자 스캔이 느리다. 에이전트/사람 구분이 배지 텍스트에만 의존.
- **[실측]** 스레드 빈 화면 카피("첫 답글을 남겨 이 대화를 이어가세요")가 부모 메시지 맥락 없이 붕 뜬다(스크린샷 2).
- **[실측]** "재연결됨, seq 52까지 복구" — 내부 어휘(seq)가 사용자 화면에 노출.
- **[후보]** 메시지 그루핑(같은 저자 연속 발화 병합) 규칙·타임스탬프 밀도 · 날짜 구분선 스타일 · 링크/코드 블록 렌더 품질 · 긴 에이전트 응답의 접기(우리만 `detail.rows` 전부 펼침 — 진단 문서 D항 기존 지적) · 입력창(컴포저) 시각 완성도.
- 고도화 방법 제안: **화면 전수 캡처 → design-review 에이전트 정밀 진단 1회**(모바일·웹 각각, 항목별 Blocker/High 등급) → 그 산출을 티켓 묶음으로. "구리다"를 열거 가능한 결함 목록으로 바꾸는 게 첫 단계다.

## 3. 원격 클라우드 연동 UX

- **[실측]** AI 연결의 OAuth 등록 폼 부재 — ADR-0147이 서버만 랜딩, 이번에 **브라우저 콘솔 스니펫으로 우회**해야 했다(그 우회 자체가 이 축의 증거). 만료 시 재등록 UX도 없음(자동 refresh는 서버가 하지만, 죽었을 때 사용자가 볼 화면이 없다).
- **[실측]** 코드 실행 호스트(작업 세션)는 등록 표면(설정 > 코드 실행 호스트)이 있으나 라이브에 호스트 0 — 붙이는 흐름의 실사용 검증이 안 된 상태.
- 고도화: ①설정 > AI 연결에 **OAuth 등록 폼**(auth.json 붙여넣기 → 서버 파싱, 상태·만료·계정 라벨 표시) ②연결 상태의 헬스 표면(마지막 성공 호출·실패 사유 — "실패 카드가 첫 신호"인 현 상태 탈피) ③momo Cloud(T3) 온보딩은 E2B 키·리허설과 묶여 별도 트랙(ADR-0136 계열).

## 4. 온보딩 UI

- **[실측]** 웹 ConnectPage(서버 주소+mDNS 발견)·모바일 ConnectScreen 존재 — 그러나 이번 검수에서 서버 주소 프리필/덧붙음 결함(MAESTRO가 잡음), "주소를 확인하세요" 오류의 원인 미표시 등 거친 결이 확인됨.
- **[후보]** 초대 링크 → 가입 → 첫 채널 진입의 전 구간 카피·단계 수 · 첫 실행 시 에이전트 소개(김인턴 인사 프로토콜의 현세대 판) · 빈 워크스페이스의 첫 행동 유도.
- 고도화: 온보딩 전 구간을 **한 번의 신규 사용자 여정 캡처**로 실측(MAESTRO 00-login 확장으로 자동화 가능) → 마찰 지점 티켓화.

## 5. 배치 제안 (성재 승인 대기)

| 순서 | 배치 | 내용 | 크기 |
|---|---|---|---|
| U1 | **채팅 UI 정밀 진단** | 전 화면 캡처+design-review 정밀 1회(웹·모바일) → 결함 목록 산출(작업 아님, 진단) | 소 |
| U2 | **모드 전환** | 웹 토글+모바일 라이트 팔레트(토큰 선행) | 중 |
| U3 | **AI 연결 UX** | OAuth 폼+연결 헬스 표면 | 중 |
| U4 | **채팅 UI 1차 수리** | U1 산출 상위 결함(위계·아바타·시스템 라인 어휘 등) | 중~대 |
| U5 | **온보딩 여정** | 신규 여정 실측→마찰 티켓화→수리 | 중 |

권고 순서: U1(진단이 싸고 전부의 입력이 된다) → U3(연동 실패가 현재 최다 빈도 마찰) → U2 → U4 → U5. 마스코트/컨셉 이미지는 별도 트랙(codex-image)으로 병행.
