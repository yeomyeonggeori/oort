- 작성: 2026-07-25, momo-main (Fable). 상태: **성재 검토 대기** (재고 2종 + 레퍼런스 리서치 반영 완료)

## 2. 워크스트림 (AX-1 ~ AX-7)

### AX-5. 작업중 표시 — 즉시 (엔진·정책 결정 불필요)
웹 `agentWorkingSignal.ts`는 스토어·소비 3표면(사이드바/컴포저/타임라인)까지 완비된 채 "observation 착지까지 의도적 空" 주석으로 대기 중. `lib/realtime.ts`에 `agent.status`·`agent.partial` 구독을 추가하고 mac `AgentWorkingSignal.swift`의 리졸버 규칙(run>status>typing, 90s TTL, 채널당 병합)을 이식하면 끝.
레퍼런스 확정 문법(buzz 소스 1차 확인): 사이드바는 스피너가 아니라 **틱하는 경과시간 pill**(`42s`→`3m 12s`, tabular-nums, 2명 이상 `(N)`), 컴포저는 현재 활동 헤드라인 ~2.2s 회전, reduced-motion 정적 폴백.
**좀비 방어 필수**: Slack식 강제 클리어(응답 없이 2분) + Linear식 `stale` 상태 — 죽은 에이전트가 영원히 "작업 중"으로 남는 것이 이 UI의 최대 실패 모드.
→ **티켓 1장 (웹)**.

### AX-3. 관전 패널 — 이식 (성재 "핵심" 지목)
서버 계약 전부 main: work-sessions REST, `work.session.*`/`momo.work_session.acp_event.v1` 투영, terminal-attach `observer` 등급(MOMO-516), observer_count, diff 카드 props(MOMO-518). mac 구현(MOMO-517)이 레퍼런스.
웹 신규: ①작업 패널 라우트/서랍(세션 리스트+상세) ②read-only 터미널 관전 — **xterm.js 도입 결정 필요**(성재 결정 큐) ③diff/커밋/PR 카드 웹 렌더 ④발췌→스레드 브리지.
레퍼런스 확정 문법: 우측 보조 패널 + **스코프 라벨 상시 노출**(`#채널` / `전체` — buzz 주석 "없으면 all-channels 패널이 '틀려 보인다'"), 툴 호출은 과거형 한 줄 요약(`Ran command`/`Edited file`)+상태 4종, **자리 안 잃는 인라인 프리뷰**(Claude Agent View), **프로세스는 살리고 턴만 중단**(buzz "Stop current turn" — 불가 사유 분리 표기), 10s 초과 시 색 전환 생존 신호.
잔여 엔진 의존: 원격 workd ACP 정규화 릴레이(X-11/MOMO-546 진행 중) — 로컬 ACP는 지금도 완성.
→ **티켓 2~3장 (웹 패널 / 웹 터미널 관전 / diff 카드)**.

### AX-7. 워크스페이스 과금 가시화 — 1층은 즉시, 2층은 ADR
1층(즉시): `usage_ledger`가 workspace_id 축+시간 인덱스까지 완비 — **워크스페이스 롤업 REST**(기간 파라미터: 일/주/월, 모델별·에이전트별 분해) 1장 + 웹 설정 "사용량" 섹션. budget soft/hard 상태를 같은 화면에.
레퍼런스 확정 문법: 구독 할당량(잔여율+절대시각 리셋)과 선불 크레딧(잔액 소진)은 **프레임을 섞지 말고 시각 분리**. Claude식 "짧은 창+주간" 2게이지 병기. **조회 실패 시 `마지막 확인값 표시` 폴백 필수**. "이 속도면 언제 소진" 예측은 6개 제품 어디에도 없음 — momo 차별화 후보(2층에서).
2층(ADR): ADR-0125 D7의 과금 축(동시 슬롯·월 활성시간 H)은 현 원장과 **다른 단위** — 활성시간 미터 원장 + T3 종량은 T3 프로비저너 ADR과 함께.
→ **티켓 2장 (엔진 롤업 REST / 웹 사용량 섹션) + ADR 1건과 공유**.

### AX-6. work host T1~T3 — 정책 UI 이식 + T3 프로비저너 ADR
이식(즉시): WorkHostSection을 mac 콘솔 설정과 동렬로 — 티어 정책(`t1_only|ask|auto`)·호스트 목록/자기등록 상태·툴 프로파일. 카피는 mac 정본("이 Mac에서만"/"연결 끊김 시 묻기"/"자동 재개") — 티어 번호를 사용자에게 노출하지 않는 기존 결정 유지.
ADR(선행): **momo Cloud 프로비저너** — ADR-0125 D3 미결분. 기질(E2B 우선 검토)·크레딧 충전·슬롯/오토스케일 관측(성재 지시 6의 "크레딧 충전+오토스케일링 보기"가 정확히 이것). 성재 1인 테스트 중점 항목이므로 **실동 검증 리허설**(T1→T2→T3 순 CLI 작업 실왕복)을 티켓에 포함.
기존 ready 티켓 합류: **MOMO-520**(호스트 상실→T3 재개 제안 카드, ENGINE_HANDOFF A-14 `ready`, mac도 미착수) — 신규 발급 없이 웹 대상으로 재지정.
크레딧·스케일 UX(레퍼런스 확정): 충전은 **Threshold+Target 2필드 auto top-up**(Daytona, 둘 다 0=비활성), 알림은 **50/75/100% 단계 + 소프트(알림만)/하드(차단) 분리**(Vercel·Railway). 동시 에이전트 캡은 잔액이 아니라 **레이트 미터(N/M)**로, 캡 도달 시 즉시 실패 대신 **큐 깊이 노출**(Modal) — "김인턴이 대기열 2번째"가 "실패했습니다"보다 낫다.
→ **티켓 1장 (웹 정책 UI) + ADR 1건 (T3 프로비저너+크레딧) + 검증 리허설 1장 + 520 재지정**.

### AX-2. 요청 단위 모델/프로바이더/effort + auto — ADR 선행
현실: run 생성 `WorkRunInput.allowedKeys` closed-world가 우회조차 차단(400). effort는 코드 전역에 개념 부재. 프로바이더는 인스턴스 전역 1개.
ADR 골자(제안): ①`CreateAgentRunRequest`에 선택적 `routing {model?, effort?, provider_ref?}` 추가 — 워크스페이스 허용목록(`allowed_agent_models`) 교집합 게이트는 기존 0131 D2 재사용 ②effort 축 신설(원장 `usage_ledger`에 기록, **유효값은 provider×model 테이블** — buzz 소스 확인 패턴) ③auto 모드 = 서버 정책(작업 타입→모델 매핑)으로 시작, 학습형은 후순위 ④**auto가 고른 모델은 노출**(Cursor는 의도적 은닉·Copilot은 항상 노출 — 에이전트가 멤버인 제품에서 "누가 답했는지 모름"은 치명적, 비용·감사 원장과 일관되게 노출 권고).
UI 문법(레퍼런스 확정): 기본값 vs 오버라이드는 **3단 상속 체인(전역→에이전트→요청) + 명시적 "상속 (실제값 병기)" 옵션**(buzz). 모델 변경으로 현재 effort가 무효해지면 **자동 클리어+안내**(t3.chat의 조용한 리셋이 반면교사). Claude처럼 effort와 thinking은 별개 축으로 다룰지 ADR에서 결정.
UI: 컴포저 @멘션 시 인라인 피커(기본값=agent model_pref, 오버라이드=요청 1회) + 에이전트 생성 다이얼로그(R-1 §5 스케치, **MOMO-537**/A-19 `ready` — 서버 model_pref 필드 기존재, 폼만 부재 → 웹 대상 재지정). 수신 게이트는 서버 집행 계약 부재로 의도적 보류(X-12) — 이 ADR 범위에 포함할지 성재 결정 큐에.
→ **ADR 1건 + 티켓 2장 (엔진 라우팅 / 웹 피커) + 537 재지정**.

### AX-4. 캐스캐이드 + 사용량/잔여량 대시보드 — ADR 선행 2건
①폴백 체인: `provider_link` 싱글톤 해체 → 순서 있는 링크 목록(우선순위·health 기반 캐스캐이드, hermes 어댑터 다형화). 실패 전환은 **원장에 기록**하고 대시보드에 "이 런은 2차 프로바이더로 처리됨" 표기.
②OAuth 잔여량: **ADR-0004(자격증명 비유입)와 정면 충돌** — momo 서버는 조회 주체가 될 수 없음. 경계 안(제안): 잔여량 프로브를 **호스트/어댑터 측**(자격증명이 이미 있는 곳)에서 수행하고 momo에는 **숫자만** 투영(자격증명 비유입 유지). 이 경계로 ADR 발의.
③대시보드 표면: AX-7 웹 사용량 섹션에 프로바이더 축 추가(주/월 토글, 프로바이더별·캐스캐이드 전환 이력·잔여량 게이지).
→ **ADR 2건 + 티켓 2장**.

### AX-1. 첫 실행 와우 — 설계 스프린트 (레퍼런스 리서치 기반)
현재 체인: 사이트→다운로드→발견카드/딥링크→로그인→**에이전트 인사 1건**→(끝). 마지막 칸까지는 있고 "두 번째 수"가 없다.
확정 수리(즉시): **웹 채널 생성 막다른 골목** — ChatShell "채널 만들기"가 `/settings`로 보내는데 설정에 채널 섹션이 없음. mac `MomoChannelCreationSheet` 동렬 이식.
설계(R-3 스펙 대상, 레퍼런스 확정 재료):
- **와우의 정체 = 에이전트가 에이전트를 호출하는 장면.** buzz Welcome Kickoff: 리드 에이전트가 오프너에서 다른 에이전트들을 @멘션해 자기소개를 시킨다 — 유저가 아무것도 안 했는데 멀티 에이전트 협업이 눈앞에서 재생. momo는 김인턴이 hermes를 소개시키는 각본으로 직역 가능(기존 OnboardingGreeting 확장, 정규 쓰기경로 유지).
- 지연 백스톱은 buzz 실측 교훈 승계: 15s는 틀렸고 **120s**("unresolved는 무지이지 사실이 아니다"). degraded 경로별 정직한 카피(프로바이더 미연결/크래시/지연 각각).
- 온보딩 스텝은 2개로 자른다(buzz `totalSteps_is_2`). 실패 2회면 CTA가 "지금은 건너뛰기"로 바뀌어 유저를 안 가둔다. Raycast식 **상시 재진입 커맨드**(⌘K "온보딩 다시 보기").
- 하네스/CLI는 "설정하라"가 아니라 **`$PATH` 스캔으로 "찾아놨다"**로 시작(Orca 패턴), 권한 기본값은 컨텍스트로 제안(Codex: 버전관리 감지→Auto 추천).
- 원칙: 가짜 튜토리얼 금지 — 실제 에이전트와의 첫 왕복이 곧 튜토리얼.
→ **티켓 1장 (채널 생성) + R-3 스펙 1건 → 후속 티켓**.

## 4. 성재 결정 큐

1. **Wave 순서 승인** (A→B→C→D, A·B는 착수 승인만으로 진행 가능)
2. **auto 라우팅의 모델 노출**: Cursor식 은닉 vs 노출 — 권고: 노출(팀 도구·감사 원장 일관성)
3. **xterm.js 도입**(웹 터미널 관전) — 대안 없음에 가까움, 확인 차원
4. **OAuth 잔여량 경계**: 호스트/어댑터 측 프로브+숫자만 투영 안으로 ADR 발의 동의 여부
5. **T3 기질·크레딧**: E2B 우선 검토 동의 + 크레딧 충전 시점(1인 테스트 전 필요)
6. **Orca 제품 식별**: 레퍼런스 조사에서 동명 제품 다수 — 문맥상 stablyai/orca(병렬 코딩 에이전트 ADE, `$PATH` 스캔 온보딩)로 추정했는데 성재가 의도한 제품이 맞는지 확인

## 5. 리스크·정합성 메모

- 모든 신규 실시간 소비는 기존 불변식 유지: 단일 쓰기경로(outbox 경유)·Centrifugo 전송전용·RLS. 관전·작업중 표시는 **이미 투영되는 이벤트의 구독 추가**라 경계 변경 없음.
- ADR-0004 관련 작업(AX-4)은 Accepted ADR 없이 머지 금지(ADR-0100).
- 웹 v0 액센트 인디고→여명 팔레트 불일치는 R-2 이관 항목으로 별도(이 프로그램 범위 아님).
- 원격 workd ACP 카드(X-11/MOMO-546)는 엔진 트랙 진행 중 — AX-3 웹 패널은 로컬 ACP부터 실왕복.

## 6. 레퍼런스 리서치 정본
