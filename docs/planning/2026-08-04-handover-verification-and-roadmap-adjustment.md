### 1.4 ADR-0148·0149 — 하드 불변식 충돌 판정 (구현 #981·#982까지 검수)

**ADR-0148(인용): 충돌 없음.** 인용은 기존 메시지 INSERT에 실리는 컬럼이라 단일 쓰기경로·gapless seq 그대로. 마이그레이션 0 확인. 인용 대상의 채널 내 검증(`validate_quote_target_in_tx`) 존재. realtime `message.edited`에 본문을 싣지 않아 참조≠스냅샷 규칙 유지(outbox 행은 영원히 재생되므로).

**ADR-0149(휘발): 경계 변경(Centrifugo publisher 1→2)의 비용이 구현에서 제대로 막혔다.** 판정 근거:
1. **권한 검사가 RLS 아래에서 돈다** — grant 발급이 유일한 PG 접촉이고, `is_channel_member`를 tenant tx(NOBYPASSRLS `momo_app` + GUC) 안에서 부른다(`ephemeral.rs:152-195`). "RLS가 공짜로 보장 안 함" 비용을 발급 시점으로 옮겨 갚았다.
2. **두 벌 권한 검사 드리프트 자체를 제거** — subscribe 프록시와 **같은 함수**를 쓰고, `typing:` 채널명이 `ch:`와 같은 파서 분기를 탄다(테스트로 고정).
3. **발행 라우트 PG 0회를 테스트가 강제**(`ephemeral_typing_touches_no_pg.rs` — 모든 커넥션을 거부하는 풀로 핸들러 구동). 사람 전용(에이전트 403 = ADR-0101 봇 래핑 거부의 집행), 레이트리밋 2축, grant는 member+ws+channel 바인딩 HMAC + `JWT_HMAC` 도메인 분리 파생, leeway 60s 함정 차단.
4. **클라이언트 직접 publish는 계속 닫혀 있다** — 발행 주체는 서버 하나가 늘었을 뿐.

잔여 비용(수용 가능, 기록): 축출된 멤버가 **grant TTL 최대 60초** 동안 typing 신호를 낼 수 있다. 신호 자체가 60초 내 소멸하는 휘발이고 본문이 없어 실질 누설은 "아직 그 채널에 있는 척" 정도 — 티켓 불요, ADR-0149 Consequences에 한 줄 추가 권고.

### 2.2 차별점("에이전트가 1급 멤버") — ADR-0101 기준 판정

- **폰**: #980으로 "봇이 있는 채팅"에서 한 발 나왔다 — 에이전트 목록·프로필·재우기/깨우기·채널 배치·세션 관전이 선다(배포·검수 대기). 그러나 **행위 통제(승인)가 전 층에서 사용자에게 닿지 않으므로**, "1급 멤버" 주장의 절반(멤버를 지켜보고 **허락**한다)은 아직 주장할 수 없다.
- **웹**: 관전·운영은 서 있으나 승인 결정이 없다. 에이전트가 멈춰 서면 사용자가 할 수 있는 일이 없다.
- **경계는 지켜지고 있다**: typing 사람 전용(에이전트는 `agent_run`으로 말한다 — 403 테스트), 승인 hold 중 "작업 중" 오표기 차단(#980 H2), provider 자격증명 비유입 유지.
- **채팅 기본기 배치가 정당했나**: 정당했다. 키보드·스크롤·답글은 실기기 검수를 막는 blocking defect였고, 기본기 없는 차별점은 검수 자체가 불가능하다. 진단 문서(2026-08-03) 스스로 "필요했지만 편향을 키웠다"고 판정했고 그 판정에 동의한다. **지금부터의 헤드라인이 코어로 옮겨졌는지가 관건이며, 아래 배치 순서가 그 전환이다.**

### 2.3 Rust 재작성 — 남은 거리와 parity 전제 재검토

유니크 경로 기준 **65/137(47%)**. 그러나 **v0 축에 필요한 것은 사실상 다 넘어왔다.** 미이식 패밀리 분류(Swift 유니크 경로 수):

| v0 판정 | 패밀리 |
|---|---|
| **v0 필요 후보 1건** | **attachments 3경로**(uploads·complete·content) — 파일 전송은 메신저 기본기인데 **서버·웹·모바일 3층 모두 0**. 단 클라 표면도 없으므로 서버만 이식하면 죽은 라우트 — 서버+클라 동시 티켓이어야 하고, 저장 경계(Drive 확정과의 정합) ADR 선행(§5) |
| v0 불요(관전·승인·대화 무관) | plugins 5 · memories 5+2 · webhooks 4 · mcp 4 · huddles 4 · workstreams 3 · platform 3 · work-controls 2 · work-auto-approvals 2 · bans 2 · event-subscriptions 2 · work-tool-profiles 2 · members 잔여 · context-packets 1 · audit 1 · hooks 1 · agent-runtime 1 · work-pool 1 |
| v0 불요·형제 예외 1건 | **agent-run cancel 1경로** — 관전 축이 "지금 이거 꺼도 되나"에 답하는 순간 "그럼 꺼줘"가 다음 문장이다. Swift 계약 이식이라 ADR 불요, 상향 권고 |

**"parity를 다 채워야 Swift를 지운다"는 전제는 그대로 두면 안 된다.** 137 전 경로 parity로 읽으면 삭제가 무기한 밀리고, 이식 원본이 오래 살수록 "계약의 정답이 두 곳"인 기간이 길어진다. 미이식 137−65 중에는 제품이 **v1에서도 안 쓸 것**(예: `__momo_stub`, context-packets v0 형태, platform admin 일부)이 섞여 있다. → **parity의 정의를 "제품이 쓰기로 결정한 라우트 집합"으로 좁히는 결정**을 성재에게 올린다(§4-B). 좁힌 정의 아래에서만 "도달 시 일괄 삭제"가 실행 가능한 문장이 된다.

| 5 | **⑧중 인용·typing 클라** | 서버가 이미 섰으니(배포 후) 클라만. 대화 축 메신저 기준선 |
| 6 | **⑥openapi 백필** · **③roster pause** | 게이트 정합·에이전트 탭 N+1 제거(중) |
| 7 | **②어휘 통일** | 제품 결정 — §4-C로 |
| 8 | **④실행 기록 클라** | agentRunHistory 읽기 경로 이식 필요(서버 GET 3경로) — 축 마감 뒤 |

## §3. 로드맵 조정 제안 — 다음 배치 (성재 승인 대기)

각 배치가 축 언어로 "무엇을 닫는가"를 명시한다. 병렬 규칙(≤5·파일군 비충돌)은 기존 계약대로.

- **배치 0 (성재 한 줄 + 오케스트레이터)**: 디스크 회수 → `compose up -d` → 라이브 approvals 401 확인 → 폰/웹 검수 개방. **닫는 것: 승인 축 서버 배포.**
- **배치 1 「승인이 사람 손에」**: (a) 웹 승인함 — 목록+결정 UI(`serverSurfaces` 플립 포함) (b) 모바일 `approvals.provided` 플립 + 인앱 결정 개방(푸시와 같은 core `approvalDecision` 경로 재사용) (c) hermes 체크섬 수리(독립 레인, 같은 배치에 병렬). **닫는 것: 승인 축 4층 폐곡선 + TestFlight 레인 복구.**
- **배치 2 「관전의 마감」**: agent-run cancel 라우트 이식(Swift `AgentRunRoutes.swift:25` 계약) + 폰 문구를 "끌 수 있다"로 상향 · 실시간 턴 신호 폰 배선(웹 "작업 중"과 동일 어휘) · roster pause 필드(탭 N+1 제거). **닫는 것: 관전 축 — 보인다→멈출 수 있다.**
- **배치 3 「대화의 기준선」**: 인용 답글 클라(웹 렌더+작성 · 모바일 작성 — 렌더 글리프는 존재) + typing 클라(웹·모바일, grant 프로토콜 소비). **닫는 것: 대화 축이 "메신저 수준" 기준선 도달**(성재 발단 지시의 직접 응답).
- **배치 4 「위생」**: openapi.yaml 백필(실서버 샘플링 게이트와 함께) + 어휘 통일 집행(§4-C 결정 후) + NCP 이미지 회수 자동화. **닫는 것: 게이트 신뢰·운영 위생.**
- **배치 5 (결정 후)**: 첨부 3경로 이식 + 웹/모바일 업로드 표면(§4-D·§5 ADR 선행). **닫는 것: 대화 축 파일 전송.**

**폰 검수 분기점**(성재 "조금 분기가 되면 한번에" 원칙): 배치 1 완료 시점이 첫 분기 — 승인·에이전트 탭·관전을 한 번에 검수.
