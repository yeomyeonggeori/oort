# 커토버 & parity 전략 (D5)

> ADR-0145 B안 Phase 0 산출물 D5. **성재 승인: 빅뱅**(사용자 0·동일 DB → strangler 이중운영은 지킬 다운타임이 없어 불필요).

## 1. 커토버 = 빅뱅 (결정)

- **왜 빅뱅**: 출시 전·사용자 0. strangler(엔드포인트별 프록시로 Swift↔Rust 점진 라우팅)의 이득은 무중단 전환인데, 지킬 트래픽·다운타임이 없다. 이중운영 오버헤드(프록시·두 서버 동시 유지·계약 drift)만 남는다.
- **동일 DB가 안전망**: Rust 서버는 **기존 59 마이그레이션 DB를 그대로** 쓴다. Swift 서버 태그를 보존하면 같은 DB에 대해 **롤백 = 이미지 교체**로 가능(스키마 불변이므로).
- **컷 지점**: 전 도메인 배치(B1~B5) 완료 + parity 통과 후 단일 컷. 부분 컷 없음(빅뱅 정의).

## 2. parity oracle = 동일 DB·기존 게이트 픽스처

재작성이 "동일하게 행동하나"의 판정 기준:
- **동일 마이그레이션 DB**에 Rust 서버를 세우고, **기존 게이트/통합 테스트·픽스처를 그대로 조준**. oort 게이트가 이미 docker 계층에서 도는 자산(파이프라인 교훈: 오케스트레이터가 그 계층 테스터).
- 판정 단위: **"동일 요청 → 동일 DB 상태 + 동일 응답"**. 응답 바이트 동일이 과하면 계약(스키마) 동일 + 상태 전이 동일로 완화.
- **D2 red 테스트 편입**: 불변식 7개의 red 테스트(특히 신규 승격분 #3 원자성·#6 cross-tenant 누출)를 conformance suite에 포함 → 무회귀 세트(파이프라인 교훈: 세트 밖 검증기는 조용히 red).

## 3. 컷오버 체크리스트 (컷 직전)
- [ ] B1~B5 전 배치 parity green (동일 DB).
- [ ] D2 불변식 red 테스트 7개 전부 green + 되돌림 실패 확인.
- [ ] 웹 표면 design-review Blocker 0(해당 배치).
- [ ] prod 이미지 빌드·퍼블리시(현 prod는 이미지 pull — `MOMO_API_IMAGE`).
- [ ] Swift 서버 태그 보존(롤백 경로).
- [ ] NCP smoke를 Rust 이미지로 재실행(§독립 트랙, 현재는 Swift 이미지로 선행).

## 4. 롤백
- 스키마 불변 → **이미지 교체로 즉시 롤백**(Swift 태그로). 데이터 마이그레이션 불요.
- 단 컷 이후 새 마이그레이션(예: ADR-0146 `action_signature` 060+)이 추가되면, 그 시점부터 롤백은 해당 마이그레이션 역호환 필요 → 컷 직후 창에서는 신규 마이그레이션 보류 권고.
