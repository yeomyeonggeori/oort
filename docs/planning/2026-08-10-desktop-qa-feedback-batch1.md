## 웨이브 A — 순수 프론트 (지금 발사 가능, 병렬 2)

### W-QA1 · #1 포커스 링을 border 색상 변경으로 (전면 스윕)
- 현황: `ring` 없음. 실체는 `focus-visible:outline-2 outline-offset-2 outline-accent`가 **63파일 109곳 복붙**. 프리미티브(button/input/select/dropdown)조차 각자 문자열 보유 — 한 곳 수리로 전파 안 됨.
- 방식(구조 정합): tokens.css `@layer utilities`에 **공용 focus 유틸 신설**(transition-colors 중앙화 선례 `tokens.css:370-376`와 동형) — 포커스 시 `border-color: var(--accent)` + outline 제거(또는 `outline: transparent`). 전 사이트 109곳을 이 유틸로 치환.
- 주의: `-outline-offset-2`(인셋) 쓰는 일부(ADE·WorkPanel 행·ObserverTerminal 등)는 컨테이너 특성상 border 방식이 부적합할 수 있음 — 그건 유지하거나 별도 판정(워커가 실측 후 보고). **border가 없는 컨트롤**(예: 고스트 버튼)은 focus 시 border를 새로 그리는 게 맞는지 표면별 확인.
- design-review 필수(B0). 폰(clients/mobile)은 이번 범위 밖(웹/데스크탑만).

### W-QA2 · #2 멤버 초대 모달화
- 현황: "멤버 초대하기"→`navigate("/settings?section=members")`(별도 페이지). 모달 프리미티브(`dialog.tsx`)·컨텍스트 오픈 패턴(`useOpenCreateChannel`)·판박이 선례(`CreateChannelDialog` — MOMO-614 "설정으로 보내던 걸 액션 자리로") 전부 있음.
- **결정 필요(성재)**: 현재 초대 폼(`InviteSection`)은 **워크스페이스 초대 링크 생성기**(역할·횟수·기간→링크 발급)이지 "이 채널에 멤버 추가"가 아니다. 채널 멤버 추가 API는 `addChannelMember`로 별개. 두 갈래:
  - **(a) 그대로 모달화**: 기존 초대 링크 폼을 모달에 담음(최소 변경, 문맥 미스매치는 유지)
  - **(b) 채널 멤버 추가 모달**: 워크스페이스 멤버 중 골라 `addChannelMember` 호출(문맥 정합, 신규 UI)
  - → **권고 (a)**(이번 배치는 UX 흐름 개선이 목적, 문맥 재설계는 별건). (b)는 별도 티켓.

## 웨이브 B — 프론트 + API 래퍼 (백엔드 확인 후, A와 병렬 가능)

### W-QA3 · #3 채널 헤더 개선
세 조각, 서버 상태가 다름:
1. **멤버 표시 👤 N** (즉시): "루나, 오르트 외 2" → 사람 아이콘+인원수. 인원수는 클라가 이미 계산 가능(`names.length`/`memberIds.length`). 순수 프론트.
2. **채널 이름 클릭/우클릭 메뉴** (프론트): context-menu 프리미티브 없음 → 기존 `dropdown-menu`로 클릭 트리거(헤더의 `PinListMenu` 선례). 항목: 이름 수정·알림 끄기·채널 떠나기.
3. **각 액션의 API**:
   - 떠나기(leave): **있음** — `removeChannelMember(ws, ch, 자기 memberId)`(`api.ts:1064`). 즉시 배선.
   - 이름 수정(rename): 웹 클라 래퍼 **없음**, 단 서버는 `channel_renamed` 이벤트 방출 정황 있음 → **백엔드 엔드포인트 실재 확인 후** 클라 API 함수 추가. 없으면 서버 티켓 선행.
   - 알림 끄기(mute): `Channel.muted` 읽기만 있음, **토글 write API 없음** → 백엔드 확인/추가 선행.
- **워커 지시**: 프론트(1·2)+leave(3)를 먼저 세우고, rename/mute는 서버 라우트 실측 → 있으면 배선, 없으면 그 사실을 보고에 적립(서버 티켓 분리). "메뉴에 비활성 항목을 두지 말 것 — API 없는 항목은 이번 PR에서 빼고 티켓으로."

## 웨이브 C — 백엔드 신설 선행 (이번 배치 발사 안 함 · 성재 결정+ADR 대상)

### #6 사용자 상태(presence) — 상태칩을 프로필로+상태 변경
- 조사 판정: presence 개념이 **서버 필드·set/read API·Centrifugo 프레임 전 계층에 전무**. 좌하단 칩은 사실 **소켓 연결 상태**(사용자 상태 아님) — 옮기면 연결 표시가 사라지는 문제.
- 필요: ①서버 status 모델(online/away/dnd) ②set/read API ③실시간 브로드캐스트 ④프론트 프로필 패널(하단 유저 패널 골격은 `Sidebar.tsx:507` 존재). **ADR 사안**(실시간 경계·프레즌스 정책).
- 분할 제안: **6a(즉시·프론트)** = 연결칩을 하단 프로필 패널로 이동(의미 보존, presence 아님) / **6b(대형)** = presence 모델 신설. 6a만 원하시면 웨이브 B에 편입 가능.

### #4 워크스페이스 레일(디스코드형)
- 조사 판정: **멀티 워크스페이스가 세션·데이터·API 전부 미완**(`WorkspaceRail`이 명시: "multi-workspace lands (ADR-0117)"). 생성만 부분 존재(오퍼레이터 게이트), 목록·나가기·이미지 업로드 API 전무, 워크스페이스 아바타 필드 없음. 게다가 현재 레일의 "데"는 워크스페이스가 아니라 **로그인 사용자 이름 첫 글자**(prop 오배선).
- 이건 UI 리팩토링이 아니라 **멀티테넌시 기능 신설**(ADR-0117 실현). 대형 로드맵 항목.
- 분할 제안: **4a(즉시·소)** = prop 오배선 정정(워크스페이스명을 실제로 표시)+[+]를 설정 링크가 아닌 실제 생성 진입점으로+현재/호버 시각 구분 강화 / **4b(대형)** = 멀티 워크스페이스 스택(ADR 선행). 4a만으로도 스크린샷 개선 상당수 해소.
