## 1. 이 세션이 한 일 (시간순)

발단은 성재 지시: *"아직 메신저 정도 수준에도 못 미치는 UXUI야. **우리 핵심기능을 담는 부분도 미흡해.** 로드맵 체크하고 그 부분을 강화하는 방향으로. **현재의 로드맵 진단부터.**"*

### 1-1. 로드맵 진단
정본 `docs/planning/2026-08-03-roadmap-diagnosis.md`. 판정 두 줄:
1. `ROADMAP.md` §0이 한 세대 낡음 — "Swift 패키지 5개", "`clients/iOS` 미존재", MOMO-2xx AWS 알파를 서술. ADR-0145(Rust 재작성)·0137(RN)·0133(Tauri)·0120(푸시 relay) **중 하나도 반영 안 됨**.

### 1-3. ADR 2건 기안 → 성재 승인("ㄱㄱ") → Accepted
- **ADR-0148 인용 답글.** `reply_to_id`는 컬럼·FK·INSERT 바인딩까지 있는데 **모든 호출부가 `None`**. 스레드는 `root_id`라 충돌 없음 → **마이그레이션 불필요.** 의미 확정: `root_id`=소속(옆으로 치움), `reply_to_id`=지목(본류에 두고 맥락만).
- **ADR-0149 휘발 신호(작성 중).** outbox 경유 기각(타이퍼당 3초 = 안 읽힐 행) · 클라 직접 publish 기각(지금 "클라는 publish 못 한다"가 **설정 한 줄로 강제**되는 걸 정책으로 내려앉히지 않는다) → **서버 경유 직접 publish, PG 미접촉.** 명시한 비용: **RLS가 격리를 공짜로 보장해 주지 않게 된다.**

## 3. 이 세션에서 나온 **서버 사실** (구현 결정에 영향)

1. **`paused`는 run을 *만드는* 시점에만 검사된다** (`run.rs:400`·`mention.rs:131`·`a2a.rs:184`). 진행 중 run을 멈추는 코드 없음. **Rust에 agent-run cancel 라우트 0개**(Swift에만 있음). → 폰 문구가 "이미 실행 중인 작업은 그대로 끝까지 갑니다".
2. **승인 hold 중에도 work session은 `running`으로 남는다.** `work_session`↔`agent_run` FK 부재 + `work_session.status`를 쓰는 8개 문장이 전부 `momo-t3`라 승인 경로에서 도달 불가. → 폰이 "작업 중"이라 하면 **사람을 기다리는 에이전트를 그렇게 부르는 것**이라 문구를 「세션 실행 중」으로 좁혔다.
3. **서버 `ApiError` 문구에 한글 0건.** 한국어 문장은 `momo-core`의 `http.ts`/`api.ts`가 상태코드에서 만든다.
4. **`work_session` DTO에 호스트 등급 없음**(`host_id`만) → D5 배지는 클라이언트 조인, 조인 실패 시 **fail-closed**.
5. **roster에 pause 상태 없음** → 목록 한 줄이 에이전트당 요청 1건, 그 읽기는 owner/admin 게이트라 **일반 멤버 403**.

## 4. 열린 티켓 후보 (우선순위는 Fable이 판단)

1. **커밋된 `Podfile.lock`의 `hermes-engine` 체크섬이 로컬 `pod install` 결과와 달라 깨끗한 체크아웃에서 Release 빌드 실패** — TestFlight 레인에서 터질 것.
2. 어휘 통일: **재우기 / 일시정지 / 자고 있음** 셋 — 서버 `mention.rs:622` `paused_mention_body`까지 걸린 **제품 결정**.
3. roster에 pause 상태 부재(위 §3-5).
4. 에이전트 실행 기록 클라 미제공(`agentRunHistory: provided: false`).
5. 실시간 턴 신호 폰 배선(웹의 "작업 중"과 대응).
6. `openapi.yaml` 백필 — 게이트가 **실행 중인 서버에 샘플링**하므로 스펙만 앞서 적으면 깨진다.
7. Rust에 agent-run cancel 라우트 부재.
8. 승인/인용/작성중 **클라 표면**(웹·모바일) — 서버는 섰고 클라가 없다.
9. NCP 디스크 82%(여유 1.7G) — 다음 배포 전 옛 이미지 회수 필요.

## 5. **내가 이 세션에서 틀린 것 — Fable은 여기부터 의심하라**

성재 지적: *"너가 지금 헛소리하는게 심상치 않음."* 정당한 지적이다. 실제로 틀린 것들:

| # | 내가 말한 것 | 실제 | 어떻게 드러났나 |
|---|---|---|---|
| 1 | `server-rust` 라우트 **12개** → "재작성이 8%" | **58개**(현재 63) | grep이 **여러 줄로 등록된 라우트**를 놓쳤다. 내가 스스로 재측정해 잡음 |
| 2 | "승인 배포하려면 **`track/engine → main` 머지**가 필요, 성재 승인 사안" | **`main`에는 `server-rust`가 아예 없다.** 배포는 track/engine에서 직접 나간다. main엔 기획 문서만 | main 트리를 직접 확인하다 발견 |
| 3 | `srv_t2_2` 실패 원인 = **outsider probe** | **교차 테넌트 probe**. `ch:`/`typing:` 패리티는 원래 green이었다 | **워커가 갈라서 반증** |
| 4 | 패킷: 거부 문장을 **한국어로** 써라 | 서버 `ApiError` 한글 0건 — 한국어는 클라가 만든다 | **워커가 반박** |
| 5 | **NCP 배포 맥락을 통째로 잃고** 성재에게 ssh 별칭·키를 물었다 | 런북 §2에 접속 절차가 있었고(`getRootPassword`→`sshpass`), 비번 파일도 스크래치패드에 있었다 | **성재가 지적** |
| 6 | (초기) `paused`가 진행 중 run을 멈춘다고 가정 | 생성 시점만 검사 | 워커 보고 → 내가 실측 확인 |

**패턴**: (a) **grep 한 번으로 단정**하고 교차검증을 안 한다 (b) **compact 이후 운영 맥락을 문서에서 복원하지 않고 사람에게 묻는다** (c) 실패 원인을 **추정으로 먼저 말한다**.

**Fable에게**: §1~§4의 수치와 판정을 **그대로 믿지 말고** 최소한 다음은 직접 재라 — 라우트 수(여러 줄 등록 주의), 모바일/웹 feature 수, 배포된 이미지와 라이브 응답, `paused`/cancel의 실제 코드 경로, ADR 상태.
