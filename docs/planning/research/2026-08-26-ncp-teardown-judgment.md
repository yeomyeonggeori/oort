# NCP 정리 판정 — 무엇을 내리고 무엇을 남기나 (2026-08-26)

> 발제: 성재 — "NCP 부분 생각보다는 비용이 많이 나가고 있어서, oort 웹 서버 관련한 부분이랑 셀프호스팅 사용자 관점에서 필요한 부분 제외하면 다 내리는 것도 고민해줘. (…) 우리도 그록봇 VM으로 테스트가 가능하다면 로컬 도커 정도로 해서 비용을 거의 발생 안 시킬 수 있지 않아? oort 웹 서버는 버셀같은 걸 쓰고."
> 근거: `2026-08-26-selfhost-external-dependency-audit.md`(전수 감사) · `docs/runbooks/{ncp-rust-deploy,turn-host-install,cubesandbox-host-install}.md` · 2026-08-26 실측 프로브.
> **집행 문서가 아니다** — 삭제는 되돌리기 어려우므로 성재 결재 후 별도 체크리스트로 집행한다.

## 한 줄 판정

**성재가 원하는 4대 테스트(터미널·UXUI·허들·그록봇)는 NCP 3대를 전부 내려도 가능하다.** 허들이 공인 IP를 요구한다는 통념이 유일한 반론인데, **같은 머신 안(로컬 도커 + 브라우저 2개)에서는 LiveKit이 `127.0.0.1` 바인드 그대로 도달하므로 성립한다.** 내리면 잃는 것은 **display/T3(화면 관측·원격조작)** 검증과 **공개 TLS·푸시** 검증, 그리고 상시 데모 주소뿐이다.

|---|---|---|---|
| `app.oor7.com` (101.79.11.189) | 디스크 9.8G | 라이브 데모/내부 알파 Rust 스택 + (배포했다면) push relay | **`/healthz` 200 — 살아 있음** |
| `momo-cube-host` (101.79.18.230) | **8vCPU·32GB·300GB** | CubeSandbox microVM — T3 클라우드 작업 세션 substrate | 8443 filtered(ACG가 운영자 IP만 허용 — 정상) |

**`oor7.com` 루트(및 www)는 응답이 없다** — 즉 "oort 웹 서버"라 부를 공개 랜딩/마케팅 사이트는 **아직 존재하지 않는다.** 존재하는 웹은 `app.oor7.com`이 서빙하는 **앱 SPA**뿐이고, 그건 이미지 안에 임베드되어 `caddy`+`web-init`이 꺼내 놓는 구조라 셀프호스터는 **자기 서버가 자기 웹을 서빙한다.**

### 의존 사슬 — 중요
**`momo-turn`은 `momo-cube-host`의 자식이다.** 런북 문면: "CubeSandbox microVM의 NAT이 symmetric이고 host/srflx 후보로는 P2P가 성립하지 않는다 (…) TURN은 CubeSandbox 호스트에 동거시킬 수 없다. 그래서 별도 공인 호스트 1대다"(`turn-host-install.md:6-9`). ⇒ **CubeSandbox를 내리면 TURN도 함께 내려간다. 두 대가 한 묶음이다.**

### 흔한 오해 정정
**허들은 이 TURN을 타지 않는다.** 허들(LiveKit SFU)과 display(coturn)는 별개의 WebRTC 평면이고, `infra/livekit.yaml:15-19`에서 **허들 쪽 TURN 블록은 통째로 주석**이다. 즉 `momo-turn`은 화면 관측 전용이다.

## ② 판정

### 묶음 A — `momo-cube-host` + `momo-turn`: **내릴 수 있다** (비용의 핵심)
- **잃는 것**: display/T3 — 에이전트 클라우드 작업 세션 + 화면 관측·원격조작 검증.
- **왜 지금 감당 가능한가**: TC-2(작업 콘솔 원격조작)는 **아직 기획 단계**이고 ADR도 없다. 그리고 **#1777이 방금 랜딩되어 로컬 데몬(T1) 경로가 열렸으므로**, 터미널 축 검증은 클라우드 substrate 없이 로컬에서 폐곡선을 낸다.
- **되돌리는 비용**: 런북 두 편(`cubesandbox-host-install.md`·`turn-host-install.md`)이 재설치 절차 정본이고 one-click 설치 실소요가 **2분 이내**로 기록돼 있다 ⇒ 재구축은 싸다. **이것이 내림을 정당화하는 가장 강한 근거다.**
- **주의**: TC-2를 실제로 착수할 때 substrate가 다시 필요하다. 그때는 "필요할 때만 띄운다"가 성립한다.

### 묶음 B — `app.oor7.com`: **조건부 — 데이터 백업이 선행**
- **남길 이유**: 유일한 공인 IP 호스트 ⇒ **공개 도메인/TLS 경로**(#1239 미결)와 **푸시 relay**를 검증할 수 있는 유일한 자리.
- **내릴 수 있는 이유**: 셀프호스팅이 제품 방향이면 우리가 **상시** 서버를 돌릴 제품적 이유가 없다. 데모가 필요하면 검증 창에만 켜면 된다.
- **선행 조건(필수)**: 내부 알파 데이터가 남아 있으면 `scripts/self_host_pg_dump.sh`로 덤프 확보 후. **PG 볼륨을 확인하지 않은 채 인스턴스를 지우면 복구 불가.**
- **주의**: ADR-0120이 "모든 셀프호스트 서버는 운영 relay 경유"라고 못박았다. 오늘 그 relay에 의존하는 **외부** 셀프호스터가 없다면 무해하지만, 있다면 내림이 곧 그들의 푸시 중단이다. **확인 필요(성재만 안다).**

### Vercel — **옮길 대상이 아직 없다**
성재가 말한 "oort 웹 서버"의 실체는 둘 중 하나다:
- **앱 SPA**라면 → Vercel로 옮길 수 없다. 셀프호스트 스택은 자기 서버가 자기 웹을 서빙해야 하고(same-origin 전제), 이미지 임베드가 그 구조다.
- **랜딩/문서 사이트**라면 → **아직 존재하지 않는다**(`oor7.com` 무응답). 새로 만든다면 Vercel/GitHub Pages 무료 티어로 충분하고, **NCP와 무관한 별건**이다.
⇒ 어느 쪽이든 **Vercel 전환이 NCP 비용을 줄이지는 않는다.** 비용은 묶음 A가 쥐고 있다.

## ④-bis 정정 — 터널 기본값 (2026-08-26)

이 문서를 쓸 때 참조한 전수 감사 ⑨의 "현행 v1 = cloudflared quick tunnel"은 **오독이었다.** 플레이북 §2.2의 기본은 **Tailscale Funnel(사용자 자기 tailnet)**이고 quick tunnel은 production 금지 폴백이다.

**이 판정에 미치는 영향**: NCP 정리 결론은 **바뀌지 않는다**(우리 relay를 쓰는 모델이 아니라는 점은 동일). 다만 **허들 도달성의 전제가 유리해진다** — 셀프호스터는 서버 URL 발급 단계에서 **이미 Tailscale에 가입하고 설치를 마친 상태**이므로, 허들을 위한 추가 가입·추가 설치가 **0**이다. 남은 미지수는 "이미 있는 Funnel에 통화 통로를 얹을 수 있는가" 하나로 좁혀진다(RA-8 P1).

## ④-quater `app.oor7.com` 처분 — 로드맵 편입 (성재 지시)

**존재 이유가 오늘 얇아졌다.** 남겨 두려던 명분이 *"공개 도메인+TLS를 검증할 유일한 자리"*였는데, **Tailscale Funnel이 v1 기본이 되면서 `*.ts.net` 인증서가 그 역할을 대신한다.** 우리가 공인 IP를 잡고 Let's Encrypt를 돌리는 경로는 더 이상 제품의 주 경로가 아니다.

데모 명분도 약하다 — **셀프호스팅이 제품인데 데모만 우리가 상시 운영하는 것은 앞뒤가 맞지 않는다.** 보여줄 일이 있으면 그록봇 VM이나 로컬에 띄우는 편이 오히려 사용자가 겪을 경험 그대로다.

**Vercel/Cloudflare 이전은 불가**(성재 제안 검토): 둘 다 서버리스라 요청 시에만 함수를 깨우는 구조인데, 이 스택은 PostgreSQL 상주 프로세스 · Centrifugo WebSocket 유지 · Rust 바이너리가 **계속 켜져 있어야** 한다. 아키텍처가 맞지 않는다. (랜딩 사이트 신설은 별건이며 성재가 이미 승인 — 무료 티어로 충분.)

**로드맵 처분안:**

| 단계 | 시점 | 행동 |
|---|---|---|
| **R1** | 묶음 A 정지와 **동시** | `scripts/self_host_pg_dump.sh`로 PG 덤프 1벌 확보(로컬+오프사이트). 데이터 판단을 나중으로 미룰 수 있게 만드는 안전장치 |
| **R2** | R1 직후 | **정지**(삭제 아님). 컴퓨트 비용 멎고 되돌릴 수 있다 |
| **R3** | 정지 후 1~2주 | 관측 창. 몰랐던 의존이 드러나는지 본다 |
| **R4** | #1239(사이트 주소 파라미터화) 해소 시점 | 공개 TLS 검증처가 어디서든 서므로 **완전 철수 판정.** 그 전까지는 정지 상태 유지 |
| **R5** | 랜딩 사이트 신설 시 | Vercel/Pages 무료 티어. **NCP와 무관한 별건**이며 `app.oor7.com`을 대체하지 않는다 |

**정지 순서는 cube → turn → app.** TURN은 cube의 자식이라 함께 가고, app은 마지막에 두어 되돌릴 여지를 남긴다.

**정정 1**: 이 문서가 "비용의 핵심"으로 지목한 묶음 A(cube+turn)는 **이미 컴퓨트 과금이 멎어 있었다.** 앞선 프로브에서 두 호스트의 SSH가 닫혀 있던 것을 ACG 방화벽으로 해석했으나, **실제 사유는 서버가 꺼져 있던 것**이었다. 오독이었다.

**정정 2**: 따라서 실제로 켜져 있던 oort 서버는 **`app.oor7.com` 하나**였고, 남은 컴퓨트 비용도 그 하나였다. 성재가 체감한 비용에는 **oort가 아닌 `factsheet-data405-worker`**의 몫이 섞여 있을 수 있다.

**정정 3 — R1(덤프 선행)의 근거를 좁힌다**: 이 문서의 R1은 "정지와 동시에 덤프"였으나, **정지는 디스크를 보존하며 되돌릴 수 있다.** 덤프가 실제로 필요한 시점은 **삭제 직전**이다. pem 부재로 덤프를 뜨지 못한 상태였으나 정지는 안전하게 진행했다.

### 집행 방식의 안전장치
정지 호출 전에 **이름과 공인 IP를 둘 다 대조**하고 하나라도 어긋나면 중단하도록 가드를 두었다(`scratchpad/stop_app.py`). 삭제(`terminate`) 호출은 하지 않았다.

### 사후 확인
`app.oor7.com/healthz` → **응답 없음**(정지 전 200). API 목록 재조회에서 oort 3대 전부 `stopped`.

### 남은 것 — 스토리지 비용과 삭제 판정
정지된 서버도 **블록 스토리지 요금은 계속 나간다.** 그것까지 없애려면 **삭제**가 필요하고, 삭제는 되돌릴 수 없다. 순서: ①서버를 잠깐 켜고 접속 키를 확보해 PG 덤프 ②오프사이트 2벌 보관 ③성재 확인 ④삭제. **접속 키(pem)가 현재 로컬에 없다** — `~/.ncp/`에 pw 파일들과 API 키만 있다. 재발급 또는 `getRootPassword` 경로가 선행되어야 한다.
