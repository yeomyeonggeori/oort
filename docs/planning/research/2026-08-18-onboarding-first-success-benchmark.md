## §0. 한 문단 요약

**시간은 우리가 이긴다. 끝점이 다르다.** Docker가 완전히 빈 머신에서 브라우저 화면까지 **1분 20초**, 첫 메시지가 레일까지 가는 데 **1분 20.5초**다 — dsh 기준선 5~10분의 **1/4 이하**. 그런데 dsh가 5~10분 안에 도달한다고 말하는 지점은 "첫 화면"이 아니라 **키 입력 후 첫 태스크**이고, oort는 문서대로 따라간 셀프호스터가 **그 지점에 도달할 수 없다.** `PUT /v1/provider/link`가 MOMO-583 인스턴스 오퍼레이터 게이트에서 403이고(**5/5 회전 재현**), 그 게이트를 여는 `PLATFORM_ADMIN_EMAILS`는 셀프호스트 env 생성기가 만들지도 않고 정본 compose의 api 서비스가 읽지도 않는다 — env 파일에 손으로 적어도 컨테이너에 들어가지 않는다. 별도로, 생성된 env가 `MOMO_ENV=staging`이라 **노트북의 로컬 모델(루프백 http)을 에이전트에 붙이는 것도 400으로 막힌다**(5/5 재현). 즉 **우리의 병목은 속도가 아니라 첫 실행의 권한 기본값**이고, 그것은 시간을 줄이는 일이 아니라 **막힌 문을 여는 일**이다.

## §1. 무엇을 재기로 했나 — "첫 성공"을 어디에 두었나

dsh의 5~10분은 **"설치 한 줄 → Web UI → 키 입력 → workspace 선택 → 첫 태스크"**까지다. oort에서 그 문장에 대응하는 정본은 `docs/SELF_HOST.md`이고, 그 문서가 약속하는 것은 시간이 아니라 **결과**다("시간은 약속하지 않는다 … 약속하는 것은 **결과**다"). 그래서 이 감사는 문서가 약속한 결과를 마일스톤으로 쪼개고, 각 마일스톤이 실제로 성립하는 시각을 잰다.

| 마일스톤 | 성립 조건 (기계적) | dsh 대응 |
|---|---|---|
| **M1 첫 화면** | 엣지가 `/` 200 **+ `/healthz` 200** | `npx dsh web` 이 뜬 시점 |
| **M2 첫 로그인** | `POST /v1/auth/login` 이 `accessToken` 반환 | Web UI 진입 |
| **M3 첫 메시지** | 메시지 커밋 **+ outbox가 `broadcast/done`으로 비워짐** | 첫 태스크 제출 |
| **M4 첫 에이전트** | 에이전트 member 생성 + 채널 합류 + 베어러 발급 | 키 입력 후 에이전트 응답 |

**M3에서 outbox까지 본 것은 의도적이다.** relay는 성공 publish를 **로그하지 않으므로**(`docs/SELF_HOST.md` §막히면) "메시지가 레일까지 갔다"의 서버측 증거는 로그가 아니라 `outbox` 질의뿐이다. HTTP 201만 보고 성공이라 부르면 relay가 죽은 스택도 통과한다.

**M1에서 `/healthz`를 함께 본 것도 의도적이다.** 엣지는 `/healthz`만 프록시하고 `/health`는 SPA 폴백에 걸려 **index.html을 200으로 돌려준다**(`infra/rust/Caddyfile.local:36-38`). `/health`를 헬스체크로 쓰면 api가 죽은 스택이 통과한다 — 하네스에 못으로 박아 둔 함정이다.

### 1회 측정을 금지한 이유

이미지 빌드 시간은 캐시 상태에 지배당한다. 1회 측정은 캐시 상태를 수치 안에 숨긴 채 발표하게 된다. 그래서 하네스는 캐시 상태를 **모드로 승격**시키고 회전마다 `docker system df`·`docker image ls`를 앞뒤로 남긴다.

| 모드 | 무엇을 비우나 | 무엇의 답인가 |
|---|---|---|
| 기본(warm) | 아무것도 | 이미 한 번 지어 본 머신의 **재실행 하한** |
| `--cold` | `docker builder prune -af` | 소스는 있고 캐시는 없는 **재빌드** |
| `--first-run` | 위 + 미사용 이미지 전량 | 베이스 이미지까지 다시 받는 **정말 처음** |

## §2. 실측 수치 (구간별)

측정 머신: Apple Silicon 18코어 · Docker Compose v5.3.1 · `feat/1526-dsh-b-onboarding-n@5e598773`(base `track/engine`).
**5회전**(재기동 2 · 재빌드 1 · 콜드 1 · 첫 실행 1)을 각각 독립 실행했고, 회전 끝마다 `down -v` + 프로젝트 스코프 자원 회수를 거쳤다. 감사 판정(A1·A4·A6·A7)은 **5회전 전부 동일**했다 — 환경 편차가 아니라 기본값이다.

**읽는 법 1 — 변하는 것은 P2a 하나다.** 캐시 상태가 4배로 벌어지는 동안 `P2b converge`는 **15.4~15.8초로 붙어 있다.** 즉 oort의 온보딩 시간은 「이미지를 굽거나 받는 시간」+「고정 15.5초」로 분해되고, 로그인 이후 네 구간을 다 합쳐도 **0.33초**다 — 사람이 인지할 수 없는 값이다. 그러므로 **"온보딩을 몇 분에서 몇 분으로 줄인다"는 개선 방향은 이 제품에 남은 여지가 거의 없다.** 남은 문제는 전부 §3의 마찰이다.

**읽는 법 2 — 가짜 콜드가 아니다.** ③의 증거는 build cache **0B** · `CACHED` **0건** · `Updating crates.io index` 실행 · **241 crate 다운로드 후 226 crate 컴파일 13.5초**다. 이렇게 빠른 이유는 `server-rust/Dockerfile`이 의존성 전용 스테이지를 따로 두기 때문이다(:105-116 스텁 소스로 `cargo build --release` → :119-128 실소스로 재빌드). ④는 거기에 베이스 이미지 여섯 개의 pull이 더해진 값이고, 그 부분만 회선에 지배당한다.

**읽는 법 3 — ②가 개발자의 일상값이다.** 소스가 바뀐 뒤의 재빌드(54초)는 셀프호스터가 아니라 **이 레포에서 일하는 사람이 매번 겪는 값**이다. 첫 실행보다 짧지만 재기동보다 3배 길다.

| **A5** 로그인 워크스페이스 칸 | 빈 칸 / 쓰레기 / 정확한 UUID | INFO — 200 / 400 / 200 |
| **A6** 에이전트 엔드포인트 게이트 | 루프백 http baseUrl 이 받아들여지나 | **BLOCKED** — 400 |
| **A7** 시드 계정 | 공개 기본 비밀번호가 잠겼나 | **PASS** |

A1·A4·A6·A7은 **5회전 모두 같은 판정**이었다. 환경 편차가 아니라 **기본값**이다.

## §6. 재현 방법

```sh
# 계획만 (아무것도 띄우지 않는다)
scripts/bench_onboarding.sh plan

# 실측 — 기본 2회전(warm), 회전 끝마다 down -v
scripts/bench_onboarding.sh run

# 재빌드 상한 / 정말 처음 받는 사람
scripts/bench_onboarding.sh run --repeat 1 --cold
scripts/bench_onboarding.sh run --repeat 1 --first-run

# 스택을 남겨 손으로 이어보기
scripts/bench_onboarding.sh run --repeat 1 --keep
```

증거는 repo 밖 `${TMPDIR:-/tmp}/oort-onboarding-bench/<UTC>/`에 남는다 —
`timings.tsv` · `audit.tsv` · `summary.md` · 회전별 `container-timeline.tsv` · `df-before/after` · `images-before` · redacted env · 스택 로그 · 각 감사의 응답 본문.

하네스는 **제품 코드에 손대지 않는다.** 정본 절차(`scripts/self_host_env.sh`)와 공개 REST 표면만 호출하고, 정상 종료·실패·신호 어느 경로로 끝나도 `EXIT` 트랩이 프로젝트 스코프 컨테이너·볼륨·네트워크를 회수한다(이 호스트의 자원 누적이 정확히 "게이트가 실패한 자리에 스택이 남는" 데서 왔기 때문이다).

## §7. 측정하지 않은 것 (추측 금지 유지)

- **첫 에이전트 응답 시간.** F1 때문에 문서 경로로는 도달할 수 없다. compose 오버레이를 손으로 써서 우회한 시간은 "셀프호스터의 시간"이 아니므로 재지 않았다. T1 랜딩 후 같은 하네스로 M5를 추가해 재는 것이 맞다.
- **published-digest 모드.** 하네스는 `--published-image`를 지원하지만 공개 digest 발행이 아직 owner/M7 게이트 뒤에 있어 실측하지 않았다(`docs/SELF_HOST.md` §2-B).
- **브라우저 실제 조작 시간.** 이 하네스는 REST 왕복을 잰다. 사람이 화면에서 클릭·입력하는 시간은 별도 측정이며, §3의 클릭 수 계수(F5·F7)는 코드에서 센 것이지 사람으로 잰 것이 아니다.
- **네트워크 편차.** `--first-run`의 베이스 이미지 pull은 회선에 지배당한다. 다른 회선의 수치는 다르게 나온다.
- **다른 호스트 형상.** 전부 한 대(Apple Silicon 18코어)에서 잰 값이다. 저사양·x86·저메모리에서의 P2a는 재지 않았다 — `P2b converge`가 네 캐시 상태에서 15.4~15.8초로 붙어 있었다는 사실이 다른 하드웨어에서도 유지된다는 보장은 없다.
- **게이트 등록.** 하네스는 `scripts/local_gate.sh`의 shell-syntax 목록에 등록하지 않았다. 그 파일은 이번 파도에서 #1525에 배정된 **보호 정책 경로**여서 이 goal이 만지지 않았다(PR의 §계획 이탈 참조). 등록은 T7의 일부다.
