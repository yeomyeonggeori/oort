# Slack 게스트 UX 리서치 (2026-11-02)

> 이슈 #5187 · ADR-0219(게스트 접근) 초안의 바깥 근거. 조사·작성은 리서치 워커, 검토는 planner, 결정은 owner. 확인일 2026-11-02.
> oort 코드 현황 감사는 별도 문서(`2026-11-02-guest-access-oort-audit.md`)가 맡는다. 이 문서는 **바깥 자료만** 다룬다.
> 출처는 `[S번호]`로 표기하고 맨 끝 「출처 목록」에 URL·구분·날짜를 모았다.

## 요약

- Slack 게스트는 우리 워크스페이스에 계정을 두되 **지정한 채널만** 보이는 사람이다. 초대·채널 변경·기간 설정은 소유자·관리자만 하고, 멤버는 요청만 낸다 [S1][S2][S5].
- 초대 화면에서 고르는 것은 이메일·게스트 유형·들어갈 채널·선택 기간이 전부다. 초대 메시지 입력란은 도움말에 없고, 게스트 초대는 데스크톱에서만 된다 [S5].
- 기간은 「일정 기간 뒤 / 특정 시각 / 없음」 중 고른다. 만료 5일 전 알림과 연장이 있고, 만료는 삭제가 아니라 비활성화이며 복구해도 예전 채널은 자동 복원되지 않는다 [S1][S6][S7][S15].
- 경계 쪽은 기본이 강하다. 공개 채널 둘러보기·사용자 그룹·앱 설치·AI 앱과 에이전트·AI 기반 Slackbot이 모두 막힌다 [S1][S14][S17][S24].
- 경계 안은 넉넉하다. 같은 채널 멤버와 DM, 접근 채널의 기록 열람, 허들, 파일 올리기, 요약·검색 답 같은 AI 기능은 쓴다. 멤버는 공유 채널이 없어도 게스트에게 DM을 보낼 수 있다 [S1][S17].
- 표시는 얇다. 이름 옆 도형(유형별)과 디렉터리 프로필(초대자·채널·만료일)이 확인되고, 모바일 앱에는 게스트 프로필 필드가 없다. 외부 조직 표시(프로필 사진 아이콘·배너)는 Slack Connect 쪽에서 더 분명하다 [S1][S26].
- **문서로 닫히지 않는 곳**: 게스트의 디렉터리·자동완성 노출 범위, 메시지 링크 미리보기, 검색의 사람·채널 결과, 초대 이전 기록 숨김, 에이전트가 호출자 권한을 따르는지. oort가 자기 규칙으로 정해야 한다.
- 감사 기록 API·기간 설정 API·최대 기간 상한은 Slack에서 Enterprise 전용이다 [S8][S15][S18]. 세션 초기화 API의 플랜 요건은 확인 못 함. oort는 게스트 감사를 기본 기능으로 두는 편이 경계 원칙에 맞다(제안).
- Slack Connect는 게스트와 다른 모델이다. 양쪽이 각자 워크스페이스를 유지하고 채널 하나만 공유하며, 보존·수정·삭제는 보낸 조직이 정한다 [S21][S26].
- 마지막 절에 판단 항목 정리: owner 결정 6건, 경계 보강 확정 제안 9건, Slack 그대로 6건.

## 판정 기준 (owner 인터뷰 결정)

| 항목 | owner 결정 | 이 문서에서의 쓰임 |

| 등급 | 초대받은 채널만 보이는 게스트 하나 + 기간 + 외부 표시 | Slack의 「여러 채널 게스트 / 한 채널 게스트」 구분은 요금과 얽혀 있으므로 그대로 옮기지 않는다 |
| 판정 원칙 | 경계는 엄격하게, 안에서는 Slack만큼 | 항목마다 「Slack 기본 / 경계 위험 / owner 결정 필요 여부」로 가른다(마지막 절) |

## 읽는 법과 자료의 한계

- **구분**: 「공식」은 Slack·Microsoft·Google의 도움말과 개발자 문서다. 「오래된 자료」는 2019년 Slack 블로그 두 편이다. 제3자 자료(대학 IT 문서·커뮤니티 글)는 검색에 나왔으나 **인용하지 않았다**.
- **날짜**: Slack 도움말은 갱신일을 적지 않고 저작권 표기(©2026)만 있다. 「확인일 2026-11-02 시점의 공개 페이지」로 읽는다.
- **읽은 방법**: 페이지를 요약 도구로 읽었다. 표의 기호 해석이 도움말 두 곳에서 엇갈리는 행(@channel 등)은 따로 표시했다. 원문 대조가 필요한 행은 「확인 필요」로 적었다.
- **보지 못한 것**: 로그인이 필요한 관리 화면·실제 앱 화면은 보지 않았다. 표시 모양·첫 화면처럼 화면을 봐야 하는 항목은 도움말이 말하는 만큼만 적었고, 말하지 않으면 「확인 못 함」으로 두었다.
- **요금제**: 대부분 유료 플랜 기준 문서다. 게스트 계정은 유료 플랜에서만 쓸 수 있다 [S1].

## 1. 흐름

### 1.1 누가 게스트를 초대할 수 있나

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 기본 초대 권한 | 멤버는 새 사람을 초대할 수 있고, 게스트는 초대할 수 없다 | [S2] |
| 게스트 초대 | 소유자(Owner)·관리자(Admin)만 한다. 멤버는 **요청**을 낼 수 있고, 「관리자 승인 필수」 설정이 꺼져 있어도 게스트 초대 요청은 관리자가 승인해야 한다 | [S1][S2] |
| 요청 라우팅 | 모든 관리자에게 Slack 알림으로 보내거나 지정한 채널로 보낼 수 있다. 요청자는 승인·거절 결과를 알림으로 받는다 | [S2] |
| 설정 위치 | 관리 > 워크스페이스 설정 > 권한 > 초대(Admin > Workspace settings > Permissions > Invitations) | [S2] |
| Enterprise | 조직 소유자가 게스트 초대 권한 자체를 제한할 수 있다(조직 설정 > 역할·권한 > 계정 유형). 자체 앱(API)으로 초대 요청을 관리할 수도 있고, 그 앱을 설치하면 요청이 조직 관리자에게만 가고 워크스페이스 관리자는 받지 않는다 | [S2][S8] |
| 요금제 | 게스트 계정은 유료 플랜에서만 쓸 수 있다 | [S1][S5] |

### 1.2 초대 화면에서 고르는 것

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 시작 | 사이드바의 워크스페이스 이름 > 「Invite people to…」. **데스크톱에서만** 가능하고 iOS·Android 앱에서는 게스트를 초대할 수 없다 | [S5] |
| 입력 | 초대할 사람의 이메일을 넣고 드롭다운에서 멤버 대신 게스트를 고른다 | [S5] |
| 고르는 것 | 게스트 유형(다채널/한 채널), 들어갈 채널, 선택 항목으로 계정 기간 제한. 이 셋이 전부이고 초대 메시지 입력란은 도움말에 나오지 않는다 | [S5][S1] |
| 초대 메일 내용 | 도움말이 설명하지 않는다. **확인 못 함** | [S5] |
| 초대 링크 | 링크 기능(유효 30일, 최대 400명, SSO가 켜져 있으면 쓸 수 없음)은 있으나 이 링크로 게스트가 들어오는지는 도움말이 말하지 않는다. **확인 못 함** | [S5] |
| 멤버의 요청 | Pro·Business+·Enterprise Grid(여러 워크스페이스를 묶는 대기업용 구조)에서 초대 권한이 없는 멤버는 같은 드롭다운으로 게스트 초대를 요청하고, 관리자가 승인·거절하면 알림을 받는다 | [S5] |
| 대기 중 초대 | 보낸 초대는 30일 유효하다. 관리자는 다시 보내 되살리거나 철회할 수 있다. 수락되지 않은 초대가 많으면 Slack이 초대 자체를 제한할 수 있다 | [S5] |

### 1.3 수락·가입

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 수락 절차 | 초대받은 사람이 초대를 수락한다는 것만 나온다. 이메일 링크·계정 생성 화면의 단계는 도움말에 없다. **확인 못 함** | [S5] |
| 대기 상태 | 초대받았지만 아직 로그인하지 않은 사람은 API에서 `is_invited_user`가 붙은 사용자로 나타나고, 로그인하면 사라진다 | [S9] |
| 가입 사건 | 앱은 새 게스트를 `team_join` 이벤트로 알게 된다. 게스트 상태 변경 이벤트는 새로 초대된 게스트를 다루지 않는다 | [S10] |
| 로그인 방식(SSO) | 워크스페이스가 SSO(통합 인증)를 쓰면 「모두 필수 / 게스트를 뺀 모두 필수 / 선택」 중 고른다. Slack은 게스트가 있는 곳에는 「게스트 제외」를 권하며, 그러면 게스트는 이메일·비밀번호로 로그인한다. 조직 관리자는 멤버·게스트를 SSO에서 빼는 것만 관리할 수 있다 | [S19][S20] |
| 초대 링크와 SSO | SSO가 켜져 있으면 초대 링크를 쓸 수 없다 | [S5] |
| 2단계 인증 | 게스트에 대한 규칙은 도움말에서 확인 못 함 | [S19][S20] |

### 1.4 게스트의 첫 화면

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 보이는 채널 | 초대 때 고른 채널에만 들어간다. 공개 채널을 둘러보고 스스로 참여하는 것은 안 된다 | [S5][S14][S17] |
| 기록 | 한 채널 게스트는 합류 이전의 채널 전체 기록까지 위로 스크롤해 볼 수 있다고 2019년 블로그가 설명한다 | [S12] |
| 채널 추가 | 한 채널 게스트는 채널 추가를 **요청**할 수 있고 관리자가 승인·거절한다 | [S3] |
| 환영·안내 화면 | 환영 메시지·안내 배너 같은 첫 화면 구성은 도움말에 없다. **확인 못 함**(로그인 화면은 보지 않았다) | — |
| 모바일 | 게스트 초대는 데스크톱에서만 하고, 게스트 프로필 필드는 모바일 앱에 없다 | [S5][S1] |

### 1.5 기간 설정·연장·만료 뒤 동작·복구

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 기간 선택지 | 일정 기간 뒤 자동 비활성화 / 특정 날짜·시각에 비활성화 / 기간 없음, 셋 중 하나를 소유자·관리자가 정한다. 초대 때 또는 멤버→게스트 전환 때 고른다 | [S1][S3][S4][S5] |
| 사전 알림 | 비활성화 **5일 전** 게스트 본인과 기간을 정한 소유자·관리자에게 알림이 간다. 소유자·관리자는 기간을 연장할 수 있다 | [S1] |
| 사전 알림(오래된 자료) | 2019년 블로그는 「2일 전」, 한 번의 클릭으로 연장이라고 적는다. 현행 도움말(5일 전)과 다르므로 **도움말을 따르고** 블로그는 참고로만 둔다 | [S4] |
| 요금 | 기간제 다채널 게스트도 일반 멤버처럼 과금되며, 청구 주기 중 일부만 활성이면 일할 계산 크레딧이 들어온다 | [S1] |
| 처리 시각 | 만료는 매시 30분·45분에 처리된다(시간대를 맞추기 위해). 이 값은 API(`admin.users.setExpiration`) 문서에 있고 그 API는 Enterprise 전용이다 | [S18] |
| 만료 = 비활성화 | 감사 기록의 `guest_expired`는 「만료 시각에 도달해 게스트가 비활성화됨」으로 정의된다. 즉 만료는 삭제가 아니라 일반 비활성화와 같은 상태다 | [S15] |
| 비활성화 때 | 모든 채널에서 빠지고, 모든 기기에서 로그아웃되며, 다시 로그인할 수 없다. 당사자에게 알림은 가지 않는다. 메시지·파일은 지워지지 않는다 | [S7] |
| 복구 | 소유자·관리자가 **언제든** 다시 활성화할 수 있다. 바로 로그인할 수 있고 예전에 보낸 메시지는 남아 있지만 **예전 채널에는 자동으로 다시 들어가지 않는다**. 조직 수준에서는 다시 활성화할 때 한 채널·다채널 게스트를 역할로 고를 수 있다. 복구 때 채널·기간을 어떻게 지정하는지는 도움말에 없다 | [S6] |
| 복구 기한 | 복구 가능한 기한을 말하는 도움말은 확인 못 함 | [S6][S7] |

### 1.6 게스트 ↔ 정식 멤버 전환

| 방향 | Slack 동작 | 출처 |
|---|---|---|
| 게스트 → 멤버 | 워크스페이스 한 곳에만 속한 게스트는 소유자·관리자가 멤버 관리 화면에서 바꾼다. Enterprise에서 여러 워크스페이스에 걸치면 조직 관리자가 조직 멤버로 올린다. 한 사람이 어떤 곳에서는 게스트, 어떤 곳에서는 멤버일 수 없다 | [S3] |
| 멤버 → 게스트 | 「계정 유형 변경」에서 게스트 유형을 고르고 **채널과 선택적 기간**을 정한다. Enterprise에서 여러 워크스페이스에 속한 사람은 비활성화한 뒤 게스트로 다시 활성화해야 하고, 그다음 워크스페이스에 넣어 채널을 정한다 | [S3] |
| 게스트 → 관리자 | 직접 올릴 수 없다. 먼저 정식 멤버로 바꾼 뒤 관리자·소유자로 올린다. 반대 방향도 같다 | [S3] |
| 전환 때 DM | 게스트의 채널이나 역할을 바꿔도 이미 있는 DM은 끊기지 않는다 | [S1] |
| 전환 뒤 채널 소속 | 게스트→멤버 전환 뒤 기존 채널 소속이 어떻게 되는지는 도움말에 없다. **확인 못 함** | [S3] |
| 비활성화→재활성화 때 채널·DM | 「DM은 이어지고 채널 소속은 이어지지 않는다」는 문장이 있으나 Frontline 멤버(별도 요금 등급의 멤버 유형) 항목 안에 있다. **게스트에도 같은지는 확인 못 함**(채널 소속 비복원 자체는 [S6]에서 게스트 포함 일반 규칙으로 확인) | [S3][S6] |
| 전환 때 요금 | 도움말이 설명하지 않는다. **확인 못 함** | [S3] |

### 1.7 제거

| 외부 조직 앱 | 다른 조직이 추가한 앱은 그 조직의 아이콘을 달고 보이고, 외부 조직은 그 앱을 지울 수 없다 | [S26] |
| 외부에 보이는 프로필 항목 | Slack Connect에서는 각 조직이 상대에게 보일 프로필 항목(기본 / 상태·시간대 등 추가)을 정한다 | [S26] |
| 게스트가 보는 구성원 정보 | 게스트가 다른 구성원의 프로필에서 무엇을 보는지(이메일 등)는 도움말에 없다. 관리자가 이메일을 숨기면 이메일 검색 결과가 나오지 않는다는 일반 규칙만 있다 | [S13] |

## 3. 기능 목록 (게스트가 할 수 있는 것)

Slack 도움말의 권한표는 「다채널 게스트(Multi-Channel)」와 「한 채널 게스트(Single-Channel)」 두 열이며 정식 멤버 열은 없다 [S1]. 별도의 「역할별 권한」 도움말에는 멤버 열이 있다 [S17]. [S1]은 일부 칸을 범례에 없는 기호(`✷`)로 표시하는데 문맥상 「워크스페이스 소유자가 허용할 때만」으로 읽었고(추정), 아래 표에는 그 칸을 「소유자 설정 시」로 적었다. [S17]은 자체 범례를 쓰며 기호의 뜻이 달라, 같은 행이 다르게 읽히는 곳은 「표 엇갈림」으로 적었다. 원문 대조가 필요하다. 「갈림」은 두 게스트 열의 값이 다른 행이다. oort는 등급이 하나이므로 갈리는 행은 마지막 절에서 판단한다.

## 4. Slack AI·에이전트와 게스트

### 4.1 Slack AI(자체 AI 기능)

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 게스트의 AI 사용 | 대화·스레드·파일 요약, 검색 답, 번역, 메시지 설명, 캔버스 내용은 쓸 수 있다. 워크플로 생성·허들 노트·AI 기반 Slackbot은 쓸 수 없다 | [S1][S17] |
| 접근 규칙 | AI는 요청한 사람이 **그 시점에** 접근할 수 있는 데이터만 쓴다. 자기가 속하지 않은 비공개 채널·DM의 내용은 보여 주거나 쓰지 않는다. AI 검색 답은 일반 검색으로 찾을 수 있는 결과만 담는다. 요약·Slackbot 답에도 사용자가 볼 수 없는 내용은 들어가지 않는다 | [S11] |
| 게스트에 대한 문장 | 이 도움말은 게스트·외부 사용자·Slack Connect를 따로 말하지 않는다. 「요청자가 볼 수 있는 것만」이라는 일반 규칙이 게스트에도 적용된다고 읽을 수 있으나(추정), 게스트 전용 문장은 확인 못 함 | [S11] |
| 보관 | 요약·검색 답은 저장하지 않는 일회성이고, 요약본(recap)은 90일 보관되며 원본이 삭제되면 같이 지워진다 | [S11] |
| 관리자 제어 | 소유자·관리자가 멤버에게 허용할 AI 기능을 정하고, Enterprise에서는 특정 사용자·그룹으로 제한한다 | [S11] |

### 4.2 AI 앱·에이전트·봇

| 항목 | Slack 동작 | 출처 |
|---|---|---|
| 게스트의 에이전트 사용 | 게스트는 AI 앱·에이전트를 **어떤 앱 승인 설정에서도** 쓸 수 없다. 외부(Slack Connect) 사용자에 대한 문장은 없다 | [S24] |
| 앱 설치 | 게스트는 앱 설치·제거·계정 인증을 할 수 없다. 접근 가능한 채널의 앱은 본다 | [S1] |
| 워크플로 | 권한이 있는 워크플로만 쓴다. 채널 만들기 같은 게스트가 못 하는 단계가 든 워크플로는 못 쓴다 | [S1] |
| 앱·봇이 읽는 범위 | 앱의 접근은 스코프(권한 범위)가 정하고, 채널·DM 내용을 읽으려면 앱을 그 대화에 추가해야 한다. 봇은 일반 멤버와 같은 정보에 접근하고 같은 행동을 할 수 있다(옛 `bot` 스코프는 넓고 새 앱은 좁은 스코프를 쓴다) | [S24][S25] |
| 에이전트와 호출자 권한 | 에이전트는 사용자를 대신해 메시지를 읽고 올리고 채널에 들어갈 수 있으며, 권한은 앱 스코프에 따르고 Slack 자체 AI에 걸린 제한의 영향을 받지 않는다. **에이전트가 호출한 사람의 권한을 상속하는지는 도움말에 없다** | [S24][S25] |
| 앱이 게스트를 아는 법 | 사용자 객체의 `is_restricted`(게스트)·`is_ultra_restricted`(한 채널)·`restricted_user_type`(정수, 값 정의 없음)·`guest_expiration_ts`·`guest_invited_by`. 비활성화는 `deleted: true` | [S9] |
| 상태 변경 이벤트 | `user_guest_status_changed`(스코프 `users:read`)는 멤버↔게스트, 한 채널↔다채널, 게스트→비활성 게스트 전환 때 발생한다. 새로 초대된 게스트는 `team_join`으로 알게 된다. 한 채널과 다채널 구분은 이벤트 페이지가 설명하지 않고 사용자 객체 문서를 봐야 한다 | [S9][S10] |
| 이메일 | 사용자 객체의 `email`은 `users:read.email` 스코프가 있어야 보인다 | [S9] |
| 외부 사용자 | `is_stranger`는 앱 토큰의 워크스페이스와 다른 곳의 사용자이면서 앱이 볼 수 있는 공유 채널에도 없을 때 참이다. `is_external`은 워크스페이스 밖 사용자를 뜻한다. Slack Connect 사용자의 프로필 항목은 경우에 따라 다르다 | [S9] |
| 관리자 도구 | 앱 설치 승인 설정, Enterprise의 앱 관리 정책, 에이전트 표시·숨김 설정이 있다 | [S24] |

## oort에 옮길 때 판단이 필요한 항목

**분류**: 「A 따름」은 Slack 기본을 그대로 따라도 경계가 지켜진다. 「B 보강」은 Slack 문서가 비어 있거나 약해서 경계 쪽으로 규칙을 정해야 하며 분쟁 소지가 작아 확정 제안으로 올릴 수 있다. 「C 결정」은 「경계는 엄격하게」와 「안에서는 Slack만큼」이 부딪혀 owner 결정이 필요하다.

**등급이 하나일 때 어느 열을 따르나(제안)**: 「초대받은 채널(여러 개)만 보이는 게스트」는 기능상 다채널 게스트에 가깝다. 다만 다채널 열이 허용하는 「채널을 늘리는 행위」(아무 멤버가 보낸 비공개 채널 초대 수락, 비공개 채널에 다른 멤버 초대, 채널 만들기)는 경계를 넓히므로 **한 채널 열(불가)을 기본으로 삼는 편**이 판정 원칙에 맞다. 채널 안에서 보고 말하는 행위(DM, 허들, 기록, 파일)는 두 열이 같거나 다채널 열이 넓으므로 다채널 열을 따른다. 아래 B5·C3에서 다룬다.
