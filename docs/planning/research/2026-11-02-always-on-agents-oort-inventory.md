# 늘 켜져 있는 에이전트 — oort 지금 기능의 자리와 빈틈 (내부 정리, 2026-11-02)

- 날짜: 확인한 날 2026-11-02. 기안: 리서치 워커(#5188 B칸). 성격: **결정이 아니라 ADR-0220(제품 방향) 초안의 근거 재료**다. 바깥 동향·경쟁 비교는 짝 문서 `2026-11-02-always-on-agents-landscape.md`(다른 워커)의 몫이고, 이 문서는 oort 안쪽만 다룬다.
- 질문: owner는 oort가 「늘 켜져 있는 에이전트가 메신저에 머물고, 사람이 메신저로 점검하고 방향을 바꾸는」 경험에서 최고가 되길 원한다. 방향 문서가 답할 질문 넷 중 ③ **지금 기능의 자리와 빈틈**이 이 문서의 몫이고, ① 점검·방향 전환 ④ 권한·비용·밖에서 점검에 대해 지금 무엇을 하고 무엇이 비었는지를 함께 적는다. ②(경쟁 대비)는 「oort만 가진 것」만 적는다.
- **기준선**(로컬 ref, `git fetch` 하지 않음): 작업 폴더 HEAD `853f82de7` = `origin/track/engine`(2026-11-02 21:09) · `origin/main` `8bec2f53f`(2026-10-31 19:33) · `origin/track/uxui` `e291d88ac`(2026-11-02 18:25). 11-01~02에 착륙한 것(#4656·#4578/#5124·#4763·#4764·#4968·#4889·#4890·#4944/#5026)은 **engine에만 있고 main에 승격되지 않았다**.
- 표기: [V] 이 세션에서 문서·코드를 직접 읽어 확인(경로:줄) · [확인 필요] 읽었지만 닫지 못함 · **읽기만 했고 아무것도 실행하지 않았다 — 전부 `runtime-unverified`다.** 줄 번호는 이 작업 폴더 기준이다. ADR 본문의 실명은 「owner」로 바꿔 적었다.
- 상태 어휘: **착륙(main)** main에 있다 · **착륙(engine)** track/engine에만 있다(승격 전, 팀 인스턴스·기기에는 아직 없다) · **일부** 한 표면이나 한 갈래만 · **계획** ADR는 Accepted인데 코드가 없거나 못 찾았다 · **보류** ADR가 Proposed·보류다.
- 표면 약어: 웹·데(스크탑)·폰. 웹과 데스크탑은 같은 React 코드를 쓴다(ADR-0133)라 대개 같이 ✓이고, 데스크탑에만 있는 것은 터미널·작업 호스트(host)·OS 알림이다. ✓ 있다 · ✕ 없다 · △ 일부 · ? 확인 못 함.

## 1. 요약

1. oort는 「에이전트=1급 멤버, 일은 채널 원장 위에서, 방향은 사람이 승인 카드로 정한다」는 뼈대를 이미 갖췄다(ADR-0101·0114·0186·0200). 비어 있는 것은 이 뼈대를 「늘 켜져 있음」이라는 제품 약속으로 묶는 문장과, 에이전트가 **먼저 알리는 규칙**이다.
2. 에이전트는 오늘 네 종류다. **24시간 상주하고 먼저 말할 수 있는 것은 바깥 에이전트(그록봇류)뿐**이다. 팀 AI 도우미(서버 내장)와 함께 호스팅된 Hermes는 부를 때만 반응하고, 내 맥의 하네스는 맥이 켜져 있는 동안만 응답한다(§2).
3. 바깥 에이전트는 oort가 부르지 못한다. 그쪽이 자기 루틴으로 oort에 접속해 내구 inbox를 가져가고(다이얼인), oort는 내용 없는 도어벨(기본 꺼짐)로 깨울 뿐이다. 그래서 oort가 「늘 켜져 있음」을 약속할 수 있는 근거는 서버가 재는 사실(생존 라벨·확인 박자·마지막 보고)뿐이다(ADR-0200).
4. **점검**은 사실 기반 상태·결과 중심 「작업」 화면·승인 카드로 꽤 갖췄지만, owner가 10-15에 「팀 감시·대신 승인·남의 일 세밀 추적」을 뺐다(ADR-0202 D5). 활동·계획 보고(#4656)와 계획 독은 engine에만 있고, 폰은 읽지 않는다.
5. **방향 전환**의 길은 승인·거부 카드(주된 길), run 중단 버튼, 에이전트 일시정지 스위치, 스레드 답글 깨우기(이어 가기)다. **메시지로 멈추는 길은 없고**, 실행 중 끼어들기(고침)는 바깥 에이전트에 없다(원격 입력은 비목표, ADR-0162 D17). 이것이 ①의 가장 큰 빈틈이다.
6. **먼저 알리는 규칙**은 승인이 필요한 제안 하나뿐 정해져 있다(`oort_action_initiate`, 행동 4개, 시간당 6·하루 20). 자발 발화(`oort_message_post`)는 핸들러가 승인 채널과 멤버십만 보고 ADR에서도 속도 제한을 못 찾았으며 [확인 필요: 메시징 층의 쓰기 예산은 읽지 못했다], 「새 정보를 더할 때만 말한다」는 규약은 지시문일 뿐 외부 런타임에는 닿지 않는다(ADR-0132 D4). 「채널에도 한 줄」(ADR-0186 R-e)의 쓰는 쪽은 코드에서 못 찾았다.
7. **권한**: 모든 워크스페이스 변경은 제안 → 사람 승인 → 승인자 권한으로 서버 실행이고, 「무승인 위임」은 두 번 미뤘다(ADR-0186 D3·V7). 늘 켜짐과 부딪히는 결정이 셋 있다: 도어벨 기본 꺼짐(ADR-0171 D6), Hermes `cronjob` 끔(ADR-0203 K4-1), 예약 메시지는 사람 전용·반복 없음(ADR-0208 D1). **에이전트가 스스로 예약해 깨어나는 길이 oort 안에 없다.**
8. **비용**: 에이전트별 월 비용을 멤버 전원이 읽고(ADR-0147 증보 D1, main), 도우미는 BYOK 기본 무제한에 관리자 한도(ADR-0201 B9, engine)다. 요청자별 비용·바깥 에이전트의 실측값·예산 도달 시 자동 정지(ADR-0164)는 없다.
9. **밖에서**: 승인 푸시(잠금 화면 바로 승인은 낮은 위험만), 내가 부른 에이전트의 답·멈춤 푸시, 작업 끝남 푸시, 터미널 CLI·MCP(ADR-0216)가 있다. 폰에는 에이전트 재우기가 없고(owner 10-16), 활동 보고·계획 독·run 도구 줄을 읽지 않으며, 「먼저 알림」을 위한 푸시 종류가 없다.
10. oort만 가진 것은 §4-②, 자리가 겹치거나 흩어진 곳은 §4-③, ADR 머리줄이 낡은 곳(ADR-0200 증보 7·ADR-0206 증보 1·ADR-0201 증보 v3)은 부록 B다. ADR-0220이 이 셋을 인용하려면 머리줄 정리가 먼저다.

- 실행 방식은 ADR-0162 D1이 세 부류로 나눈다: 관리형(managed, oort worker)·연동형(BYOA, 사용자 self-host gateway)·다이얼인. 위 표의 도우미·Hermes는 관리형 경로를, 바깥 에이전트는 다이얼인을 쓴다. 일반화 가능한 와이어 계약은 gateway REST(pending·events·complete·lease)이고 전송만 oort 고유라는 판정은 2026-07의 내부 실사에 있다(`research/19-agent-native-fabric/01-internal-audit-agent-surface.md` — Swift 서버 시절 문서라 파일 경로는 낡았고 계층 구조만 유효하다).
- dots·Muse(뮤즈)가 실재하는 개발자 표면을 가졌는지는 **확인 못 했다**. ADR-0186 증보 V3-3 표가 「공식 문서·실계정 확인 필요」로 적었다(`0186:551-552`). 이 문서도 지어내지 않는다.
- owner의 정의가 ADR-0198에 남아 있다: 상시 에이전트는 「VM에서 24시간 돌고 팀이 쓴다」, 개인 에이전트는 「내 맥이 켜져 있는 동안만 응답한다」(`0198:196`). 같은 ADR의 맥락도 에이전트(동료)와 하네스(도구)를 갈랐다(`0198:27`).
- 바깥 에이전트의 「상주」는 실시간 연결이 아니라 **루틴 박자**다. 같은 연결의 표본에서 깨어남 간격의 중앙값이 15분이었고, 그래서 화면은 「연결 안 됨」 대신 「다음 확인 때 가져가요」를 말하도록 바꿨다(ADR-0200 증보 6 배경 `:794-797`, 추정식 `hosted_cadence.rs:197`). 확인 박자·생존 라벨은 모두 에이전트가 이런 박자로 깨어난다는 전제 위에 서 있다.
- 에이전트가 아닌 두 가지: **사람의 도구**(개발자 토큰·`oort` CLI·사람 MCP, ADR-0216 D1 — 멤버가 아니라 그 사람의 이름 붙은 자기 위임)와 **팀 박스**(ADR-0210, 에이전트가 쓰는 컴퓨터. 계획, §3 E1).
