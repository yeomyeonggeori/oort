## 1. 원칙 (업계 표준에서 가져온 것)

1. **반응은 즉시.**
   - 입력 피드백은 100ms 안에 준다.
   - 화면 전환은 200–350ms다(iOS 기본 push는 약 350ms, 스프링).
   - 스크롤과 애니메이션은 60Hz를 유지하고, ProMotion 기기에서는 120Hz를 해친다고 보이면 안 된다.
2. **모션은 설명이다.**
   - 상태가 어디서 와서 어디로 갔는지를 보여 줄 때만 쓴다(정본 §2.6·웹 §4와 같다).
   - 장식 루프는 금지다. 예외는 **기다리는 동안의 로딩 마크 하나**이고, 대기가 끝나면 즉시 멈춘다.
3. **햅틱은 의미 있는 결과에만, 드물게 쓴다.**
   - iOS 표준 세 종류를 의미대로 쓴다: `selection`(값 선택), `impact`(물리적 접촉·임계 통과), `notification`(success/warning/error 결과).
   - 스크롤, 타이핑, 수신 메시지처럼 반복되는 이벤트에는 쓰지 않는다.
   - 시스템 햅틱 설정을 따른다.
4. **플랫폼 관례가 먼저다.**
   - iOS: push/pop 전환, 시트 스와이프 닫기, 가장자리 뒤로가기, 길게 누르기 메뉴.
   - macOS: 앱 메뉴와 ⌘ 단축키, 창 위치·크기 기억, Dock 배지, 알림을 누르면 그 자리로 가기.
5. **접근성은 기본값이다.**
   - Reduce Motion에서는 모든 전환이 페이드나 즉시로 바뀐다.
   - Dynamic Type 최대 크기에서도 잘리지 않는다.
   - VoiceOver 순서는 시각 순서와 같다.
   - 비텍스트 대비는 3:1 이상이다.
6. **한 브랜드.** 앱 아이콘, 런치 화면, 파비콘, 로딩 마크는 같은 표식을 쓴다. 액센트는 디자인 토큰 하나에서 온다.
7. **예산은 숫자로.** 콜드 스타트, 방 진입, 스크롤 프레임, 입력 지연을 잰다. 넘으면 RED가 되는 예산을 둔다.

## 3. 햅틱 지도 (초안)

| 이벤트 | 종류 | 이유 |
|---|---|---|
| 메시지 전송이 서버에 받아들여짐 | impact light | 보냈다는 물리적 확인. 전송 실패는 아래 오류로 간다 |
| 길게 눌러 메시지 메뉴가 열림 | impact medium | iOS 컨텍스트 메뉴 관례 |
| 반응 추가·해제 | selection | 값 선택 |
| 당겨서 새로고침이 임계를 넘음 | impact light(1회) | 「놓으면 된다」 신호 |
| 스와이프 답장이 임계를 넘음 | impact light(1회) | 같은 이유 |
| 승인 카드 결정 성공 | notification success | 결과 |
| 전송·결정 실패 | notification error | 결과 |
| 토글·세그먼트 변경 | selection | 값 선택 |

- **쓰지 않는 곳:** 스크롤, 타이핑, 수신 메시지, 타이핑 표시, 목록 갱신, 백그라운드 동작, 같은 이벤트의 반복.
- **구현 방향:** 새 의존성보다 기존 자체 Swift 모듈(`clients/mobile/modules/momo-*`)에 `UIFeedbackGenerator`를 얇게 붙이는 쪽을 먼저 검토한다. 호출은 한 파일의 이벤트 → 종류 표에서만 한다. 그래야 시험이 그 표를 고정할 수 있다.
- **결정 필요:** 앱 안에 햅틱 끄기 설정을 둘지. 시스템 설정은 항상 따른다.

| App Store 스크린샷 | iPhone 6.9" 세트. iPad를 지원하면 iPad 13" 세트도(현재 `TARGETED_DEVICE_FAMILY = "1,2"`) | iPad 지원 범위는 결정 대상 |
| 앱 미리보기 영상 | 15–30초, 기기 해상도별 | 선택 |
| OG·README | 1200×630, 히어로 배너 | 기존 `docs/brand/hero-banner.png` |

**파이프라인.**
1. SVG 마스터 한 벌을 레포의 브랜드 폴더에 둔다.
2. 스크립트 하나가 모든 대상 크기를 만든다.
3. 검사를 건다: 크기, iOS 1024의 알파 없음, 대비 3:1, sRGB 태그, 원본 해시 출처(생성물이 마스터에서 나왔는지).
4. `projectShape` 가드를 새 구성에 맞춘다(#2650 N-4).

성재가 테서랙트·codex CLI·SVG 도구로 만든 결과물을 마스터 자리에 넣으면, 나머지는 파이프라인이 만든다.

## 7. 인테이크 규칙

- 성재의 추가 요청은 받는 즉시 **전량 티켓**으로 만들고, 위 시리즈에 배정하거나 새 시리즈를 연다. 즉흥으로 고치지 않는다.
- 티켓마다 「자동화로 잡을 것 / 실기기 체감」 두 칸을 채운다.
- 체감 항목은 다음 증거 빌드의 5분 체크리스트에 올린다. 결과는 해당 이슈에 성재 발화로 남긴다.
