# TURN + CubeSandbox 전용 호스트 발주 검토 패키지 (성재 대행)

> 2026-08-16 Fable 작성 — 성재 결재(2026-08-15 구조화 질의 "발주 검토 패키지") 집행분.
> 목적: 관전 라이브 화면의 **실화면 E2E 개방 조건**(ADR-0165 증보 1 Accepted)을 여는 인프라 2대의 사양·비용 구조·발주 절차를 한 장으로. 최종 발주 결정·콘솔 조작 = 성재.
> 근거: `research/2026-08-15-reachability-spike-1411.md`(F1~F8) · `research/2026-08-09-cubesandbox-d42-spike.md` §1 · ADR-0156(발주 사양 증보) · ADR-0165(+증보 1).

## 0. 왜 2대인가 (한 줄씩)

- **CubeSandbox 전용 호스트**: 지금까지 전부 폐기 VM 실측이었고 상시 T3 기질이 없다 — 템플릿(producer 탑재)·실기동·운영이 전부 여기 걸림.
- **TURN 호스트**: 스파이크 실측 확정 — microVM NAT symmetric이라 relay가 유일 경로이고, CubeSandbox 호스트에 동거 불가(호스트↔VM UDP 무경로·헤어핀 불가). 별도 공인 호스트 필수.

## 1. CubeSandbox 전용 호스트 사양 (기존 ADR-0156 사양 + 스파이크 반영)

| 항목 | 사양 | 근거 |
|---|---|---|
| 플랫폼 | NCP VPC 전용 서버(또는 베어메탈급) — **nested virt(KVM) 필수** | U1/d42 실측: NCP 표준 VM에서 성립 |
| OS | **Rocky 9** (Ubuntu 금지) | d42: Ubuntu multipathd `+cpu` 차단 함정 |
| CPU/RAM | x86_64 · 8vCPU+ · **32GB** | ADR-0156 발주 사양 |
| 디스크 | **단일 대용량 XFS(예: 300GB)** — 시스템/데이터 분리 불요 | 스파이크 F7: 단일 XFS가 d42 §1.3 bind-mount·xattr 사고 구간을 통째로 회피 |
| 콘솔 | 웹 콘솔 접근 필수(커널 스왑 복구용 VNC) | ADR-0156 |
| 네트워크 | 사설 CIDR가 CubeNet(`10.244.x`·`192.168.x`)과 비충돌 확인 | ADR-0156 CIDR 회피 |
| ACG | 22(관리, 소스 IP 제한) + **8443(display 시그널링 WS 프록시 — 증보 1 D2-1)** 만 | 스파이크 형상 A·F1 |

설치 런북 반영 의무(스파이크 F1~F8 — 발주 후 설치 goal의 수용기준): ①호스트 방화벽 활성(ACG 단일 실패점 제거 — F1) ②preflight 9999/9998/9966 점유 확인+**설치기 rc=0 불신, 유닛 상태 검증**(F2) ③**사설 레지스트리**(템플릿 빌더가 로컬 docker 이미지 못 읽음 — F3) ④`EXPOSED_ENDPOINT` 무실체 — 시그널링 프록시는 직접 구성(F4) ⑤docker FORWARD drop 대비 DOCKER-USER 예외(F5) ⑥192.168.0.1:8443/:80 점유 회피(F6) ⑦검증 스크립트는 refused/timeout 양태 모두 수용(F8).

## 2. TURN 호스트 사양

| 항목 | 사양 | 근거 |
|---|---|---|
| VM | 소형(2vCPU·4~8GB)부터 — CPU보다 **대역폭**이 병목 | coturn은 경량, 미디어 relay는 NIC/트래픽 |
| 소프트웨어 | coturn(BSD, permissive — AGPL 백본 금지 정합) | 표준 TURN 구현 |
| 공인 IP | 전용 1개 (CubeSandbox 호스트와 분리 — 증보 1 D3-2) | 스파이크: 헤어핀 불가 |
| ACG | 3478/tcp+udp(TURN)·49152–65535/udp(relay 포트레인지)·22(관리) | coturn 표준 |
| 자격 | long-term credential — **발급 경계는 ADR-0004 증보 3과 교차 확인 후 LIVE-4 시점 결선**(v0: 서버가 세션 capability와 함께 단명 TURN 자격 발급) | 스파이크 §6-1 |

## 3. 비용 구조 (산식 — 실요금은 NCP 콘솔 견적으로 확정)

- **고정**: 전용 호스트 VM(32GB급) + TURN VM(소형) + 공인 IP 2개 — 월 정액.
- **변동(핵심)**: **TURN 아웃바운드 대역폭 = 세션 수 × 시청 시간 × 비트레이트**. 예: 1 Mbps 스트림 × 관전 1시간 ≈ 0.45GB 아웃바운드. NCP 인터넷 아웃바운드 요금(GB당 — 콘솔 요금표 확인)을 곱해 월 추정. 초기(내부 검수 규모)엔 수 GB/월 수준으로 미미하나, **다중 관전·상시 시청이 열리면 세션 비례로 증가** — ADR-0164 과금 설계에 대역폭 항목 편입 여부는 실사용 후 별도 결정.
- 발주 전 성재 확인 항목: ①NCP 계정의 32GB급 VM 월 단가 ②아웃바운드 GB 단가 ③전용 호스트를 상시 켤지/업무시간 운영할지(T3 수요 전까지 정지 운영 옵션).

## 4. 발주 절차 (성재 콘솔 대행 체크리스트)

1. NCP 콘솔: Rocky 9 · 32GB · 단일 300GB · VPC(기존 momo VPC — CIDR 확인) · 신규 로그인키 생성(**pem을 `~/.ncp/`에 보관** — 이번 유실 교훈) · 전용 ACG(22+8443).
2. TURN VM: 소형 · 공인 IP · 전용 ACG(3478·relay 레인지·22).
3. 발주 완료 통보 → Fable이 설치 goal 2건(CubeSandbox 설치+템플릿 / coturn 설치+검증) 티켓·패킷 발급, 워커 발사(런북 §1 반영).
4. 설치 검증 후 → **실기동 E2E goal**(producer 실기동+LIVE-2 실화면+relay 강제) 발사 — `runtime-unverified` 라벨 3종 해소.

## 5. 열리는 것 (발주의 가치)

전용 호스트+TURN이 서면: ①LIVE-2 실화면 E2E(개방 조건 7항목 중 1·4·5번 해소) ②LIVE-3/4 control 실입력 E2E ③T3 상시 기질(크레딧 과금 축 ADR-0164의 실행 기반) ④템플릿·스냅샷 실측(ADR-0156 계열 잔여 실측 전부).
