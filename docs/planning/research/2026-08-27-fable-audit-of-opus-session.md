### 2.3 빠뜨린 것 (가장 중요)

1. **DNS 미정리 — 이 검수의 최대 발견.** `dig +short app.oor7.com A` → **`101.79.11.189`**(2026-08-27 실측). 공인 IP 3개를 반납했으므로 이 A 레코드는 **반납된(재할당 가능한) IP를 가리키는 dangling DNS**다. 철수 판정문의 안전 검수 8축(S1~S8, `2026-08-26-ncp-teardown-judgment.md:88-97`)에 **DNS 축이 없고**, 재구축 스냅샷에도 DNS 레코드가 없으며, 자기 보고 §3(:31-39)도 무언급. NCP가 이 IP를 다른 고객에 재할당하면 그 고객이 `app.oor7.com` 트래픽을 받는다 — HTTP-01 챌린지는 IP 소유자가 통과할 수 있으므로 **유효한 인증서까지 발급받아 과거 알파 사용자의 재로그인 자격증명을 수집할 수 있는 표면**이 열려 있다.
2. **AC-2(#1768 멤버 라이프사이클) 무언급.** 자기 보고 §7 표(:67-73)는 계정축을 5행으로 좌표 확정했다고 하나 **승격·강등·정지·추방·밴(ADR-0128:22-27의 본체)이 표에 없다**. #1768은 open 상태다. 계정축 잔여 산정이 실제보다 작게 읽히게 하는 누락.
3. **집행 스크립트 미보존.** 철수를 수행한 스크립트(`scratchpad/stop_app.py` 계열)가 레포에 없다(`scratchpad/` 빈 디렉터리 실측). 판정문이 집행 기록을 남겼으나 재현 수단은 채팅 밖으로 유실 — CLAUDE.md 플러시 의무("채팅에만 있는 맥락은 잃어버린 것")의 부분 위반.
4. **문서 잔재.** `AGENTS.md` 헤더가 여전히 "`app.oor7.com`에서 돌고 있고"라고 서술(현재 위치 문단). `CLAUDE.md`·`CODEX.md`·`docs/runbooks/ncp-rust-deploy.md`도 동일 계열 잔존. 철수 후 정본 갱신이 판정문 밖으로 안 나감.
5. **Caddyfile 실도메인.** `infra/rust/Caddyfile:1`이 `app.oor7.com` 사이트 블록 하드코딩(+`:23` 주석에 IP 실기록). #1239(파라미터화)가 open인 채 철수만 실행 — 이 파일로 재기동하면 존재하지 않는 배포를 향해 ACME 발급을 시도한다.

## 3. Q1 — 방향성이 옳은가

### Q1-a. NCP 완전 철수 — 방향 옳음, 검수 8축은 불충분

- **방향**: 옳다. 외부 의존 감사(`2026-08-26-selfhost-external-dependency-audit.md`)가 "런타임 강제 의존은 실질 1곳(데스크톱 자동 업데이트)"임을 선행 확인했고, 셀프호스트 정본 전환(ADR-0165 증보3 — TURN 신뢰 경계를 "해당 배포의 운영자 소유분"으로 재정의)과 정합한다.
- **8축의 구멍**: S1~S8(`…teardown-judgment.md:88-97`)은 전부 **"레포 안에서 그 호스트를 참조하는 곳"**만 봤다. **레포 밖 표면 3종 — ① DNS 레코드, ② 발급된 인증서/갱신 체인, ③ 기존 설치 클라이언트가 저장한 서버 URL·세션 — 을 보는 축이 없다.** ①은 §2.3-1의 dangling DNS로 실증됐다. ③은 S6이 "클라이언트 기본값 없음"으로 스치지만, 기본값이 없어도 **성재 기기에 저장된 과거 접속 정보**는 남는다.
- **재구축 스냅샷 충분성**: **그 정보만으로는 재구축 불가.** 스냅샷은 zone·이미지·스펙·디스크 구성을 담지만 (a) DNS 레코드 세트, (b) `*.secrets.env` 값(스냅샷 스스로 "값은 없다"고 인정 — 그런데 **키 목록조차 없다**), (c) ACG 규칙 상세(런북 링크 의존)가 빠져 있다. 재구축은 "스냅샷 + 런북 + 별도 비밀 저장소" 3점 세트여야 하는데 그 합집합이 어디에도 명시돼 있지 않다.
- **판정**: 철수 자체는 되돌릴 필요 없는 옳은 결정. 단 **DNS 정리(레코드 삭제 또는 무해한 곳으로 변경)는 지금 즉시 필요**하고, teardown 체크리스트에 "레포 밖 표면" 축을 추가해야 재발하지 않는다(§5 제안 1).

### Q1-b. 허들 = Funnel TURNS — 방향 타당, 단 "TLS 악수 = 미디어 흐름"이 아니다

- **추론 비약 여부**: RA-8의 소거 논리(RP-1 실측으로 홀펀칭 사망 → 인바운드 가능한 통로는 Funnel뿐 → TCP 843x TLS 종단 통로에 TURN/TLS를 얹는다)는 비약 없다. 자기 보고 :51-52의 RP-1/RP-2 실측 서술도 RA-8 원문과 일치한다.
- **TLS 악수가 보장하는 범위**: **SNI 라우팅이 8443 TCP를 VM 내부 리스너까지 전달한다는 것까지만.** 그 위에서 ① TURN long-term credential 인증, ② relay allocation 수립, ③ UDP↔TCP 변환 미디어의 양방향 릴레이, ④ 60분 soak(기존 Funnel WS 1001 드롭의 TCP 재현 여부), ⑤ Funnel 대역폭 한도 내 통화 품질 — 은 전부 미검증이다. RA-8 스스로 이를 남겼다(:935 "미실측으로 남은 것은 TURN 트래픽이 이 통로에서 실제로 미디어를 나르는가"). 즉 **#1792(SPIKE-HD)가 성공해야 방향이 "확정"되는 것이고, 지금은 "유력"이다.**
- **더 단순한 길**: **있고, RA-8 자신이 적었다** — §8.2 P3(LiveKit Cloud 무료 티어): 가입 1회 외 설치 0·비용 0·오늘 즉시 동작. P1 대비 유일한 열위는 미디어가 제3자(LiveKit Cloud)를 경유한다는 것. 성재의 "클라우드는 추천만" 모델과 P3의 위치(셀프호스터에게 옵션으로 제시)는 충돌하지 않는다. **P1 스파이크가 실패하면 P3가 기본 폴백이라는 순서를 성재에게 명시 결재받아야 한다**(§7-2).

### Q1-c. 외부 도구 = 에이전트 자격(#1797) — 정합, 옳다

- ADR-0101이 정의한 에이전트 신원 모델(에이전트=`member.kind='agent'` + `agent_bearer` 장수명 토큰, 사람 세션과 분리)과 정면 일치. **현행(오케스트레이터가 사람 세션 토큰으로 접속)이 오히려 ADR-0101 위반 상태**이고, #1797은 그것을 정본 쪽으로 되돌리는 티켓이다. 발급 표면(`/v1/workspaces/{ws}/agents/{agent}/credentials`)이 이미 있으므로 신규 API 설계도 불요.
- 자기 보고 :58-60의 "CDP 재도입 거절" 판단도 옳다 — 2026-08-22 성재가 약관 사유로 은퇴시킨 경로의 재도입을 성재 지시라도 거절하고 대안을 낸 것은 기록상 올바른 에스컬레이션.

## 4. Q2 — 구현이 올바른가 (코드 리뷰)

### 4.1 #1788 same-origin 파생 (`ffb5a033`) — 준용 구조는 옳으나 "위험 동일"은 부정확

- ADR-0167의 파생 기전(`X-Forwarded-Proto`+`Host` → base 도출)을 `server-rust/bins/momo-server/src/realtime_advert.rs`의 `derive_same_origin_http_base`로 **문자 그대로 재사용**하고, `lib.rs::advertised_local_upload_url`이 attachments/workspace_avatar 라우트에 공급한다. 코드 재사용 자체는 옳다.
- **그러나 위험이 완전히 같지는 않다**: ① realtime WS는 연결 시 별도 connection JWT 인증 + Centrifugo `allowed_origins` 대조가 이중 방어로 있지만, ② capability 업로드 URL은 **URL 자체가 bearer(업로드 토큰 내장)**이고 PUT에 origin 대조가 없다. 오염된 Host로 파생된 업로드 URL은 파일과 토큰을 함께 나른다. **"오염 응답은 오염 요청자 자신에게만 간다"는 자해 모델이 성립하는 한 실질 위험은 동등**하나, 그 성립 전제는 "신뢰 프록시(Caddy)가 Host를 정규화한다"이다. 셀프호스트 정본 경로(Caddy 엣지)는 전제를 만족하므로 **머지 판정은 유지**하되, ADR-0169 증보1에 "프록시 없는 직접 노출 배치는 이 전제 밖"이라는 운영자 고지가 있는지 확인 필요(미확인 — 증보1 원문 재독으로 확인 가능).

### 4.2 #1767 / PR #1798 `credential_claim` 일반화 — 구조는 옳으나 **머지 블로커 1건**

옳은 것:
- **RENAME 안전**: `server/Migrations/081_credential_claim.sql`이 `owner_claim`→`credential_claim` RENAME + `kind` 컬럼 + backfill을 단일 마이그레이션으로 처리, `schema_v0.sql` 비접촉(정본 이동/수정 금지 준수). 참조 지점(`infra/prod/bootstrap_owner_claim_if_absent.sql`, `scripts/verify_owner_claim.sh`)도 같은 PR에서 동반 수정됨 — patch 내 `+420`·`+529` 파일들이 `kind='owner_bootstrap'` 조건으로 갱신.
- **유니크 인덱스 kind 분리 옳음**: owner_bootstrap은 workspace당 1(미소비), password_reset은 (workspace, member)당 1(미소비) — 의미가 다른 제약을 부분 유니크로 분리한 것은 정확.
- **세션 회전 판정 타당**: `momo-auth/src/token_store.rs::revoke_member_session_tokens`가 `kind='session'`만 만료 — reset/변경 시 인간 세션은 전부 끊되 `agent_bearer`는 비접촉. ADR-0101(에이전트 자격 분리)과 정합. reset 소비·`change_own_password` 모두 같은 트랜잭션에서 회전.
- 대상 검증: `issue_password_reset_in_tx`(PR diff, `momo-auth/src/owner_claim.rs`)가 `kind='human'`·`status='active'`·비삭제를 `FOR UPDATE OF m`으로 잠그고 검사 — 에이전트 비밀번호 발급 차단, 재발급 시 이전 미소비 reset 무효화의 원자성도 확보.

**블로커 — 권한 위계 검사 부재 (Admin의 Owner 계정 탈취 가능)**:
- 라우트 층 `require_admin`(PR diff, `momo-server/src/routes/password.rs`)은 **행위자가 admin 이상인지만** 검사한다(`role.is_admin()`). 도메인 층 `issue_password_reset_in_tx`는 **대상 멤버의 role을 SELECT조차 하지 않는다**(위 인용 — kind/status/deleted만 조회).
- 따라서 **Admin이 Owner를 대상으로 `POST …/members/{owner}/password-reset`을 치면 201로 토큰 원문을 자기가 받고, `/v1/claim`으로 Owner의 새 비밀번호를 자기가 설정하며, 소비 시점의 세션 회전이 Owner의 살아있는 세션을 전부 끊는다** — 완전한 계정 탈취.
- 이는 ADR-0128:22의 명문 규칙 위반: "admin→(member|guest 관리, **admin 임명·owner 조작 불가**). **자기보다 높거나 같은 역할 조작 불가**(Discord 계층 규칙)".
- **수정 방향(1줄 계약)**: 발급 라우트에서 대상 role을 조회해 `행위자 role > 대상 role`(owner만 owner/admin 대상 발급 가능, admin은 member/guest만)을 강제. conformance 테스트에 "admin→owner reset = 403" 케이스 추가.
- PR #1798의 테스트 7본(tokio::test)에는 이 케이스가 없다 — 워커 브리프의 수용기준에도 위계 조항이 없었다는 뜻(Q5와 연결).

### 4.3 #1769 / PR #1799 초대 3경로 — Swift 참조와 계약 일치, 문제 없음

- **revoke 멱등**: Swift 참조 `server/Sources/MomoServer/Routes/InviteRoutes.swift:186-187`의 `SET revoked_at = COALESCE(i.revoked_at, now()), revoked_by = COALESCE(…)` 패턴을 Rust(`momo-settings/src/invite.rs`)가 동일 재현 — 재호출 시 최초 revoke 시각·행위자 보존, 200 반환. 멱등 맞음.
- regenerate는 원자 교체(구 코드 revoke + 신 코드 발급 단일 tx), redeem은 소비된 코드에 410 — PR diff와 Swift 참조(`InviteRoutes.swift:241-257`) 계약 일치. 테스트 3본 존재.
- admin 전용 게이트·감사 레코드 동반 — ADR-0128 계열과 충돌 없음. **머지 가능 판정**(최종 게이트는 momo-main 몫).

### 4.4 #1747 drive-init (`c965d4bc`) — 신뢰 경계 수용 가능, fail-fast 보존

- root(`user: "0:0"`)로 도는 일회성 컨테이너지만: 스코프가 **단일 볼륨 chown 1회**로 한정되고, 시크릿·네트워크 접근이 없으며, 본체 컨테이너는 계속 비-root — 셀프호스트 first-boot 권한 문제의 표준 해법(공식 이미지들의 init 패턴)과 동형. 수용 가능.
- fail-fast: `depends_on: condition: service_completed_successfully`(`infra/rust/local.override.yml`)로 chown 실패 시 본체가 아예 안 뜬다 — "조용히 잘못 뜨는" 퇴행 없음. 보존 맞음.

### 4.5 #1777 / #1778 — 주장 대체로 맞음, 표현만 부정확

- **#1777**(`9a308276`+`c131e0f2`): host-signed 세션 생성·수명·PTY 바인딩의 서버 수용면. 미이식분(ACP 이벤트 릴레이)을 숨기지 않고 **#1785로 후속 명시** — 정직한 스코프 처리.

## 5. Q3 — 검수 품질 (자기 보고 §9의 인정이 충분한가)

**§9의 다섯 패턴 인정은 정직하지만, ㉢·㉠은 "패턴 인식"에서 멈췄고 구조 처방이 없다. 인정 자체가 재발 방지가 아니다.**

### ㉢ printf 회귀 — 일회성 실수가 아니라 **구조적 구멍**

- 사실관계: #1790이 `scripts/self_host_env.sh`에 넣은 `printf "$fmt"` 계열이 사용자 문자열의 `%`를 서식으로 해석 — 다음 날 리그에서 발화, `05dea47f`로 `printf '%s'` 수정.
- **구조 진단**: 이 레포의 게이트는 셸 스크립트에 대해 `bash -n`(문법)까지만 돈다(철수 판정문 S2가 이를 자인 — `local_gate.sh:665`가 `bash -n`만 수행). printf 서식 버그는 **문법도 shellcheck도 못 잡고 실행만이 잡는다.** 검수(diff 읽기)도 못 잡는 부류다. 자기 보고 :95의 원인 분석("모드 테스트가 claim 분기만 밟아 비-claim 문자열이 한 번도 실행되지 않았다")은 정확하나, **처방이 없다**.
- **처방(기획 제안)**: `scripts/self_host_*.sh` 계열 접촉 PR에 한해 "대표 입력 2종(claim/비-claim, `%` 포함 문자열)으로 스크립트를 실제 1회 실행하고 출력 스냅샷 대조"를 local_gate 프로파일에 추가하는 티켓. 전 스크립트 확대는 과잉 — 사용자 입력을 나르는 생성기류만.

### ㉠ "실기동 없이 측정 불가" 4건 — 게이트 설계 문제 맞음, 단 처방은 선별적으로

- 4건(compose 가드 오탐·printf·migrate env·볼륨 권한)의 공통분모는 **"컨테이너 조립면"** — 코드 단위가 아니라 compose·env·볼륨의 접합부다. 이 면은 현행 게이트(fmt/clippy/test/tsc)가 원리적으로 못 본다.
- 모든 PR에 리그 실기동을 넣는 것은 반대한다(게이트 시간 폭증·flake 유입). **처방**: ① `infra/rust/*.yml`·`scripts/self_host_*` 접촉 PR에만 "compose up 스모크(부팅 성공+헬스체크)" 조건부 게이트, ② 축 단위 머지 완료 시점(성재 검수 직전)에 오케스트레이터가 클린 리그 1회 재현 — 이번 세션이 사후에 한 일을 사전 의무로 옮기는 것.

### 오케스트레이터의 워커 결과 재판정 방식 — 코드 정합은 잡았으나 축 2개가 없다

- 현행(diff 정독 + 게이트 로그 + 계약 문서 대조)은 #1788 기전 오류·#1790 문서 모순을 **문면 대조로 잡아냈다**(자기보고 :89-92 ㉡ — 실제 성과). 그러나:
- **놓친 축 ①: 권한 매트릭스.** "이 API를 **누가 누구에게** 쏠 수 있나"를 표로 강제하는 검토축이 없었고, 그 자리에서 #1798 위계 결함이 통과됐다.
- **놓친 축 ②: 실행 결함.** printf처럼 diff 읽기가 원리적으로 못 잡는 부류(㉢와 동일 뿌리).
- 처방: 재판정 체크리스트에 "신규/변경 엔드포인트마다 행위자 role × 대상 role 매트릭스를 적고 각 칸의 기대 응답(2xx/403)을 명시, conformance 테스트와 대조" 1행 추가. 이것 하나로 #1798류는 구조적으로 걸린다.

## 7. Q5 — 워커 운용

### 브리프 품질·게이트 지정 (PR 본문·이슈 코멘트 역추적)

- PR #1798/#1799 본문은 계약 인용(ADR·마이그레이션 관례·테스트 목록)이 충실하고 §5 템플릿 준수 — 브리프가 계약을 전달한 흔적은 뚜렷하다.

### ㉣ 게이트 브리핑 누락 — 구조적으로 막는 법

- AC-4 브리프부터 수동 포함(자기보고 :98)은 임시방편이다. **처방: 사람 기억에서 경로 트리거로 이관** — `docs/api/openapi.yaml` 접촉 PR이면 `scripts/verify_web_generated_types.sh`를 local_gate가 자동 요구(경로 조건부 게이트). AGENTS.md §5가 이미 이 검증기를 정본으로 지정하고 있으므로 트리거만 옮기면 된다. 같은 원리를 §5의 셸 스모크·compose 스모크에도 적용(접촉 경로 → 게이트 자동 편입). **브리프는 "무엇을 만들라"만 남기고, "무엇을 통과하라"는 기계가 정하게 한다.**

### ㉤ AC-4 워커의 정지 — 옳았고, 더 자주 유도하는 법

- 판정: **옳다.** `workspace.settings`를 쓰는 REST가 없는데 localStorage 우회나 임의 라우트 신설(경계 변경 — ADR-0100 위반)로 갔다면 더 큰 비용이었다. 정지가 #1800이라는 정확한 티켓을 낳았다.
- 유도 방법: AGENTS.md §4-10(임의 재설계 대신 `goal_release --blocked`)이 이미 규범이므로 새 규칙은 불요. **브리프 템플릿에 "정지 조건" 절을 상설**하라 — "다음을 발견하면 우회하지 말고 멈춰라: (a) 계약 문서와 스키마/코드 불일치, (b) 수용기준 달성에 필요한 표면 부재, (c) 경계(API/보안/스키마) 신설 필요". 정지를 "실패"가 아니라 "발견"으로 브리프가 먼저 명명하면 워커의 손실회피가 정지 쪽으로 기운다.

## 8. 더 나은 방식이 있었던 지점 (구체안)

1. **NCP 철수: teardown 체크리스트에 "레포 밖 표면" 축.** 8축 전부가 레포 내부 참조 검사였다(§3 Q1-a). "DNS 레코드 → 인증서 → 클라 저장 상태 → 외부 등록물(스토어·웹훅)" 4항을 표준 축으로 추가한 재사용 체크리스트를 `docs/runbooks/`에 두면, 이번 dangling DNS류는 기계적으로 걸린다.
2. **허들: 결재 순서가 거꾸로였다.** P1 실측(RP-2)에 먼저 들어가는 대신, **P1 vs P3 트레이드오프 표(미디어 제3자 경유 여부 · 오늘 되는가 · 운영 복잡도)를 성재에게 먼저** 올려 폴백 순서를 결재받았어야 한다. 지금이라도 §9-2로 회수 가능.
3. **#1798: 권한 매트릭스를 수용기준에.** "행위자 role × 대상 role → 기대 응답" 표 한 장이 브리프에 있었으면 워커가 위계 검사를 구현하고 403 테스트를 썼을 것이다. 신규 엔드포인트 브리프의 상설 항목으로 제안(§5 재판정 체크리스트와 동일 원천).
4. **집행 스크립트 보존.** 철수 스크립트를 `scratchpad/`가 아니라 판정문 옆(`docs/planning/research/` 부속 또는 `scripts/oneoff/`)에 커밋했어야 한다 — "채팅에만 있는 맥락은 잃어버린 것"(CLAUDE.md)의 적용 대상은 코드도 포함이다.
5. **없다고 판정한 것**: #1769 초대 3경로, #1747 drive-init, #1777 스코프 분할(+#1785 후속)은 지금 방식이 최선에 가깝다 — 더 나은 대안을 찾지 못했다.
