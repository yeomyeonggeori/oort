- **증거**: `clients/mobile/src/features/conversation/MessageRow.tsx:846-862`
  ```tsx
  body.includes('```') ? <CodeBlock text={body} /> : <Text style={styles.body} …>{body}</Text>
  ```
  코어 파서 `packages/momo-core/src/features/timeline/markdown.ts:310` 은 **웹만** 소비한다(`clients/web/src/features/timeline/MessageBody.tsx:9,214`). 모바일의 임포트 수 = 0. 코드 주석 `MessageRow.tsx:66-76` 이 이 상태를 자인한다.
- **캡처가 드러낸 것 — 가설보다 나쁘다.** 지배적 실패 모드는 "마크다운이 안 그려진다"가 아니라 **답변 전체가 하나의 모노스페이스 상자로 들어간다**는 것이다. 기술 답변에는 코드 펜스가 거의 항상 하나쯤 있고, 분기 조건이 `body.includes('\`\`\`')` 이므로 **산문·제목·목록까지 전부** 코드 취급된다. `md-01` 에서 실측되는 것:
  - `# 배포 롤백 원인` → `#` 가 그대로 보인다
  - `**결론**:` → 별표가 그대로 보인다
  - `- \`outbox_drain_worker\` 가…` → 하이픈과 백틱이 그대로 보인다
  - 펜스 마커 ` ```sh ` 와 닫는 ` ``` ` 가 **본문에 글자로 남는다**
  - 한국어 산문이 12px Menlo로 조판된다 — 가독성이 본문 폰트보다 명백히 낮다

- **비고**: `md-01` 하단의 `Open debugger to view warnings.` 는 Debug 빌드의 개발자 배너다 — 제품 결함이 아니므로 세지 않았다.

#### BL-2 · 폰 — 메시지 텍스트를 복사할 수 없다

- **증거**: `clients/mobile/.../MessageRow.tsx:860` — `selectable={!actionable}`. `actionable = actions !== undefined && hasAnyAction(available)` (`:631`) 이므로 **액션이 하나라도 있는 행 = 사실상 모든 일반 메시지**에서 선택이 꺼진다. 액션 시트에도 복사 항목이 없다 — `MessageActionSheet.tsx` 의 컨트롤은 반응/다른 반응/답글/고치기/지우기 5개뿐(`:110,:140,:148,:176,:232`).

- **알려진 막힘(수리 견적에 반영할 것)**: 코드 주석(`:851-858`)이 이유를 자인한다 — iOS 텍스트 선택 자체가 롱프레스라 액션 시트와 제스처가 충돌하고, *"A 복사 action needs a clipboard native module; RN's own is deprecated"*. 즉 이건 실수가 아니라 **미해결 의존성**이다. 수리에는 클립보드 네이티브 모듈 도입이 선행한다.

| **U4-c · 시간과 경계를 되돌려준다** | 연속 행 hover/상시 타임스탬프, 날짜 구분선 오늘/어제, 그룹 내 분절(패딩·가터), 구분선 스타일 양 클라 통일 | H-3, H-4, H-7, M-2, L-3, L-4 | **중** | `relativeLabel` 이 이미 있다. 대부분 렌더 순서·간격 작업 |
| **U4-d · 행 꼬리와 위계 정리** | 꼬리를 칩 위로 되돌림, 아바타 격상(크기·모양·`avatarUrl` 경로 개통·폰 신설), 작성자 줄 감량 | H-6, H-11, M-3 | **중** | H-6은 렌더 순서 한 줄. 아바타는 CSP·타입까지 건드려 별도 티켓 권장 |
| **U4-e · 긴 응답을 접는다** | 산문·코드펜스·에이전트 카드 값에 접기 예산 도입(`ArtifactCard` 의 기존 예산 패턴 재사용) | H-8 | **중** | 재사용할 선례가 같은 폴더에 있다(`EAGER_LINE_BUDGET`) |
| **U4-f · 컴포저 완성** | 초안 보존(양 클라) → 오프라인 비활성 → auto-grow 교체(`useAutoGrow` 재사용) → 첨부 | H-10, M-7 | **중~대** | 초안 보존·auto-grow는 소, 첨부는 서버 계약까지 가므로 분리 |
| **U4-g · 폰 승인 행동 복원** | 타임라인 승인 카드에 승인/거부 버튼(인박스 `ApprovalDecision` 재사용) | H-1 | **중** | 결정 로직은 이미 폰에 있다 — 배치만 옮기는 일 |
| **U4-h · 카피·브랜드 감사** | 에이전트 카드 영문 카피 한국어화, `momo`→`oort` 잔재 일소, `seq` 제거, 교육 배너 수명 정책 | H-2, H-5, H-12, M-15 | **소~중** | 문자열 작업. 리브랜딩 트랙과 묶는 편이 싸다 |
| **U4-i · 폰 위생 묶음** | 탭 타깃 44pt, 낙관적 에코 여백, 삭제 메시지 접기, 하드코딩 hex→토큰 | M-1, M-12, M-13, M-14 | **소** | 전부 스타일 수정. U2(라이트 모드)의 선행 작업이기도 하다 |
| **U4-j · 타임라인 항법** | 최신으로 점프 / 아래 새 메시지 배지 | M-9 | **소~중** | 웹은 `VirtuosoHandle` 이 이미 연결만 안 된 상태 |

**권고 순서**: `U4-a` → `U4-b` → `U4-h` → `U4-c` → `U4-d` → `U4-g` → `U4-e` → `U4-i` → `U4-f` → `U4-j`.

이유: ①폰이 결함의 무게중심이고 BL 3건이 전부 거기 있다. ②`U4-h`(카피·브랜드)는 싸면서 인상에 직결한다. ③`U4-i` 는 U2(모드 전환)의 토큰 정리와 선행 관계라 U2 앞에 두면 두 번 일하지 않는다.

### 배치 밖으로 빼야 할 것

- **M-11(폰 라이트 모드)** 은 U2의 본체다. 여기서는 채팅 표면 증거로만 남긴다.
- **L-7(타이핑 인디케이터)** 은 의도된 부재일 수 있다 — 고치기 전에 결정이 필요하다.

### M-10이 §3(원격 클라우드 연동 UX)로 넘어가는 이유

축 문서 §3은 *"연결 상태의 헬스 표면(마지막 성공 호출·실패 사유 — '실패 카드가 첫 신호'인 현 상태 탈피)"* 를 이미 요구하고 있다. M-10은 그 요구의 **채팅 표면 판 증거**다: 실시간 레일이 거절당했는데 UI가 가진 어휘가 `연결 중…` 하나뿐이라, 실패가 대기로 위장된다. 따라서 U4-k로 따로 끊기보다 **U3(AI 연결 UX)의 연결 헬스 표면에 "실시간 레일" 축을 하나 더하는 편이 옳다** — 같은 결함의 두 얼굴이기 때문이다.

부수로, **로컬 QA 스택(`momowebqa`)의 centrifugo `allowed_origins` 에 RN 앱 origin이 없다**는 사실 자체는 인프라 티켓감이다. 지금 상태로는 **폰의 실시간 경로가 이 스택에서 한 번도 검증된 적이 없다** — MAESTRO 레인이 초록이어도 그렇다.
