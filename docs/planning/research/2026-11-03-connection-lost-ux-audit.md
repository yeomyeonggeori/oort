## 0. 요약

1. **#786은 이미 사실이 아니다.** 한 번 붙었던 소켓이 끊기면 2026-07-26(MOMO-613, `fa0f80e97`)부터 곧바로 `disconnected`로 보고된다 [V]. 이슈는 열려 있고, 이 전이를 고정하는 시험은 없다.
2. **그 수리에는 유예가 없다.** 웹은 소켓이 1초만 흔들려도 막대가 붉어지고 컴포저·승인·폼(38개 파일)이 잠긴다. 위쪽 띠만 15초를 기다린다. 폰은 첫 1초 침묵, 10초 유예이고 보내기·승인은 기기 오프라인일 때만 막는다. 한 제품에 규칙이 둘이다.
3. **#4783은 수리가 착륙했고 재발 여부는 재지 못했다.** 토큰 선갱신, 복귀 때 재연결, 10초·1초 표시가 들어갔다. 수리 전·후 실기기 수치는 PR에도 이슈에도 없다. 웹·데스크탑에는 같은 복귀 장치가 없다.
4. **#4328은 끝났다.** 복구 표지 판정이 코어에 있고 웹·폰이 같이 쓴다.
5. **서버 REST만 죽는 장애에는 전역 신호가 없다.** 배포 중 api가 9초 내려가면(이슈 #4783 진단) 소켓은 살아 있어 어디에도 안 뜨고, 사용자는 화면마다 다른 실패 문장을 만난다.
6. **실패 문장이 원인을 말하지 못하거나 잘못 말한다.** 웹 불러오기는 이유 없이 「불러오지 못했습니다」, 업로드 502·503은 「파일 보관소가 연결돼 있지 않습니다」, 설정류 22곳은 서버 원문을 그대로 낸다.
7. **웹 콜드 스타트(서버에 못 닿음)와 로그인 만료는 말없이 로그인 화면으로 간다.** 폰은 둘 다 문장이 있다.
8. **시안:** 코어에 연결 상태 모델 하나(문턱·원인·게이트·문구 키), 데스크탑은 사이드바 아래 연결 카드(Buzz 방식), 폰은 지금의 띠를 유지·확장, 원인은 닫힌 분류로 말하고 코드는 말하지 않는다.
9. **슬라이스 5개**(코어 1, 웹·데스크탑 2, 폰 1, 엔진 확인 1). owner가 고를 것 5개(§1).
10. **재지 못한 것:** 현재 화면 캡처, 데스크탑 절전 복귀 시간, 폰 복귀 재연결 수치(§9).

### 2.4 다시 붙었을 때 복구 (#4328 포함)

- **복구되는 것.** 타임라인: 재구독이 복구되면 되쏜 줄을 받고, 아니면 REST `?after` 꼬리를 읽는다(웹 `useTimeline.ts:739-757`, 폰은 같은 규칙). 표지는 「남의 새 줄을 들였을 때만」 선다(`recoveryMarker.ts:84`). 인박스·예약·표현 목록은 `onSubscribed` 때 `onResync`로 다시 읽는다(`realtime.ts:616, 644, 683`). 내 낙관 행은 확정 줄이 오면 정착한다(`unsettledPending`).
- **복구되지 않는 것.** 실패한 전송(수동 「다시 보내기」), 실패한 업로드, `error` 상태 타임라인(수동 다시 시도). 웹 REST 쿼리는 창 포커스 때 다시 읽지 않고(`queryClient.ts:5`) 재연결 때만 react-query 기본 동작에 맡긴다.

## 3. Buzz 대응표

|---|---|---|---|
| 사이드바 아래 카드: 상태 한 줄 + 보조 한 줄 + 아이콘, 눌러서 다시 연결 | 레일 12×4 막대(글 없음) + 위쪽 띠 | **따라 한다** (정상일 때는 카드가 없다) | 상태와 행동이 한 자리에 있고 채널 머리를 밀지 않는다 |

## 4. 신호 원칙: 언제 보이고 언제 숨기나

1. **건강은 침묵이다.** 연결돼 있으면 아무것도 그리지 않는다(막대의 기존 원칙, `connStatusIndicator.ts:35-40`).
2. **사실의 확정도에 맞춰 기다린다.** 기기 오프라인은 OS가 확정한 사실이라 즉시. 소켓 틈은 1초 미만 침묵, 1~10초 「연결 중…」(로더만, 단추 없음), 10초부터 「끊김」. 끝난 소켓(재시도 안 함)은 즉시 끊김. 복구는 5초 유지돼야 풀린다(`HEALED_MS`, 깜빡이는 소켓이 문턱을 영영 못 넘는 일을 막는 현 규칙 승계).
3. **지속 신호는 한 곳, 실패한 곳은 행동과 짧은 이유.** 원인 문장을 곳곳에서 되풀이하지 않는다.
4. **막는 기준은 「이 요청이 나갈 수 있는가」이다.** 기기 오프라인이거나 서버에 닿지 못함이 **확정**일 때만 보내기·올리기·승인을 막는다. 실시간만 끊기면 막지 않는다. 막을 때도 입력은 열어 두고 초안을 지킨다. 모르면 막지 않는다.
5. **원인은 닫힌 분류로 말하고 코드는 말하지 않는다.** 기기 오프라인 / 서버에 닿지 못함 / (서버가 알리면) 서버 업데이트 중 / 실시간만 끊김 / 알 수 없음. 알 수 없음은 안전 문장 + 「연결 기록 복사」(지원용 코드는 복사본에만).
6. **받아 둔 것은 남긴다.** 이미 받은 글·목록을 지우지 않고, 오래된 화면은 「마지막 동기화 N분 전」을 말한다.
7. **복구는 조용하다.** 「끊김」이 보였던 경우에만 2초 「다시 연결됐어요」, 아니면 사라질 뿐이다. 놓친 글은 지금처럼 메운다(복구 표지 규칙 유지).
8. **세 클라이언트가 한 모델을 쓴다.** 문턱·분류·게이트·문구 키는 코어에 한 벌.

**「서버에 닿지 못함」의 판정.** 소켓 상태로는 알 수 없다. 코어 `http.ts`가 모든 REST 결과를 관찰해(가산 변경) 「서로 다른 요청 3건이 연속으로 `NetworkError`·502·504·`error.code` 없는 503이고 그 뒤 성공이 없음」이면 선언하고, 성공 1건으로 푼다. 한 건으로 판정하지 않는 이유: 정상 운영에서도 503을 내는 길이 있다(허들 미구성 인스턴스의 `…/huddles/active`, 이슈 #4783 진단 48시간 11건). 「지금 다시 연결」은 실시간 토큰 발급(REST)을 거치므로 별도 상태 확인 경로 없이 이 관찰기에 결과를 준다.

### 7.2 7개 언어 장부 규칙 메모 (ADR-0213)

- **언어와 단계.** 일곱 언어는 ko-KR·en-US·ja-JP·zh-Hans·zh-Hant·es-419·fr-FR. 출시된 키는 **ko·en 둘 다 필수**(CI가 막는다)이고 나머지 다섯은 P2의 번역 생산 순서를 따른다: LLM 초안 → 용어·변수·ICU 자동 검사 → 원어민 문맥 검수 → 화면 검수(manifest의 `draft / llm-draft / reviewed`). 지금 `catalogs/`에는 `ko-KR`·`en-US`만 있다.
- **키와 인자.** `feature.surface.intent`(여기서는 `connection.*`). 한국어·문장 자체를 키로 쓰지 않는다. 문장 조각 이어붙이기·번역문 재보간 금지 — 원인별로 **완결된 문장 틀**을 따로 둔다(오프라인용·서버용 두 문장). ICU `select`로 문장 일부만 바꾸지 않는다. 시간은 로케일 서비스(`formatRelativeTime`)를 거친 값으로, 개수는 `{count, plural, …}`로 넣는다(영어 one/other, 프랑스어·스페인어 many 고려).
- **서버 원문 금지.** 마지막 폴백 단계에서도 키 문자열·서버 원문·내부 오류를 사용자에게 보이지 않는다(§4). 알 수 없는 원인은 선택 언어의 안전 문장 + 「연결 기록 복사」.
- **직접 문구 장부.** 새 화면·새 문구는 키로만 넣는다. 웹·폰 장부(`direct-copy-baseline.json`)에는 `ConnectionBanner.tsx`(14), 폰 `ConversationHeader.tsx`(36), `authGate.ts`(7) 등이 기존 직접 문구로 잡혀 있어 이관 슬라이스에서 키로 옮기며 **수를 줄이고 늘리지 않는다**. 코어 문구(`connectionAlert.ts`, `composerCopy.ts`, `approvalNote.ts`, `http.ts`의 `NetworkError` 문구)는 장부 표면(웹·폰) 밖이라 같이 키로 옮긴다. `NetworkError.message`가 한국어를 직접 든 것(`http.ts:56-61`)은 종류(`failure`)만 들고 화면이 키를 고르는 모양으로 바꾼다.
- **길이.** 의사 로케일(+35%)에서 카드 제목이 잘리지 않아야 한다. 카드 제목은 2줄까지 허용하고 단추 이름은 짧게 둔다. 영어는 sentence case.
- **확인 명령.** `node packages/momo-core/src/i18n/tooling/direct-copy.mjs web`·`… mobile`, `npm --prefix packages/momo-core run i18n:generate`·`i18n:check`.

## 9. 부록

### 9.1 실행 증거 [V]

`createRealtime`의 상태 전이를 가짜 `centrifuge`로 돌린 임시 시험 2건(`clients/web`에서 `vitest run`, 파일은 실행 뒤 지웠고 커밋하지 않았다):

1. 첫 `connected` 전에 `connecting`을 세 번 보내면 보고도 `connecting` 세 번 → **PASS**.
2. `connecting` → `connected` → `connecting` → `connected`를 보내면 보고는 `connecting`, `connected`, **`disconnected`**, `connected` → **PASS**.

결과: 1 file, 2 tests passed. 이 시험은 현재 동작을 보이기 위한 것이고 가드가 아니다(사보타주 대상 아님).

### 9.2 재지 못한 것 (`runtime-unverified`)

- 현재 웹·데스크탑 화면 캡처(모의 `/v1`·끊긴 실시간). 시안은 코드에서 지은 ASCII다.
- 데스크탑 절전 복귀 뒤 「연결됨」이 유지되는 시간(35초는 폰 코드 주석의 값이다).
- 폰 #4783의 복귀 재연결 시간·시도 횟수의 수리 후 값(기기 안 기록에만 있다).
- 웹 컴포저가 소켓 1초 흔들림에서 실제로 잠기는 화면: 코드(`Composer.tsx:584-587`, `useOffline.ts:18-20`)와 [V]의 매핑 시험으로 이어 읽은 결론이고, 합친 화면은 돌려 보지 않았다.
- 서버가 점검·재시작 중 `Retry-After`나 구분 코드를 주는지, 엣지가 api 교체 중 돌려주는 응답의 모양.
- 폰의 채널 머리 이름 폴백. 폰 홈에 오프라인 표시가 없다는 판단은 `SidebarScreen.tsx`에서 오프라인·온라인 참조가 없음을 읽은 것이다 [소스].
