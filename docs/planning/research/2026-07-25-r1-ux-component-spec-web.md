# R-1 컴포넌트 UX 스펙, momo-web (React) 5장 (2026-07-25, Fable)

> 파생: ADR-0133(SwiftUI → TS/React + Tauri) Accepted. 목표: "buzz와 거의 동일한 UXUI 체감"을 momo-web으로 구현하되, momo 구조 우위(seq 결정론·승인 원장·RLS FORCE)를 화면에 표면화한다.
> 스택 정본(ADR-0133 §Decision.3): Tailwind + shadcn/ui(Radix) + react-virtuoso(타임라인 가상화) + cmdk(Cmd+K) + Tauri 2 셸. Next.js 배제(SPA/Vite).
> 실측 제약: 현행 `clients/web` v0는 CSP `style-src 'self'`(인라인 스타일·style 속성 금지, 모든 스타일은 컴파일된 시트로). 토큰/모델 어휘는 실제 코드에서 인용(`TimelineMessage.seq`, `reconcileMessages`, `ApprovalStatus`, `approval_request` props).
> 팔레트: R-2 스킬의 여명(Dawn) 토큰을 정본으로 참조. 현행 v0의 인디고 액센트(`#4f46e5`)는 잠정값이며 R-2에서 호박색으로 교체 대상(AI-tell 회피, §각 장 차별점).
> 규칙 준수: em-dash 0. 추측과 실측 구분(실측=코드/ADR 근거, 제안=UX 판단). P1~P15는 `docs/ux-bible/README.md` 인용.

## 공통 계약 (5장 전체에 적용)

**상태 4종 의무(모든 surface)**: 빈(empty) / 로딩(loading) / 오류(error) / 오프라인(offline). 빈 상태는 "포스터"가 아니라 행동 1개를 담은 초대(카피 1줄 + 액션 1개). 오프라인은 WS 끊김을 별도 배너로(아래 재연결 계약).

**재연결/seq 계약(실측 근거)**: `TimelineMessage.seq`가 전역 단조. 재구독은 시각 스큐가 아니라 **마지막 확인 seq**로(`reconcileMessages`가 seq 기준 정렬·머지, `mergeMessages`는 append 별칭). buzz의 `since-5s` 시계 스큐 세금을 원천 제거, 이것이 화면에 나타나는 momo 우위의 뿌리다.

**키보드 우선(P11)**: Cmd+K 퀵스위처(cmdk), 채널/스레드/멤버 전역 이동. 방향키 순회. 행 단위 액션은 항상-보이는 버튼줄이 아니라 컨텍스트 메뉴(Radix ContextMenu)로.

**AI-tell 금지(공통)**: 인디고/보라 그라데이션 히어로, 토스트 스택, 리스트 행마다 과대 라운드 카드, 중앙 일러스트 빈상태, 이모지 기능 아이콘. 상세는 R-2 §Web AI-Tells.

**에이전트 발화 프레임(공통, buzz §7-2 소화)**: 에이전트 활동은 "the agent did {verb} to {object} → {outcome}" 문장으로. 사람 메시지와 **같은 그리드·같은 타이포**, 정체성은 `--agent-accent` 토큰(아바타/배지)에만. 버블 모양·행 배경 tint로 사람/에이전트를 가르지 않는다.

## 1장. 사이드바 (워크스페이스 / 채널 / DM / pill · 설정 진입)

### 목적과 IA
buzz IA 소화(§7): Slack 기본기(채널/DM/스레드/⌘K) 위에 **글로벌 표면을 채널보다 위**에 얹는다. momo v0은 과잉을 피해 글로벌 표면을 2개로 축소: **인박스(2장)**, **활동(에이전트 활동 피드)**. Pulse/Projects/Workflows는 예약(비스코프).

### 레이아웃 스케치 (density 6~7)
```
┌───────────┬────────────────────────────────────────────────┐
│ ◱ Dawn Co │  (rail: 워크스페이스 스위처, 세로 40px 폭)       │
│ ◱ 알파팀  │                                                 │
│ ⊕         │  ┌──────────────┐                               │
├───────────┤  │ 채널 사이드바 │  (240~280px, 리사이즈 가능)   │
│           │  ├──────────────┤                               │
│  [검색 ⌘K]│  │ ⌂ 인박스   3 │  ← 글로벌 표면(2장)            │
│           │  │ ⚡ 활동       │  ← 에이전트 활동 피드          │
│           │  ├──────────────┤                               │
│           │  │ 채널          ⌄│                              │

│  ┌──────┐ │                                                 │

### 핵심 요소
- **워크스페이스 rail**(좌 40px): 멤버인 워크스페이스 아이콘 세로 스택 + 하단 `⊕`(워크스페이스 생성/참여, 5장 연결). ADR-0117 멀티워크스페이스. 현재 워크스페이스는 좌측 액센트 바(2px)로 표시(배경 tint 아님).
- **채널행**: `#이름` + unread 신호. **unread = P7 서버 단일 진실**. 미읽음 카운트는 `.monospacedDigit()` 등가(CSS `font-variant-numeric: tabular-nums`), 멘션 있으면 pill(액센트 배경). "읽음만" 채널은 dot 없음.
- **에이전트 working 배지(buzz §7-1 최우선)**: 채널행/DM행에 에이전트가 턴 중이면 `◐` + 경과시간(예 `3m`). 단일 `agentWorkingSignal` 모듈 소비(관측 이벤트 1차, typing 폴백), 사이드바·컴포저·타임라인이 같은 소스. typing과 시각적으로 구분(색·글리프 다르게).
- **presence dot**: ADR-0104 "보이는 유저만 구독"(P14). 실상태 없으면 dot 없음(장식 dot 금지 = AI-tell).
- **설정 진입**: 하단 나 아바타 + 톱니(⌘,). Tauri에서 `Settings` 유사 별창 아님, 웹은 라우트 `/settings`(모달 아닌 전체 화면 셸, 5장).

### 상태
- **빈**: 채널 0개면 "첫 채널을 만들어 팀을 시작하세요" + `[채널 만들기]` 1개(포스터 금지). DM 0개면 섹션 자체를 접음.
- **로딩**: 채널 리스트 skeleton은 행 높이 유지한 회색 바 3~5줄(shimmer 금지, R-2). 부트는 P6, 활성 채널만 먼저, 나머지 lazy backfill.
- **오류**: 채널 fetch 실패 시 사이드바 상단 인라인 배너("채널을 불러오지 못했습니다" + `[다시 시도]`). 토스트 금지.
- **오프라인**: WS 끊김 시 워크스페이스 rail 하단에 점(●→◌) + 툴팁("연결 끊김, 재연결 중"). 사이드바 자체는 캐시로 계속 렌더(P6/P15 내구층).

### 키보드 경로
- `⌘K` 퀵스위처(cmdk): 채널/DM/멤버/설정 전역 점프. `⌘⇧K` DM 새로.
- `⌥↑/⌥↓` unread 채널 순회(P11, Slack 문법). `⌘1..9` 워크스페이스 rail 전환.
- `⌘.` 설정. 사이드바 포커스 시 `↑/↓` 행 이동, `Enter` 열기.

### buzz 대비 차별점 (momo 우위 표면화)
- buzz는 read state가 클라 로컬+replaceable 이벤트 동기화라 멀티디바이스 unread가 구조적으로 약함. momo 사이드바 unread는 **서버 단일 진실(P7/ADR-0109)**, 기기를 바꿔도 카운트가 일치. 이 일관성 자체가 조용한 우위(광고할 필요 없이 "그냥 맞다").
- 에이전트 working 배지는 buzz도 하지만, momo는 관측 이벤트(관측 surface ADR-0126)에서 파생, typing 위조가 아니라 실제 턴 liveness.

### shadcn/Radix 컴포넌트 매핑
| 요소 | 컴포넌트 |
|---|---|
| 워크스페이스 스위처 | `DropdownMenu` + 커스텀 rail(정당화: 세로 아이콘 스택은 시스템 없음) |
| 채널/DM 리스트 | 순수 `<nav><ul>` + `data-*` 상태(과대 카드 금지, 플랫 행 + hover 배경) |
| unread pill | shadcn `Badge` variant=`secondary`/`accent` |
| 검색 진입 | `cmdk` `Command` + `Dialog`(Cmd+K) |
| 리사이즈 | `react-resizable-panels`(shadcn `Resizable`) |
| 행 컨텍스트 액션 | `ContextMenu`(음소거·나가기·읽음 표시) |
| presence/working dot | 커스텀 `<span>` + 토큰 색(상태 바인딩된 것만) |

## 2장. 통합 인박스 · 알림 (buzz zero-noise 소화)

### 철학 (buzz + P8/P9)
buzz: **"Zero is the default. You opt in to noise, not out."** 알림 기본 0 + 통합 Inbox가 보상. momo는 P8("보내지 않을 이유가 기본값") + 에이전트가 알림을 만들 수 있어 **Slack보다 더 엄격**해야 함. 인박스는 그 급진적 축소의 안전망: 조용해도 놓치지 않는다.

### 레이아웃 스케치
```
┌────────────────────────────────────────────────────────────┐
│  인박스                        [Needs Action] [멘션] [에이전트]│  ← 필터 탭(Segmented)
│  ────────────────────────────────────────────────────────  │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ ⚠ 승인 대기 · @hermes → #엔진            2분 전        │  │  ← Needs Action 최상단
│  │   "rm -rf build/ 를 실행하려 합니다 → 승인 필요"        │  │     verb/object/outcome
│  │   [검토]  [승인]  [거절]                                │  │  ← 인라인 액션(원장)
│  ├──────────────────────────────────────────────────────┤  │
│  │ @ 성재님이 #general 에서 회원님을 멘션           1시간  │  │  ← 멘션
│  │   "이거 김인턴한테 시켜볼까요?"                          │  │
│  ├──────────────────────────────────────────────────────┤  │
│  │ ✓ @hermes 가 #엔진 작업 완료 → PR #565 머지     3시간  │  │  ← 에이전트 outcome
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  (하단) 모두 읽음 처리   ·   설정: 알림 규칙 →              │
└────────────────────────────────────────────────────────────┘
```

### 핵심 요소
- **3필터**(buzz Needs Action/Agents 소화): `Needs Action`(승인·나에게 배정된 것) / `멘션`(@나·@here) / `에이전트`(내가 owner인 에이전트의 outcome). 기본 탭 = Needs Action(행동 유발 우선).
- **행 = verb/object/outcome 문장**(buzz §7-2): "{누가} {동사} {대상} → {결과}". 승인 행은 인라인 `[승인]/[거절]`으로 컨텍스트 전환 없이 원장에 기록.
- **알림 규칙은 서버 단 하나(P9)**: 6-노드급 결정 트리, 플랫폼별 재구현 금지. 인박스 하단 "알림 규칙" 링크 → 5장 설정.
- **관측 가능성 내장(P10)**: 각 알림 행에 "왜 왔는지"를 호버 툴팁(멘션/승인/규칙 매칭). buzz도 안 하는 것, trigger→sent→opened 트레이스의 사용자 표면.

### 상태
- **빈(핵심)**: "받은 알림이 없어요. 조용한 게 정상입니다." + 부제 "중요한 건 여기 모입니다", **조용함을 실패가 아니라 설계로 프레임**(zero-noise 철학의 카피화). 액션 없음(빈 인박스는 좋은 상태).
- **로딩**: 행 skeleton 3줄.
- **오류**: 인라인 배너 + 재시도.
- **오프라인**: 상단 "오프라인, 마지막 동기화 {상대시간}" 배너. 캐시된 인박스는 계속 표시, dim 처리 없이(P15 내구층).

### 키보드 경로
- `⌘⇧A` 인박스 열기. `↑/↓` 행 이동, `E` 읽음/보관, `Enter` 원본으로 점프.
- 승인 행 포커스 시 `Y` 승인 / `N` 거절(확인 다이얼로그 경유, 파괴적 액션은 즉발 금지, R-2).

### buzz 대비 차별점
- **승인이 암호학 체인 위의 원장**(buzz §5-6 소화 + momo 우위): 인박스 승인은 토큰 해시 저장·단일 사용 UPDATE·서명 이벤트로 남는 **"누가 언제 yes 했는가"**. buzz는 승인 UI는 있으나 executor suspend 미영속으로 반쪽 배포한 전례, momo는 거버넌스로 반쪽 금지(ADR-0132 안전 계약).
- **멀티 에이전트 권한 질문에 대한 표면 답**(커뮤니티 최대 미해결, §4-③): 에이전트 outcome 행에 owner("managed by 성재") 표기 → 책임 소재가 알림 단계에서 이미 보인다.

### shadcn/Radix 매핑
| 요소 | 컴포넌트 |
|---|---|
| 필터 탭 | `Tabs`(또는 `ToggleGroup` segmented) |
| 알림 행 | 플랫 리스트 행(카드 아님) + 좌측 상태 아이콘(SF 대체: lucide 아이콘 1 모드/weight) |
| 인라인 승인 | `Button` variant primary/outline + 확인 `AlertDialog` |
| "왜 왔는지" | `Tooltip`(Radix) |
| 보관/읽음 | `ContextMenu` + 키보드 |

## 3장. 타임라인 (메시지 그리드 · 스레드 · 가상화 계약 · seq/재연결 상태)

### 목적
채널/DM의 메시지 흐름. momo 타임라인의 제1 리스크는 buzz §6-(b)가 경고한 "역방향 무한 스크롤 + 실시간 append + 스레드 오버레이 = 수십 커밋 늪". 계약을 스펙에 못박아 진입한다.

### 레이아웃 스케치
```
┌────────────────────────────────────────────────────────────┐
│  # 엔진   🔒     성재, @hermes, 김인턴 외 3     [스레드] [ℹ]  │  ← 채널 헤더
│  ──────────────────────────────────────────────────────────│
│         ┌─ 새 메시지 3개 · 여기까지 읽음 ─────────────────┐  │  ← unread divider(P7)
│                                                             │
│  ◑ 성재                                    14:02            │  ← author group 시작
│    prometheus mem_limit 붙였어요                             │     (5분 window 실측)
│    이거 확인 좀 부탁                                          │  ← 같은 author 연속(헤더 생략)
│                                                             │
│  ◆ @hermes  · managed by 성재              14:03            │  ← 에이전트: 같은 그리드
│    확인했습니다. 아래를 실행하려 합니다 →                      │     정체성=◆ 액센트만
│    ┌──[ 에이전트 카드: 4장 ]──────────────────────────┐     │
│    │ ⚡ shell · rm -rf build/        [awaiting-approval]│    │  ← 상태 칩

│                                                             │
│  ─────────── 재연결됨 · seq 1420까지 복구 ───────────────    │  ← 재연결 마커(momo 우위)
│                                                             │
│  ◑ 성재                                    14:07            │
│    좋아요 승인할게요                                          │
│  ──────────────────────────────────────────────────────────│
│  ┌────────────────────────────────────────────────────┐    │
│  │ 메시지 입력…  (@멘션 자동완성)              [보내기] │    │  ← 컴포저
│  │ ◐ 김인턴이 로그를 읽는 중…                            │    │  ← working 회전 바(buzz §7-1)
│  └────────────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────┘
```

### 가상화 계약 (react-virtuoso, 실측 모델 기반)
- **정렬·머지는 seq 단조**: `reconcileMessages(existing, incoming)`가 `Map<seq>` 병합 후 seq 오름차순. 라이브 append는 `mergeMessages` 별칭. 화면 로직은 인덱스가 아니라 seq를 키로.
- **불변 페이지 + 라이브 오버레이 분리(buzz NIP-CW 소화, §5-1)**: 과거 페이지는 불변 이력, 라이브 이벤트는 별도 구독 렌더타임 머지. **재연결 시 마지막 확인 seq로 재요청**(page 0 재요청 아님, momo는 seq가 있어 buzz보다 단순·강함).
- **author grouping**: `startsAuthorGroup`, 작성자 변경 OR 5분(`AUTHOR_GROUP_WINDOW_MS = 300_000`) 초과 OR 날짜 경계면 헤더 표시. 연속이면 헤더 생략(밀도 확보, Slack 관례).
- **reactions/edit/delete/thread-summary는 2-hop closure로 페이지에 동봉**(1왕복, buzz §5-1). 카운트·리스트·타임라인을 **전부 같은 seq 스트림에서 파생**(buzz §6-b "하나의 사실이 세 갈래로 오는" 버그의 근원 회피, "카운터는 서버가 따로 재계산해 쏜다"는 최적화 금지).
- **역방향 무한 스크롤**: virtuoso `startReached` → 이전 seq 범위 fetch. `firstItemIndex` 조정으로 스크롤 점프 없이 prepend.

### 상태
- **빈 채널**: "이 채널을 함께 시작하세요" + [사람 추가] · [에이전트 추가] **동급 버튼**(buzz §7-4, 온보딩 감사 §2). 빈 채널 인트로에서 첫 멘션까지 4클릭 예산(MOMO-570).
- **로딩(초기)**: 메시지 skeleton(행 높이 유지 회색 바). "쓰기 직후 읽기가 인덱싱 앞지름" 윈도우(buzz §6-b)는 낙관 삽입으로, 내 메시지는 seq 미확정이어도 로컬 echo(전송중 표시), 서버 seq 도착 시 reconcile.
- **오류**: 페이지 fetch 실패 → 해당 지점 인라인 "이 구간을 불러오지 못했습니다 [다시]"(전체 화면 오류 아님).
- **오프라인**: 헤더 아래 얇은 배너 "연결 끊김 · 재연결 중". 재연결 성공 시 **"재연결됨 · seq N까지 복구" 마커**(buzz의 부트 리커버리 원장 §6-a 소화, 복구 이벤트를 새 것처럼 응답하지 않도록 사용자에게도 명시). 이 마커는 momo만 가능(seq 덕).
- **컴포저 전송 실패**: 메시지 옆 인라인 "전송 실패 [재시도]"(rate-limit-aware, buzz §6-c). 큐 캡 초과 시 가시적 드롭 표시.

### 키보드 경로
- `↑`(빈 컴포저에서) 마지막 내 메시지 편집. `Esc` 편집 취소.
- `⌘↵` 전송(줄바꿈은 `↵`). `@` 멘션 자동완성(방향키+Enter). `⌘F` 채널 내 검색.
- 메시지 포커스: `R` 답글(스레드), `E` 편집(내 것), `⌫`+확인 삭제, `+` 리액션 피커.
- `Shift+Esc` 미읽음 divider로 점프. `⌥⌘↑/↓` 스레드 간 이동.

### buzz 대비 차별점 (momo 우위 표면화)
- **재연결 결정론**: buzz는 서명이 `created_at`을 덮어 서버 seq 발급 불가 → 복합 커서·커밋타임 fence·CLI `sleep 1` 보정이 겹겹. momo는 `message.seq` 하나로 "seq N까지 복구" 마커를 **정확히** 그린다. 사용자는 "뭘 놓쳤나"를 다시 묻지 않는다.
- **전달 보장 가시화**: buzz outbox 없음(fire-and-forget). momo REST→PG→outbox→relay는 전송중/전달됨/실패를 정직하게 표시할 근거가 있다.
- **스레드**: P12, 채널 밖 답글 + All Threads 뷰. buzz 무한중첩은 "에이전트 간 장시간 협업엔 승리, 사람에겐 고통"(§4). momo는 사람 가독성 우선(메인 뷰 가독성이 제1제약, P12) + 에이전트 작업 스레드는 종결 시 아카이브(§7-5 축소 이식).

## 4장. 에이전트 카드 (상태 칩 수명주기 · 승인 · 비용 mono · verb/object/outcome)

### 목적
타임라인 안에 인라인으로 나타나는 에이전트 작업의 구조화 표현. mac 스킬 §4의 웹 이식: "structured, calm, dense". 카드는 사람 메시지와 같은 그리드 안에, 에이전트 발화의 **본문**으로 존재(별도 부유 카드 아님).

### 레이아웃 스케치 (도구 실행 / 승인 / 비용)
```
◆ @hermes · managed by 성재                          14:03
  로그를 확인하고 빌드 캐시를 정리하려 합니다 →

  ┌──────────────────────────────────────────────────────┐
  │ ⚡ shell 실행                        [awaiting-approval]│  ← 타이틀행: 아이콘+이름+상태칩
  │ ──────────────────────────────────────────────────── │
  │ 명령      rm -rf build/                                │  ← 타입드 key-value(LabeledContent 등가)
  │ 작업 위치  ~/projects/momo (worktree: 565)             │
  │ 영향      빌드 산출물 삭제 · 되돌릴 수 없음             │  ← outcome 정직 고지
  │                                                        │
  │ ▸ 원본 payload 보기                                    │  ← disclosure(raw는 접힘)
  │ ──────────────────────────────────────────────────── │
  │ 이 작업은 승인이 필요합니다.        [검토] [승인] [거절]│  ← 원장 액션
  └──────────────────────────────────────────────────────┘

  (완료 후 같은 카드가 상태 전이)
  ┌──────────────────────────────────────────────────────┐
  │ ⚡ shell 실행                                    [done] │
  │ 결과      3개 디렉터리 삭제 → 빌드 캐시 정리 완료       │  ← verb/object/outcome
  │ 소요      2.4s   ·   토큰  1,240 in / 380 out          │  ← 비용: monospace, 우측정렬
  │ 비용      $0.012                                       │
  │ 승인      성재 · 14:04 (원장 #a1b2)                    │  ← 누가 언제 승인(감사 연결)
  └──────────────────────────────────────────────────────┘
```

### 상태 칩 수명주기 (mac 스킬 §4 + 실측 ApprovalStatus)
- **에이전트 턴 칩**: `queued` → `thinking` → `streaming` → (`awaiting-approval`) → `done` / `error`. 텍스트 우선, 펄스 애니메이션 금지(R-2). 색은 토큰 상태색만.
- **승인 상태**(실측 `ApprovalStatus`): `pending` / `approved` / `rejected` / `expired` / `cancelled`. 실측 `approvalCardModel`은 basic-mode 공개 필드만 파싱(도구 인자·경로·자격증명·비용 상세는 opaque), **UI는 서버가 준 공개 필드만 렌더**, 민감 payload는 disclosure 뒤에도 노출 금지 계약 준수.
- **재개 제안**(실측 `isResumeOffer`, props `kind: resume_offer`): 중단된 작업 재개 카드는 별도 표현("이어서 진행할까요? [재개] [중단]").

### 비용/수치 규율 (mac 스킬 §4 이식)
- 토큰/비용/소요/seq는 **monospace + 우측 정렬 + tabular-nums**. 데이터가 바뀌는 속도보다 빠르게 애니메이트 금지(카운트업 연출 금지). 스트리밍 텍스트는 caret, shimmer skeleton 아님.

### 소유자·수신 게이트 (buzz §7-3, 커뮤니티 최대 쟁점)
- 헤더에 "managed by {owner}"(owner 프로필 팝오버). agent_profile 원장에 owner 존재(ADR-0131) → UI 비용 최소.
- 생성 다이얼로그(5장)의 "누가 이 에이전트에게 말할 수 있나"(owner-only 기본/Anyone/Allowlist)가 카드 수신 게이트의 근거.

### 상태 (카드 자체)
- **빈**: 해당 없음(카드는 이벤트가 있을 때만 존재).
- **로딩/진행**: `thinking`/`streaming` 칩 + caret. 헤드라인은 컴포저 회전 바와 동일 소스(agentWorkingSignal).
- **오류**: `error` 칩 + "무엇이 실패했고 다음에 무엇을"(사과 금지, R-2). retryable이면 [재시도], actionable이면 [수정] 구분(buzz §6-a 실패 고지 원칙).
- **오프라인**: 카드 상태는 마지막 확인 seq 기준으로 고정 표시 + "연결 끊김, 최신 상태 아닐 수 있음" 상단 배너에 위임(카드 개별 오프라인 UI 없음).
- **타임아웃/침묵**: buzz §6-a "타이머가 사실을 이기면 거짓 서사" 반례, 무응답을 "실패"로 승격 금지. `error` 아닌 `stalled`(LLM 스톨/도구 실행/취소 드레인 하위 상태 구분)로 표시하고 백스톱만.

### 키보드 경로
- 카드 포커스: `Y` 승인 / `N` 거절(확인 경유), `Space` disclosure 토글, `Enter` 검토(상세 뷰/스레드), `⌘.` 에이전트 정지(킬스위치, buzz §6-a: 킬스위치는 실제 클라 표면 E2E로 도달 가능해야; 정확매칭 함정 금지).

### buzz 대비 차별점 (momo 우위 표면화)
- **승인 원장 = 감사 연결**: "성재 · 14:04 (원장 #a1b2)"가 해시체인 감사(buzz §5-7 소화)로 뒷받침. buzz는 executor suspend 미영속으로 승인 후 런 Failed 처리한 전례, momo는 거버넌스+ADR-0132로 반쪽 방지.
- **verb/object/outcome 강제**: 원 payload 덤프(buzz도 피하려 한 것)를 disclosure 뒤로, 전면은 "무엇을→무엇에→결과" 문장. mac 스킬 §4 "raw JSON 금지"의 웹 이식.
- **RLS FORCE가 뒷받침하는 데이터**: 카드가 보여주는 모든 필드는 RLS 통과분, "이 에이전트가 이 채널에서 볼 수 있는 것"이 DB 레벨에서 이미 집행(§4-③ 정보누출 질문에 대한 구조적 답).

### shadcn/Radix 매핑
| 요소 | 컴포넌트 |
|---|---|
| 카드 컨테이너 | shadcn `Card`(단, elevation=그룹핑 의미일 때만, 리스트 행마다 금지) |
| 상태 칩 | `Badge` variant per status(토큰 색) |
| key-value 행 | `<dl>` 또는 커스텀 `LabeledRow`(raw JSON 금지) |
| 원본 payload | `Collapsible`(Radix) disclosure |
| 승인/거절 | `Button` + `AlertDialog`(파괴적/승인 확인) |
| owner 팝오버 | `HoverCard`/`Popover` |
| 비용 수치 | `<span class="tabular-nums text-right font-mono">` |

## 5장. 설정 셸 (AI 연결 · 코드 실행 호스트 · 워크스페이스 생성 · 초대)

### 목적
운영자/오너 대상 구성 표면. 온보딩 감사 §2: AI 연결·코드 실행 호스트는 **관리자 전용 노출**(일반 사용자 온보딩 무오염). "패널 수는 죄"(Codex 앱 비판, 온보딩 감사 §1), 좌측 네비 + 우측 폼, 투어 없음.

### 레이아웃 스케치
```
┌────────────────────────────────────────────────────────────┐
│  설정                                                  [✕ ⌘,]│
│  ┌────────────┬──────────────────────────────────────────┐ │
│  │ 계정        │  AI 연결                                   │ │
│  │ 알림 규칙   │  ────────────────────────────────────────│ │

│  │ 코드 실행   │  ┌────────────────────────────────────┐   │ │
│  │ 워크스페이스│  │ Anthropic         [연결됨]  성재 · 어제│  │ │
│  │ 멤버·초대   │  │ 키는 이 기기/서버에만 저장됩니다        │  │ │  ← ADR-0004 비유입 고지

### 섹션별 계약
- **AI 연결(provider)**: provider별 연결 상태 + "키는 이 기기/서버에만 저장"(ADR-0004 비유입 고지 = 신뢰 카피). 키 입력은 마스킹, 저장 후 마지막 4자리만. buzz "LLM 키는 하네스 env에만"과 동형. Tauri에서 키는 OS keychain(ADR-0133 Rust 플러그인 경계).
- **코드 실행 호스트**(ADR-0125 work host + t3code 소화): 연결된 work host 목록 + 페어링. **Full Access / Supervised 이중 런타임**(t3code §4 명명 이식) 토글, 승인 경계(ADR-0114 D5)를 이 두 모드로 사용자에게 제시. 동봉 엔진(goose/opencode) + Codex 로컬 연결(ACP∪JSON-RPC, t3code §4-1) 표시.
- **워크스페이스 생성/참여**(ADR-0117): 생성 폼(이름·슬러그) + rail의 `⊕`에서 진입. 이름 변경은 경계(ADR-0118), 오너만.
- **멤버·초대**(온보딩 감사 W-O1/W-O5): 초대 링크 발급(`momo://join?server=…&code=…` 딥링크). 초대 카드 복붙 템플릿(다운로드 링크+서버주소+딥링크). 에이전트 초대는 별도 흐름(생성 다이얼로그 + owner + 수신 게이트).

### 에이전트 생성 다이얼로그 (ADR-0131 간편 생성 + buzz §7-3)
```
┌─ 에이전트 만들기 ──────────────────────────────┐
│ 이름     [ 김인턴                    ]          │
│ 역할     [ 코드 리뷰와 빌드 정리를 돕습니다  ]  │  ← 페르소나(자연어)
│ AI 연결  [ Anthropic · claude-…    ⌄]          │  ← 위 provider에서
│ 누가 말할 수 있나  ( ) 나만  (•) 팀 전체  ( ) 지정│  ← 수신 게이트(buzz §7-3)
│ 코드 실행  ( ) 없음  (•) Supervised  ( ) Full   │  ← 이중 런타임(t3code)
│                              [취소]  [만들기]    │
└────────────────────────────────────────────────┘
```
- buzz의 200+ 파일 관리 패널(EnvVars/Provider/MCP)은 "운영자=개발자" 제품이라 허용되는 복잡도, momo는 간편 생성 노선(§7 반면교사). 가져오는 것은 패널이 아니라 **페르소나 카탈로그**(구성=복제 가능 자산, export/import) 상위 추상(후속).

### 상태
- **빈**: provider 0개 → "에이전트가 쓸 AI를 연결하세요" + [연결하기]. work host 0개 → "코드를 실행할 호스트를 페어링하세요".
- **로딩**: 연결 검증 중 인라인 스피너(버튼 내부), 폼은 락.
- **오류**: 연결 실패 시 필드 아래 "무엇이 틀렸고 어떻게"(예 "키가 유효하지 않습니다. provider 콘솔에서 다시 발급하세요"). 사과·모호 금지.
- **오프라인**: 저장 불가 → 상단 배너 "오프라인, 변경은 재연결 후 저장됩니다", 저장 버튼 disabled + 이유 툴팁.

### 키보드 경로
- `⌘,` 설정 열기/닫기. `⌘W`/`Esc` 닫기. 좌측 네비 `↑/↓`, `Enter` 섹션 전환.
- 폼: `Tab` 순회, `⌘S` 저장, `⌘↵` 다이얼로그 기본 액션(만들기).

### buzz 대비 차별점
- **초대 딥링크 + mDNS 발견**(온보딩 감사 W-O1/W-O2): buzz는 디바이스 추가에 전용 사이드카 relay+SAS 페어링 필요(§3). momo는 서버 관리 identity라 초대 링크 1클릭이 가능, 팀 메신저 맥락에서 운영상 압도적 단순.
- **키 비유입 고지의 카피화**: buzz도 같은 신념이나, momo는 설정 화면에서 이를 명시 카피로 노출 → 신뢰가 기능(P2 "모든 디테일이 마케팅").
