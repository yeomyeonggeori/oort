# 에이전트-운영 셀프호스팅(AOP) — 그록봇이 핸드오프 하나로 oort를 띄우고 운영한다

- 날짜: 2026-08-22 · 작성: Fable(momo-main, PLN-20260815-01) · 상태: 계획 상신(발사=성재 승인 대기)
- 발제(성재): "내 로컬 그록봇이 핸드오프 문서/프롬프트 하나로 도커·경량 컨테이너로 띄우고, 호스팅해서 서버 주소·알림·웹훅까지 전 기능을 제공하고, 그록봇을 통해 업데이트·서버관리도 할 수 있는 형태."
- 선행 브리핑: 그록봇 VM co-host 디깅(2026-08-22 채팅 — 이 문서가 그 후속·구체화). 관련 원장: #1361(다이얼인)·#1613(충돌 가드)·v0.1.0 발행·#1643(multi-arch 준비).

## 1. 해석과 판정

발제의 실체는 **"에이전트가 oort의 오퍼레이터가 되는" 축**이다 — 설치자(provisioner)→호스트 운영자(operator)→관리 인터페이스(manager)의 3역을 에이전트가 맡는다. 판정: **agent-native 정체성("에이전트는 멤버다")의 자연 연장**이며, 런칭 정의("외부 셀프호스터 3명")의 첫 사례가 *사람이 아니라 에이전트*가 될 수 있는 차별화 서사다. 기존 자산 정합도가 매우 높아 신규 발명이 거의 없다 — 핵심 산출물은 **AOR(Agent Operator Runbook) 단일 문서**와 갭 수리 소수다.

## 4. 위험과 경계

- **시크릿**: G-E — 에이전트 오퍼레이터의 프롬프트/전사/보고에 시크릿 비유입을 AOR 하드 룰로. provider 키 주입은 v1에서 **사람 몫 유지**(에이전트는 절차 안내까지).
- **순환 관리(그록봇이 oort 안에서 자기 호스트의 oort를 관리)**: 매력적이지만 셀프 업데이트 중 자기 연결 단절 등 재진입 문제가 있다 — **v1 스코프 제외**, S4에서 읽기(상태 보고)부터.
- **모더레이션/공개 서버**: 이 축은 성재 소유 인스턴스라 ADR-0121 D6-A와 무충돌. "무료 공용" 전환은 별도 ADR(선행 브리핑 그대로).
- **LIVE(VM 화면 조작) 축은 스코프 밖** — cube-host 전용 어플라이언스 판정 기존재.

## 5. 단계 계획 (S1→S4, 각 단계가 독립 가치)

### S1 — 에이전트 설치 스파이크 (실측 먼저, 문서는 그다음)
grok 4.6 헤드리스(성재 로컬 그록봇과 동형)에게 **현행 SELF_HOST.md만** 주고 격리 환경(#1613 가드 하 프로젝트 분리)에서 설치→로그인 API 왕복까지 완주시킨다. 측정: 완주 여부·임기응변 횟수·막힌 지점 전수(=AOR 요구사항 목록)·M1~M3. **이것이 ITO-1의 에이전트 버전이자 이 축의 타당성 실측.**
AC: 완주 or 막힘 지점 전수 기록 · 실스택 잔재 0 회수 · 기존 스택/볼륨 비접촉.

### S2 — AOR 신설 + 갭 수리 소파도
S1 갭 목록 기반으로 `docs/AGENT_OPERATOR_RUNBOOK.md`(가칭) 신설: 설치(digest 우선·로컬 빌드 폴백)→검증 게이트→온보딩(키 둘·워크스페이스·초대)→**업그레이드 절**(신규)→진단·백업→보고 형식→시크릿 하드 룰(G-E 성문). 병행 수리: G-D 알림 범위표. AC: **grok이 AOR만 보고 설치→온보딩→업그레이드 1사이클 무개입 완주**(재실측).

### S3 — 외부 접속 + 웹훅 (기능 완성)
G-C 택일(권장: 그록봇 호스트가 공인 IP·도메인 가능하면 caddy 경로+#1239 파라미터화 수리 / 아니면 Tailscale 절 신설) 집행 + **#1265 웹훅 인바운드 Rust 이식**(엔진 goal — 이 축의 최대 코드 작업). AC: 성재 맥 웹/데스크탑이 그록봇 호스트의 oort에 정상 접속·웹훅 1왕복 실측.

### S4 — 그록봇 관리 통합 (다이얼인)
그록봇을 hosted agent로 등록(#1361 계약 — 연기된 실증을 이 축에서 소화 가능)·상주 다이얼인으로 inbox 폴링(routine 수동 실행 의존 해소)·oort 채널에서 "상태 보고" 지시 왕복. 쓰기형 관리(업데이트 지시)는 v2. AC: 채널 멘션→그록봇 상태 보고 응답 1왕복.

**순서 논리**: S1은 오늘이라도 발사 가능(제로 코드)·S2가 핵심 산출물·S3은 기능 약속 이행·S4는 차별화. S1→S2는 순차, S3의 #1265는 S2와 병렬 가능(파일군 분리).
