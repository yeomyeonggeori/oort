# ADR-0162: busy 프레즌스와 알림 일시정지 경계 — legacy DND 어휘 해소

- Status: **Proposed** (2026-08-11 · 성재 승인 전 Accepted 승격·추가 구현 금지)
- 관련: ADR-0100(결정 거버넌스), ADR-0120(P9 서버 단일 판정), ADR-0124(채널 mute + Proposed 증보 1), ADR-0160(사용자 프레즌스), `docs/planning/research/2026-08-11-server-security-selfhost-review.md` N-H1~N-H3·G-H4
- 발단: 현재 라이브는 `member.presence_status='dnd'`와 `notification_rule.dnd=true`라는 두 값을 갖지만, push는 후자만 읽고 데스크톱 로컬 알림은 둘 다 우회한다. Proposed인 ADR-0124 증보 1을 그대로 Accepted로 올리면 이 분열을 정본화한다. 더구나 공개 상태가 알림을 억제하지 않는다면 `dnd`(do not disturb)라는 이름 자체가 지키지 않는 약속이다.

## Context

현행 `presence_status=dnd`는 채널을 공유하는 동료에게 보이는 **공개 선언 상태**다. 반면 “모든 알림 일시정지”는 본인과 서버만 알아야 하는 **비공개 delivery 정책**이다. 둘은 함께 켤 수 있지만 같은 사실은 아니다. 공개 상태를 바꾸면 알림이 암묵적으로 꺼지거나, 조용히 알림만 끄려 했는데 동료에게 상태가 노출되어서는 안 된다. 이 분리를 택한다면 공개 상태의 정본 어휘도 효과에 맞게 `busy`(바쁨)여야 한다. `dnd`를 그대로 두고 “표시만 한다”고 설명하는 것은 wire와 UI가 계속 알림 억제를 약속하게 만들어 경계를 다시 흐린다.

현재 서버 `momo-push::judge_targets`는 `notification_rule.dnd`를 읽어 APNs push를 억제한다. 그러나 데스크톱 `DesktopNotifications`는 공유 `message.new`를 받아 채널 mute만 로컬 재판정하므로, 전역 일시정지와 멘션 예외가 push와 반대로 동작할 수 있다(N-H1). ADR-0160은 presence DND가 알림을 억제한다고 썼지만 실제 구현은 별도 원장을 읽는다(N-H2). 이 경계 변경은 Accepted ADR 선행 없이 이미 라이브에 들어갔다(N-H3).

## Decision (Proposed)

### D1. 두 상태를 의미·저장·가시성에서 분리한다

| 개념 | 정본 | 가시성 | 효과 |
|---|---|---|---|
| 공개 busy 프레즌스 | `member.presence_status='busy'` (`dnd`는 migration 중 legacy alias) | ADR-0160의 co-member 로스터 경계 | 동료에게 “바쁨”을 표시할 뿐, 알림 판정 입력이 아니다 |
| 비공개 알림 일시정지 | 도메인/API `pauseAll`(v0 물리 컬럼은 호환을 위해 `notification_rule.dnd` 유지) | 본인 + 서버 판정기만 | 해당 워크스페이스의 제품 소유 알림을 전 기기에서 억제 |

한 값을 다른 값에서 추론·복사·OR하지 않는다. presence API는 notification rule을 쓰지 않고, notification-rules API는 presence를 쓰거나 브로드캐스트하지 않는다. 제품의 새 wire/UI에는 `dnd`를 쓰지 않는다. 이 이름은 두 legacy 계약을 옮기는 동안만 각각 `busy` 또는 `pauseAll`로 번역한다. unread/read-state와 인앱 인박스는 둘 모두의 영향 밖이다.

### D2. 서버가 모든 기기의 알림 policy 권위다

알림의 **제품 정책 eligibility**는 서버 한 곳에서 `pause_all > channel mute(mention override 반영) > reason` 순으로 판정한다. 이 판정은 먼저 `(workspace, member, message, reason)` 단위로 이루어지고, 그 뒤 APNs token이나 접속 중인 데스크톱 같은 transport target으로 확장한다. push token이 없는 멤버도 데스크톱 eligibility 판정을 받을 수 있어야 한다.

- native/mobile push와 데스크톱·향후 web OS 알림은 같은 서버 판정 결과를 소비한다.
- 데스크톱은 raw `message.new`에서 mute/pause/reason을 재판정해 OS 배너를 만들지 않는다. actor-bound 사용자 채널의 id-only `momo.notification.eligible.v1`(가칭) 같은 서버 발급 delivery intent만 소비한다.
- realtime-token/bootstrap은 exact intent channel과 함께 shared `notificationDeliveryMode:"legacy"|"intent"|"disabled"`를 제공한다. `legacy`에서만 raw-message local fallback을 허용하고 intent를 OS 알림으로 소비하지 않는다. `intent`에서는 intent 부재가 authoritative deny이며 raw fallback은 금지한다. `disabled`에서는 local OS 알림을 모두 멈춘다. 필드 부재는 `legacy`로 해석하되, old incompatible client usage 0과 legacy-mode session drain 전에는 `intent`로 flip하지 않는다.
- 클라이언트는 창 focus, OS 권한, stale/replay, 로컬 중복처럼 **그 기기에서만 아는 조건으로 추가 억제**할 수 있다. 서버가 거부한 알림을 되살리거나 정책을 완화할 수는 없다.
- 사용자별 intent 구독은 본인의 **현재 workspace authority episode** credential과 episode-scoped personal rail에 결속하고 다른 member/workspace 또는 같은 member의 과거 episode가 읽을 수 없어야 한다. 대화 내용 추가는 ADR-0120의 id-only 경계를 별도로 승인받지 않는 한 금지한다.
- 모든 transport의 봉인 reason 어휘는 `dm|mention|approval_request|resume_offer|work_session_idle` 5종이다. 본 ADR은 ADR-0120 부록 A의 **선택지 1**을 채택해 `work_session_idle`을 거짓 `resume_offer`로 접거나 조용히 버리지 않는다. live PushRelay validator와 정직한 mock/gate를 먼저 5종으로 넓히고, RN iOS kit/JS validator를 뒤따르게 한다. 구 모바일은 기존 fail-open generic notification을 표시하므로 기능은 유지되지만, relay 5종 support와 client/gate 배포 전에는 “모든 transport 동일 reason”을 완료로 표기하지 않는다.

### D2.1. delivery verdict는 candidate별 bounded cursor에서 member마다 한 번만 확정한다

`message INSERT`가 만든 기존 `push_candidate` outbox가 유일한 source다. message transaction은 ADR-0165의 workspace authority **shared** key → workspace channel-set **shared** key → target channel **shared** key를 고정 순서로 잡고, current `workspace.authority_generation`과 `channel.membership_generation`을 각각 candidate의 `source_authority_generation`, `source_channel_membership_generation`으로 봉인한다. workspace lifecycle episode mutation과 channel join/rejoin/leave는 대응 key의 exclusive lock 아래 counter를 먼저 증가시키므로 concurrent transaction의 시작/commit timestamp가 아니라 이 lock+counter가 source order의 SoT다.

이를 claim한 `momo-notifier`가 **sole policy writer**로서 candidate header를 `collecting`으로 만들고 stable `(channel_membership_id, member_id)` cursor를 최대 **500 recipient/page**로 전진시킨다. 각 page tenant transaction은 workspace→channel 순서의 shared lock을 잡고 source generation 이하인 live channel access와 authority episode만 읽는다. member별 최초 durable judgment에서 그 시점의 notification rule을 읽어 allow/deny와 봉인 reason, current authority row의 membership ID·별도 `authority_episode_id`·episode generation, live channel-membership ID·`access_generation`을 immutable child row로 쓴다. eligible member의 `notification_delivery_intent`·user-targeted `Broadcast` outbox와 **APNs transport-expansion cursor** 및 다음 recipient cursor를 같은 page transaction에 기록한다. APNs token별 dispatch는 별도 cursor가 최대 **500 target/page**로 만들며 current recipient episode에 등록된 token만 선택하고 `push_token_id`, 그 row의 immutable `registration_authority_episode_id`와 단조 `registration_generation`을 snapshot한다. 마지막 recipient page가 exhaustion을 확인할 때만 `judgment_completed_at`; 모든 transport cursor가 끝나야 candidate settled marker를 쓴다. 따라서 channel/device 크기와 무관하게 한 transaction의 verdict·intent 또는 transport-target WAL은 각각 500개 이하이고, 501개 이상도 부분을 잘라 “전체 완료”로 속이지 않고 cursor로 끝까지 진행한다.

crash가 page commit 전이면 그 page만 다시 판단/확장하고, commit 뒤면 unique child key와 저장된 cursor/verdict만 재사용한다. 이미 확정된 member의 규칙은 다시 읽지 않으며, 아직 확정되지 않은 member의 정책은 **그 member의 최초 judgment 시점** 값이다. candidate 전체를 한 벽시계 snapshot으로 판정했다고 주장하지 않는다. `authority_episode_generation > source_authority_generation`이거나 live channel-membership `access_generation > source_channel_membership_generation`인 episode는 과거 candidate의 새 수신자가 될 수 없고 deny다. transport claim은 영속 authority episode가 active이고 current workspace membership pointer와 channel `access_generation`이 저장 snapshot과 모두 같으며, APNs이면 token row를 잠가 저장 `registration_authority_episode_id`가 recipient/current active episode와 같고 `invalidated_at IS NULL`, 저장 `registration_generation`이 current와 같을 때만 성공한다. device re-register는 같은 token lock에서 generation을 올리고 current episode를 새 registration binding으로 명시 교체하며 revoke는 generation을 올려 이후 claim을 막는다. claim transaction이 revoke보다 먼저 선형화한 이미 in-flight인 id-only APNs 한 건은 외부 provider에서 retract할 수 없다는 한계를 명시하고, revoke commit 뒤 **새 claim**은 0이며 payload fetch는 inactive authority에서 403이다. workspace/channel leave·rejoin은 source 뒤 새 episode/access를 추가하지 못한다. lifecycle transaction은 child 전체를 UPDATE하지 않고 old episode/access를 terminalize한 뒤 한 건의 revocation cursor를 넣으며, 이미 판단된 pending intent/dispatch는 그 cursor가 최대 500/page로 cancel/scrub한다. claim-time fence는 cursor 완료 전에도 즉시 적용된다. deny를 생략하거나 확정된 child를 candidate settle 전에 다시 판정하는 경로는 허용하지 않는다.

현재 notifier의 BYPASSRLS pool에 `SET LOCAL app.workspace_id`만 추가하는 것은 tenant 격리가 아니다. 최종 topology는 notifier가 BYPASS role을 보유하지 않고 전용 **NOBYPASSRLS policy role**을 쓰며, 전 테넌트 candidate discovery/lease는 `search_path=''`, 고정 ID projection·batch size·`SKIP LOCKED`만 허용하는 좁은 `SECURITY DEFINER claim_notification_candidate_batch`로만 한다. 함수 EXECUTE는 그 role에만 주고, 반환된 각 workspace의 판단·batch/intent/dispatch write·candidate settle은 `SET LOCAL app.workspace_id` tenant transaction에서 수행한다. API나 클라이언트가 직접 Centrifugo로 publish하는 경로는 만들지 않으며 relay는 committed outbox만 운반한다.

이 role cutover는 push loop 하나만의 변경이 아니다. 현 `momo-notifier`가 같은 BYPASS pool로 수행하는 T3 reconcile, fallback/retry lease, approval sweep 등 모든 cross-tenant loop를 inventory하고, loop별로 같은 `search_path=''`·bounded ID-only claim function과 workspace별 NOBYPASS settle로 이설한다. 미분류 loop, raw cross-tenant SELECT/WRITE, 별도 BYPASS pool/role이 하나라도 남으면 notifier role flip과 새 notification writer activation을 거부한다. 각 loop의 lease/retry/idempotency 회귀와 old BYPASS process/lease·grant 0을 함께 증명한다.

- decision batch unique key는 source candidate ID, member verdict key는 `(candidate_id, member_id)`, intent unique key는 `(workspace_id, member_id, message_id)`이고 outbox idempotency key는 `notification:<workspace>:<member>:<message>`다. candidate retry는 새 verdict나 중복 OS 알림을 만들지 않는다.
- 허용 payload는 `schema`, `intent_id`, `workspace_id`, `channel_id`, `message_id`, 봉인 `reason`, `created_at_ms`, `expires_at_ms`뿐이다. message body·sender display name·rule 값·token은 싣지 않는다. 클라이언트는 현재 인가로 message를 fetch한다.
- intent TTL은 5분이다. 기존 read-state용 `user` namespace의 recovery/history 계약을 바꾸지 않고, proxy-authorized 전용 notification namespace를 추가해 history size/TTL을 0으로 둔다. exact `notificationIntentChannel`은 이 namespace만 사용하며 infra config·subscribe proxy matrix가 먼저 landing한다. 클라이언트는 `intent_id`를 dedupe하고 만료·focus·OS permission으로 추가 억제한다. durable은 commit→publish 재시도를 뜻하지 오래된 OS 알림 복구를 뜻하지 않는다.
- workspace leave/suspend/remove와 channel leave/rejoin transaction은 authority episode/channel access를 먼저 회전하고 해당 old snapshot의 **revocation cursor 한 건**과 D2.2의 옛 episode-subject disconnect effect를 넣는다. per-intent/outbox/APNs dispatch 대량 UPDATE나 membership-delete FK cascade는 lifecycle transaction에 넣지 않는다. 이미 publish된 intent는 되감을 수 없지만 message fetch는 inactive membership에서 거부된다. 재가입한 같은 member ID나 같은 channel-membership row도 새 authority/channel-access generation이므로 옛 connection, verdict, dispatch를 재활성화하지 않는다.
- authority 결속은 immutable `recipient_membership_id_snapshot NOT NULL`, `recipient_authority_episode_id_snapshot NOT NULL`, `recipient_channel_membership_id_snapshot NOT NULL`, `recipient_channel_access_generation_snapshot NOT NULL`이다. episode snapshot은 `(workspace_id,id)` 영속 `workspace_authority_episode`에, channel snapshot은 보존되는 same-tenant membership row에 composite FK로 결속한다. dispatch는 current workspace membership이 membership+active episode snapshot을 가리키고 live channel row의 `left_at IS NULL`+`access_generation`이 snapshot과 같을 때만 claim된다. membership 삭제 시 child FK update는 0이고 immutable verdict 증거는 새 episode/access generation과 일치하지 않는다.
- active APNs token은 `(workspace_id,member_id,current_authority_episode_id)`당 최대 **32개**다. `push_token.registration_authority_episode_id`는 등록을 만든 영속 same-tenant episode에 FK로 결속하고 `registration_generation`은 등록·무효화 수명주기를 단조 구분한다. dispatch snapshot은 세 값을 모두 보존한다. 기존 device re-registration은 허용하지만 반드시 인증한 current episode로 binding을 바꾸고, 33번째 distinct active device는 stale/invalid/old-episode token을 먼저 정리한 뒤에도 상한이면 409 `device_limit_reached`로 side effect 0이다. 이 admission과 별개로 transport expansion은 500 target/page라 legacy over-cap 데이터도 단일 transaction을 폭증시키지 않는다.
- registration episode binding과 live target-reader floor는 ADR-0165/S-6b가 먼저 nullable expand·backfill·writer/reader drain·NULL/FK contract로 소유한다. C-1a는 그 column을 재생성하지 않고 `registration_generation`을 nullable/output-off expand해 existing token을 generation 1로 backfill한다. register·same-row re-register·rotate·revoke·lifecycle invalidation을 포함해 binding, `invalidated_at` 또는 token credential 상태를 바꾸는 모든 writer가 generation-2로 이관되어 같은 row lock 안에서 generation을 반드시 올려야 한다. old API/lifecycle writer process·lease 0 뒤 DB transition fence를 켜 generation 없는 상태 변경을 red로 만들고 generation NULL 0/NOT NULL을 validate한 다음에만 APNs dispatch output을 연다. old writer가 revoke 뒤 generation/episode를 유지한 채 same row를 active로 되살리는 rollback은 허용하지 않고 output-off만 rollback한다.
- source-generation 컬럼은 nullable expand로 추가하지만 pre-migration pending candidate의 NULL을 “현재 generation”으로 추정 backfill하지 않는다. old notifier가 원래 계약으로 drain하거나 24시간 hard deadline에서 fail-closed expire한 뒤 source NULL 0을 증명한다. `channel.membership_generation`/`membership.access_generation` expand에는 모든 join/rejoin/leave writer의 generation-2 mode와 DB legacy-write fence를 포함한다. 모든 API writer·lease 0과 legacy mutation red proof 전에는 notification output을 열지 않는다.
- private deny reason과 `pauseAll` 사용 이력을 영구 메시지별 원장으로 만들지 않는다. 모든 child가 terminal이면 즉시, 아니어도 candidate 생성 24시간 뒤에는 candidate/dispatch를 expired로 닫고 per-member deny row·reason·intent를 scrub한다. 그 뒤에는 batch의 terminal/expired marker와 aggregate allow/deny counts만 남기며 재판정·재발행하지 않는다. 보존 기한을 늘리려면 별도 privacy 결정을 요구한다.
- 신규 decision/intent/dispatch table·queue와 push registration binding은 `workspace_id`, same-tenant member/live-membership 또는 영속 authority-episode composite FK, RLS FORCE와 정본 RLS 등록을 갖는다. 제한 claim 함수 외 raw cross-tenant SELECT/WRITE는 실패해야 한다.

### D2.2. 기존 realtime 구독에는 65초 revocation fence를 적용한다

subscribe proxy는 구독 시점에만 membership을 검사하므로 “전달 순간마다 재검사”를 약속하지 않는다. connection JWT의 `sub`와 user-limited rail suffix는 ADR-0163/0165의 `<member_id>:<authority_episode_id>` subject를 사용한다. lifecycle mutation은 app token을 즉시 revoke하고 같은 transaction에 **옛 episode subject**의 Centrifugo disconnect effect를 durable·멱등하게 넣는다. relay가 post-commit `disconnect(user=old_episode_subject)`를 retry하고, connection token TTL을 60초 이하·clock leeway를 5초 이하로 고정해 broker 장애 때도 기존 channel 구독의 잔존 상한을 **65초**로 만든다. 새 notification intent는 새 episode rail에만 publish하므로 빠른 재가입이나 같은-row reinstate도 옛 connection에 새 메타데이터를 흘리지 않는다. refresh/reconnect는 active credential, membership row와 authority episode를 다시 검사한다. 기존 300~1800초 token과 member-only legacy subject를 모두 drain한 뒤에만 이 상한과 episode 격리를 검증됐다고 표기한다. ADR-0163/0165가 정의한 server-directed personal-channel client rollout과 공용 fence가 완료되지 않으면 delivery-intent rail을 열지 않는다.

### D3. 기존 ADR과의 관계

- **ADR-0160 부분 supersede (이 ADR이 Accepted일 때만):** 가용성=휘발, 선언 상태=내구, 유효 프레즌스=계산, 사람 전용, co-member 가시성은 유지한다. 선언 enum/UI의 `dnd`는 `busy`로 대체하고, D2의 “presence DND가 알림을 억제”, 프라이버시 절의 “DND→푸시 억제”, 미결 5의 notifier 연동은 폐기한다.
- **ADR-0124 본문 유지:** 채널 mute의 서버 저장, unread 무영향, 멘션 기본 억제는 유지한다.
- **ADR-0124 증보 1 부분 대체:** `dnd`라는 정책 어휘를 비공개 `pause_all`로 바꾸고, “push만”이 아니라 모든 제품 알림 transport에 같은 판정을 적용한다. `mention_overrides_mute`와 우선순위는 유지한다. 증보 1은 현재처럼 **Proposed**이며, 라이브 코드가 승인을 대신하지 않는다.
- **ADR-0120 강화:** “notifier 한 곳”을 transport별 중복 판정이 아니라 member-level policy 판정 하나로 해석한다.
- **ADR-0120 부록 A 해소:** 본 ADR이 Accepted되면 미결 부록의 선택지 1을 결정으로 승격해 reason enum을 5종으로 고정한다. ADR-0139의 idle 완료와 resume-offer 구분은 유지한다.

## Migration / API / client impact

1. 새 독립 boolean을 추가해 두 SoT를 만들지 않는다. 현행 `notification_rule.dnd` 값은 그대로 **private pause** 값으로 보존하고 v0에서는 물리 rename하지 않는다. column comment와 도메인 mapping으로 legacy 물리명임을 봉인하고 `(workspace_id, member_id) → member(workspace_id, id)` composite FK를 보강한다. `pause_all` 물리 rename은 구 binary가 사라진 뒤 별도 expand/dual-write/contract ADR·migration으로만 한다.
2. `/notification-rules`의 정본 JSON 어휘는 `pauseAll`이다. 신서버는 호환 창에 응답으로 `pauseAll`과 deprecated `dnd`를 **같은 값으로** 함께 싣고 둘을 모두 입력 alias로 읽는다. 둘이 함께 와서 값이 다르면 400으로 거부한다. GET 응답에는 additive `writeField:"dnd"|"pauseAll"`을 싣고, 필드가 없는 구서버는 `dnd`로 해석한다. 이 값은 instance-local 추정이 아니라 fleet-wide shared rollout flag이며 기본은 `dnd`다. 모든 client는 그 값이 지시한 필드 **하나만** write body에 보낸다. 구서버는 `pauseAll`을 모르는 `deny_unknown_fields` DTO이므로 old instance/lease 0을 확인하기 전에 fleet flag를 `pauseAll`로 바꿀 수 없다. rollback으로 flag가 `dnd`가 되면 client write도 즉시 `{dnd}`로 돌아간다. 구클라이언트 사용량 0과 rollback binary drain을 확인한 뒤 별도 contract change로 `dnd` wire를 제거한다.
3. notification rule에는 `rule_revision bigint NOT NULL DEFAULT 0`을 두고 GET/PUT에 strong ETag를 결속한다. 행 부재는 `{false,false,revision:0}`의 logical row이고 conditional upsert로 동시 최초 write도 한 건만 revision 1을 얻는다. legacy `writeField=dnd` 창에는 `If-Match`를 권고하되 구클라이언트 호환을 위해 선택으로 받는다. old client/server usage 0 뒤 `writeField=pauseAll` cutover는 `If-Match`를 필수로 하고 누락은 428, mismatch는 412와 최신 ETag로 거부한다. 성공 PUT은 row lock 아래 예상 revision을 확인해 두 필드를 원자 교체하고 실제 값이 바뀔 때만 revision을 1 올린다. client는 412에서 최신값을 refetch하고 사용자가 실제 토글한 필드만 새 snapshot에 재적용해 확인받는다. 따라서 두 기기의 stale full-replacement가 다른 필드를 조용히 되돌리지 않는다. route-specific JSON rejection은 닫힌 body/unknown field를 OpenAPI와 같은 400으로 정규화하고 Axum 기본 422를 그대로 노출하지 않는다.
4. presence는 expand→cutover→contract로 옮긴다: (a) 클라이언트가 `busy|dnd`를 모두 읽고 둘 다 “바쁨”으로 렌더, (b) numbered migration으로 enum에 `busy`를 추가하고 서버가 두 입력을 같은 `Busy` 도메인 값으로 읽되 출력은 아직 `dnd`, (c) 구서버 프로세스를 모두 drain한 다음 신규 write/output을 `busy`로 전환하고 **후속 migration**에서 기존 행을 `dnd→busy`로 backfill, (d) 구클라이언트 호환 창 뒤 별도 contract migration에서 `dnd` enum label/input을 제거한다. 새 enum label을 추가한 transaction과 그 값을 쓰는 backfill을 분리한다. 두 label은 같은 공개 의미의 호환 표기이며 별도 상태가 아니다.
5. `/presence`와 roster/realtime의 정본 wire는 `presenceStatus: busy`다. legacy `dnd` 입력은 `busy` alias로만 받고, presence write에서 notification-rules write를 연쇄 호출하지 않는다. 서버가 `busy` 출력·입력을 시작하기 전에 web/desktop/mobile의 dual-read를 배포하고 구서버 drain 전 client write는 legacy `dnd`만 사용한다.
6. 서버 판정기를 member eligibility와 transport expansion으로 분리하고, D2.1의 durable user intent·인가·OpenAPI/realtime 문서를 추가한다. PushRelay, mock, verifier와 mobile validators의 reason enum을 위 5종으로 맞춘다. realtime-token/bootstrap response에는 ADR-0163의 server-directed exact-name 계약을 따라 additive `notificationIntentChannel`, `notificationDeliveryMode`를 제공하고 클라이언트는 이를 그대로 소비하며 subject/channel을 조립하지 않는다. intent output flag가 off인 expand 단계에는 mode=`legacy`로 먼저 landing한다. mode는 shared durable generation이지 instance-local flag가 아니며, 정책 입력과 persisted verdict는 PG가 SoT이고 Centrifugo는 결과 전송만 한다.
7. 설정 UI는 **“모든 알림 일시정지 · 비공개”**, 프로필 메뉴는 **“바쁨 · 동료에게 표시”**로 서로 다른 저장 경로와 설명을 쓴다. 데스크톱은 mode=`intent`에서 raw-message 판정과 muted-channel 구독 제외를 제거하고 서버 intent + local suppress-only guard로 전환한다. activation은 지원 client 배포와 old incompatible usage 0 뒤 writer output이 off인 채 `legacy→disabled`로 flip해 legacy-mode connection/bootstrap lease를 drain하고, 다시 mode=`intent`로 올린 뒤 disabled-mode session이 refresh하거나 signed mode-update를 ACK해 active supported session의 intent-mode adoption이 확인될 때까지 output을 계속 off로 둔다. 그 다음에만 sole writer output을 켠다. rollback은 writer output off→mode=`disabled`→intent-mode session drain→mode=`legacy` 순서만 허용한다.
8. ADR-0163과 함께 배포할 때 두 축을 같은 release에서 flip하지 않는다. 먼저 모든 클라이언트를 `v1|v2` frame과 `dnd|busy` label dual-read로 배포하고, 서버는 **revision v2 + legacy `dnd` output**을 먼저 연다. v2 adoption과 stale-drop을 확인한 뒤 별도 flag로 `busy` output을 연다. rollback도 `busy_output`을 먼저, `revision_v2`를 나중에 독립적으로 되돌린다. `v1/busy`는 발행하지 않는다.

## Alternatives considered

- **presence DND 하나로 합치기:** 단순하지만 비공개 pause가 공개되고, 사회적 상태와 delivery 선택을 독립적으로 표현할 수 없어 기각.
- **공개 상태를 `dnd`로 유지하되 “표시만”이라고 설명:** migration은 싸지만 이름과 익숙한 UI 관습이 알림 억제를 약속한다. 문서 한 줄로 계속 생길 오해를 상쇄할 수 없어 기각.
- **공개 상태를 `busy`/“바쁨”으로 migration (권고):** staged wire·enum 호환 비용은 들지만 공개 신호가 실제 효과와 일치하고 `pauseAll`만 delivery 의미를 가진다.
- **두 boolean을 OR:** 현재 불일치를 숨길 뿐 어느 화면이 무엇을 꺼야 하는지 답하지 못하고, 사용자가 한쪽을 해제해도 알림이 계속 막혀 기각.
- **규칙을 모든 클라이언트에 동기화해 각자 판정:** 오프라인 캐시·버전 차이·새 transport마다 정책 복제가 생겨 P9와 다기기 일관성을 깨므로 기각.
- **서버 member-level eligibility + transport fan-out (권고):** 판정은 하나이고 클라이언트는 표현만 담당한다.

## Consequences

- (+) 공개 신호와 비공개 선택의 프라이버시뿐 아니라 이름과 실제 효과가 일치하고, push/desktop/mobile의 결과가 일치한다.
- (+) 새 transport가 정책을 다시 구현하지 않으며 unread 원장은 그대로다.
- (-) 사용자별 delivery-intent rail과 서버 fan-out/관측이 추가되고, 데스크톱 알림이 서버 연결·판정 지연에 의존한다.
- (-) presence enum/wire와 notification API/DB에 서로 다른 뜻으로 남은 `dnd`를 단계적으로 폐기해야 한다. 먼저 모든 클라이언트를 dual-read로 배포해야 하며, 오래된 self-host/server·클라이언트의 호환 창이 길어진다.

## Verification contract (Accepted 후 구현 수용기준)

1. `presence=busy, pauseAll=false`는 “바쁨”으로 보이되 DM/멘션/승인 알림 eligibility를 억제하지 않고, `presence=auto, pauseAll=true`는 공개 상태를 바꾸지 않은 채 모든 transport를 억제한다.
2. 같은 message/member에 대해 APNs와 데스크톱의 server eligibility/reason이 일치한다. 다섯 reason 각각의 relay/intent/mobile matrix가 green이고 특히 `work_session_idle`이 relay 400으로 영구 폐기되거나 `resume_offer`로 오표기되지 않는다. `pauseAll`은 mention override보다 우선하고, mention override는 channel mute만 관통한다.
3. push token이 없는 eligible member도 본인 desktop intent를 받고, ineligible member는 message frame을 받아도 OS 알림을 만들지 않는다. `legacy|intent|disabled` matrix에서 raw fallback은 legacy에만 있고 intent 부재는 deny다. old incompatible client 또는 legacy-mode session이 남으면 intent-mode flip이 실패하고, disabled-mode session이 refresh/ACK되지 않으면 writer output activation이 실패한다.
4. 다른 member/workspace는 intent를 구독·재생할 수 없고, notification rule은 roster/presence/outbox 공개 payload에 노출되지 않는다. 지원 client는 server-provided `notificationIntentChannel`과 `notificationDeliveryMode`만 사용하고 suffix를 조립하지 않는다.
5. 클라이언트의 focus/stale/duplicate guard는 eligible 결과를 줄이기만 한다. 서버 deny를 클라이언트가 뒤집는 코드 경로가 없다.
6. 현행 `notification_rule.dnd=true` 데이터와 legacy notification API 요청은 전환 뒤 `pauseAll=true`로 보존되고, 상충 alias는 거부된다. 행 부재는 false다.
7. 현행 `presence_status=dnd` 행·입력은 `busy`로 읽히고 신규 출력/저장은 `busy`다. dual-read 구클라/신클라 × 구서버/신서버 호환 매트릭스와 backfill 후 legacy row 0을 검증한다.
8. pause/presence 어느 변경도 unread·badge 원장을 바꾸지 않으며, RLS·active-human actor binding과 서버 판정 DB 오류 시 fail-closed를 검증한다.
9. recipient/transport page commit 전후와 마지막 page→candidate settle 사이에 crash를 주입해 committed member의 규칙을 다시 읽거나 verdict/intent/outbox/dispatch를 중복하지 않는지 검증한다. channel recipient와 active token 각각 0/1/100/500/501/5,000 legacy fixture에서 page당 verdict 또는 transport target·WAL이 500 이하이고 cursor resume 뒤 누락·중복 없이 terminal marker에 도달해야 한다. 신규 33번째 current-episode device 등록은 409+write 0이다. `candidate 생성 → workspace leave/suspend → rejoin/reinstate → judgment`, `leave → rejoin → cleanup 정지 → 새 candidate/APNs expansion`, `candidate 생성 → channel join/rejoin → judgment`, `judgment page → channel leave/rejoin → transport claim`, `target 생성 → device revoke/re-register → dispatch claim`을 모두 재현한다. old registration episode token은 cleanup 전에도 새 candidate target/claim 0이고 명시 re-register 뒤 새 episode+증가 generation만 성공해야 한다. source 뒤 생긴 authority/channel generation이나 registration episode/generation이 바뀌거나 invalidated된 token에는 새 claim이 0이다. revoke보다 먼저 claim된 in-flight id-only APNs는 별도 계수하고 revoke commit 뒤 claim은 0이다. nullable episode/generation backfill→register/rotate/revoke/lifecycle writer gen2→old process/lease 0→DB transition fence 순서를 검증하고, fence 뒤 generation/episode를 갱신하지 않는 invalidation/reactivation SQL은 red여야 한다.
10. NOBYPASS notifier role의 raw cross-tenant SELECT/WRITE는 실패하고 push/T3/fallback/lease/approval/revocation 각 제한 claim 함수만 bounded ID를 반환한다. unclassified loop와 old BYPASS process/lease·role grant는 0이며 각 loop의 retry/idempotency가 회귀하지 않는다. authority membership row 삭제는 leave를 막거나 verdict를 cascade-update/delete하지 않고, persistent episode state+current-pointer mismatch가 claim을 막는다. notifier/relay 정지+message flood 뒤 lifecycle을 commit해도 transaction의 child UPDATE/FK action은 0, revocation cursor enqueue는 1이고 worker가 500/page로 정리한다. pre-migration source NULL candidate와 old channel-membership writer/lease는 0이고 legacy mutation은 DB fence에서 실패한다. payload allowlist·5분 expiry·전용 namespace history 0·기존 read-state history 불변·다른 user 구독 거부, 새 fetch 403, durable disconnect 정상 시 즉시 종료·broker 장애 시 65초 안 종료를 검증한다.
11. child terminal 직후와 24시간 hard deadline에서 private reason/per-member deny/intent가 scrub되고 marker+aggregate counts만 남는다. scrub 뒤 candidate retry는 재판정이나 dispatch 없이 terminal no-op이다.
12. 구/신 client×server 매트릭스에서 `writeField` 부재/`dnd`/`pauseAll`마다 notification write가 지정 필드 하나뿐인지, old instance가 남으면 fleet flag flip이 거부되는지, `v1/dnd → v2/dnd → v2/busy` 순서만 허용되고 `v1/busy`가 0인지 검증한다.
13. 두 기기의 stale full-replacement는 412로 거부되어 다른 필드를 덮지 못하고, missing `If-Match`는 cutover 전 호환·cutover 뒤 428인지 검증한다. malformed/unknown JSON은 runtime/OpenAPI 모두 400이다.

## Rollback

delivery-intent 장애 시 writer output을 먼저 끄고 shared mode를 `disabled`로 내려 desktop/web OS 알림을 fail-closed한 뒤 intent-mode session을 drain한다. old incompatible client 0이 계속 성립할 때만 mode=`legacy`로 raw fallback을 복구한다. 완료 batch를 삭제해 재판정하지 않고 native push도 이 persisted immutable verdict의 drain 결과만 사용한다. notification API는 legacy `dnd` alias와 물리 컬럼을 유지해 구 binary rollback을 허용하고 capability를 내리면 client write도 legacy body로 돌아간다. presence rollout 중에는 `busy`와 `dnd` enum label을 모두 남기고 서버가 둘을 같은 도메인 값으로 읽는다. 문제가 생기면 `busy_output`만 legacy `dnd`로 되돌리되 UI 의미는 계속 “바쁨”이고 알림과 결합하지 않는다. dual-read 호환 창과 backfill 검증이 끝나기 전에는 어느 legacy label/column도 drop하지 않는다. 이미 기록한 verdict/intent/outbox는 idempotency와 expiry로 drain하며 삭제해 재발행시키지 않는다.
