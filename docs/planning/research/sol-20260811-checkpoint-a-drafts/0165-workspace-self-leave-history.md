# ADR-0165: 워크스페이스 self-leave 이력·세션 종료 계약

- Status: **Proposed**
- Date: 2026-08-11
- 관련: ADR-0161 D4(self-leave와 해당 workspace 로컬 세션), ADR-0128 D1·D3·D4(owner 불변식·토큰 revoke·self-service), ADR-0163(realtime revocation fence, Proposed), `docs/planning/research/2026-08-11-server-security-selfhost-review.md` W-H2·W-M3
- 승인 전 경계: 본 ADR이 Accepted 되기 전에는 channel membership hard delete를 새 정본으로 간주하지 않는다.

## Context

ADR-0161은 `DELETE /v1/workspaces/{ws}/members/me`가 모든 채널의 `membership.left_at`을 세팅하고 member를 soft state로 전이하며, 마지막 active owner는 409로 거절한다고 결정했다. 여기서 `membership`은 스키마상 **채널 `membership` 테이블**이다. `workspace_membership`에는 `left_at`이 없고 0161도 그 row의 append-only 보존을 약속하지 않았다. 현 구현은 두 테이블을 모두 hard delete한 뒤 `member.status='deleted'`로 바꿔, 0161이 요구한 채널 소속 증거까지 지우고 이미 모든 접근 쿼리가 사용하는 `left_at IS NULL` 수명주기와 어긋난다(W-M3).

동시에 self-leave는 단순 UI 삭제가 아니다. 두 owner의 동시 탈퇴가 워크스페이스를 고아로 만들지 않아야 하고, 성공한 순간 모든 기기의 access/refresh를 포함한 워크스페이스 세션이 끝나야 하며, 재초대 때 과거 메시지 저자와 비공개 채널 접근 경계가 보존되어야 한다. 현재처럼 같은 `member.id`를 재활성화하면 token revoke만으로는 충분하지 않다. member ID에만 묶인 APNs token, `agent.owner_human_id`, 명시 memory grant, WorkHost key, pending avatar와 personal realtime rail이 새 authority episode에서 다시 유효해질 수 있다. 더구나 Rust의 공개 `POST /v1/join` deleted-human 분기는 이미 같은 ID 재활성화를 허용하지만, OpenAPI에 있는 admin suspend/reinstate/remove는 Rust router에 mount되지 않았다. 따라서 rollout 계획은 “기존 admin lifecycle hook”을 가정하지 않고 live rejoin부터 먼저 닫아야 한다.

## Options

1. **모든 membership hard delete(현행)**: 쿼리는 단순하지만 이력·감사 증거를 지우고 Accepted ADR과 충돌한다. 기각한다.
2. **현재-state row를 `left_at`으로 닫고 audit를 episode 원장으로 사용(권고)**: 기존 unique key와 읽기 쿼리를 유지하면서 탈퇴·재가입·저자 이력을 보존한다.
3. **membership을 append-only episode 테이블로 재설계**: 매 재가입마다 새 row를 만들고 partial unique active index를 둔다. 가장 풍부하지만 현재 `UNIQUE(channel_id, member_id)`·`ON CONFLICT`·다수 조인을 전면 이관해야 한다. v0에서 기각하고, 다회 episode 분석이 필요해질 때 별도 ADR로 연다.

## Decision

### D1. self-leave는 한 tenant transaction에서 접근권만 종료한다

트랜잭션의 첫 문장은 workspace-scoped membership-mutation advisory lock이다. 역할 변경·ownership transfer·정지/추방도 같은 lock을 사용한다. lock 뒤 active human membership과 현재 workspace role을 다시 읽고, owner이면 다른 **active** owner가 있는지 검사한다. 마지막 owner는 409이며 token revoke·membership/member 변경·성공 audit가 모두 0이다. 두 owner가 동시에 leave하면 직렬화 결과 최대 한 명만 성공하고 최소 한 active owner가 남는다.

거절 지점을 모두 지난 뒤 하나의 canonical timestamp로 **권한 종료 transaction**을 commit한다.

1. current authority episode를 `ended`로 전이하고 `workspace_membership` 권한 row를 제거한 뒤 `member.status='deleted'`로 soft-deactivate한다. `member`·`human`·message author row는 삭제하거나 새 ID로 바꾸지 않는다.
2. 모든 active channel row를 한 transaction에서 무제한 UPDATE하지 않는다. 대신 `(workspace, member, ended_episode, leave_at)`의 durable `channel_membership_close_cursor` 한 건을 넣는다. NOBYPASS worker가 workspace authority exclusive → channel-set exclusive 아래 UUID 순으로 최대 500 row/page를 잠그고 **아직 ended episode에 결속된 row만** `left_at = COALESCE(left_at, leave_at)`으로 닫는다. 새 reactivation episode에 이미 재결속된 row는 old cursor가 건드리지 않는다. 행을 DELETE하지 않고 재시도도 최초 `left_at`을 다시 쓰지 않는다.
3. 종료된 episode를 모든 auth/claim reader가 즉시 거부하는 O(1) fence로 삼고, D2의 고정된 subsystem별 cleanup-cursor head, 옛 episode `RealtimeDisconnect` effect와 `workspace.left` audit만 같은 transaction에 commit한다. token·push·WorkHost·grant·avatar·agent-run 등 공격자 수에 비례한 child를 이 transaction에서 열거하거나 bulk UPDATE하지 않는다. 최초 audit는 `member_id`, 이전 workspace role, authority row의 기존 `joined_at`, canonical `left_at`, cursor ID를 기록하고, cursor 완료 audit가 실제 materialize한 aggregate를 기록한다.

채널 인가는 `membership.left_at IS NULL`만 보지 않고 **current active workspace authority episode + channel row의 같은 episode binding**을 항상 함께 요구한다. 따라서 권한 종료 commit 즉시 모든 REST/subscribe/grant/transport claim이 닫히고, 아직 cursor가 materialize하지 않은 legacy `left_at IS NULL` 행은 접근권이 아니다. 이 predicate와 DB writer fence가 전 fleet에 배포되기 전에는 async close를 켜지 않는다. `membership.left_at`은 channel 참여 종료의 보존 materialization이고 과거 message는 `member.id` 저자를 그대로 가리키므로 기록·표시가 보존된다. cursor 지연은 authorization 지연이 아니며 self-leave 200은 권한 종료 transaction 뒤 반환할 수 있다.

**이력 책임 경계:** 채널 참여의 현재/종료 증거는 `membership.left_at`, workspace 권한의 현재값은 `workspace_membership`, 탈퇴 전 workspace role·authority `joined_at`과 사람이 읽는 leave/rejoin 서사는 append-only audit가 소유한다. 아래 `workspace_authority_episode`는 권한 재사용을 막는 최소 보안 ledger(ID/generation/state/timestamps)이지 role/history 분석 테이블이 아니다. 이 ADR은 `workspace_membership`을 이력 테이블로 바꾸거나 그 row를 보존한다고 주장하지 않는다.

`workspace_membership.id`는 현재 권한 **row identity**이지 재사용 불가능한 episode가 아니다. 신규 `workspace_authority_episode`는 `(workspace_id, id)` UNIQUE, `member_id`, 단조 `generation`, `state(preparing|active|suspended|ended)`, `started_at`, nullable `ended_at`을 가지며 RLS FORCE다. `preparing`의 generation은 예약값일 뿐 source/claim snapshot에 사용할 수 없고, `active` 전이 transaction이 workspace counter를 다시 올려 최종 generation을 봉인한다. `workspace_membership.authority_episode_id`는 그 current episode를 same-tenant composite FK로 가리킨다. active channel `membership.authority_episode_id`도 그 접근을 만든 workspace episode를 가리키고, authorization은 두 current pointer와 active episode의 일치를 요구한다. token/grant/personal rail/staged capability는 membership row가 아니라 이 영속 episode ID를 결속하므로 self-leave에서 current membership을 삭제해도 child FK cascade가 발생하지 않는다. claim은 episode state=active이면서 current `workspace_membership`이 같은 member+episode를 가리킬 때만 성공한다.

workspace에는 lifecycle 전용 단조 `authority_generation` counter를 두고, join/rejoin/suspend/reinstate/remove처럼 episode 집합을 바꾸는 exclusive mutation이 먼저 counter를 1 올린 뒤 old episode를 terminal하고 새 episode에 그 값을 복사한다. message/candidate source처럼 “그 시점까지 존재한 episode”를 봉인해야 하는 writer는 같은 advisory key의 shared lock 아래 current generation을 snapshot한다. 따라서 transaction 시작/벽시계가 아니라 lock+counter가 causal order의 SoT다. active→suspended 전이는 옛 ID·시작 시각·generation을 audit/terminalizer 입력으로 캡처한 뒤 old row를 ended, 새 episode를 suspended로 만들고 current membership pointer를 회전한다. **human** admin reinstate도 channel row를 한 transaction에서 무제한 재결속하지 않고 D3의 `preparing` episode+bounded cursor를 거친다. final transaction만 새 active generation/current pointer를 열며 대상 사용자의 token을 발급하거나 관리자에게 반환하지 않는다. 그 사용자가 이후 정상 first-party login/reauth를 통과할 때만 current episode에 결속된 새 token pair를 받는다. agent reinstate는 D3의 별도 pairing/reissue 계약 전 fail-closed한다. remove/rejoin은 membership row 자체와 episode가 모두 새것이고 사용자 주도 human rejoin 성공만 새 token pair를 반환한다. old writer가 episode 회전 없이 deleted→active 또는 suspended→active를 수행하지 못하도록 DB writer-generation fence를 둔다. role 변경은 episode를 회전하지 않으며 **모든 role 변화에 공통 generation을 올리지 않는다**. 대신 staged action마다 필요한 capability의 `loss_generation`을 소유하고, 그 capability가 `있음→없음`으로 바뀔 때만 같은 exclusive lock에서 정확히 +1 한 뒤 해당 generation의 cleanup cursor head를 enqueue한다. claim은 immutable capability-loss generation snapshot과 현재 generation/role을 함께 요구한다. 따라서 demotion→cleanup 정지→재승격에도 과거 action은 부활하지 않지만, capability를 계속 보유하는 owner↔admin 전환이나 상승은 진행 중 action을 무효화하지 않는다. 단순 role 변경이 모든 device/session을 끊지는 않는다.

이 원장은 즉시 NOT NULL로 도입하지 않는다. rollout은 **nullable ledger/current-pointer/token/channel binding expand + compatibility trigger → existing active/suspended membership·live token·active channel row backfill → workspace create, 신규 human join, agent provisioning, login/refresh/token mint, channel join/rejoin을 포함한 모든 writer generation-2 전면 배포 → channel authorization reader 전수 generation-2 배포 → old writer/reader process·lease 0 → DB contract mode flip·legacy NULL write red → NULL 0과 same-tenant FK/NOT NULL validate** 순서다. reader inventory는 message/read-state/search/attachment, subscribe/grant, notification/presence, agent/work-session과 background worker를 포함해 `membership.left_at IS NULL`만으로 허용하는 query가 0이어야 한다. 모든 reader는 current active workspace episode와 channel row episode binding 일치를 함께 요구한다. compatibility trigger는 정상 신규 authority에 episode를 생성·전파할 수 있지만 S-0의 deleted-human reactivation freeze를 우회하지 못한다. async close와 reactivation output/personal rail은 writer/reader contract와 client cutover 전까지 off/legacy다. 구 binary rollback은 contract flip 뒤 허용하지 않고 generation-2 output flag만 내린다.

close/reactivation cursor table은 `workspace_id`, RLS FORCE, same-tenant episode FK와 정본 RLS 등록을 갖는다. cross-tenant discovery는 새 BYPASS role이나 raw table scan이 아니라 `search_path=''`, 고정 ID projection·batch size·`SKIP LOCKED`만 허용하는 좁은 SECURITY DEFINER claim 함수다. 실행체는 ADR-0162/C-1a에서 NOBYPASS로 전환한 `momo-notifier`의 별도 lifecycle-cursor loop이고, 반환된 workspace마다 `SET LOCAL app.workspace_id` tenant transaction에서 lock/predicate를 재검사해 process/settle한다. raw cross-tenant SELECT/UPDATE, 한 page 500 초과와 membership-delete child cascade는 금지한다.

채널 접근의 causal order는 별도 current-state counter로 봉인한다. `channel.membership_generation`을 두고 channel join/rejoin/leave가 channel-scoped mutation advisory **exclusive lock** 아래 counter를 먼저 증가시킨다. 활성 join/rejoin row는 그 값을 `membership.access_generation`과 current `authority_episode_id`에 복사한다. 전역 lock 계층은 **workspace authority key → workspace channel-set key → 영향받는 channel key를 UUID byte 순 오름차순**이다. workspace lifecycle은 앞의 두 key를 exclusive로, 개별 channel join/leave/archive는 authority shared+channel-set exclusive로, message/candidate와 presence PUT은 두 key를 shared로 잡고 필요한 channel shared key를 뒤따른다. multi-channel close/reactivation cursor도 batch마다 channel-set을 고정한 뒤 최대 500 channel key를 UUID 순으로 잡으며 어느 단계에서도 역순 획득은 금지한다. message/candidate source는 이 shared 계층 아래 두 generation을 snapshot한다. 그러므로 message 뒤 가입한 row와 leave 뒤 같은 row를 재활성화한 접근은 source generation보다 커서 과거 candidate의 새 수신자가 될 수 없다. v0는 append-only channel episode table을 만들지 않지만 이 access generation은 알림 source/transport fence이며 audit 이력을 대신하지 않는다.

### D2. leave·suspend·remove는 그 authority episode의 세션과 capability를 종료한다

self-leave뿐 아니라 admin suspend/remove도 같은 workspace membership-mutation lock과 canonical lifecycle transaction에서 old episode/current pointer를 먼저 닫는다. 모든 access·refresh·delegation·agent bearer 및 member-owned capability의 인증·claim query는 current `workspace_membership`이 가리키는 `workspace_authority_episode(state='active')`와 자기 episode binding의 일치를 요구하므로, 물리 `revoked_at` UPDATE가 아직 cursor에 남아 있어도 old bearer/child는 즉시 사용할 수 없다. 같은 transaction에는 고정된 subsystem별 cleanup cursor와 **종료되는 옛 episode subject**를 정확히 지정한 `RealtimeDisconnect` outbox effect만 넣는다. member ID나 membership row ID만 같은 reinstate도 새 episode subject를 사용한다.

`member.id` 보존은 권한 episode 보존이 아니다. lifecycle transaction은 다음 **closed capability inventory**를 즉시 unusable하게 만들고, cleanup cursor가 보존 timestamp/terminal 상태를 bounded하게 materialize한다. 새 member-owned credential/staged-action table을 추가할 때 이 목록 또는 명시적 episode binding 없이 owner의 `member.status='active'`만 보고 되살아나는 경로를 만들 수 없다.

1. 모든 server token은 old episode에서 즉시 인증 실패하고 token cleanup cursor가 `token.workspace_id=ws`이며 대상 member가 actor 또는 subject인 access·refresh·delegation·agent bearer의 `revoked_at`을 최대 500/page로 `COALESCE` 설정한다. ephemeral grant는 발급 access token ID와 current `authority_episode_id` 둘 다에 결속한다. connection JWT·personal rail도 같은 episode를 쓴다. rejoin은 새 token/rail, reinstate는 token 0이고 이후 사용자 login이 새 episode-bound token/rail을 발급하므로 leave/suspend 전 grant/connection을 어느 경로와도 교차 조합할 수 없다.
2. push token은 등록 당시 영속 `registration_authority_episode_id`에 결속한다. expansion/claim은 recipient current episode와 token registration episode가 모두 같을 때만 성공하므로 push cleanup 전에도 old token은 새 episode candidate의 target이 아니다. cleanup cursor는 해당 workspace/member/old-episode token의 `invalidated_at`을 canonical leave 시각으로 최대 500/page 설정한다. `device`·dispatch log는 감사·재등록 식별용으로 보존하되, 새 episode는 새 인증 요청으로 APNs token을 current episode에 명시 재등록하고 generation을 올리기 전 push target을 얻지 않는다.
3. WorkHost auth/control/attach claim은 old episode에서 즉시 실패한다. cleanup cursor는 `work_host.revoked_at`, 관련 `work_auto_approve`, nonterminal control/attach capability를 최대 500/page로 revoked/failed materialize한다. 재가입 뒤에는 새 host row/key를 명시 등록해야 한다.
4. old human-episode를 owner로 보는 agent edit/work-session claim은 즉시 실패한다. cleanup cursor는 그 human을 가리키는 `agent.owner_human_id`를 최대 500/page로 NULL 해제하고 old/new owner를 audit한다. agent 자체와 대화는 보존하며 workspace admin이 명시적으로 다시 assign하기 전 옛 human은 권한을 얻지 않는다. 같은 member ID 재가입은 자동 reassignment가 아니다.
5. `memory_visibility_grant(grantee_kind='member', grantee_id=member)`와 코드·migration inventory가 찾은 그 밖의 explicit member-grantee row는 claim-time episode 불일치로 즉시 실패하고 cursor가 최대 500/page로 `revoked_at`을 닫는다. 과거 grantor가 떠났다는 이유만으로 다른 grantee의 조직 접근까지 자동 취소하지는 않는다. 재가입은 각 resource owner/admin의 새 명시 grant가 필요하다.
6. ADR-0164의 해당 membership row+`authority_episode_id`에 묶인 avatar `allocating|pending` row는 complete claim이 즉시 실패하고 cleanup cursor가 최대 500/page로 `abandoned`+GC queue를 materialize한다. 같은 member ID, 같은 reinstate row ID나 owner/admin capability를 잃었다가 다시 얻은 role로 complete할 수 없다. owner/admin capability 상실만 해당 pending row를 닫고 capability를 계속 보유하는 owner↔admin 변경은 닫지 않는다.
7. notification decision/dispatch는 recipient authority episode를 저장하므로 claim이 즉시 실패하고 revocation cursor가 pending child를 최대 500/page로 취소한다. immutable 과거 candidate가 재가입 뒤 다시 dispatch되지 않고, device token도 2의 명시 재등록 전에는 target이 아니다.
8. ADR-0163의 current episode/view generation 회전이 bootstrap·새 publish를 즉시 fail-closed하고, bounded cursor가 이전·현재 authorized viewer invalidation 및 departing viewer의 opaque purge를 최대 500/page로 materialize한다.
9. 대상 `member.kind='agent'`의 suspend/remove에서는 Accepted ADR-0128의 진행 중 run 종료 계약을 보존한다. worker claim은 old episode/lease로 새 step을 즉시 시작할 수 없고, cleanup cursor가 nonterminal `agent_run`·approval·live `work_session`을 최대 500/page로 기존 terminal 상태 `cancelled`/`ended`로 전이하며 durable provider/worker stop effect를 낸다. 외부 stop은 post-commit retry지만 DB authority와 새 claim은 즉시 닫힌다. human self-leave/role mutation은 agent run을 근거 없이 종료하지 않으며 이 dormant primitive는 C-6c의 agent suspend/remove에서만 호출한다.

위 모든 subsystem은 cardinality와 무관하게 같은 규칙을 따른다. lifecycle transaction에서 child를 bulk UPDATE하거나 `ON DELETE SET NULL` cascade하지 않고, old authority episode/access generation 회전과 **schema로 고정된 수의 cursor head**만 commit한다. cursor 하나가 여러 subsystem progress를 소유하거나 subsystem별 한 건을 쓰더라도 attacker-created child 수에 비례해 cursor row를 만들 수 없다. 각 NOBYPASS worker는 최대 500 child/page만 잠그고 materialize하며 모든 claim reader는 cursor와 무관하게 current active episode/access를 재검사한다. cursor 정지 중에도 권한 종료 latency는 child 수와 무관하다. 어떤 child reader도 episode fence를 붙일 수 없다면 그 테이블에는 DB-enforced hard admission cap+최대 transaction/WAL budget을 별도 Accepted 계약으로 두기 전 activation할 수 없다.

이 목록의 범위는 테이블 이름을 손으로 나열한 문서에만 의존하지 않는다. migration/SQL query inventory가 `member_id`, `owner_human_id`, `grantee_id`, credential/staged 상태를 가진 workspace-scoped row를 분류하고, 각 행이 `identity/history(보존)`, `authority-episode FK`, `lifecycle terminalizer`, `명시적 조직 소유권 유지` 중 하나로 판정되지 않으면 gate가 실패한다. 새 capability table/query도 같은 machine-readable inventory를 갱신해야 한다.

200 응답은 클라이언트가 그 workspace의 refresh/access 및 캐시를 즉시 삭제하고 rail에서 세션을 제거하라는 terminal 신호다. 다른 로컬 workspace 세션은 유지한다. 이미 발급된 access/refresh는 재가입으로 되살아나지 않으며, 새 REST/subscribe/grant는 revoked token과 inactive membership에서 즉시 fail-closed한다. 기존 broker 구독은 전달마다 SQL을 읽지 않으므로 0초 차단이라고 표현하지 않는다. ADR-0163의 필수 durable disconnect retry + connection-token TTL 60초/leeway 5초 fence로 최악 65초 안에 종료한다. 긴 legacy connection token을 drain하기 전에는 이 bound를 주장하지 않는다. 외부 disconnect 호출을 leave transaction 안에서 하지 않는다.

### D3. 신규 join·재가입·human reinstate는 bounded preparation 뒤 새 권한을 활성화한다

모든 human join은 유효한 invite·ban 검사를 통과해야 하며 channel 수에 비례한 row를 한 transaction에서 무제한 upsert하지 않는다. 신규 identity 첫 `/join`은 workspace authority exclusive → channel-set exclusive 아래 invite·ban·email uniqueness를 다시 읽고 `member.status='preparing'`인 never-active provisional member/human과 `workspace_authority_episode(state='preparing')`, durable `workspace_reactivation_cursor(mode='new_join')`를 만든 뒤 **token·active membership 없이 202 `reactivation_pending` + `Retry-After`**를 반환한다. same-ID deleted member는 identity/history를 재사용하되 `mode='rejoin'` cursor와 새 preparing episode를 만들고 동일하게 202/token 0이다. human reinstate 첫 요청도 strict admin/last-owner 규칙 아래 suspended pointer를 재확인하고 새 preparing episode+`mode='reinstate'` cursor를 만든 뒤 target token 0인 202를 반환한다. cursor에는 desired role/mode, invite 또는 admin mutation의 idempotency binding과 channel-set generation을 저장하되 invite secret 자체는 저장하지 않는다.

- NOBYPASS cursor worker는 batch마다 같은 lock 순서와 UUID 순 최대 500개 channel lock을 사용한다. unique `(workspace,member-or-provisional-email)` preparing cursor와 idempotency key가 concurrent 시작을 하나로 수렴시킨다. `new_join`은 각 live joinable public channel에 never-active provisional row를 만들고, `rejoin`은 public channel의 existing/new row를 새 preparing episode에 결속해 `left_at`을 지우며 **현재 invite의 허용 role을 `public_join_channel_role`로 다시 계산해 설정한다**. 기존 channel owner/admin role을 보존·상한승격하지 않는다. `reinstate`만 suspend 직전 live였던 public/private/DM row와 channel role을 그대로 새 episode에 재결속한다. 각 touched row의 `was_new`, 이전 `left_at`, `role`, episode/access generation을 RLS FORCE backup row에 저장한다. preparing episode/member는 current active pointer가 아니므로 어느 mode의 중간 materialization도 REST/subscribe/grant 권한을 만들지 않는다.
- caller가 같은 idempotency key로 join/reinstate를 재시도하면 final tenant transaction이 mode별 invite·ban·email/deleted 또는 strict admin·suspended state를 다시 검사하고 authority+channel-set exclusive 아래 `LIMIT 501` missing/stale 대상 row를 확인한다. channel-set generation이 바뀌었거나 미완 row가 있으면 cursor를 재개하고 202를 유지한다. stable exhaustion일 때만 workspace `authority_generation`을 **다시 1 올려** 그 값을 preparing episode의 최종 generation으로 봉인한 다음, new join/rejoin은 새 `workspace_membership.id`를 만들고 reinstate는 기존 row의 current pointer를 회전한다. episode/member를 active로 바꾸고 target/view revision·mode별 audit를 같은 transaction에 commit한다. 따라서 preparation 중 생성된 message candidate의 source generation은 항상 새 active episode보다 작아 과거 recipient가 될 수 없다. new join/rejoin final 200만 새 session pair/episode subject를 반환하고 reinstate final 200은 target token 0이다.
- final revalidation deny·expiry는 먼저 preparing episode를 `ended`, cursor를 `aborting`으로 바꿔 접근을 계속 0으로 유지한다. abort worker는 최대 500/page로 existing row의 이전 `left_at`/`role`/episode/access generation을 정확히 복원하고 never-active provisional channel row만 삭제한다. `new_join` provisional member/human은 영속 ended episode의 FK target이므로 삭제하지 않고 `status='deleted'`/never-active로 보존하며 다음 유효 invite는 active episode 이력이 없는 같은 identity를 `new_join` mode로 재사용한다. 실패/재시작은 abort cursor 완료 전 새 attempt를 거부하며, partial-active index와 row aggregate가 시작 전과 같아진 뒤 terminal audit로 끝난다. 실제 참여 이력을 가진 row나 persistent episode를 이 경로에서 hard delete/cascade하지 않는다.
- 과거 workspace/channel owner·admin이었다는 이유로 권한을 복원하지 않는다. new/rejoin은 새 invite가 정한 workspace role과 그로부터 허용된 public-channel role만 쓰고, reinstate만 suspension 전 role을 보존한다. current-state row의 `left_at`을 재가입 preparation이 지울 수 있으므로 이전 leave episode의 정본은 append-only `workspace.left` audit다. `workspace.rejoined` audit는 같은 member id, 새 workspace/channel role, 새 join 시각과 이전 leave event를 결속한다. v0는 다회 channel episode 분석 테이블을 약속하지 않는다.

**부분 rollout 중 join/reinstate fail-closed:** 첫 안전화 goal은 현재 live인 `POST /v1/join`의 deleted-human branch를 shared fleet/DB gate와 공용 lock으로 먼저 닫고, 신규 identity join은 legacy 동기 경로로 유지한다. authority episode/cursor schema를 expand하고 신규+same-ID 202 client가 배포된 뒤 old join writer/client 0에서만 모든 human `/join`을 bounded mode로 flip한다. D2 capability fence, ADR-0162 notification, ADR-0163 presence, episode personal rail이 landing·drain되고 inventory `unclassified=0`이기 전에는 same-ID rejoin을 열지 않는다. future admin reinstate는 dormant route/spec→admin UXUI→old client/writer 0 뒤 별도 human-only flag로 연다. 이 창에는 identity/history 삭제나 새 member ID 우회를 하지 않으며 old join/reinstate writer가 gate를 우회하지 못하도록 DB generation fence를 둔다.

human reinstate와 agent credential bootstrap은 같은 경로가 아니다. human은 D3의 202/bounded preparation과 token-free final 200 뒤 자신의 first-party login/reauth로 current episode token을 얻는다. agent는 first-party login이 없고 ADR-0101의 one-time pairing bearer만 사용하므로 v0 admin reinstate는 agent target에 stable 409 `agent_repairing_required`와 side effect 0을 반환한다. 별도 Accepted pairing/reissue goal이 admin proof, 새 authority episode, 1회 노출 `agent_bearer`, old bearer 재사용 0을 함께 구현하기 전에는 agent를 active-but-credentialless로 만들거나 admin lifecycle response에 bearer를 싣지 않는다.

## Consequences

- (+) 탈퇴가 메시지 저자·채널 소속 증거를 파괴하지 않고, 기존 `left_at IS NULL` 인가 모델과 정렬된다.
- (+) 마지막 owner, 토큰 revoke, membership 종료가 하나의 lock/transaction 계약이 되어 부분 탈퇴와 orphan workspace가 없다.
- (+) 재가입은 같은 사람의 과거 대화를 보존하면서도 이전 private/DM·관리자 권한을 조용히 복원하지 않는다.
- (+) token 밖 push device·WorkHost·agent ownership·explicit grant·upload·personal rail도 leave transaction/authority episode에 결속되어 같은 member ID 재활성화로 되살아나지 않는다.
- (-) 모든 기기의 해당 workspace REST 세션은 즉시 끝나고 기존 realtime connection은 정상 disconnect 또는 최대 65초 expiry로 닫힌다. 실수로 leave한 사용자는 새 invite와 새 login이 필요하다.
- (-) current-state row 재활성화만으로는 다회 channel episode 분석을 제공하지 않는다. workspace-level audit가 v0 이력 원장이다.
- (-) episode-aware notification/presence/client와 closed inventory가 모두 배포되기 전에는 재활성화가 fail-closed한다. 최종 cutover 뒤 신규 human join도 same-ID rejoin·human reinstate와 함께 channel materialization 동안 202/retry 단계를 거친다. 가용성보다 권한 부활 방지와 bounded transaction을 우선하는 명시적 rollout 비용이다.

## Schema / API impact

- channel membership을 append-only episode 테이블로 바꾸지는 않는다. 본 ADR 소유 self-leave 변경은 기존 `membership.left_at`과 partial active index를 유지하며 hard DELETE 대신 bounded close cursor로 logical close를 materialize하는 것이다. 알림 causal fence용 `channel.membership_generation`과 `membership.access_generation`의 schema/writer fence는 ADR-0162 migration이 소유하고, 본 ADR은 `member.status='preparing'` 호환 상태, `membership.authority_episode_id`, close/new-join/rejoin/reinstate/abort cursor+backup과 join/leave primitive를 소유한다. `workspace_membership.id`는 current row identity, 영속 `workspace_authority_episode`는 재활성화마다 새로 생기는 최소 capability ledger, `workspace_membership.authority_episode_id`는 current pointer, workspace `authority_generation`은 causal snapshot용 단조 counter, `member`는 보존 identity, audit는 role·leave/suspend/reinstate/rejoin 서사 원장이다. capability별 immutable episode/channel-access snapshot은 각 소유 ADR migration에서 추가하고 membership 삭제 cascade 대신 current-pointer/episode-state claim을 사용한다.
- S-6b security floor는 `push_token.registration_authority_episode_id` nullable same-tenant FK를 먼저 추가하고 기존 token을 당시 current episode로 backfill하며 증명 불가 row는 invalidate한다. register/same-row re-register/lifecycle invalidation writer와 live push target reader를 episode-aware로 전환해 old process/lease 0→legacy NULL/binding write red→NULL 0/FK validate 뒤 live behavior를 연다. ADR-0162/C-1a는 이 column을 재생성하지 않고 `registration_generation`, immutable dispatch snapshot과 token-state transition fence를 확장한다.
- S-6b는 ADR-0164가 정한 `workspace_membership.avatar_operator_generation bigint`를 expand/backfill하고 모든 현행/future role writer가 같은 lock에서 **owner/admin capability 상실 때 정확히 +1, capability 유지·획득 때 불변**이 되도록 dormant DB transition fence를 준비한다. old role writer process·lease 0 뒤 fence를 연다. avatar cleanup cursor는 `(workspace,member,authority_episode,old_avatar_operator_generation)`에 고정한다. C-4a가 avatar pre-intent의 immutable generation snapshot을 추가한다. 다른 subsystem은 자기 capability-loss 의미가 같다고 별도 ADR/goal에서 증명하지 않는 한 이 counter를 재사용하지 않는다.
- `DELETE /v1/workspaces/{workspaceId}/members/me`는 유지한다. 200 응답에 `memberId`, `status:"deleted"`, canonical `leftAtMs`를 싣고 “해당 workspace의 모든 서버 세션 revoke”를 OpenAPI에 명시한다. 401=revoked/invalid token, 403=active member 아님, 409=last owner이며 409는 side effect 0이다.
- expand 동안 신규 identity join은 legacy 동기 계약을 유지하지만 bounded-join activation 뒤 모든 human `/join`은 준비 중 202 `reactivation_pending`/`Retry-After`/opaque attempt ID를 반환하고 token은 0이다. stable final retry의 200에서만 신규/same-ID `memberId`와 **새** token pair를 돌려준다. 이전 token 재활성화나 role/private-channel 자동 복구는 API 계약이 아니다. `member.status='preparing'`과 cursor/backup schema는 nullable/output-off expand로 넣고 web/mobile/web-legacy가 신규+same-ID 202 retry를 지원하며 old incompatible usage가 0이 되기 전에는 bounded-join flag를 열지 않는다.
- 현재 Rust에 mount되지 않은 workspace role PATCH, channel self-leave/role PATCH, admin suspend/reinstate/remove와 ban list/create/delete는 이 ADR의 Accepted 전환만으로 공개 API가 되지 않는다. 먼저 published OpenAPI/generated surface를 honest-unavailable로 맞춘다. 별도 parity goal이 strict 인가·last-owner/DM/ban 불변식, D1/D2 canonical transaction, channel access generation, episode rotation, audit와 runtime parity를 함께 구현하기 전에는 route를 mount하거나 2xx 제공을 주장하지 않는다. remove의 Accepted ADR-0128 `{ban:true,reason}` 옵션은 remove와 같은 transaction에서 canonical ban ledger/audit를 써야 하므로 workspace authority parity가 그 primitive를 선행 소유하고, standalone ban 표면은 후속 goal이 재사용한다. human reinstate는 위 activation gate를 우회할 수 없고 준비 중 202/final 200 모두 target token 0인 `MembershipLifecycleResponse`만 반환하며 대상 사용자 credential은 후속 first-party login/reauth만 발급한다. agent reinstate는 별도 pairing/reissue 계약 전 409+side effect 0이다.

## Verification

1. 실제 PG에서 leave authority transaction은 channel 수와 무관하게 current pointer/episode를 즉시 닫고 cursor 한 건만 쓴다. worker 0/1/500/501/5,000 fixture의 transaction당 channel UPDATE/lock은 최대 500이고 crash/resume 뒤 row 수와 id는 같다. old cursor는 여전히 ended episode에 묶인 row만 같은 canonical 시각으로 닫고, 새 preparing/active episode로 재결속된 public row를 닫지 않는다. 반복 실행은 최초 시각을 보존한다. NOBYPASS worker raw cross-tenant access는 실패하고 bounded claim+tenant settle만 green이다.
2. 과거 message author/display가 유지되고 떠난 bearer로 REST·새 subscribe·realtime grant가 실패한다. 모든 access/refresh가 401이며 다른 workspace 세션은 정상이다. 정상 broker에서는 disconnect effect가 멱등 처리되고, broker 장애에서도 legacy token drain 뒤 기존 구독이 65초 안 종료된다.
3. barrier 동시성 test에서 두 active owner의 동시 leave는 한 건 성공·한 건 409, owner 수 ≥ 1이다. ownership transfer/강등과의 race도 같은 lock 순서로 결정되며 거절 transaction은 token/audit/membership write 0이다.
4. leave와 join barrier race는 같은 lock으로 직렬화되어 `member.status`와 `workspace_membership`이 엇갈리지 않는다. 신규 join·same-ID 재초대·human reinstate의 첫/중간 요청은 202+target token 0이고, 0/1/500/501/5,000 대상-channel cursor가 page당 최대 500으로 resume된다. preparing 중 old/new channel subscription은 모두 거부되고, cursor 완료·stable channel-set 재확인 뒤 final retry가 authority counter를 다시 bump해 active generation을 봉인한 경우만 활성화된다. new join/rejoin final 200은 새 workspace membership+authority episode와 새 token이고, human reinstate final 200은 기존 membership row+새 episode지만 target token 0이다. `preparing → message candidate source → final activation → judgment/claim` barrier에서 그 candidate의 intent/dispatch는 새 episode에 0이다. 후속 사용자 login만 reinstated episode의 token/subject를 발급하며 old connection/grant는 거부된다. agent reinstate는 `agent_repairing_required` 409, member/episode/token/audit side effect 0이고 old bearer도 계속 거부된다. new join/rejoin은 live public channel만 새 `access_generation`으로 열고 old channel owner/admin role은 현재 invite의 safe mapping으로 낮아지며, same-ID rejoin의 private/DM `left_at`은 남긴다. reinstate는 suspend 전 live였던 public/private/DM과 role만 새 episode에 재결속하고 신규 public channel을 자동 추가하지 않는다. final invite/ban/admin 재검사 deny와 expiry를 501/5,000-row 중간에서 발생시켜 episode 즉시 ended/token 0, abort page 최대 500, existing row의 이전 `left_at`/role/episode/access와 partial-active-index 완전 복원, never-active provisional channel row만 제거, provisional member/ended episode 보존, 재시작 후 aggregate 동일을 검증한다. old channel owner/admin→leave→member invite rejoin은 privileged channel role 0이다. message source 뒤 public channel join/rejoin은 과거 notification candidate 대상이 되지 않고, judgment 뒤 channel leave/rejoin은 pending transport를 claim하지 못한다. audit에 old/new episode와 과거 authority `joined_at`이 이어진다.
5. leave 전 grant+새 token, old personal connection, active push token, WorkHost 서명, agent owner edit/work-session, explicit memory grant, pending avatar complete, pending notification dispatch, auto-approve/terminal attach를 각각 재가입 뒤 시도해 모두 즉시 거부인지 검증한다. 특히 push cleanup worker를 멈춘 채 leave→rejoin→새 candidate를 만들면 old registration-episode token target/claim은 0이고, current episode로 명시 재등록해 generation을 올린 뒤만 성공해야 한다. 각 subsystem에 0/1/500/501/5,000 child를 만들고 authority 종료 transaction의 child lock/UPDATE가 0, cursor head 수가 schema 상수, cleanup transaction당 최대 500이며 crash/resume 뒤 terminal materialization이 완료되는지 확인한다. agent suspend/remove는 진행 중 run이 DB에서 즉시 새 step claim 불가이고 durable stop retry 뒤 terminal이며, slow worker/duplicate stop에서도 old episode run이 재개되지 않는다. 옛 connection은 새 episode read-state/notification/presence rail event를 0건 받는다. 새로 명시 등록·assign·grant·발급한 capability만 성공한다. 다른 viewer의 presence cache는 leave invalidation으로 지워지고 delayed event가 rejoin 상태를 지우지 않는다.
6. rollout matrix는 nullable expand/backfill 동안 정상 workspace create·legacy 신규 human join·agent provisioning·login/refresh/channel join이 끊기지 않되 same-ID reactivation과 async close는 계속 닫혀 있음을 보인다. 모든 current membership/live token/active channel binding NULL 0, writer/reader inventory generation-2, old process·lease 0 뒤 DB contract flip이 legacy NULL write를 red로 만들어야 한다. old private/DM row가 `left_at IS NULL`이어도 current episode binding이 다르면 모든 channel-auth reader에서 0 row/403이고 구 reader 한 개라도 남으면 close/join flag가 거부된다. 신규+same-ID 202-retry client와 bounded join writer가 배포되고 old join writer/client 0일 때만 `/join`을 cursor mode로 flip한다. terminalizer/notification/presence/personal-rail 중 하나라도 미배포면 same-ID join은 계속 fail-closed하고, admin reinstate는 dormant route/client/old writer 0 뒤 별도 flag 전까지 503이다. agent reinstate는 모든 조건이 green이어도 별도 pairing/reissue 계약 전 409다.
7. cross-tenant leave·rejoin은 0 row이고 OpenAPI/runtime 응답·오류가 일치한다. `[rust]` gate와 PG18 workspace-membership suite가 green이다.

## Rollback

문제가 생기면 먼저 bounded human join과 reinstate gate를 닫아 새 authority episode 활성화를 멈추고, 그 뒤 leave/admin lifecycle route를 필요한 만큼 닫는다. old writer가 drain된 뒤에는 신규 join을 unbounded legacy transaction으로 되살리지 않고 일시 fail-closed한다. personal rail을 내릴 때는 ADR-0163의 gate-closed→dual-publish→history 0인 새 opaque legacy generation→양쪽 connection drain→generated-legacy-only 순서를 지키며 과거 168시간 recovery를 가진 member-only exact name은 재사용하지 않는다. 이미 기록된 `left_at`, audit와 revoked token은 복구·삭제하지 않는다. token revoke는 되돌릴 수 없으므로 사용자는 안전화된 새 invite/login으로만 돌아온다. rollback 때문에 membership hard delete, old writer 복원이나 자동 권한 복원을 수행하지 않는다.

## ADR-0161 부분 supersede

본 ADR이 Accepted 되면 **ADR-0161 D4의 “멤버십 종료”와 self-leave 시 해당 workspace 세션 제거 상세를 대체**한다. D6의 일반 세션 저장·전환·전 세션 로그아웃 계약은 대체하지 않는다. endpoint, 마지막 owner 409, D5-A의 workspace-scoped 세션과 재진입은 재초대라는 상위 결정은 유지한다. ADR-0128 D3의 “전 채널 membership 제거”는 물리 DELETE가 아니라 access를 끝내는 logical close(`left_at`)로 정제하고, D4 self-service·owner 불변식·token revoke는 유지한다. 멀티 워크스페이스 목록·전역 identity·일반 세션 전환은 ADR-0161 그대로이며 재개봉하지 않는다.
