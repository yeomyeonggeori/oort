## 델타 (이 검토로 적용하는 수정)

### 델타 1 — MOMO-526에 `memory_visibility_grant` 복원 (갭 1)
성재 원문 "1급 멤버지만 **권한**은 있을 수도"의 데이터 기반. 스코프 4단은 기본 격리만 제공 — 역할·에이전트별 차등 접근(예: 특정 에이전트에게 다른 멤버 스코프 열람 허용, 민감 메모리의 명시 grant)은 grant 원장이 필요하다.
- **적용**: 526 스키마에 `memory_visibility_grant(id, workspace_id, memory_id FK, grantee_kind ∈ member|agent, grantee_id, granted_by, created_at, revoked_at?)` + RLS FORCE 추가. v0 소비 최소화: **528 서빙 필터에서 "기본 스코프 ∪ 유효 grant"로 검색 범위 확장 1줄** — 관리 UI는 529 범위에 가산(grant 목록·회수). 추출 워커는 grant 무관(쓰기 없음).
- 진행 중인 596 worker 산출물에 grant가 없으면 검수에서 델타 반영(마이그레이션 가산은 소형).

### 델타 2 — 웹 Work 관전을 실행 큐에 등재 (갭 2)
CTO 원문 "다양한 직군이 하나의 화면"의 전제 = 브라우저 접근. 진단 권고가 큐 편성에서 유실됐다.
- **적용**: **W-6(웹 Work 관전 v0)** 백로그 등재 — 세션 카드 리스트(read-only)+세션 스레드 관전+observer 터미널(read-only, 516 capability 소비)+diff 카드(518 props 계약 공용이라 웹 렌더 추가). 착수 시점: Wave U-1(518) 랜딩 후(props 계약 확정 뒤) — 웹은 track/engine 소관이므로 내 fleet 큐.

### 델타 3 — 문서·첨부 컨텍스트를 0129 후속으로 명기 (갭 3)
"회사 단위 **데이터**"의 절반(첨부·Drive 문서·웹훅 유입물)은 v0 추출원이 아님 — 의도적 축소임을 기록하고 경로를 남긴다.
- **적용**: 0129 Consequences에 후속 한 줄 — "추출원 확장(첨부 텍스트·Drive 문서·웹훅 payload)은 v1 — memory_source_ref가 message_id 외 source_kind를 받도록 확장 여지 확보(v0 스키마에 source_kind 컬럼 선반영 권고, 값은 'message' 고정)". 526 델타에 `source_kind text NOT NULL DEFAULT 'message'` 1컬럼 선반영(마이그레이션 재작업 방지).

## 판정하지 않은 것 (범위 밖 확인)
- Blaxel 관련 전부(성재 지시로 제외 — 캔슬 결정은 §5 기록 유지).
- AMP 스펙 초안 시점(12~18개월 창) — 전략 판단이며 현 시점 검증 불가, "창은 데드라인 아님" 명시가 건전.
