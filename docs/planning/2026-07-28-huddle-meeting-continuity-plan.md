# 허들 · 회의 지능 · 원격 세션 연속성 — 현황 실사와 작업 계획

- 작성: 2026-07-28 (Fable). 발단: 성재 질문 3건 — ①허들 작업이 포함돼 있나 ②음성 회의록·액션아이템은 ③T3 원격 클라우드 터미널이 기기 간 auto sync 되나.
- **결론 먼저: ①은 서버만 살아 있고 화면이 없다. ②는 설계만 있고 코드 0건. ③은 절반만 된다 — 세션 목록과 작업 스레드는 동기화되지만 터미널 화면은 안 되고, T3 자체가 아직 없다.**
- 근거는 전부 코드에서 확인했다(2026-07-28, `main@99ea7330`).

---

## 1. 허들 — 서버는 완성, **출하 클라이언트에 화면이 없다**

ADR-0122(음성 허들과 회의 지능) Accepted. 슬라이스 4개가 랜딩했다:

| 슬라이스 | 내용 | 상태 | 근거 |
|---|---|---|---|
| V-1 | huddle 스키마 + 수명주기 REST + LiveKit JWT | **랜딩** | `server/Migrations/016_huddle.sql`, `HuddleRoutes.swift`(start/join/leave/active 4종) |
| V-2 | compose livekit profile + TURN/버전 핀 | **랜딩** | `verify_huddle_livekit.sh` |
| V-3 | **macOS** 허들 UI | **랜딩** | MOMO-471 |
| V-3b | **iOS** 허들 참가 | **랜딩** | MOMO-473 |

**문제**: V-3/V-3b가 붙은 두 클라이언트가 지금 출하 경로가 아니다.
- macOS SwiftUI는 **2026-07-25 은퇴**했다(기본 다운로드 = momo-next Tauri).
- iOS 킷은 **ADR-0137로 버그픽스 전용 동결**이고 RN 전환 대기다.
- **웹/Tauri에는 허들 코드가 0건이다**(`clients/web/src`·`clients/desktop`에서 `huddle` 검색 0).

즉 **서버는 허들을 완전히 지원하는데 지금 사람이 쓰는 앱에서는 허들을 시작할 수도 참가할 수도 없다.**
#838(플러그인 마켓플레이스 복원)과 **정확히 같은 유실 클래스**다 — macOS 은퇴 때 포팅되지 않은 기능.

## 2. 회의록·액션아이템 — **설계만 있고 구현 0건**

ADR-0122가 두 슬라이스를 남겨뒀고 **둘 다 티켓조차 발급되지 않았다**(`BUILD_TICKETS.md`에 항목 없음, 코드 0건):

| 슬라이스 | 내용 | 상태 |
|---|---|---|
| V-4 | Egress + 전사(transcription) job 파이프라인 | **미착수** |
| V-5 | 회의록 Work 자동화 — 요약/액션아이템 | **미착수** |

ADR-0122가 이미 정해둔 설계(재사용할 것):
- **신규 인프라 0**. 전사 완료 → 채널에 초대된 **에이전트의 `agent_run`** → 기존 승인/비용/감사 게이트 → 액션아이템(**담당자·기한·원문 anchor** 스키마)을 **허들 스레드에 아티팩트로 게시**.
- 즉 "실체는 프롬프트·출력 스키마·UX"이고 실행 개체는 이미 있다. Slack이 유료 add-on으로 막은 지점을 momo는 원장 게이트로 흡수한다는 것이 ADR의 논거.
- V-4의 선행 조건이던 **ADR-0113/0116(Drive 저장 계약)은 이미 랜딩**했으므로 지금은 막힌 게 없다.

**주의**: 녹음은 사람 목소리다. 동의 기록은 V-1 스키마에 자리가 있지만(ADR-0122 V-1 "동의 기록"), **실제 동의 UX와 보존기간은 아직 결정된 바 없다.** `legal/privacy-policy.md`가 빈칸인 상태와 직접 얽힌다.

## 3. 원격 세션 연속성 — **절반은 이미 되고, 절반은 설계상 안 된다**

성재 시나리오: *폰으로 작업하다 노트북을 열고 momo를 켜면, 원격에 떠 있는 내 터미널의 개수와 내용이 auto sync 되고 작업 내역이 트래킹된다.*

### 3-1. 이미 되는 것 (Postgres가 SoT이므로 공짜로 따라온 것)

- **세션 목록은 기기와 무관하게 같다.** `work_session`이 PG에 있고 `GET /v1/workspaces/{ws}/work-sessions?active=1`이 그것을 준다. 웹 클라이언트에 `WorkPanel`·`WorkSessionDetail`·`useWorkSessions`가 이미 붙어 있다. → **"떠 있는 세션의 개수"는 지금도 노트북에서 그대로 보인다.**
- **작업 내역 트래킹도 이미 있다.** ADR-0114 D2 "세션=스레드" — 세션의 큐레이션된 진행 로그가 **채널 메시지로 durable하게** 남는다. 기기를 바꿔도 스레드를 읽으면 무슨 일이 있었는지 복원된다.
- **호스트 등록·heartbeat·online 판정**이 있다(`WorkHostRoutes`, `WorkHostDaemon`).
- **관전 터미널**이 웹에 있다(`ObserverTerminal.tsx`, `observerStream.ts`) — 살아 있는 세션에 붙어 실시간 바이트를 본다.

### 3-2. 안 되는 것 ①: **터미널 "내용"은 동기화되지 않는다 (설계상)**

- ADR-0125 D10과 `TerminalAttachRoutes.swift` 주석이 명시한다 — **momo 서버는 바인딩을 인증·영속할 뿐 바이트 스트림 연산을 구현하지 않는다.** stdout/stderr는 **클라이언트와 호스트 엔드포인트 사이에서만** 흐른다.
- 그리고 **호스트 데몬에 스크롤백 버퍼가 없다**(`workers/WorkHostDaemon/Sources`에서 replay/backlog 0건. `readBuffer`는 JSON-RPC 줄 파서지 터미널 히스토리가 아니다).
- → **두 번째 기기에서 붙으면 "붙은 순간부터"의 바이트만 보인다.** 폰에서 보던 화면이 노트북에 그대로 뜨지 않는다.
- 이건 버그가 아니라 **결정의 결과**다(서버가 실행 내용을 보관하지 않는다). 바꾸려면 **ADR 개정이 필요하다** — 아래 D1.

### 3-3. 안 되는 것 ②: **T3(클라우드 호스트) 자체가 아직 없다**

- ADR-0136(momo Cloud 프로비저너 + 크레딧 원장) **Accepted 2026-07-26**이지만 **코드 0건**이다. 크레딧/활성시간 원장 마이그레이션도 없다(`server/Migrations`에 credit/cloud/provision 없음).
- 진행을 막고 있는 것은 **E2B 키 부재 — 성재 조달 대기**(이전 저널 기록, `.env`에 BLAXEL/DAYTONA만 있음).
- → 지금 존재하는 호스트는 **T1(로컬)·T2(self-host 데몬)**뿐이다. "원격 클라우드에 떠 있는 내 터미널"은 아직 만들 대상이 없다.

### 3-4. 안 되는 것 ③: **"내 세션"이라는 1급 표면이 없다**

- 목록은 **워크스페이스 범위**다. "지금 나에게 붙어 있는 세션 N개, 각각 어느 호스트에서, 마지막 활동 언제" 같은 **개인 연속성 화면**은 없다.
- 호스트가 사라졌을 때의 재개 흐름은 ADR-0125 D11에 **설계돼 있으나**(재개 카드 + `resumed_from_session_id` 계보 + git 계보 재개), 파생 티켓 **MOMO-519(엔진)·MOMO-520(웹)이 아직 발급되지 않았다.**
- 참고: D11이 정한 재개 의미론은 **PTY 상태 이전이 아니라 git 계보 재개**다(마지막 push된 커밋에서 새 세션 + 이전 스레드 요약 주입, 미커밋 작업 손실은 명시 고지).

## 4. 성재 결정이 필요한 것 (ADR 사안 — 착수 전 선행)

### D1. 터미널 출력을 momo가 보관하는가 — **ADR-0125 D10 개정 여부**
"폰에서 보던 화면이 노트북에 그대로"를 만들려면 **누군가 스크롤백을 보관**해야 한다. 선택지:

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 호스트 로컬 링버퍼 + 재연결 시 replay** | 서버는 여전히 바이트를 안 본다. 호스트가 최근 N KB를 들고 있다가 attach 때 흘려준다 | 서버 불변식 유지. **호스트가 죽으면 같이 사라진다.** T3에서는 샌드박스 볼륨에 붙음 |
| B. 서버가 스크롤백을 영속 | 어느 기기에서도 완전 복원 | **ADR-0125 D10 정면 개정.** 실행 출력에 비밀이 섞인다(토큰·키). 저장·감사·삭제 정책 필요 |
| C. 안 한다 | 현행 유지. 연속성은 "세션 스레드 요약"이 담당 | 성재 시나리오 미충족 |

**권고: A.** 서버 불변식(바이트 비경유)을 지키면서 체감의 대부분을 준다. B는 "momo는 당신 실행 내용을 보관하지 않는다"는 보안 문서의 주장(`docs/security/README.ko.md`)을 바꾸는 일이라 별건으로 다뤄야 한다.

### D2. 회의 녹음 동의·보존 — **ADR-0122 증보**
전사를 하려면 녹음이 필요하고, 녹음은 사람 목소리다. 동의 UX·보존기간·삭제 경로·참가자 열람 범위가 미결이다. `legal/privacy-policy.md` 빈칸과 함께 다뤄야 한다.

### D3. T3 착수 시점 — **E2B 키(성재 조달)**
키가 없으면 프로비저너를 만들어도 실동 검증이 안 된다. 키 조달 전에는 T1/T2 위에서 연속성만 먼저 만드는 것이 낫다.

## 5. 작업 계획 (권장 순서)

**결정 불요분을 먼저 낸다** — 이번 배치에서 쓴 방식 그대로.

| # | 작업 | 선행 | 비고 |
|---|---|---|---|
| **1** | **웹 허들 복원**(시작/참가/나가기·live 배지·참가자·503 미구성 상태) | 없음 | 서버 4 REST 완비. macOS V-3가 참조 구현. **#838과 같은 복원 작업** |
| **2** | **내 세션 연속성 표면**(개인 범위 활성 세션 목록·호스트·마지막 활동·바로 붙기) | 없음 | 기존 `work-sessions` + `work-hosts`로 파생 가능. 새 경계 없음 |
| **3** | **호스트 상실 → 재개 카드**(MOMO-519 엔진 / MOMO-520 웹) | 없음(ADR-0125 D11 Accepted) | git 계보 재개. 미커밋 손실 고지 포함 |
| **4** | **터미널 재연결 replay** | **D1** | A안이면 호스트 데몬 링버퍼 + attach replay |
| **5** | **V-4 전사 파이프라인** | **D2** | Drive 저장 계약은 이미 랜딩 |
| **6** | **V-5 회의록·액션아이템 Work** | 5 | 담당자·기한·원문 anchor 스키마 + 허들 스레드 아티팩트 게시 |
| **7** | **T3 프로비저너 + 크레딧 원장**(ADR-0136) | **D3** | 키 조달 후 |

**1·2·3은 지금 바로 티켓으로 낼 수 있다.** 4~7은 위 결정이 선행한다.

## 6. 이 문서가 정정하는 오해

- "허들은 안 만들었다" → **아니다. 서버·인프라·macOS·iOS까지 만들었다.** 다만 지금 쓰는 앱에 화면이 없다.
- "회의록도 어딘가 있을 것" → **없다. ADR 설계만 있다.**
- "원격 세션은 아무것도 안 된다" → **아니다. 세션 목록과 작업 스레드는 이미 기기 간에 같다.** 안 되는 것은 터미널 화면 복원과 T3 존재 자체다.
