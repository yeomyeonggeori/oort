## 3. 원격 세션 연속성 — **절반은 이미 되고, 절반은 설계상 안 된다**

성재 시나리오: *폰으로 작업하다 노트북을 열고 momo를 켜면, 원격에 떠 있는 내 터미널의 개수와 내용이 auto sync 되고 작업 내역이 트래킹된다.*

### 3-1. 이미 되는 것 (Postgres가 SoT이므로 공짜로 따라온 것)

- **세션 목록은 기기와 무관하게 같다.** `work_session`이 PG에 있고 `GET /v1/workspaces/{ws}/work-sessions?active=1`이 그것을 준다. 웹 클라이언트에 `WorkPanel`·`WorkSessionDetail`·`useWorkSessions`가 이미 붙어 있다. → **"떠 있는 세션의 개수"는 지금도 노트북에서 그대로 보인다.**
- **작업 내역 트래킹도 이미 있다.** ADR-0114 D2 "세션=스레드" — 세션의 큐레이션된 진행 로그가 **채널 메시지로 durable하게** 남는다. 기기를 바꿔도 스레드를 읽으면 무슨 일이 있었는지 복원된다.
- **호스트 등록·heartbeat·online 판정**이 있다(`WorkHostRoutes`, `WorkHostDaemon`).
- **관전 터미널**이 웹에 있다(`ObserverTerminal.tsx`, `observerStream.ts`) — 살아 있는 세션에 붙어 실시간 바이트를 본다.

### 3-2. 안 되는 것 ①: **터미널 "내용"은 동기화되지 않는다 (설계상)**

- ADR-0125 D10과 `TerminalAttachRoutes.swift` 주석이 명시한다 — **oort 서버는 바인딩을 인증·영속할 뿐 바이트 스트림 연산을 구현하지 않는다.** stdout/stderr는 **클라이언트와 호스트 엔드포인트 사이에서만** 흐른다.
- 그리고 **호스트 데몬에 스크롤백 버퍼가 없다**(`workers/WorkHostDaemon/Sources`에서 replay/backlog 0건. `readBuffer`는 JSON-RPC 줄 파서지 터미널 히스토리가 아니다).
- → **두 번째 기기에서 붙으면 "붙은 순간부터"의 바이트만 보인다.** 폰에서 보던 화면이 노트북에 그대로 뜨지 않는다.
- 이건 버그가 아니라 **결정의 결과**다(서버가 실행 내용을 보관하지 않는다). 바꾸려면 **ADR 개정이 필요하다** — 아래 D1.

### 3-3. 안 되는 것 ②: **T3(클라우드 호스트) 자체가 아직 없다**

- ADR-0136(oort Cloud 프로비저너 + 크레딧 원장) **Accepted 2026-07-26**이지만 **코드 0건**이다. 크레딧/활성시간 원장 마이그레이션도 없다(`server/Migrations`에 credit/cloud/provision 없음).
- ~~진행을 막고 있는 것은 E2B 키 부재~~ → **정정: 키는 이미 있다**(상단 정정 2). 막는 것은 없고 **미착수**일 뿐이다.
- → 지금 존재하는 호스트는 **T1(로컬)·T2(self-host 데몬)**뿐이다. "원격 클라우드에 떠 있는 내 터미널"은 아직 만들 대상이 없다.

### 3-4. 안 되는 것 ③: **"내 세션"이라는 1급 표면이 없다**

- 목록은 **워크스페이스 범위**다. "지금 나에게 붙어 있는 세션 N개, 각각 어느 호스트에서, 마지막 활동 언제" 같은 **개인 연속성 화면**은 없다.
- ~~호스트 상실 재개 흐름은 설계만 있고 티켓 미발급~~ → **정정: 전부 랜딩돼 있다**(상단 정정 1). sweep→orphaned→푸시→resume REST→계보가 실동한다.
- 참고: D11이 정한 재개 의미론은 **PTY 상태 이전이 아니라 git 계보 재개**다(마지막 push된 커밋에서 새 세션 + 이전 스레드 요약 주입, 미커밋 작업 손실은 명시 고지).

## 4. 성재 결정이 필요한 것 (ADR 사안 — 착수 전 선행)

### D1. 터미널 출력을 oort가 보관하는가 — **ADR-0125 D10 개정 여부**
"폰에서 보던 화면이 노트북에 그대로"를 만들려면 **누군가 스크롤백을 보관**해야 한다. 선택지:

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 호스트 로컬 링버퍼 + 재연결 시 replay** | 서버는 여전히 바이트를 안 본다. 호스트가 최근 N KB를 들고 있다가 attach 때 흘려준다 | 서버 불변식 유지. **호스트가 죽으면 같이 사라진다.** T3에서는 샌드박스 볼륨에 붙음 |
| B. 서버가 스크롤백을 영속 | 어느 기기에서도 완전 복원 | **ADR-0125 D10 정면 개정.** 실행 출력에 비밀이 섞인다(토큰·키). 저장·감사·삭제 정책 필요 |
| C. 안 한다 | 현행 유지. 연속성은 "세션 스레드 요약"이 담당 | 성재 시나리오 미충족 |

**권고: A.** 서버 불변식(바이트 비경유)을 지키면서 체감의 대부분을 준다. B는 "oort는 당신 실행 내용을 보관하지 않는다"는 보안 문서의 주장(`docs/security/README.ko.md`)을 바꾸는 일이라 별건으로 다뤄야 한다.

### D2. 회의 녹음 동의·보존 — **ADR-0122 증보**
전사를 하려면 녹음이 필요하고, 녹음은 사람 목소리다. 동의 UX·보존기간·삭제 경로·참가자 열람 범위가 미결이다. `legal/privacy-policy.md` 빈칸과 함께 다뤄야 한다.

### D3. T3 착수 시점 — **E2B 키(성재 조달)**
키가 없으면 프로비저너를 만들어도 실동 검증이 안 된다. 키 조달 전에는 T1/T2 위에서 연속성만 먼저 만드는 것이 낫다.

## 5-1. 성재 결정 (2026-07-28) — D1·D2·D3 확정

### D1 — **세션은 클라이언트와 무관하게 완료까지 돌고, 끝나면 idle로 살아 있다가, 돌아오면 이어서 쓴다**

성재 지시: *"폰이든 맥이든 요청하면 닫더라도 완료까진 돌아야지. 작업이 끝나면 감지해서 idle 상태로 있다가, 맥북 열고 들어오면 다시 작업 재개할 수 있는 것처럼."*

**이건 스크롤백 보관 여부(초판 D1)보다 큰 요구다.** 초판은 "화면을 어떻게 복원하나"만 물었는데, 실제 요구는 **세션의 수명이 클라이언트와 분리되는 것**이다. 다시 실사한 결과:

| 요구 | 현재 | 판정 |
|---|---|---|
| 클라이언트를 닫아도 완료까지 실행 | 호스트가 T2 데몬/T3 샌드박스면 **성립**(실행 주체가 호스트다). T1(로컬 맥 앱)이면 앱과 함께 죽는다 | **호스트 티어에 달렸다** |
| 호스트가 죽었을 때의 처리 | **이미 있다** — sweep이 `orphaned`로 전이, `resume_offer` 푸시, `resume` REST, `resumed_from_session_id` 계보 | **완성** |
| 작업 완료를 감지 | `exit_code`와 `ended` 전이가 있다 | **감지는 된다** |
| 완료 후 **idle로 살아 있기** | **없다.** 상태는 `running \| orphaned \| ended`뿐이고 **완료 = `ended` = 세션 종료**다 | **공백 ①** |
| 돌아왔을 때 **같은 세션에 다시 붙기** | 살아 있는 세션엔 붙을 수 있으나, 위 때문에 완료된 세션은 붙을 대상이 없다 | **공백 ①과 동일** |
| 붙었을 때 **직전 화면 복원** | 없다(서버는 바이트 비경유, 호스트 데몬에 버퍼 0건) | **공백 ②** |

→ **결정: 공백 ①·② 둘 다 채운다.** 스크롤백은 **호스트 로컬 링버퍼(초판 A안)** — 서버가 실행 출력을 보관하지 않는다는 불변식과 보안 문서의 주장을 지킨다.

**주의(설계 시 반드시 반영)**: ADR-0125 D11이 정한 재개는 **git 계보 재개**(PTY 상태 이전 없음)다. D1이 요구하는 "같은 세션에 다시 붙기"는 **PTY가 살아 있는 경우**의 이야기라 **다른 경로**다. 둘은 대체가 아니라 보완이다 — 호스트가 살아 있으면 재부착, 죽었으면 계보 재개.

**T3에서의 비용**: 유휴 세션을 살려두는 것은 곧 과금이다. 파일럿 실측이 이미 답을 갖고 있다(`research/17-work-host-fabric/01`): **E2B는 명시적 pause/resume(keep_memory)이 sub-second**, **Blaxel은 0-컴퓨트 스탠바이 무제한 + 25ms 재개**. 업계 기본 유휴 타임아웃 ~15분. → **idle = 프로세스를 죽이는 게 아니라 샌드박스를 pause**로 구현하면 비용과 체감을 동시에 잡는다. ADR-0136 크레딧 모델(활성시간 H)과 직결되므로 **"pause 중은 활성시간에 안 센다"를 원장에 정의**해야 한다.

### D2 — **회의록 스크립트 + 액션아이템 + 발화자 구분까지 제공. 필요하면 외부 솔루션 또는 자체 호스팅**

성재 지시대로 산출물 범위를 확정한다. 아래 §7의 실사 결과가 이 결정을 바꾸는 부분이 있어 함께 읽어야 한다 —
**발화자 구분은 이미 모델 없이 풀려 있고**(트랙 분리), **한국어 품질만이 진짜 미결**이다.

### D3 — **E2B 키는 이미 있다. T3는 막혀 있지 않다**

`.env`에 `E2B_API_KEY` 존재 확인. 초판의 "조달 대기"는 낡은 정보였다. → ADR-0136 프로비저너·크레딧 원장 착수 가능.

## 7. 허들 음성 기록·정리에 무엇을 쓰나 — 실사 (성재 질문)

성재 기억: *"예전에는 맥 내장 AI 사용을 추천했는지, 지금은 모바일이나 윈도우 쪽도 있어서."*
**기억이 맞고, 그 우려도 맞다. 다만 허들 전사는 처음부터 Apple 경로가 아니었다.** 두 개가 서로 다른 트랙이다.

### 7-1. 허들 전사(STT) — **whisper.cpp / faster-whisper, 서버측 사후 배치 job**

`research/15-platform-expansion/05` + ADR-0122 D2가 정한 것:

- **녹음**: LiveKit Egress(Apache-2.0, 별도 컨테이너, Redis 필요 — prod compose에 Centrifugo용 Redis가 이미 있어 공유/분리 검토만).
- **전사**: **whisper.cpp / faster-whisper(둘 다 MIT)**. GPU 없는 단일 VPS 전제라 **회의 종료 후 배치**(컨테이너 기동 → 전사 → 종료). 실시간 캡션은 v0/v1 제외.
- **발화자 구분**: **모델로 풀지 않는다.** LiveKit **참가자별 Track egress → 트랙별 전사 → 타임스탬프 병합**. 화자분리(diarization)를 **인프라에서 회피**한다(Mattermost 동일 접근).
  → **성재가 요청한 "발화자가 누구인지 감지"는 별도 솔루션 없이 이미 설계에 들어 있다.** 게다가 추정이 아니라 **트랙=사람이라 정확**하다.
- **요약·액션아이템 LLM**: **별도 모델 결정이 없다.** 전사 완료 → **채널에 초대된 에이전트의 `agent_run`**(BYOA) → 기존 승인·비용·감사 게이트 → 액션아이템(담당자·기한·원문 anchor)을 허들 스레드에 게시. **워크스페이스가 이미 쓰는 provider를 그대로 쓴다.**

### 7-2. Apple 내장 AI는 **다른 트랙**이었다 — 그리고 그 트랙은 지금 죽어 있다

성재가 기억하는 "맥 내장 AI"는 둘인데 **둘 다 허들 전사가 아니다**:

| 무엇 | 무엇에 쓰려던 것 | 현재 |
|---|---|---|
| **SpeechAnalyzer/SpeechTranscriber**(macOS 26, `ko_KR`) | **음성 입력(받아쓰기) 1순위**. 폴백 WhisperKit(MIT) | `research/13-redesign/01`의 권고. **미착수**(ROADMAP Phase 3) |
| **Foundation Models**(MOMO-130/131/174) | **온디바이스 컨텍스트 작업** — 요약·분류·컨텍스트 압축·PII redaction·오프라인 초안 | 랜딩. 단 **"서버 에이전트 대체가 아니다"**라고 STATUS에 명시 |

**둘 다 macOS 전용이고 macOS는 은퇴했다.** 웹/Tauri(Win·Linux·mac)와 RN 모바일이 출하 경로인 지금 **Apple 온디바이스 경로는 통째로 재검토 대상**이다. 성재의 직관이 맞다.
**다행히 허들 전사·요약은 애초에 서버측 설계라 이 붕괴의 영향을 받지 않는다.**

### 7-3. 진짜 미결은 하나 — **한국어 품질**

- 리서치가 경고를 남겨뒀다: **large-v3 KsponSpeech CER 11.13%(낭독체 기준)** — 회의 도메인은 더 나쁘다. **staging 실측 필수**, 미해결 질문으로 명시("small/medium/large-v3-turbo 비교 후 모델 확정").
- 처리량 실측(Mattermost 인용): **10분 통화 전사가 tiny 2m20s ~ small 16m50s @1스레드.** GPU 없는 단일 VPS에서 **small이 사실상 실용 한계**다. 1시간 회의면 small로 ~100분 — 사후 배치라 견딜 수는 있으나 여유가 없다.

**→ 성재가 "외부 솔루션 의존 또는 자체 호스팅 허용"이라 했으므로 2단 구성을 권고한다:**

1. **기본 = self-host whisper 배치**(현 설계 유지). 데이터가 서버 밖으로 안 나간다 — `docs/security/README.ko.md`의 핵심 주장을 지킨다.
2. **품질/처리량 미달 시 = 외부 ASR을 워크스페이스 옵트인**으로. 단 **이건 보안 문서의 "당신 서버 밖으로 안 나간다"를 회의 음성에 한해 깨는 일이다.** 기본값 off, 켤 때 명시 고지, 무엇이 어디로 가는지 문서에 적는다. **끄면 self-host로 되돌아가야 한다.**
3. 어느 쪽이든 **한국어 회의 도메인 실측이 선행**한다 — 모델 확정 전에 파이프라인을 확정하지 않는다.

**주의**: 외부 ASR은 ADR-0004(provider 자격증명 비유입)와는 다른 축이지만, **보안 문서가 말하는 "Dawn은 아무 데도 없다"의 예외를 만드는 결정**이다. 켜는 순간 그 문장이 조건부가 되므로 **ADR-0122 증보에 명시**해야 한다.

## 8. 설계 검토 (2026-07-28, 착수 전 전제 재검증 — 워커 모델 sol medium)

지난 배치에서 티켓 6장 중 4장의 전제가 코드와 달랐으므로, 패킷 작성 전에 전부 재검증했다.

### #850 웹 허들 — 전제 확인 + 설계 구체화 4건
- **join 응답이 `livekitUrl`을 준다**(`JoinHuddleResponse`) — 클라이언트가 주소를 유도할 필요 없음(ADR-0110 동형). 패킷에 명시.
- 실시간 와이어 타입은 **`huddle_started`·`huddle_participants_changed`·`huddle_ended`**(Core `RealtimeEnvelope.swift:44-46`이 정본) — 웹 `realtime.ts`에 파서 추가 필요.
- `livekit-client`는 **xterm과 같은 lazy-load**(`terminalRuntime.ts` 선례) — 허들 안 여는 사람에게 0 비용. CSP는 통과(`connect-src` 넓음, npm 번들이라 `script-src 'self'` 충족).
- **위험 1건**: Tauri WKWebView의 `getUserMedia` 마이크 권한 — 워커가 해결 금지·보고만, 실측은 오케스트레이터.

### #851 내 세션 표면 — 전제 확인 + **범위 정정 1건**
- 필요한 필드 전부 실재(`WorkSession.memberId/hostId/status/startedAtMs/resumedFromSessionId`, `WorkHost.online/lastSeenAtMs`). **서버 변경 불요** 확정.
- **정정: 티켓의 "마지막 활동 시각"은 서버 필드가 없다.** 지어내지 말고 startedAtMs·상태 전이·실시간 이벤트로 표현 가능한 범위까지만(durable 최근활동이 필요하면 엔진 티켓 별도). 패킷에 반영.
- ADR-0139(idle)가 이 표면에 얹히므로 **미지 상태 안전 렌더**만 요구(미리 구현 금지).

### #853 → **ADR-0139 기안 완료** (`docs/adr/0139-work-session-idle-reattach.md`, Proposed)
- 번호 정정: 티켓에 적었던 0146이 아니라 **0139**다(0138은 일반유저 온보딩에 예약). D1 셸 래핑 PTY로 `idle` 상태(도구 종료≠세션 종료) · D2 호스트 링버퍼 replay(D10 유지) · D3 재부착 vs 계보 재개 분기 명문화 · D4 T3 idle=pause+**활성시간 미계상**. **성재 승인 대기 — 승인 전 구현 착수 금지.**

### #854 전사 v1 — **범위 재절단**: 1단계는 구현이 아니라 실측 하니스
- 워커는 오디오를 못 구한다 → **하니스(모델 3종 CER·RTF 표) + 파이프라인 골격 + 동의 fail-closed 게이트**까지만. 실오디오 런과 모델 확정은 오케스트레이터/성재.
- Egress의 Redis: **prod에는 있다**(`install.sh:66` postgres/redis/centrifugo). dev compose에는 없음 → dev는 profile에 포함.
- 동의 게이트를 서버가 막으면 웹 동의 UI는 나중에 얹어도 안전 — 순서 정당화.

### #855 T3 — 전제 확인(ADR-0136 D1: 서버측 프로비저너·workd Ed25519 자기등록 재사용) + 접합 1건
- **ADR-0139 D4 요구를 원장 스키마에 선반영**: pause 구간 미계상을 표현할 것. 나중에 붙이면 과금 신뢰가 깨진다.
- 워커는 `.env`의 E2B 키를 **읽지 않는다**(자격증명 계약) — 실호출 스모크는 오케스트레이터가 키 주입.
