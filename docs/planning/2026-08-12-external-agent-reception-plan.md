# 외부 에이전트 수용 축 — 실행 계획 (2026-08-12)

> 성재 지시: Grok Bot 다이얼인 방향("배포 허들 0 호스팅 에이전트를 팀메이트로") 리서치 → 로드맵화 → ADR 초안 → **sol 검수 → 실작업**. 본 문서가 이 축의 로드맵 정본.
> 입력 정본: `research/2026-08-12-grok-bot-integration-feasibility.md` · `research/2026-08-12-grok-bot-reverse-teammate-direction.md`(§8 설계 감사 포함) · ADR-0162(Proposed) · ADR-0163(Proposed).

## 방침 (성재 확인 사항의 성문화)

- **주=연동형(BYOA/ACP), 부=관리형 동봉.** oort는 에이전트를 소유하지 않는다(ADR-0102 정본 재확인). 다이얼인형은 제3 수용구로 신설(ADR-0162).
- 3분류 어휘: **관리형(managed) / 연동형(BYOA) / 다이얼인형(dial-in)** — 명명 확정은 성재(ADR-0162 D1).
- Grok Bot 의존 금지 — 모든 표면은 벤더 중립, Grok Bot은 첫 클라이언트.
- provider 선택: 관리형=run 단위(ADR-0134) · 연동형=하네스 단위 · 다이얼인형=불가(번들) — 제품 카피에 정직 반영.

## DAG

```
#1343 (sol 검수) ──┬──> ADR-0162 성재 승인 ──> Wave 1 티켓 발급·발사
                   ├──> ADR-0163 성재 승인 ──> Wave 3 (단, #1228 선행 권고)
                   └──> 편성 검증 피드백 → 본 문서 갱신
#1344 (스파이크) — 성재 게이트(구독 계정) → 결과가 ADR-0162 D3(토큰 형식)·Wave 1 수용기준에 반영
#1345 (0130 감사) — 병렬 → 분해 결과 → 성재 편성 승인 → Wave 2
```

- Wave 1과 Wave 2는 독립(Agent Port는 서버 신설면, 0130 재랜딩은 work host 층) — 병렬 가능.
- #1344가 막혀도(계정 미결) Wave 1 설계·구현은 진행 가능 — Grok Bot 실기 실증만 뒤로 밀린다(표면은 벤더 중립이므로).

## 완료 정의

- **Wave R**: 두 ADR이 "성재 승인 요청 가능" 상태(수정 반영 완료) + 티켓 분해 초안 존재.
- **Wave 1**: 임의 MCP 클라이언트로 폴링→클레임→게시 폐곡선 + red proof 4종(ADR-0162 검증 방향) green.
- **Wave 2**: #1345 분해 티켓 전부 랜딩 — ACP 세션이 현행 스택에서 실왕복.
- **Wave 3**: 새 기계 e2e "에이전트 1종 선택 설치→provider link→멘션 응답" 임기응변 0회 + 업데이트 폐곡선 실증.
