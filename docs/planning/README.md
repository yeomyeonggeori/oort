# 공용 기획·오케스트레이션

Codex와 Claude Code는 같은 [AGENTS](../../AGENTS.md), [CURRENT_STATE](CURRENT_STATE.md), 로컬 체크포인트를 사용한다. 역할의 현재 모델·상한은 [PIPELINE](PIPELINE.md)에만 정의한다.

## 시작·재개
`scripts/planning_context.sh`는 현재 checkout과 최신 스냅샷, 공용 로컬 작업 기록을 출력한다. 과거 결정 조사에는 `--details`, 실시간 이슈/PR 조회에는 `--github`를 사용한다. 일반 구현자는 배정된 이슈와 관련 파일부터 읽는다.

한 범위의 owner는 한 세션이다. 같은 모델 이름도 세션 식별자는 다르다. 다른 하네스로 넘어갈 때 owner·워크트리·HEAD·이슈/PR·검증·다음 행동을 인계한다. 모델 전환 자체는 제품 결정을 새로 승인받을 이유가 아니다.

## 작업 크기에 맞는 계약
| 작업 | 필요한 입력 |
|---|---|
| 사소한 문서의 로컬 diff 확인만 | 소유권 확인·격리 워크트리·구문/링크 확인. 새 Issue/worker/PR/전체 게이트 불필요; 코드·운영 계약에는 적용하지 않음 |
| 리포에 반영할 작은 수정·기존 결함 수리 | Issue의 Goal / Acceptance / Out of scope. 관련 정본 링크와 검증 범위 |
| 여러 영역·의존 순서가 있는 작업 | Issue + [핸드오프 패킷](HANDOFF_TEMPLATE.md). 파일 맵·지킬 계약·통합 순서 |
| 공개 API·보안·스키마·방향·스택 변경 | 기존 또는 새 Accepted ADR + 해당 이슈/패킷 |
| 출시·실서비스 변경 | 승인된 출시 계약과 환경별 런북·검증·owner 승인 |

수용기준은 한 곳에 쓰고 다른 문서에서는 링크한다. 기존 BUILD_TICKETS/패킷이 계약이면 그대로 따른다. 일반 이슈에 새로운 MOMO 번호, 별도 ADR, 패킷, 수용기준 사본을 모두 만들 필요는 없다.
패킷은 착수 전에 해당 기준 커밋에서 읽을 수 있어야 한다. 변경된 계약은 이탈과 영향받는 작업을 명시하고 인계한다. 판단을 돕지 않는 업계 비교나 정형 연구 절은 생략한다.

## 역할과 지속성
- **product-owner**: 방향·우선순위·ADR·출시 권한 결정.
- **planner/orchestrator**: 기획, 범위 분해, 독립 검수, 후속 수정 지시, 상태 갱신. 제품·실행 도구 구현은 worker에 배정한다. 공용 운영 문서·검수 기록과 위 로컬 문구 수정은 planner가 작성한다.
- **worker**: 한 이슈 구현과 관련 시험, PR, 인계. 머지·이슈 close·로드맵 재편성은 하지 않는다.
- **integrator(momo-main)**: owner가 조율된 세션 하나가 맡는다. 순차 트랙 통합과 승인된 승격을 수행한다. 모델명이나 하네스명이 독점 권한을 만들지 않는다.

승인된 범위의 구현→검증→검수→필요 수정까지 계속한다. worker가 PR을 넘기면 orchestrator가 다음 단계로 이어간다. 이미 승인된 로컬 테스트·가역적 수정의 매 단계에서 다시 묻지 않는다. 새로운 제품 결정, 권한 밖 외부 변경, 해소되지 않은 소유권 충돌만 분리해 확인한다.

## 공용 작업 기록
추적하는 지식과 실행 중인 로컬 상태의 역할을 구분한다.

| 위치 | 용도 / 갱신 시점 |
|---|---|
| CURRENT_STATE.md | 최신 위치와 다음 행동만. 통합·범위 변경·세션 종료에 갱신 |
| JOURNAL.md | 짧은 이력. 기존 항목 불변, 세션 종료에 한 일/열린 것/다음 |
| STATUS.md | 코드/실행 증거. 이슈 완료·통합 시 |
| ROADMAP·ADR·Issue/패킷 | 각각 계획·결정·수용기준의 정본 |
| `<git-common-dir>/oort-coordination/` | 같은 로컬 저장소의 워크트리/하네스가 공유하는 owner·중간 체크포인트. 유의미한 작업 경계에 저장 |

로컬 기록은 `scripts/planning_session.py --help`로 관리한다. `integration` 범위는 통합자 한 명만 claim한다. 자기 이슈/기획 범위의 note에 owner/세션, source worktree/HEAD, 이슈·PR, 워커 run/PID/종료 파일, 마지막 검증, 다음 행동과 막힘을 적는다. 시크릿·전체 로그를 넣지 않는다.

같은 Git common directory를 사용하는 워크트리끼리 공유된다. **별도 clone이나 다른 머신에는 동기화되지 않는다.** 그 경우 커밋된 CURRENT_STATE와 Issue/PR을 기준으로 인계한다. 등록이 없다고 다른 프로세스도 없다고 단정하지 않는다. 오래됐다는 이유로 owner를 자동 탈취하지 않는다.

## 검수·통합
[AGENTS](../../AGENTS.md)의 필수 검증과 [MULTI_SESSION_OPS](../MULTI_SESSION_OPS.md)의 순차 통합을 따른다. 수정된 HEAD·환경에 영향이 없으면 기존 증거를 재사용하고, 변경/병합으로 생긴 차이는 검증한다. 필요한 버그 회귀 증명은 실제 동작 경로를 대상으로 한다.

구현의 계약 이탈은 PR에 기록한다. 방향 판단이 필요한 이탈만 DEVIATION_LOG/ADR로 환류하고 owner 결정을 받는다. 모든 로컬 작업에 전역 pending 목록 처리를 선행시키지 않는다.

## 보고·문서 수명
사용자에게 **전체 단계 표 + 이번 작업의 한 일 / 현재 / 다음 / 완료 조건**을 보여준다. 구현·검수·통합·발행·실환경 검증을 구분하고 근거 없는 완료율·날짜를 붙이지 않는다.

CURRENT_STATE는 스냅샷을 누적하지 않는다. 교체 시 필요한 이력을 JOURNAL/기존 archive로 옮긴다. JOURNAL은 최근 20항목, 초과분은 월별 archive로 원문 보존한다. 종료된 패킷·비인용 연구의 수명은 ADR-0183 D6를 따른다. 살아 있는 코드/정본의 참조는 먼저 정리한다. `claudedocs/`와 하네스 개인 메모리는 scratch다.
