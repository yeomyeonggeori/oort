## 1. 결정 정본 (ADR-0139 D4 — 바꾸지 마라)
- T3 호스트 세션이 **idle 진입 → 프로비저너 pause**(E2B keep_memory), **재부착/running 복귀 → resume**. **T1/T2는 무동작.**
- **pause 구간은 활성시간(H)에 세지 않는다** — idle을 이유로 한 자동 과금 없음.
- resume 실패(샌드박스 소멸 등) → **orphaned 경로로 정직 전이**. 죽었는데 idle로 보이면 안 된다.

## 2. 검증된 출발점 (전부 랜딩됨 — 재확인하고 써라)
- **#855**: `E2BProvisioner.swift`(create/pause/resume/destroy) · `CloudProvisionerRoutes.swift`(pause/resume REST) · `work_host_usage_interval` — **`active_seconds`가 GENERATED 컬럼이라 `paused` 구간은 구조적으로 0**. 즉 원장은 준비돼 있다 — 네가 할 일은 **idle 전이가 pause를 부르고 interval 경계를 기록하게 배선**하는 것.

- cloud host 상태: `work_cloud_host.state ∈ provisioning|ready|running|paused|destroyed|failed`.

## 3. 할 일
1. **idle→pause 배선**: T3 호스트(work_cloud_host 연결) 세션이 idle 전이 시 프로비저너 pause + interval `paused` 개시. running 복귀 시 resume + interval `active` 재개. **T1/T2 판정은 host 기준으로 확실하게**(cloud host 아니면 완전 무동작 — 기존 경로에 1바이트도 영향 없어야 한다).
2. **resume 실패 → orphaned**: E2B가 sandbox 소멸을 답하면 세션을 orphaned로 전이(기존 sweep 경로/이벤트 재사용) + cloud host `failed|destroyed` 반영 + 감사.
3. **파일럿 수치 실측 자리**: pause→resume 지연을 원장/로그에서 읽을 수 있게(E2B 실측 sub-second 주장 검증은 오케스트레이터 스모크).
4. openapi 갱신(변경 경로 있으면).
