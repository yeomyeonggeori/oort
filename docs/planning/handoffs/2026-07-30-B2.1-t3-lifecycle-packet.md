## 1. 이 배치의 진실 (ADR-0140 교훈)
**정합성의 최종 강제는 이미 DB에 있다**: `t3_terminate` 단일 정산 문(053) · `settled_at` 트리거 봉인(053) · 전이표 `work_cloud_host_transition` BEFORE UPDATE 트리거 · 호스트 advisory 직렬화 `acquire_t3_lifecycle_lock`(052) · 잠금 사다리(advisory→credit→cloud_host→usage→interval→session) · pause 미계상 GENERATED 컬럼(045). **너의 일은 이 DB 강제를 Rust에서 우회 불가능하게 배선하는 것**이지 재구현이 아니다. Swift `Cloud/T3LifecycleLock.swift`·`Cloud/CloudUsageLedger.swift`·`WorkSessionRoutes.swift`의 해당 경로를 실측 이식하라.

## 2. 할 일 — `server-rust/crates/momo-t3` 신설 (수명주기+과금 척추만)

### 2-1. lifecycle 모듈
- `with_t3_lifecycle_tx` — momo-db 패턴 위에 T3 전용 tx 가드: workspace GUC + **`acquire_t3_lifecycle_lock`(052) advisory 선획득**(Swift `T3LifecycleLock.acquirePrelude` 실측 이식). momo-db에 변형 tx 추가가 자연스러우면 공개 API 추가로(명시).
- work_session 생성(T1/T2/T3 공통 최소) → cloud_host 바인딩(T3) → 상태 전이는 **일반 UPDATE로**(전이표 트리거가 거부를 강제 — 앱은 트리거 에러를 도메인 에러로 매핑).
- **종료 = `t3_terminate` DB 함수 호출만**(053 실측 — 시그니처·인자 확인). 앱 코드에 정산 SQL 직접 작성 금지(단일 정산 문 우회 = 불변식 위반).

### 2-2. billing 모듈
- usage_ledger 계상 경로(045 실측 — GENERATED 컬럼·interval 잠금 순서). credit 원장 조회·차감은 t3_terminate가 하는 범위 확인 후 그 밖(예: 사전 잔액 검사)만 앱에.

### 2-3. provider 모듈 (ADR-0142)
- B0의 `momo-provider` trait에 **mock provider 2종 구현**(`mock-a`/`mock-b` — #897 Swift 패턴 실측): 정상 수명주기 + pause 후 호출 정직 실패 + `probe` 죽음 정직 보고. BYOC degenerate(create/destroy 없음).
- **#7 red(D2)**: mock 등록→세션→종료 흐름 뒤 **PG dump·로그에 provider 시크릿 문자열 0건** 단정. 어댑터 설정은 env 네임스페이스(`MOMO_T3_PROVIDER_<ID>_*`) — 값이 DB로 흘러가면 red.

### 2-4. conformance (`#[ignore]`, 오케스트레이터 실행)
- **정산 단일문**: t3_terminate 경유 종료 → `settled_at` 세팅 + usage 확정. **직접 UPDATE로 settled_at 재변경 시도 → 트리거 거부**(봉인 red).
- **전이표**: 허용 전이는 통과, 금지 전이(예: settled→running) UPDATE → 트리거 에러(red).
- **advisory 직렬화**: 같은 host에 동시 2 lifecycle tx → 직렬 실행(교착·이중정산 0).
- **이중 정산**: t3_terminate 2회 호출 → 멱등(두 번째가 이중 차감 안 함 — 053 실측 의미대로).
- **#7 비유입**: 위 2-3.
