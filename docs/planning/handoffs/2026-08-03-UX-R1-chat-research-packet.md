## 2. 답을 가져와야 할 질문 (성재 지목 순)

### 2-1. 메시지 행 자체
행 밀도·아바타/이름 표시 규칙·**연속 메시지 묶기(grouping)** 기준(같은 사람 N분 이내?)·시각 표시 위치·읽음/전송중/실패 상태를 어디에 어떻게 놓나. **우리 것과 무엇이 다른지** 짚어라.

### 2-2. 스레드
- 목록에서 스레드를 **어떻게 알리나**(롤falls·참여자 아바타·미읽음).
- 스레드를 **어떻게 여나**(탭? 전용 버튼?). 우리는 지금 롤업 버튼뿐이다.
- 스레드 화면의 **루트 메시지 표시**와 답글 컴포저 배치.
- **성재 실측 결함**: *"스레드에서도 채팅을 하면 위에 숨겨져 있어서 채팅 닫아야 보이더라."* → 그들은 이걸 어떻게 푸나.

### 2-3. 인용 답글 (성재 요청)
> "인용 느낌으로 답글 대신에 해당 글에 대해 직접 인용 답글을 다는 기능"

스레드(별도 공간)와 **인용 답글(같은 흐름에 부모를 인용)**은 다른 물건이다. 두 참조가 **어떻게 공존**하나 — 자료구조(우리는 `root_id`와 `reply_to_id`가 **둘 다 스키마에 있다**), 렌더(인용 블록 모양·탭하면 원문으로 점프), 컴포저(인용 대상 취소 어포던스).

### 2-4. 작성 중(typing) 표시
누가·언제·어디에 뜨나(헤더? 목록 하단? 컴포저 위?)·여러 명일 때·**전송 빈도와 만료**(매 keystroke? 디바운스? TTL?)·전송 채널(우리는 Centrifugo). **비용**도 적어라 — 이건 트래픽을 만든다.

### 2-5. 에이전트/봇 메시지
사람과 **시각적으로 어떻게 가르나**(배지·색·아이콘)·**실행 중 표시**·긴 출력(코드·툴 결과) 접기·실패 표시. Mattermost는 봇/웹훅, buzz는 에이전트가 1급이니 **buzz 쪽이 우리와 더 가깝다** — 거기를 특히 봐라.

### 2-6. 키보드·입력
컴포저를 **어떻게 닫나**(성재 실측: *"채팅창 여는 건 성공했는데 다시 닫을 때 어떻게 해야 하는지 모르겠다"*) — 바깥 탭? 스크롤? 명시 버튼? 그리고 멘션 자동완성 UI·전송 버튼 상태·여러 줄 성장.
