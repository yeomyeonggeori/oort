## 2. 순서 (이 순서대로 커밋을 나눠라)

### 2-1. 리허설 시나리오 문서 (첫 커밋)
`docs/planning/` — T1→T2→T3에서 같은 goal을 수행·중단·재개하는 대본 + 단계별 측정 항목(spawn 지연·재개 지연·원장 기록 정합). ADR-0125 D11 폴백 경로 포함. 성재 1인 테스트의 대본이 된다.

### 2-2. 활성시간 원장 (마이그레이션 + 기록 경로)
- `usage_ledger` 확장이냐 신설이냐 — **판단하고 근거를 적어라.**
- **필수 요구(ADR-0139 D4에서 옴)**: **pause 구간은 활성시간에 세지 않는다.** 스키마가 pause/resume 구간을 표현해야 한다. 나중에 붙이면 과금 신뢰가 깨진다.
- RLS FORCE·워크스페이스 격리·감사 — 기존 원장 마이그레이션(043 등) 선례를 따라라.

### 2-3. 프로비저너 v0 (E2B 기질)
- create/pause/resume/destroy를 `work_host` 계약에 얹는다. E2B API 클라이언트는 **키를 env에서 읽되 키 부재 시 T3 경로만 503 fail-closed**(다른 티어 무영향 — 허들 503 선례).
- **잔액/슬롯 게이트**: 없으면 spawn 거부(fail-closed), **거부 이유가 사용자가 읽을 수 있는 문장**으로.
- 자동 T3 전환 기본값 금지(ADR-0125 D11 기각 사유 — 질문 없는 과금). opt-in만.
