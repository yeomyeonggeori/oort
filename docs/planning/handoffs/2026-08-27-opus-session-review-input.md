## 2. 결재받은 ADR

- **0165 증보 3 (Accepted)** — TURN 신뢰 경계의 주어를 "oort 운영分"에서 **"그 배포의 운영자 소유分"**으로 재정의. `D3-부재`(과도기 허용)는 성재가 (가)로 결정.

성재 발제("비용이 의미 없이 발생")로 감사 → 판정 → 집행.

- **oort 자원 0**: 서버 3대 · 블록스토리지 **360GB** · 공인 IP 3개 반납. `factsheet` 프로젝트는 비접촉.

- 가드 5중(인스턴스 번호·이름·공인 IP·`momo` 접두사·`stopped` 상태) 후 호출. 삭제 전 **재구축 스냅샷 정본화**.

## 5. 허들 — 방향 확정 + 급소 통과

- **RP-1 실측**(그록봇 VM): 매핑이 목적지마다 **포트뿐 아니라 공인 IP까지** 다름(AWS 로드밸런싱 NAT 풀) ⇒ **VM 에 안정적 공인 신원 없음, 홀펀칭 사망.**
- **RP-2 급소 통과**: Funnel `--tls-terminated-tcp=8443` 통로로 **TLSv1.3 악수 성립 + 인증서 검증 OK**. 앞선 EOF 는 백엔드 부재였음이 확인됨.
- ⇒ **추가 가입 0 · 설치 0 · 비용 0 으로 허들을 열 수 있는 경로가 살아 있다.** 남은 것은 LiveKit 내장 TURN 을 그 자리에 앉히는 설정(서버·클라 코드 0줄).
- #1789(전제 오류) close → **#1792 SPIKE-HD** 로 대체.

## 6. 그록봇 제어 — 경로 전환

- 성재가 "CDP 로 직접 제어하라" 했으나 **성재 본인이 2026-08-22 Cursor 약관 때문에 은퇴시킨 경로**라 거절하고 대안 제시.
- **우리 제품 자체를 경로로 씀**: 그록봇 VM 의 oort 가 Funnel 로 공개 → 오케스트레이터가 멤버로 가입 → **`#agent-lab` 에 직접 지시 전송 성공**(seq:1).
- 회전형 refresh 자동 갱신 클라이언트 작성. **계정 생성·비밀번호 입력은 하지 않음**(그록봇이 대행, 토큰만 수령).
- 이 과정에서 **제품 갭 발견 → #1797**(외부 도구는 사람 세션이 아니라 **에이전트 자격**으로 붙어야 한다. `/v1/workspaces/{ws}/agents/{agent}/credentials` 가 이미 있다).

## 7. 계정·워크스페이스 축 (성재 5축 중 하나)

**리그 실측으로 좌표 확정**:

| 축 | 상태 |
|---|---|
| 워크스페이스 생성 | ✅ 됨 (`POST /v1/workspaces`, slug 필요) |
| 계정 생성(초대 발급·수락) | ✅ 됨 |
| 초대 회수 | ❌ 404 → **AC-3 #1799 PR** |
| 비밀번호 초기화 | ❌ 경로 0건 → **AC-1 #1798 PR** |

## 9. 이 세션에서 반복적으로 드러난 패턴 (Fable 이 특히 봐 주길)

### ㉠ "실기동 없이는 측정할 수 없는 축"
리그를 세우는 과정에서 결함 **4건**이 나왔고 **전부 컨테이너를 실제로 띄워야만** 드러났다 — `bash -n`·단위 테스트·문법 검사가 모두 지나갔다. compose 가드 오탐, printf 회귀, migrate env 부재, drive 볼륨 권한.

### ㉡ 문서와 코드가 서로를 무효화
- #1790: 플레이북 §1.4 가 "생성기 재실행 금지"라 해놓고 §2.3 이 실행을 시킴
- #1788: `--public-origin` 이 `same-origin` 을 덮어써 **문서대로 따르면 수리가 원상복귀**
둘 다 워커가 못 봤고 **문면 대조**에서 잡혔다.

### ㉢ 내가 랜딩한 것에서 회귀가 나왔다
#1790 검수를 통과시킨 printf 버그를 다음 날 리그에서 밟았다. 모드 테스트가 claim 분기만 밟아 비-claim 문자열이 한 번도 실행되지 않았다.

### ㉣ 게이트 브리핑 누락 반복
AC-1·AC-3 이 **같은 계약 게이트**(OpenAPI ↔ web-legacy 생성 타입)에 연속으로 걸렸다. 워커 브리프에 그 게이트를 넣지 않은 것이 원인이고, AC-4 브리프부터 포함시켰다.

### ㉤ 워커의 정직한 정지가 더 큰 발견으로 이어짐
AC-4 워커가 전제 검증 중 멈춰서 #1800(워크스페이스 설정 표면 부재)이 드러났다. localStorage 우회나 트랙 위반 대신 멈춘 판단이 옳았다.

## 10. Fable 에게 묻는 것

1. **방향성**: NCP 완전 철수 · 허들을 Funnel TURNS 로 · 외부 도구를 에이전트 자격으로 — 이 세 판정이 옳은가. 더 나은 길이 있었나.
2. **구현 정합**: 랜딩 7건의 설계가 ADR·불변식과 맞는가. 특히 #1788(same-origin 파생, ADR-0167 준용) · #1767(credential_claim 일반화, 유니크 인덱스 kind 분리) · #1747(drive-init, fail-fast 보존).
3. **검수 품질**: 내가 놓친 것이 있나. ㉢(내가 랜딩한 회귀)이 재발하지 않으려면 무엇을 바꿔야 하나.
4. **잔여 규모**: 성재 5축(UXUI·허들·터미널·그록봇·계정) 기준으로 **얼마나 남았나**. 우선순위 재배치가 필요한가.
5. **워커 운용**: 브리프 품질·게이트 지정·정지 규약이 적절했나. ㉣ 같은 누락을 구조적으로 막을 방법은.
