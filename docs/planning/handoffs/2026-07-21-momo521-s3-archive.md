# MOMO-521 핸드오프: S3 호환 첨부 어댑터 + compose MinIO 프로파일 (ADR-0127)

> 발급: 2026-07-21 Fable (성재 승인 — 셀프호스트 하드 블로커 해소). 정본: ADR-0127(Accepted) D1~D3.
> 트랙: 엔진 · base = main · PR base = track/engine · 도메인 = server(Drive/) + infra + docs. **migration 불요.** verifier 포트 밴드 **28040~28044**(MinIO 포함 — 기존 밴드 충돌 사전검사).

## 목표
셀프호스터가 Google Workspace 없이 첨부를 쓰게 한다: `MOMO_ARCHIVE_BACKEND=s3` 한 줄로 S3 호환(MinIO/AWS/R2/B2) 백엔드 선택.

## 구현 범위
1. **`S3ArchiveClient`** (server/Sources/MomoServer/Drive/ — 기존 `DriveArchiveClient` 프로토콜 구현): 업로드 세션 발급=presigned PUT URL(만료 기존 세션 TTL과 동일), complete=HEAD로 존재/크기 확인 후 메타 확정, 콘텐츠 서빙=presigned GET(기존 capability URL 문법 그대로 — 서버 바이트 무중계 유지), 삭제 지원. AWS SigV4 서명은 **외부 SDK 없이 직접 구현**(HMAC-SHA256 — 의존성 최소, permissive 하드 룰. swift-crypto는 기존 의존성에 있음).
2. **백엔드 선택**: env `MOMO_ARCHIVE_BACKEND=drive|s3`(기본 drive). s3 시 `MOMO_S3_ENDPOINT/REGION/BUCKET/ACCESS_KEY/SECRET_KEY`(+`MOMO_S3_FORCE_PATH_STYLE=1` — MinIO 필수). 자격 미비 시 기존 `UnavailableDriveArchiveClient` fail-closed 유지. App.swift 부팅 분기.
3. **compose 프로파일**: infra/docker-compose.e2e.yml에 `minio` 서비스(profile: s3, 포트 파라미터화) + infra/prod에 opt-in 프로파일. DEPLOY.md에 셀프호스트 S3/MinIO 절 추가.
4. **REST/OpenAPI 무변경** — 어댑터는 서버 내부 결정(ADR-0127 D3). 클라이언트 전부 무변경.

## 수용 기준
- `verify_attachment_upload.sh`에 **s3 모드 추가**(env로 분기, MinIO 컨테이너 28044): 세션 발급→presigned PUT 직송→complete→메시지 첨부→다운로드 왕복→비멤버 403→URL 비유출(로그/원장 grep) 단정. 기존 drive(stub) 모드 회귀 0.
- server 단위 테스트: SigV4 서명 벡터(AWS 공식 test vector), presign URL 만료, path-style. 기존 테스트 회귀 0.
- 시크릿 커밋 금지 — env 예시는 placeholder만.
