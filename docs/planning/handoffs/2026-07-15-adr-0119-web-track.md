## 1. 결정 요약 (왜 이 작업인가)

ADR-0119(Accepted)는 oort의 세 번째 클라이언트 표면으로 웹을 신설한다: **서버 대표 도메인이 곧 웹 주소** — Caddy가 같은 오리진에서 SPA와 `/v1` 프록시를 함께 서빙해 CORS·쿠키 문제를 원천 회피하고(D1-A), 서버 코드는 무변경으로 시작한다. 웹은 초대받은 사람의 무설치 합류 경로이며(성재 "웹 먼저" 확정), v0 스코프는 "초대받은 사람이 브라우저로 합류해 대화한다"(D5-A)다. 이 배치는 그 전제 3개를 놓는다: ① REST 계약의 스펙 정본화(두 번째 클라이언트의 drift 방지, D4-A) ② 서빙 인프라(D1-A) ③ 웹 스캐폴드 + 로그인/타임라인 v0(D2-A·D3-A).

## 4. 지켜야 할 계약

- **서버 소스 무변경** (389/391 하드 계약, 390은 infra만). 계약 불일치 발견 = 멈추고 이탈 보고, 서버를 고치지 않는다.
- 단일 쓰기 경로·RLS·seq 불변식(`docs/architecture/overview.md`) — 웹도 REST만 쓴다. Centrifugo 직접 publish 금지.
- websocket 주소는 서버 응답 `realtimeWebSocketUrl`이 유일 권위(ADR-0110). API URL에서 추론 금지.
- 의존성 라이선스 permissive만(MIT/Apache/ISC/BSD) — GPL/AGPL 유입 금지(하드 룰).
- ADR-0112 기본 모드 문법만. 파일/웹훅/presence/멀티WS rail은 각 ADR 게이트 전 비구현.
- 토큰 정책은 ADR-0119 D3-A + 공개 배포 전 승격 게이트를 `clients/web/README.md`에 명문화.
- `APP_DOMAIN` 미설정 배포의 완전 하위 호환(웹 없는 셀프호스팅 허용).

## 5. 알려진 함정 / 컨텍스트

- login은 workspace 미지정 시 demo workspace 폴백이 있다(`AuthRoutes.swift` — single-tenant v0 편의). 웹 로그인 폼도 workspace 입력(옵션)을 지원할 것.
- e2e compose의 시드 계정/워크스페이스는 `server/Migrations/002_seed.sql` 기준 — smoke 로그인에 사용.
- Caddy security_headers의 `X-Frame-Options DENY`는 유지. SPA CSP의 `connect-src`에 `{$REALTIME_DOMAIN}` wss를 열어야 realtime이 붙는다.
- centrifuge-js recovery: 재구독 시 `recovered:false`면 REST `?after=<seq>` backfill — Centrifugo history는 편의, PG가 권위(`docs/DEPLOY.md:279`).
- 로컬 알파 러너 수명주기 이슈(2026-07-15 momo-main 보고: 러너 종료 시 서버 동반 종료)는 이 배치와 무관 — 웹 검증은 e2e compose를 쓰고 local runner에 의존하지 않는다.
- npm 생태계 특성상 전이 의존성 라이선스 오염 주의 — 라이선스 검사 산출물을 PR에 첨부(391 수용기준).
