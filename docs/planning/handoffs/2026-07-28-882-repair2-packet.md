## 1. [보안·최우선] topup이 읽기 스코프로 크레딧을 증액한다
`CloudCreditRoutes.swift:31-36` → `ProviderLinkRoutes.requireOperator` → **`ProviderLinkRoutes.swift:338`이 `platform:read`면 DB 조회 없이 즉시 통과**("Platform scope authorizes without any DB lookup").
이 엔드포인트는 **임의 워크스페이스에 최대 1조 micro-USD를 증액**한다. `platform:read`는 코드·문서에서 **cross-tenant 읽기**로 서술된 스코프다 → **읽기 토큰 유출 = 유료 실행 권한 부여.**

→ 쓰기 전용 스코프(`platform:credits:write` 등)를 신설하고 topup에 요구하라. **`platform:read`만 가진 토큰이 거부되는 회귀 테스트 필수.**
→ **같은 가드를 쓰는 다른 mutation 엔드포인트를 전수 조사**하라. read-통과 성질이 다른 곳에도 걸려 있으면 **같은 등급의 결함**이다 — 발견 목록을 PR에 적고, 이 티켓에서 고칠지 별건으로 뺄지 판단해 근거를 남겨라(임의로 범위를 넓히지는 마라).

## 2. [high] 404/410 resume intent 영구 교착
`CloudLifecycleReconciler.swift:126-132`: REST resume은 missing sandbox를 terminal로 처리하는데 **reconciler는 200/201만 수용**한다. 최초 REST가 timeout으로 결과를 잃고 재조정에서 404/410을 받으면 intent가 `resuming`에 영구히 남는다. `TierFallbackSweep`은 transitional cloud state를 제외하므로 **session·usage·유료 슬롯이 영구 미정산** — #876이 닫으려던 구멍이 다른 경로로 재발한다.
→ reconciler도 404/410을 terminal missing-sandbox로 처리해 **host revoke·정산·orphan 적격을 한 트랜잭션**으로 확정.

## 3. [high] reconciler가 CAS 확인 전에 종속 상태를 바꾼다
`CloudLifecycleReconciler.swift:134-186`: provider 호출 후 usage interval과 `work_session`을 **먼저** 바꾸고 **마지막 host UPDATE에만** operation ID/state CAS를 건다. 외부 호출 중 다른 경로가 intent를 바꾸면 host CAS는 0행인데 **앞선 변경은 커밋**된다 → **destroyed host의 idle 세션이 running/active로 되살아난다.**
→ 트랜잭션 시작에 host row를 잠그고 operation ID/state 재검증 후에만 종속 상태 변경. **최종 CAS 1행 단정**, 실패 시 전체 롤백.

## 4. [medium] 함께 고칠 것
- **동시 provisioning 재시도 비멱등**(`CloudProvisionerRoutes.swift:76-124`): idempotency row 조회가 직렬화 lock **보다 먼저**라 동시 요청 둘 다 "없음"을 관찰 → 두 번째가 재조회 없이 INSERT → unique 오류 **500**. 네트워크 재시도가 겹치는 **정상 시나리오**다. → lock 선취 후 재조회 또는 `INSERT ON CONFLICT` 단일 upsert.
- **유일성 마이그레이션의 기존 위반 데이터**(049:42-46): 이미 한 host에 미정산 usage가 둘 이상인 인스턴스에서 마이그레이션 실패. → 선정리하거나, 실패 시 **읽히는 진단**(어느 host인지)을 남겨라.
