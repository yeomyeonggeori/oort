# goal RN-G1 — 시뮬레이터 게이트가 세션 복원을 실제로 검증하게 만든다

너는 momo(제품명 oort) 레포의 구현 worker다. 이 문서가 유일한 지시서.
**base = `track/engine`**. 워크트리 `~/projects/momo-tracks/momo-worktrees/RN-G1-signing-gate`(브랜치 `feat/RN-G1-signing-gate`, 생성됨).

발단: RN-C3 워커의 실측 보고 —
> **`scripts/build-sim.sh`(`CODE_SIGNING_ALLOWED=NO`) 빌드는 키체인을 못 써서 세션 복원이 아예 안 된다.** 애드혹 서명해서 다시 빌드하면 정상 동작하는 것까지 확인했다.

즉 **지금의 `build:sim` 으로는 세션 복원 회귀를 영영 못 잡는다.** 하필 방금 그 영역에서 라이브 결함이 하나 나왔다(오프라인 시작 한 번에 리프레시 토큰이 지워지던 것). **게이트가 못 보는 영역에 결함이 산다.**

## 0. 규율
`.env`·자격증명 금지 · **서버 코드·`schema_v0.sql` 수정 금지** · **docker 금지** · **실서버 접속 금지** · **`clients/web`·`clients/iOS`·`clients/mobile-spike`·`packages/momo-core` 수정 금지** · **`clients/mobile/src/features/**` 수정 금지**(다른 배치가 소유한다 — 이 배치는 **빌드·게이트 인프라**다) · `expo prebuild`·EAS·`android/` 금지 · 커밋은 새 커밋만 · **PR 후 STOP**.
Apple 계정이 필요한 것(`match`·프로파일 발급)은 **하지 마라** — 애드혹/로컬 서명 범위 안에서 푼다.

## 1. 할 일
1. **원인을 코드로 확인해라.** 왜 `CODE_SIGNING_ALLOWED=NO` 가 키체인을 막는가(entitlement·팀 prefix·`kSecAttrAccessGroup` 중 무엇이 없어서인가). 추측 말고 실패 코드(`-34018` 등)를 실제로 재현해서 적어라.
2. **시뮬레이터 빌드가 키체인을 쓸 수 있게 만들어라.** 애드혹 서명이 답이면 그렇게 하고, 왜 그것으로 충분한지(그리고 무엇을 여전히 못 하는지) 적어라.
3. **세션 복원을 실제로 검증하는 게이트를 붙여라.** 지금 없는 것이 바로 이것이다. 최소 시나리오:
   - 로그인 → 앱 재시작 → **세션이 복원된다**
   - **오프라인 재시작 → 자격증명이 지워지지 않는다**(방금 고친 결함의 회귀 가드)
   - 서버가 거절 → 자격증명이 지워지고 로그인 화면으로
   시뮬레이터에서 앱을 실제로 띄워 검증하는 형태여야 한다 — 단위 테스트로는 키체인 경로를 못 지난다(그게 이 배치의 전제다).
4. **일부러 깨뜨려 게이트가 무는지 증명해라.** 세션 복원 코드를 되돌리는 훼손을 넣고 게이트가 실패하는 것을 로그로 보여라. 그게 없으면 이 게이트도 장식이다.
5. 실행 방법을 `package.json` 스크립트와 README 에 남겨라.

## 2. 하지 마라
- **재시도·대기 늘리기로 넘어가지 마라.** 최근에 `capture:design` 플레이크를 그런 식으로 방치했다가 걷어냈다.
- 게이트를 **느리게 만들어 아무도 안 돌리게** 하지 마라. 걸리는 시간을 재서 적어라.
- 앱 기능 코드를 고치지 마라. 이 배치는 인프라다. 고쳐야 할 제품 결함을 발견하면 **PR 본문에 적고 넘겨라**.

## 3. 검증
- 새 게이트가 **현재 코드에서 통과**하고 **훼손하면 실패**한다(둘 다 로그).
- 기존 게이트 무회귀: mobile `tsc`·`jest`·`lint`·`gate:project-shape`, core `test`·`gate:purity`, web `test`·`build` 수치 불변.
