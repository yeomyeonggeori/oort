## 1. [Blocker] 다이얼로그 본문에 스크롤 상자가 없어 승인 버튼이 화면 밖으로 나간다

`PluginSection.tsx:775` — `<div className="flex flex-col gap-4 p-4" aria-busy=…>`.
`dialog-panel`(tokens.css:290)은 `max-block-size`만 걸고, `dialog.tsx` 주석이
*"The panel body scrolls inside it; callers put the scrolling box inside"* 라고 **계약을 명시**한다.
이 caller가 그 상자를 안 넣었다. 레포의 다른 다이얼로그는 넣었다 —
`CreateChannelDialog.tsx:243` `flex min-h-0 flex-col gap-4 overflow-y-auto p-4`.

실측(전부 `documentScrolls:false`, `panelComputedOverflow:"visible"`):

| 케이스 | 뷰포트 | 패널 bottom | 본문 bottom | 취소/확인 |
|---|---|---|---|---|
| Notion 4-scope | 1280x800 | 768 | 917 | top 873 화면 밖 |
| **GitHub 1-scope(출하 시드)** | **900x600** | 568 | 670 | top 626 **화면 밖** |
| GitHub 1-scope | 760x480 | 448 | 670 | 화면 밖 |

scope 행 본문이 패널 흰 면 **바깥**에 배경과 겹쳐 그려진다. 가설이 아니라 **오늘 서버에 있는 시드
4종**이, 레포 자신의 shell 게이트가 필수로 재는 900x600·760x480에서 그렇다.

키보드는 더 나쁘다(900x600): Tab이 `write OFFSCREEN → comment OFFSCREEN → admin OFFSCREEN →
취소 OFFSCREEN → 선택한 권한 허용 OFFSCREEN`. **보이지 않는 승인 버튼에 포커스가 가고 Enter가 먹는다.**

→ 레포의 기존 두 다이얼로그와 같은 방식으로 고쳐라. 새 패턴을 발명하지 마라.

## 2. [Blocker 재발 방지·필수] 게이트로 잠가라

같은 클래스(뷰포트 밖 컨트롤)가 **#838에서도 나왔다**(2열 상세가 폴드 위로 잘림). 두 번째다.
사람 눈이 아니라 게이트가 잡아야 한다.

`clients/web/gates/gate-shell-layout.mjs`는 이미 `900x600`·`760x480`을 돌고 있다(`:62-63`).
**동의 다이얼로그를 연 상태에서 확인·취소 버튼이 뷰포트 안에 있고 패널 밖으로 새지 않는지**
단정하는 검사를 추가하라. 최소한 900x600에서, **scope가 여러 개인 앱**으로.

- 기존 목 서버·부팅 절차를 재사용해라(새로 짜지 마라).
- **레드 증명이 성립해야 한다**: `overflow-y-auto`를 빼면 게이트가 빨개져야 한다.
  네가 Playwright를 못 돌리면 **어떤 조작으로 빨개지는지 PR/커밋에 정확히 적어라** —
  오케스트레이터가 그대로 재현한다.

## 3. [High] 서로 다른 scope가 같은 라벨로 렌더된다

`model.ts:101` `scopeSentence` — `:read`/`:write`만 특별 처리하고 나머지는 전부 `${name} 사용 권한`.
그래서 `notion:comment`와 `notion:admin`이 **둘 다 "notion 사용 권한"** 이다.
부분 실패 영수증도 같은 문자열로 실패를 지목한다: `"1개는 변경하지 못했습니다: notion 사용 권한"` —
**어느 쪽인지 말할 수 없다.**

단일 scope 시절엔 안 드러났고, **다중 scope를 도달 가능하게 만든 게 이 PR이다.**

→ **서로 다른 scope가 절대 같은 문장으로 렌더되지 않게** 하라. 모르는 action을 버리지 말고
문장에 남겨라. 알려진 action의 한국어 표현은 유지해라(기존 read/write 문구를 바꾸지 마라 —
다른 화면과 문구가 갈라진다).
**테스트로 잠가라**: 시드 매니페스트 4종의 모든 scope에 대해 문장이 서로 유일한지 단정.

## 4. [High] 실패 원인이 사라지고, 전량 실패에 선택이 통째로 날아간다

`settlePluginScopeChanges`는 error를 outcome에 담는데 **읽는 곳이 0건**이다
(`grep outcome.error` → 없음). scope 액션은 항상 `onSuccess`로 떨어져 `mutation.isError`가 안 서고,
400/403/404/409/NetworkError를 각각 다르게 말하던 `pluginActionErrorMessage`(`model.ts:260`)가
이 경로에서 **죽은 코드**가 됐다.

실측: 403 전량 실패 → `"선택한 권한을 허용하지 못했습니다. 현재 권한을 다시 확인하세요."`
무슨 일인지도, 다음에 뭘 할지도 없다(403이면 "관리자에게 확인", 네트워크면 "재시도"가 정답인데
같은 문장). **PR 이전 단일 scope 경로에 있던 정보가 없어진 회귀다.**

게다가 `PluginSection.tsx:158` `setConsenting(null)`이 **전량 실패에도** 다이얼로그를 닫아
사용자가 고른 선택이 사라진다.

→ 두 가지를 고쳐라:
1. **실패 원인을 말하라.** `pluginActionErrorMessage`를 이 경로에서 실제로 쓰게 하라.
   실패가 여러 건이면 어느 것을 대표로 쓸지 규칙을 정하고 **주석으로 근거를 남겨라.**
2. **전량 실패면 다이얼로그를 닫지 마라.** 오류를 다이얼로그 안에서 보여주고 선택을 유지하라.
   레포에 이미 in-dialog 오류 배너 선례가 있다 — `PluginSection.tsx:451-460`
   (`InlineBanner` + `오류 닫기` + `actionErrorRef`). **그 패턴을 재사용하고, 배너를 닫은 뒤
   포커스가 어디로 가는지도 그 선례대로 명시해라**(#838 4R에서 body로 떨어져 High를 받은 자리다).
   부분 실패는 지금처럼 닫고 영수증을 보여주는 것이 맞다.
3. **영수증이 성공한 것도 이름으로 말하게 하라**(M5). 지금은 성공은 개수, 실패만 이름이다.

## 5. [High] 전량 성공 후 포커스가 `<body>`로 떨어진다

실측: `focus-after-full-grant → activeElement: "BODY", grantButtonStillPresent: 0`.
`opener`로 되돌리는 것까진 맞는데, invalidate 재조회가 `grantableScopes`를 비워
`PluginSection.tsx:582` `{grantableScopes.length > 0 && <PluginScopeConsentButton …>}`가
**되돌려준 그 버튼을 언마운트**한다. **#838이 4라운드 쓴 바로 그 클래스**다.
Escape·부분 실패 경로는 멀쩡하므로 깨지는 건 "전부 허용" 한 갈래다.

→ opener가 사라질 수 있는 경우, **변경 뒤에도 반드시 존재하는 컨트롤**로 포커스를 넘겨라.
어디로 보낼지 근거를 주석에 남기고 **테스트로 잠가라.**

## 6. [High] 위험도가 선택 단위가 아니라 앱 단위로만 말해진다

`dl`의 "도구 위험도와 승인 티어"는 모든 도구 라벨을 dedup해 이어붙인 한 줄이다:
`위험도 읽기, 읽기 전용, 위험도 쓰기, 워크스페이스 쓰기, 네트워크 쓰기, 위험도 관리자`.
**어느 체크박스가 "위험도 관리자"인지 화면 어디에도 없다.** 체크박스 행은 도구 description만 싣는다.
아이러니하게 **다이얼로그 뒤의 상세 패널이 scope별로 더 자세하다**
("notion 사용 권한, 네트워크 쓰기, 위험도 관리자"). **결정하는 화면이 결정 근거를 덜 준다.**

→ 위험도·승인 티어를 **각 scope 행에** 붙여라. 상세 패널이 이미 하는 계산을 재사용하고
새 엔드포인트를 만들지 마라. 앱 단위 요약 줄은 중복이면 빼도 된다(판단은 네 몫, 근거를 커밋에).

  accent를 나눠 갖는다. → 늘어나지 않게 하라. **그리고 회수 다이얼로그에는 이 칩이 무관하다 —
