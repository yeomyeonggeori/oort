# #1820 브리프 — EXT-1-READ generic 자격 메시지 읽기 REST (engine)

> 정본: **ADR-0173 Accepted**(성재 위임·Fable 검토 확정 2026-08-28). 이 브리프는 그 §engine 구현 티켓 계약의 실행판.
> 새 브랜치 `feat/1820-ext1-read`, base=`origin/track/engine`(2f715c8b). 워크트리 `~/projects/momo-tracks/momo-worktrees/w1820-ext1-read`.

## 0. 결정 (ADR-0173 — 그대로 적용, 재결정 금지)

외부 도구(generic agent credential)가 **자기 active 멤버 채널의 메시지를 REST로 읽게** 연다. hosted connection 경로·검색·전 채널·비-default는 불변.

## 1. 계약

1. **스코프 매핑만 추가**: `required_agent_scope`(`agent_scope.rs`)에 다음을 `messages:read`로 매핑 —
   - `GET /v1/workspaces/{ws}/channels/{ch}/messages`
   - `GET /v1/workspaces/{ws}/channels/{ch}/messages/{root}/replies`
   현재 이 경로들은 스코프 표에 없어 agent bearer 403(`the_mcp_only_scopes_open_no_rest_route` 단정이 messages:read=REST 0을 못박고 있음 — 이 단정을 갱신).
2. **hosted 판별 가드 신설 금지**(ADR-0173 D3): hosted 자격은 `AgentBearerClass` 프리플라이트(`auth.rs:836-848`)에서 이미 전 라우트 403, `GenericOrUnknown`만 스코프 표 진행. **라우트 핸들러에 hosted 여부 검사 넣지 마라** — 잉여·오작동. 격리 근거는 클래스 선격리.
3. **채널 경계**: 읽기는 사람 경로와 **같은 술어** `is_channel_member(conn, channel_id, member_id)` 재사용(`messages.rs` history/replies 공유). 신규 경계 발명 금지. RLS 테넌트 트랜잭션 유지.
4. **감사 신설 금지**(D4): auth 층이 이미 method+path로 감사(`auth.rs:972`). 핸들러 추가 감사 행 만들지 마라.
5. **비-default 유지**(D5): `agent_credential.rs`의 DEFAULT/GRANTABLE 무접촉 — messages:read는 GRANTABLE에 이미 있음, 기본 미포함 유지.

## 2. red proof (conformance PG — 신설/확장)

각 칸이 테스트 1건:
- generic + `messages:read` → `GET …/messages` **200**(자기 active 멤버 채널), replies도 200.
- messages:read 없는 generic bearer → **403**.
- **hosted 자격은 어떤 상태에서도 GET messages 403**: `hosted_active`·grace·`cleanup_pending` 각각. hosted→`GenericOrUnknown` 낙하 엣지(`agent_bearer.rs:114-130`)가 REST 표면으로 새지 않음을 못박기(ADR-0173 Note-2).
- **비멤버 채널 403** · **교차 테넌트 RLS 자가검증**.
- `is_channel_member`가 **active까지** 판정하는지 실측 — 비활성(정지·추방) 멤버 자격으로 403.
- 페이지네이션(`list_channel_page` cursor/limit) 그대로 동작(회귀).
- 사람 bearer의 같은 GET는 불변(회귀 0).
- red 관례: 매핑 전 정상 케이스가 403인 RED 선행 커밋 → GREEN.
