## 2. 할 일

### 2-1. H1 — 미이식 표면 정직화
원칙: **에러를 던지지 말고, 못 하는 걸 못 한다고 말하라.**
1. **진입점 정리** — 서버가 제공하지 않는 표면은 사이드바/네비에서 **진입점을 감추거나 비활성**으로. 눌러도 아무 일 없거나 에러 토스트가 뜨는 상태를 남기지 마라.
2. **도달 가능한 화면은 정직한 빈 상태로** — "아직 준비 중인 기능입니다" + **왜**(한 문장, 내부 용어·코드명·경로 노출 금지) + 대체 행동 안내. 스켈레톤이 영원히 도는 상태나 빈 껍데기 금지.
3. **이중 방어** — (a) 정적 capability 목록으로 진입점 판정 + (b) 그래도 404/501이 오면 에러가 아니라 "미제공" 상태로 접기. 네트워크 장애(오프라인·5xx)와 **미제공은 다른 문구**여야 한다 — 사용자가 "내 인터넷 문제"와 "아직 없는 기능"을 구분할 수 있어야 한다.
4. **capability 목록은 한 곳에** — 표면별 제공 여부가 코드 여기저기 흩어지면 다음 배치가 이식할 때 갱신을 빠뜨린다. 단일 모듈에 모으고, 이식되면 그 한 줄만 바꾸면 되게 하라.

### 2-2. H5 — 메시지 검색 배선 (클라만, 서버 이미 존재)
1. `crates/momo-messaging/src/search.rs`와 `routes/search.rs`를 **먼저 읽고** 실제 쿼리 파라미터·응답 형태·페이지네이션·권한 범위를 확인해라(추측 금지).
2. 검색 진입 → 입력 → 결과 목록(**채널 · 작성자 · 시각 · 본문 스니펫**, 검색어 강조) → 선택 시 **해당 메시지 위치로 이동**.
3. 상태 전부 처리: 입력 전 / 검색 중 / 결과 없음 / 오류. 디바운스. 결과 없음은 정직하게(검색 범위가 한정적이면 그 사실을 한 문장으로).
4. **모바일 동등** — 전체폭 검색 화면, 44px 터치 타깃, 가로 스크롤 0, 안전영역 준수. 데스크탑은 키보드 접근(⌘K류가 기존 셸에 있으면 편승, 없으면 만들지 말고 명시적 진입점).
