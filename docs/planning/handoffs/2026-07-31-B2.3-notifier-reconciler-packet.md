## 2. 할 일

### 2-1. `server-rust/bins/momo-notifier` (바이너리)
- `momo_notifier` 롤(BYPASSRLS — 전 테넌트 폴링, `bootstrap_roles.sql` 실측)로 접속. env 계약은 prod compose notifier/worker 서비스 실측 파리티.
- 두 루프를 tokio task로: reconciler(주기 실측 — Swift 값), sweep(주기 실측). 이미지 진입은 후속(entrypoint 역할 추가는 이 배치 아님 — bin까지만, compose 편입은 오케스트레이터/후속).

### 2-2. cloud lifecycle reconciler (Swift `CloudLifecycleReconciler.swift` 의미 파리티)
- durable intent claim(테이블·클레임 방식 실측 — FOR UPDATE SKIP LOCKED류) → provider adapter로 실상태 probe → **수렴은 반드시 momo-t3 API 경유**(t3_terminate·lifecycle lock — reconciler에 정산 SQL 0).
- **T-4 수렴 규칙 실측 이식**: `provider_missing`(probe 부재 보고 → 종료 수렴), deadline(057 — 기한 도과 세션 강제 수렴), 국면별 수렴표. Swift와 마이그레이션 중 충돌하면 **마이그레이션(DB)이 정본**.
- advisory lock 존중: 호스트 단위 직렬화(`acquire_t3_lifecycle_lock`) 안에서만 전이.

### 2-3. tier fallback sweep (`TierFallbackSweep.swift` 의미 파리티)
- stale 판정(hearbeat/last_seen 기준 실측)→host-lost 전이→세션 수렴. sweep 그레이스·주기 값 실측(하드코딩 금지, env 기본값).

### 2-4. conformance (`#[ignore]`, 오케스트레이터 실행)
- **provider_missing 수렴**: mock-a 호스트에 세션 → mock probe가 부재 보고 → reconciler 1 iteration → 세션 `t3_terminate` 경유 수렴·정산 1회·`settled_at` 봉인 유지. **red**: probe가 죽음을 숨기면(존재 거짓 보고) 수렴 안 됨을 이름 있는 단정으로.
- **deadline 수렴**: 기한 도과 세션 → reconciler → 수렴. 
- **이중 정산 0**: reconciler 2 인스턴스 동시 1 iteration → 정산 1회(advisory+intent claim이 직렬화).
- **sweep host-lost**: heartbeat 고사 호스트의 세션 → sweep → 전이·수렴.
- 기존 스위트 공유 DB 무회귀 전제(잔여 정리 패턴은 relay 하니스 참고).
