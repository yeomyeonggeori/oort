## 2. 할 일

### 2-1. `server-rust/bins/momo-server` (Axum 바이너리)
- **Config**: env에서 로딩 — `DATABASE_URL`(또는 PG* 조각), `PORT`, `MOMO_JWT_SECRET`(HS256), `MOMO_ENV`. Swift `Config.swift` 참고하되 **이 배치가 쓰는 것만**(전체 이식 금지). `.env` 파일 읽기 금지 — env 주입은 실행자 몫.
- **auth 미들웨어**: `Authorization: Bearer <JWT>` → `momo-auth` 검증 → `Principal`(member/token/workspace) request extension. 실패 401. Swift `AuthMiddleware.swift` 의미 파리티(만료·서명 오류 구분은 Swift 응답 코드 따름).
- **route (이 배치 범위)**:
  - `GET /healthz` — DB ping 포함.
  - `POST /v1/auth/login` — **Swift 실측 파리티**: 기존 로그인 엔드포인트(경로·요청/응답 형태)를 `AuthRoutes.swift`에서 실측해 동일하게. password 검증은 스키마의 password_hash 방식(005 마이그레이션·pgcrypto) 실측 후 동일 알고리즘.
  - `POST /v1/channels/{id}/messages` — `momo_messaging::send_message` 호출. 요청/응답 형태는 Swift `MessageRoutes` 실측 파리티(멱등 `client_msg_id` 포함).
  - `GET /v1/channels/{id}/messages` — `list_messages`. (Swift의 페이지네이션 파라미터 실측, 최소 `limit`.)
  - 경로 프리픽스·이름이 Swift와 다르면 **Swift 쪽이 정답**(클라 재배선 최소화 — B4 원칙).
- **배선 불변식**: 모든 tenant write는 `with_tenant_tx` 경유. route 계층에 raw SQL 금지(도메인 crate API만). workspace 식별은 Principal에서.

### 2-2. `server-rust/bins/momo-relay` (outbox 소비 바이너리)
- Swift `relay/OutboxRelay/RelayService.swift` 의미 파리티:
  - claim: `SELECT ... FOR UPDATE SKIP LOCKED`로 `kind='broadcast'` pending 배치 → 같은 tx에서 `processing`. **B0의 `momo_outbox::claim_batch` 골격을 완성/사용**(outbox SQL은 momo-outbox 소유 유지 — relay 바이너리에 raw outbox SQL 금지, 필요한 상태전이 API를 momo-outbox에 추가).
  - publish: Centrifugo HTTP `/api/publish`(api key 헤더), `version=seq`·`idempotency_key` 전달. 페이로드는 outbox row의 `payload`(BroadcastPayload) 그대로.
  - 성공→`done`+`processed_at`, 일시 실패→`pending`+백오프(`available_at`, attempts), maxAttempts→`failed`. 
  - wakeup: `LISTEN outbox` + 폴백 폴링(300ms 스펙).
  - **BYPASSRLS `momo_relay` 롤로 접속**(테넌트 전체 드레인). 
- Centrifugo HTTP 클라이언트는 최소 구현(reqwest 등 워크스페이스 의존 추가 OK — `Cargo.toml` workspace deps에).

### 2-3. 통합 conformance (`#[ignore]`, 오케스트레이터 실행)
`bins` 또는 `momo-outbox` tests에:
- **#2 전송전용 e2e**: DB에 send_message → relay 1 iteration → mock Centrifugo(로컬 HTTP 서버 — 테스트 내 axum/hyper listener)가 받은 publish의 `channel`·`version=seq`·`idempotency_key` 단정 → outbox row `done`. Centrifugo 서버 실물 불요(mock 수신자로 계약 단정).
- claim 경합: 두 relay 인스턴스 동시 claim → 같은 row 이중 publish 없음(SKIP LOCKED).
- 실패 백오프: mock이 500 → row가 pending+attempts+1+available_at 미래로.
- HTTP smoke: `momo-server`를 테스트 내 기동(임의 포트) → login→JWT→send→list 왕복 + 401 케이스. (DB 필요라 `#[ignore]`.)
