# goal RN-S1 — RN 스파이크 하네스 (#837 게이트 1·2·3·5)

너는 momo(제품명 oort) 레포의 구현 worker다. 이 문서가 유일한 지시서.
**base = `track/engine`**(`a591bc62`). 워크트리 `~/projects/momo-tracks/momo-worktrees/RN-S1-spike-harness`(브랜치 `feat/RN-S1-spike-harness`, 생성됨).

발단: ADR-0137(**Accepted**, bare RN + Expo 모듈 낱개, EAS 미도입)의 첫 티켓 **#837 = 구현이 아니라 스파이크**. 성재가 착수 지시.

## 0. 이 배치의 성격 — 착각하지 마라
- **산출물은 코드가 아니라 판정 보고서다.** 스파이크 코드는 **버려지는 것이 정상**이다. 재사용하려고 품질을 올리지 마라.
- 그러나 **계측은 진짜여야 한다.** 눈대중·추정 금지. 수치와 근거를 남겨라.
- **6항목 중 하나라도 FAIL이면 구현 착수 금지**다. 애매하면 **FAIL로 적어라**. 스택 선택 자체가 재검토 대상이 될 수 있다 — 네가 "대체로 되는 것 같다"고 적으면 그 판단 위에 수만 줄이 쌓인다.
- 너는 게이트 **1·2·3·5**를 맡는다. 게이트 4(푸시/NSE)는 다른 워커, 게이트 6(Android)은 2차다.

## 1. 규율
`.env`·자격증명 금지(파일명 출력도) · **PR 후 STOP**(amend/force-push 금지, 머지·close 금지) · 워크트리 밖 파일은 **읽기만** · `schema_v0.sql` 수정/이동 금지 · 서버 코드 수정 금지.
설치 허용: 이 프로젝트 로컬 npm 의존성, 그리고 **iOS 빌드에 필요한 CocoaPods**(`brew install cocoapods` — 현재 미설치, 시스템 ruby 2.6이라 gem 설치 말고 brew를 써라). watchman도 없으면 brew로 넣어도 된다. **그 외 전역 설치는 하지 마라.**

## 2. 현재 환경 (오케스트레이터 실측)
Node **v24.14.0** · npm 11.13.0 · **Xcode 26.5 있음** · **CocoaPods 없음** · watchman 없음 · 시스템 ruby 2.6.10 · Android SDK **없음**(게이트 6은 이번 범위 아님).

## 3. 놓을 자리
`clients/mobile-spike/` — **버려질 스파이크임을 디렉터리 이름과 README로 못박아라.** ADR-0137 D3의 `packages/momo-core` 모노레포는 **스파이크 전항 PASS 후의 다음 티켓**이다. 지금 모노레포를 만들지 마라.

## 4. 게이트별 할 일

### 게이트 1 — 한글 IME (**최우선. 이게 FAIL이면 나머지는 의미 없다**)
관련 이슈: RN `#48497`(open, 재현코드 첨부) · `#55257`(open, "[Japanese Market Blocker] Missing IME Composition Underline") · 수정 PR `#56082`가 `mergeable_state: blocked`.
**정직한 심각도**: 확증된 증상은 **조합 밑줄 소실**이다. "한글 입력 불가"는 집계 이슈의 서술이고 RN팀이 재현하지 못했다. 반증 신호로 **Mattermost(New Arch, 한·일 사용자 다수)에 열린 CJK 이슈 0건**. 이 구분을 보고서에도 유지해라.

계측 화면을 만들어라. **2벌식 · 천지인 · iOS 기본 한글** 각각에서 아래 4가지를 판정할 수 있어야 한다:
1. 조합 중 **밑줄 표시**
2. 조합 중 **백스페이스** 동작
3. **controlled value**(React state로 값을 통제) 조합 깨짐 여부 — 우리 컴포저가 controlled다
4. **조합 중 리렌더**가 끼는 경우(멘션 자동완성처럼 매 keystroke마다 목록이 갱신되는 상황을 재현해라)

화면이 **스스로 증거를 남기게** 만들어라: 키 이벤트·composition 이벤트·value 변화를 타임라인으로 화면에 찍고, 사람이 스크린샷 한 장만 찍으면 판정이 되게. 사람이 눈으로 "밑줄 보이나?"만 답하면 되는 항목과, 앱이 기계적으로 답하는 항목을 나눠라.

### 게이트 2 — URL 폴리필 + `oort://join` 실왕복
`new URL`/`URLSearchParams`가 웹에 **15개 파일**에서 쓰인다 → `react-native-url-polyfill` 선결.
**판정 기준 = `deepLink.ts`가 무수정 통과하는가.** (주의: B13에서 스킴이 `momo://` → `oort://`로 이관됐다. 발급은 oort, 수용은 양쪽이다. 최신 `clients/web/src/.../deepLink.ts`를 읽어라.)
통과 못 하면 **어댑터 크기를 실측**해 보고(몇 줄인가, 무엇이 안 되는가).
이 항목은 상당 부분 **기기 없이도 판정 가능**하다 — 가능한 만큼 지금 판정해라.

### 게이트 3 — centrifuge-js 실왕복 + 리플레이 게이트
- centrifuge-js가 RN에서 **실제로 붙는지**(공식 지원 표기는 확인됨 — 표기가 아니라 실측이 필요).
- **리플레이 게이트가 동작하는지**: 웹의 `gate:resume`이 검사하는 성질(끊김 후 재연결 시 빠진 메시지를 seq로 복구)이 RN에서도 성립하는가. 웹 게이트 스크립트를 먼저 읽고 **같은 성질**을 재라.
- 붙일 대상은 로컬 스택이 원칙이다. 실서버(app.oor7.com)에 붙이려면 자격증명이 필요하니 **시도하지 말고**, 필요하면 보고서에 "실서버 왕복은 오케스트레이터 몫"으로 남겨라.
- **Android cleartext**(`ws://*.local`이 Android 9+ 기본 정책에 막힘)는 게이트 6 소관이다. 여기서는 **무엇이 막히는지 문서로만** 정리해라.

### 게이트 5 — 타임라인 리스트 3자 실측
난점은 가상화 성능이 아니라 **inverted + 스크롤 위치 보존**이다. Mattermost는 여기서 **RN 코어 Fabric ObjC++를 패치**했다(`RCTScrollViewComponentView.mm`).
단 **FlashList v2는 New Arch 전용이고 `maintainVisibleContentPosition`을 기본 활성화**해 인버티드 채팅에 유리해졌다 — Mattermost의 판단(v2 이전)을 그대로 승계하지 마라.

**3자를 1k행 기준으로 실측**: `Animated.FlatList` / **FlashList v2** / `@legendapp/list`(채팅을 1급 시나리오로 설계).
판정 기준은 **프레임률만이 아니다**:
- 1k행 스크롤 프레임률(측정 방법을 보고서에 적어라)
- **새 메시지 도착 시 스크롤 위치가 튀지 않는가** ← 이게 진짜 판정 항목
- 과거 메시지 프리펜드(위로 로드) 시 위치 보존
- 한국어 가변 높이 행(2~5줄 섞임)에서의 동작

## 5. 시뮬레이터 금지선 (티켓 명시)
**IME·푸시·스크롤 보존은 시뮬레이터가 거짓말한다.** 시뮬레이터로 낸 수치를 PASS 근거로 쓰지 마라.
→ 그러니 이 배치의 실제 산출은 **"기기에 꽂으면 즉시 판정이 나오는 하네스" + "기기 없이 이미 판정된 항목"** 두 가지다. 기기 검증은 성재의 iPhone이 필요하고 오케스트레이터가 별도로 잡는다.
**보고서에 항목마다 상태를 셋 중 하나로 명시해라**: `PASS(근거)` / `FAIL(근거)` / `기기대기(무엇을 어떻게 재면 되는지 + 사람이 할 조작 순서)`.
