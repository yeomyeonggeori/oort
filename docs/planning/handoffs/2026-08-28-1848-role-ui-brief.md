# 워커 브리프 — #1848 웹 명부 역할 변경 UI 배선 (uxui)

> 워커: cursor-agent grok-4.6-high-fast · 병렬 1 · base=origin/track/uxui
> 정지 조건: 머지·이슈 close 금지(오케스트레이터 몫). 서버 코드 무접촉(이 티켓은 클라 배선만).

## 배경 (2026-08-28 종합 테스트 실측, #1848)
- 서버에는 `PATCH /v1/workspaces/{ws}/members/{member}/role`이 **완비**되어 있다(`server-rust/bins/momo-server/src/routes/member_lifecycle.rs:67` — owner/admin 게이트·감사·outbox·last-owner 보호). 클라가 호출하지 않아 owner가 admin 위임을 하려면 curl뿐.
- 웹 명부 프로필(`clients/web/src/features/directory/MemberProfileDialog.tsx`)은 역할을 읽기 전용 `Fact`(143행 `{role && <Fact term="역할">{role}</Fact>}`)로만 표시한다.

## 서버 계약 (변경 금지 — 이대로 소비)
- 요청: `PATCH /v1/workspaces/{ws}/members/{member}/role`, body `{"role": "owner"|"admin"|"member"|"guest"}`. 응답에 적용된 `role`(db 라벨)이 실린다.
- 거부 형상(`server-rust/crates/momo-settings/src/membership_lifecycle.rs` `change_workspace_role_in_tx`):
  `CannotManageSelf`(자기 자신) · `CannotManageEqualOrHigher`(동급·상위 대상) · `AdminsCannotGrantAdminOrOwner`(admin이 admin/owner 부여) · `LastOwner`(마지막 owner 강등) · 비운영자 403.
- **클라에서 이 규칙들을 재현(사전 차단)하지 않는다** — 서버가 권위, 클라는 거부를 문장으로 표면화만 한다. 유일한 클라 게이트는 아래 "노출 조건" 두 가지.

## 구현 계약
1. **API 함수 신설** — `packages/momo-core/src/lib/api.ts`에 workspace 멤버 역할 변경 함수 1개(PATCH 위 경로). 채널 role 엔드포인트(`…/channels/{ch}/members/{member}/role`)는 **범위 외**.
2. **컨트롤 위치** — `MemberProfileDialog`의 역할 `Fact` 자리. 노출 조건 2개만:
   - viewer가 operator일 때(명부의 자기 행 `memberFor(directory, session.member.id)?.role ∈ {owner, admin}` — roster projection이 서버 truth),
   - 대상이 자기 자신이 아닐 때(self는 서버도 `CannotManageSelf` — 읽기 전용 유지).
   그 외(비운영자·self)는 현행 읽기 전용 Fact 유지. 에이전트 행도 동일 표면(별도 분기 신설 금지 — 에이전트=member, ADR-0004).
3. **셀렉트 4종 + 명시 적용** — owner/admin/member/guest. 표기는 `roleLabel`/`useRoleLabels` 오버라이드(#1770 role_labels)와 정합 — `DEFAULT_ROLE_LABELS`·워크스페이스 오버라이드를 옵션 라벨에도 적용. 선택 즉시 발사 금지, 명시적 적용 액션으로 1회 호출.
4. **낙관적 갱신 금지** — 성공 시 `["roster", workspaceId]` invalidate로 서버 값 재조회 후 반영. 요청 중 컨트롤 disabled + `aria-busy`.
5. **거부 표면화** — 400/403/409를 `InlineBanner`로 문장 도달(기존 DM 오류 배너 패턴 준수). 재시도 액션 포함.
6. **상태 4종·접근성** — 오프라인(`connStatus === "disconnected"`)이면 컨트롤 disabled + 기존 오프라인 배너 사유 연결(`aria-describedby`). 키보드 전 경로 조작 가능, 포커스 이탈 없음. 카피는 문장형 한국어(기존 다이얼로그 톤 준수).

## red proof (선행 커밋)
- 비운영자(member/guest) viewer → 컨트롤 미노출·읽기 전용 Fact 유지.
- self 프로필 → 컨트롤 미노출.
- operator viewer → 셀렉트+적용 노출, 적용 시 PATCH 1회·body 정확.
- 서버 403/409(LastOwner 등) 모킹 → 배너에 문장 도달, 역할 표시는 이전 값 유지(낙관 갱신 없음 증명).
- 성공 모킹 → roster invalidate 발생 확인.
- role_labels 오버라이드 존재 시 셀렉트 라벨에 반영.
