## 1. 목표

## 2. 할 일

### 2-1. `server-rust/Dockerfile` (멀티스테이지)
- build 스테이지: `rust:1.80+`(slim) — 워크스페이스 빌드 `cargo build --release --bin momo-server --bin momo-relay`. 의존 캐시 레이어(Cargo.toml/lock 선복사→dummy build→소스 복사) 적용.
- runtime 스테이지: `debian:bookworm-slim` + **`postgresql-client`**(마이그레이션 러너가 psql shell-out — B0 교훈) + ca-certificates. 두 바이너리 복사.
- entrypoint 스크립트: 첫 인자로 역할 선택 — `api`(momo-server) | `relay`(momo-relay) | `migrate`(러너 CLI — 없으면 §2-2). prod compose가 `command: ["api"]` 패턴이므로 동일 계약.
- 마이그레이션 SQL: 이미지 안에 `server/Migrations/*.sql` 복사(러너가 읽을 경로 — 러너의 경로 해석이 `CARGO_MANIFEST_DIR` 기반이라 **런타임 경로 인자/env로 오버라이드 가능한지 실측**, 안 되면 momo-db에 env 오버라이드 공개 API 추가 허용·명시).
- `.dockerignore`(target/ 등).

### 2-2. migrate 진입점
- `momo-db` 러너를 부르는 소형 bin(`server-rust/bins/momo-migrate` 또는 momo-server 서브커맨드 — 네 판단·근거 명시): `DATABASE_URL`+`MOMO_MIGRATIONS_DIR`(+`MOMO_AGENT_SEED_MODE` 매핑) → `run_migrations` → applied/skipped 출력, 실패 시 비0 exit. prod compose의 `migrate`/`runtime-roles` 서비스 자리에 꽂힌다. runtime-roles는 psql로 `infra/e2e/bootstrap_roles.sql`(스테이징)·prod 상당물 적용 — prod compose 실측 후 동일 패턴.

### 2-3. env 계약 파리티 (중요 — 실측)
- **prod compose api 서비스의 env 이름이 정본**: `HOST`·`PORT`·`DATABASE_URL`·`JWT_HMAC`·`CENT_API_URL`·`CENT_API_KEY`·`MOMO_ENV` 등(`docker-compose.prod.yml:148-162` 실측). 현 Rust Config가 다른 이름(`MOMO_JWT_SECRET` 등)을 읽으면 **Rust Config를 prod 이름으로 정렬**(B1.5 Config 수정 허용 — 이 배치의 정당 표면). relay도 동일(`:200-` 실측).
- Rust가 아직 안 쓰는 prod env(webhook 키 등)는 **무시**하되 부팅을 막지 않게. 단 필수 env 누락 시 명확한 에러(fail-fast).

### 2-4. `infra/rust/docker-compose.rust.yml`
- prod compose 구조 미러(실측): postgres(pgvector 동일 digest)·centrifugo(v6 동일 digest·`infra/centrifugo.json` 참조)·migrate·runtime-roles·api(`${MOMO_RUST_IMAGE}` + `command:["api"]`)·relay(같은 이미지 `command:["relay"]`). caddy·redis·prometheus·worker·web은 **제외**(메신저-부분 smoke 최소셋).
- 로컬 빌드 오버라이드: `docker-compose.rust.build.yml`(image 대신 `build: server-rust`).
- `infra/rust/README.md`: 로컬 기동 절차(빌드→migrate→api/relay→smoke 곡선: login→send→list, relay가 Centrifugo에 publish 확인 방법) + NCP 절차와의 연결(런북 §3 참조).
