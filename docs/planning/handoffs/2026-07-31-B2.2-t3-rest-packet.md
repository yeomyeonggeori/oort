## 1. 목표
NCP T3 smoke 곡선을 REST로 완성: **호스트(BYOC) 등록 → 세션 생성 → 상태 조회 → 종료(t3_terminate 경유) → 과금 조회.** momo-t3가 이미 conformance로 증명한 도메인 로직을 momo-server에 마운트한다. mock provider로 곡선이 닫히면 NCP에서 실 workd 없이도 T3 부분 smoke가 가능해진다.

## 2. 할 일 — momo-server에 T3 route 모듈

### 2-1. work-hosts (BYOC 등록 — Swift `WorkHostRoutes.swift` 실측 파리티)
- `POST /v1/workspaces/:ws/work-hosts`(등록 — 부트스트랩 토큰 흐름 실측: 토큰 발급인지 직접 등록인지 Swift 확인 후 동일하게) · `GET /v1/workspaces/:ws/work-hosts`(목록) · `DELETE .../work-hosts/:host`(revoke) · `POST .../work-hosts/:host/heartbeat`(**workd 서명 검증 — momo-auth WorkHost 검증기 사용**, 미들웨어 밖 경로임을 실측 확인).
- 상세 조회 GET 2종(`:97`·`:101` 실측)과 `:105` POST의 실체 실측 후 smoke에 필요한 것만(전부면 전부 — 판단·근거).

### 2-2. work-sessions (수명주기 — Swift `WorkSessionRoutes.swift:120-123` 파리티)
- `POST /v1/workspaces/:ws/work-sessions`(생성 — momo-t3 lifecycle 사용, T3면 cloud_host 바인딩) · `PATCH .../work-sessions/:session`(종료 — **t3_terminate 경유만**, momo-t3 API) · `POST .../work-sessions/:session/resume` · `GET /v1/workspaces/:ws/work-sessions`(목록/상태).
- 요청/응답 DTO·상태코드는 Swift 실측(2676 LOC 전부가 아니라 이 4 엔드포인트의 계약만).

### 2-3. usage/credit 조회
- `GET /v1/workspaces/:ws/usage/summary`(Swift `UsageSummaryRoutes.swift:30` 파리티) — smoke의 "과금 계상 확인" 단계.
- `POST /v1/admin/workspaces/:ws/credits/topups`(`CloudCreditRoutes.swift:30`) — smoke에서 크레딧 사전 적립이 필요하면(실측: 세션 생성이 잔액 검사하는지) 포함, 아니면 제외·근거.

### 2-4. HTTP smoke 확장 (`#[ignore]`, 오케스트레이터 실행)
`http_smoke_pg.rs`(또는 신규 `t3_smoke_pg.rs`)에 **전체 곡선 1개**: login→(필요시 topup)→BYOC 호스트 등록(mock provider `mock-a`)→세션 생성→상태 조회→종료→`settled_at` 확인+usage summary에 계상 확인. red: 종료를 직접 UPDATE로 바꾸면 봉인 트리거에 거부(B2.1 conformance와 접합).
