## 4. 지켜야 할 계약 (첫 배치 패킷 §4 전체 + 추가분)

- 서버·clients/macOS 무변경. 스펙이 코드와 어긋나면 멈추고 이탈 보고(drift 게이트가 잡는다).
- 작성 멱등: `clientMsgId` 재사용 재전송이 중복 메시지를 만들지 않음을 smoke로 실증. 표시는 서버 echo(브로드캐스트/backfill) 기준 — seq 권위(M1) 준수, 클라이언트 임의 정렬 금지.
- read-state cursor는 단조 전진만(서버가 보장하지만 클라도 후퇴 PUT을 보내지 않는다). unread 계산은 서버 projection이 권위.
- 승인 카드는 ADR-0112 기본 모드 문법: "무엇을 하려는지 + 승인/거부"만. tool JSON/비용 노출 금지.
- 401 initial-auth/세션 만료 처리와 토큰 정책(D3-A)은 기존 `auth/session.ts` 경로 재사용 — 새 저장 위치 금지.
- `/join/<code>`: join 응답 스키마는 openapi 정본을 따른다. 응답이 로그인 토큰을 포함하지 않으면 가입 성공 → 로그인 폼 프리필로 연결(스펙을 앞지르는 자동 로그인 구현 금지). 초대 오류(만료/소진/revoked)는 서버 오류 envelope 기반 사용자 카피.
- CSP·websocket-only transport 계약 유지(connect-src 확장 금지 — 필요 시 멈추고 이탈 보고).

## 5. 알려진 함정 / 컨텍스트

- `user:read-state#<member-id>`의 member-id 표기(대소문자)는 서버 outbox가 굽는 채널명이 정본 — relay 대조는 첫 배치 리뷰 방식(ReadStateRoutes/outbox 코드 확인)을 승계할 것.
- approval decision의 409(이미 결정됨)는 receipt 스키마로 오며 정상 흐름의 일부(다른 탭/기기 선결정) — 오류 토스트가 아니라 카드 상태 갱신으로 처리.
- e2e 시드에 pending approval이 없을 수 있다 — drift 게이트(`verify_openapi_contract.sh`)의 픽스처 SQL 패턴을 참고해 smoke 픽스처를 구성하라.
- 초대 코드는 `POST /v1/workspaces/:ws/invites`(owner/admin)로 발급 — smoke에서 시드 admin 계정 사용.
- momo-main(UX 트랙)이 병렬로 서버·macOS를 진행 중(MOMO-392~397) — 이 배치는 `clients/web`·smoke·docs만 만지므로 충돌 없음. **서버 파일에 손대는 순간 트랙 경계 위반이다.**
