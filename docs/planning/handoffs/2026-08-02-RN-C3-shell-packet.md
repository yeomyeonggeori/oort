## 2. 범위 (이번 배치)
1. **내비게이션 셸** — 인증 전/후 분기, 탭 또는 스택 구조. **v0 범위 밖 화면을 위한 자리를 만들지 마라**(설정·디렉터리·업데이트는 D5 제외 항목).
2. **인증** — 서버 주소 → 로그인 → 세션 복원 → 로그아웃. 스캐폴드의 `ConnectScreen`·`SessionPort`·키체인 저장을 이어받아 **완성**한다. 초대 코드 참여(`oort://join` 딥링크가 이미 콜드스타트로 들어온다)도 여기서 착지시켜라.
3. **사이드바(채널/DM 목록)** — 워크스페이스의 채널·DM·에이전트를 나열하고 선택하면 **대화 화면 자리**로 이동. 대화 화면 자체는 다음 배치이므로 **자리표시자 하나**만 두고, 그 파일은 다음 배치가 통째로 대체할 것을 주석으로 남겨라.
4. **인박스(결정 대기)** — 승인/멘션 목록. D5가 v0의 축으로 꼽은 **"관전·승인"** 의 승인 쪽이다.

## 3. 반드시 지킬 것

### 3-1. 로직은 코어에서 온다
목록 정렬·읽음 계산·필터·라벨 문구 판정을 **RN에서 다시 짜지 마라.** `@momo/core` 의 `inbox/model.ts`·`notifications/model.ts`·`lib/api.ts` 등이 이미 답을 갖고 있다. 코어에 없으면 **왜 없는지 확인하고**(웹 전용 C군/F군일 수 있다) PR에 적어라.

### 3-2. 스파이크 제약 (실기기 실측)
- **컴포저 `value` 를 비동기로 반영하면 한글이 깨진다** — 이번 배치에 컴포저는 없지만 **검색·서버주소·초대코드 입력칸도 같은 규칙**이다. 입력 상태는 **동기**로 유지해라.
- **리스트에 `inverted` 를 쓰지 마라**(사이드바·인박스 포함). 정방향 + 필요 시 명시적 위치 보존.
- 커스텀 스킴 URL 은 폴리필 경유(이미 배선됨).

### 3-3. 모바일 UX 기본선
- **터치 타깃 44px**, 안전영역 준수, **가로 스크롤 0**.
- 오류 문구는 **한국어 사용자 문장** — 내부 코드·raw JSON·영문 원문 노출 금지(웹 B8의 원칙을 그대로).
- **미제공 표면을 있는 척하지 마라**(웹 B12의 정직화 원칙). 서버가 안 주는 것은 정직하게 접어라.
- 로딩·빈 상태·오류 상태를 **전부** 설계해라. "대체로 되는 화면"은 없다.
