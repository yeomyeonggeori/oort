# 목표 A 실행 계획 (2026-09-23, Opus 5.5 planner)

> 결정은 ADR-0187(Accepted)에 있고, 원격 작업은 ADR-0188(Accepted)에 있다. 배포 게이트는 [M7](../cicd/03-store-readiness-gate.md)의 M7-I·M7-S다.
> 이 문서는 **파도 표와 iOS 범위 권고안**만 둔다. 진행 상태의 정본은 [CURRENT_STATE](CURRENT_STATE.md)와 이슈다. 대체하는 편성: `2026-09-22-plan-revision.md` §4, `2026-09-02-launch-program-plan.md` 09-08 상자.

## 1. 끝 그림
- **데스크탑:** 팀원 맥에 공증 DMG로 설치되고, 자동 업데이트된다.
- **iOS:** TestFlight로 시작해 App Store로 간다.
- 둘 다 **Railway 팀 인스턴스** 하나에 붙어 매일 메신저로 쓴다.
- 폰에서 할 수 있는 일:
  - 알림을 받는다.
  - 에이전트에게 일을 시킨다.
  - 데스크탑의 Claude Code·Codex 세션을 따라가며 권한 요청을 승인한다.
  - 이 모두를 Tailscale 없이 한다.

## 2. iOS 범위 (2026-09-23 — 경계는 성재 결정, 표는 기안자 권고)
- **성재 결정(결재 질문 응답):** 「원격 작업까지 팀 배포 전에」. M7-I 팀 배포는 ADR-0188 R1(데스크탑 세션 관전·권한 승인)까지 기다린다.
- **기안자:**
  - 「독」은 기안자 읽기(데스크탑 작업 세션을 따라가고 폰에서 작업을 끝까지 요청)대로 둔다. 결재 질문 문안에 이 읽기를 적었고, 성재는 이의가 없었다.
  - 내부 테스트 기간은 기본값 2주다. S-1 하한과 같고, 성재 확정을 기다린다.
  - 아래 표의 칸 배치는 기안자 권고다.

표의 기준은 두 가지다. 매일 쓰는 빈도, 그리고 Buzz 모바일 실측선(부록 A)이다. Buzz 모바일은 대화와 관전까지이고, 승인·작업 생성·중단이 없으며 공개 푸시도 아직 없다. **Codex·Claude 같은 원격 작업은 Buzz를 넘는 부분**이라 ADR-0188로 따로 짓는다.

| 기둥 | M7-I 팀 배포 전 | M7-S 스토어 전 | 넣지 않음 |
|---|---|---|---|
| **대화** | 타임라인 승인 버튼과 결과 카드(#1084+#2513), 안읽음 표시(#1964), 점프 항법(#1892), 본문 렌더(#1048), 시간 경계(#1083), 복사(#1049) | 컴포저(#1752·#1103), 이모지(#1748), 초안 패널(#1908), 인용 답글(#1045), 작성 중(#1046), 채널 관리(#1278), 온보딩 S3(#2090), 링크 프리뷰(신규) | 음성 메모, 허들, 포럼 |

- M7-I 전 목록은 **팀이 첫날부터 메신저로 쓰고, 데스크탑 세션을 폰에서 따라가며 승인할 최소선**이다. 폰에서 새 작업을 시키는 R2가 오기 전까지 팀은 Tailscale 임시 경로를 쓸 수 있다(ADR-0187 D2).
- 오래된 폰 이슈는 착수 전에 현재 코드와 대조해 이미 된 것을 닫는다. #1045–#1103은 7–8월 적립분이다.

## 4. 성재가 할 일
1. **결재:**
   - 2026-09-23에 모두 받았다: iOS 범위(원격 R1까지 팀 배포 전), ADR-0188 Accept, 데스크탑 next = 팀 채널, W1 전부(코드 레인·Railway 배포와 APNs sealed 변수·v0.1.6 발행·첫 증거 빌드 2종).
   - 남은 것: 내부 테스트 기간(기본 2주), M7-I 승인 단위 완화 여부, 스토어 직행 여부, Enterprise Trust 연기(ADR-0187 §3·§4).
2. **계정·콘솔(짧은 확인):**
   - Apple Developer에서 APNs 키 `4SSR3XS7WZ`의 환경 범위에 Production이 있는지 확인
   - Xcode › Settings › Accounts 세션이 유효한지 확인
   - 폐기된 Distribution 인증서를 키체인에서 삭제
   - **첫 TestFlight 업로드 전:** ASC의 내부 그룹 자동 배포와 Xcode Cloud TestFlight 액션이 꺼져 있는지 확인하고 날짜를 남긴다(M7 증거 빌드 조건)
3. **기기:** TestFlight 초대 수락, 실기기 푸시 확인, M7-I 스모크 30분.
4. **배포 건마다 owner 승인:** TestFlight 업로드, 공증 DMG 전달, next 게시 때 승인 한 줄(발화 인용)을 받는다.
5. **나중에:** Developer ID 인증서(G1, 2027-02-01 만료)를 G2로 갱신한다.

## 부록 A — Buzz 모바일 실측 (2026-09-23)
- **공개판에 있는 것:**
  - 채널·스레드·DM·멘션·미디어·음성 메모·검색·포럼·허들.
  - QR과 6자리 SAS로 데스크탑과 같은 신원.
  - Activity 인박스. 읽음·별표·음소거·섹션·리마인더가 기기 간 동기화된다.
  - 내 에이전트의 **실시간 관전**. 소유자만 볼 수 있고, 지난 기록은 없다.
- **요청하는 방법:** 멘션이나 DM뿐이다. 작업 중에 새 메시지를 보내면 실행 중인 작업에 섞여 들어간다(harness 기본값).
- **없는 것:**
  - 승인·거부. 인박스 행은 있지만 그 이벤트를 만드는 코드가 없다.
  - 작업 생성 화면, 중단, 모델 전환, 터미널, 오프라인 캐시.
- **푸시는 공개 사용자에게 나가지 않았다.** README 원문은 「Push has not shipped to existing users」이고, 앱 리뷰에 알림 불만이 반복된다.
- **oort가 넘을 자리:** 공개 빌드에서 믿을 수 있는 푸시, 폰 승인, 중단.

## 부록 B — Codex·Claude의 폰 원격 제어 (2026-09-23)
- **VPN을 쓰지 않는다.** 에이전트가 도는 기기가 밖으로 벤더 클라우드에 연결하고, 폰은 그 클라우드를 거친다. Codex는 WSS를, Claude Remote Control은 HTTPS 등록·폴링을 쓴다.
- **공통 보안 문법:**
  - 목적별 단기 자격
  - 기기별 1:1 QR 페어링과 기기 목록 revoke
  - 생체 인증 단계 상승
  - 정화·자격 가림이 된 승인 미리보기
  - 조직 기본 꺼짐
  - 명령 단위 암호 서명은 두 제품 모두 없다. oort ADR-0146이 더 간다.
- **체감을 만드는 여섯 가지:**
  1. host 목록과 온라인 점
  2. 「나를 기다리는 것」 우선
  3. 범위가 있는 승인 카드
  4. 예약과 끼어들기
  5. host가 계산하는 diff
  6. 행동이 필요할 때 푸시
- **Claude Code Channels:** 실행 중인 세션에 메시지를 밀어 넣는 로컬 MCP 서버다. 권한 요청은 5글자 id로 폰에 넘기고, 먼저 온 답이 이긴다. 미리보기 기능이고 허용목록 제약이 있어 정식 경로로 쓰지 않는다.
- **oort에서는 Railway 서버가 중계를 맡는다.** transcript가 팀 서버에만 남아서, Claude처럼 벤더에 저장되는 문제가 없다.
