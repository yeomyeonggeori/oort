# 워커 실행 어댑터

워커를 띄우거나 실행 장애를 복구할 때만 읽는다. 모델·상한은 [PIPELINE](PIPELINE.md), 구현 계약은 [AGENTS](../../AGENTS.md)에 있다. 하네스별로 새로운 작업 정본을 만들지 않는다.

| 환경 | 실행 경로 |
|---|---|
| Codex | 요청한 모델을 지원하는 native subagent가 있으면 사용. 실제 모델·세션 ID를 확인 |
| Codex 또는 Claude Code의 로컬 Grok | 호스트에 설치된 grok-fleet의 `grok_codex_spawn.sh` / `grok_codex_resume.sh`, 또는 현재 지원되는 Grok CLI |
| 실행 도구 미설치·지원 불명 | 사용 가능한 도구와 버전을 확인하고 적용 가능한 경로만 선택. 문서의 예전 모델명/명령을 추측해 사용하지 않음 |

호스트의 grok-fleet 경로 관례는 `~/.claude/skills/grok-fleet/scripts/`다. 이는 설치 위치이며 공용 작업 상태 경로가 아니다. 실행 인자는 설치된 도구의 help를 확인한다. 로컬 코드/문서 작업에는 필요한 파일·셸 도구만 주고, DB/네트워크 검증은 해당 환경과 자원 범위를 명시한다.

입력은 이슈·필요한 패킷·기준 브랜치·허용 파일·검증·인계 지점이면 충분하다. 일반 작업에 모든 과거 실패 사례를 복사하지 않는다. 동시에 작업할 때 파일 소유권을 분리한다.

## 관측과 복구
- run 디렉터리, 실제 모델·하네스, session ID, 프로세스/종료 코드, 변경 커밋, 다음 행동을 공용 체크포인트에 남긴다.
- 관리되는 실행 세션 또는 독립 프로세스 세션을 사용한다. 백그라운드 발사 직후 실제 프로세스와 로그 생성 여부를 확인한다. PID 출력만으로 실행됐다고 판정하지 않는다.
- 로그가 멎으면 종료 코드와 프로세스 상태를 함께 본다. 죽은 worker를 다시 띄우기 전에 남은 코드·커밋을 확인한다. 지원되는 resume에는 정확한 session ID/cwd를 사용한다.
- 도구 개수 초과는 작업에 필요한 도구만 제공해 해결한다. 모델·제공자의 권한/콘텐츠 거부는 사유를 기록하고 해당 동작을 중단하며 다른 경로로 우회하지 않는다.
- 자격증명·전체 로그는 공용 문서에 복사하지 않는다. transient 실행 오류는 허용된 같은 범위에서 복구하고, 제품 정책이나 승인 범위를 임의 변경하지 않는다.

출력은 한 일 / 커밋·파일 / 검증 / PR / 남은 것·이탈로 충분하다. 구체적인 버그가 있을 때만 실패 재현·회귀 증거를 요구한다. 모든 Markdown 수정에 스크래치 변조 시험을 붙이지 않는다.
