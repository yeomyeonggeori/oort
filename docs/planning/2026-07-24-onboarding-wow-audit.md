# 온보딩 "와우" 감사 — 사이트→다운로드→첫 멘션 (2026-07-24, Fable — 성재 발제)

> 발단: "codex 앱·Raycast·Cursor(최근 Orca도)는 온보딩의 매끄러움으로 초반 부담을 줄여 성공했다. 레퍼런스 조사 후 우리 사용자가 자연스러운 온보딩 와우 UI로 온보딩할 수 있게 설계돼 있는지 검토하라."
> 방법: ①레퍼런스 4종 웹 실측 ②momo 첫 실행→첫 멘션 흐름을 코드 기준으로 전수 지도화(Explore, 파일:라인 근거) ③공식 대조 격차 판정.

## 0. 한 줄 판정

**사이트(다운로드→설치→시작 문서)와 앱 내 기본 장치(경로 선택기·quickStart 카드·빈 채널 온보딩·오류 상태)는 예상보다 탄탄하다. 그러나 레퍼런스들이 "와우"를 만드는 3대 축 — ①초대 링크 원클릭(딥링크) ②환경 자동 발견 ③로그인 직후 첫 가치 순간 — 이 전부 비어 있다.** 지금 신규 팀원은 서버 URL·초대코드·이메일을 전부 손으로 타이핑해야 하고, 입장해도 에이전트가 먼저 말을 걸지 않는다.

## 1. 레퍼런스 실측 — 매끄러움의 공식

| 앱 | 핵심 장치 | 교훈 |
|---|---|---|
| **Raycast** | 짧은 워크스루 + 히어로 액션 1개("Replace Spotlight" 단축키 설정) + 스킵 가능·`Show Onboarding`으로 언제든 재실행 + v1 설정 자동 임포트 | 가치를 몇 초 안에 체감시키는 **행동 1개**에 집중, 나머지는 스킵 |
| **Cursor** | 첫 실행 마법사가 기존 VS Code **감지 → 원클릭 임포트**(설정·확장·키바인딩·테마) | "이미 쓰던 환경 그대로" = 제로에서 시작시키지 않는다 |
| **Codex 앱** | 브라우저 핸드오프 로그인(앱에서 비밀번호 안 침) → 즉시 "폴더 열기/대화 시작". 단 "권한 하나에 패널 5장" 비판 존재 | 인증 마찰 최소화. **패널 수는 죄** — 투어를 늘리지 말 것 |
| **Orca (Stably ADE)** | 첫 실행에 `$PATH` 스캔 → 설치된 CLI 에이전트 자동 발견·목록 프리필 → 계정 연결 → 첫 실행까지 "60초" | **환경을 스캔해서 사용자 대신 채워라** |

**공식**: ①기존 컨텍스트 감지·자동 연결 ②몇 초 안에 가치를 보여주는 히어로 순간 1개 ③패널 최소·스킵 가능·재실행 가능 ④인증 마찰 최소화 ⑤즉시 체험 가치(데모/샘플).

## 2. momo 현재 상태 (코드 실측 — 있는 것)

- **경로 선택기 4종**(`MomoServerSession.swift:1176`): 초대 참여(⌘1)/기존 로그인(⌘2)/**이 Mac에서 체험(⌘3, 서버 없이 즉시 데모)**/운영자 연결(⌘4). 공식 ⑤(체험 가치)는 이미 충족.
- **검증·오류·오프라인 폴백**: URL/이메일/비번 검증, 실패 종류별 복구문, offline이면 "서버 없이 데모 열기" 제안(:1282).
- **quickStart 카드**(`MessageListView.swift:611`): "처음이라면 이렇게 시작하세요" 3단계(채널→에이전트 멘션→승인/비용) + "에이전트 호출"·"요약 요청 넣기"(@hermes 프리필) 버튼. 닫으면 영구 저장.
- **빈 채널 온보딩**(`:1815`): "이 채널을 함께 시작하세요" + 사람/에이전트 추가 동급 버튼(권한별 분기), 에이전트 추가→첫 멘션 4클릭 예산(MOMO-570).
- **멤버 인스펙터 기본 열림 + @자동완성**: 에이전트 발견 경로 존재.
- 코치마크/투어 없음 — **이건 결핍이 아니라 자산**(Codex 앱 비판 교훈: 패널 늘리지 말 것).

## 4. 제안 — "와우 온보딩" 배치 (성재 승인 대기)

원칙: 패널을 늘리지 않는다. 기존 chooser/quickStart 구조 위에 **감지·프리필·첫 인사**만 얹는다.

| 티켓 | 내용 | 트랙 | 크기 |
|---|---|---|---|
| **W-O1 초대 딥링크** | `momo://join?server=…&code=…` URL 스킴 등록 + chooser join 프리필(코드·서버 채워진 채 이름/비번만 입력). 서버: 초대 링크 발급(기존 invite에 링크 표현 추가). 웹 폴백: 링크 열면 안내 페이지→앱 열기 | 엔진+UXUI | M |
| **W-O2 LAN 서버 발견** | chooser 진입 시 Bonjour/mDNS 스캔 → "같은 네트워크에서 momo 서버를 찾았습니다: MacBook-Pro-2.local" 제안 카드(누르면 URL 프리필) | 엔진+UXUI | S~M |
| **W-O3 첫 입장 인사** | 신규 멤버 첫 입장 시 워크스페이스 에이전트가 기존 발화 경로(REST→PG→outbox)로 **실제 인사 메시지** 1건: 환영 + 할 수 있는 것 2가지 + "저를 멘션해보세요". 가짜 클라 연출 금지(봇 래핑 금지 철학) — 서버가 join 이벤트에 agent job enqueue | 엔진(+카피) | M |
| **W-O4 알파 기본값 정리** | placeholder/기본값을 배포 채널 현실로(127.0.0.1→내부알파 mDNS 예시, demo@momo.local 제거). 알파 빌드 한정 서버URL 프리필 옵션 | UXUI | XS |
| **W-O5 초대 카드 템플릿** | 운영자용 복붙 초대 메시지(다운로드 링크+서버주소+초대코드, W-O1 후엔 딥링크 1개)를 TESTER_GUIDE+사이트에 | docs | XS |
| W-O6 (장기) | Developer ID 서명+공증 — Gatekeeper 우클릭 제거. Apple Developer 계정/비용 필요 | 인프라 | 성재 결정 |

**권장 순서**: W-O4·W-O5(즉시, XS) → W-O1(최대 임팩트) → W-O2·W-O3(와우 완성). W-O1+W-O2+W-O3가 합쳐지면: **초대 링크 클릭 → 앱이 서버·코드 프리필 → 이름/비번 → 입장하자마자 에이전트가 먼저 인사** = 사이트 히어로가 약속한 그 장면이 60초 안에 실현된다.

## 6. 후속 점검 — "사이트만 보고 보조 없이 첫 사용" 워크스루 (2026-07-24, 배치 랜딩 후)

성재 질문("내가 사용자라면 웹사이트에서 보조 없이 첫 사용까지 가능한가")에 대한 실측 답.

- 페르소나 A(초대받은 팀원): 사이트→다운로드→우클릭 열기→앱 실행→초대 링크 클릭→이메일/비번→입장+에이전트 인사. **가능**(0.0.4). 초대 링크는 운영자 발송(초대제 설계상 의도) — TESTER_GUIDE §7 카드가 그 전달을 표준화.
- 페르소나 B(초대 없는 방문자): 앱의 ⌘3 로컬 데모로 **체험 가능**했으나 사이트가 미안내 → 막다른 길.
- 발견 격차 3건 즉시 수정(사이트 커밋): **G-A** 무초대 데모 경로 미안내 → "초대가 아직 없다면" 섹션 신설. **G-B** "시작하기"가 구식 수동 경로(서버 URL 입력이 1단계) → 초대 링크 클릭 경로+자동 발견+에이전트 인사 중심으로 재작성, 수동 입력은 폴백으로 강등. **G-C** 다운로드 버튼 JS 실패 시 `href="#"` 죽은 링크 → GitHub releases 폴백.
- 잔여 마찰(정직 목록): ①Gatekeeper 우클릭(W-O6 서명/공증으로만 해소, 성재 결정) ②momo:// 링크는 앱 설치 전 클릭 시 무반응(카드가 "앱 먼저 실행" 순서로 완화; 궁극 해법=https 유니버설 링크, 후속 후보) ③mDNS 발견은 운영자 서버 가동 중일 때만(설계상 정상) ④JS 차단 시 버전/sha 미표시(다운로드는 폴백으로 동작).
