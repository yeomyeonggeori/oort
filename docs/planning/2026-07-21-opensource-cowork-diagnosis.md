# 오픈소스화 준비도 + Figma식 cowork 진단 (2026-07-21, Fable — 성재 발제)

> 발단: 성재 4대 관점(①웹 접근 ②모바일 개발자 모드 트래킹 ③티어별 폴백 노티스 ④Mattermost급 셀프호스팅) + 외부 개발자 피드백("에이전트를 hermes처럼 호스팅해 결과물을 모두가 공유·확인·논의하는 cowork 설계 = Figma가 패러다임을 바꾼 지점").
> 결론 요약: **①④는 설계 완료·실행 대기**(Accepted ADR 존재 — 티켓 미발급), **②는 절반 계획됨**(iOS 505/506, 단 실터미널·과정 스트림 미계획), **③⑤는 설계 공백 — 이번에 설계 추가**(ADR-0125 D11 증보 + ADR-0126 신규 기안).

## 1. 웹 접근 ("호스팅 사이트 + 서버 URL 입력") — 설계 완료, 구현 0

- **정본: ADR-0119 (Accepted 2026-07-15)** — 성재 발제 그대로 "서버 URL이 곧 웹 주소".
  - D1-A: 같은 오리진 1-site(Caddy에 `{$APP_DOMAIN}` 추가, SPA+`/v1/*` 프록시 → CORS 불요)
  - D2-A: TS+Vite+React+centrifuge-js (전부 permissive)
  - D3-A: 메모리 access+localStorage refresh(내부 알파 한정, 공개 전 httpOnly 쿠키 승격 게이트 명시)
  - D4-A: openapi.yaml 정본화+생성 타입(이후 실제로 openapi가 계약 정본이 됨 — 이미 이행 중)
- **주의**: 성재 이번 발제는 "우리가 호스팅하는 사이트에서 서버 링크 입력" — 0119 D1은 셀프호스터 자기 도메인 서빙이 기본. 두 모델은 공존 가능: momo.app(우리 호스팅 랜딩)에서 서버 URL 입력 → 그 서버가 서빙하는 SPA로 리다이렉트(또는 랜딩 자체가 SPA 셸). **momo.app 랜딩 = ADR-0121 D2(초대 관통 universal link)의 1차 표면과 동일 결정** — 별도 ADR 불요, W 배치 티켓에 랜딩 모드 1장 추가만.
- **갭**: ①구현 0건(W 배치 MOMO-389+ 티켓 미발급 상태로 7/18 트랙 대전환에 밀림) ②웹 v0 범위=기본 모드만 — Work 콘솔/터미널 관전은 웹 v1+(ADR-0126과 합류) ③CORS 없음은 D1-A 하에서 무해하나 momo.app 랜딩→타 서버 API 호출 모드를 추가하면 CORS 필요(랜딩을 리다이렉트 모델로 하면 회피).
- **액션**: W 배치 티켓 발급 재개(성재 트리거). 순서 권고: W-1 셸+로그인+채널목록 → W-2 타임라인(read) → W-3 컴포저 → W-4 초대 관통 랜딩.

## 2. 모바일 개발자 모드 — 에이전트 생성과정 트래킹 (절반 계획됨)

- **있는 것**: iOS 모바일 플랜 MOMO-505(Work 탭=세션 관제 리스트)·506(세션 상세=카드 스레드 관전+개입+승인 인라인) — Claude 앱 모델. 서버 의존 전부 main 랜딩 완료(work_session/control/pool + 511-E attach + 503 push v2 `momo.work` 카테고리).
- **갭**:
  1. **iOS 실터미널 attach 미계획** — 511-U는 macOS만, iOS는 "후속" 한 줄. SwiftTerm은 iOS 지원하므로 기술 장벽 낮음. 개발자 모드 on 시 세션 상세에서 read-only 터미널 뷰(입력은 v1) = **MOMO-515 신규 티켓 후보**.
  2. **AgentPartial(생성과정 스트림) iOS 소비 미계획** — macOS AgentPartialView에 있는 스트리밍 중간출력이 iOS 505/506 수용기준에 명시돼 있지 않음 → 506 수용기준에 가산.
  3. **개발자 모드 토글의 iOS 판 규칙 미명문화** — ADR-0112(듀얼 모드)는 macOS 기준. iOS 설정에 개발자 모드 토글 + off 시 Work 탭 자체를 요약 카드로 축소(비개발자는 "작업 진행 중/완료"만) = 505 수용기준에 가산.
- **액션**: 505/506 수용기준 증보 + MOMO-515(iOS 터미널 관전) 신규 등재. 모바일 배치 발급 시 함께.

## 3. 티어별 작업 정책·폴백 노티스 (설계 공백 → ADR-0125 D11 증보)

- **있는 것**: D5 work_pool(슬롯), D6 호스트 선택기(= spawn "시점"의 선택·승인 카드), D8 보안 기본값, 503 푸시 `momo.work` 카테고리(노티 전송로).
- **없는 것(성재 지적 정확)**: ①사용자/워크스페이스 **티어 정책 설정**(T1-only / T1→T2→T3 ask / auto) ②**세션 도중 호스트 상실**(맥 닫힘 = work_host heartbeat 끊김) 감지 → "T3로 전환해 재개할까요?" 질문 노티 → 재개 흐름 ③재개의 의미론(어디까지 이어지나).
- **설계 추가(D11, Proposed)**: ADR-0125에 증보 — 핵심: v0 재개 = **"마지막 커밋 지점부터 새 세션"**(PTY 상태 이전은 불가능·불필요. E5 파일럿이 증명한 git 사이클 재사용: T1에서 커밋·push된 지점을 T3 샌드박스가 clone해 재개). 원장에 `resumed_from_session_id` 계보. 노티는 승인 카드 문법 재사용(전환도 spawn 승인의 일종).

## 4. 셀프호스팅 friendly (설계 완료 — 실행 갭 4건)

- **있는 것(강함)**: ADR-0121(D1 배포 포장·D2 초대 관통·D5 **Zulip 모델**=셀프호스팅 전 기능 무료·D6 기본 서버 비내장), ADR-0120(푸시: Dawn relay 등록 + **BYO-relay 가능** + id-only로 대화 내용 Dawn 비경유 = Mattermost MPNS 패턴 상위호환), MOMO-406 install.sh/upgrade.sh(digest 고정·rollback), permissive 스택(AGPL 백본 금지), RLS FORCE, T1/T2 완전 무료 티어(0125).
- **실행 갭(오픈소스 공개 전 필수)**:
  1. **[하드 블로커] 파일 저장 Google Drive 유일** — `GoogleDriveArchiveClient`만 실구현. 셀프호스터가 Google Workspace 없으면 첨부 불가. `DriveArchiveClient` 프로토콜이 이미 있어 구조는 준비됨 → **S3/MinIO(권고: S3 호환 1개로 셀프호스트 표준 커버) 어댑터 ADR 필요**(저장 경계 변경 = Accepted ADR 없이 머지 금지). ADR-0127 후보.
  2. **LICENSE 파일 부재 + 법무 검토 미실시**(L4 §10 — 외부 배포 전 1회 필수). 후보: Apache-2.0(permissive 하드 룰 정합).
  3. **공식 이미지 미발행** — install.sh가 기대하는 digest 고정 이미지의 발행 채널(ghcr.io) 부재. CI 릴리스 파이프라인 티켓 필요.
  4. **웹 클라 부재가 사실상 온보딩 블로커** — Mattermost류 채택 문법은 "설치 → 브라우저 접속". 현재는 macOS 앱 배포(서명/TestFlight)가 전제라 셀프호스터 마찰 큼. §1 W 배치가 셀프호스트 채택의 전제조건.
- 참고: 허들(LiveKit)은 compose에 포함(infra/livekit.yaml)돼 자체 호스팅 가능 — 갭 아님.

## 5. Figma식 cowork (피드백 반영 — ADR-0126 신규 기안)

- **이미 지향과 일치하는 것**: 세션=채널 스레드(0114 D2) → **과정이 팀 공개 원장에 남음**(중간보고·승인 카드·개입 입력 전부 스레드) — "에이전트 의존적이라 과정 확인 불가" 문제는 구조적으로 없음. BYOA(0125 D7)로 워크스페이스 공유 계정의 claude/codex를 T2/T3에 호스팅하는 것도 이미 가능. X-9 수정으로 라이브 카드 정합도 확보.
- **부족(피드백이 정확히 짚은 갭)**:
  1. **터미널 관전이 소유자 전용** — 511 계약이 owner-only 발급. "하나의 화면을 보면서 논의"가 안 됨. → **D1: read-only 관전 attach**(채널 멤버에게 입력 불가 capability 발급, 동시 N명, 관전자 수 배지).
  2. **산출물 표면 빈약** — 발췌 코드블록·PR 링크 수준. diff 카드/파일 트리 없음 → **D2: 산출물 카드 표준**(diff 카드 v0 = unified diff 렌더+파일별 접기, 커밋/PR 링크 카드 승격).
  3. **논의 앵커 없음** — 스레드 답글이 유일. Figma 코멘트 핀에 해당하는 "발췌 n번째 줄에 코멘트" 없음 → **D3: 발췌 앵커 코멘트(v1)** — 발췌 카드에 라인 앵커 reply_to 확장.
  4. **세션 소유가 개인 고정** — 작업이 개인 자산처럼 귀속. 팀 공동 소유 세션(퇴근한 소유자 대신 다른 멤버가 개입 승계) 없음 → **D4: 워크스페이스 소유 세션(v1)** — owner=member 대신 owner=workspace+operator 위임 모델.
- 정본: `docs/adr/0126-cowork-observation-surface.md` (Proposed — 성재 승인 대기).
