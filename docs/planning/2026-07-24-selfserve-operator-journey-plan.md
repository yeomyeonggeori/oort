# 셀프서브 운영자 여정 배치 계획 — "개설→초대 메일→ACP 에이전트" 실사용 루프 (2026-07-24, Fable — 성재 발제)

> 발단: "처음 momo에 들어와서 괜찮네 하고 워크스페이스 개설, 팀원 초대(가능하면 메일 전송), 필요하면 회원가입, 에이전트 호스팅해서 ACP로 붙이는, 데모 이상의 실사용 테스트를 하고 싶다."

## 0. 현재 갭 지도 (코드 실측)

| 단계 | 현재 | 갭 |
|---|---|---|
| 워크스페이스 개설 | `momo-ops workspace-create`(SQL, 운영자 CLI 전용, MOMO-571) | **인앱 생성 없음** — 서버 REST도 GUI도 부재. ADR-0117 D1-A(운영자 생성)의 "표면"을 앱으로 확장하는 증보 필요 |
| 회원가입 | 초대 코드 join(`POST /v1/join`)이 곧 계정 생성 | 사실상 충족. 공개 셀프 가입은 공개 단계 결정으로 유보 권고 |
| 팀원 초대 | **인앱 초대 생성 GUI 존재**(createInvite + 단축링크/코드 복사) | **메일 전송 없음** · 초대 공유물에 momo:// 딥링크 미포함(단축링크/코드만) |
| 에이전트 ACP 연결 | momo-workd+ACP 어댑터(WH-1)·GUI 페어링/엔진 선택(WH-2)·주소 온보딩 GUI(관리자) 전부 존재 | 끝-끝 실행 런북 부재(성재가 혼자 완주할 문서/원커맨드 없음) — 걸어보면 갭 나올 것 |

## 1. 배치 제안 (승인 대기)

| 티켓 | 내용 | 트랙 | 크기 |
|---|---|---|---|
| **W-S2 초대 메일** | 초대 생성 시트에 "메일로 보내기": `mailto:` 프리필(초대 카드 본문 + **momo://join 딥링크** + 다운로드 페이지). 인프라 0(사용자 Mail 앱). 초대 공유물에 딥링크 포함하도록 갱신. 실 SMTP 서버발송은 후속 옵션(도달성/스팸 고려 별도 결정) | UXUI | S |
| **W-S3 ACP 여정 런북+검증** | momo-workd 기동(사이드카/로컬)→GUI 페어링→엔진 선택→주소 온보딩→멘션 응답까지 성재 혼자 완주하는 런북 + 원커맨드 스크립트. 걸어보며 나오는 갭은 수리 티켓화 | docs+engine | S |
| **W-S1 인앱 워크스페이스 생성** | 서버 `POST /v1/workspaces`(인가=**등재 인스턴스 운영자**, 583 allowlist 재사용 — D1-A 정책 유지·표면만 확장) + initial owner/#general 시딩 서버화 + chooser·사이드바 "새 워크스페이스 만들기" GUI. **ADR-0117 증보 필요(기안→성재 승인 후 구현)**. 멀티WS 전환 UX(W-4 백로그)와 접점 | engine+UXUI | M~L |

권장 순서: **W-S2·W-S3 즉시(기존 자산 완성) → W-S1(ADR 증보 승인 후)**. 셋이 끝나면: 앱에서 워크스페이스 만들고 → 초대 메일 보내고 → 팀원은 링크 클릭으로 입장(에이전트 인사) → 성재는 ACP로 실에이전트 연결 — 전 루프가 앱 안에서 완결된다.

## 2. 비스코프 (명시)
- 공개 셀프 가입(초대 없는 open signup): 공개 단계 결정으로 유보.
- 서버발송 SMTP: W-S2 v0은 mailto. 필요 확인 후 별도 티켓.
