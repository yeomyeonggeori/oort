| 한 번에 | `npm --prefix clients/web run icons:brand` | 위 둘을 차례로 실행한다. 데스크탑 세트는 `cargo tauri icon`으로 만든다. |

### 대칭 기준

위성 중심과 꼬리 꼭짓점은 링 중심을 지나는 −45°/135° 대각선 위에 있다.
꼬리의 두 변은 이 축에 대해 대칭이다. 탐색본에서도 위성(−41°)과 꼬리 끝(139°)은 이미 한 직선 위에 있었다. 이 축을 45°로 반올림해 정수 격자에 올렸다.

### 틈은 잘라낸 홈이다

틈은 배경색으로 칠한 것이 아니다. 위성과 중심이 같고 반지름이 s+g인 원으로 링 바깥 윤곽을 잘라낸 홈이다.
그래서 단색판은 어떤 바탕 위에서도 한 색으로 성립한다. 인라인 컴포넌트는 mask id 없이 path 두 개로 끝난다.

## 크기별 확인

`render-brand-icons.mjs`는 단색 검정을 흰 바탕에 그린 뒤 틈 한가운데 픽셀의 잉크 비율을 잰다(0=바탕, 1=잉크).
small의 틈이 0.5 미만이고 링 몸통보다 0.35 이상 옅지 않으면 실패한다.

| 크기 | small 틈 / 링 | regular 틈 |
|---|---|---|
| 16px | 0.31 / 0.79 | 0.36 |
| 24px | 0.09 / 0.84 | 0.56 |
| 32px | 0.00 / 0.83 | 0.75 |

regular는 24–32px에서 틈이 절반 넘게 메워진다. 그래서 32px 이하에서는 small을 쓴다.
탭 파비콘, `OortMark`의 기본값(`size-4`·`size-6`), `public/oort-mark.svg`가 small이다.
온보딩 S0처럼 큰 자리는 `optical="display"`로 regular를 쓴다.

모든 값은 `clients/web/src/design/tokens.css`에 있다.

|---|---|---|---|

비텍스트 대비(WCAG 1.4.11, 기준 3:1). 스크립트가 색 상수로 계산하고, 1024 렌더의 픽셀로 다시 잰다.

| 조합 | 대비 |
|---|---|
| 앱 아이콘 링 / 바탕 | 16.66:1 |
| 앱 아이콘 위성 / 바탕 | 8.94:1 |
| 단색 검정 / 흰 바탕 | 18.01:1 |
| 단색 흰색 / 검정 바탕 | 18.01:1 |
| 단색 호박 / 검정 바탕 | 8.94:1 |

단색 호박은 **어두운 바탕 전용**이다. 흰 바탕에서 `#f0a850`은 약 2.0:1이라 기준에 못 미친다.
밝은 바탕에서는 단색 검정을 쓰거나, 앱 안에서처럼 라이트 `--accent`(`#a54c08`)를 입힌다.

## 앱 아이콘

- **전면판 (iOS·PWA):** 1024 정사각이다. 바탕이 끝까지 차고 모서리는 직각이다. 런처가 자기 모양으로 자른다.
  마크 경계 상자는 한 변의 60%이고, 중심은 캔버스 중심과 같다.
  iOS는 RGB이고 알파가 없다(App Store Connect 요구, `projectShape.test.ts`와 `ci_post_xcodebuild.sh` §6이 지킨다).
- **macOS판:** Apple 아이콘 그리드를 따른다. 1024 캔버스에 824×824 둥근 사각형(모서리 185.4)을 100 여백으로 앉힌다.
  여백은 투명이고, 마크는 판 한 변의 60%다. Tauri가 이 한 장에서 `icons/*`(icns·ico 포함)를 만든다.
- **PWA maskable:** 마크에서 가장 먼 점(꼬리 끝)이 지름 80% 안전 원의 95% 안에 들어가게 줄인다. 도달 거리는 0.380으로 측정됐다.
- 떠낸 PNG에는 모두 sRGB 청크가 있다(#2650 N-3).
- **iOS 18 다크·틴트 변형: 지금은 두지 않는다.** 바탕이 이미 어둡다. 그래서 시스템 다크 모드에서도 같은 판이 자연스럽다.
  변형을 들이면 `Contents.json`의 `appearances`가 늘어난다. 그때 `projectShape.test.ts`의 `toHaveLength(1)`도 함께 고친다(#2650 N-4).
