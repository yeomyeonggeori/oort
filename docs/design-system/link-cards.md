# 링크 카드 — 빠진 것마다 정한 대체 규칙 (#4882, owner 2026-10-31)

> **한 줄.** 링크 카드는 서버가 준 것 중 **빠진 항목마다 한 가지 모양**으로 채워요. 그림이 없으면 아이콘 타일, 제목이 없으면 사이트 이름이나 도메인, 정보가 하나도 없으면 카드 없이 링크만 남아요. 이 규칙은 **코어 `features/timeline/unfurl.ts`의 표시 모델 한 곳**에만 있고, 웹·데스크탑(이 이슈)과 폰(#4883)은 그 모델을 읽어서 그려요. 화면 쪽에는 규칙이 없어요.
>
> - 계기: owner 2026-10-31 「링크 미리보기를 Buzz·카카오톡 등을 참고해 다시 설계하고, 이미지나 제목 등이 하나씩 빠졌을 때의 기본값을 정해 달라」. 시안은 owner에게 공유한 비공개 시안 캔버스에 있어요.

## 1. 크기 셋 (이 기기 설정, 서버·다른 멤버 화면과 무관)

| 설정 낱말 | 저장 값 | 모양 |
|---|---|---|
| **작게** (기본) | `compact` | 왼쪽 그림 칸, 오른쪽에 주소(아이콘 + 도메인) · 제목 한 줄 · 설명 한 줄. 테두리 없는 카드(면은 `--surface-muted` 하나) |
| **크게** | `rich` | 글이 위(제목·설명 두 줄까지), 큰 그림이 아래(1.91:1, 높이 상한 336). 큰 그림을 채울 수 없는 링크는 작게와 같아요(§2) |
| **끄기** | `off` | 카드를 그리지 않고 본문의 링크만 남아요(예전과 같아요) |

- **기본이 「크게」에서 「작게」로 바뀌었어요.** 한 번도 이 설정을 열지 않은 사람(저장된 값이 없는 기기)은 큰 카드에서 작은 카드로 바뀌어요. 「크게」를 직접 고른 기기는 저장된 값이 있어 그대로예요. 저장 값의 이름(`rich`·`compact`·`off`)은 안 바꿨어요.
- 그림 칸은 셋 중 하나예요: **보통 그림 104×64**(칸에 맞춰 자름) · **작거나 정사각형인 그림 64×64**(자르지 않고 통째로) · **아이콘 타일 64×64**. 높이는 늘 64라서 카드 높이가 그림에 따라 뛰지 않아요.
- 설정 › 대화 표시의 **대화 미리보기 샘플**은 늘 전형적인 카드 하나(보통 그림 104×64, 크게는 1.91:1 틀)를 그려요. 아이콘 타일·작은 그림·동영상 같은 대체 모양은 샘플이 보여 주지 않고, 눌리지 않는 그림이라 같은 클래스를 다시 적었어요(어긋나면 `ConversationPreview.test.ts`가 붉어요).
- 카드 전체가 링크 하나예요(`<a>` 하나, 안에 눌리는 것 없음). 보낸 사람의 「링크 미리보기 제거」 칩과 확인 창은 예전 그대로 카드 바깥 형제 단추예요.

## 2. 대체 규칙 표 (전 행이 코어 `unfurlCardModel`·`visibleUnfurls`의 갈래예요)

| 빠진 것 | 보이는 모양 |
|---|---|
| 그림 | 그림 자리에 64×64 **아이콘 타일**. 사이트 아이콘도 없으면 기본 **지구** 아이콘 |
| 그림 받기 실패(받기 오류·그리기 오류) | 깨진 그림 대신 **같은 아이콘 타일**. 크게 카드는 작은 카드로 내려와요 |
| 설명 | 설명 줄만 빼요. **제목과 같은 설명도** 빼요(대소문자·공백 차이는 같은 것으로 봐요) |
| 제목 | **사이트 이름 → 도메인** 순서로 제목 자리에 |
| 사이트 이름 | 영향 없음. 주소 줄에는 **늘 실제 도메인**이에요. 사이트가 바꿀 수 있는 이름을 주소 자리에 두면 `apple.com`이라 부르는 가짜 사이트가 진짜처럼 읽혀서, 도메인은 서버가 링크에서 뽑은 값(없으면 링크 자체에서 읽은 값)만 써요 |
| 작거나 정사각형 그림(가로 300px 미만 **또는** 가로세로 비율 1.3 미만) | 자르지 않고 64×64 칸에 **맞춰 넣어요**. 크게 카드에서는 작은 카드로 내려와요(1.91:1 틀을 채울 수 없어서) |
| 크기를 모르는 그림(옛 서버·크기 선언 없음) | 예전처럼 자르는 보통 그림으로 봐요. 크기는 페이지의 선언이라 **분류에만** 쓰고 칸 크기를 정하는 데는 쓰지 않아요 |
| 동영상(`isVideo`) | 그림 위 **재생 표시**. 카드를 누르면 원래 페이지가 열려요(카드 안에서 재생하지 않아요). 그림이 없으면 타일 자리에 재생 표시가 서요 |
| 제목도 그림도 없음 · 받기 실패 · 차단 | **카드 없이 링크만**. 오류 문구 없음. 사이트 이름·설명·아이콘만 있는 페이지도 같아요 |
| 링크 여러 개 | **앞의 서로 다른 링크 3개까지만** 카드. 같은 페이지를 다르게 쓴 것(`#조각`, 대소문자만 다른 호스트, 주소만 있는 링크의 `/`)은 한 링크로 세요. 카드를 못 만든 링크가 자리를 비워 주지는 않아요(4번째 이후는 늘 카드 없음) |

한 줄로 된 규칙의 순서: **받은 행이 카드를 만들 수 있는가**(제목이나 그림이 있는가) → **크기와 모양**(그림 분류, 작게·크게) → **글**(제목, 설명) → **주소 줄**.

## 3. 글은 텍스트로만

- 제목·설명·사이트 이름은 서버가 방향 제어 문자(U+202A–202E, U+2066–2069)를 지워 보내요. **모델이 한 번 더 지우고** 공백 연속을 하나로 줄여요(서버 이전에 저장된 행도 있어서예요). 화면은 이 글을 **텍스트 노드로만** 그려요. `dangerouslySetInnerHTML` 금지(시험이 소스에서 재요).
- 그림·아이콘의 주소는 원격 주소가 아니에요. **서버 프록시 경로**(`…/unfurls/{id}/image`·`…/icon`)만 받고, 코어 디코더가 그 모양이 아니면 버려요. 인증은 `Authorization` 머리로만 가고 `<img>`는 `data:`로 받은 값을 써요.

## 4. 아이콘은 보일 때만, 실패는 조용히

- **카드가 화면에 보일 때 처음** 사이트 아이콘을 불러요(`IntersectionObserver`, 한 번 보이면 계속 보인 것으로 쳐요). 프록시가 그때 사이트로 나가기 때문이에요(ADR-0170 증보 D9). 엔진에 이 API가 없으면 막지 않고 바로 불러요. 그림(`imageUrl`)은 카드가 서면 바로 받아요.
- 같은 아이콘은 주소 줄과 타일이 **한 요청**을 나눠 써요(메모리 캐시·진행 중 요청 공유).
- 아이콘이든 그림이든 **실패는 지구/타일로 흡수**해요. 오류 문구는 없어요. 프록시가 **404**(사이트에 없음, 서버가 10분 기억)나 **429**(남용 막이, `Retry-After`)로 답하면 클라이언트도 기억해서, 카드가 화면에서 나갔다 들어와도 그 시간 안에는 다시 묻지 않아요(404는 10분, 429는 서버가 말한 초, 상한 1시간). 네트워크 오류는 기억하지 않아요. 기다린 뒤 다시 묻는 것은 **다음에 카드가 서는 때**예요(타이머로 따로 되풀이하지 않아요).

## 5. 키보드·접근성

- 카드는 행의 **로빙 그룹**에 합류해요(`data-row-action`). 링크 메시지마다 탭 정차가 카드 수만큼 늘지 않아요. 키보드 초점 링은 README의 `focus-visible:focus-ring`이에요.
- 접근성 이름은 **「링크 미리보기: 제목, 도메인」**(사전 키 `timeline.unfurl.label`). 동영상이면 `aria-describedby`로 「동영상」을 따로 읽어요(이름은 그대로 두고 설명으로 더해요). 그림·아이콘·재생 표시는 `aria-hidden` 장식이에요.
- 글자가 길면 작게 카드는 줄임표로 한 줄에서 끊고, 크게 카드는 두 줄(`line-clamp-2`, 한국어는 어절 유지)에서 끊어요. 오른쪽 위 제거 칩 자리(40px)는 두 크기 모두 글 쪽 끝 여백으로 비워 둬요.

## 7. 폰(#4883)에 넘기는 것

- 폰은 코어의 `unfurlCardModel`·`visibleUnfurls`·`DEFAULT_UNFURL_SIZE`를 그대로 읽어요. **표의 어떤 행도 폰에서 다시 정하지 않아요.** 가르는 문턱(가로 300, 비율 1.3, 카드 3개)은 코어 상수이고, 그림 칸의 크기(64, 104×64)는 웹에서는 토큰(`--spacing-unfurl-tile`·`--spacing-unfurl-thumb`)이에요. 폰은 같은 숫자를 자기 토큰으로 옮기고, 이 문서 §1의 모양을 따라요.
- 사전 키(`timeline.unfurl.label`·`timeline.unfurl.video`)와 429 처리(`fetchUnfurlImage`가 `Retry-After`를 오류에 실어 줘요)도 같이 써요.

## 8. 폰 판 (#4883, owner 2026-10-31 · 카카오톡 세로 카드)

폰도 코어 `unfurlCardModel`·`visibleUnfurls`가 정한 모양을 **그리기만** 해요(그림 크기·문턱·3개 상한을 읽는 코드가 화면에 없고, 폰 시험이 소스에서 재요). 이 절은 폰이 §1·§7에서 **달리 잡은 값**과 폰에만 있는 동작이에요. 코드는 `clients/mobile/src/features/conversation/UnfurlCards.tsx`예요.

- 그림 바이트는 웹과 같은 길이에요(코어 `fetchUnfurlImage` → `data:` 주소, 항목 48 · 32 MiB 상한, 404·429 기억). 폰은 JS 힙에 문자열을 들므로 더 키우려면 디스크 캐시(`memberAvatarImage.ts`)로 가야 해요.

- **아무것도 재지 않는 것**: 라이트·다크에서 실제로 어떻게 보이는지, 375/390 폭, 큰 글씨 실기기, 실제 사이트의 아이콘·그림, 길게 누르기 손맛. 캡처와 독립 design-review는 스택 검증에서 해요(`runtime-unverified`).

## 9. 보내기 전 입력칸 미리보기 (#5005·#5016, owner 2026-10-31 · 웹·데스크탑·폰)

링크를 넣고 멈추면 **보내기 전에** 입력칸 위에 카드가 먼저 떠요. 카드 한 장은 타임라인 카드와 **같은 컴포넌트**(`UnfurlCard`)이고, 무엇을 보일지는 같은 코어 표시 모델이 정해요(§2 표 전 행, 작게·크게는 이 기기 설정을 따라요). 서버 계약은 [ADR-0170](../adr/0170-link-unfurl-server-surface.md) 증보 2026-11-01(Accepted)의 D14~D22예요. 규칙(언제·무엇을 묻나)은 코어 `createComposerLinkPreviewController`(`packages/momo-core/src/features/timeline/composerLinkPreview.ts`) 한 곳이 정하고, 웹의 `clients/web/src/features/chat/useComposerLinkPreview.ts`와 폰의 같은 이름 훅은 그것을 입력칸에 붙이는 얇은 래퍼예요(#5037). 줄과 ✕는 웹 `ComposerLinkPreview.tsx`예요. 아래 표는 웹 채널 입력칸 기준이고, 스레드 입력칸과 폰 입력칸이 다른 점은 표 뒤의 「스레드 입력칸 · 폰 입력칸」에 있어요.

| 항목 | 규칙 |
|---|---|
| 언제 묻나 | 글이 바뀔 때마다 기다림이 처음부터이고, 입력이 350ms 멈추면 한 번 물어요(코어 상수 `UNFURL_PREVIEW_DEBOUNCE_MS`). 링크가 그대로면 이미 나간 요청은 두고, 답이 온 뒤에는 다시 묻지 않아요. |
| 무엇을 묻나 | 이 글이 보내지면 서버가 카드로 만들 주소와 **같은 규칙**으로 고른 앞의 서로 다른 3개예요(코어 `draftPreviewLinks`: 코드 블록·인라인 코드 안은 빼고, 끝 문장부호·`#조각`을 걷고, 호스트는 소문자, 기본 포트·경로 끝 `/`는 없애요). 서버 시험 네 개를 같은 입력으로 코어 시험이 다시 돌려서, 규칙이 갈라지면 붉어져요. 주소는 **한 번에 하나씩 차례로** 물어요(서버가 한 멤버의 동시 받기를 4개로 묶어서, 3개를 한꺼번에 보내면 그림·아이콘 자리가 모자라요). |
| 같은 주소 | 이 입력칸이 서 있는 동안 받아 둔 답을 써요. `ok`는 25분, `failed`는 2분 동안 다시 묻지 않아요(서버가 30분·2분 기억하고 그림 열쇠도 그때 사라져서 조금 짧게). 이 시간이 지나면 **다음 글 변경 때** 다시 묻고, 그때까지 받아 둔 카드는 그대로 보여요(그림 열쇠가 죽었으면 아이콘 타일로 그려요). 같은 페이지를 다르게 쓴 것(호스트 대소문자·`#조각`·끝 `/`)은 한 주소예요. |
| 늦은 답 | 링크 구성이 바뀌면 나가 있던 요청을 끊어요(서버 예산을 안 쓰려고). 끊은 요청의 답이 늦게 와도 기록하지 않고 옛 링크의 나머지도 묻지 않아요. 화면의 카드는 늘 「지금 글의 링크」와 「받아 둔 답」에서 뽑아서, 지운 링크의 카드가 다시 그려지지 않아요. |
| 실패 | 거절·사이트 오류·꺼진 스위치·보여 줄 것이 없는 페이지는 모두 **카드 없음**이에요. 문구도 없고 입력도 막지 않아요. 429는 `Retry-After` 동안 그 주소를 묻지 않고, 그 뒤에 **한 번** 다시 물어요(초를 말하지 않은 429는 기다림을 지어내지 않고 넘겨요). 오프라인이면 묻지 않고, 풀리면 이어서 물어요. |
| ✕ | 첫 카드 오른쪽 위에 **한 개**예요(타임라인의 제거 칩과 같은 자리·같은 모양). 「이번 메시지는 미리보기 없이 보내기」: 카드 한 장이 아니라 **이 메시지의 미리보기 전체**를 꺼요. 보낼 때 `suppressUnfurl: true`가 가요(켠 때만 키가 가요). 실패한 전송을 다시 보내도 같은 요청이에요(대기 행이 표시를 들고 있어요). |
| 되살리기 | ✕는 누른 때의 **링크 구성**에만 걸려요. 링크를 지우거나 바꾸거나 더하면(채널을 옮겨도) 다시 떠요. 문장만 고치면 그대로예요. 보내고 나면 글이 비어서 저절로 풀려요. 오프라인이 되었다 돌아와도 ✕는 그대로예요. |
| 키보드 | ✕는 폼 **밖**의 `<button type="button">`이라 Tab으로 닿고 Enter·Space로 눌리며, 보내기를 일으키지 않아요. Esc는 위에서부터 하나씩 닫아요: **멘션 목록 → 이 카드 → 인용**(카드는 저절로 나타난 것이라 Esc로 물리치는 일이 흔하고, 인용은 사람이 일부러 건 것이라 먼저 날아가면 안 돼요). 카드나 ✕에 초점이 있을 때의 Esc도 같아요. 닫으면 초점은 입력칸으로 돌아와요. 규칙은 코어 `composerKeyIntent`의 `preview-dismiss`예요. |
| 낭독 | 줄은 「보내기 전 링크 미리보기」 묶음, ✕는 「이번 메시지는 미리보기 없이 보내기」, 카드는 타임라인과 같은 「링크 미리보기: 제목, 도메인」이에요. ✕를 누르면 늘 붙어 있는 안 보이는 상태 노드가 「이번 메시지는 링크 미리보기 없이 보내요.」를 읽어요(사전 키 `timeline.unfurl.preview*`, ko·en). |
| 자리·높이 | 폼 **위**, 첨부 트레이와 같은 줄 모양(`attachment-tray`: 폰은 구분선이 있는 띠, 넓은 창은 입력 카드 가장자리에 맞춘 좌우 24)이에요. 높이는 트레이와 같은 상한(`max-h-tray-max`, 240) 안에서 스크롤해요. 작은 카드는 한두 장이 다 보이고, 크게 카드는 이 안에서 잘려 스크롤돼요. |
| 끄기·그림 | 이 기기가 **끄기**이면 아무것도 묻지 않아요(초안의 링크를 서버로 보내지 않고, 보이지 않는 카드를 끄는 ✕도 없어요). 그림·아이콘은 미리보기 프록시 경로(`…/unfurl-previews/{id}/image|icon`)로만 받고, 코어의 같은 경로 문으로 걸러요. |

**알려진 한계**(ADR-0170 증보의 「남는 위험」과 같은 뿌리): ① **예약 전송**은 ✕를 아직 싣지 못해요(서버가 예약 요청에서 이 필드를 받지 않아요, D21). ② 443이 아닌 포트의 링크는 입력칸에서 카드가 안 뜨는데 보낸 뒤에는 카드가 생길 수 있어요(D17). ③ 손으로 천천히 주소를 치다 350ms 넘게 멈추면 그 중간 상태도 한 번 물어요(예산 60에 여유를 둔 이유예요).
