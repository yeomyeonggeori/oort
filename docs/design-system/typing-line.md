# 「작성 중」 줄 — 웹·폰 규칙 한 장 (#5582)

사람이 지금 자판을 두드리고 있다는 휘발 신호(ADR-0149)를 대화 화면에 그리는 규칙이다. 웹(`clients/web`, 데스크탑은 같은 번들)과
폰(`clients/mobile`)이 **같은 것**과 **다르게 둔 것**을 한 표에 적고, 다르게 둔 칸마다 이유를 붙인다.

- 자리: 이 문서는 [디자인 시스템 정본](README.md)의 곁 문서다. 정본에는 「작성 중」 절이 없고, 같은 대화 화면의 에이전트 신호
  「작업 중」이 이미 곁 문서 [agent-work-display.md](agent-work-display.md)에 웹·폰을 한 번에 적고 있어서 같은 꼴로 둔다.
- 근거: #5567(owner 11-09, 웹 자리 이동) → PR #5574 design-review 2회차 R2-M1·R2-M2·R2-M3 → 이 문서(#5582).
- 코드 정본: 웹 `features/chat/TypingLine.tsx`·`typingLineParts.ts`·`tokens.css` `typing-line`·`typing-names`, 폰
  `features/conversation/TypingBar.tsx`·`screens/ConversationScreen.tsx`, 코어 `features/chat/typing.ts`.

## 1. 같은 것 (두 클라가 반드시 함께 지킨다)

| 규칙 | 내용 | 잠금 |
|---|---|---|
| 낱말 | 사람은 「작성 중」, 에이전트는 「작업 중」. 「입력 중」은 이 신호에 쓰지 않는다(#5574 검수 H-1) | 웹 `gate-typing` 1b, 코어 `typing.test.ts` |
| 누가 서나 | 사람만. 나·에이전트·명부에 없는 사람·만료된 신호는 그리지 않는다 | 웹 `Composer` `isEligible`, 폰 `isTypistEligible` |
| 이름의 무게 | 이름만 사람 잉크(`--ink` / `color.text`) 굵게, 나머지는 흐린 글자(meta 크기) | 웹 `TypingLine.test.tsx`, 폰 `typingStability.test.tsx` M-4 |
| 뭉치는 수 | 1명 = 그 이름, 2명 = 두 이름, 3명부터 = 첫 이름 + 외 N명. **고정 규칙**이다(아래 3절) | 웹 사전 one/two/many, 폰 `typingVisualSegments` |
| 잘리는 쪽 | 넘치면 이름 쪽이 잘리고 서술어(「작성 중」)는 안 잘린다. 한국어는 동사가 끝이라 줄 전체를 자르면 동사가 사라진다(W-3) | 웹 `gate-typing` [cut], `typingLineFit.browser.test.ts` |
| 이름별 줄임 | 이름마다 자기 칸에서 줄어든다. 첫 이름이 길어도 둘째 사람이 줄에서 사라지지 않는다. 두 이름이 넘치면 **남는 폭을 똑같이 나누되 이름마다 자기 글 폭에서 멈춘다** — 짧은 이름은 온전히 남고 긴 이름만 준다(둘 다 길면 반씩). 이름에 붙은 조사·쉼표는 그 이름과 함께 잘린다(고아 조사 없음, W-3) | 웹 `typingLineFit.browser.test.ts` R2-M1, 폰 `typingStability.test.tsx` R2-M1·「두 이름이 넘치면」(#5645) |
| 자리 예약 | 아무도 안 쳐도 칸이 늘 서 있다. 줄이 서고 져도 입력창·보내기·대화 목록이 움직이지 않는다. **글자를 키워도 같다**: 칸은 그 글자 크기의 한 줄만큼 미리 잡혀 있다(폰은 2절 「칸 높이」, #5645) | 웹 `gate-typing` [shift]·`gate-typing-jitter`, 폰 `typingStability.test.tsx`·`conversationGap.test.tsx` 「글자 크기 배율 × 줄 상태」 |
| 한 줄 고정 | 칸은 한 줄이다. 두 줄로 자라지 않는다 | 같음 |
| 낭독 | 보이는 조각은 보조기술에서 숨기고 온전한 문장 하나(말줄임표 없음)를 준다. live 영역이 아니다(3초마다 다시 오는 신호) | 웹 `composerMeta.test.ts`, 폰 `typingStability.test.tsx` |
| 움직임 줄이기 | 점 파도가 멈춘다 | 웹 `RespondingDots`, 폰 `RespondingDots` |
| 점 색 | 사람의 줄의 점은 그 줄의 글자와 같은 흐린 잉크다(웹 `--ink-muted`, 폰 `color.textMuted`). 에이전트 색(`--agent` / `color.agent`)은 에이전트를 뜻하는 자리에만 쓴다 — 정본 토큰 계약(`clients/web/src/design/tokens.css` 머리말 「agent identity is --agent on avatar/badge only」). 폰은 「작업 중」과 「작성 중」이 컴포저 위에 붙어 서는 곳이라 두 줄의 점이 같은 색이면 가르는 축이 하나 사라진다(#5582 검수 M3 → #5645에서 폰을 웹 쪽으로 맞춤) | 웹 `RespondingDots human`(`RespondingIndicator.tsx`), 폰 `typingStability.test.tsx` 「점 색」·`respondingDots.test.tsx` |

## 2. 다르게 둔 것과 이유

| 축 | 웹 | 폰 | 이유 |
|---|---|---|---|
| 자리 | 입력 카드 **아래** 왼쪽 | 컴포저 **위**, 「작업 중」 줄 아래 | 폼 팩터의 관례를 따른다. 넓은 창은 Slack·Discord 데스크탑처럼 입력창 아래(owner 11-09 #5567: 입력창 안 오른쪽 자리는 일반적이지 않다). 카드 위에는 이미 에이전트 「작업 중」 레일이 서서, 같은 자리에 쌓으면 두 낱말의 경계가 한 덩어리로 읽힌다. 폰은 컴포저 아래가 자판·홈 인디케이터라 줄을 둘 자리가 없고, 모바일 메신저(Slack·Discord 모바일)는 입력창 위에 둔다. 「작성 중」을 「작업 중」 아래에 두는 이유는 사라지는 줄이 아래여야 「중단」 단추가 손가락 밑에서 안 움직이기 때문이다(`TypingBar.tsx` 머리말) |
| 칸 높이 | 600 이상 34(글 한 줄 18 + 위아래 8), 600 아래 26(위아래 4) | 줄 상자 16 × min(글자 배율, 1.6)의 고정 높이. 그중 아래 4는 컴포저 위 여백에 걸치고 나머지가 흐름이다(배율 1에서 흐름 12 + 걸침 4) | 웹 넓은 창의 8은 카드 float 그림자 띠에서 글자를 떼는 값이다(M-1). 600 아래 카드는 그림자가 없어 한 단계 줄인다(R2-M2). 폰은 「마지막 행 → 알약 20」 안에 줄을 넣은 값이다(#4264). 폰 칸이 글자 배율을 따르는 것은 Dynamic Type 때문이다(#5645): 줄의 글이 배율만큼 자라는데 칸이 16에 머물면 줄이 설 때 대화가 밀린다. 상한 1.6은 바로 위 레일 칸(`railSlotHeight`)과 같은 식·같은 상한이라 두 줄이 함께 자라고 함께 멈추고, 줄의 글도 모두 같은 상한(`maxFontSizeMultiplier`)에서 멈춘다. 상한이 없으면 가장 큰 글자(배율 3.571)에서 57pt 빈 띠가 늘 선다. 걸침 4는 자라지 않는다 — 자라면 컴포저 위 여백 8을 넘어 알약에 닿는다 |
| 문구의 꼴 | 사전 문장 `timeline.typing.*`: 「●●● 한지후님, 오민재님이 작성 중…」 / en 「●●● A and B are typing…」 | 코어 `typingVisualSegments`: 「한지후, 오민재 ●●● 작성 중」 | 웹 줄은 사전(ko·en)으로 현지화되어 있고, 언어마다 이름과 서술어의 자리가 달라 점을 문장 밖 앞에 둔다(어순과 무관한 유일한 자리). 님은 코어 `typingSentence`의 「이름마다 님」(U4-4 N-1)과 같은 규칙이다. 폰은 owner 10-30 #4797 사양(이름 + 점 파도 + 「작성 중」, 「A, B」, 「A 외 N명」)을 그대로 쓴다. **폰 줄은 아직 현지화되지 않았다**(영어 폰에서도 「작성 중」) — 이것은 이유가 아니라 남은 일이다(5절) |
| 말줄임표 | 문장 끝 「…」(사전 문장의 일부) | 없음(점 파도가 진행을 말한다) | 위 「문구의 꼴」과 같은 갈래다 |
| 이름 나누기의 방법 | CSS grid(`typing-names`: `grid-auto-columns: minmax(0, max-content)`) | 조각마다 제 폭을 숨은 거울로 재고, 줄 폭에서 여백·점·꼬리·이름 아닌 칸을 뺀 몫을 `shareTypingNameWidths`로 나눠 이름 칸에 명시 폭을 준다. 재기 전(첫 프레임)·다 들어갈 때는 명시 폭 없이 제 폭으로 선다 | 규칙은 1절 「이름별 줄임」 하나다. 폰의 Yoga에는 grid가 없고, flex 줄임은 늘 글 폭에 비례해서 짧은 이름도 함께 준다(#5582 검수 M1: 390 폭 긴 309 + 짧은 31 → 짧은 이름 28). 그래서 폰은 재고 셈한다(#5645). 한 이름(「A」·「A 외 N명」)은 줄어드는 칸이 하나라 재지 않는다 |

## 3. 뭉치는 수 — 서버 grant의 `aggregateThreshold`를 화면이 읽지 않는다 (R2-M3 결정)

grant 응답(`POST …/typing/grant`)에는 `aggregateThreshold`가 실려 오고, 서버 값은 컴파일 상수 3이다
(`momo-ephemeral/src/signal.rs` `TYPING_AGGREGATE_THRESHOLD`). **두 클라 모두 화면에서 이 값을 읽지 않고 1·2·3부터의 고정
규칙을 쓴다.** 웹이 이 값을 담아 두던 저장소와 구독 훅(`rememberTypingThreshold`·`useTypingThreshold`)은 화면이 한 번도 읽지
않아 지웠다. 와이어 필드는 그대로다(API 변경 없음).

- **grant는 발행 자격이다.** 한 번도 친 적 없는 사람은 grant가 없다. 임계를 grant에서 읽으면 같은 채널을 보는 두 사람이 「내가
  이 세션에 쳐 봤나」에 따라 다른 꼴(두 이름 / 외 1명)을 볼 수 있다. 화면의 꼴이 대화의 성질이 아니라 보는 사람의 행동에 달린다.
- **그릴 문장이 없다.** 웹 사전은 one/two/many 세 꼴뿐이다. 서버가 4를 보내면 「세 이름」 문장이, 2를 보내면 owner #4797이 요구한
  「두 이름」을 버리는 문장이 필요하다. 바꿀 수 있는 손잡이처럼 보이지만 실제로는 돌리면 틀린 말을 하는 손잡이다.
- **서버도 고정값이다.** 워크스페이스·설정으로 바뀌지 않는 컴파일 상수이고, 서버 주석이 이유를 「한국어 컴포저 폭에 두 이름까지
  들어간다」로 적었다 — 화면 규칙이다. 바꿀 일이 생기면 서버 상수와 두 클라의 사전·조각을 한 PR에서 함께 바꾼다.

## 4. 폰 폭 웹의 칸 26 — 대화가 내주는 높이 (R2-M2)

| 폰 폭 390 | 칸 | 앞 판(#5567 전, 폼 아래 여백 12)보다 대화가 내주는 높이 |
|---|---|---|
| #5567 판 | 34 | 22 (자판 근사 390×508에서 283 → 261, −7.8%) |
| 이 판 | 26 | 14 (283 → 269, −4.9%) |

- 26인 이유: 600 아래 카드는 그림자 없는 테두리 그릇이라 그림자 띠를 피할 이유가 없다. 리듬 한 단계 아래(4)로 내리면 잉크가
  카드 밑변·화면(자판) 위에서 약 7 떨어진다. 숨 0(칸 18)이면 잉크가 다시 3~4px에 끼어 M-1로 돌아간다.
- **0을 내주는 길은 줄을 카드 아래에서 떼는 것뿐이다.** 앞 판이 아래에 쓰던 높이는 폼 아래 여백 12이고, meta 글 한 줄 상자는 18이다.
  남은 길은 둘이다: (가) 폰 폭에서만 줄을 대화 목록 바닥 위에 띄운다(흐름 0, Slack·Discord 모바일 꼴). 지금 목록 바닥에는 빈 꼬리가
  없어서 줄이 서는 동안 가장 새 메시지의 아랫부분을 덮는다. (나) 폰 앱처럼 카드 위에 둔다. 카드 위 여백(13)도 줄 상자(18)보다 작아
  같은 값을 치른다. 둘 다 owner 11-09 「카드 아래」 자리와 갈리므로 이 문서는 26에서 멈추고 결정을 owner에게 남긴다.
- 잠금: `clients/web/src/features/chat/typingLineFit.browser.test.ts`(R2-M2), `gate-typing-jitter`가 390×844도 돈다(R2-L4).
