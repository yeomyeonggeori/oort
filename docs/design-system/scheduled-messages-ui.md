## 0. 공통 규칙

### 0.1 화면에 나오는 말
- 기능 이름은 「예약해서 보내기」, 목록 이름은 「예약됨」, 한 건은 「예약한 메시지」다.
- **해요체**다. 줄표(U+2014, U+2013) 금지, 사과·느낌표·이모지 금지, 홍보 낱말 금지(웹 스킬 §7). 버튼은 동사로 시작한다(「예약하기」).
- 이 문서의 문장은 그대로 코어 `packages/momo-core/src/features/scheduled/copy.ts`에 들어간다. 웹·폰이 같은 상수를 쓴다(디자인 시스템 README §1: 문장·토큰·코어 로직만 공유).
- 기존 리마인더 문구는 합쇼체(「고릅니다」)라서 복사하지 않는다. 시각 계산 함수만 재사용한다(`presets.ts`의 `localHourOnOffsetDay`·`nextMondayLocalHour`).

### 0.2 시각 표기 (`formatScheduledAt`)
- 오늘·내일·모레는 말로: 「오늘 오후 3:00」, 「내일 오전 9:00」. 그 밖은 「10월 26일 (월) 오전 9:00」, 다른 해는 「2027년 1월 4일 (월) 오전 9:00」.
- 12시간제 「오전·오후」, 분은 두 자리(`9:00`). 숫자 칸은 `data-numeric`.
- **시간대는 시각을 고르는 자리(메뉴·직접 고르기)에서 이름과 UTC 오프셋을 함께 적는다**: 「Asia/Seoul (UTC+9) 기준이에요」. 목록 행에는 적지 않는다. 화면은 언제나 **지금 기기의 시간대**로 그린다(예약은 절대 시각이다).
- 프리셋은 둘이다. 「내일」(내일 오전 9:00)과 「다음 주 월요일」(오전 9:00). 일요일에는 두 값이 같은 시각이라 둘째를 숨긴다.

### 0.3 확인과 지속의 자리 (ADR-0182 D2·D3)
토스트는 금지다. 「나중에 다시 찾을 일이 있는가」를 물으면 있다(보내기 전까지 보고 바꾼다). 그래서 둘을 함께 쓴다.
- **예약 직후 확인 = ② 컴포저 상태줄**: `role="status"` 한 줄, 3초 뒤 소거. 이 줄에는 **누를 것을 두지 않는다**(사라지는 줄에 포커스할 것을 두면 키보드 사용자가 못 닿는다).
- **다시 찾는 길 = ③ 지속 카드**: 입력창 위 배너와 「예약됨」 줄. 시간으로 사라지지 않는다.
- **실패 = 맥락 안 인라인**(배너·행의 사유 줄). 시간으로 사라지지 않는다(README §4 오류).

### 0.4 보내기와 예약 단추의 비활성 사유 (한 번에 한 가지, 위가 먼저)
| 조건 | 예약 단추 | 설명 문장 |
|---|---|---|
| 오프라인 | 흐림(포커스 가능) | 연결이 없어서 지금은 예약할 수 없어요 |
| 이 서버가 예약을 껐다(앞선 요청이 503) | 흐림(포커스 가능) | 이 서버에서는 예약 보내기를 쓸 수 없어요 |
| 메시지 수정 중 | 서지 않음 | (없음) |
| 명령(/) 작성 중 | 흐림(포커스 가능) | 명령은 예약할 수 없어요 |
| 인용 답장 중 | 흐림(포커스 가능) | 인용 답장은 예약할 수 없어요. 인용을 지우면 예약할 수 있어요 |
| 보낼 내용 없음(글도 첨부도 없다) | 흐림(포커스 가능) | 보낼 내용을 쓰면 예약할 수 있어요 |
| 대기 50개 | 메뉴는 열리고 항목이 흐림 | 예약은 50개까지 걸 수 있어요. 지난 예약을 지우고 다시 해 보세요 |

흐린 단추는 `disabled`가 아니라 `aria-disabled="true"`로 포커스를 받고, 설명 문장을 `aria-describedby`로 읽어 준다. 이유를 모르는 채 잠긴 단추를 만들지 않는다.

모델 지정(`routing`)이 켜져 있으면 예약은 되지만 **모델 지정은 담기지 않는다**(ADR-0208 D1). 메뉴 안내 줄과 직접 고르기에 「모델 지정은 예약에 담기지 않아요」를 한 줄 보인다.

### 0.5 데이터
- 목록은 `GET …/scheduled-messages`(`status=open`)와 개인 채널 이벤트 `scheduled_message.updated`로 만든다. 이벤트는 id·상태·시각만 싣고 `rev`가 더 큰 것만 반영한다. 모르는 낱말·유실은 다음 `GET`이 복구한다(ADR-0208 D12).
- 서버가 201을 준 뒤에만 입력창·첨부 트레이·초안을 비운다. 실패하면 그대로 남는다. 재시도는 같은 `clientRequestId`를 쓴다(ADR-0208 D16).
- 직접 고르기의 처음 값은 **내일 오전 9:00**이다(프리셋과 같아 이미 미래다). 한 시간 뒤가 아니다: 예약은 대개 다음 날이다.

### 1.2 상태 1. 기본
```
+--------------------------------------------------------------------+
| 내일 회의 전에 자료 올려 둘게요                                        |
|                                                                    |
| [@] [:)]                                                 (^)(v)    |
+--------------------------------------------------------------------+
   (^) 메시지 보내기 (Enter)      (v) 예약해서 보내기

보낼 내용이 없을 때
| [@] [:)]                                                 (^)(v)    |   둘 다 흐림, (v)는 포커스를 받는다
                                                                         설명: 보낼 내용을 쓰면 예약할 수 있어요
```
- (^)는 지금 보낸다(변화 없음). (v)는 메뉴를 연다. Tab 순서는 (^) 다음 (v).
- 스레드 패널의 입력창도 같다(`rootId`를 실어 예약한다).

### 1.3 상태 2. 메뉴 열림
```
                                 +-----------------------------------------+
                                 |  내일 오전 9:00            10월 23일 (금) |  <- 첫 항목에 초점
                                 |  다음 주 월요일 오전 9:00   10월 26일 (월) |  <- 일요일에는 없다
                                 |-----------------------------------------|
                                 |  직접 고르기…                             |
                                 |-----------------------------------------|
                                 |  Asia/Seoul (UTC+9) 기준이에요             |  <- 안내 줄, 항목이 아니다
                                 +-----------------------------------------+
| [@] [:)]                                                 (^)(v*)   |
```
- 항목 오른쪽의 날짜는 보조(`text-meta text-ink-muted`)다. 낭독 이름은 요일까지 풀어 한 문장이다(「내일 오전 9:00, 10월 23일 금요일」).
- 한도(50개) 도달: 세 항목이 흐려지고 안내 줄 위에 한도 문장이 선다. 모델 지정이 켜져 있으면 안내 줄 위에 「모델 지정은 예약에 담기지 않아요」가 선다.
- 선택하면 메뉴가 닫히고 예약이 바로 걸린다(프리셋). 「직접 고르기…」는 상태 3으로 간다.

### 1.4 상태 3. 직접 고르기
```
                +----------------------------------------------+
                | 보낼 시각 고르기                               |
                | 고른 시각에 이 메시지를 보내요. 내 기기가 꺼져    |
                | 있어도 보내요.                                 |
                |                                              |
                | #일반                                         |
                | 내일 회의 전에 자료 올려 둘게요 ...              |
                |                                              |
                | 날짜               시간                        |
                | [ 2026-10-23 ]    [ 09:00 ]                  |
                |                                              |
                | 10월 23일 (금) 오전 9:00에 보내요               |
                | Asia/Seoul (UTC+9) 기준이에요                  |
                | 1분 뒤부터 예약할 수 있어요       (오류일 때만)  |
                |                                              |
                |                        [취소]   [예약하기]     |
                +----------------------------------------------+
```
- 처음 값은 내일 오전 9:00이다. 결과 문장은 값이 바뀔 때마다 갱신된다(`aria-live="polite"`). 오류 줄은 `role="alert"`이다.
- 확인 전 검증: 지금+1분 미만이면 「1분 뒤부터 예약할 수 있어요」, 120일 넘으면 「120일 안에서 골라 주세요」, 칸이 비면 「날짜와 시간을 확인해 주세요」. 서버가 같은 이유로 400을 주면 같은 문장을 보인다.
- 「예약하기」는 눌리면 버튼 안 스피너와 「예약하는 중」이고, 그동안 Esc·바깥 누름으로 닫히지 않는다. 오프라인이면 흐리고 이유를 한 줄 보인다.
- 같은 대화상자가 「시간 바꾸기」(제목 「보낼 시각 바꾸기」, 확인 「변경하기」)와 실패 행의 「다시 예약」(제목 「다시 예약하기」, 확인 「예약하기」)에도 쓰인다.

### 1.5 상태 4. 예약 직후
```
+--------------------------------------------------------------------+
| (clock) 이 채널에 예약된 메시지 1개 · 보기                            |  <- 배너(지속, 방금 생겼거나 숫자가 올랐다)
+--------------------------------------------------------------------+
| (입력창은 비워지고 초점이 돌아와 있다)                                  |
|                                                                    |
| [@] [:)]                                                 (^)(v)    |
| 내일 오전 9:00에 보낼게요                                             |  <- 상태줄 3초, role=status
+--------------------------------------------------------------------+
```
- 상태줄에는 누를 것이 없다. 「예약 보기」 길은 배너의 「보기」다(0.3).
- 첨부 트레이도 비워진다(첨부는 예약이 점유한다). 초안(`draftStore`)도 비워진다.

### 1.6 상태 5. 배너 (입력창 위)
```
(a) 대기   [clock] 이 채널에 예약된 메시지 2개 · 보기
(b) 스레드 [clock] 이 스레드에 예약된 메시지 1개 · 보기
(c) 실패   [!]     예약한 메시지 1개를 보내지 못했어요 · 보기          (위험 어조)
```
- 채널 화면은 그 채널의 것을 센다. 스레드 패널은 그 스레드(`rootId`)의 것만 센다.
- 실패가 하나라도 있으면 (c) 한 줄만 선다((a) 대신).
- 「보기」는 목록을 그 채널로 거른 채 연다(`/scheduled?channel=<id>`). 개수가 바뀌면 `aria-live="polite"`로 한 번 읽는다. 0개면 배너가 사라진다.

- 구획 순서: **보내지 못함이 위**(사람이 할 일이 먼저), 그 아래 보낼 예정(마감 임박순). 구획이 비면 제목도 없다.
- 행: 채널 이름(또는 DM 상대 이름과 아바타), 미리보기 두 줄(`line-clamp-2`), 첨부 개수 칩, 보낼 시각 한 줄. 행 동작은 호버 툴바가 아니라 `⋯`와 컨텍스트 메뉴다.
- 마감 30초 안의 행: 시각 줄이 「곧 보내요」가 되고 「시간 바꾸기」·「편집」이 흐리다(설명: 「곧 보내서 바꿀 수 없어요」). 「지금 보내기」·「삭제」는 된다(ADR-0208 D9).
- 「지금 보내기」는 한 번 누르면 간다(확인 없음). 행에는 버튼 안 스피너와 「보내는 중」, 성공하면 행이 사라지고 목록 머리에 상태줄 한 줄 「메시지를 보냈어요」가 3초 선다. 거절이면 행이 보내지 못함 구획으로 옮겨 가고 사유가 선다.
- 「삭제」는 `AlertDialog`: 제목 「예약을 지울까요?」, 본문 「지우면 이 메시지는 보내지 않아요. 되돌릴 수 없어요.」, 「취소」·「지우기」(위험 채움). 지운 뒤 초점은 다음 행으로 간다.
- 「편집」은 대화상자(제목 「예약한 메시지 편집」, 글 칸 + 시각, 확인 「저장하기」). 첨부는 바꿀 수 없다고 한 줄 말한다(「첨부는 바꿀 수 없어요. 바꾸려면 지우고 다시 예약해 주세요」).
- 이 화면의 네 상태: **빈**(「예약한 메시지가 없어요」 + 「메시지를 쓰고 보내기 옆 화살표에서 시각을 고르면 예약돼요」 + 「대화로 돌아가기」), **로딩**(세 행 높이의 중성 스켈레톤), **오류**(「예약 목록을 불러오지 못했어요」 + 「다시 불러오기」), **오프라인**(상태 8).
- 채널로 거르면 머리에 「#일반 예약만 보고 있어요 · 모두 보기」가 선다.

### 1.8 상태 7. 실패
```
채널 화면 (입력창 위)
+--------------------------------------------------------------------+
| [!] 예약한 메시지 1개를 보내지 못했어요 · 보기                         |
+--------------------------------------------------------------------+

목록 행 (사유별 문장은 3절)
| #배포                                                        (...) |
| 금요일 배포 공지                                                     |
| 예약한 시각이 많이 지나서 보내지 않았어요                              |

```
- 사유 줄은 위험 어조 텍스트(`text-danger`), 다음 행동 줄은 보조 텍스트다. 시간으로 사라지지 않는다.
- 행의 바로 보이는 단추는 되살릴 수 있는 사유(`missed`, `send_error`)에서만 「지금 보내기」·「다시 예약」이고, 나머지 사유는 「내용 복사」만 보인다. 전체 동작은 `⋯`에 있다(서버가 마지막에 다시 판정한다).
- 푸시는 없다(ADR-0208 D8). 그래서 배너·점·목록이 전부다.

### 1.10 키보드와 접근성
- (v): Enter·Space·ArrowDown으로 열기, ArrowUp/Down 이동, Home/End, Enter 선택, Esc 닫기(초점은 (v)로 복귀), Tab은 닫는다. 메뉴가 열리면 초점은 첫 항목이다. 선택하면 입력창으로 초점이 돌아온다.
- 직접 고르기: 초점은 날짜 칸, 마지막 칸에서 Enter로 제출, Esc로 닫으면 연 단추로 돌아간다(`PauseUntilDialog`의 `opener` 선례).
- 이름: (v) `aria-label="예약해서 보내기"` + `aria-haspopup="menu"` + `aria-expanded`. 목록 행 `aria-label`은 「{채널}, {미리보기}, {보낼 시각}에 보내요」, `⋯`는 「{채널} 예약 동작」, 실패 행은 사유를 `aria-describedby`로 읽는다.
- 단축키는 v1에서 두지 않는다(후속 후보: ⌘K 「예약해서 보내기」 명령).
- 전환은 기존 오버레이 모션 규칙을 따르고 「동작 줄이기」에서는 페이드만이다. 색은 토큰만 쓴다(원 hex 0). 터치(`hover: none`)에서는 44까지 자란다.

## 2. 폰

### 2.1 컴포저와 메뉴
- 보내기 원(`Composer.tsx` `.a-send` 잉크 ↑ 원, `testID="composer-send"`, `hitSlop`)을 **길게 누르면** 예약 메뉴가 열린다. 탭은 그대로 보내기다. 길게 누르기는 `useLongPress`(코어 `longPressModel`: `LONG_PRESS_MS = 250`, 이동 10px 허용, `longPressModel.ts:51,54`)를 쓴다.
- 보낼 내용이 없어 원이 흐릴 때는 길게 눌러도 열리지 않는다.
- **메뉴 문법은 첨부 메뉴 #4180과 같다**(코드는 `origin/track/uxui`의 `clients/mobile/src/features/attachments/AttachMenu.tsx`이고 이 문서의 기준 브랜치에는 아직 없다): 측정한 기점에서 자라나는 둥근 카드(크기·이동·불투명도를 한 진행값으로), 열림 스프링 `MENU_OPEN_SPRING`·닫힘 `MENU_CLOSE_SPRING`(`design/motion.ts:62-65`), 「동작 줄이기」면 페이드만(`MENU_FADE_MS` 180), 열린 뒤 200ms 행 누름 무시(`touchGuardMs`), Modal이 사라진 뒤에만 다음 화면(`onDismissed`), 바깥 탭·원 재탭·VoiceOver 탈출 제스처로 닫힘, 초점은 첫 행으로 갔다가 닫히면 원으로 돌아감, 열릴 때 가벼운 햅틱.
- 기점이 화면 오른쪽이므로 `attachMenuFrame`의 「카드 왼쪽 = 원 중심 − `anchorFromLeft`」를 **좌우 대칭 인자**로 일반화한다(오른쪽 기준 + 오른쪽 가장자리 `edge` 10).
- 치수(제안): 폭 264, 행 높이 64(두 줄 행), 모서리 34 연속 곡선, 재질은 첨부 메뉴와 같은 잉크 86% + 흐림(투명도 줄이기면 불투명). 첨부 메뉴의 폭 216은 「다음 주 월요일」과 보조 줄을 담기에 좁아 새 값을 **이름을 지어** 둔다(README §6). 높이는 3행 × 64 + 위아래 12 + 시간대 줄 28.

+--------------------------------------+     +--------------------------------------+

|                                      |     |            +------------------------+|
|                                      |     |            | 내일                    ||
|                                      |     |            | 오전 9:00 · 10월 23일 (금)||
|                                      |     |            |------------------------||
|                                      |     |            | 다음 주 월요일            ||
|                                      |     |            | 오전 9:00 · 10월 26일     ||

   (^) 탭: 보내기 / 길게 누르기: 예약          |            | 날짜와 시간을 골라요       ||

- 행은 코어의 같은 프리셋 객체를 그린다: 웹은 `제목 + 시각`을 한 줄로, 폰은 `제목`과 `시각 · 날짜`를 두 줄로. 일요일에는 둘째 행이 없다. 시간대 줄은 카드 맨 아래 작은 글씨다.
- 낭독: 보내기 원은 `accessibilityLabel` 「보내기」 + `accessibilityHint` 「길게 눌러 예약」(「보내기, 버튼, 길게 눌러 예약」). 길게 누르기를 못 하는 사람을 위해 `accessibilityActions`에 「예약해서 보내기」를 둔다(활성화하면 같은 메뉴가 열린다). 메뉴 행의 이름은 요일까지 푼 문장이다.
- 비활성 사유는 0.4 표와 같다. 폰은 길게 눌러도 열리지 않고 `accessibilityHint`가 이유를 읽는다. 오프라인이면 도크의 기존 오프라인 줄이 말한다.

### 2.5 상태 5. 배너
- 입력 도크 바로 위 한 줄(도크 형제 줄의 같은 계열, #4203이 정렬을 다룬다): 「이 채널에 예약된 메시지 2개 · 보기」. 스레드 화면은 「이 스레드에 예약된 메시지 1개 · 보기」, 실패는 위험 어조 「예약한 메시지 1개를 보내지 못했어요 · 보기」(실패가 있으면 이 한 줄만).
- 누르면 「예약됨」 시트가 그 채널로 걸러 열린다.

### 2.7 상태 7과 8. 실패, 오프라인
- 실패: 행 아래 사유 줄과 다음 행동 줄(3절), 시트 맨 위 「보내지 못함」 구획, 프로필 줄·아바타의 점(안 읽음 점과 같은 신호 토큰), 대화 배너의 위험 어조. **푸시는 없다**(ADR-0208 D8): 앱을 열어야 보인다.
- 오프라인: 보내기 원을 길게 눌러도 메뉴가 열리지 않고, 시트는 캐시된 목록 위에 「연결이 없어요. 연결되면 예약을 바꿀 수 있어요」 한 줄을 세우고 행 동작을 흐리게 한다.
- 「동작 줄이기」에서는 메뉴·시트가 페이드만이다.

## 4. 구현 분담과 코어 모듈
- **코어가 먼저다.** `packages/momo-core/src/features/scheduled/`는 #4215가 첫 PR로 랜딩하고 #4216이 소비한다. 서버 PR 전에는 계약대로 mock으로 진행한다.
  - `types.ts` 계약 타입, `api.ts` 다섯 호출(기존 http 도우미), `presets.ts` 프리셋과 `validateSendAt`·`formatScheduledAt`·시간대 표기, `events.ts` `asScheduledMessageFrame`(알 수 없는 모양은 `null`, `rev`가 오래된 것은 버린다), `model.ts` 구획·채널별 개수·마감 30초 판정(`editableUntilMs`)·비활성 사유 우선순위, `copy.ts` 3절의 문장 전부.
  - 시험: 프리셋 경계(일요일·자정·월말·DST가 있는 시간대를 `TZ`로), 이벤트 `rev` 순서, 비활성 사유 우선순위, 문구에 줄표가 없다는 점(코어 preflight `design_preflight_core.mjs`가 이미 잰다).
- 웹은 `clients/web/src/features/scheduled/`, 폰은 `clients/mobile/src/features/scheduled/`가 뷰를 갖는다. 컴포넌트는 공유하지 않는다.
