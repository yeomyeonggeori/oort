| 예외 줄 (D) | **거의 그대로예요.** 예외 줄은 전달·생존(받지 않음·신호 소실·실패)을, 묶음 카드는 사람이 결정한 제안의 결과를 말해요. 다만 **승인으로 끝난 run(거부 `approval_rejected`·만료 `approval_expired`)에는 예외 줄을 세우지 않아요**: 칩이 말하고 묶음 카드가 설명해요(채널에는 칩 하나만 남긴다는 결정 1, 그리고 같은 행의 칩과 줄은 한 낱말만 말한다는 #4619 §5·§6). 지금 이 run의 줄은 「시간 초과 · 승인이 만료됐어요」(`runException`이 `runPhaseLabel`의 「시간 초과」에 `END_REASON_TEXT`를 붙여요)라서 칩의 「만료」와 어긋나요 **[Proposed]**. |

네 자리가 같은 run·같은 approval을 말하므로 **같은 낱말·같은 판정**을 코어 한 곳에서 읽어요(#4619 §6의 확장). 교차 시험이 같은 시각에 맞대요(§8).

**이 문서가 #4619에서 완화하는 두 가지 [Proposed].** ① #4619 §4는 평소의 진행에 문장 행을 세우지 않는다고 했어요. 이 문서는 **요청 스레드 안에 한해** 요청마다 생각 줄 한 줄을 세워요(채널 본류에는 여전히 문장 행이 없어요). 사고 중임을 보여 달라는 요청이 향한 곳이 스레드이기 때문이에요. ② #4619는 대화창에 경과 시간을 말하지 않는다고 했어요. 생각 줄의 「N분째 소식 없음」은 서버가 본 사실(마지막 보고 시각)이고 1분에 한 번만 바뀌며, 초 단위 숫자는 여전히 없어요. 둘 다 DM에서도 같아요.

## 2. 묶음 카드 문법

묶음은 한 요청의 제안·결정·결과예요. 닻은 에이전트 명의의 승인 카드(`approval_request` 메시지) 한 장이고, 새 컴포넌트가 아니라 웹 `AgentCard`와 폰 `MessageRow`의 승인 카드 **문법을 바꾸는 것**이에요.

코어 진입점은 `agentCardModel.agentRequestBundle`·`requestBundle`·`triggerChip`이에요(#4760). owner 10-29 결정에 따라 `workspace_action`과 `tool_call` 모두 같은 카드의 props·상태 코드로 여덟 상태를 읽고, `shouldFoldBundleLine`은 같은 목록의 종결 카드가 설명하는 옛 `bundle_of` 줄만 접어요(아래 1단계의 도구 승인 제외·옛 줄 유지 문구보다 이 결정이 우선해요).

### 2.1 한 장의 짜임

```
[달] 달무리봇이 자기 소개를 바꾸려고 해요               [? 승인 필요]    ← 머리 문장 · 상태(아이콘 + 낱말)
       달무리 실험실 봇  →  알림 시험                                    ← 값 칩 (이전 → 이후)
     [승인] [거부]                          23시간 남음 · 자세히 ▾       ← 버튼(결정할 사람에게만) · 조용한 줄
     ─ 자세히 ─ 요청 · 대상 · 사유 · 영향 · 결정 권한 · (관리자) 원장 번호 · 원본 데이터
```

1. **머리 문장.** 얼굴 + 제안자 이름 + 하려는 일 한 구절이에요. 이름은 메시지 작성자에서 읽어요(문장에 굽지 않아요. 이름이 바뀌면 낡아요, ADR-0186 증보 v5 U-c와 `proposal_summary`의 문서). 하려는 일은 **서버가 행동마다 만든 한 구절**(`intent`)이에요 **[Proposed]**: 값에 따라 달라지는 문장(어느 항목이 바뀌나)은 행동 실행기가 이미 행을 만드는 Rust에서 만들어야 푸시·접근성·폴백이 한 말을 해요(D1: 워크스페이스 행동의 정본은 Rust). 두 줄을 넘으면 줄여요.
2. **값 칩.** 결정에 필요한 것만 「이전 → 이후」로 보여요. 최대 둘이고 넘치면 「외 N건」이에요. 이전 값은 취소선 + `--ink-muted`, 이후 값은 `--ink`예요. **취소선만으로 말하지 않아요**: 칩의 접근성 이름은 「소개: 이전 값에서 이후 값으로」예요. 이전 값이 없으면(만들기) 이후만 보여요. 지금 행(rows)은 값 문자열 안에 「→」를 넣고 있어서, 구조(`before`·`after`)를 더하는 것은 가산 변경이에요 **[Proposed]**. 구조가 없는 옛 카드는 한 줄 값으로 그려요.
3. **버튼.** 「승인」(채움, `--primary`)과 「거부」(윤곽) 한 쌍이에요. 웹 작은 버튼 · 폰 전폭 상자 · 폰 알약, 지금의 세 모양을 이 한 쌍으로 모아요(웹 높이 32, 폰 44). 확인 단계 없이 한 번에 결정해요(taste 규칙). **결정할 사람에게만** 서고, 그 밖의 사람에게는 자리에 「이도현 님의 승인을 기다려요」가 서요(결정할 수 있는 사람이 여럿이면 「관리자의 승인을 기다려요」). 요청한 에이전트 본인에게는 버튼이 없어요. 서버가 카드에 `decision_mode: "open"`을 실은 승인은 푸시·인박스 행·채널 칩에서 결정하지 않고 이 카드에서만 결정해요(§5.4).
4. **조용한 줄.** 「23시간 남음 · 자세히」예요. 남은 시간은 크기에 맞는 단위로 말해요: 한 시간이 안 되면 분(「15분 남음」), 하루가 안 되면 시간, 그 위는 일이고 초 단위는 없어요. 단위 안에서는 내려서(61분은 「1시간 남음」) 실제보다 길게 말하지 않아요. 15분짜리 허락이 「1시간 남음」이라고 말하던 올림을 걷은 규칙이에요(#4986). 10분 안이면 「10분 안에 만료돼요」(웹에 있는 규칙을 폰에도 같게)로 바뀌어요. 지나면 상태가 「만료」로 바뀌어요. 끝의 「자세히」는 누르는 곳(타임라인 카드의 펼침)을 가리키는 말이라서, 누를 수 없는 표면(결정 무대)은 남은 시간만 말해요.
5. **자세히.** 같은 카드 안에서 펼쳐요(새 화면이 아니에요). 지금 일곱 줄로 늘어선 라벨 행(요청·대상·사유·결정 권한·영향·예상 비용 …)이 여기로 들어가요. **원장 번호와 원본 데이터는 워크스페이스 관리자에게만** 보여요.

### 2.2 상태표

한 묶음은 아래 여덟 상태 중 정확히 하나예요. 모양은 아이콘 + 낱말이고(색에만 기대지 않아요), 아이콘은 lucide예요(README §2.8).

| 상태 | 아이콘 | 낱말 | 토큰 | 문장(예) | 다음 행동 |
|---|---|---|---|---|---|
| **생각 중** | `CircleDot` | 생각 중 | 중립 바탕 · `--warn` 글리프(레일의 「작업 중」과 같은 그릇) | 프로필 읽는 중 ··· (지금 단계) | 없어요. 오래 소식이 없으면 생각 줄이 「N분째 소식 없음」으로 말해요(예외 줄은 가져가기 전 상태만 말해요) |
| **승인 필요** | `ShieldQuestion` | 승인 필요 | `--warn` | 달무리봇이 자기 소개를 바꾸려고 해요 | 결정할 사람: 승인·거부. 그 밖: 「이도현 님의 승인을 기다려요」 |
| **실행 중** | `CircleDot` | 실행 중 | 중립 바탕 · `--warn` 글리프 | 승인됐어요 · 이어서 하는 중 | 없어요 |
| **끝** | `Check` | 끝 | `--ok` | 소개를 바꿨어요 · 이도현 승인 오후 7:35 | 결과가 가리키는 곳으로 가기(있으면), 자세히 |
| **거부** | 새 글리프 **[Proposed]** | 거부 | 중립(`--ink-muted`) | 이도현 님이 거부했어요 | 요청한 사람: 「다시 요청」 |
| **만료** | `Clock` | 만료 | `--warn` | 승인을 기다리다 만료됐어요 | 요청한 사람: 「다시 요청」 |
| **실패** | `CircleX` | 실패 | `--danger` | 소개를 바꾸지 못했어요 · 다시 요청해 보세요 | 「다시 요청」 |
| **취소** | 새 글리프 **[Proposed]** | 취소 | 중립(`--ink-muted`) | 요청이 취소됐어요 | 없어요 |

- **`--danger`는 서버가 일을 끝내지 못한 것(실패)에만 써요.** 사람이 한 일(거부·취소)과 아무도 하지 않은 일(만료)은 오류가 아니에요(#4619 §3, ADR-0132의 「사실이 결정한다」 원칙). 지금 인박스 행이 거부를 `danger`로 칠하는 것(`inbox/model.ts` 승인 결과 표)은 이쪽으로 맞춰요.
- 새 글리프 둘(거부·취소)은 구현 이슈가 고르되, **실패(`CircleX`)·만료(`Clock`)와 모양이 갈려야 해요**. 색만 다른 같은 모양은 안 돼요(#4619 §3). 이름은 repo가 아직 쓰지 않는 lucide 이름일 수 있어서 `iconSystem` 예외 목록부터 확인해요.
- **「실행 중」은 도구 승인에만 있어요.** 행동 승인은 결정과 같은 트랜잭션에서 실행돼서(ADR-0186 D2) 카드가 곧장 「끝」이 돼요. 그 트랜잭션이 실패하면 결정 자체가 일어나지 않고 카드는 「승인 필요」로 남아요. 그때 버튼 자리에 서는 오류 문장은 상태가 아니라 **결정 오류**예요.
- **「승인됨」은 상태가 아니에요.** 승인은 과정 행의 동사(승인 · 이도현 · 오후 7:35)로만 써요(§7).
- 상태의 원천: 승인 카드의 `status`(대기·승인·거부·만료·취소)와 run 진행이에요. 「생각 중」「실행 중」은 클라이언트가 run에서 읽고, 나머지는 서버가 카드에 쓴 마지막 상태예요(§2.4).

### 2.3 머리 칩과의 대응

상태 칩은 `triggerChip`(머리 칩)을 넓힌 것이에요. 받음·가져감·아직 받지 않았어요·시간 초과는 **전달·생존의 낱말**이라 #4619 그대로고, 묶음 상태는 일이 시작된 뒤의 이야기예요.

| 묶음 상태 | 칩 kind | 칩 낱말 | 바뀌는 것 |
|---|---|---|---|
| 생각 중 · 실행 중 | `working` | 작업 중 | 없어요. 칩·레일의 「작업 중」이 **상위 낱말**이고 카드·생각 줄이 「생각 중」「실행 중」으로 **더 잘게 갈라요**. 상위·하위 낱말만 허용하고 대응표는 코어 한 곳에 둬요 **[Proposed]** |
| 승인 필요 | `approval` | 승인 필요 | 낱말 「승인 대기」가 「승인 필요」로 바뀌어요(§7) |
| 끝 | `answered` | 끝 / 답함 | 제안 묶음이면 「끝」, 말로 답한 요청이면 「답함」. 눌렀을 때 가는 곳은 묶음이면 스레드의 카드, 답이면 답 메시지예요 **[Proposed]** |
| 거부 | `declined`(새) | 거부 | 새 kind. 중립 톤. 낱말은 `runPhaseLabel`이 종료 코드 `approval_rejected`에서 정해요 |
| 만료 | `expired`(새) | 만료 | 새 kind. `--warn` + 시계. 낱말은 `runPhaseLabel`이 종료 코드 `approval_expired`에서 「만료」로 정해요(「시간 초과」가 아니에요). 시계 모양이 시간 초과와 같아서 낱말이 늘 같이 서요 |
| 실패 | `failed` | 실패 | 없어요 |
| 취소 | (칩에 세지 않음) | — | 사람이 직접 한 일이라 칩에 안 세요(#4619). 카드와 인박스 행에는 서요 |

칩의 폭은 가장 넓은 낱말(「아직 받지 않았어요」)에 고정이라서 새 낱말이 들어와도 머리 줄 높이가 변하지 않아요. **거부와 만료는 run의 종료 코드로 갈라요**: 거부는 run이 `cancelled`로 끝나지만 코드가 `approval_rejected`라서 「취소」로 세지 않고, 만료는 `timed_out`이지만 코드가 `approval_expired`라서 「시간 초과」가 아니라 「만료」예요. 사람이 run을 직접 멈춘 `cancelled`만 「취소」예요(요청한 사람에게 새 소식인 거부가 #4619의 「취소는 칩에 세지 않는다」에 먹히지 않게 해요). 새 kind의 급한 순서(`PRIORITY`)는 실패 > 만료 > 거부 > 시간 초과 > 아직 받지 않았어요 > 승인 필요 > 작업 중 > 가져감 > 받음 > 끝·답함이에요 **[Proposed]**. 승인 필요 kind가 입는 「일시 정지」 얼굴(`triggerChip.ts`)은 그대로예요. 칩이 승인의 마지막 상태를 알려면 스레드 안 카드를 읽을 수 없는 채널 표면에 **run 진행 읽기에 묶음 한 덩어리**(`bundle`: 승인 id·상태·`decision_mode`·내가 결정할 사람인지·한 줄 문장)가 필요해요 **[Proposed, 가산]**.

### 2.4 서버가 쓰는 것과 옛 클라이언트가 읽는 것

한 장이 끝까지 말하게 하는 길은 **서버 쓰기** 하나예요. 서버가 카드를 종결 패치하고 옛 별도 줄을 더 쓰지 않아서 클라이언트가 줄을 접을 일이 없어요(owner 「다음 단계로 미루지말고 바로바로 ㄱㄱ」). 근거와 계약은 ADR-0186 증보 v6 R-b에 있어요 **[Accepted]**.

| | 서버 쓰기(정본) | 옛 클라이언트 · 옛 기록 |
|---|---|---|
| 끝 상태 | 결정·만료·취소 때 **같은 카드**의 props와 `body`를 패치하고(`result`: 상태 코드·결과 행·참조·다음 행동·한 줄) `message.edited` 프레임으로 알려요. 지금은 결정만 패치하고 만료·취소는 안 해서 칩이 「승인 대기」로 남아요(#3982) | 옛 클라이언트는 카드가 아는 상태(승인됨·거부됨·만료됨)를 그대로 그리고, 끝 상태를 카드 `body`의 한국어 한 문장으로도 읽어요(본문 폴백, 이행 기간만) |
| 옛 줄 | **쓰지 않아요.** 행동 승인의 실행됨 카드·거부 줄·만료 줄을 서버가 더 쓰지 않아요. 도구 승인도 같아요. 요청한 사람에게 가던 만료 푸시는 종결 이벤트가 이어받아요(ADR-0204 증보 6 D6-5) | 이미 쓰인 옛 줄은 기록이라 그대로 그려요(고치거나 지우지 않아요). 새 줄이 더 생기지 않으니 접기 규칙은 없어요 |
| 영어 원문 | 사람 화면용 필드에 0건이에요. 상태 코드(`props.status`·`props.code`)가 정본이에요 | 클라이언트가 코드를 한국어로 읽어요(§7) |

**범위:** 1단계는 **행동 승인(`workspace_action`)과 도구 승인(`tool_call`) 둘 다**예요(owner 「도구 승인도 바꿔」). 도구 승인의 차이는 하나예요: 승인 뒤 실행이 워커에서 이어져서 카드가 「실행 중」을 거쳐 「끝」이 되고(run이 말해요), 거부·만료·취소는 행동 승인처럼 곧장 닫혀요. 승인 뒤 도구가 도는 길의 도구 결과 줄은 모델의 결과라서 그대로 생겨요.

### 3.2 저장 규칙 [Accepted: 결정 2]

- **남는 것: 진행 메모(`stage`) 40자까지.** 서버 상한은 지금 80자이고 지시문 규약이 40자예요(ADR-0200 D5). 서버 검증을 40자로 줄일지는 #4655의 `activities[].label ≤40`과 한 번에 정해요(호환을 깨지 않으려고 이 문서는 80을 그대로 두고 **화면이 40자를 넘는 메모를 한 줄에서 줄여요**) **[Proposed]**.
- **안 남는 것: 흐르는 생각 글(`textDelta`).** 서버는 릴레이만 하고(ADR-0200), 화면도 메모리에만 둬요. 새로고침·재접속·나중에 연 사람에게는 없고, 끝나는 순간 펼친 칸의 흐르는 글은 사라져요. 한계 문장은 작업 패널의 `RUN_STREAM_SENTENCE`(흐르는 글과 도구 호출은 저장하지 않아요)와 같은 뜻이에요. 그 문장은 「이 패널을 연 뒤」라고 말해서 스레드에는 그대로 못 쓰니, 「이 칸을 연 뒤」로 말하는 문장 하나를 같은 파일(`runLedger`)에 더해요 **[Proposed]**.
- **요약 생각은 저장하지 않아요.** 결정 2의 (나)가 (다)가 아니므로 ADR-0200 증보가 필요 없어요. 생각 저장은 새 결정이 아니라 #4655 Q2의 반복이고, ADR-0200은 한 줄로 가리키기만 해요.
- **펼친 과정 행의 원천은 이미 저장된 원장**이에요: `stage`·`agent_port.call`(ADR-0200 증보 4)·승인 요청과 결정·끝, 그리고 #4656이 오면 활동 보고예요. 새 저장소가 없어요.
- **끝난 뒤 요약 한 줄**의 숫자(걸린 시간 · 도구 수 · 승인 수)는 원장에서 센 값이에요. 시간은 분 단위(1분 미만은 「1분 미만」)이고 끝난 뒤에는 변하지 않아요.

|---|---|---|
| 채널 최상위 | **요청 메시지의 스레드**(root = 요청 메시지) | 요청 메시지 + 머리 칩 + 스레드 요약 줄(답글 N · 문장 · 결정 버튼) |
| 에이전트와의 1:1 DM | **제자리**(DM이 곧 작업실) | 없어요(DM이 곧 스레드) |
| 스레드 안 | **같은 스레드** | 스레드 요약 줄(지금 그대로) |
| 먼저 제안(사람이 안 불렀어요) | 소유자와의 1:1 DM(ADR-0186 증보 v5 U-c, C1 그대로) | DM 본류 |
| 트리거 메시지가 없는 사람 요청(작업 탭에서 제목만으로 만든 run) | 지금처럼 본류 | 없어요(§9, #4619 §9의 5번과 같은 빈틈) |

### 4.2 서버가 한 곳에서 정해요

카드 · 도구 줄 · 결과 · 최종 답이 **같은 root**를 읽어요. 지금은 최종 답만 `trigger_root_id`를 따르고(#4622), 행동 제안 카드와 결과·거부·만료 줄은 본류(`root_id` 없음)라(인플레이스 채널 승인 카드와 호출 불가 안내 줄만 서버가 「말한 자리」를 따라요) 스레드 안에서 부른 일이 답은 스레드·카드는 본류로 갈라져요(ADR-0200 증보 5 표의 「어긋남」). 이 규칙을 채널 최상위 트리거까지 넓히면(#4646 흡수) 한 곳이 모든 쓰기의 자리를 정해요. 에이전트는 자리를 못 골라요. 스레드 root 자신을 가리키는 인용 블록은 중복이라 그리지 않아요 **[Proposed]**.

### 4.3 채널의 상태 칩과 결정 버튼

- **머리 칩**이 상태 낱말을 말해요(§2.3). **스레드 요약 줄**은 「답글 N · 문장」이고, 일하는 중이면 지금처럼 작업 중 칩을 달아요.
- **결정 버튼이 요약 줄에 서는 조건 셋:** ① 이 요청의 대기 제안이 **하나**, ② 내가 **결정할 수 있는 사람**, ③ 서버가 준 `decision_mode`가 `inline`. 하나라도 아니면 칩은 말만 하고, 눌러서 스레드를 열어요. 제안이 여럿이면 「승인 필요 2」 + 열기예요.
- **버튼은 무엇을 결정하는지 같은 줄에 보일 때만 서요**: 줄에는 푸시와 같은 질문 문장(「소개를 바꿔도 될까요?」)이 한 줄로 서요. 폭이 모자라 문장이 안 들어가면 버튼을 접고 「승인 필요」 + 열기만 둬요(근거 없이 누르게 하지 않아요).
- 폰: 칩/요약 줄을 누르면 스레드 화면이 열리고 카드로 도착 강조(#3921)가 돼요. 버튼 표적은 44예요.

### 4.4 「채널에도 한 줄」과 판단 칸 [Accepted: 결정 4]

**기본 규칙 [Accepted].** 요청이 채널(최상위)에서 왔고 결과가 **채널에 보이는 변화**(채널 만들기·고정 등)면 채널 본류에 에이전트 명의로 **한 줄**이 더 서요. 아니면 스레드에만 있어요. 모양은 「✓ 비공개 채널 「qa」를 만들었어요 · 이도현 승인 · 스레드 보기」이고, 요청 메시지를 인용(`reply_to_id`)해서 맥락이 서요. 이 줄 때문에 푸시가 한 번 더 가지 않아요(요청한 사람은 이미 결과를 받아요).

**행동별 기본값 [Proposed].** 「채널에 보이는 변화」의 첫 판은 아래예요. 행동 레지스트리의 속성 한 줄로 두고 구현 이슈가 바꿔요.

| 채널에도 한 줄(기본) | 스레드에만(기본) |
|---|---|
| `channel.create` · `channel.member.add` · `message.pin` · `message.unpin` · `agent.rename` | `invite.create`·`agent.invite`(1회 값) · `member.avatar.set` · `agent.profile.update` · `hosted.channels.grant` · `workspace.*` 설정 · `plugin.install` |

이유: 채널 사람들이 대화 속에서 마주치는 변화(고정이 보이고, 새 채널이 생기고, 이름이 바뀌어요)와 요청한 사람·관리자만 알면 되는 변화를 갈라요. DM과 스레드 안 요청은 해당 없음이에요(그 자리가 이미 맥락이에요).

**판단 칸.** 모델이 정하는 것은 하나뿐이에요.

```
행동 결과 ─▶ [규칙] ─▶ 스레드에만 / 채널에도 한 줄
                │
         (켰을 때만) ▶ [모델: 두 선택지 중 하나] ──┐
                │            실패·늦음 ─────────────┤
                ◀────────── 규칙으로 돌아가요 ───────┘
```

- **질문 하나, 선택지 둘**: 「이 결과를 채널에도 한 줄 알릴까?」 — 스레드에만 / 채널에도 한 줄.
- **기본은 규칙이고, 기본은 꺼짐이에요.** 켜는 사람은 인스턴스 운영자(셀프호스트에서는 소유자)예요. #2883의 **같은 결정 칸**을 써요: 별도 키 슬롯 · 꺼짐/관찰/켜짐 · 외부 전송 동의 문장. 이 질문은 그 칸의 두 번째 질문 종류예요.
- **모델이 못 하는 것**: 승인·거부·권한·보안·결정 라우팅·푸시 받는 사람·카드 내용. 모델의 답은 **보이는 자리**만 바꿔요(스레드의 결과는 어느 쪽이어도 같아요). 규칙이 「채널에도」인데 모델이 「스레드에만」이라고 해도, 반대여도 둘 다 허용돼요 — 표시만 달라지기 때문이에요.
- **모델이 보는 것 [Proposed]**: 행동 id와 서버가 만든 결과 요약 행. 요청 메시지 본문과 대화 이력은 보내지 않아요. 에이전트는 이 판정을 부르지도 결과를 보지도 못해요(임계값을 더듬어 우회하지 못하게).
- **실패·늦음 → 규칙.** 제한 시간은 800ms로 시작해요 **[Proposed]**. 첫 단계는 「관찰」(판정은 하되 적용 없이 기록만)이에요. 어느 쪽이 쓰였는지(규칙·모델·대체)는 묶음 감사 행에 한 키로 남겨요.
- 선례: 단조 강화만 · 실패 시 규칙 · 기본 꺼짐(1차 판정기 제안서), 결정 칸의 키 슬롯과 관찰 모드(F13, #2883). 여기서는 보안 판정이 아니라 **표시 판정**이라서 「더 엄격하게만」 대신 「표시만, 두 방향 모두 허용」을 써요.

## 5. 푸시

### 5.1 받는 사람 (변화 없음)

그 승인을 **결정할 수 있는 사람**에게만 가요(ADR-0204 D7: 채널 멤버 + 행동의 역할·소유자 조건. 결정할 수 있는 사람은 사람이라 요청한 에이전트는 받지 않아요). 방해금지·음소거는 승인도 막아요. 와이어는 id만 가고 기기가 REST로 읽어 채워요. 제목은 에이전트 이름, 사진과 #채널은 커뮤니케이션 알림(#4316)이 붙여요.

### 5.2 상태별 제목·본문 [Proposed]

본문은 지금 카드 메시지의 `body`예요(「승인 요청: 채널 만들기」, 도구 승인은 영어 「Approval required: …」). 이것을 **질문 한 문장**으로 바꾸고, 서버가 카드를 쓸 때 한 번 만들어요. 같은 `body`가 푸시·데스크탑 알림·카드를 모르는 옛 클라이언트의 폴백·검색에 한 말을 해요.

| 상태 | 받는 사람 | 제목 | 본문 | 버튼 |
|---|---|---|---|---|
| 승인 필요(바로 승인) | 결정할 수 있는 사람 | 달무리봇 | 소개를 바꿔도 될까요? · 「알림 시험」 | 승인 · 거부 (잠금 해제 필요) |
| 승인 필요(열어서 결정) | 결정할 수 있는 사람 | 달무리봇 | 비공개 채널을 만들어도 될까요? · 「qa」 (먼저 제안이면 앞에 「먼저 제안 ·」) | 열어서 결정 |
| 만료 10분 전 (#3969) | 결정할 수 있는 사람 | 달무리봇 | 10분 안에 만료돼요 · 소개 바꾸기 | 위와 같은 버튼 |
| 끝 | 요청한 사람(결정한 사람이 아닐 때) | 달무리봇 | ✓ 소개를 바꿨어요 · 이도현 승인 | 열기 |
| 거부 | 요청한 사람(결정한 사람이 아닐 때) | 달무리봇 | 이도현 님이 거부했어요 · 소개 바꾸기 | 열기 |
| 만료 | 요청한 사람 | 달무리봇 | 승인을 기다리다 만료됐어요 · 소개 바꾸기 | 열기 |
| 실패 | 요청한 사람 | 달무리봇 | 소개를 바꾸지 못했어요 · 다시 요청해 보세요 | 열기 |
| 생각 중 · 실행 중 | 보내지 않아요 | — | 일하는 중에는 푸시하지 않아요 | — |

- **지금과 다른 점**: 만료는 이미 요청한 사람에게 가요(ADR-0204 D8). **거부와 끝은 지금 조용해요**(D8 증보 1: 진행·거절 줄은 조용함). 이 표는 요청한 사람이 결정한 사람과 **다를 때만** 거부·끝을 알려요 — 같은 사람이 방금 눌렀다면 0건이고, 그 대화를 보고 있으면 생략해요. 옛 줄이 없어지므로 만료까지 포함해 종결 이벤트가 이 알림을 만들어요(ADR-0204 증보 6 D6-5, owner 「바로바로 ㄱㄱ」) **[Accepted]**.
- **값 뒤에 조사를 붙이지 않는 틀이 기본이에요**: 값은 「」로 문장 뒤에 붙어요(「소개를 바꿔도 될까요? · 「알림 시험」」). 「소개를 「…」으로 바꿔도 될까요?」처럼 값 뒤 조사를 쓰는 틀이 더 자연스럽지만, 조사는 값의 끝 글자가 정해요. 코어에는 으로/로를 정하는 `directionParticle`과 이/가·을/를·은/는·과/와를 정하는 `particleFor`가 있는데 둘 다 **한글 끝만 판정하고**(영문·숫자·기호 끝은 일부러 판정하지 않고 「을(를)」처럼 헤지해요), 서버 문장 쪽(`momo-agent`의 `korean.rs`)에는 으로/로 쌍이 없어요. 그래서 값 뒤 조사를 쓰는 틀은 값이 한글로 끝날 때만, 서버가 으로/로를 배운 뒤에 써요 **[Proposed]**. 한글이 아닌 끝은 언제나 조사 없는 틀이에요.
- 값이 개인정보이거나 길면 본문에 넣지 않아요. 메시지 고정 같은 카드는 「메시지 하나를 고정해도 될까요?」처럼 값을 빼요(고정 카드는 열어서 결정이라 본문은 힌트일 뿐이에요).
- 본문을 못 받으면 버튼을 떼고, 「미리보기 끄기」는 승인에 걸리지 않아요(지금 그대로).

### 5.3 결정 뒤 같은 알림이 바뀌는 문장 [Proposed]

지금은 「승인했어요 · {에이전트 이름}」이라 **무엇을 승인했는지** 안 나와요. 결정 응답(영수증)에 서버가 만든 한 줄 `line`을 더하고 기기는 그것을 그대로 보여요(구버전 서버는 지금 문장으로 폴백해요). 소리 없이 바뀌어요.

| 한 일 | 바뀐 문장 | 지금 |
|---|---|---|
| 승인 | ✓ 소개를 바꿨어요 | 승인했어요 · 달무리봇 |
| 거부 | 소개 바꾸기를 거부했어요 | 거부했어요 · 달무리봇 |
| 이미 승인됨 | 이미 승인된 요청이에요 · 소개 바꾸기 | 이미 승인된 요청이에요 |
| 이미 거부됨 | 이미 거부된 요청이에요 · 소개 바꾸기 | 이미 거부된 요청이에요 |
| 실패 | 승인하지 못했어요 · 눌러서 앱에서 마무리해 주세요 | 지금 그대로 |

### 5.4 바로 승인과 열어서 결정의 기준 [Accepted: 결정 3의 원칙 / Proposed: 행별 판정]

**원칙 [Accepted].** 위험이 낮은 것만 잠금 해제 뒤 바로 승인하고, 되돌릴 수 없음 · 권한 · 1회 값 · 먼저 제안은 앱을 열어 결정해요.

| 기준 | 지금 `opens_in_app` 목록에 있나 |
|---|---|
| 1회 값(초대 링크·페어링 코드) | 있어요 |
| 먼저 제안(사람이 안 불렀어요) | 있어요 |
| 앱에서 봐야 판단되는 것(그림·긴 글·호스트 선택·로그인 인계) | 있어요 |
| 모르는 모양(레지스트리에 없는 행동·이름 없는 도구·모르는 종류) | 있어요(모르면 연다) |
| **권한**(접근 범위·역할을 넓혀요) | **없어요** |
| **되돌릴 수 없음** | **없어요** — 서버가 값을 모르고(`isReversible`을 안 보내요), 레지스트리의 행동은 정의상 모두 반대 행동으로 되돌려요 |

**지금과 달라지는 행만 [Proposed]:**

| 승인 | 지금 | 제안 | 기준 |
|---|---|---|---|
| `hosted.channels.grant`, 에이전트가 먼저 청한 것 | 바로 승인 | **열어서 결정** | 권한 — 에이전트가 읽고 쓰는 범위가 늘어요 |
| `hosted.channels.grant`, 사람이 그 채널에서 직접 부른 인플레이스 카드(`origin=server_in_place`) | 바로 승인 | 바로 승인(그대로) | 방금 그 대화에서 부른 일이라 놀랍지 않아요 |
| `member.role.set`(선언만, 아직 실행 안 함) | 해당 없음 | 실행을 열 때 **열어서 결정**으로 등록 | 권한 |
| 카탈로그 밖 운영자 도구 호출(`tool_call`) | 바로 승인(현행 주석이 정한 선택) | **열어서 결정** | 되돌릴 수 있는지 서버가 몰라요 — 현행 선택을 뒤집으니 확인이 필요해요(§9) |
| 그 밖의 모든 승인(`channel.member.add`·`agent.rename`·`workspace.*`·`plugin.install` 포함) | — | **그대로** | 배너로 판단돼요. `channel.member.add`·`plugin.install`·`workspace.work_tier.update`가 「권한」에 닿는지는 확인 항목이에요(§9) |

**한 곳이 정해요 [Proposed].** 서버의 `opens_in_app()` 결과를 카드 props와 승인 목록에 `decision_mode`(`inline`/`open`)로 실어요. 푸시 카테고리 · `push_action` 토큰 거절 · 인박스 칸의 결정 버튼(오른쪽 칸·시트) · 채널 칩 버튼 · 카드가 모두 같은 값을 읽고, **클라이언트는 다시 계산하지 않아요.** 이것으로 지금의 차이가 사라져요: 푸시는 사진·고정 카드를 앱에서 열게 막는데 앱 인박스 행에서는 바로 눌려요(그것이 안전 문제인지는 확인 항목이에요, §9). 모든 등록 행동의 결정을 글로 적게 한 기존 기록 시험(`every_registered_action_has_a_recorded_lock_screen_decision`)이 위 표의 정본이고, 새 행동은 이유(1회 값·권한·되돌릴 수 없음·없음)를 같이 적게 해요.

### 5.5 데스크탑 OS 알림 [Proposed]

- 제목은 에이전트 이름, 본문은 위와 **같은 질문 문장**이에요(지금은 「승인 필요 · 보낸 이」 + 카드 제목).
- 버튼은 없어요(지금처럼). 누르면 **그 자리**로 가요: 채널 최상위 요청이면 스레드가 열리고 카드로 이동(도착 강조), DM이면 대화의 카드, 스레드 안 요청이면 그 스레드예요.
- 1.2초 안에 여럿이면 「승인 필요 N건」 + 이름 셋으로 묶여요(지금 그대로). 창을 보고 있을 때의 규칙은 폰과 맞추는 #4553이 정해요.
- 다른 기기에서 결정되면 알림을 걷는 것은 Tauri 알림의 한계를 확인해야 해서 `runtime-unverified`예요.

## 6. 인박스 「승인」 칸

### 6.1 새 화면이 아니에요

ADR-0186 증보 v5 U-c의 **C3(별도 승인함)가 아니에요.** 새 채널 종류도, 새 화면 종류도, `approval.channel_id` 변경도 없어요. 지금 인박스 안에 흩어진 둘 — 웹 「처리할 일」(폰 「결정 대기」)과 숨은 「활동」(웹 `/activity`, 폰 8번째 칩 「에이전트」) — 의 **승인 부분을 한 칸으로 합쳐요**. 대기 승인이 이미 인박스 응답에 합쳐진다는 사실(ADR-0199)은 그대로예요.

### 6.2 구역과 행

```
승인
  결정할 것 1
    [달] 달무리봇 · 소개 바꾸기                              오후 7:34
         승인 필요 · 23시간 남음 · #달무리-실험실 · 스레드
  오늘
    [달] 달무리봇 · 채널 「qa」 만들기                        오후 2:02
         ✓ 이도현 승인 · 다이렉트
    [모] 모래시계봇 · 메시지 고정                             오전 11:20
         ✕ 박서연 거부 · #qa
  어제
    [달] 달무리봇 · 도구 실행                                오전 4:07
         ⏱ 만료 · #달무리-실험실
```

| 요소 | 규칙 |
|---|---|
| 구역 | **결정할 것**(내가 결정할 수 있는 대기 건, 만료 임박순) · **오늘** · **어제** · 그 뒤는 「이전」으로 접고 쪽매김해요 **[Proposed]** |
| 얼굴 | 제안한 에이전트(둥근 사각형) |
| 문장 | 「에이전트 · 하려는 일」 짧은 형태. 영어 줄도 「되돌릴 수 없음」도 없어요(서버가 `reversible`을 보낼 때만 말해요) |
| 상태 | 아이콘 + 낱말(§2.2) + 곁말: 승인 필요는 남은 시간, 끝·거부는 결정한 사람, 만료는 없어요 |
| 자리 | `#채널 · 스레드` 또는 `다이렉트` |
| 시각 | 요청 시각(결정한 건은 결정 시각을 곁말에) |
| 결정할 것 구역의 행 | 값 칩 한 줄(최대 하나)을 더해 **무엇이 바뀌는지** 보이게 해요 **[Proposed]** |
| 기록의 범위 | 내가 결정한 것 · 내가 요청한 것 · 내가 담당하는 에이전트의 것. 채널 멤버십으로 서버가 걸러서 줘요(ADR-0199 D4의 조회 시 가시성 재판정, D5의 수신자 격리와 같은 규칙) **[Proposed]** |

### 6.3 거르기 · 누르면

- **거르기** 둘: 에이전트 · 상태(결정할 것·끝·거부·만료·취소). 웹은 목록 위, 폰은 「승인」 칩을 고르면 목록 머리에 한 줄이에요.
- **행을 누르면 그 자리로** 가요: 채널 최상위 요청이면 스레드가 열려 카드로(도착 강조), DM이면 대화의 카드, 스레드 안 요청이면 그 스레드예요.
- **행에는 결정 버튼이 없어요.** 결정은 아래 두 칸/시트에서만 해요. 지금 폰 행이 근거 없이 전폭 버튼을 세우는 것을 없애요(`decision_mode=open`인 승인은 어디서도 인박스로 결정하지 않아요).

### 6.4 웹 두 칸, 폰 목록 → 시트

| 표면 | 모양 |
|---|---|
| 웹·데스크탑 | **두 칸**(지금 구조 그대로): 왼쪽은 목록, 오른쪽에 **같은 묶음 카드** + 요청 메시지와 생각 줄 요약 몇 줄(판단 근거). 결정 버튼은 `inline`이고 내가 결정할 사람일 때만 서요. `open`이면 「스레드에서 결정」이 서요 |
| 폰 | **목록 → 바텀시트**(phone-sheets.md: 미리보기와 행동 6개 이하는 시트). 시트 안에 같은 묶음 카드. `open`이면 시트의 「열어서 결정」이 스레드 화면(페이지)을 열어요 |

숫자와 빈 상태: 탭 배지는 **결정할 것**의 수만 세요(지금 규칙). 비었을 때 「지금 결정할 일이 없어요. 조용한 게 정상이에요.」(설계된 빈 상태, README), 기록이 없을 때 「승인 기록이 아직 없어요.」예요. 결정하면 행이 사라지는 대신 **오늘 구역으로 내려가** 결과가 남아요(지금은 영수증 한 줄뿐이에요).

### 6.5 읽기 계약 [Proposed]

지금 승인 읽기는 대기 건 중심이고 기록은 4상태 × 50건에 취소가 빠지며 쪽매김·결정자·결과가 없어요. 이 칸은 서버 읽기에 **모든 상태 · 결정자 · 결정 시각 · 결과 요약 · 자리(채널·root·DM 여부) · `decision_mode` · 쪽매김**을 더한 가산 확장을 써요.

### 합쇼체 섞임

승인 고리의 화면 문장은 모두 해요체예요. 지금 합쇼체인 곳: `approvalNote.ts`의 `APPROVAL_OFFLINE_COPY`(「연결이 끊겨 지금은 결정할 수 없습니다 …」) 하나(곁의 `APPROVAL_ELSEWHERE_COPY`는 이미 해요체예요)와 웹 활동의 빈 상태 넷(`ActivityRoute.tsx` 39-57: 「승인 기록이 아직 없습니다.」 …)이에요. 활동의 빈 상태는 §6의 빈 상태로 대체돼요. 메시지 수정·삭제 실패 문구(`actionCopy.ts`)는 이 고리 밖이라 건드리지 않아요.

### 영어 원문 줄을 대신할 문장

서버는 사람 화면용 필드에 영어를 쓰지 않아요. **상태 코드가 정본이고 한국어는 클라이언트가 코드에서 만들어요.** 푸시·옛 클라이언트·에이전트가 읽는 `body`만 서버가 한국어 중립문으로 써요(그 자리는 기기가 코드를 읽을 수 없어요).

| 영어 원문(서버 상수) | 상태 코드 | 대신할 문장 |
|---|---|---|
| `Tool call expired without a human approval.` (`approval_sweep.rs`) | `expired` · `approval_expired` | 승인을 기다리다 만료됐어요 |
| `Tool call rejected by human approval.` (`approvals.rs`) | `rejected` | 이도현 님이 거부했어요 (결정한 사람을 모르면 「거부됐어요」) |
| `Approval required: {도구}` (`approval.rs`) | — (카드 `body`) | 도구 「{이름}」을 실행해도 될까요? |
| `Approval expired before a human decision.` | — | 감사 사유라서 화면에 나오지 않아요(그대로) |
| 「도구 실행 · 실패」 제목 | 상태가 만료·거부면 제목을 제안 문장으로, 실패만 「실패」 | — |

사람 이름은 결정한 사람의 **현재 표시 이름**을 읽어요(바뀌면 따라가요). 문장 안에 이름을 구워 넣는 것은 서버 `body`(푸시 폴백)뿐이에요.

| 생각 줄 | 상태 낱말 + 지금 단계. 점 셋은 `aria-hidden`. 낭독은 국면이 바뀔 때만 |
| 승인 필요가 나타남 | `role="status"` 한 번(polite) |

### 8.3 시험할 행동 (구현 이슈의 Acceptance로 그대로 옮겨요)

호출자가 보는 결과(응답 · DB 행 · 화면)만 단정해요. 시험은 대상(컴포넌트 · 모듈) 이름으로 두고 이슈 번호를 파일 이름에 넣지 않아요. 새로 쓰거나 바꾼 단정은 실제로 붉어지는지 확인하고 그 결과를 PR 본문에 남겨요(바뀌지 않은 단정까지 일률적으로 요구하지 않아요, AGENTS.md).

**코어 (묶음 모델 · 말 사전)**
1. 같은 입력(승인 5상태 × run 단계(일하는 중 · 승인 대기 · 끝) × 종료 코드 `approval_rejected` · `approval_expired` · 성공 · 실패 · 사람이 멈춤)이면 묶음 상태는 여덟 중 정확히 하나이고, 낱말 · 아이콘 이름 · 톤이 §2.2와 같아요(전수). 전달·생존의 낱말(받음 · 가져감 · 아직 받지 않았어요 · 시간 초과 · 신호 소실)은 묶음 상태가 아니라 #4619 칩 그대로예요(신호 소실을 「실패」로 접지 않아요).
2. 같은 시각에 같은 run · approval을 칩 · 카드 · 예외 줄 · 인박스 행 · 푸시 문장 모델에 넣으면 낱말이 일치하고, 거부 · 만료로 끝난 run에는 예외 줄이 서지 않아요(`runExceptionChipParity`와 같은 교차 시험의 확장, 상위·하위 대응 포함).
3. 승인 고리의 사람 화면 문장에 영어 원문 · 합쇼체 · 「거절」 · 「승인 대기」가 0건이에요(문구 프리플라이트 규칙, 양성 fixture로 실제로 잡는지 확인).
4. 같은 카드를 결정할 수 있는 사람 · 없는 사람 · 요청한 에이전트 본인에게 주면 버튼은 첫 경우에만 서고, 나머지는 「~님의 승인을 기다려요」예요.
5. 푸시 · 카드 문장 틀: 기본 틀은 값 뒤에 조사를 붙이지 않아요. 값 뒤 조사를 쓰는 틀은 한글 끝 값에서만(받침 있음 · 없음 · ㄹ받침) 쓰고 서버와 코어가 같은 표를 읽어 같은 조사를 골라요. 영문 · 숫자 · 기호 · 이모지 끝 값에서는 헤지 조사 「을(를)」이 화면에 나오지 않아요.

**웹·데스크탑**
6. 승인 필요 카드에 머리 문장 · 값 칩 · 버튼 한 쌍 · 조용한 줄이 있고, 라벨 일곱 줄은 「자세히」가 닫혀 있으면 접근성 트리에도 없어요.
7. 채널 최상위 요청의 스레드 요약 줄에서 ① 대기 제안 하나 ② 내가 결정할 사람 ③ `inline` ④ 문장이 같은 줄에 보일 때만 버튼이 서요. `open`이면 「열어서 결정」만 서요.
8. 채널 최상위 요청의 카드 · 결과 · 최종 답은 스레드에만 있고 본류에 없어요. DM은 본류에, 스레드 안 요청은 같은 스레드에 있어요.
9. 생각 줄: 일하는 동안 한 줄, 누르면 과정 행, 끝나면 요약 한 줄. 이동 0 · 초 단위 글자 0 · 동작 줄이기에서 점 정지.
10. 펼친 칸에 흐르던 글은 새로고침 · 재접속 뒤에 없고 단계 메모만 남아요.
11. 데스크탑 OS 알림 제목 · 본문이 §5.2와 같고, 누르면 스레드의 카드로 도착 강조가 돼요.

**폰**
12. 같은 카드 문법 · 버튼 표적 44 · 시트 안 결정 · VoiceOver 액션 이름(승인 · 거부) · 동작 줄이기.
13. 칩/요약 줄을 누르면 스레드 화면이 열리고 카드로 도착 강조가 돼요.

**서버 (자리 · 상태 코드)**
14. 카드 · 도구 줄 · 결과 · 최종 답이 네 경로(외부 Agent Port · REST 콜백 · 관리형 워커 · 팀 AI)에서 같은 root를 써요(실제 PG 행으로).
15. 승인 · 거부 · 만료 · 취소 모두 같은 카드 props와 `body`에 상태와 결과가 패치되고 `message.edited` 프레임이 한 번 나가요(만료 · 취소 포함, 행동 승인과 도구 승인 모두).
16. 사람 화면용 필드에 영어 원문이 0건이고 `props.status` · `props.code`가 있어요. 카드 `body`는 한국어 중립문이고 종결 때는 결과 한 문장이에요.
17. 어느 종결 경로도 옛 별도 줄(실행됨 카드 · 거부 줄 · 만료 줄)을 쓰지 않고(행동 승인 · 도구 승인 모두), 카드의 끝 상태는 `props`로 그려져요. 옛 클라이언트와 에이전트의 대화 읽기는 카드 `body`의 한 문장으로 끝 상태를 읽어요(정보 손실 0).
18. 「채널에도 한 줄」: 행동별 기본값 표대로 본류 한 줄이 생기고 푸시는 한 번만 가요.

**푸시**
19. 본문 문장이 §5.2 표와 같고, 결정 뒤 알림 문장에 한 일이 들어가요(`receipt.line`, 구버전 폴백 포함).
20. 푸시 카테고리 · `push_action` 거절 · 인박스 칸의 결정 버튼(오른쪽 칸 · 시트) · 채널 칩 버튼이 같은 `decision_mode`를 읽어요. 바뀌는 행(§5.4)만 현행과 달라요(기록 시험표 갱신).
21. 받는 사람: 결정할 수 있는 사람과, 종결 때 요청한 사람이에요. 요청한 사람이 결정한 사람이면 0건, 그 대화를 보고 있어도 0건이고, 만료 알림은 옛 줄 없이도 요청한 사람에게 한 번 가요.

**인박스**
22. 구역 넷(결정할 것 · 오늘 · 어제 · 이전) · 행 다섯 요소 · 거르기 둘이 서고, 행을 누르면 스레드/대화의 카드로 도착 강조가 돼요.
23. 행에는 결정 버튼이 0개이고, `inline`만 오른쪽 칸/시트에서 결정돼요. `open` 승인은 어디서도 열지 않고는 결정되지 않아요.
24. 끝 · 거부 · 만료 · 취소 행에 결정한 사람과 시각이 있어요.

**판단 칸**
25. 꺼짐이 기본이면 모델 호출 0. 켜짐에서 실패 · 시간 초과 · 잘못된 답이면 규칙대로 가요. 승인 · 보안 · 권한 경로에 모델 호출이 닿는 코드 경로 0(구조 시험 + 사보타주). 외부 전송 동의 없이는 호출 0. 에이전트가 판정 결과를 읽을 수 없어요.

### 8.4 재지 못하는 것

실제 외부 에이전트가 단계 메모를 어떤 박자로 보내는지, 내장 에이전트의 요약 생각(`runtime-unverified`), 스크린리더의 실제 낭독, 실기기 잠금 화면의 알림 모양과 버튼, Tauri 알림을 걷을 수 있는지, 모델의 실제 판정 품질은 PR의 캡처와 실기 점검으로 사람이 봐요.
