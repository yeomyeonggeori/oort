## 3. 새로 결정해야 하는 것 — 이번 리서치가 연 질문들

기존 결정 큐(ADR-0103~0108)에 이번 리서치 결과를 접속하면:

| 질문 | 업계 답 (요약) | 걸리는 자리 |
|---|---|---|
| presence/typing을 어떻게 | 연결 기반 + 구독 문법 + 안 보는 사람에겐 안 보냄 (03§4·04§3) | **ADR-0104** (기존 큐) |
| 한국어 검색 | PGroonga 계열 vs 외부 엔진 — 설치 난이도가 배포판 변수 | **ADR-0105** (기존 큐) |
| CI·배포 신뢰 경계 | install/upgrade 스크립트, 이미지 서명 | **ADR-0107** (기존 큐) + ADR-0002 후속 |
| 서버 스택 지속 판정 | 단일 노드 표준 확인됨 (05§4) | **ADR-0108** (기존 큐) |
| **push relay를 momo가 운영하는가** | 구조적 필연 (05§1) — id-only 페이로드, Zulip 과금 모델 | **신규 ADR 필요** (0119+ 제안) |
| **웹 클라이언트 트랙 신설** | 서버 동일 도메인 서빙 (05§3) — 로드맵에 웹 트랙 자체가 없음 | **신규 ADR + 로드맵 개정** |
| **셀프호스팅 배포판·초대 온보딩 모델** | 스토어 단일 앱 + URL + universal link (05§2), 단일노드 상한 명시 (05§4) | **신규 ADR** (ADR-0002/0107과 연동) |
| 첨부(가벼운 파일)와 Drive(문서)의 분리 여부 | 첨부는 만료형 서명 URL 필수 (04§5) | ADR-0113/0116 논의에 합류 |

신규 ADR의 구체 분해·옵션·권고는 `research/15-platform-expansion/02-decision-proposals.md`가 담는다. 번호 발급과 착수 순서는 성재 승인 사항.

## 4. 슈퍼앱 경사로 — 이미 결정된 것 위에서

"비개발자도 따라오고 개발자는 더 깊이"라는 질문의 정본 답은 이미 ADR-0112다: **하나의 타임라인, 두 개의 밀도.** 이번 리서치가 추가로 확인해 준 것:

- Discord의 passive sessions(04§3)와 Slack의 구독 presence(03§4)는 "보지 않는 것은 보내지도 렌더링하지도 않는다"는 같은 원칙 — ADR-0112의 "동료의 업무 로그가 대화를 침범하지 않는다"와 동일 문법의 인프라 버전이다.
- Codex 앱의 ⌃` 드로어·승인 프리셋 문법은 ADR-0112 D3와 MOMO-375(transcript 드로어), ADR-0114(인터랙티브 host 결정 대기)로 이미 티켓 체계에 들어와 있다.
- 남은 기획 과제는 "모드 2개"가 아니라 **경사로**다: 기본 모드 → 카드 펼치기 → 개발자 모드 토글 → 드로어 → (ADR-0114 이후) 실행 개입. 각 단계가 바로 아래 단계에서 한 클릭이면, 비개발자가 개발자가 되는 경로가 UI 안에 존재하게 된다. 이 경사로 정의는 ux-bible 개정 제안으로 research/15에 포함한다.
