- Date: 2026-10-03
- Deciders: 성재

## 맥락

### 풀려는 문제
- 「랩탑을 꺼도 폰에서 내 하네스(Claude, Codex)를 이어서 쓰고 싶다」. 지금은 사용자가 자기 VM에 `curl | sh --pair`로 workd를 설치해야 한다(ADR-0192 D1, 파일은 아직 없다). VM이 없는 사람은 길이 없다.
- 성재의 결재는 oort가 사용자별 격리 컨테이너를 **운영**해 주는 쪽이다. 비용과 약관의 무게가 사용자 VM(시나리오 D)과 다르다. 컨테이너를 돌리는 쪽이 oort의 운영자가 되기 때문이다.

### 약관이 허용하는 좁은 길 (시나리오 E)
정책 진단의 원문 대조가 결론 근처에서 만든 사실이다. 전부 2026-10-03 취득이고 최종 법무 판단 전에 원문 재확인이 필요하다.

1. Anthropic은 「hosted sandboxes」에서 Claude Code를 돌리려면 **상업 약관에 동의**하고, **바이너리를 수정하지 않고**, 사용 요금을 **대신 내거나 재판매하지 않으며** 사용자가 자기 자격으로 로그인해야 한다고 적었다([V] §1.1 「Can customers offer Claude Code in their products?」).
2. 같은 문서는 「developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow」라 적고, 곧바로 「Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code」라고 적는다([V] §1.1). 로그인 코드를 붙여 넣는 흐름은 Anthropic 인증 문서가 컨테이너·SSH용으로 직접 안내한다([V] §1.3).
3. 그래서 E의 조건은 넷이다. ⓐ 운영 주체가 상업 약관에 동의한다. ⓑ 바이너리 무수정, 인증 수단 제거 금지. ⓒ 비용을 운영 주체가 대신 내거나 재판매하지 않는다. ⓓ **oort가 토큰·세션 토큰·로그인 코드를 수집·저장·중개하지 않는다.**
4. 아직 닫히지 않은 것: (i) oort가 ACP·`claude -p`로 구독을 구동하는 경로는 Agent SDK 제한에 걸릴 수 있다(§2 각주 ★, #3397이 기본 꺼짐으로 닫는다). (ii) 컨테이너 디스크에 CLI가 쓴 자격 파일이 oort가 운영하는 디스크에 놓이는 것이 「store」인가는 확정 문구가 없다(§4.4-5). (iii) OpenAI 쪽 E는 **회색**이다. OpenAI가 「paid or remotely hosted app」을 따로 심사 대상으로 분류한다([S] §1.7, §2). Codex는 성재가 이 ADR에서 허용하기로 했으나, 이 ADR은 그것을 「약관이 허용한다」가 아니라 **「결재가 허용하고 질문이 미회신」** 으로 기록한다.

### 현행 불변식과 부딪히는 곳
이 ADR의 핵심 난점이다. 컨테이너 안에서 사용자가 로그인하려면 **사람이 보는 raw 터미널**이 폰·웹·데스크탑에 필요하다. 그런데 현행은 이렇다.
- ADR-0188 D1 「폰에는 raw 터미널 바이트가 가지 않는다」, ADR-0125 D10 「서버는 터미널 바이트를 싣지 않는다」.
- ADR-0188 D6 「원격 셸 금지」, workd는 셸을 거부한다. ADR-0190 D1 「PTY는 데스크탑 앱 프로세스가 열고 workd는 PTY를 열 수 없다」, D6 「팀원 터미널 raw 관전은 목표 A 뒤」.
- 진단 §3.2는 E에 「로그인 코드가 oort 서버를 통과하지 않는 터미널 중계」를 요구한다.

이 셋을 한 번에 만족하는 설계가 D5의 **눈먼 중계(blind relay)** 다. 서버는 암호문 프레임만 전달하고 평문을 갖지 않는다.

### 현재 코드 사실
- `momo-workd`는 host 키를 macOS 키체인에 두고, 그 외 플랫폼은 `--dev-key-file`(개발·시험 전용)뿐이며 키체인이 없으면 에러다([V] `server-rust/bins/momo-workd/src/keystore.rs:64-65`). 컨트롤 소켓·피어 코드서명 검증도 macOS 전용이다([V] `cli.rs`, 진단 §3.2-D-2). **Linux 컨테이너에서 workd를 돌리려면 키 보관 설계가 선행한다.** #2786(한 줄 설치)이 같은 문제를 갖는다. 이 ADR은 그 결정을 따로 하지 않고 D6의 「영속 게이트」로 묶는다.
- 팀 인스턴스 카탈로그에는 per-user 컨테이너를 위한 것이 없다. `infra/railway/railway.json`은 service 9개(postgres·centrifugo·api·relay·webhook-sender·agent-worker·notifier·push-relay·caddy) 정적 카탈로그이고, 같은 프로젝트의 서비스는 모두 `*.railway.internal` 사설망을 공유한다([V] `infra/railway/README.md`). `infra/fly/Dockerfile.host`와 `infra/cubesandbox/`는 단일 VM 호스트와 microVM 선례다([V]).
- ADR-0157 증보 1은 CubeSandbox Cubelet의 eBPF `deny_out`이 기본으로 RFC1918·loopback·169.254를 막는다는 실측을 적었다([V]). 컨테이너 런너에는 이 기대값을 호스트 선언 규칙으로 다시 세워야 한다.

### 판단
- **MVP는 A로 간다.** 이유 셋: ① 한도가 없고 비용이 가장 예측 가능하다. ② 네트워크·백업·exec 동사를 우리가 선언으로 쥔다. ③ 런너가 서버로 outbound만 다이얼하므로 Railway 팀 인스턴스와 셀프호스트 compose에서 똑같이 쓴다. 런너 VM은 팀 서버와 **다른** 기계다(DB와 같은 기계에서 사용자 코드를 돌리지 않는다).
- **B는 같은 런너 인터페이스 뒤의 대안 어댑터로 둔다.** 팀이 새 VM을 원치 않을 때만 쓴다. 쓰려면 S1이 (a) 별도 프로젝트 분리, (b) 볼륨 백업을 끌 수 있는지, (c) 프로젝트 토큰을 api가 아닌 전용 프로비저너에만 두는 구조, (d) 볼륨 한도를 실측해야 한다. 하나라도 안 되면 B는 닫는다.
- **C는 하드닝 단계의 선택지다.** 여러 팀에 파는 다중 테넌트는 범위 밖(#2788 Out of scope). 한 팀 안의 멤버끼리라도 커널 공유 위험이 불편해지면 gVisor나 microVM 런너로 올린다.

## 결정

### D1. 격리 단위는 「멤버 × 워크스페이스」당 컨테이너 1 + 볼륨 1이다
- 한 멤버가 한 워크스페이스에서 갖는 박스는 **최대 1개**다. 다른 워크스페이스는 별개 박스다.
- 컨테이너: 비루트 사용자, `--privileged` 금지, docker 소켓·호스트 경로 마운트 금지, 모든 capability drop, 기본 seccomp, 사용자 네임스페이스 재매핑, 읽기 전용 루트 파일시스템(쓰기는 홈 볼륨과 tmpfs뿐), PID·메모리·CPU 상한, 코어 덤프 끔(`ulimit -c 0`).
- 볼륨은 **그 박스 하나에만 붙는다.** 다른 박스, 런너 데몬, 서버 프로세스가 마운트하지 않는다(런너 데몬은 볼륨 경로를 열지 않는다. 시험이 소스와 syscall 추적으로 잠근다).
- 이미지는 다이제스트로 고정한 **공용 박스 이미지** 하나다. 공식 CLI(Claude, Codex)는 게시된 그대로 설치하고 수정하지 않는다. 이미지에는 자격이 없다.

### D2. 배치는 런너 호스트(A)를 MVP로 하고, 런너는 member host처럼 서버로 outbound만 다이얼한다
- 런너 데몬 `momo-box-runner`(이름은 가칭)는 서버로 outbound HTTPS만 한다. 서명된 수명 컨트롤(`create|start|stop|delete|status`)만 폴링해 실행한다. **런너 API에는 `exec`·`cp`·`commit`·`export`·`snapshot`·볼륨 복제 동사가 없다.** 허용 동사 목록이 소스에 고정되고 시험이 잠근다.
- 런너 등록은 member host 등록과 같은 문법이다(ADR-0188 D2, 0192 D2: 1회용 페어링 코드, 소유 확인 전 비활성). 런너 소유자는 워크스페이스 관리자다. 런너는 사용자 자격과 무관하다.
- 박스 안에서는 `momo-box-agent`(가칭, D5)가 박스의 host 신원이다. 이 신원은 **`scope='member'`, 소유자 = 박스 주인**으로 등록한다. 따라서 ADR-0188 D3(결정자=소유자), 0192 D5, 0191 D2가 새 규칙 없이 그대로 적용된다.
- Railway 어댑터(B)는 같은 런너 인터페이스를 구현하는 별도 구현이다. 도입 조건은 위 판단대로 S1 통과다. 도입하더라도 프로젝트 토큰은 api 서비스에 두지 않고 시작 명령을 고정한 전용 프로비저너 서비스에만 둔다.

### D3. 수명주기와 한도
| 상태 | 뜻 | 전이 |
|---|---|---|
| 없음 | 박스 없음 | 소유자가 「만들기」 → 만드는 중 |
| 만드는 중 | 이미지 받기·볼륨 만들기·box-agent 기동 | 성공 → 켜짐, 실패 → 없음(볼륨 정리) |
| 켜짐 | 컨테이너 실행. 기기가 붙었거나 세션이 있음 | idle 조건 → 유휴 |
| 유휴 | 컨테이너 실행 중이나 **붙은 기기 0 + 하네스 세션 0**이 30분(기본) | 정지 |
| 정지 | 컨테이너 중지, 볼륨 유지(영속 게이트 통과 시) | 켜기 → 켜짐, 30일(기본) 정지 지속 → 삭제 |
| 삭제 중 → 없음 | 컨테이너 제거 + 볼륨 파기 + 검증(D10) | 되돌릴 수 없다 |

- **「계속 켜 둠」은 소유자가 명시로 켜고, 기기가 붙어 있는 동안만 연장한다.** 기본 최대 12시간, 갱신에는 붙은 기기가 필요하다. `claude remote-control`을 tmux에 띄운 채 24시간 가동하는 것은 Pro/Max의 「ordinary, individual usage」 해석 위험(진단 §4.4-2)이라 기본으로 열지 않는다.
- **한도(기본, 워크스페이스 관리자가 줄일 수 있다):** 멤버당 박스 1, 박스당 1 vCPU·2GB RAM·디스크 10GB·PID 512, 워크스페이스 동시 켜짐 5, 런너 용량 초과 시 만들기 거절(「자리가 없어요」).
- 관리자는 박스를 **정지·삭제할 수 있다**(자원 관리). 관리자가 **붙거나 내용을 보는 일은 없다**(D6).

### D4. 로그인 — 사용자가 박스 안에서 공식 흐름으로, oort는 코드를 묻지도 읽지도 않는다
1. 사용자가 박스를 만들고 터미널 칸을 연다(D5).
2. **Claude:** 터미널에서 사용자가 `claude`를 실행하고 `/login`을 한다. 터미널에 뜬 URL을 **사용자 자신의 브라우저**에서 열고, 브라우저가 보여 주는 코드를 터미널의 `Paste code here if prompted` 프롬프트에 직접 붙여 넣는다([V] 진단 §1.3).
3. **Codex:** 사용자가 `codex login --device-auth`를 실행한다. 터미널에 뜬 URL과 1회용 코드를 사용자 브라우저에서 입력한다. 개인 계정은 ChatGPT 보안 설정에서 기기 코드 로그인을 켜야 한다[S].
4. oort 서비스, UI, 로그는 **로그인 URL·코드·토큰을 만지지 않는다.**
   - oort UI에는 **코드를 받는 입력창이 없다.** 안내 문구는 「코드는 이 터미널에만 입력해요. oort는 묻지 않아요」다.
   - 터미널 I/O는 D5의 암호문 경로로만 오간다. 서버·런너·관리자 도구에 평문이 없다.
   - box-agent는 PTY 바이트를 로그·크래시 덤프·스크롤백 동기화·세션 녹화에 남기지 않는다.
   - 앱과 폰은 터미널 스크롤백을 **서버로 동기화하지 않는다**(기기 메모리에만 둔다. 폰은 영속하지 않는다).
5. 자격 파일(`~/.claude/…`, `~/.codex/auth.json` 등)은 CLI가 박스 홈에 스스로 쓴다. box-agent·workd·런너·서버 중 **누구도 그 경로를 열지 않는다**(경로 거부 시험). 로그인 상태는 `claude auth status`·`codex login status`의 **종료 코드만** 읽는다(ADR-0190 D3·0191 D3 문법).
6. **금지:** `claude setup-token` 결과나 `auth.json`을 oort UI에 붙여 넣게 하거나 박스로 복사해 넣는 길, `CLAUDE_CODE_OAUTH_TOKEN`·`ANTHROPIC_API_KEY`·`OPENAI_API_KEY` 등 환경변수 주입(0191 D2와 0188 §8.1 조건 8의 허용목록이 박스 안에서도 적용된다), 로그인이 든 상태를 템플릿으로 굽는 일. 키 기반(BYOK)은 이 경로가 아니라 ADR-0147의 팀 키와 별도로 설계되는 「개인 API 키」(#3397 결재 ③) 경로다.

### D5. 제어 경로 — member host 서명 재사용, PTY는 눈먼 중계의 새 레인
박스는 두 레인을 갖는다.

**(1) ACP 레인(Codex만):** 박스 안 `momo-workd`가 Codex를 ACP로 구동한다. 서명 heartbeat, 서명 컨트롤, 권한 다리(0188 D5), 허용 폴더, 모드 고정(D6)이 member host와 **똑같이** 적용된다. 새 제어 의미는 없다. 박스 안 workd도 PTY를 열지 않는다(0190 D1 유지).

**(2) PTY 레인(사람이 직접, Claude와 Codex 모두):** 박스 안 별도 프로세스 `momo-box-agent`가 PTY를 연다.
- **관할:** 이 레인은 「박스 주인이 자기 박스에 붙는다」 하나뿐이다. 에이전트, 다른 멤버, 관리자, 웹훅은 붙을 수 없다.
- **붙기(attach):** 소유자 기기가 `cloud_pty_attach` 컨트롤을 **기기 키(생체 ACL) 서명**(ADR-0146 R2)으로 낸다. 서버는 서명, 소유자 = 박스 주인, 박스 `켜짐`, host `revoked_at` 없음을 확인하고 중계를 연다. 서버가 도출하는 대상 host는 요청이 아니라 박스 행이다(0188 D3 문법).
- **눈먼 중계:** 서버의 새 WebSocket 라우트가 기기와 box-agent 사이 **프레임을 그대로 전달**한다.
  - 종단간 암호화다. 기기와 box-agent가 임시 X25519로 키를 합의하고, box-agent는 자기 host 키로 합의 값을 서명한다. 기기는 **박스 등록 때 소유자 기기가 서명해 둔 host 공개키 지문**으로 검증한다. 서버가 공개키를 바꿔치기해도 소유자 기기 서명이 없으면 검증이 실패한다.
  - AEAD(ChaCha20-Poly1305 또는 AES-GCM)에 방향별 단조 카운터를 쓴다. 정확한 프로토콜(예: Noise 변형)과 의존 라이선스는 S2가 확정하고 이 ADR에 증보로 적는다. 새 의존은 permissive여야 하고 NOTICE를 반영한다.
  - 서버는 프레임을 **저장·로그·메트릭 라벨에 싣지 않는다.** 바이트 수와 시각만 센다. 프레임 크기·속도 상한과 역압을 둔다. 박스당 동시 붙기 수 상한(기본 2)을 둔다.
  - 기기 폐기·로그아웃·박스 정지 시 중계를 즉시 끊는다(0188 D7 문법).
- **이 레인은 0188 D1·0125 D10·0190 D6에 대한 좁은 예외다.** 폰·웹이 raw 터미널 바이트를 받는다. 단 ① 자기 박스에만, ② 소유자 본인에게만, ③ 서버는 암호문만 본다. 이 세 조건 중 하나라도 빠지면 예외가 없다. 로컬 레인의 데스크탑 PTY(0190 D1)와 원장 경유 원격 세션(0188)은 바뀌지 않는다.
- 새 컨트롤 종류와 중계 라우트는 **새 공개 API다.** 이 ADR의 Accept가 ADR-0100의 근거 선언이다. 스키마와 라우트 계약은 M4가 같은 ADR 증보로 확정한다.

### D6. 누가 조종하나 — 박스 주인만
- 박스의 모든 컨트롤(붙기, 입력, ACP spawn, 승인, 삭제 제외 수명 컨트롤 시작/정지)은 **박스 주인 본인**만 낸다. 워크스페이스 관리자, 에이전트, 다른 멤버는 낼 수 없고 서버가 거부한다(0188 D3 불변식 그대로).
- 관리자는 자원 관리만 한다: 목록(주인·상태·사용량·마지막 접속 시각), 정지, 삭제, 한도. **내용·터미널·파일·로그인 상태 세부는 보지 않는다.**
- 박스의 Codex 에이전트 멤버(「성재의 Codex · 클라우드」)는 owner_only다(ADR-0188 D4·0193 D4). 비소유자 멘션은 작업을 만들지 않는다.
- **Claude 구동은 #3397 규칙을 박스에서도 따른다.** 박스 이미지에는 Claude ACP 어댑터를 설치하지 않고, 서버도 박스의 Claude ACP spawn을 거부한다(플래그 기본 꺼짐). 사용자가 PTY에서 `claude`를 직접 쓰거나 `claude remote-control`을 직접 띄우는 것은 사람 입력이므로 영향이 없다. Remote Control 세션 URL 카드 공유는 0192 D4를 따르고 **원장 비대칭**(승인이 oort에 남지 않음)을 카드에 표시한다.
- Anthropic의 회신이 오면 ACP/`-p` 허용 여부를 #3397과 이 ADR의 증보로 바꾼다. 이 ADR이 먼저 열지 않는다.

### D7. 이미지·스냅샷·볼륨은 복제도 공유도 하지 않는다
- 박스의 컨테이너 이미지, 체크포인트, 볼륨을 복제·export·commit·공유하지 않는다. 다른 멤버가 쓰게 만들지도 않는다(0192 D5의 박스 판). 「내 박스를 템플릿으로」 기능을 만들지 않는다.
- 런너 동사 목록에 해당 동사가 없다(D2). 서버도 해당 컨트롤을 만들 수 없다.
- 호스트 쪽 **백업·스냅샷 금지는 영속 게이트**다(D8).

### D8. 영속 게이트 — 자격 파일과 host 키의 영속은 「백업이 없다」는 사실에 달려 있다
플랫폼 백업과 스냅샷이 자격 파일의 **oort 운영 사본**을 만들면 ⓓ와 진단 §4.3(이미지·체크포인트에 넣지 않는다)을 어긴다. 그래서:
- 박스 볼륨의 영속(정지 후에도 로그인 유지)은 **런너가 볼륨에 백업·스냅샷이 없음을 검증한 경우에만** 켠다. 런너 A: 백업 작업을 두지 않고, VPS 제공사의 디스크 스냅샷이 꺼져 있는지 설치 런북이 확인한다. 런너 B: 볼륨별 백업 비활성이 확인될 때만 켠다.
- 게이트를 통과하지 못하면 박스의 **자격 디렉터리와 host 키는 tmpfs에만** 둔다. 정지하면 사라지고 다음 시작에 다시 로그인한다(홈의 코드·작업 파일은 볼륨에 둘 수 있다).
- Linux host 키 보관(키체인 없음)은 #2786과 같은 설계다. 이 ADR의 결정은 「게이트 통과 시 볼륨 0600 파일, 아니면 tmpfs + 시작 때 서버가 낸 재페어링 코드」이고, 이 방식의 위협 모델 개정은 S4가 한다. dev 파일 키(`--dev-key-file`)를 프로덕션 박스에 쓰지 않는다.
- **운영자는 기술적으로 볼륨을 읽을 수 있다.** 이를 암호학으로 막지 못한다. 정책(어떤 oort 코드와 절차도 열지 않는다), 접근 통제, 감사로 줄이고 **잔여 위험으로 공개한다**(진단 §4.4-5).

### D9. 네트워크 egress
ADR-0157 D1~D3를 박스에 적용한다.
- 박스는 **인바운드 포트가 없다.** 박스와 런너는 outbound만 한다.
- 박스 → 호스트, 사설 대역(10/8, 172.16/12, 192.168/16), loopback, 링크로컬(169.254/16, 클라우드 메타데이터), 다른 박스, 서버 내부망(PG·Centrifugo·내부 포트): **차단.** 박스가 닿는 oort 표면은 공개 HTTPS(workd와 같은 문)뿐이다.
- 인터넷 egress는 **허용**한다(패키지 설치, git, 모델 API가 본질이다). 명제는 0157 D3 그대로다: **「박스 안에 있는 것은 유출될 수 있다고 간주한다」.** 통제 지점은 egress 필터가 아니라 ① 박스에 무엇을 넣는가(자격은 사용자가 로그인한 것뿐, oort 비밀은 박스 host 키뿐) ② 승인 게이트(Codex ACP 권한 다리)다.
- 남용 방지: SMTP(25) 차단, 박스당 동시 연결·대역폭 상한, 지속 고CPU(예: 10분 평균 90% 이상) 시 자동 정지와 알림.
- 규칙은 호스트에 **선언 파일**(nftables, 레포 관리)로 둔다. 런타임 API로 심지 않는다. 배포마다 **박스 안에서 사설 대역·메타데이터·이웃 박스로 프로브**하는 게이트가 통과해야 한다(0157 증보 1의 「기대값 검증」 문법).
- 허용목록(도메인 allowlist) 모드는 하드닝 단계의 옵션이다.

### D10. 삭제와 데이터 파기
- 트리거: 소유자의 삭제, 정지 30일 경과, **멤버 비활성·탈퇴·제거(즉시 정지 후 삭제)**, 워크스페이스 삭제(전 박스 연쇄), 관리자의 삭제.
- 절차: 컨테이너 중지·제거 → 볼륨 파기(런너 A: 볼륨 삭제 후 해당 블록 디바이스 trim/덮어쓰기, 런너 B: provider 볼륨 삭제와 백업 부재 확인) → 런너가 `deleted`를 서명 보고 → 서버가 박스 행을 `deleted`로 닫고 host를 revoke → 중계 연결 해제 → 감사 행(누가·언제·사유, 내용 없음).
- 삭제 `검증`: 런너가 컨테이너·볼륨 부재를 확인해 보고하지 못하면 `delete_failed`로 남기고 관리자 알림과 재시도를 건다. 「삭제됐다」는 표시는 확인 뒤에만 한다.
- 서버에 남는 것: 박스 행(상태·한도·시각), 감사 행. 터미널 내용, 로그인 상태 세부, 자격은 서버에 없다.

### D11. 운영자 약관 (E-ⓐ)과 하네스별 허용
- **「운영자」는 박스를 돌리는 주체다.** 셀프호스트에서는 그 팀의 운영자다. oort 프로젝트가 호스팅 서비스를 열면 oort 쪽이다. 소비자 약관(Pro/Max) 사용자가 섞인 구성에서 상업 약관의 효력은 **불분명**하다(진단 §4.4-4). 이 ADR은 법적 판단을 하지 않고 **기록과 게이트**만 둔다.
- 워크스페이스 설정 「개인 클라우드 작업 공간」은 **기본 꺼짐**이다. 켜려면 관리자가 하네스별 확인 문구에 동의하고, 서버는 동의자·시각·문구 버전을 기록한다. 동의 없이는 해당 하네스의 박스를 만들 수 없다.
  - Claude: 「이 워크스페이스의 운영자는 Anthropic의 상업 약관에 동의했고, 멤버는 각자 자기 구독으로 직접 로그인하며, 요금을 대신 내거나 재판매하지 않는다」. UI 표기는 **「조건부」** 이고 Anthropic 회신(#3397 문의 Q2) 전까지 유지한다.
  - Codex: 같은 형식의 동의 + 「OpenAI 약관상 원격 호스팅은 확정되지 않았고 문의 중」 표기. 성재 결재로 허용된다.
- oort는 구독 요금도 사용량도 재판매하지 않는다. 박스 컴퓨트 비용은 운영자가 부담하고, 멤버별로 청구하지 않는다.
- 제품·기능 이름에 「Claude Code」를 쓰지 않는다. 화면은 「클라우드 작업 공간」「Claude」「Codex」로 부른다. 정확한 평문 서술(「Claude Code가 설치돼 있어요」)은 법무 문서가 허용한 범위다.

### D12. 화면에 나타나는 방식
- **AI 허브(#3388):** 「내 AI 계정」 안에 행 「클라우드 작업 공간 (oort 운영)」. 상태 칩 `없음 · 만드는 중 · 켜짐 · 유휴 · 정지 · 삭제 중`, 하네스별 로그인 점(종료 코드 기준: `claude ✓ · codex ✗`), 라벨 「Claude: 조건부 · 사람이 직접 터미널로」「Codex: 문의 중」. 만들기·켜기·정지·삭제(확인 포함). 용어는 #3391(AIH-1) 용어집을 쓰고 새 낱말은 거기에 더한다.
- **「내 작업」:** 박스 host가 **원격 host 카드**(온라인 점, 이름 「성재의 클라우드 · 팀A」)로 나타난다. 칸 종류는 로컬 PTY 칸과 같은 격자의 **「클라우드 터미널」 칸**과 Codex ACP 세션이다. 폰의 작업 탭은 보드 문법(#3344)을 따르고 클라우드 터미널 칸은 폰에서 **내 박스에 붙는 칸**으로 열린다. 폰 터미널은 새 UI 표면이라 하드닝 단계에서 design-review Blocker 0·High 0을 받는다.
- 박스가 정지 중일 때 입력하면 「켜는 중이에요」 후 붙는다. 첫 로그인 안내는 터미널 칸 위의 한 줄이다(D4의 문구 그대로, 코드 입력창 없음).

## 이 ADR이 바꾸지 않는 것
- 서버는 토큰·세션 토큰·로그인 코드를 받거나 저장하거나 전달하지 않는다. 구독 OAuth 금고를 넓히지 않는다(ADR-0147 증보, 0193 (b) 기각).
- 한 구독을 둘 이상이 부르게 하지 않는다. 박스는 주인 1인의 것이다.
- 로컬 PTY 레인(0190)과 원장 경유 원격 세션(0188)의 불변식은 그대로다.
- 팀 공용 샌드박스(scope=workspace), 팀 공용 에이전트 구독 경로는 여전히 목표 A 뒤다.
- 개인 BYOK 키(#3397 ③)는 별도 설계다.

## 결과
- (+) 노트북이 꺼져도 폰에서 하네스를 이어 쓰는 길이 생긴다. 서버는 자격을 만지지 않는다.
- (+) member host 문법을 재사용해 새 제어 의미가 거의 없다.
- (−) raw 터미널 바이트가 폰·웹으로 가는 첫 레인이 생긴다. 눈먼 중계와 소유자 서명이 어긋나면 0188의 방어선 하나를 잃는다. 시험으로 잠근다(S2, M4, H4).
- (−) 운영자는 박스 볼륨을 기술적으로 읽을 수 있다. 정책과 공개된 잔여 위험으로 다룬다.
- (−) 운영 부담(런너 VM, 스냅샷 차단, 용량)이 생긴다. Codex는 OpenAI 회색, Claude는 「조건부」다.

## 업계 비교
- **Claude Remote Control·클라우드 세션:** Anthropic이 원격 머신+tmux를 문서화한다. 박스 안에서 사용자가 직접 `claude remote-control`을 띄우는 길과 같은 표면이다([V] 진단 §1.3).
- **Codex 클라우드/원격:** 헤드리스 device code 로그인이 공식 경로다([S]).
- **Orca:** 헤드리스 서버에서 에이전트 CLI 로그인은 서버에서 한다. oort 박스도 같은 문법이되, 중계가 서버를 거치므로 종단간 암호화를 더한다.
- **Cursor·Railway 샌드박스:** 작업 세팅은 레포 커밋이나 체크포인트로 옮기고 시크릿은 묶음에 넣지 않는다. oort는 체크포인트 공유를 금지한다(D7).

## 사용자 결재 요청 (소유자 질문)
1. **MVP 배치는 어디로?** 권장: **런너 호스트(전용 Linux VM)**. Railway 한도(프로젝트당 볼륨 20, 서비스별 egress 제어 [?])와 프로젝트 토큰 위험 때문이다. Railway 별도 프로젝트는 S1 통과 시 대안.
