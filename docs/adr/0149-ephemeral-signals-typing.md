# ADR-0149: 휘발 신호(작성 중·읽는 중) — 척추에 싣지 않는다

- Status: **Accepted** (2026-08-03 성재 승인 · 기안 Fable)
- 관련: **하드 불변식**(단일 쓰기경로 · Centrifugo 전송전용), ADR-0145(Rust 재작성), ADR-0137 D5
- 발단: 성재 실기기 피드백 — *"누가 말하는 중에는 **작성중** 관련 부분 UX도 메신저 앱들 분석해서 봐줘."*

## 왜 ADR인가 — 순진하게 만들면 불변식을 깬다

"작성 중"은 메신저의 기본기지만, momo에서는 **하드 불변식 두 개와 정면으로 만난다.**

단순 구현(작성 중 = 메시지처럼 취급)의 비용을 실측 규모로 계산하면:

```
타이퍼 1명 × 3초 주기 × 5분 대화 = outbox 100행
채널 5명이 동시에 = 500행
… 그리고 그 전부가 절대 읽히지 않을 행이다
```

- **단일 쓰기경로**(REST→PG→outbox→relay)는 **영속 상태**를 위한 경로다. 휘발 신호를 여기 태우면 outbox가 쓰레기로 차고, relay 지연이 **실제 메시지**에 전가된다.
- **`message.seq`는 gapless**여야 한다. 작성 중이 seq를 소비하면 안 된다(당연하지만, "메시지처럼" 만들면 그렇게 된다).

## 실측 — 지금 무엇이 있나

| 사실 | 근거 |
|---|---|
| 서버·클라 어디에도 **typing 구현이 없다** | Rust·Swift 전수 grep 0건 |
| **클라이언트 publish는 어디에도 열려 있지 않다** | `centrifugo.prod.json` 전 네임스페이스에 `allow_publish_for_*` 부재 |
| Centrifugo는 **presence가 이미 켜져 있다** | `ch`·`dm`·`agent` 네임스페이스 `presence: true`, `ch`/`agent`는 `join_leave`도 |
| **Centrifugo로 publish하는 주체는 relay 하나뿐이고, relay는 outbox만 읽는다** | `momo-relay/src/centrifugo.rs` — `POST /api/publish` |

마지막 줄이 이 결정의 전부다. **오늘 Centrifugo에 무언가를 흘려보내는 유일한 길이 outbox다.** 그래서 "outbox를 쓰지 마라"는 곧 "새 길을 하나 뚫어라"가 된다.

## 결정

**휘발 신호 전용 발행 경로를 서버에 하나 만든다. PG에 쓰지 않고, outbox를 거치지 않고, 서버가 직접 Centrifugo에 publish한다. 클라이언트 publish는 계속 닫아 둔다.**

```
영속:  클라 → REST → PG → outbox → relay → Centrifugo     (기존, 불변)
휘발:  클라 → REST → ─────────────────────→ Centrifugo     (신설, PG 미접촉)
```

### 왜 이 모양인가 (기각한 대안과 함께)

- **기각 A — outbox 경유.** 위 계산대로 척추가 쓰레기로 찬다. 그리고 outbox는 **재시도·순서·내구성**을 보장하는 장치인데, 휘발 신호는 셋 다 필요 없다. 필요 없는 보장에 값을 치르는 것이자, 그 값을 진짜 메시지가 대신 낸다.
- **기각 B — 클라이언트 직접 publish.** Centrifugo 네임스페이스에 publish 권한을 열면 된다. **열지 않는다.** 지금 "클라는 절대 publish 못 한다"가 **설정 한 줄로 강제**되고 있고, 그건 감사하기 쉬운 성질이다. 이걸 "휘발 네임스페이스에서만"으로 바꾸는 순간 강제가 **정책**으로 내려앉는다. 하드 불변식(단일 쓰기경로)이 방어하는 것은 PG지만, 그 방어를 **설정 수준에서** 유지하는 편이 싸다.
- **채택 C — 서버 경유 직접 publish.** 서버는 여전히 유일한 저자다. PG는 안 건드린다. outbox 의미론도 안 건드린다. 대신 **`emit_outbox()` 말고 두 번째 발행 지점이 생긴다** — 이것이 이 결정의 유일한 실질 비용이고, 아래 가드로 막는다.

### 가드 (이 결정이 새는 것을 막는 것)

1. **휘발 채널은 네임스페이스로 분리한다.** 영속 채널(`ch`·`dm`)에 섞지 않는다. 구독자가 둘을 **채널 이름만으로** 구분할 수 있어야 하고, 휘발 네임스페이스는 **`history_size: 0`**(재접속 시 과거 작성 중이 되살아나면 유령이 된다).
2. **휘발 발행 함수는 페이로드 타입으로 봉인한다.** 아무 값이나 받는 범용 publish를 만들지 마라. 허용된 휘발 신호 enum만 받는다. 새 신호를 늘리는 건 그 enum을 늘리는 일이고, 리뷰에 걸린다.
3. **PG 접근 금지를 테스트로 못박는다.** 휘발 경로 처리 중 **쿼리 0건**을 단언한다. "실수로 한 줄 썼다"가 조용히 통과하면 안 된다.
4. **서버가 상태를 안 들고 있는다.** "지금 누가 작성 중인가"는 클라가 **만료 시간과 함께** 받아 스스로 잊는다. 서버에 타이머·맵을 두면 그게 곧 상태고, 재시작에 살아남지 못하는 상태는 버그가 된다.
5. **속도 제한은 서버에서.** 클라가 얼마나 자주 보내든 채널당·사람당 상한을 서버가 건다.

### 범위 — v0에서 여는 신호는 **하나**

**「작성 중」만.** 「읽는 중」·「접속 중」·「타이핑 정지」는 열지 않는다.
- 이유: 신호 하나로 위 가드 5개가 실제로 서는지 먼저 본다. 통로를 뚫는 결정과 통로에 무엇을 흘릴지는 다른 결정이다.
- **에이전트는 여기 타지 않는다.** 에이전트가 일하는 중이라는 신호는 이미 `agent_run` 상태로 **영속**한다(웹 `agentWorkingSignal`). 에이전트를 "작성 중"으로 흉내 내면 봇 래핑(ADR-0101이 거부한 것)이다. **사람은 작성 중, 에이전트는 작업 중** — 다른 말이어야 한다.

## 불변식 대조

| 불변식 | 판정 |
|---|---|
| Postgres = SoT | **유지** — 휘발 신호는 상태가 아니라 신호다. 서버 재시작하면 사라지는 게 맞다 |
| 단일 쓰기경로 | **유지** — PG 쓰기는 여전히 REST→PG 하나뿐. 휘발 경로는 아무것도 쓰지 않는다 |
| Centrifugo = 전송전용 | **유지** — 전송만 한다. 다만 **발신자가 relay 하나에서 둘(relay + 서버)로 는다** ← 이 결정의 비용 |
| gapless `message.seq` | **유지** — 휘발 신호는 seq를 소비하지 않는다 |
| 에이전트 = member | **유지** — 범위에서 에이전트를 뺐다 |
| RLS FORCE | **주의** — PG를 안 거치므로 RLS가 격리를 강제해 주지 않는다. **채널 구독 권한 검사를 발행 시점에 직접 해야 한다.** 이게 가드 중 가장 깨지기 쉬운 자리다 |

**마지막 줄이 이 ADR에서 가장 중요한 문장이다.** 지금까지 격리는 "PG를 거치니까 RLS가 잡아준다"로 공짜였다. 휘발 경로는 그 공짜를 잃는다.

## 되돌리기

라우트를 끄고 네임스페이스를 지우면 끝. 데이터가 없으므로 잔여물도 없다. **한 방향 문이 아니다.**
