## 배경

### 지금 있는 것 [V]
- 데스크탑 앱 프로세스가 PTY를 연다(ADR-0190 D1). `pty.rs`(2,538줄)가 PTY 열기, 하네스 허용목록, 계정 변수 빼기(`STRIPPED_ENV`), 폴더 검사, 출력 흐름 제어(`pty_ack`)를 맡는다. `pane_signal.rs`(576줄)는 훅 신호를 받는다. 0700 폴더의 Unix 소켓이고 같은 uid만 받으며, 칸마다 무작위 토큰이 있어 칸 3의 프로그램이 칸 5의 상태를 바꾸지 못한다.
- 앱이 끝나면 모든 칸이 끝난다(`lib.rs`의 `RunEvent::Exit` → `kill_all`). 웹뷰의 headless 미러가 스크롤백을 이 기기 localStorage에 둬서 다시 열면 전의 화면을 보이지만, 프로그램은 새로 뜬다.
- workd(A 레인)는 앱의 자식이라 앱과 함께 꺼진다(ADR-0188 D2). 앱과 workd는 0700 폴더의 Unix 소켓 하나로만 말한다. workd는 접속마다 울타리 셋(폴더·같은 uid·상대의 코드 서명)을 확인하고, 앱은 반대로 소켓 상대가 자기가 띄운 자식 pid인지 확인한다(`momo-workd`의 `control_socket.rs`, 데스크탑 `work_host.rs`).
- OSC 7501 상태 보고는 오늘 허용 출처가 됐고 읽는 곳은 전용 모듈 하나다(ADR-0190 증보 2026-11-09). 구현 #5579가 진행 중이다. 이것이 칸 코어 0단계다.

### herdr-core에서 확인한 것 (v0.1.19, 읽기만 했다)
- 앱이 꺼져도 칸을 붙드는 서버(hc)와 holder가 있다. 다시 붙으면 지금 화면·기록·상태를 준다. 상태는 OSC 7501 보고만 쓰고 화면 글자로 짐작하지 않는다. 이벤트 구독은 첫 스냅숏 + 하나씩 오르는 순번이고, 15초마다 심장 박동, 뒤처지면 놓침 + 새 스냅숏이다([API 문서](https://github.com/herdrdev/herdr-core/blob/v0.1.19/schema/README.md)).
- **모든 칸의 환경에 hc 소켓 주소를 넣는다**([`api/run.rs`](https://github.com/herdrdev/herdr-core/blob/v0.1.19/crates/herdr-core/src/api/run.rs#L218-L219)). 보안 문서는 「There is no separate API password or per-client permission check.」라고 적는다([security](https://github.com/herdrdev/herdr-core/blob/v0.1.19/docs/security.md)). 그래서 한 칸의 프로그램이 다른 칸의 화면을 읽고, 입력하고, 서버를 끌 수 있다. 지금 oort의 칸별 토큰보다 후퇴다.
- 빌드에 Zig 0.16과 Ghostty 서브모듈이 필요하고 `rust-version` 선언이 없다. 공개 뒤 15일에 10판이 나왔고 기본 동작이 자주 바뀐다. 라이선스는 Apache-2.0이다([저장소](https://github.com/herdrdev/herdr-core)).
- 원격 컴퓨터(`machine.*`)·파일(`file.*`)·화면 읽기(`read`)·입력(`send`·`keys`)·문서 저장(`doc.*`) 명령이 있다.

## 업계는 (ADR-0100 비교 참조)
- **herdr-core**: 보는 창과 PTY 주인을 나눠서 앱을 꺼도 칸이 산다. 대신 칸끼리 서로 믿는 구조다(위).
- **tmux**: 소켓은 기본으로 주인만 접근한다. 읽기 전용 손님의 경계는 `attach -r`이 아니라 서버의 접근 목록(`server-access -r`)이다([설명서](https://man.openbsd.org/tmux.1)).
- **OSC 7501**(Program Status Protocol 0.4): 프로그램이 터미널에 자기 상태를 알리는 공개 규격이다([kitty 문서](https://github.com/kovidgoyal/kitty/blob/master/docs/misc-protocol.rst)). Codex TUI와 Claude Code(2.1.295부터)가 낸다.
- oort가 다른 점: PTY 주인의 소켓을 칸에게 주지 않는다. 원격·화면 읽기·입력 명령을 두지 않는다. 같은 공개 규격을 쓰고 herdr-core에서는 생각만 빌린다.

## 선택지와 기각 사유

| 선택지 | 판단 |
|---|---|
| A. herdr-core를 crate로 의존 | 기각. workd는 PTY를 열 수 없고(ADR-0190 D1·ADR-0188 D6), 앱 안에서 돌리면 앱과 함께 죽어 결국 B가 된다. 판을 올릴 때마다 컴파일이 깨질 수 있고, 데스크탑 MSRV(1.89)를 올리고 CI·배포에 Zig를 더해야 한다 |
| B. 판을 고정한 hc 바이너리를 옆에 띄우기 | 기각. 모든 칸이 hc 소켓을 받아 칸끼리 화면을 읽고, 입력하고, 서버를 끌 수 있다. oort 쪽에서 막을 길이 없다. 기본 동작이 판마다 바뀌고, macOS에서 「Herdr Core」 이름으로 권한 창이 뜬다 |
| C. herdr-core를 포크하거나 옮겨 오기 | 기각. 65파일 870KB를 15일 10판 속도로 따라가야 해서 버전 따라가기를 포기하는 셈이다 |
| D. 지금 PTY에서 OSC 7501만 받기 | 이미 한다(0단계). 앱을 꺼도 칸이 사는 것은 얻지 못한다 |
| **E. 지금 데스크탑 코드를 우리 crate로 떼고 칸 지기를 둔다** | **채택.** 칸별 토큰 경계를 지키고 판 따라가기는 생각만 빌리는 일로 가벼워진다. 품은 5~7주로 본다(hc 붙이기의 3~4.5주보다 길다) |

## 결정

### D1. 칸 코어 라이브러리 `momo-orbit`와 칸 지기 — PTY 주인을 앱이 띄운 칸 지기로 바꾼다 (ADR-0190 D1 증보)
- 데스크탑 터미널 코드를 Rust crate `momo-orbit`(가칭)로 뗀다. 들어가는 것은 PTY 열기, 하네스 허용목록과 경로 찾기, 계정 변수 빼기(ADR-0191 D2), 폴더 검사, 화면 모델, 상태 기계(OSC 7501 + 훅), 이벤트 순번(D5), 출력 흐름 제어, 프로토콜 타입이다. 처음에는 지금 `pty.rs`·`pane_signal.rs`의 동작을 그대로 옮긴다.
- 화면 모델은 permissive 후보(`alacritty_terminal` Apache-2.0, `vt100` MIT)를 시험으로 고르고 NOTICE에 귀속을 반영한다.
- **칸 지기**는 crate를 감싼 작은 실행 파일이다. 이름은 `momo-` 접두로 구현이 정한다(가칭 `momo-orbit-holder`). 앱 번들 안 helper로 같은 팀이 서명하고, 앱이 첫 칸을 열 때 띄운다. 칸 지기는 앱보다 오래 산다.
- **PTY를 여는 것은 칸 지기뿐이다.** 여는 요청은 앱(웹뷰 → 앱 → 칸 지기)에서만 온다. ADR-0190 D1의 「서버 이벤트·딥링크·workd는 PTY를 열 수 없다」는 이제 칸 지기의 제어 소켓이 지킨다(D3). `shell_contract.rs`의 소스 시험은 crate와 칸 지기로 옮겨 같은 단정을 한다.
- 칸 지기가 붙드는 것은 사람이 연 터미널 칸(L 칸)뿐이다. 앱이 스스로 돌리는 짧은 명령(ADR-0190 D3-a 상태 확인·D3-c git 읽기·D3-e 앱 명령·D3-f 로그인)은 지금처럼 앱 프로세스에 남고 앱과 함께 끝난다.
- 화면 모델과 스크롤백은 칸 지기의 메모리에 있고 이 기기 밖으로 나가지 않는다(ADR-0190 D2). 디스크에 둘지는 미결 1이다.
- workd(A 레인)는 이 ADR 밖이다. 앱을 끄면 workd는 지금처럼 꺼진다(ADR-0188 D2).
- 앱은 「칸 호스트」 경계 하나로만 칸 지기와 말한다. 그래서 칸 지기를 다른 구현으로 바꿔 끼울 수 있다(D6).
- 지키는 경계: PTY로 가는 입구는 서명된 앱 하나다. 화면 글자는 기기 밖으로 나가지 않는다.

### D2. 앱을 꺼도 칸이 산다 — 기본 켬, 「앱 밖에서 도는 중」 표시, 끌 때 한 번 묻기
- 설정 「앱을 꺼도 터미널 유지」는 **기본 켬**이다. 끄면 앱이 끝날 때 모든 칸이 끝난다(지금과 같다).
- 앱을 끌 때 도는 칸이 있으면 **한 번 묻는다.** 고를 것은 계속 두기와 모두 끝내기이고 기본은 계속 두기다. 업데이트도 앱을 끄는 일이라 같이 묻는다. 문구는 디자인 검수가 정한다.
- 칸 목록에 **「앱 밖에서 도는 중」**을 표시한다. 앱을 꺼도 계속 도는 칸이라는 뜻이다. 앱을 다시 켜면 칸 지기에 다시 붙고, 그동안 돈 칸이 이 표시와 함께 목록에 돌아온다.
- 앱이 꺼진 동안 공유 요약(S1)은 갱신되지 않는다. 칸 지기는 서버와 말하지 않는다. 공유 카드는 마지막 업데이트 시각만 말하고 「진행 중」을 이어 주장하지 않는다(ADR-0220 P1).
- 칸이 하나도 없고 앱이 붙어 있지 않으면 칸 지기는 스스로 끝난다. 로그아웃하거나 컴퓨터를 끄면 칸과 함께 끝난다.
- 지키는 경계: 사람이 모르는 채 도는 프로세스가 되지 않는다(표시·묻기·설정 셋이 함께 간다).

### D3. 제어 소켓은 앱만 쓴다. 칸에는 자기 칸 신호 토큰만 준다
- **제어 소켓**은 workd 제어 소켓과 같은 울타리 셋을 쓴다. ① 이 사용자 전용 0700 폴더와 0600 소켓 ② `getpeereid`로 같은 사용자 ③ 상대의 코드 서명: audit token(`LOCAL_PEERTOKEN`)으로 찾은 상대 코드가 oort 앱의 identifier여야 하고, 그 팀이 칸 지기 자신의 서명에 적힌 팀과 같아야 한다. 서명 없는 개발 빌드만 깃발로 ③을 건너뛰고, 서명된 칸 지기는 그 깃발을 거부한다.
- 같은 사용자의 프로그램은 폴더와 소켓 경로를 찾을 수 있다. 그래서 「앱만 쓴다」는 경로를 숨겨서가 아니라 ③으로 지킨다.
- **반대 방향도 확인한다.** 처음 띄운 직후 앱은 소켓 상대가 자기 자식 pid인지 본다(`work_host.rs`와 같다). 앱이 다시 켜진 뒤에는 칸 지기가 이 앱의 자식이 아니므로 pid로는 알 수 없다. 그때는 상대의 코드 서명(칸 지기 identifier와 같은 팀)으로 확인한다. 확인되지 않는 소켓에는 붙지 않고 키 입력을 보내지 않는다. 같은 사용자의 가짜 소켓이 키 입력(비밀번호 포함)을 가로채는 길을 막는다.
- **칸의 환경에는 제어 소켓 주소와 토큰을 넣지 않는다.** 칸에는 그 칸의 신호 토큰·칸 ID·신호 소켓 주소만 준다(지금 `pane_signal.rs`). 신호 소켓은 제어 소켓과 다른 소켓이고, 그 칸의 토큰이 맞는 닫힌 신호 한 줄만 받는다. 칸 3의 프로그램은 칸 5의 화면을 읽지도, 입력하지도, 칸 지기를 끄지도 못한다.
- 앱 바이너리의 보조 모드(훅 클라이언트 `--oort-pane-hook`)는 신호 소켓에만 붙고 제어 소켓에는 붙지 않는다. 앱 바이너리에는 호출한 쪽이 고른 제어 명령을 대신 보내는 모드가 없다. 소스 시험으로 단정한다.
- 지키는 경계: 칸끼리 서로 건드리지 못한다. herdr-core가 모든 칸에 서버 소켓을 주는 것과 다른 점이 이것이다.

### D4. 원격 입력·에이전트 입력·바깥 통신은 없다
- 칸에 입력하는 것은 앱 창 앞에 앉은 사람의 키 입력뿐이다(ADR-0190 D2). 서버·폰·다른 컴퓨터·에이전트(Agent Port 도구, workd, 칸 안의 다른 프로그램)가 칸에 입력하는 길은 없다. 입력 명령은 서명을 확인한 앱 연결에만 있다.
- 화면 글자를 읽어 내보내는 명령은 없다(ADR-0190 D4-b 「긁지 않는다」).
- **칸 지기는 바깥과 통신하지 않는다.** 서버·다른 컴퓨터·업데이트 서버에 연결하지 않고 TCP를 열지 않는다. 원격 컴퓨터·파일 명령은 없다(ADR-0188 D6). 공유 요약은 지금처럼 앱이 올린다(ADR-0190 D4, ADR-0222 D9). 칸 지기 코드에 네트워크 연결이 없다는 것을 소스 시험으로 단정한다.
- 지키는 경계: 원격 셸 금지. 화면 글자는 기기 밖으로 나가지 않는다. 에이전트는 터미널을 조작하지 않는다.

### D5. 이벤트에는 순번·심장 박동·놓침 스냅숏을 둔다
- 앱이 붙으면 칸 지기는 먼저 스냅숏(칸 목록, 칸마다 상태·크기·제목·첫 화면)을 보내고, 이어서 순번이 하나씩 오르는 이벤트를 보낸다.
- 이벤트가 없어도 심장 박동을 보낸다(**[추정]** 15초). 앱은 박동이 끊기면 다시 붙는다. 칸 지기는 앱이 떨어져도 칸을 끝내지 않는다.
- 앱이 뒤처지거나 순번이 비면 칸 지기가 「놓침」과 새 스냅숏을 보낸다. 앱은 잃은 이벤트를 찾지 않고 스냅숏으로 다시 맞춘다.
- 칸 상태는 OSC 7501과 훅을 합친 한 상태 기계에서 나오고 「에이전트 보고」로 표시한다. 서버가 확인한 사실과 섞지 않는다(ADR-0220 P1, ADR-0190 증보 2026-11-09). ADR-0222 R2의 시계 둘은 이 이벤트의 시각으로 센다.
- 지키는 경계: 상태는 프로그램이 알린 값만 쓴다. 신호가 없으면 상태를 짐작하지 않는다(ADR-0222 D12).

### D6. herdr-core는 쓰지 않는다 — 칸별 인증이 생기면 다시 본다 (ADR-0154 D5-⑵ 갱신)
- herdr-core를 crate·바이너리·포크 어느 모양으로도 쓰지 않는다. 코드는 가져오지 않는다(클린룸). 같은 공개 규격(OSC 7501)을 쓰고, 공개 문서에서 생각만 빌린다(다시 붙을 때의 첫 화면, 흐름 제어, 순번과 놓침, 터미널 질의에 대한 자동 응답과 사람 입력의 구분).
- herdr-core 새 판의 바뀐 기록은 승격 주기마다 한 번 훑는다. 칸별 인증(칸마다 다른 권한)이 들어오면 칸 지기 자리에 hc를 꽂는 시험을 다시 연다. 앱이 「칸 호스트」 경계 하나로만 말하므로(D1) 그때 바꿔 끼울 수 있다.
- ADR-0154 D5-⑵(「herdr = 워커 호스트 런타임 실험, 실행만, 버전 핀」)는 「oort 칸 코어(궤도)」로 갱신한다.

## 프로세스 계약 스케치

숫자는 **[추정]**이고 구현이 확정한다.

### 수명
- **시작**: 앱이 칸을 열 때 칸 지기가 없으면 띄운다. 칸 지기는 로그인한 사용자마다 하나다. 둘째가 뜨면 소켓 폴더의 잠금으로 알아채고 스스로 끝난다.
- **붙기**: 앱은 시작할 때 소켓 폴더에서 칸 지기를 찾고, 서명을 확인한 뒤 붙는다(D3). 인사에서 프로토콜 판을 맞추고 스냅숏을 받는다(D5).
- **떼기**: 앱이 끝나면 연결이 닫힌다. 설정이 켬이고 사람이 계속 두기를 고르면 칸 지기는 칸을 붙든 채 남는다. 설정이 끔이거나 모두 끝내기를 고르면 앱이 끝나기 전에 모두 끝내기를 보내고, 칸 지기는 칸을 끝낸 뒤 스스로 끝난다.
- **끝**: 칸이 없고 앱이 붙어 있지 않으면 **[추정]** 60초 뒤 스스로 끝난다. 칸을 끝내는 순서는 지금 `kill_all`과 같다(프로세스 그룹에 SIGHUP, 짧게 기다린 뒤 남은 것에 SIGKILL).

### 소켓과 칸별 토큰
- 제어 소켓은 연결 하나에 요청과 이벤트가 흐른다. 줄마다 크기 상한이 있고 모르는 필드는 거절한다. TCP는 루프백도 없다.
- 칸을 열 때마다 무작위 토큰을 만든다. 칸 환경에는 그 칸의 토큰·칸 ID·신호 소켓 주소만 넣고, 계정 변수는 뺀다(ADR-0191 D2). 칸이 끝나면 토큰을 버리므로 끝난 칸의 늦은 신호는 아무 데도 가지 않는다.

### 이벤트
- 순번은 칸 지기 안에서 하나씩 오른다. 칸 지기가 새로 뜨면 세대 번호가 바뀌고, 앱은 세대가 다른 순번을 섞지 않는다.
- 이벤트 종류는 닫힌 목록이다: 생김 · 끝남(끝난 이유: 프로그램이 끝남·사람이 끝냄·칸 지기가 끝남) · 상태 · 제목 · 크기.
- 출력은 지금 `pty_ack` 방식의 흐름 제어를 그대로 쓴다.

### 업데이트 넘김
- 칸 지기는 앱 번들 안에 있고 스스로 갱신하지 않는다. 앱이 업데이트돼도 도는 칸 지기는 옛 판으로 남아 칸을 붙든다.
- 새 앱은 인사에서 판을 맞춘다. 새 앱은 지금 판과 직전 판(**[추정]** 한 판 뒤까지)의 칸 지기와 말한다.
- 판이 달라도 바뀌지 않는 최소 명령을 둔다: 칸 목록 · 칸 끝내기 · 칸 지기 끝내기. 맞지 않는 판이면 앱은 칸을 「업데이트 전 터미널」로 보이고 최소 명령만 쓴다.
- 마지막 칸이 끝나면 옛 칸 지기도 끝나고, 다음 칸은 새 판 칸 지기로 뜬다.
- [확인 필요] 업데이트가 번들을 새 파일로 바꿔 끼우는지(같은 파일을 덮어쓰면 도는 칸 지기가 코드 서명 검사로 죽을 수 있다)와 새 앱이 옛 판 칸 지기의 서명을 확인할 수 있는지는 궤도-2의 첫 확인이다. 둘 중 하나라도 안 되면 업데이트 전에 「터미널이 끝나요」로 묻는다. 칸이 말없이 사라지는 일은 없게 한다.

### 결코 범위에 들지 않는 것
원격 컴퓨터와 원격 셸(`machine.*`) · 파일 읽기·쓰기 명령(`file.*`) · 화면 글자를 읽어 내보내는 명령(`read`) · 에이전트·서버·폰·다른 칸의 입력(`send`·`keys`·`wait`) · 문서 저장(`doc.*`) · TCP와 바깥 통신 · 스스로 갱신 · 칸끼리 서로 보기 · A 레인 세션(workd) · 칸 배치(탭과 분할은 웹이 그린다).

## 위협과 방어
- **칸끼리 조작**: 칸 환경에 제어 소켓이 없고, 신호 소켓은 그 칸의 토큰이 맞는 닫힌 신호만 받는다(D3).
- **같은 사용자 프로그램의 제어 소켓 접속**: 경로는 찾을 수 있어도 코드 서명 울타리를 넘지 못한다. 앱 바이너리의 보조 모드는 제어 소켓에 붙지 않는다(D3).
- **소켓 자리 가로채기**: 앱이 칸 지기의 서명을 확인하기 전에는 키 입력을 보내지 않는다(D3).
- **메모리에서 화면 읽기**: 칸 지기는 강화 런타임으로 서명하고 `get-task-allow`를 주지 않는다. [확인 필요] 서명·공증 단계에서 칸 지기 helper에도 강화 런타임이 걸리는지 빌드로 확인한다.
- **칸 지기 끄기(남는 위험)**: 같은 사용자의 프로그램이 OS 신호로 칸 지기를 끝내는 것은 막지 못한다. 그러면 칸이 끝나고, 앱은 칸이 끝났다는 사실만 보인다. 화면을 읽거나 입력하는 길은 아니다.
- **모르는 채 남는 프로세스**: 기본 켬이어도 끌 때 묻고, 칸 목록에 표시하고, 설정으로 끈다(D2).

## 결과
- (+) 앱을 껐다 켜거나 업데이트해도 Claude Code·Codex 세션과 화면이 그대로다.
- (+) 칸별 토큰 경계를 지키고, herdr-core의 가장 큰 위험(칸끼리 조작)을 들이지 않는다.
- (+) 상태 기계와 이벤트 순번이 crate 하나에 모여, 화면은 한 곳의 낱말을 쓴다.
- (−) 우리 코드라 품이 크다(5~7주). herdr-core의 새 기능은 생각만 빌려 다시 만들어야 한다.
- (−) 앱 밖에서 도는 프로세스가 하나 는다. 표시·묻기·설정을 함께 지켜야 한다.
- (−) 같은 사용자의 프로그램이 칸 지기를 OS 신호로 끄는 것은 막지 못한다.
- (−) 업데이트 뒤 옛 판 칸 지기와 새 앱이 함께 도는 기간이 생겨서 프로토콜 판을 둘 맞춰야 한다.

## 미결
1. **칸 지기의 화면을 디스크에 둘지.** 지금 결정은 메모리뿐이라 칸 지기가 끝나면 화면도 끝난다. 디스크에 두려면 0700 폴더, 보존 기한, 비밀 경고가 함께 필요하다.
2. **컴퓨터를 다시 켠 뒤 칸 되살리기(셸로).** 이번에 정하지 않았다. 칸 코어 메모의 추천은 「되살려도 원래 명령은 다시 돌리지 않는다」다.
3. **끌 때 묻는 창에 「다시 묻지 않기」를 둘지.** 디자인 검수가 정한다.
