## 배경 [V]

- 채널 이름 규칙은 서버의 `normalize_channel_name` 하나가 정해요. 가장자리 빈칸을 지우고 소문자로 바꾼 뒤 `^[a-z0-9][a-z0-9_-]*[a-z0-9]$|^[a-z0-9]$`인지 손으로 검사해요(`server-rust/crates/momo-messaging/src/channel.rs:281-302`). 시험이 「도그푸딩」과 `a b`를 거절하는 것을 못 박고 있어요(같은 파일 `:924-932`).
- 같은 규칙을 베낀 곳이 둘 있어요. 공유 코어의 정규식(`packages/momo-core/src/features/channels/model.ts:22,25`)과 API 문서의 `pattern`(`docs/api/openapi.yaml:23197`)이에요. 웹·데스크탑·폰은 코어 함수를 불러요.
- DB는 글자를 막지 않아요. `channel.name`은 `text`이고, 유일 인덱스가 `(workspace_id, lower(name))`로 보관되지 않은 채널끼리의 중복만 봐요(`schema_v0.sql:97,110-113`).
- **채널 이름을 바꾸는 길이 서버에 없어요.** 코어가 「라우트가 없어 메뉴에 넣지 않았다」고 적어 두었어요(`model.ts:89-91`).
- 다국어 1차는 한·영·일·중(간체·번체)·스·프 7개 언어예요(ADR-0213). 한글만 푸는 규칙으로는 모자라요.

## 결정

### D1. 쓸 수 있는 글자

이 규칙은 **공개·비공개 채널의 이름**에만 걸려요. 그룹 DM의 방 이름은 같은 `channel.name` 칸에 들어가지만 규칙이 달라요(빈칸 허용, 1~60자 — [ADR-0221](0221-group-dm.md) D3). 그쪽은 건드리지 않아요.

정규화(D3)를 마친 이름의 글자 하나하나가 아래 넷 중 하나여야 해요. 유니코드 일반 범주(General_Category)로 정해요.

| 받는 것 | 범주 | 예 |
|---|---|---|
| 글자 | `L*` (Lu·Ll·Lt·Lm·Lo) | 한글, 가나, 한자, 라틴(악센트 포함), 긴소리 `ー`, `々` |
| 숫자 | `N*` (Nd·Nl·No) | `0-9`, 다른 문자의 숫자, `〇`, `①` |
| 결합 표시 | `M*` (Mn·Mc·Me) — **글자·숫자·다른 결합 표시 바로 뒤에서만** | 태국어·힌디어의 모음 부호, `i` 뒤의 U+0307 |
| 구분자 | `-`(U+002D) · `_`(U+005F) | |

**받지 않는 것**: 이모지와 기호(`S*`), 문장부호(`P*` — `.` `!` `#` `@` `[` `]` `・` `·` `'` 포함), 빈칸(D2에서 `-`로 바뀌거나 지워져요), 제어·방향 제어·보이지 않는 글자(D4).

자리 규칙은 지금 것을 그대로 넓혀요.
- 첫 글자는 글자나 숫자예요(`-`·`_`·결합 표시로 시작할 수 없어요).
- 끝 글자는 `-`·`_`가 아니에요.
- `-`·`_`가 잇달아 오는 것(`a--b`)은 지금처럼 돼요. 지금 되는 이름을 하나도 막지 않기 위해서예요.

### D2. 빈칸

빈칸으로 치는 글자는 유니코드 `White_Space` 속성의 25자예요: U+0009~U+000D(탭·줄바꿈 등), U+0020(빈칸), U+0085, U+00A0(줄 안 바뀌는 빈칸), U+1680, U+2000~U+200A, U+2028·U+2029(줄·문단 구분자), U+202F, U+205F, U+3000(전각 빈칸). Rust `char::is_whitespace`와 같은 집합이에요. 지금 서버의 `trim()`이 가장자리에서 지우는 글자와 같아서, 지금 받는 입력이 새 규칙에서 거절되지 않아요. 코어는 JS의 `\s`가 아니라 이 목록을 그대로 써요(`\s`는 U+FEFF를 넣고 U+0085를 빼요).
- 가장자리의 빈칸은 지워요.
- 가운데의 빈칸 묶음은 `-` 하나로 바꿔요. 바로 옆에 이미 `-`나 `_`가 있으면 빈칸만 지워요(`a - b` → `a-b`).
- **서버도 이렇게 해요.** 화면만 고쳐 주면 에이전트나 CLI가 「디자인 리뷰」를 보냈을 때 거절돼요. 서버는 지금도 대소문자와 가장자리 빈칸을 고쳐 저장하고, 응답에 저장된 이름을 돌려줘요. oort는 채널을 이름으로 가리키는 에이전트가 주된 API 손님이라 같은 함수가 양쪽을 다 고쳐 주는 쪽이 어긋남이 적어요.

### D3. 정규화 차례

서버가 권위예요. 차례는 아래 여섯 걸음이고, 저장되는 값은 이 결과예요.

1. **NFC**로 합쳐요. 맥에서 온 풀어쓴 한글(U+1112 U+1161 U+11AB)이 `한`이 돼요.
2. **전각 → 반각.** U+FF01~U+FF5E(전각 영숫자·기호)를 U+0021~U+007E로 옮겨요. `ＱＡ` → `QA`, `－` → `-`.
3. **빈칸 처리**(D2).
4. **소문자**로 바꿔요(유니코드 기본 규칙, 언어를 타지 않음). 지금 규칙 그대로예요.
5. 다시 **NFC**(소문자화가 드물게 풀어 놓는 글자를 다시 합쳐요).
6. 길이(D5) → 보이지 않는 글자(D4) → 글자(D1) → 자리 규칙 차례로 검사해요. 길이를 먼저 말하는 지금 차례를 지켜요.

두 번 돌려도 값이 같아야 해요(시험 벡터가 확인해요).

**NFKC를 쓰지 않는 까닭**: NFKC는 전각 영숫자를 접어 주지만, 한글 낱자 「ㅋ」(U+314B)를 초성 전용 글자(U+110F)로 바꿔 버려요. 그러면 사람이 다시 친 「ㅋㅋㅋ」와 맞지 않아요. 그래서 NFC에 「전각 → 반각」 한 가지만 더해요. 반각 가타카나는 접지 않아요(「막지 않고 적어 두는 것」).

### D4. 보이지 않는 글자는 거절

이름에 아래가 하나라도 있으면 거절해요. 고쳐 주지 않고 거절하는 까닭은, 조용히 지우면 사람이 붙여 넣은 것과 다른 이름이 되기 때문이에요.

- 제어·서식·사용자 정의 글자(범주 `Cc`·`Cf`·`Co`, 그리고 짝 없는 대리 `Cs`): 폭 없는 빈칸(U+200B), ZWJ·ZWNJ(U+200D·U+200C), 방향 제어(U+202A~U+202E, U+2066~U+2069), BOM(U+FEFF), U+E000 같은 사용자 정의 글자 등. D2의 빈칸(일부는 범주가 `Cc`·`Zl`·`Zp`)은 D3 걸음 3에서 이미 사라져서 여기에 닿지 않아요. 짝 없는 대리는 올바른 UTF-8에는 없지만 JS 문자열에는 생길 수 있어서 코어가 같은 답을 내도록 적어 둬요.
- **글자나 결합 표시로 분류되지만 보이지 않는 것**: 한글 채움 문자(U+115F·U+1160·U+3164·U+FFA0), U+034F, U+17B4·U+17B5, U+180B~U+180D·U+180F, 변형 선택자(U+FE00~U+FE0F, U+E0100~U+E01EF). 「글자면 받는다」만으로는 U+3164 하나짜리 **빈 이름처럼 보이는 채널**이 만들어져요(U+3164의 범주는 `Lo`예요).

서버에는 비슷한 목록이 이미 있어요(`server-rust/crates/momo-messaging/src/name_guard.rs:144-146,493-510`). 그 목록은 손으로 쓴 것이라 `Cf` 몇 곳(U+0600~U+0605 등)을 빠뜨리고, 이모지 때문에 U+FE00~U+FE0F를 일부러 뺐어요(`:503`). 그래서 채널 이름은 그 목록을 그대로 쓰지 않고 **범주로** 거른 뒤(`Cc`·`Cf`·`Co`·`Cs`), 범주가 글자·결합 표시인 보이지 않는 것만 위 목록으로 더해요.

### D5. 길이

- **정규화한 뒤의 글자 수(코드포인트) 1~80.** 바이트가 아니에요. 한글 80자는 240바이트예요. DB 칸은 길이 제한 없는 `text`라 그대로 둬요.
- 공유 코어는 지금 `name.length`(UTF-16 단위)로 세요(`model.ts:49`). 서버는 `chars().count()`(코드포인트)예요(`channel.rs:283`). 코어를 코드포인트로 맞춰요. BMP 밖 글자(드문 한자 등)에서만 차이가 나요.
- **에이전트 쪽 바이트 상한을 같이 올려요.** 에이전트 행동과 MCP 도구는 글자가 아니라 UTF-8 바이트로 상한을 재요(`server-rust/crates/momo-mcp/src/tools.rs:267`, 재는 곳 `:2091-2100`). 이름 상한이 80바이트(`server-rust/crates/momo-agent/src/actions.rs:1111-1113`, `tools.rs:807`)이고 채널 참조 상한이 81바이트(`server-rust/crates/momo-agent/src/actions.rs:1553-1554`, `tools.rs:809`)예요. 그대로 두면 한글 27자부터 걸려요. 같은 파일들의 전례(글자당 4바이트 — 주제 280자 = `1_120`바이트 `server-rust/crates/momo-agent/src/actions.rs:1114-1116`, `tools.rs:657-658`)대로 **320·321바이트**로 올려요. 80자 검사는 정규화 함수가 계속 해요.

### D6. 같은 이름 판정

- 저장되는 값이 곧 정규화한 값이에요. 그래서 지금의 유일 인덱스 `lower(name)`이 그대로 중복을 잡아요. **migration은 없어요.** `schema_v0.sql`도 건드리지 않아요.
- 이름으로 채널을 찾는 곳은 전부 **같은 함수로 접은 값**으로 찾아요. 지금 두 곳이 어긋나 있어요.
  - 에이전트 행동은 이미 같은 함수를 써요(`server-rust/crates/momo-workspace-actions/src/action_resolve.rs:740,799,1303` → `:2383`).
  - 팀 AI 도구의 `resolve_channel`은 가장자리를 다듬고 앞의 `#`을 떼고 SQL `lower()`로 견줘요(`server-rust/crates/momo-workspace-actions/src/team_ai_tools.rs:536-556`, 쿼리 `:547-548`). NFC·빈칸 접기가 없어서 풀어쓴 한글이나 빈칸 든 이름이 오면 못 찾아요. 같은 함수로 접은 값을 견주게 고쳐요. 이 쿼리에는 채널 종류 조건이 없고, 보관된 채널은 뒤로만 밀어요(`:548`). 그룹 DM 방 이름이 같은 칸에 들어오므로(ADR-0221) `kind IN ('public','private')`를 같이 넣고, 보관 채널은 에이전트 행동 쪽(`action_resolve.rs:2383-2388`)과 같은 조건으로 맞춰요.
- DB의 `lower()`가 한글 밖의 글자를 어떻게 다루는지는 DB 로캘에 달려 있어요. 서버가 이미 소문자로 바꾼 값만 넣고 찾으므로 로캘에 기대지 않아요. 운영 DB의 로캘은 확인하지 못했어요(이미지는 `pgvector/pgvector:0.8.7-pg18-trixie`, `infra/railway/railway.json:30`).
- DB에 「NFC여야 한다」는 CHECK를 더하지 않아요. 공개·비공개 채널 줄을 넣는 곳은 둘뿐이에요: 만들기(이 함수를 지나요, `channel.rs:139-148`)와 워크스페이스를 만들 때의 `general`(글자 그대로, `server-rust/crates/momo-settings/src/workspace.rs:223-224`). DM은 이름이 NULL이에요(`server-rust/crates/momo-messaging/src/dm.rs:219-220`). D10의 이름 바꾸기도 이 함수를 지나요.

### D7. 닮은 글자 속이기 — 에이전트가 제안한 이름만 막아요 (owner N-2)

- **사람이 만드는 길은 막지 않아요.** 채널은 소유자·관리자만 만들어요(ADR-0128). 그 사람들은 채널을 속여 만들 까닭이 적어요. 그리고 「문자 체계를 섞지 못하게」 하면 `qa-피드백`, `design-リビュー`처럼 한·일·중 팀이 흔히 쓰는 이름이 걸려요.
- **에이전트가 제안한 이름은 검사해요.** `channel.create` 제안은 승인 카드에 이름이 뜨고 사람이 그걸 보고 눌러요. 에이전트가 `g\u0435neral`(라틴 글자 사이에 키릴 U+0435)을 제안하면 눈으로는 못 가려요.
- 검사 방법: 새 이름과 그 워크스페이스의 보관되지 않은 공개·비공개 채널 이름들을 「키릴·그리스 닮은꼴 → 라틴」으로 접어 견줘요. 같으면 「이미 있는 채널과 헷갈리는 이름」으로 거절해요. 제안 때와 결정 때 두 번 해요(ADR-0186 V1-d의 재증명과 같아요).
- **지금 있는 `skeleton` 함수를 그대로 쓰면 안 돼요.** 그 함수는 `-`·`_`를 지우고 `0`→`o`, `1`·`i`→`l`로 접어요(`name_guard.rs:354-377`). 사람 이름에는 맞지만 채널에는 `team-1`과 `team-l`, `dev_ops`와 `devops`가 같은 이름이 돼요. 닮은꼴 표(`confusable`)만 빌려 쓰는 새 함수를 둬요.
- 이 검사는 에이전트 길에만 걸려요. 사람의 만들기(REST)와 D10의 이름 바꾸기(사람 전용)는 D3·D4만 지나요. 그것만으로도 「눈에 같은데 다른 이름」의 흔한 경우(풀어쓴 한글, 전각 영문, 폭 없는 빈칸)는 사라져요.

### D8. 본문 속 `#채널`

지금 사실부터 적어요.
- **본문에서 `#이름`을 읽어 내는 파서가 없어요.** 웹 작성창은 `#`을 치면 내가 든 채널을 이름 부분 일치로 보여 주고(`clients/web/src/features/chat/composerAutocomplete.ts:104-110,380-396`), 고르면 `#이름 ` **평문**을 넣어요. id를 박지 않고, 보낸 글의 `#이름`은 링크로 그려지지 않아요(같은 파일 `:426-451`이 그렇게 정한 까닭을 적어 둠). 폰 작성창에는 `#` 자동 완성이 없어요(`clients/mobile/src/features/conversation/mentionQuery.ts:35-37`).
- 자동 완성이 질의를 끊는 곳은 빈칸이에요(`:205-246`). 글자 종류로 끊지 않아서 한글 이름도 지금 그대로 찾아져요.
- 그래서 「#공지에서」처럼 조사가 붙은 글은 **지금도 앞으로도 그냥 글자**예요. 이 결정으로 깨지는 것이 없어요.

정하는 것:
1. 이 ADR은 본문 속 `#채널`을 링크로 만들지 않아요. 지금처럼 평문이에요.
2. 나중에 링크로 그릴 때는 **자동 완성으로 고른 것만 채널 id 토큰으로 넣고, 손으로 친 `#이름`은 풀지 않아요.** 한글은 이름 뒤에 조사가 띄어쓰기 없이 붙고(「#공지에서」), 조사도 「글자」라서 글자 종류로는 이름의 끝을 알 수 없어요. 채널 목록에서 가장 길게 맞는 이름을 찾는 방법은 `공지`와 `공지에서`라는 채널이 둘 다 있을 때 틀려요.
3. 에이전트가 채널을 가리키는 `#이름`은 **인자 한 칸 전체**예요(문장 속에서 뽑아내지 않아요). 한 칸 전체를 D3로 접어 정확히 같은 이름을 찾아요. 조사 문제가 없어요.
4. 서버가 만드는 문장에서 채널 이름 뒤에 조사를 바로 붙이지 않아요. 지금 결과 줄이 `#{이름}에 멤버 …`예요(`server-rust/crates/momo-agent/src/actions.rs:2587-2589`). 에이전트가 이 줄을 다시 읽으면 「디자인-리뷰에」를 이름으로 볼 수 있어요. `#이름 채널에 …`로 바꿔요. 승인 문장은 이미 「이름 뒤에 조사를 붙이지 않는다」를 시험으로 지키고 있어요(`server-rust/crates/momo-agent/src/approval_sentence.rs:725`).
5. 이름을 바꾸면(D10) 이미 보낸 글 속의 `#옛-이름`은 평문이라 옛 이름으로 남아요.

### D10. 이미 있는 채널과 이름 바꾸기 (owner N-1)

- **지금 되는 이름은 전부 그대로 돼요.** 옛 규칙의 이름은 영문 소문자·숫자·`-`·`_`뿐이라 D3를 거쳐도 값이 안 바뀌고 D1을 통과해요. 시험 벡터에 옛 시험의 이름을 그대로 넣어 지켜요.
- DB가 규칙을 강제한 적이 없으니, 실제 팀 인스턴스의 공개·비공개 채널(`kind <> 'dm'`)에 옛 규칙 밖의 이름이 한 줄도 없는지 **읽기만 하는 쿼리로 한 번 확인**해요(E1). 있으면 그 채널은 id로는 잘 돌지만 이름으로는 못 찾을 수 있어요.
- **이미 있는 채널의 이름 바꾸기를 이번에 같이 넣어요.** 그래서 `qa-feedback` 같은 지금 채널도 한글 이름으로 바꿀 수 있어요.
  - 누가: 워크스페이스 소유자·관리자(채널 만들기와 같은 사람, ADR-0128). 사람 전용이에요(`require_human`, 에이전트 경로 허용목록에 넣지 않음). 에이전트가 이름 바꾸기를 제안하는 행동은 이번에 만들지 않아요. 나중에 만들면 D7이 걸려요.
  - 무엇을: 보관되지 않은 공개·비공개 채널. DM·그룹 DM은 이 길로 바꾸지 않아요(그룹 DM 방 이름은 ADR-0221 규칙).
  - 검사: 만들기와 같은 함수(D1~D5). 보관되지 않은 채널과 이름이 겹치면 409예요(지금 만들기와 같은 유일 인덱스).
  - **`general`은 이번에 잠가요.** 이름이 `general`인 채널은 이름을 바꿀 수 없고(409), 다른 채널의 이름을 `general`로 바꾸는 것도 받지 않아요. 환영 글이 `general`을 이름 그대로 찾기 때문이에요(`server-rust/crates/momo-agent/src/welcome.rs:174`, `:189`, `:231`). 잠금을 푸는 것은 새 결정이에요 — [ADR-0224](0224-public-channel-browse-and-self-join.md)의 엔진 칸이 환영 글을 「기본 채널」 표시로 찾게 바꿔도 잠금은 그대로 남아요.
  - 기록: 감사 기록 `channel.renamed`(누가·어느 채널·옛 이름·새 이름).
  - 다른 기기: 실시간 이벤트는 이 ADR이 정하지 않아요. 다른 기기는 다음 채널 목록 조회에서 새 이름을 받아요. 이미 보낸 글 속의 `#옛-이름`은 그대로예요(D8-5).
  - 라우트: 채널 자체를 고치는 라우트가 지금 없어요. 이 칸(R1)이 `PATCH /v1/workspaces/{ws}/channels/{ch}`를 만들고 `name` 칸을 받아요. [ADR-0224](0224-public-channel-browse-and-self-join.md)의 「둘러보기에 보이기」·「기본 채널」 칸은 같은 라우트에 칸을 더해요. 먼저 착륙하는 칸이 라우트를 만들고, 뒤 칸은 칸을 더해요.
- 앞으로 생기는 이름 바꾸기 길(에이전트 행동, 가져오기 등)도 반드시 이 함수를 지나야 해요.

### D11. 서버와 거울이 어긋나지 않게

- **정본은 시험 벡터 파일 하나예요**: `docs/api/channel-name.vectors.json`. E1이 이 문서 끝의 「시험 벡터」 표를 그대로 옮겨 만들어요. 입력 → `ok`와 저장 값, 또는 거절 까닭(`required`·`tooLong`·`hidden`·`unsupported`·`edge`).
- 이 저장소에 전례가 있어요. `docs/api/*.vectors.json`을 Rust 시험이 `include_str!`로 읽고, 코어의 사본이 **바이트까지 같은지**를 Rust 시험이 지켜요(`server-rust/crates/momo-wire/tests/human_control_v4_vectors.rs:17,135-137`). 같은 틀을 써요.
- 파일은 ASCII만 쓰고 그 밖의 글자는 `\u` 표기로 적어요. 편집기가 풀어쓴 한글 같은 시험 글자를 몰래 합쳐 버리지 않게요(같은 전례).
- 벡터를 읽는 곳 셋: 서버(`momo-messaging`), 공유 코어(웹·데스크탑·폰이 함께 씀), CLI(접기만 — 걸음 1~5).
- **서버가 권위, 거울은 빠른 안내예요.** 거울이 서버와 어긋나 400이 오면 화면은 영어 문장을 그대로 보이지 않고 「서버가 이 이름을 받지 않았어요. 글자, 숫자, -, _만 쓸 수 있어요」를 보여요(지금 문장은 `model.ts:323-330`).
- 서버 구현: 유니코드 범주가 필요한데 Rust 표준 라이브러리에는 없어요(`is_alphabetic()`은 `L*`과 같지 않아요). `unicode-properties` 크레이트(0.1.4, MIT/Apache-2.0, `general-category` 기능)가 이미 `Cargo.lock`에 간접 의존으로 있어요(`server-rust/Cargo.lock:4394`, `stringprep`을 거쳐 `sqlx-postgres`가 씀). 직접 의존으로 올리고 NOTICE를 확인해요. NFC는 이미 쓰는 `unicode-normalization`(`server-rust/Cargo.toml:83`, 잠금 판 0.1.25)이에요.
- 코어 구현: `\p{L}`·`\p{N}`·`\p{M}`과 `normalize("NFC")`. 폰이 이미 돌리는 코드에는 `\p{L}\p{N}`(`packages/momo-core/src/features/auth/personalAgentCall.ts:148`, 폰이 부르는 곳 `clients/mobile/src/features/conversation/personalAgentCallModel.ts:218`)과 `normalize("NFC")`(`clients/mobile/src/features/search/localSearch.ts:52`)가 있어요. **`\p{M}`은 폰에서 돌아간 적이 없어요** — 코어에서 쓰는 곳은 글꼴 이름 검사(`packages/momo-core/src/design/fontName.ts:27`) 하나이고, 그 파일은 「`\p{…}`를 모르는 엔진에서는 앱이 시작도 못 한다」며 정규식을 처음 쓸 때 만들고 폰은 그 길을 타지 않는다고 적어요(`:17-20`). 그래서 같은 조심(처음 쓸 때 만들기)을 하고, P1이 실제 폰 엔진에서 `\p{M}`을 확인해요.
- **남는 어긋남**: 유니코드 표의 판이 서버(잠긴 Rust 크레이트 둘은 17.0.0)와 기준 구현(파이썬 `unicodedata` 14.0.0), 브라우저·폰 엔진마다 달라요. 아주 새로 생긴 문자는 서버가 받고 화면이 막을 수 있어요. 7개 언어의 글자는 오래전에 들어온 것이라 해당이 없고, 벡터에는 판에 따라 갈리지 않는 글자만 넣어요(14.0.0과 17.0.0이 같은 답을 내는지는 E1의 시험이 확인해요).
- API 문서: OpenAPI 3.0.3의 `pattern`은 `\p{…}`를 믿고 쓸 수 없어요(유니코드 플래그를 적을 자리가 없어요). `pattern`을 빼고, 설명에 규칙과 벡터 파일 경로를 적어요. 에이전트 행동 스키마의 `maxLength`(`server-rust/crates/momo-agent/src/actions.rs:1129`)도 D5대로 바꿔요.

### D12. 정렬과 검색

- **정렬**: 사이드바는 이미 `localeCompare(…, "ko")`로 세워요(`packages/momo-core/src/features/sidebar/sidebarSections.ts:534-540`). 한글·라틴이 섞여도 사람이 기대하는 차례가 나와요(한글이 앞, 시험 `sidebarSections.test.ts:625`). 서버의 목록 차례는 `lower(name)`(`channel.rs:835-841`)인데 화면이 다시 세우므로 바꾸지 않아요.
  - 고칠 것 하나: 자를 「ko」로 못 박지 않고 **보는 사람의 화면 언어**로, 숫자는 값으로(`sprint-2`가 `sprint-10` 앞에) 세워요. 일본어·중국어 화면에서 자기 말 차례가 나와요.
- **이름으로 찾기**(작성창 `#`, 빠른 이동, 폰 검색): 작성창은 부분 일치(`composerAutocomplete.ts:393`), 빠른 이동은 낱말 앞부분 → 부분 → 띄엄띄엄 맞추기 차례(`clients/web/src/app/paletteFilter.ts:69-75`, 쓰는 곳 `QuickSwitcher.tsx:804`), 폰 검색도 띄엄띄엄 맞추기로 물러서요(`localSearch.ts:68-78`). 폰 검색에는 「ko」를 못 박은 정렬이 하나 더 있어요(`localSearch.ts:149`). 한글 이름이 생기면 **조합 중 깜빡임**이 드러나요. 「디자인」을 치는 도중 입력기가 잠깐 「디장」을 만들고, 그 순간 「디자인」이 목록에서 사라졌다 돌아와요.
  - 코어에 한글 맞추기 도우미를 하나 두고 세 곳이 같이 써요. 질의의 **마지막 글자만** 느슨하게 봐요: 받침이 다음 글자의 첫소리로 넘어갈 수 있으면 맞는 것으로 쳐요(「디장」 ↔ 「디자인」). 질의는 NFC로 맞춘 뒤 견줘요.
  - 초성 검색(「ㄷㅈㅇ」 → 디자인)은 이번에 하지 않아요. 요청이 오면 같은 도우미에 더해요.
- 메시지 검색은 채널을 id로 좁히므로 영향이 없어요.

### D13. 문구와 화면

- 안내 글(칸 아래): 「글자, 숫자, 하이픈(-), 밑줄(_)로 80자까지. 빈칸은 -로 바뀌고 영문 대문자는 소문자로 저장돼요.」 「영문」이라는 낱말을 빼요(지금 `clients/web/src/features/channels/CreateChannelDialog.tsx:291`, `clients/mobile/src/shell/NewChannelSheet.tsx:119`).
- 거절 문장 넷: 쓸 수 없는 글자 / 보이지 않는 글자(「보이지 않는 글자가 들어 있어요. 이름을 지우고 다시 적어 주세요.」) / 처음·끝 구분자 / 80자 넘음. 이름 바꾸기에는 「`general` 채널의 이름은 바꿀 수 없어요.」가 더해져요.
- **입력 칸의 글자를 치는 도중에 바꾸지 않아요.** 한글 조합 중에 값을 바꾸면 입력기가 깨져요. 칸은 친 그대로 두고, 친 것과 저장될 이름이 다를 때만 아래에 「`#디자인-리뷰`로 만들어져요」 한 줄을 보여요. 보낼 때 접어요. 이름 바꾸기 창도 같아요.
- 자리표시자 `product-planning`(`CreateChannelDialog.tsx:300`, `NewChannelSheet.tsx:191`)은 화면 언어에 맞는 예로 바꿔요(한국어 화면: `디자인-리뷰`).
- 서버 오류 문장(영어, `channel.rs:253-256`)의 글자 쪽은 「channel name must use letters, numbers, hyphen, or underscore, and start with a letter or number」로 바꿔요. 오류 종류는 지금처럼 둘(길이·글자)이에요.
- 새 문구는 모두 7개 언어 사전(ADR-0213)을 거쳐요.

## 막지 않고 적어 두는 것

- 간체·번체는 서로 다른 글자라 `设计`과 `設計`은 다른 채널이에요.
- 반각 가타카나와 전각 가타카나는 다른 이름이에요.
- 독일어 `ß`는 `ss`로 접지 않아요(`straße` ≠ `strasse`).
- 가운뎃점(U+30FB·U+00B7)과 마침표(`v1.2`)는 거절해요. 일본어 팀이 가운뎃점을 자주 쓴다면 나중에 `-`로 고쳐 주는 것을 더할 수 있어요.
- 결합 표시를 수십 개 쌓은 이름(글자가 위아래로 번지는 장난)은 막지 않아요. 만드는 사람이 소유자·관리자이고, 에이전트 제안은 승인 카드에서 보여요.
- ZWJ·ZWNJ가 꼭 필요한 문자(페르시아어, 일부 인도 문자)는 7개 언어 밖이라 이번에는 거절돼요.
- `#공지`를 그대로 붙여 넣으면 거절돼요(`#`은 문장부호). 에이전트 인자는 지금처럼 앞의 `#` 하나를 떼고 봐요.

- 칸 수: 구현 **10칸**(엔진 5 · UXUI 5). 설계 초안의 기본 7칸에 owner N-1(R1·R2)과 N-2(E4)가 3칸을 더했어요.
- 워커 고르기: R1·E4는 권한·보안 판정이 들어가는 새 길이라 Opus, 나머지는 닫힌 범위예요.
- 세 결정 사이의 이음매:
  - **채널을 고치는 라우트**: 이 문서의 R1과 [ADR-0224](0224-public-channel-browse-and-self-join.md)의 E4·E5가 같은 `PATCH …/channels/{ch}`를 써요. S-1 차례로는 R1이 먼저 만들고, ADR-0224 칸이 칸을 더해요.
  - **`general` 잠금**: 환영 글의 이름 찾기(`welcome.rs:174`)에 기대요. ADR-0224의 E1이 그 찾기를 「기본 채널」 표시로 바꿔도 잠금은 남아요(새 결정 전까지).
  - **migration 번호**: 이 문서는 migration이 없어요. ADR-0177 증보와 ADR-0224는 각자 「착수 때의 다음 빈 번호」를 써요.
- 차례(S-1): 나가기 → 한글 이름 → 둘러보기, 준비된 것부터 승격. 이 문서의 칸은 E1·C1·W1·P1이 함께 나가면 「한글 이름으로 만들기」가 서요. R1·R2는 같이 나가야 해요(서버만 나가면 화면이 없고, 화면만 나가면 404).

## 확인하지 못한 것

- 운영 DB의 로캘. 저장 값을 서버가 접으므로 이 결정은 로캘에 기대지 않아요.
- 실제 팀 인스턴스에 옛 규칙 밖의 채널 이름이 있는지(E1에서 쿼리로 확인).
- 폰의 실제 엔진에서 `\p{L}`·`\p{N}`·`\p{M}`과 `normalize("NFC")`가 벡터 전부를 통과하는지. 쓰는 코드가 이미 있다는 것까지만 봤어요(P1에서 확인).
- Slack·Discord의 화면 동작과 비라틴 글자 허용, 멘션 저장 형식은 기억이에요. 표에 그렇게 적었어요.
- 폰 알림 확장이 채널 이름을 어디서 가져오는지.
