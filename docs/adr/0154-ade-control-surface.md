# ADR-0154 — ADE 관제 표면: 멀티 세션 스플릿뷰·기기 독립 연속성·하이브리드 실행

- Status: **Proposed** (성재 발제 2026-08-06 — "하나는 로컬, 두 개는 클라우드로 작업해도 셋을 스플릿뷰처럼 트래킹하고, 랩탑을 닫으면 로컬만 중단·클라우드는 계속. oort가 지향해야 할 포인트." 세부 D 승인 대기)
- Date: 2026-08-06
- 근거: `research/2026-08-06-prime-agent-ade-herdr.md`(업계 수렴 3원칙·함정) · 기존 부품: ADR-0125(host fabric)·0136(T3)·0139/0140/0142(수명주기·연속성)·0143(workstream)·작업 패널(랜딩)·#1114(스폰 폐곡선 — 이 방향의 1단계)

## Context
부품(호스트별 실행·클라우드 지속·관전 패널·workstream)은 전부 로드맵에 있으나 **묶는 제품 경험이 없다**: 다중 세션 동시 뷰 없음(패널은 run 하나), "기기를 꺼도 계속된다"를 사용자가 신뢰할 표면 없음, 로컬 재개와 원격 인수의 어휘 미분리. 업계는 worktree=세션 경계·3상태 배지·resume/teleport 분리로 수렴했고, 진짜 함정은 병렬도가 아니라 리뷰 병목이다.

## Decision (Proposed)

**D1 · 세션 생존성 모델**: 모든 작업 세션에 ⑴상태 3분류 `working/blocked/idle` ⑵**생존성 등급** `기기 종속(로컬)/지속(클라우드·원격)`을 1급 속성으로. **blocked=멘션급 우선순위**(채널 목록 상태 점·푸시는 blocked만, done은 배지). 로컬 세션의 중단은 정직하게("랩탑이 닫혀 중단됨 — 이어받기 가능") — 지속 세션엔 "이 작업은 기기를 꺼도 계속됩니다" 명시.

**D2 · 멀티 세션 관제 뷰**: 작업 패널을 다중 세션 동시 뷰로 확장 — 세션 카드 그리드(상태·생존성·diff 인디케이터 `+42 -18`·경과)+카드 확대=기존 패널. oort는 메신저이므로 **채널이 세션의 홈, 관제 뷰는 집계**(별도 앱 아님 — 웹 우선, 폰은 목록형). 리뷰 병목 방어: diff 요약 카드→인라인 코멘트→"다음 지시에 첨부" 루프를 관제 뷰의 1급 동선으로.

**D3 · 이어하기 어휘 분리**: **재개**(같은 기기 로컬 히스토리)와 **인수**(다른 기기/클라우드 세션 가져오기)를 다른 동사·다른 버튼으로. 인수는 사전조건 선검사(클린 트리·브랜치 push·동일 repo)+실패를 "무엇을 하면 되는지"로. 부분 복원(대화만 복원·환경 새로) 정직 표기.

**D4 · 단계**: 1단계=#1114(스폰 폐곡선+승인 카드 호스트 선택 — 이미 편성) → 2단계=D1 생존성 모델+D2 관제 뷰 → 3단계=D3 핸드오프(초기 단방향 허용 — 비대칭 명시). worktree/브랜치=세션 경계 기본값.

**D5 · 외부 하네스 트랙(테스트→정식)**: ⑴ **prime agent** = hermes/codex와 같은 층의 3번째 provider 스파이크 — 컨테이너 격리 필수(비샌드박스)·RPC JSONL 어댑터·델타는 REST 단일 경로만·`steer`→"실행 중 끼어들기" UX 실험·`extension_ui_request`→승인 카드 렌더 실험. 계약 요건은 리서치 표 2. ⑵ **herdr** = 워커 호스트 런타임 실험 — 상태(blocked 감지)→oort 릴레이 어댑터(소켓 폴링+REST), 실행만(코드 재사용 금지 — 라이선스 재확인 전). 버전 핀.

## Slack·업계 비교
Slack에는 이 층이 없다 — huddle·canvas는 사람 협업이지 에이전트 세션 관제가 아니다. ADE 제품군(Conductor·Cursor Cloud·Claude web)이 IDE 옆에 이 층을 세우는 동안, oort는 **대화 공간 안에** 세운다는 것이 차별점(에이전트=member이므로 세션 상태가 곧 멤버 상태). 관제만 하는 도구(herdr)와 겹치지 않고 그 위층이 된다.

## Consequences
- (+) 기존 부품 재사용 — 신규는 표면(D2)과 모델 필드(D1)·어휘(D3)가 대부분. (+) prime/herdr 실험이 provider 어댑터 자산으로 축적.
- (−) 관제 뷰는 리뷰 동선까지 져야 실익(함정: 세션만 늘리는 UI) — D2에 리뷰 루프를 묶은 이유. (−) 클라우드 생존성은 T3 실활성(E2B) 전까지 원격 호스트 한정 — 3택 완성은 T3 트랙 의존.
