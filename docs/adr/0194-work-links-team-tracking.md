## Context

- 성재 요청(2026-09-27): 개발자는 claude·codex 세션 8~10개를 한 탭에서 돌리고 worktree·로그를 보고, 비개발자는 남이 돌리는 작업을 「이 사람 지금 이 작업 중이구나」 수준으로 추적하고, 앱 안에서 진행 중인 작업이나 결과를 링크로 주고받고 싶다.
- 로컬 세션(L 레인)은 ADR-0190 D2·D4에 따라 원장 밖이 기본이고, 공유는 옵트인이다. 공유 범위는 D4-b의 S1로 넓어졌다.
- `work_session`에는 `channel_id`와 `root_message_id`가 NOT NULL이다(`server/Migrations/019_work_session.sql`). 모든 공유 세션에는 집 채널 하나와 root 메시지 하나가 있다.
- 지금 링크 펼침(`momo-unfurl`)은 본문의 `http(s)://` 토큰을 골라 **메시지마다 미리보기 하나**를 저장한다. 모든 보는 사람이 같은 미리보기를 본다. 보는 사람마다 다른 가시성을 이 경로에 태울 수 없다.
- 공개 API가 늘고(공유 PATCH, 팀 보드 목록, 카드 조회) 새 테넌트 테이블이 생긴다. ADR-0100 대상이다.

## Options

| 선택지 | 내용 | 판단 |
|---|---|---|
| **A. 링크는 id만, 카드는 보는 사람마다 조회** | 메시지에는 링크만 남고, 클라가 카드 API로 보는 사람 기준 데이터를 받아 그린다. 실시간은 상태 전환 이벤트 후 다시 조회 | **채택.** 가시성을 서버 조회 한 곳에서 강제한다. 카드가 제자리에서 살아 있다 |
| B. 기존 unfurl 파이프라인에 태우기 | 서버가 링크를 해석해 미리보기를 저장 | 기각. 미리보기가 메시지마다 하나라 채널 밖 사람에게도 이름이 보인다 |
| C. 상태가 바뀔 때마다 카드 메시지 편집 | root 메시지 본문을 갱신 | 기각. 메시지 원본을 매번 바꾸고, 링크가 붙은 다른 메시지는 갱신되지 않는다 |
| D. 작업 전용 채널 | 작업마다, 또는 팀에 하나 | 기각(Q1). 세션의 대화 홈은 이미 채널·스레드다. 같은 세션이 두 채널에 흩어진다 |

## Decision

### D1. 진입점(Q1)
- 사이드바 「작업」 묶음에 두 줄을 둔다. **「내 작업」**(작업 탭 격자, 데스크탑)과 **「팀 작업」**(팀 보드, 웹·데스크탑·폰). 둘 다 클라 라우트 `/work`를 채운다.
- 작업 전용 채널은 만들지 않는다.
- 폰 탭바 「작업」은 팀 보드의 한 열 판이다. 내 A 세션은 거기서 「내 것」 필터로 본다(ADR-0188 D4 작업 탭과 합친다).

### D2. 작업 링크 스킴
- 세션 링크: **`oort://work/<session_id>`**. `session_id`는 `work_session.id`(uuid)다.
- 보드 링크: **`oort://work?view=team&channel=&member=&status=`**. 필터 값은 D5 목록 API의 쿼리와 같다.
- 워크스페이스: 선택 인자 `ws=<workspace_id>`. 없으면 지금 연 워크스페이스로 해석한다. 메시지 안의 링크는 그 메시지의 워크스페이스로 해석한다.
- 발급은 `oort://`만, 소비는 `oort://`와 `momo://` 둘 다 받는다(`docs/onboarding-deeplink.md`의 스킴 규칙과 같다).
- 웹 폴백: `https://<팀 서버 공개 오리진>/work/<session_id>`와 `/work?view=team&…`. 웹이 받고, 앱이 있으면 앱으로 넘긴다.
- **링크는 공유된 세션에만 있다.** 공유하지 않은 L 세션은 서버에 id가 없다. 「링크 복사」는 공유 확인을 먼저 묻고(ADR-0190 D4-b, Q5), 주인만 여는 링크는 따로 없다.
- 딥링크는 화면을 여는 것뿐이다. 딥링크로 세션을 만들거나, 공유를 켜거나, 컨트롤을 만들 수 없다(ADR-0190 D1과 같은 경계).
- 역링크는 두지 않는다. 공유 세션이 만든 커밋·PR 본문에 oort 링크를 넣지 않는다. 외부 저장소에 내부 링크가 남기 때문이다. 대신 oort 안에서 PR URL로 세션 카드를 찾는다(D7).

### D3. 펼침(unfurl) 가시성 — 보는 사람 기준
- 메시지 본문의 작업 링크(`oort://work/…`, `momo://work/…`, 자기 오리진의 `/work/<id>`)는 **클라가 D6 카드 API로 보는 사람마다 조회해** 카드로 그린다. 서버는 이 링크의 미리보기를 저장하지 않는다.
- **`momo-unfurl`은 자기 공개 오리진의 `/work/` 경로를 건너뛴다.** 그러지 않으면 웹 폴백 URL이 모든 사람에게 같은 미리보기로 저장된다. 요구 시험: 웹 폴백 URL이 든 메시지를 보내면 `unfurl_job`·`message_unfurl` 행이 0개다. 건너뛰기 분기를 지우면 실패해야 한다.
- 판정(카드 API가 한다):

| 보는 사람 | 응답 |
|---|---|
| 집 채널 멤버, 공유 켜짐 | 카드 데이터(D6) |
| 집 채널 멤버, 공유 꺼짐 | `{shared:false}`만. 이름·브랜치·상태 없음. 카드는 「공유가 꺼진 작업이에요」 |
| 세션 주인 | 공유 여부와 관계없이 자기 세션 카드 |
| 집 채널 멤버가 아님, 세션 없음, 다른 워크스페이스 | **모두 같은 404.** 몸통도 같다. 카드는 「볼 수 없는 작업이에요」. 이름·채널 이름·존재 여부를 구분할 수 없다 |

- 가시성 규칙은 새로 만들지 않는다. `work_session.channel_id`의 채널 멤버십과 기존 채널 RLS만 쓴다. 워크스페이스 전체 공개는 없다(Q4).

### D4. 공유 라우트
- **`PATCH /v1/workspaces/{ws}/work-sessions/{session}/share`**
  - host 서명(ADR-0125·0188 v2 서명)만 받는다. 사람 토큰으로는 부를 수 없다. 서명한 host가 세션의 host이고, 세션이 `origin='local_pty'`여야 한다. A 세션은 이 라우트를 쓰지 않는다.
  - 본문은 ADR-0190 D4-b의 S1 필드다. 알려진 필드 외 거부, 상한 초과 거부, 닫힌 목록 밖 값 거부. PR URL은 D7 형식 검증을 통과해야 한다.
  - 해제는 `{"shared": false}`. 같은 tx에서 `work_session_share` 행을 지운다.
  - 갱신과 해제는 같은 tx에서 outbox에 상태 전환 이벤트를 넣는다(D8).
- 기존 `PATCH …/work-sessions/{session}`(종료)는 그대로다. 공유는 하위 경로로 분리한다.
- 집 채널과 root 카드는 공유 세션을 처음 만들 때 정해진다(ADR-0190 D4-b 집 채널 규칙). root 카드 게시는 기존 메시지 전송 경로(단일 tx + outbox)를 탄다.

### D5. 팀 보드 목록
- **`GET /v1/workspaces/{ws}/work-sessions?scope=team&channel=&member=&status=`**
  - 기존 목록 라우트(`list`)에 `scope=team`을 더한다. 사람 토큰만 받는다.
  - 보는 사람이 멤버인 채널에 집이 있는 **공유 L 세션과 A 세션**만 돌려준다. 공유하지 않은 L 세션은 서버에 없으므로 셀 수도 없다. 응답에 「공유되지 않은 세션 n개」 같은 숫자를 넣지 않는다.
  - `status`는 파생 상태 목록(ADR-0190 D4-b)의 값으로 거른다. `member`는 세션 주인, `channel`은 집 채널이다.
  - 각 행은 D6 카드 데이터의 요약 부분과 같은 모양이다.
- 「오늘 끝난 것」 보기는 `status=ended`와 기간 인자로 한다. 기간 인자의 형식은 구현 이슈가 정한다.

### D6. 카드 조회와 카드 데이터 모델
- **`GET /v1/workspaces/{ws}/work-sessions/{session}/card`** — 사람 토큰. 판정은 D3 표.
- 카드 데이터(공유 켜짐·집 채널 멤버 기준):

| 묶음 | 필드 | 출처 |
|---|---|---|
| 신원 | `session_id`, `lane`(`local`·`agent`), `owner_member_id`, `agent_member_id`(A만), `host_label`(A만), `home_channel_id`, `root_message_id` | `work_session`, 멤버·호스트 |
| 제목 | `title` | 세션 이름(L), 세션 라벨(A) |
| 위치 | `repo`, `branch`, `folder`, `harness` | S1(L), 세션 필드(A) |
| 상태 | `status`(원장), `derived_status`(파생), `last_activity_at`, `ended_at`, `exit`(`ok`·`error`·없음) | 원장 + S1 |
| 진행 | `steps[]`(최대 12, 각 80자) | 단계 표지(L), ACP `plan`(A) |
| 변경 | `diff{additions, deletions, files, ahead, behind, uncommitted}` | S1 숫자 |
| 결과 | `pr{url, number}`, `pr.checks`, `pr.review` | D7 |
| 산출물 | `artifacts[]`(A만: 첨부·파일 수) | 기존 첨부 |
| 멈춤 | `stop_reason`(A만: 한도·오류와 고칠 길) | ADR-0191 한도 카드 |
| 보는 사람별 | `viewer.is_owner`, `viewer.can_open_in_workspace`, `viewer.can_decide`(A 권한 요청, 주인만) | 판정 시 계산 |

- 커밋 제목, 파일 이름, raw 출력은 카드에 없다(ADR-0190 D4-b).
- **진행 카드와 결과 카드는 같은 데이터, 같은 root 메시지다.** 세션이 끝나면(`ended`) 클라가 결과 카드 모양으로 그린다. 메시지를 새로 만들거나 편집하지 않는다.
- 끝날 때 스레드에 **주인을 멘션하는 시스템 줄 하나**를 기존 전송 경로로 붙인다. 이것이 알림이다. 카드의 상태 변화 자체는 알림을 만들지 않는다. 토스트는 없다(ADR-0182).
- 행동 버튼: 「진행 보기」(세션 상세), 「PR 보기」·「변경 보기」(`pr`이 있을 때), 「작업 공간에서 열기」(주인에게만. 이 기기의 로컬 세션이면 그 칸에 포커스, 다른 기기면 「MacBook에서 열려 있어요」 안내). A 레인의 「PR 만들기」·「이번 한 번 허락」은 주인에게만 보이고, 기존 A 레인 결정 경로(ADR-0188 D3·D5)를 탄다.
- 공유 L 세션의 카드와 상세에는 입력 칸·멈춤·허락 버튼이 없다. 서버가 컨트롤을 거부하기 때문이다(ADR-0190 D4).

### D7. PR 데이터 출처 단계(Q6)
- **1단계(지금):** 주인 기기가 아는 PR URL과 diff 숫자만 쓴다. PR URL은 공유 페이로드(L) 또는 A 세션의 host 보고로 들어온다. 카드의 `pr.number`는 URL에서 뽑는다. PR 제목·체크·리뷰는 1단계에 없다(`pr.checks`·`pr.review`는 `null`).
- PR URL 형식 검증: `https`, 허용 호스트(`github.com`과 운영자가 설정한 GitHub Enterprise 호스트), 경로가 `/<소유자>/<저장소>/pull/<번호>`. 쿼리·조각은 버린다. 이 URL은 `소유자/저장소`를 드러낸다. Q2가 받아들인 노출이다.
- **2단계(#2783 뒤):** GitHub 웹훅 레시피가 들어오면, 웹훅이 알린 PR을 URL로 맞춰 `pr.checks`·`pr.review`와 제목을 붙인다. 웹훅은 들어오는 방향이고 서명 비밀로 검증한다.
- **서버는 GitHub 토큰을 쥐지 않는다.** 서버가 GitHub API를 부르는 경로는 커넥터 커스터디 ADR(목표 A 뒤, ADR-0192 D7) 전에는 열지 않는다. 주인 기기도 이 목적으로 `gh`를 실행하지 않는다(ADR-0190 D3-c).
- PR URL로 세션 찾기: 메시지에 PR URL이 붙으면, 클라는 같은 워크스페이스에서 그 URL을 가진 공유 세션 카드를 D3 판정대로 함께 그릴 수 있다. 이 조회도 보는 사람 기준이다.

### D8. 실시간
- 카드·보드 갱신은 기존 경로로만 한다. **공유 PATCH·종료·A 세션 상태 변화 tx 안에서 outbox INSERT → relay → Centrifugo.** Postgres가 원본이고 Centrifugo는 전송만 한다. 클라 직접 publish는 없다.
- 이벤트는 **상태 전환만** 싣는다: `session_id`와 전환 종류(예: `work.session.share_changed`, 기존 `work.session.ended`·`work.session.idle`). 이름·브랜치·숫자는 싣지 않는다. 이벤트는 집 채널 토픽으로 간다.
- 클라는 이벤트를 받으면 D6 카드를 다시 조회한다. 그래서 가시성은 조회에서 한 번 더 강제된다.
- 출력 줄, 단계 표지 하나하나, 마지막 활동 시각만 바뀐 갱신은 이벤트를 만들지 않는다. 파생 상태가 바뀔 때만 보낸다. 마지막 활동 시각은 다음 조회에서 보인다.

### D9. 저장
- S1 확장 필드는 `work_session_share`(세션당 한 행, `workspace_id` 포함, RLS FORCE)에 둔다(ADR-0190 D4-b). 새 migration으로만 추가하고 `schema_v0.sql`은 건드리지 않는다. Rust는 sqlx 런타임 쿼리를 쓴다.
- 파생 상태·단계 표지·diff·PR은 이 테이블에만 있다. `work_session`의 원장 컬럼(`status` 등)의 의미는 바꾸지 않는다.
- PR 체크·리뷰(2단계)의 저장 위치는 #2783 레시피 이슈가 정하되, 같은 RLS 규칙을 따른다.

### 요구 시험(각각 되돌리면 실패하는 red proof)
- 카드 API가 집 채널 멤버가 아닌 사람, 없는 세션, 다른 워크스페이스 세션에 **글자 그대로 같은** 404를 돌려주고, 몸통에 이름이 없다.
- 공유 꺼진 세션의 카드가 멤버에게 `{shared:false}`만 돌려준다.
- 팀 보드 목록이 보는 사람이 멤버가 아닌 채널의 세션을 돌려주지 않는다.
- 웹 폴백 URL이 든 메시지에 `unfurl_job`·`message_unfurl` 행이 생기지 않는다.
- 공유 PATCH가 사람 토큰, 다른 host의 서명, `origin`이 `local_pty`가 아닌 세션을 거부한다.
- 공유 PATCH와 같은 tx에 outbox 행이 있고, 이벤트 본문에 이름·브랜치가 없다.
- 공유 L 세션 컨트롤 생성 거부(#2793, ADR-0190 D4).

## 업계 비교
- **Claude Tag / Claude in Slack:** 채널에서 부르면 스레드에 진행 체크리스트가 제자리 갱신되고, 결과에 View Session·Create PR 버튼이 붙는다. oort는 **대화 쪽 절반**(살아 있는 카드, 제자리 진행, 결과 버튼, 작업 이름)을 L·A 두 레인에 준다. **누구나 부르는 절반**은 공용 신원이 필요해 목표 A 밖이다(ADR-0192 D7). L 세션은 채널에서 만들 수 없고, A 세션은 소유자만 시킨다(ADR-0188 D3·D4).
- **GitHub Copilot 코딩 에이전트:** PR 본문에 세션 링크를 남긴다. oort는 외부 저장소에 내부 링크를 남기지 않고 PR URL로 역검색한다(D2).
- **Devin:** 세션마다 채널을 만든다. oort는 작업 전용 채널을 두지 않는다(D1).
- **Conductor·Orca:** worktree·세션 격자와 상태 점. 작업 탭의 문법으로 가져왔다(ADR-0190 D7, D3-c).

## Consequences
- (+) 가시성이 카드 조회 한 곳에서 강제된다. 링크가 어디에 붙든 채널 멤버가 아니면 이름도 보이지 않는다.
- (+) 비개발자가 대화 안의 카드와 팀 보드로 「누가 어느 worktree에서 무엇을 하는지」 본다. raw는 여전히 기기 밖으로 나가지 않는다.
- (+) 서버가 GitHub 토큰 없이 PR 링크와 diff 숫자를 보인다.
- (−) 1단계 결과 카드에는 PR 제목·체크·리뷰가 없다. #2783 전까지 번호와 숫자만 보인다.
- (−) 카드를 그릴 때마다 조회가 필요하다. 한 화면에 카드가 많으면 요청이 늘어난다. 묶음 조회는 구현 이슈가 필요할 때 더한다(같은 판정 규칙).
- (−) 집 채널은 바꿀 수 없다. 다른 채널에 붙인 링크는 그 채널 사람 중 집 채널 멤버에게만 펼쳐진다.
- 파생 이슈(이 ADR이 머지 조건): T10(공유 PATCH·migration·스키마 검증), T11(팀 보드), T12(폰 작업 탭), T13(`oort://work` 딥링크·웹 폴백·보는 사람 기준 카드·unfurl 건너뛰기), T14(결과 카드), T15(「채널에 공유」·「링크 복사」·「작업 공간에서 열기」), T16(요약 줄 합류), T17(PR 체크·리뷰, #2783 뒤).
