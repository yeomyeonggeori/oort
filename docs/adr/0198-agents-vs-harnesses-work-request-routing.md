## 맥락

### 풀려는 문제
오늘 oort는 「내 Claude Code」를 **에이전트 멤버**(`kwak-claude`, `owner_only`)로 만들고, @멘션으로 부르게 한다. 그런데 이 모델이 막혀 있고, 막혔다는 사실보다 **모델 자체가 사용자의 머릿속 모양과 다르다.**

사실 [V, 2026-10-06 oort-team 읽기 전용 진단]:
- 구독 에이전트 `kwak-claude`와 hosted `@claude-code` 모두 연결이 `pairing_pending`, `proved_at` NULL, 활성 토큰 0. `work_host` 0행, `work_session` 0행. 한 번도 완성된 적이 없다.
- 구독 에이전트는 **호스티드(Agent Port) 레인**에만 연결돼 있다. 사용자가 터미널에서 직접 연 `claude`가 oort 수신함을 pull하는 방식이라 깨우는 데몬이 없고, 맥이 꺼졌는지·로그인이 풀렸는지·CLI가 닫혔는지를 서버가 가르지 못한다(전부 stale `last_used_at`).
- 정작 「내 맥에서 일을 시키는」 길은 **ADR-0188의 work host 레인**(momo-workd, 기기 키 서명)이다. 이 레인은 `scope=member` host를 이미 허용하고 요청자 == host 소유자를 서버가 강제한다. 그런데 멘션·DM·`agent-runs`는 이 레인으로 spawn을 만들지 않고, 폰의 새 작업 spawn(0188 D4 DM→spawn)은 **E8 이후로 미구현**이다(ADR-0146 §E8 노트).
- 결과: 「폰에서 요청 → 내 맥이 실행 → 보드·푸시」 E2E는 어느 레인으로도 성립하지 않는다 (`runtime-unverified`).

### 성재의 정정
성재 결재(아래)가 사실 한 줄로 정리한다. **Codex·Claude Code는 에이전트가 아니라 구독을 연동해 쓰는 하네스(도구)다.** 에이전트는 Grok Bot·Hermes처럼 24시간 켜져 있는 별도 클라우드/VM 기반의 AI 비서·직원·동료다. 그래서 ADR-0193이 하네스를 에이전트 멤버로 만든 것이 이질적이었다. 폰 요청은 내 맥이 켜져 있으면 내 맥의 하네스(Remote Control처럼 추적), 연결이 없으면 에이전트의 VM으로 보낸다. 「나만 쓴다」는 유지한다.

### 약관 맥락 (2026-10-07 확인, 성재 세션 전달)
- https://code.claude.com/docs/en/legal-and-compliance — 제3자는 claude.ai 로그인을 제공하거나, Free/Pro/Max 자격으로 요청을 대신 라우팅하거나, 세션 토큰을 수집·저장·중개할 수 없다. 최종 사용자가 **수정하지 않은 Claude Code**에 자기 구독으로 로그인하는 것은 허용된다. (ADR-0193 2026-09-27 약관 판단과 같은 결론.)
- https://support.claude.com/en/articles/15036540 — Agent SDK로 인증하는 제3자 앱에는 **Agent SDK 월 크레딧**이 적용된다. 구독 한도가 아니라 별도 크레딧으로 과금될 수 있다는 뜻이다. oort가 `claude-agent-acp`(ACP 어댑터)를 자동으로 띄우는 경로의 과금 영향이 [확인 필요]다(D5).

## 결정

### D1. 어휘 — 에이전트(동료)와 하네스(도구)
| | 에이전트(동료) | 하네스(도구) |
|---|---|---|
| 예 | Grok Bot, Hermes, 팀 키 에이전트, 나중에 dots | Claude Code, Codex, OpenCode |
| 정체 | `member.kind='agent'` 1급 멤버(ADR-0101) | **멤버가 아니다.** 사용자의 구독으로 로그인한 CLI |
| 어디서 도나 | 별도 클라우드·VM, 항상 켜짐 | 내 맥(member host), 또는 에이전트 VM **안**의 도구로 |
| 누가 쓰나 | 팀(권한 범위에 따라) | **나만.** 구독을 팀원에게 쓰게 하지 않는다 |
| 상호작용 | DM·멘션·작업 요청 | 「작업 요청」으로 세션을 시킨다. 이름으로 부르지 않는다 |

- 하네스에는 멤버 id·핸들·멘션이 없다. 「@claude」는 만들지 않는다.
- 에이전트 VM이 안에서 Claude Code를 쓰는 것은 그 에이전트의 구현 선택이고 oort는 알지 못한다. 그 로그인은 사용자가 VM에서 직접 하며 oort는 토큰을 받지 않는다(ADR-0197 보류 기준과 같다).

### D2. ADR-0193의 구독 에이전트와 호스티드 `@claude-code`류 — 「내 도구」로 이행, 데이터 손실 0
**대상.** ① `invocation_scope='owner_only'`이고 `subscription_harness`가 있는 에이전트(예: `kwak-claude`), ② 하네스 이름을 단 hosted 항목 중 실제 VM 에이전트가 뒤에 없는 것(예: oort-team `@claude-code`, `subscription_harness=NULL`, scope=workspace). ②는 소유자가 은퇴를 결재했다(결재 기록 Q3). 실행은 T2 dry-run을 거친다.

**이행 순서 (되돌릴 수 있는 단계로).**
1. **숨김.** 에이전트 목록·멘션 자동완성·`@` 후보·AI 허브 「에이전트」에서 대상 행을 뺀다. 읽기 계약(ADR-0193 D14)의 필드를 쓰는 클라이언트 분기로 처리한다.
2. **전환 표시.** 같은 하네스·같은 사용자 로그인은 「내 도구」 카드(D3)가 대신한다. 사용자가 다시 할 일은 없다(CLI 로그인은 맥에 이미 있다).
3. **은퇴.** 서버 쪽 행은 **삭제하지 않고** 멤버를 비활성(과거 메시지의 작성자 표기는 보존, 「이전 구독 에이전트」 표식), 연결 `revoked`, 토큰 폐기, pairing 값 무효로 닫는다. 이미 대화가 있는 행도 같다. 운영 실행은 관리자 도구/스크립트의 **dry-run → 소유자 확인 → 실행**이고 감사 한 줄(`subscription_agent.retired`)을 남긴다.
4. **앱 등록 중단.** 데스크탑 앱은 로그인 직후 `subscription-agents/register`(D15)와 `claude mcp add-json …oort`(ADR-0190 D3-h)를 더 이상 부르지 않는다. 앱이 `add-json`을 성공시킨 표식이 있는 기기에는 D3-h의 `mcp remove`(표식이 있을 때만)로 한 번 정리한다. 서버의 D15 엔드포인트는 이행 완료 뒤까지 두고 정리 이슈에서 닫는다.

oort-team 현황으로는 두 행 모두 연결된 적이 없으므로 은퇴해도 잃는 대화가 없다(진단 2026-10-06). 

**효력이 바뀌는 것.**
- ADR-0193 D2(구독은 내 개인 에이전트 1순위)·D4(구독 에이전트는 소유자만 부른다)·D14~D17의 「구독 에이전트」 개념은 **대체**된다. D4의 안전 불변식은 개념이 아니라 아래 D4(내 맥 대상은 나만)가 그대로 잇는다.
- D18(Claude 구독 서버 차단 갈래)은 **하네스 사용에는 무의미**해진다. 하네스는 서버를 거치지 않고 member host 레인으로 가며, 그 레인은 이미 `scope=member`를 허용한다. 조사 보고가 제안한 「D19 — 소유자 호출을 허용하도록 분기 뒤집기」는 **하지 않는다.** 뒤집을 대상이 사라진다.
- D17/D18 설정(`MOMO_CLAUDE_SUBSCRIPTION_AGENTS_ENABLED`, 기본 off)과 게이트는 은퇴가 끝날 때까지 **그대로 두고**, 남은 행에 대한 방어선으로만 둔다. 정리는 마지막 이슈(T7).

**계속 막는 것.** (a) 팀원이 내 구독을 쓰는 모든 경로(`NonOwner`·D4 안내 유지), (b) 워크스페이스·클라우드 host의 Claude(#3431/#3457/#3460/#3477, `scope<>member`), (c) 공용 host controller 입력·allow_once. 이 ADR은 그중 하나도 풀지 않는다.

### D3. AI 허브 정보 구조 — 「에이전트」 / 「내 도구(구독)」
- AI 허브(사이드바 「AI」)를 두 탭으로 나눈다. **에이전트**: Grok Bot·Hermes·팀 키 에이전트(기존 명부·외부 연결). **내 도구**: 내 구독 CLI 카드. 팀 AI 키(API 키 기본)는 에이전트 탭의 설정이다.
- **하네스 카드 상태.** 로그인 상태와 호스트 상태를 **하나의 카드**에 합친다(Aside형).
  - 로그인: `연결됨` / `다시 인증` / `로그인 중` / `연결 끊기`(액션). 입력은 로컬뿐이다: 상태 명령 `claude auth status`의 **종료 코드만**(0=연결됨, ≠0=다시 인증, 126/127·시그널·시간 초과=확인 불가) — ADR-0190 D3-a 그대로. 로그인은 기존 숨은 PTY(`claude auth login --claudeai`, #2816/#3419)로 공식 CLI가 브라우저·토큰을 처리하고 oort는 URL·코드·토큰을 보지 않는다. **만료와 미로그인은 구분하지 못하므로** 둘 다 「다시 인증」이다(구분이 필요하면 D3-d 허용 필드 확장은 별도).
  - 호스트: `내 맥 켜짐` / `내 맥 꺼짐` / `미등록`. 데스크탑은 로컬 workd 상태, 폰·웹은 서버의 work host 읽기(D4의 온라인 판정)로 같은 값을 읽는다.
  - 로그인 중은 모달을 닫아도 카드에 인라인으로 남는다(지금은 모달 안에서만 보임).
  - 연결 끊기 = 공식 CLI 로그아웃을 숨은 PTY로 실행해 `loggedIn:false` 확인 후 카드를 「연결 안 됨」으로. **서버에 지울 에이전트가 없다**(D2 이후). 지금 있는 `agent_port_disconnect` 미연결·서버 revoke 갭은 이 모델에서 사라진다.
- **서버는 구독 로그인 상태를 알지 못한다**(올리는 계약을 만들지 않는다). 폰은 「내 맥 로그인 상태는 맥에서 확인해요」까지만 말하고, spawn이 로그인 풀림으로 실패하면 세션 카드에 그 사유(`needs_login`)를 보여 준다.
- Claude 카드의 하드코딩 「문의 중」(`subscriptionAgentStatus`, `claudeDriveEnabled !== true`)은 제거한다. 하네스에는 D18이 적용되지 않기 때문이다.

### D4. 작업 요청 라우팅 — 내 맥 우선, 없으면 에이전트
사용자 입장의 입구는 하나다: 웹·데스크탑·폰의 **「작업 요청」**. 서버는 새 통합 엔드포인트를 만들지 않는다. 클라이언트가 두 기존 경로 중 하나를 고른다.

| 대상 | 경로 | 추적 |
|---|---|---|
| **내 맥**(하네스) | ADR-0188 work host 레인: 소유자 기기 키 서명 새 작업(spawn) 컨트롤 → host가 폴링해 ACP 세션 시작 | 기존 work session·ACP 뷰·작업 탭·팀 보드(ADR-0194)·푸시(`approval_request`·`work_session_idle`). Remote Control과 같은 방식으로 라이브 추적 |
| **에이전트**(대체) | ADR-0162 증보 3 호스티드 작업 요청: `POST …/agent-runs`(`type=work`) | 증보 3의 진행 표식·결과 산출물·팀 보드·`work_run_done` 푸시(AT 추적) |

**누가 고르나.** 사용자가 고르되 기본값은 규칙으로 정한다. 시트(스케치 참조)는 항상 **어디로 가는지 이름을 보여 준다.**
- 내 맥이 **켜져 있으면** 「내 맥」이 미리 선택된다. 하네스는 **마지막에 쓴 것**이 미리 선택된다(Claude Code·Codex가 둘 다 있을 때). OpenCode는 감지·ACP 어댑터가 확인될 때만 카드·시트에 넣는다(결재 기록 Q4).
- **「켜지면 실행」 대기 요청은 v1에 없다**(결재 기록 Q2). 꺼져 있을 때의 길은 아래 에이전트 대체뿐이다.
- **꺼져 있거나 미등록이면** 아무것도 미리 선택하지 않고 「내 맥이 꺼져 있어요」와 함께 **쓸 수 있는 에이전트 목록**을 보인다. 에이전트로의 전환은 **사용자의 명시 탭**이다. 자동으로 에이전트에 보내지 않는다. 이유: 에이전트는 다른 VM에서 코드·컨텍스트를 받고 과금·권한이 다르기 때문에 「대신 보냄」이 조용히 일어나서는 안 된다.
- 선택 뒤 전송 사이에 내 맥이 꺼지면 전송은 실패하고 대상 선택으로 돌아간다. 조용한 재라우팅 없음.
- 에이전트 목록은 ADR-0162 증보 3 D10 조건(연결 active·채널/DM 승인·요청자는 사람)을 서버가 이미 판정한 것만 보인다.

**「온라인」 판정.** `work_host.last_seen_at`(host heartbeat 90초)이 기준이다: `revoked_at IS NULL`이고 `last_seen_at`이 ~~heartbeat의 **2배(180초) 이내**~~ → **90초 이내** (T4 확정, 아래 :90 「T4 확정」 참조). 한 개의 서버 판정 식을 데스크탑·폰이 같이 쓴다. 구독 에이전트의 `hostOnline`(활성 토큰 10분 추정)은 하네스에 쓰지 않는다(조사 보고 (e)-4의 두 값 불일치 해소).

**T4 확정 (#3569).** 실측: `momo-workd`의 heartbeat 주기는 30초(`heartbeat_interval_ms`), 서버의 기존 `online` 창은 90초(주기의 3배, 두 번 놓쳐도 온라인)다. 위 「heartbeat 90초」는 주기가 아니라 창이었으므로 식은 **90초 그대로**(`revoked_at IS NULL AND last_seen_at >= now() - 90초`) 두고, 180초로 늘리지 않는다(맥을 닫고 3분간 온라인으로 보이는 쪽이 더 나쁘다). 이 식은 `momo_wire::work_host_online_sql` 한 곳에 있고 work-hosts 읽기·spawn 대상 검사·spawn 후보·reattach `host_online`이 모두 이것으로 만든다. 클라이언트는 서버 `online`만 읽는다.

**내 맥으로의 spawn은 소유자 서명이다 (E8의 빈칸을 메운다).**
- 새 작업 spawn 컨트롤을 ADR-0146 사람 기기 키(R2) 서명으로 받는다. 서버는 서명·논스·만료를 검증하고 workd도 같은 검증을 한다(`require_human_signatures` 래칫 그대로).
- 서버는 대상 host를 **요청자의 member host로부터 도출**한다. 요청 본문의 host id는 선택 힌트일 뿐이고, `scope=member`·`host.owner == requester`·`revoked_at IS NULL`·온라인이 아니면 거부한다. **다른 사람이 내 맥을 대상으로 삼을 길이 없다.** 팀원·에이전트(에이전트 bearer는 `kill`만)·웹훅·도어벨은 spawn을 만들 수 없다(ADR-0188 D3 불변식 그대로).
- 서명 대상에 프롬프트·하네스·허용 폴더 id를 넣는다. 폴더는 host의 허용 폴더(0188 D6) 안에서만 고른다. spawn도 슬롯 입장(`acquire_slot_in_tx`)을 거친다.
- 이것은 REST send → outbox 경로(메시지)와 별개의 work-control 경로이므로 `channel_seq`·outbox 불변식에는 닿지 않는다. 시험은 「메시지를 거치지 않는다」를 단정한다.

**폰이 보여 주는 것.** 시트 → 전송 후 작업 탭의 세션 카드(대기·실행·승인 필요·끝남). 맥이 꺼져 있을 때는 전송 전에 알린다. 요청자에게 가는 푸시(접수·승인 요청·끝남)의 수신 대상이 「세션을 시작한 사람」이므로 폰 요청자가 맞는지 [확인 필요](조사 보고 (e)-5).

### D5. 과금과 약관 — 구독 로그인은 늘 소유자 본인의 공식 CLI 흐름이다
- **하네스는 언제나 소유자 본인의 구독 로그인**으로 돈다. 내 맥이든 에이전트 VM 안이든 같다. 로그인은 수정하지 않은 공식 CLI의 흐름이고, VM에서는 소유자가 Grok Bot·Muse 등 에이전트의 VM 터미널을 띄워 그 안에서 직접 로그인한다(결재 기록 Q1). **oort는 토큰을 받지도·저장하지도·중개하지도 않는다.** 앱이 읽는 것은 종료 코드뿐이다(ADR-0191 D2·ADR-0193 D2(a)와 같다). oort 소유 claude.ai OAuth 구현은 하지 않는다(D6).
- **과금 풀은 실측하고 정직하게 보여 준다.** 내 맥 spawn은 workd가 `claude-agent-acp`를 자식으로 띄운다(ADR-0188). 이 어댑터가 Agent SDK 경유라면 위 지원 문서에 따라 구독 한도가 아니라 Agent SDK 월 크레딧으로 과금될 수 있다 [추정]. T0b가 실기기에서 한 세션을 돌려 사용량이 어디에 잡히는지 측정한다. 결과는 **UI 문구에 사실 그대로** 쓴다(예: 「Claude 작업은 구독 한도가 아니라 Agent SDK 크레딧을 쓸 수 있어요」). 측정 전에는 「내 구독으로 실행돼요」를 쓰지 않는다.
- **과금 풀은 이 결정을 바꾸지 않는다.** 소유자 결재(Q1)로 하네스는 구독 연동으로 가는 것이 확정이고, T0b는 문구와 노출 순서의 입력이다. 약관 리스크 기록: ADR-0193 약관 판단은 「앱이 `claude -p`를 구독으로 구동」을 회색으로 보고, 내 맥 spawn을 허용 쪽으로 읽은 것은 worker 해석(Remote Control과 같은 모양)이었다. 이 ADR은 D3-e(`claude -p` 앱 구동 금지)를 풀지 않는다. T0b에서 Claude 하네스 spawn에 별도 약관 문제가 드러나면 그 노출만 보류하고 새 결재를 구한다.

### D6. 이 ADR이 하지 않는 것
- **oort 소유 claude.ai OAuth(Aside식 토큰 캡처) — 기각.** 제3자의 claude.ai 로그인 제공·토큰 수집·저장·중개가 약관상 허용되지 않는다(위 인용). 구독 로그인은 공식 CLI의 자체 흐름이어야 하고 토큰은 기기에 남는다.
- **구독을 팀원과 공유** — 하지 않는다(「나만 쓴다」). 팀이 함께 부르는 AI는 API 키 에이전트다.
- **에이전트가 내 맥의 하네스를 빌려 쓰는 것** — 이번에 정하지 않는다. 별도 결정(성재 확인 필요)과 약관 재검토 뒤.
- **개인 클라우드 작업 공간(ADR-0197)** — 보류 유지. 「맥이 꺼져 있을 때」는 에이전트 대체(D4)로 푼다.
- 사용자가 터미널에서 직접 띄운 `claude` 세션의 oort 추적(Channels 플러그인) — 실험 경로 그대로, 범위 밖.
- 서버가 구독 로그인 상태를 알게 하는 계약 — 만들지 않는다(D3).

## 불변식 대조
| 불변식 | 이 ADR |

### 해석과 바뀌는 점 (기안자 판단)
성재의 말은 본문의 「하네스는 멤버가 아니다」를 한 단계 뒤집는다. 하네스(구독 CLI)가 **소유자가 별칭을 붙이면 부를 수 있는 개인 에이전트**가 된다. 단 두 가지는 본문 그대로다. ① 실행은 항상 소유자 본인의 공식 CLI(내 맥), oort 소유 OAuth는 없다(D5·D6). ② 「나만 쓴다」(D1). 달라지는 것은 **입구**다. 「내 도구 카드 → 작업 요청 시트」만 있던 것에 「@별칭 멘션·DM」이 더해진다. 「물어보기」 별도 탭은 만들지 않는다(성재 인용 1). 이 해석은 아래 결재(「확정하고 시작」)로 확정됐다.

### D7. 개인 에이전트 — 연동한 구독을 별칭으로 노출한다
**무엇인가.** 연결된 하네스 구독(지금 Claude Code·Codex, 이후 감지되는 것)을 소유자가 「개인 에이전트로 쓰기」로 켜면 `member.kind='agent'` 멤버가 하나 생기고 별칭(핸들)을 갖는다(예 `@kwak-claude`). 별칭은 소유자가 정하고 워크스페이스 안에서 유일해야 한다. 이 멤버의 두뇌는 **소유자의 member host에서 도는 그 하네스**다. 새 OAuth·새 토큰 저장은 없다.

**부르는 사람은 소유자뿐이다.**
- 소유자가 자기가 속한 어느 채널·스레드·DM에서든 `@별칭` 멘션, 별칭과의 DM, 별칭에게 하는 작업 요청을 할 수 있다. 에이전트 멤버가 그 채널에 있어야 하는지(멤버 초대 vs 소유자 한정 암묵 허용)는 구현 이슈에서 가르되, **초대는 소유자 본인만 한다**.
- 팀원의 멘션·DM·요청은 **현행 `NonOwner` 안내 문장**으로 거절한다. 작업은 만들지 않는다. 멤버 목록에는 「개인 에이전트 · 소유자만 호출」 표식으로 보이고, `@` 자동완성에는 소유자에게만 후보로 나온다(기본값, 구현에서 확정).

**실행 레인은 member host + ACP다.** 소유자 기기 키 서명 spawn(이 ADR D4의 T5), ADR-0188 레인 그대로. 호스티드(Agent Port) 레인은 쓰지 않는다. 토큰은 기기에 남는다. 폴더는 host의 허용 폴더 id 안에서만 고르고, 별도 지정이 없으면 host가 발급한 「질문용 폴더」(빈 작업 폴더)를 쓴다(그 id는 work-hosts 읽기가 소유자에게 노출한다 — 아래 「N5 확정 (#3590)」).

**멘션이 spawn이 되는 방식(서명 경계를 지킨다).** 멘션은 메시지이고 서버는 소유자 기기 키를 갖고 있지 않다. 그래서 **서버가 멘션을 보고 스스로 spawn을 만들지 않는다.** 소유자의 클라이언트가 `@별칭` 메시지를 보내면서 같은 동작으로 **서명된 spawn 컨트롤**(프롬프트=그 메시지 본문(+소유자가 포함한 스레드 맥락), 하네스, 폴더 id, 채널·스레드·원본 메시지 id)을 work-control 경로로 보낸다. 서버는 D4와 같은 검증(`scope=member`, `host.owner == 요청자`, `revoked_at IS NULL`, 온라인, 서명·논스·만료)을 한다. 서명 키가 없는 클라이언트(예: 키 미등록 웹)에서 보낸 멘션은 메시지로는 남지만 spawn은 일어나지 않고 「서명할 수 있는 기기(내 맥·폰)에서 다시 보내 주세요」를 알린다. 메시지 쓰기 경로(REST send → channel_seq + message + outbox 단일 tx)는 그대로이고, spawn은 별개의 work-control 경로다. 서버가 채널 내용을 긁어 프롬프트에 넣지 않는다(v1).

**기록은 부른 곳에 남긴다.** 세션의 진행·답·산출물은 소유자가 **부른 채널·스레드·DM**에 스레드 답글로 남는다(성재 인용 2). 팀 보드(ADR-0194)와 작업 탭은 기존 work session 투영을 쓴다. **채널에 쓴 요청·답은 그 채널 멤버가 읽는다.** 민감한 일은 소유자가 DM·비공개 채널에서 부른다. UI는 부르기 전 도착지(「내 맥 · <기기 이름> · Claude Code」)와 채널 공개 범위를 입력창 근처에 보인다. 답의 작성자가 별칭 멤버로 표시되는 방식(host가 별칭 멤버 이름으로 게시하는지, 세션 투영의 기존 작성자 규칙을 따르는지)은 [확인 필요] — T5 설계 입력.

**맥이 꺼져 있으면.** 본문 D4·결재 6 그대로 **대기 요청은 없다(v1)**. 소유자에게 「내 맥이 꺼져 있어요」를 보이고, 쓸 수 있는 상시 에이전트(D1 에이전트)가 있으면 그 이름을 후보로 **제안만** 한다. 자동 전송 없음. 이 안내는 소유자 앞 문장이고 채널 전체에 남는 메시지가 아니다(구현에서 확정).

**할 수 있는 일.** 채팅 같은 질의응답, 리서치, 웹 검색·열람, 코드·파일 작업 — 하네스가 하는 모든 것. 허락이 필요한 동작은 기존 `approval_request`·서명 허락 카드를 따른다. 별칭이라고 허락을 건너뛰지 않는다.

**상시 에이전트와 무엇이 다른가(D1은 그대로).** 에이전트 둘이 한 문장으로 갈린다. **그록봇 같은 상시 에이전트는 VM에서 24시간 돌고 팀이 쓴다. 개인 에이전트는 내 구독의 하네스를 내 맥에서 돌려 나만 쓰고, 내 맥이 켜져 있는 동안만 응답한다.** 둘 다 멤버지만 가용성과 호출 범위가 다르므로 UI는 「개인」 표식과 「내 맥 켜짐/꺼짐」을 늘 보인다. 에이전트가 없는 팀(그록봇·dots·Muse·Hermes를 쓰기 어렵거나 연동하기 어려운 팀)도 구독 하나로 비서를 둘 수 있다는 것이 성재 인용 1의 가치다.

**개인 에이전트가 아닌 것.** 팀 공유(D6 유지), oort 소유 OAuth(D6 유지), 내 맥이 꺼졌을 때 대신 실행(결재 6 유지), 에이전트가 내 개인 에이전트를 호출하는 것(에이전트 bearer는 spawn을 만들 수 없다, ADR-0188 D3 유지).

### D2 변경 — 은퇴가 아니라 전환
- `kwak-claude`(`owner_only`·`subscription_harness` 있음)는 **은퇴하지 않고 D7 개인 에이전트로 전환**한다. 같은 멤버 id·핸들을 유지해 과거 메시지·작성자 표기를 잃지 않는다. 호스티드 연결(`pairing_pending`)은 revoke하고 토큰·pairing 값은 폐기한다(본문 D2 3단계의 안전 조치는 그대로). 전환 뒤 이 행은 Agent Port 레인을 쓰지 않는다. **Agent Port를 구독 에이전트의 레인 A로 쓰는 계획은 여기서 끝난다.**
- `@claude-code`(`scope=workspace`, `subscription_harness=NULL`, 연결된 적 없음, VM 에이전트 아님)는 **본문 D2 ②대로 은퇴**한다(결재 7). 이것은 구독 에이전트가 아니라 하네스 이름을 단 hosted 항목이었기 때문에 전환 대상이 아니다.
- 순서: `@claude-code` 은퇴는 먼저 해도 된다(본문 T2 dry-run). `kwak-claude` 전환은 **멘션 라우팅이 서야** 의미가 있으므로 그때 한다(그 사이 행은 지금처럼 응답 없는 상태로 남는다, 잃는 것 없음).

### ADR-0193 D18 — 무엇이 D7 검사로 바뀌고 무엇이 남는가
D18의 서버 차단(전달 시점 `owner_only`+`claude_code`+설정 off → `claude_subscription_agent_paused`)을 갈래별로 정리한다.

| D18 갈래 | D7 이후 |
|---|---|
| ① 멘션·DM·스레드 멘션의 `owner_only_gate`(`ClaudePaused`) | **개인 에이전트 멤버에는 적용하지 않고 D7 검사가 대신한다.** 순서: (1) 요청자 ≠ 소유자면 기존 `NonOwner` 안내(변경 없음, 먼저) (2) 소유자면 spawn 서명 검증·`scope=member`·`host.owner==요청자`·온라인 (3) 실패 시 이유를 소유자에게 말한다. hosted job은 만들지 않는다. |
| ③ 작업 요청 `POST …/agent-runs`의 409 | **유지.** 개인 에이전트는 `agent-runs`로 가지 않는다(작업 요청은 spawn). 호스티드 레인의 구독 행 방어선이다. |
| ② hosted 수신함 fan-out·환영 대사·완료 응답, ④ `hosted_dm_delivery`, ⑤ Agent Port 도구 목록 비움 | **유지.** 개인 에이전트는 hosted 수신함·Agent Port에 들어가지 않으므로 닫힌 채로 둔다. `hosted_dm_delivery`는 개인 에이전트에 `mac_offline`/`ready` 상태를 돌려주는 분기가 필요한지 구현에서 판단한다. |
| 공용 host 갈래(#3431/#3457/#3460/#3477, `scope<>member`의 Claude spawn·input·allow_once·controller attach) | **전부 유지.** D7은 member host 하나만 연다. 워크스페이스·클라우드 host의 Claude는 계속 막는다. |
| 팀원이 내 구독을 쓰는 모든 경로 | **유지.** `NonOwner`. |
| `MOMO_CLAUDE_SUBSCRIPTION_AGENTS_ENABLED`(기본 off) | **D7을 켜고 끄는 값이 아니다.** hosted 레인에 남은 행의 방어선으로만 둔다. 정리는 T7. |

D7의 소유자 호출은 본문 D2가 이미 정한 「member host 레인은 D18이 막지 않는다」(결재 2026-10-03 「본인 사용이라 허용」)의 연장이다. 다만 멘션·DM으로 트리거되는 것은 그 결재가 명시적으로 다룬 「소유자가 서명한 지시」보다 입구가 넓으므로, **각 호출이 소유자 기기 키 서명을 동반한다는 점이 이 확장의 근거**이고 T5 보안 검수가 이를 확인해야 한다. 약관 쪽 열린 질문(D5, `claude -p` 앱 구동 금지·Agent SDK 크레딧)은 T0b 결과를 따르며 D7이 풀지 않는다.

### 서명 요구 플래그 — 보안 검수 뒤에 켠다
`require signed controls`(ADR-0146 `MOMO_HUMAN_CONTROL_SIGNATURE_REQUIRED`와 인스턴스 id)는 **oort-team에서 T5의 보안 검수가 끝난 뒤에** 켠다(성재 인용 3). 래칫이라 켜면 서명 없는 클라이언트의 허락·재개도 막히고 되돌림은 로컬 작업이다. 결과로, 켜기 전에는 폰이 허락·지시 카드를 그리지 않는 현 동작(`SignedWorkControls`가 요구 플래그에 종속)이 이어진다. 즉 **폰에서의 승인·후속 지시는 플래그 이후**이고 읽기·스트리밍·대화 화면은 그 전에 올릴 수 있다. 플래그와 별개로 키가 등록된 폰에 카드를 보이는 완화가 가능한지는 [확인 필요](T5 검수 입력).

### 그록봇 테스트 범위
그록봇 시나리오(B)는 **승인 채널까지**(성재 인용 4) — 연결·채널 승인·작업 요청·단계·산출물·푸시까지 시험하고, 그 밖의 채널·DM 승인 확장은 하지 않는다. 그록봇·Hermes를 **호스팅하고 oort에 연결하는 방법 가이드**는 별도 에픽 **#3582**가 맡는다. 이 ADR은 가이드를 쓰지 않는다.

### N5 확정 (#3590) — 폴더 읽기와 집 채널 규칙
증보 1 안의 구현 사실이며 새 결정이 아니다. 근거는 ADR-0188 D6(서버에 경로 없음)·§8.8(남의 개인 맥은 존재만), ADR-0190 D4-b(집 채널), 본 ADR D7(질문용 폴더, 부른 곳 기록)이다.

**실측(2026-10-07, `track/engine` c250e774d).** 이슈 본문의 「host가 발급한 허용 폴더 id」는 **코드에 없었다.** host(`momo-workd`)는 설정의 `working_directory` 절대경로 하나만 갖고 매 spawn마다 `realpath`로 열며, 폴더 id·표시 이름 개념이 없다. 서버에는 폴더 열이 없고(`work_host.capabilities`는 불리언만, heartbeat 본문은 비어 있었다) 등록 요청도 폴더를 싣지 않는다. 그래서 N5는 읽기만이 아니라 host가 발급해 알리는 반쪽도 같이 한다. **서명 spawn이 폴더 id를 경로로 푸는 일은 T5(#3570)이고 이 PR은 spawn을 바꾸지 않는다**(세션은 지금도 `working_directory`를 연다).

**전송과 저장.**
- host는 서명된 v2 heartbeat 본문 `{folders:[{id, displayName, kind}]}`로 알린다(본문 digest가 서명에 들어 있고 새 서명 경로가 없다). `folders`가 없거나 본문이 비면 저장분을 그대로 두고 `[]`면 비운다. 최대 32개, `question`은 호스트당 하나.
- 새 테넌트 테이블 `work_host_folder`(migration 121, RLS FORCE). `folder_id`는 `[A-Za-z0-9_-]{1,64}`, `display_name`은 1…80자에 경로 구분자·제어문자 금지를 **DB CHECK로도** 둔다. 경로를 이름·id·`path` 필드로 보내면 400이고 값을 되돌려 말하지 않는다. 이름은 슬래시 모양 문자(U+2044·2215·FF0F 등)와 보이지 않거나 방향을 바꾸는 서식 문자(Cf: U+202E·제로폭 등)도 거부하고, 이 집합은 `momo_wire::folder_name` 한 곳에서 server·workd·DB CHECK가 같이 쓴다(시험이 모든 범위를 DB에 먹인다). 폴더 행은 `(host_id, workspace_id)` 복합 FK로 같은 워크스페이스의 호스트만 가리키고, 호스트가 해지되면 같은 트랜잭션에서 지운다.
- host는 id를 처음 볼 때 무작위로 발급해 상태 폴더 `folders.json`(0600)에 경로와 함께 기억한다. 경로는 이 Mac 밖으로 나가지 않는다.

**읽기 가림.** `GET …/work-hosts`·revoke 응답의 `folders`·`defaultFolderId`는 **그 호스트의 소유자 본인에게, 해지되지 않은 호스트에서만** 나간다. 남의 개인 맥은 §8.8의 같은 함수(`dto_for_viewer`)에서 None으로 지워져 관리자도 받지 못하고, 팀 호스트(`scope=workspace`)도 소유자 외에는 받지 못한다(spawn 대상은 어차피 소유자의 member host다). 남의 호스트의 폴더는 조회조차 하지 않는다.

**「질문용 폴더」 기본값 규칙.**
1. host가 상태 폴더 아래에 만든 빈 폴더(`kind=question`, 이름 「질문용 폴더」)가 호스트당 하나 있다.
2. 서버의 `defaultFolderId`는 그 폴더의 id이고, host가 `question` 폴더를 알리지 않았으면 **없음**이다. 프로젝트 폴더로 조용히 대신하지 않는다. 클라이언트는 없음일 때 소유자에게 고르게 한다.
3. 프로젝트 폴더에 일을 맡기는 요청에는 서버 기본값이 없다. 클라이언트가 마지막에 쓴 폴더를 기기에만 기억해 미리 선택할 수 있다(ADR-0174, 서버는 대응을 저장하지 않는다).
4. 개인 에이전트(D7)·「내 도구」 질문은 폴더를 따로 고르지 않으면 규칙 2를 쓴다.

**집 채널 규칙(현 서버 제약 실측).**
- 집 채널은 필수다. `work_session.channel_id`가 NOT NULL이고, 세션 생성은 주인이 그 채널의 활성 멤버여야 통과한다(`work_sessions` `active channel membership required`). 서명 spawn 컨트롤도 채널을 싣는다.
- **나와의 DM은 없다.** `POST /dms`는 자기 자신을 대상으로 하면 DB 접근 전에 400이다(`validate_direct_message_target`).
- 그래서 별칭 없는 **「내 도구」 직접 세션**(폰 시트·T6b 포함)은 소유자가 속한 채널 중 하나를 고른다. 기본값은 ADR-0190 D4-b 그대로 「이 저장소(폴더)로 마지막에 쓴 채널」이고 기기에만 기억하며, 처음이거나 기억이 없으면(폰 포함) 고르게 한다. 고르기 전에 채널 공개 범위(그 채널 멤버가 읽는다, D7·결재 3)를 보인다. 다른 사람과의 DM을 임시 집으로 삼으라고 권하지 않는다. 읽는 쪽이 생기기 때문이다.
- **개인 에이전트**는 소유자가 부른 채널·스레드·DM이 집 채널이다(D7). 별칭 멤버는 소유자와 다른 멤버 id이므로 그 DM은 자기 자신 DM 제약에 걸리지 않는다. 다만 별칭 멤버는 P2(#3591)가 만들기 전에는 존재하지 않고, 에이전트 멤버의 채널 참여 방식(초대 vs 암묵 허용)은 위 「열린 확인」대로 P2·P1이 정한다. 이 PR은 정하지 않는다.
- 새 읽기 API는 만들지 않는다. 후보 채널은 기존 채널 목록에서 소유자가 활성 멤버이고 글을 쓸 수 있는 것만 클라이언트가 거른다.

**미검증·남는 위험.** 질문용 폴더가 세션 사이에 같은 폴더라 앞 질문의 파일이 남는다. 세션마다 새 하위 폴더나 worktree를 쓸지는 T5가 정한다(D6 「세션당 worktree」). host가 틀린 announcement를 보내면 서버가 400을 돌려 그 박동은 온라인으로 치지 않는다(host가 같은 검증을 설정 로드 때 한다). 별칭 DM 왕복과 실기기는 runtime-unverified.

### T5 확정 (#3570) — 서명 새 작업 spawn
증보 1 안의 구현 사실이며 새 결정이 아니다. 근거는 본 ADR D1(하네스는 멤버가 아니다)·D4(내 맥으로의 spawn은 소유자 서명)·D7(멘션·DM 트리거 입력과 서명 대상 확장), ADR-0146(사람 기기 키 서명 R2, E8의 빈칸), ADR-0188 D3·D6이다. 서명 규격과 DB 제약을 바꾸므로 여기에 적는다. **서명 요구 플래그는 이 PR이 켜지 않는다**(#3593, T5 보안 검수 뒤).

**1. 규격: `momo.human.control.v4`, 새 작업 spawn 전용.** 13줄 프레임은 v3와 같고 첫 줄만 v4다. 본문은 여덟 줄이다.

```
{agent_member_id | -}
{folder_id}
{tool}
{channel_id}
{thread_root_id | -}
{origin_message_id | -}
{NFC(label)}
{NFC(prompt)}
```

- `tool`(하네스)·`folder_id`(허용 폴더 id)·`channel_id`(집 채널)·`thread_root_id`·`origin_message_id`·**제목(`label`)**·**프롬프트 전체**가 서명 대상이다. 제목은 카드에 보이는 한 줄이라 서버가 바꿔치면 소유자가 시키지 않은 말이 소유자 이름으로 보이므로 서명한다(보안 검수 M-2). 제목은 서버가 저장하는 모양(앞뒤 공백 없음, NFC, 제어 문자 없음, 한 줄)으로만 받는다. 세션 줄은 `-`다(세션은 host가 일을 시작한 뒤에 생긴다).
- **에이전트가 없는 「내 도구」(D1)는 `-`다. nil UUID 같은 가짜 id를 쓰지 않는다.** D1은 하네스에 멤버 id가 없다고 했고, 개인 에이전트(D7)는 별칭 멤버 id를 싣는다. 둘을 같은 본문이 구분한다.
- v2 spawn 본문은 **재개**의 것으로 남는다(에이전트 필수, 120자 제목). 서로 대신하지 않는다. 새 작업 본문은 v4에서만 만들어지고, v4 프레임은 다른 kind를 만들지 않으므로 v2·v3 서명이 새 작업을 대신할 수도, v4 서명이 재개·지시·허락을 대신할 수도 없다. 시험이 세 verifier(`momo-wire`·서버 `momo-auth`·`momo-workd`)에서 이를 고정한다.
- 클라이언트(폰·데스크탑)의 v4 서명자와 공유 벡터 파일은 이 PR에 없다. 바이트 계약은 `momo-wire` 시험의 골든 문자열이다. T6·P1이 그 계약에 맞춘다.

**2. 저장(migration 122).** `work_control.payload`의 spawn 팔이 선택 키 `prompt`(1…32768자, `input` 한도)를 받는다. 제목(`label`, 120자)은 카드 제목으로 남고 v4 서명이 묶는다. 스레드·원본 메시지는 payload가 아니라 열(`human_spawn_thread_root_id`, `human_spawn_origin_message_id`)에 둔다(095의 서명 열과 같은 이유: payload는 host가 실행하는 내용). 규칙은 CHECK로 DB가 지킨다. **`prompt`가 있는 spawn이 새 작업이다**: 서명 행에만 있을 수 있고(서명 없는 컨트롤은 프롬프트를 못 가진다), 새 작업만 에이전트를 NULL로 둘 수 있으며 스레드·원본 열은 새 작업만 가진다. 재개(프롬프트 없음)는 서명 시 에이전트가 필수이고 위치 열이 없다.

**3. 서버 경로: `POST /v1/workspaces/{ws}/work-spawns`.** 사람 bearer 전용(`required_agent_scope`와 host 서명 allow-list에 없고 핸들러도 사람이 아니면 거부, 서명 키는 요청자 본인 것이어야 한다). `MOMO_HUMAN_CONTROL_SIGNATURE_REQUIRED`가 꺼져 있으면 403 `signed_spawn_disabled`. 거부는 모두 nonce를 쓰기 전이고, 서명 검증이 마지막이다.
- **host는 도출한다.** 요청자 본인의 `scope=member` host(`owner == 요청자`·미폐기) 중 서명된 폴더 id를 발급한 것이다. `targetHostId`는 좁히기만 한다. 요청자 본인의 member host가 하나도 없으면 404 `spawn_host_not_found`, 본인 host 중 그 폴더 id를 발급한 것이 없으면 404 `spawn_folder_not_found`다. 두 코드 모두 **요청자 본인의 데이터만** 말한다. 남의 host·남의 폴더 id·팀 공용 host는 후보에 오르지 않으므로 존재 여부가 드러나지 않고(남의 폴더 id는 없는 id와 같은 `spawn_folder_not_found`), 팀원이 남의 맥으로 가는 길은 없다. 온라인은 `work_host_online_sql` 한 식(90초 창, T4)이고 오프라인이면 409 `work_host_offline`(같은 서명으로 다시 보내면 된다).
- **폴더**는 그 host가 발표한 `work_host_folder`의 id여야 한다. 서버는 경로를 모른다.
- **에이전트**가 이름으로 올라오면 요청자 소유의 살아 있는 `owner_only` 에이전트이고 `subscription_harness`가 도구와 맞아야 한다(claude_code ↔ Claude, codex ↔ Claude 아님). P2(#3591)에 기대지 않고 089의 행 모양을 쓴다.
- **위치**: 원본 메시지는 요청자 본인이 이 방에 쓴 일반 메시지(ADR-0188 D3 「소유자가 사람 bearer로 쓴 일반 메시지에서만」)이고, 서명의 스레드는 그 메시지가 속한 스레드와 같아야 한다.
- 방(집 채널) 활성 멤버십, 도구 등록·활성, 원격 shell 거부(D6), 슬롯 입장(`acquire_slot_in_tx`, 0188 D4)을 거친다. 같은 nonce의 같은 요청은 재시도로 200(`replayed`), 다른 요청이면 409 `spawn_nonce_reused`.
- **메시지 경로를 거치지 않는다.** `work_control` 행, nonce, `action_signature`, 감사 행(프롬프트 본문은 넣지 않는다)만 쓰고 `channel_seq`·message·outbox는 건드리지 않는다. host는 `pending-controls` 폴링으로 받는다. 방에 가는 `work.control.*` 이벤트는 프롬프트를 싣지 않는다(제목·하네스만).
- host가 만든 세션은 기존 host 서명 생성 경로가 받는다(`dispatched_spawn_owner_in_tx`에 **사람 요청자 arm**: 서명된 새 작업 + 요청자 본인의 살아 있는 member host일 때만 세션 소유자가 요청자). ack 매처도 같은 행에 한해 신규 세션을 받는다.

**4. workd 검증과 폴더.**
- 프롬프트를 가진 spawn은 **host가 R2 설정과 무관하게 직접 서명을 검증**한다. 폴더 id는 검증된 봉투에서만 읽는다. 서명이 없으면 `device_signature_required`, 뿌리가 고정되지 않았으면 `device_root_not_pinned`다.
- **폴더 id → 경로는 workd 안에서만** 풀고(`FolderBook::resolve_for_spawn`) 매 spawn마다 한다. 모르는 id는 거부하고 설정 폴더로 조용히 대신하지 않는다. 프로젝트 폴더는 `realpath`가 발급 때와 같고 디렉터리여야 한다(바뀐 링크는 `folder_unsafe`). 재개는 종전대로 설정 폴더다.
- **질문용 폴더(N5 L3 이월):** spawn마다 `symlink_metadata`로 심볼릭 링크가 아닌 실제 디렉터리인지, 이 사용자 소유인지 확인하고, 모드만 어긋났으면 0700으로 재설정하며, 그 외에는 거부한다. `FolderBook::open`도 같은 검사를 하고 어긋나면 host가 시작하지 않는다. **세션마다 그 아래 새 0700 하위 폴더**(컨트롤 id로 이름)를 쓴다(N5의 「앞 질문의 파일이 남는다」 위험을 닫는다). 하위 폴더 정리(오래된 것 삭제)는 하지 않는다. 프로젝트 폴더의 「세션당 git worktree」(0188 D6)는 이 PR 범위 밖이다.
- **`folders.json` 손상(N5 L5 이월):** 파싱 실패, 발급될 수 없는 id, 한 id가 두 폴더에 붙은 경우는 **오류**다. host는 시작하지 않고 경로 없는 문장으로 「`folders.json`을 옮기고 다시 시작하면 id를 다시 발급해요」를 알린다. 다시 발급한 뒤 옛 id를 든 서명 spawn은 모르는 id로 거부된다.

**5. 보안 검수 입력(#3593 전).** 서명이 묶는 것과 묶지 않는 것을 구분해 본다. 묶음: 프롬프트·제목·하네스·폴더 id·방·스레드·원본 메시지·에이전트(또는 없음)·host·요청자·nonce·만료. 묶지 않음: 폴더가 이 Mac에서 어느 경로인지(host 몫). 서버가 메시지로 spawn을 만들지 않는다는 것(D7), 에이전트 bearer·팀원이 길이 없다는 것, 서버 신호 없이도 host가 새 작업을 직접 검증한다는 것을 확인 대상으로 둔다.

- **입력 위생(L-2):** 프롬프트는 줄바꿈·탭 외의 제어 문자(U+0000 포함)를, 제목은 모든 제어 문자를 서명 검증 전에 400(`spawn_prompt_invalid`·`spawn_label_invalid`)으로 거부한다.
- **같은 nonce 동시 두 요청(M-3):** nonce 소비가 직렬화해 `work_control`은 정확히 1행이고, 진 쪽은 200(재시도)이거나 409(`device_nonce_replayed`)다.
- **`prompt`가 빠지거나 문자열이 아닌 v4 컨트롤(M-1):** 서명을 요구하도록 잠긴 host에서는 거부된다(키가 빠지면 재개 모양이 되어 v2 문장을 v4 서명이 만족하지 못하고, 문자열이 아니면 새 작업 모양의 오류다). **잠기지 않은 host(서명 요구가 아직 래칫으로 걸리지 않음)에서는** 키가 빠진 컨트롤을 서명 검증 없는 옛 spawn으로 취급해 설정 폴더에서 실행한다. 이는 R2가 꺼진 host의 기존 동작이고(서버는 거기에 서명 없는 spawn을 원래 넣을 수 있다), 값이 문자열이 아닌 `prompt`는 잠금과 무관하게 거부한다. **서버 플래그를 켤 때 모든 member host가 실제로 잠기는지, 풀리지 않는지는 #3593의 켜기 전 필수 실측이다.**
- **질문용 하위 폴더(L-3):** 컨트롤 id 이름의 하위 폴더가 이미 있으면 재사용하지 않고 `folder_unsafe`로 거부한다(심어 둔 폴더·이전 실행 잔재).

**6. 별칭 멤버 답의 작성자 표시 규칙(확정).**
- 서명에 에이전트 id가 있으면(개인 에이전트 호출) 세션의 카드·진행·답의 **표시 작성자는 그 별칭 멤버**다. 작성자는 **서버가 서명된 컨트롤의 `agentMemberId`로 도출**한다. host는 작성자를 보내지도 고르지도 않으므로 별칭을 사칭할 수 없다(host 서명 경로는 소유자의 세션 소유권을 이미 서버에서 도출한다).
- 에이전트 id가 없으면(「내 도구」 직접 세션) 기존 세션 투영 규칙을 그대로 따른다(소유자가 주인인 세션의 시스템 카드).
- 기록 위치는 서명된 `thread_root_id`·`origin_message_id`다. 스레드 안에서 불렀으면 그 스레드에, 방의 본 줄에서 불렀으면 원본 메시지 아래에 스레드 답글로 남긴다.
- 별칭 멤버가 그 채널의 활성 멤버가 아니면 표시 작성자는 소유자로 두고 별칭 표시는 하지 않는다(멤버 참여 방식은 P2·P1이 정한다).
- **이 PR은 규칙과 그 데이터(서명된 에이전트·스레드·원본 메시지를 컨트롤에 저장하고 host에 전달)까지만 한다.** 세션 카드·이벤트에 작성자·스레드를 적용하는 것은 멘션 라우팅 본체(#3592, P1)다. 그 전의 세션 카드는 지금처럼 방에 소유자 이름으로 남는다.

**미검증(`runtime-unverified`).** 실기기·실제 ACP 왕복(host 상태 폴더 안의 질문용 폴더에서 에이전트가 도는 것), v4 클라이언트 서명자(폰·데스크탑), 별칭 멤버 표시, 스레드 답글 위치. 서명 요구 플래그가 꺼져 있는 동안 새 작업 경로는 닫혀 있다.

## 증보 2 (2026-10-08) — 워크스페이스 단위 「실행 엔진」 설정 API 제거 (#3584)

D1(하네스 = 내 도구)과 D4(작업은 내 맥 우선, 호스트 소유자 == 요청자)가 확정한 결과로, 워크스페이스가 하나의 실행 엔진(opencode·goose·codex-local)을 골라 모두에게 적용하는 모델은 폐기한다. 성재 지시(#3578 S0, 2026-10-07): 「opencode goose codex-local 이런건 어찌보면 조금 옛날 레거시의 잔재 같은데 그 부분도 해소해줘.」.

- **제거**: `GET·PUT /v1/provider/work-host-engine`(공개 API)와 그 코드(`momo-settings::engine`, DTO, 라우트, 시험, undocumented 허용목록). 호출자는 uxui 트랙의 S4(#3611)가 이미 제거했고(클라 UI·core API 함수), 두 트랙 승격 뒤에 정합한다. 승격 전 구 클라이언트는 이 경로를 404로 받는다.
- **소비자**: 이 설정을 읽는 서버·workd 코드는 없었다(`server-rust` 전체에서 `work_host_engine`·`WorkEngine`·`MOMO_WORKD_ENGINE` 참조는 제거 대상 파일뿐이다. `momo-workd`·시험의 `opencode`는 `work_tool_profile`(migration 029)의 도구 어휘이고, `momo-t3`의 `HARNESSES`도 별개라서 유지).
- **DB**: forward-only. `work_host_engine` 테이블(migration 040)은 삭제하지 않고 **미사용**으로 둔다. 쓰는 코드가 없으며 RLS FORCE 정책은 그대로다. 테이블 삭제는 필요해질 때 신규 migration으로 한다.
- 이 증보는 D1·D4의 귀결이며 새 방향을 정하지 않는다.
