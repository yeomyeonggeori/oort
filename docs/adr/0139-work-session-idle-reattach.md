# ADR-0139: Work 세션 idle 유지·재부착·스크롤백 replay

- Status: **Proposed** (2026-07-28, 기안 Fable — 성재 D1 지시의 ADR화. 이슈 #853)
- 관련: ADR-0114(세션=스레드·D6 터미널 병행), ADR-0125(D10 바이트 비경유·D11 git 계보 재개 — 본 ADR은 **증보**이지 대체가 아님), ADR-0136(활성시간 원장 — D4가 접합), `docs/security/README.ko.md`("실행 내용 미보관" 주장 유지가 제약)
- 발단: 성재 지시(2026-07-28) — "폰이든 맥이든 요청하면 닫더라도 완료까진 돌아야지. 작업이 끝나면 감지해서 idle 상태로 있다가, 맥북 열고 들어오면 다시 작업 재개할 수 있는 것처럼."

## Context

- 실행 주체가 호스트(T2 데몬/T3 샌드박스)면 클라이언트를 닫아도 완료까지 도는 것은 **이미 성립**한다. 호스트 사망 경로도 완성돼 있다(sweep→`orphaned`→`resume_offer` 푸시→`resume` REST→`resumed_from_session_id` 계보 — MOMO-519/520 랜딩).
- 공백은 둘: ① `work_session.status ∈ {running, orphaned, ended}`라 **완료=곧 세션 종료** — "끝난 뒤 살아 있다가 돌아오면 이어 쓰는" 상태가 없다. ② 재부착 시 **직전 화면(스크롤백)** 이 없다 — 서버는 설계상 PTY 바이트를 나르지 않고(D10), 호스트 데몬에 버퍼가 없다.

## Decision (Proposed 권고안)

### D1. `idle` 상태 도입 — 도구 종료 ≠ 세션 종료
- **A (권고)**: PTY를 **셸 래핑**으로 연다 — 도구 프로세스가 끝나면 셸 프롬프트로 돌아오고 세션은 `idle`로 전이한다. PTY·workdir·스크롤백이 살아 있으므로 재부착이 곧 "이어서 쓰기"다(같은 터미널에서 다음 명령·같은 도구 재기동). `running→idle→running` 왕복 허용. idle 타임아웃(기본 24h, 워크스페이스 설정) 초과 시 `ended(idle_timeout)`. 소유자만 재부착해 입력 가능(관전은 기존 observation 규칙).
- B — 도구 종료 시 PTY도 닫고 idle=메타데이터+스크롤백만: "이어서"가 새 PTY spawn이 됨. 체감이 재개가 아니라 재시작. **기각.**
- 상태 모델: `running | idle | orphaned | ended`. `exit_code`는 **마지막 도구 실행의 결과**로 의미 재정의(세션 종료 코드가 아님). sweep은 idle에도 host heartbeat 단절 시 `orphaned` 전이를 동일 적용.
- 완료 감지 푸시: 기존 NotifierWorker 수명주기 푸시에 "완료 — idle 대기" 이벤트 추가(id-only 봉투, ADR-0120 유지).

### D2. 스크롤백 = **호스트 로컬 링버퍼 + attach replay** (D10 유지)
- **A (권고)**: 호스트 데몬이 PTY별 링버퍼(기본 256KiB, 상한 설정 가능)를 유지하고, `connect(ptyID)` 시 **버퍼 replay 후 라이브 스트림**을 잇는다. 서버·relay는 여전히 바이트를 만지지 않는다 — `docs/security/README.ko.md`의 "실행 내용 미보관"이 그대로 참. T3는 샌드박스 볼륨에 얹혀 pause를 견딘다.
- B — 서버 영속: 어느 기기든 완전 복원되지만 실행 출력(토큰·키 혼입)의 저장·감사·삭제 정책이 따라오고 D10 정면 개정. **기각(별건 재론 가능).**
- replay와 라이브의 경계는 프로토콜에 명시(중복·유실 없는 이음새) — 구현 티켓에서 계약 고정.

### D3. 재부착 vs 계보 재개 — 분기 명문화
- 호스트 **살아 있음** + `running|idle` → **재부착**(같은 PTY, D2 replay). 호스트 **죽음** → `orphaned` → **git 계보 재개**(D11 기존 그대로, PTY 상태 이전 없음·미커밋 손실 고지).
- UI 문구도 분리: "이어서 보기/쓰기"(재부착) vs "새 호스트에서 재개"(계보). 같은 버튼에 섞지 않는다.

### D4. T3에서 idle = **샌드박스 pause**, pause 중 활성시간 미계상
- E2B pause/resume(keep_memory) sub-second·Blaxel 0-컴퓨트 스탠바이 실측(research/17-01). idle 진입 시 프로비저너가 pause, 재부착 시 resume.
- **원장 규칙: pause 구간은 활성시간(H)에 세지 않는다.** ADR-0136 D2 원장 스키마가 이 구간을 표현해야 한다(#855에 요구사항 전달됨). 과금 신뢰: idle을 이유로 한 자동 과금 없음.

## Consequences
- (+) "닫아도 돌고, 끝나면 기다리고, 돌아오면 이어 쓴다"가 T1~T3 동일 문법. (+) 서버 불변식·보안 문서 주장 무변경. (+) 기존 orphaned/재개 자산 재사용.
- (−) 호스트 데몬 복잡도 증가(셸 래핑·링버퍼·이음새 계약). (−) idle 세션은 호스트 자원 점유 — 타임아웃·상한이 필요. (−) 상태 4번째 값이 전 클라이언트 표면에 파급(웹 상태 칩·목록·게이트).

## 이행 (Accepted 시)
1. 엔진: 마이그레이션(status CHECK 확장·`end_reason='idle_timeout'`)+수명주기 REST/이벤트 · 2. 호스트 데몬: 셸 래핑+링버퍼+replay 계약 · 3. 웹: idle 표시·재부착 동선(#851 표면에 얹음) · 4. T3: pause 훅(#855와 접합). 순서 1→2→3, 4는 #855 진도와 병행.
