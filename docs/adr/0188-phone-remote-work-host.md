## 1. 문제

### 1.1 있는 것
- **서버의 work host 계약은 Rust로 거의 다 있고 마운트돼 있다.**
  - 등록(사람 토큰 + Ed25519 공개키), 서명 heartbeat, `pending-controls` 폴링
  - 세션 생성·PATCH(ACP 이벤트 포함)·resume
  - 컨트롤 원장(`spawn|input|read|kill`, 020 `kind_ck`와 029 `payload_ck`), 승인 폐곡선
  - 서명은 v2다. method·path·workspace·host·시각·body SHA-256·request id를 덮고, request id는 서명 검증과 같은 tx에서 1회 소비된다.
    - #875의 본체 결함(body·nonce 미인증)은 코드에서 닫혔다.
    - 다만 query 문자열은 서명 밖이고 heartbeat는 v1이라 이슈는 OPEN이다.
- **폰(RN):**
  - 작업 목록과 세션 상세가 있다. 다만 폴링·읽기 전용이고, #2166 기본 숨김이다.
  - spawn 승인과 host 선택, 턴 중단이 있다.
  - 푸시 액션에는 클라이언트 쪽 Face ID 게이트가 있다.

### 1.2 없는 것
- **데스크탑에서 세션을 실제로 돌리는 프로그램.** Swift `WorkHostDaemon`(ACP 클라이언트·Codex/OpenCode 어댑터·PTY 링버퍼)은 #2165로 삭제됐다. Rust 바이너리 7개와 Tauri 셸 어디에도 host가 없다.
- **사람이 폰에서 시키는 경로.** 컨트롤 생성은 agent bearer만 받는다(`routes/work_controls.rs` `create`).
- **ACP 권한 요청의 승인화.** 지금은 System 메시지로만 저장돼 푸시도 없다. 결정을 host로 돌려보낼 컨트롤 종류도 없다.
- **host 재시작 복구 경로.** `live-sessions`·`reconcile`이 미이식이다. heartbeat v1은 재전송하면 죽은 host가 약 5분 더 살아 보인다.
- **Railway 템플릿의 notifier·push relay.**

### 1.3 오늘 코드에 있는 위험 — 이 ADR이 먼저 막는다
- **승인 결정자가 「그 채널의 활성 사람 멤버」다**(`routes/approvals.rs` `is_active_channel_member_in_tx`). 권한 요청 승인은 오늘 아직 없다. 대신 **팀원 누구나** 소유자 맥으로 가는 spawn 승인과 host 선택을 결정할 수 있다. 판정 기준은 최종 선택된 host다.
- **에이전트의 input·read·kill은 승인이 없다.** spawn도 `work_auto_approve`가 켜져 있으면 즉시 나간다.
- **029가 `shell`(`sh`) 프로필을 기본으로 시드한다.** 서버 `launch_template` 검사는 권한 우회 플래그나 `sh -c`를 막지 않는다.

### 1.4 시장의 답
Codex와 Claude 모두 VPN을 쓰지 않는다.
- 에이전트가 도는 기기가 **밖으로** 벤더 클라우드에 연결한다.
- 폰은 그 클라우드를 거친다.
- 공통 문법은 여섯 가지다.
  1. host 목록과 온라인 점
  2. 「나를 기다리는 것」 우선 목록
  3. 범위가 있는 승인 카드
  4. 끼어들기와 다음 차례 예약의 구분
  5. host가 계산하는 diff
  6. 행동이 필요할 때의 푸시
- 두 제품 모두 명령 단위 암호 서명은 없다.

oort는 벤더 클라우드 자리에 **팀 자신의 Railway 서버**가 있으므로 제3자 중계가 필요 없다.

## 2. 결정 (권고안)

### D1. 토폴로지 — host는 팀 서버로만 다이얼하고, 서버가 유일한 중계다
- host는 팀 서버에 outbound HTTPS로 다음을 한다. 인바운드 포트는 열지 않는다(ADR-0125 D1).
  - 등록
  - heartbeat
  - 컨트롤 수신
  - 결과 기록
- 폰·웹·데스크탑은 같은 서버 URL만 안다. **제어 경로에 Tailscale이 없다.**
- **폰에는 raw 터미널 바이트가 가지 않는다.** 폰은 큐레이션된 이벤트 흐름을 본다(ADR-0137·0114 D3). ADR-0125 D10(서버는 터미널 바이트를 싣지 않는다)은 유지한다.

### D2. host의 실체 — Rust `momo-workd`, 데스크탑 앱이 싣고 켠다
- **`server-rust/bins/momo-workd`를 새로 둔다.**
  - `momo-wire` 서명을 서버와 공유한다.
  - 하는 일은 키 보관·v2 서명, heartbeat, 컨트롤 수신·ack, 세션 생성·PATCH, **ACP 클라이언트**(ADR-0130 D1)다.
  - ACP 클라이언트로 `claude`·`codex` 어댑터를 stdio로 구동한다.
- **Tauri 앱이 이 바이너리를 sidecar로 번들하고, 서명·공증도 함께 한다.**
  - 첫 단계에는 앱이 자식 프로세스로 켠다.
  - 다음 단계에서는 사용자가 「앱을 닫아도 작업 유지」를 켜면 launchd LaunchAgent로 등록한다.
- **host 키는 서명된 앱과 sidecar만 읽는 `ThisDeviceOnly` 키체인 항목에 둔다.** 서버에는 공개키만 간다.
- **workd는 TCP 포트를 열지 않는다(localhost 포함).** 앱과는 사용자 전용 Unix 소켓과 상대의 코드서명 확인으로만 통신한다.
- **host 등록 사실은 소유자의 모든 기기에 알린다.**

### D3. 누가 시키고 누가 승인하나 — host 소유자 본인만
- **소유자:** host는 `scope=member`로 등록하고, 등록한 **사람 멤버가 소유자**다. 이 ADR의 「원격 host」는 `scope='member'`인 모든 host다. 팀 공용 host(`scope=workspace`)는 목표 A 밖이다.
- **결정자 = 소유자(불변식).** 폰 원격 작업의 첫 번째 방어선이다.
  - `permission` 승인과 member-scope host로 가는 spawn 승인은 **host 소유자 본인만** 결정한다(ADR-0114 D5 보강).
  - 채널 멤버십이나 관리자 역할로 대신할 수 없다.
  - 결정 라우트는 사람 principal만 받고, host 서명 allow-list에 넣지 않는다.
  - `permission` 컨트롤은 그 결정 tx 안에서 **서버만** 만든다.
- **에이전트 컨트롤은 kill만(불변식).** member-scope host로 가는 agent bearer 컨트롤은 `kill`만 받는다. 이 범위에서 ADR-0114 D4·D5(에이전트의 input·read 무승인)를 대체한다.
- **사람 컨트롤(`input`·`kill`·`read`·새 작업)을 연다.** 조건은 세 가지다.
  - 소유자 본인
  - 인증된 기기 세션
  - `revoked_at` 없이 온라인인 host
  - 대상 host는 요청이 아니라 **세션 행에서 서버가 도출**한다.
- **무엇이 소유자의 지시인가(불변식).**
  - input·spawn은 소유자가 **사람 bearer로 쓴 일반 메시지**에서만 만든다.
  - System 메시지, 다른 멤버·에이전트·웹훅·도어벨의 메시지는 세션에 넣지 않는다.
  - 원격 host에는 `work_auto_approve`를 적용하지 않는다.
  - 세션 스레드와 에이전트 DM의 메시지는 기기 키 서명(R2)이 없으면 input·spawn이 되지 않는다. 잠긴 폰의 알림 답장 액션도 마찬가지다.
- **기기 신뢰:**
  - Face ID는 분실 대책이지 탈취 대책이 아니다(클라이언트 게이트).
  - **R1 진입 조건:** refresh 토큰 재사용이 보이면 그 기기의 세션 계열을 전부 폐기한다. 알림 확장(NSE) 토큰은 알림 읽기 전용으로 좁힌다.
  - **R1 동안** 폰의 허용은 「이번 한 번」만 된다.
  - **R2의 첫 항목:** 새 작업·input·허용을 ADR-0146 사람 기기 키(생체 ACL) 서명으로 받고, 서버가 검증한다.

### D4. 폰에서 「작업을 끝까지 요청」하는 모양 — 에이전트 멤버에게 DM·멘션
- **에이전트 멤버:** host가 켜질 때 감지된 CLI마다 **소유자 전용 에이전트 멤버**를 만든다. 예: 「성재의 Claude Code · MacBook」(ADR-0101·0130).
  - 요청은 그 에이전트에게 DM하거나 채널에서 멘션한다.
  - 소유자가 아닌 멤버의 멘션은 작업을 만들지 않고, 「소유자만 일을 시킬 수 있습니다」라고 답한다.
- **흐름:**
  1. 서버가 요청을 host 앞 spawn 컨트롤로 바꾼다. 원격 spawn도 슬롯 입장(`acquire_slot_in_tx`)을 거친다.
  2. host가 **허용 폴더**(D6) 안에서 세션을 연다.
  3. 진행은 그 대화의 스레드에 쌓인다.
- **스레드 답장:** 기본은 다음 차례 예약이다. 끼어들기는 명시 버튼, 중단은 기존 중단 버튼이다.
- **작업 탭:** 「나를 기다리는 것 → 실행 중 → 검토 대기 → 나머지」 순으로 정렬한다.
  - 행마다 host 온라인 점과 한 줄 요약을 둔다.
  - 요약은 host가 턴 끝에 사용자의 모델로 만든다(BYOA).
- **데스크탑 작업 추적:**
  - 데스크탑 앱에서 시작한 세션도 같은 host의 세션이라 폰에서 보인다.
  - 터미널에서 직접 띄운 `claude`는 oort가 모른다.
  - 그 세션을 붙이는 Claude Code Channels 플러그인은 **실험 경로**로만 둔다.

### D5. 권한 요청 다리 — ACP `session/request_permission`을 oort 승인으로
- **승인 행:** host가 ACP 권한 요청을 받으면 서버에 승인 행을 만든다.
  - 기존 `approval`은 `run_id NOT NULL`(agent_run)에 묶여 있어 데스크탑 세션의 요청을 담을 수 없다. 그래서 **`work_session_id`에 묶인 새 RLS 테이블**에 둔다(R1 진입 조건).
  - 이 행은 **host·세션·host가 발급한 1회 nonce**에 묶인다.
  - host는 모르는 nonce나 이미 끝난 요청에 대한 결정을 버린다.
  - 재시작·세션 종료·revoke 때는 대기 중인 승인을 취소한다.
- **미리보기:**
  - **닫힌 스키마**로 **소유자 기기에만** 보내고, 채널로 방송하지 않는다.
  - 소유자가 아니면 권한 승인은 목록·카드·실시간 이력 어디에도 나오지 않는다.
  - 실시간 이벤트와 푸시는 id만 싣는다. 미리보기는 소유자의 조회로만 받는다.
  - 잠금 화면에는 도구 종류와 host 이름만 보인다.
  - 정화 규칙:
    - 보이지 않는 문자와 방향 제어 문자를 무력화한다.
    - 필드당 3,500자에서 앞뒤를 남기고 자른다.
    - 인식되는 자격 문자열을 가린다.
    - 같은 정화를 이벤트 흐름과 diff에도 적용한다.
  - **잘린 미리보기는 펼치기 전에는 허용할 수 없다.**
- **푸시:** 이 승인은 항상 푸시된다. 푸시의 「승인」 액션은 잠금 화면에서 바로 허용하지 않고, 잠금 해제 뒤 **앱의 승인 카드를 연다**.
- **판정:** **첫 결정이 이긴다.**
  - 서버가 `pending` 조건부 UPDATE로 단일 판정자가 된다.
  - 결과는 **소유자 전용 채널**로 방송해 모든 소유자 기기의 카드를 닫는다.
  - 데스크탑에서 한 결정도 같은 서버 행을 거친다.
- **결정 범위:**
  - 이번 한 번, 또는 이 세션 동안이다. R1 동안 폰은 「이번 한 번」만 된다(D3).
  - 「이 세션 동안」은 host가 기억한다. 에이전트의 allow 규칙 파일에 쓰지 않는다.
  - **폰에서는 「항상 허용」 규칙과 bypass·자동 모드를 고를 수 없고, 보이지도 않는다(불변식).**
  - 「거부 + 지시」는 지시문을 다음 입력으로 보낸다.
- **migration:** 결정을 host로 돌려보낼 컨트롤 종류 `permission`을 추가한다.
  - 새 migration이 권한 승인 테이블(RLS FORCE, 테넌트 정책 대상)을 만들고, `work_control_kind_ck`(020)와 `payload_ck`(029)를 함께 바꾼다.
  - 허용 폴더 목록을 어디에 둘지도 이때 정한다(D6: 서버에는 경로를 두지 않는다).
  - `schema_v0.sql`은 건드리지 않는다.

### D6. 실행 격리 — 권한 모드 고정, 허용 폴더, 도구 제한
- **D6은 R1의 첫 workd부터 적용한다.** 서버 카탈로그(`launch_template`)를 받아 실행하는 현행 계약은 원격 host에서 쓰지 않는다.
- **권한 모드는 host가 스스로 고정한다(불변식).**
  - 실행 파일과 인자는 서버 `launch_template`이 아니라 **host 허용목록**에서 정한다.
  - 설정(에이전트 설정 파일·allow 규칙)이 bypass·auto를 요구하면 세션을 열지 않는다.
  - bypass·auto로 떠 있는 세션에는 폰 input과 승인을 거부한다. 세션 중 모드가 기본을 벗어나면 폰 경로를 닫는다.
  - 원격 세션은 프로젝트의 hooks·MCP 서버·allow 규칙을 읽지 않는다. 권한 다리를 우회하는 길이기 때문이다.
- **원격 spawn은 ACP 권한 다리가 있는 도구만 받는다(불변식).** `shell`은 원격에서 거부한다.
- **허용 폴더:**
  - 소유자가 **데스크탑에서** 저장소 루트를 정한다.
  - 폰은 host가 발급한 **불투명 폴더 id**만 보낸다. 경로는 서버에 싣지 않는다.
  - host는 매 spawn마다 `realpath`로 대조하고, worktree 경로를 스스로 만든다. 기본은 세션당 git worktree 하나다.
  - host가 돌리는 git은 hooks와 fsmonitor를 끈다.
  - **허용 폴더는 샌드박스가 아니다.** 권한 다리와 모드 고정이 실제 방어다.
- **diff:** host가 요청을 받을 때 계산해 짧게 캐시한다. raw diff는 서버에 저장하거나 로그하지 않는다. 세션 카드에는 `+42 −18` 같은 통계만 둔다.

### D7. 끄는 스위치·만료·폐기
- **워크스페이스 설정 「원격 작업」은 기본 꺼짐이다.** 관리자가 켠다.
- **폐기:**
  - host를 revoke하면 컨트롤 소비와 heartbeat가 즉시 거부된다.
  - host는 401을 받으면 원격 세션을 멈춘다.
  - 기기를 폐기하면 그 기기의 실시간(Centrifugo) 연결도 끊는다.
- **만료:**
  - 보류 중인 컨트롤은 짧은 TTL 뒤 만료한다.
  - 권한 요청은 세션당 속도 제한과 푸시 묶음을 둔다.
- **heartbeat와 서명:**
  - heartbeat를 v2 서명(request id 1회 소비)으로 올린다.
  - 서명 요청에 query 문자열이 있으면 401로 거부한다.
  - 전환 뒤에는 v1을 받지 않는다. 이 둘로 #875를 닫는다.
- **복구:** `live-sessions`·`reconcile`을 이식해 host 재시작 뒤 세션을 되찾는다.
- **오프라인 표시:** host가 오프라인이면 「맥이 돌아오면 이어서 합니다」를 표시하고 입력을 보류한다.

### D8. 알림 정책
- **항상 푸시:** 권한 요청, 입력 대기.
- **데스크탑에서 활동 중이 아닐 때만 푸시:** 완료, 실패. 판단은 ADR-0160 presence로 한다.
- **탭하면 그 세션·그 카드로 바로 간다.**
- Live Activities는 다음 단계다.

## 3. 불변식과 기본값
- **불변식(설정으로 바꿀 수 없다):**
  - 결정자 = host 소유자(D3)
  - 에이전트 컨트롤은 member-scope host에 `kill`만(D3)
  - 소유자 지시 판별(D3)
  - 폰 경로의 bypass·auto·「항상 허용」 금지와 host 모드 고정(D5·D6)
  - 원격 spawn은 ACP 권한 다리가 있는 도구만, 원격 `shell` 금지(D6)
  - 잘린 미리보기는 펼치기 전 허용 불가, 미리보기 소유자 전용(D5)
  - 서버에 폴더 경로 비저장(D6)
  - workd TCP 포트 없음(D2)
  - R2 이후 서명 없는 사람 컨트롤 거부(D3)
- **기본값(바꿀 수 있다):**
  - 원격 작업 꺼짐(D7). 관리자가 켠다.
  - 원격 세션 소유자 전용. 공개 범위만 뜻하며, 소유자만 바꾼다.
  - 세션당 worktree(D6)

## 5. 기각한 모양
- **Tailscale로 폰이 데스크탑에 직결:** 팀원마다 tailnet 가입이 필요하다. 성재 목표(ADR-0187 D2)와 반대다. 임시 경로로만 둔다.
- **Claude Code Channels를 정식 경로로:** 미리보기 기능이라 허용목록 밖 플러그인은 개발 플래그와 경고창이 필요하다. 권한 다리도 Claude 전용이다. 실험 경로로만 둔다.
- **Cursor식 「두뇌는 클라우드, 손은 로컬」:** 모델·provider 자격이 사용자 손을 떠난다(ADR-0004 BYOA).
- **서버가 터미널 바이트를 중계:** ADR-0125 D10 위반이다.
- **채널 멤버 누구나 승인:** 폰 원격 작업에서는 소유자 맥의 코드 실행 권한을 팀원에게 넘기는 것과 같다(§1.3).

## 6. 결과
- **목표 A에서 가장 긴 줄이다.** 인벤토리 기준 크기 추정은 아래와 같다.

  | 항목 | 크기 |
  |---|---|
  | host 데몬 | L |
  | 사람 컨트롤·권한 다리·폰 작업 UI·사람 기기 키 서명 | 각 M |
  | 페어링·새 작업·푸시·복구·R0 | 각 S–M |

- **R1이 끝나기 전에는** iOS가 원격 작업 없이 배포된다. 팀은 그동안 Tailscale 임시 경로를 쓸 수 있다.
- **새 공개 API는 넷이다.** 문서에 올린다.
  - 사람 컨트롤 라우트
  - `permission` 컨트롤
  - host 등록 GUI가 쓰는 라우트
  - 사람 기기 키 등록(ADR-0146)
- **새 migration은 R1에 하나다.** 권한 승인 테이블(`work_session_id`, RLS FORCE, 테넌트 정책 대상)을 만들고 `kind_ck`와 `payload_ck`를 함께 바꾼다. R2의 사람 기기 키 등록은 ADR-0146 개정에서 정한다.
- **신뢰 가정:** 서버·DB 관리자는 컨트롤 행을 직접 넣을 수 있다. R2의 사람 기기 키 서명이 이 가정을 좁힌다. host는 서명 없는 사람 컨트롤을 거부한다.
