# ADR 0100: 결정 거버넌스 — "결정은 ADR, 증거는 STATUS, 계획은 ROADMAP"

> Status: Accepted (성재 승인, 2026-07-10)
> Date: 2026-07-10
> Related: 2026-07-09 아키텍처 진단 §6 (조용히 내려진 결정들)

## Context

2026-07-09 전체 코드베이스 감사에서 확인된 패턴: **인프라·경계 결정은 ADR(0001~0005)로 기록됐지만, 제품 방향·에이전트 아키텍처의 굵직한 피벗은 전부 STATUS.md의 시간순 서사에 묻혔다.** 그 결과 프로젝트 오너가 시스템 디자인을 팔로업하지 못하는 병목이 생겼다.

기록 없이 내려진 결정(소급 대상):

| ID | 결정 | 현재 상태 | 소급 처리 |
|---|---|---|---|
| SD-1 | 김인턴 → Hermes 기본 정체성 교체 (MOMO-256) | 근거 무기록, 문서 간 이름 충돌 | → ADR-0106에서 판정 |
| SD-2 | Hermes gateway 경로의 사실상 기본화 (MOMO-325~333) | 자기 계약 문서(`research/11-agent-runtime/11-hermes-adapter-contract-v0.md`)와 모순 | → ADR-0102에서 판정 |
| SD-3 | M2 멀티팀 알파 → 로컬 1인 dogfood 피벗 | 로드맵 정본과 실행 레인 괴리 | → ADR-0103에서 판정 |
| SD-4 | GitHub Actions 중단 → 로컬 게이트 = 머지 권위 관례화 | 트레이드오프 논증 없음 | → ADR-0107에서 판정 |
| SD-5 | 핫픽스로 태어난 API 표면들 (agent realtime-token, `/gateway/jobs/pending`, `AGENT_GATEWAY_MODE`) | 스펙/README 다이어그램 미반영 | → ADR-0102에 포함 |

## Decision

문서의 권위를 셋으로 나눈다:

1. **결정은 ADR** (`docs/adr/`) — 유일한 결정 정본. 인프라만이 아니라 제품 방향·아키텍처 피벗 전부.
2. **증거는 STATUS** (`STATUS.md`) — 검증 명령·게이트 PASS·evidence 경로만. 결정 서술 금지.
3. **계획은 ROADMAP** (`ROADMAP.md`) — 마일스톤과 순서. 결정의 근거는 ADR 번호를 인용.

### ADR이 필요한 변경 (이것 없이 머지 금지)

- 공개 API 표면 추가/변경 (신규 라우트, 인증 방식, 이벤트 계약)
- 보안 경계 (시크릿, 토큰 모델, 권한/스코프, RLS 정책)
- DB 스키마 계약 (신규 테이블, 기존 계약 변경 — 단순 인덱스/컬럼 추가는 제외)
- 제품 방향 (마일스톤 피벗, 핵심 개념의 정체성/네이밍, 기본 실행 경로)
- 기술스택 선택/교체

### ADR 규칙

- **번호**: 0100번대부터 새 시대. 0001~0005는 유효한 채 유지.
- **분량**: 원칙적으로 1페이지. Context / Options(고려한 선택지와 기각 사유) / Decision / Consequences.
- **비교 참조**: 해당되는 경우 "Slack(또는 업계)은 어떻게 했나 + 근거" 1절 포함 — 오너가 배우면서 결정하는 것이 이 프로세스의 목적이므로.
- **Status 라이프사이클**: `Proposed` → `Accepted (성재 승인)` → 필요시 `Superseded by NNNN`. 승인 주체는 성재이며, Proposed 상태의 ADR은 구현 티켓으로 변환할 수 없다.
- **역할**: 기안 = 성재+Fable(기획 라인), 구현 = Codex (Accepted ADR에서 파생된 티켓만).

### 운영 반영 (이 ADR이 Accepted 되면)

- `.github/pull_request_template.md`에 "이 변경은 ADR 필요/불필요 (필요 시 ADR 번호)" 체크 항목 추가.
- `AGENTS.md`에 본 삼분법과 "ADR 없는 경계 변경 머지 금지" 조항 반영.
- `STATUS.md`는 분기별 아카이브로 분할 (현재 ~197KB 단일 파일).

## Consequences

- (+) 오너가 모든 방향 결정을 승인 시점에 학습·검증할 수 있다 — 이번 진단의 핵심 병목 해소.
- (+) 두 코드에이전트(Fable 기획 / Codex 구현)가 대화가 아닌 레포 파일로 정렬된다.
- (−) 경계 변경의 리드타임 증가 — 의도된 비용. 핫픽스는 "사후 24h 내 ADR 기안" 예외를 둔다.
