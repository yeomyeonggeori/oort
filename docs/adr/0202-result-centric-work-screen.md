## 맥락

### 왜 줄이는가
#3278 리서치(2026-10-01 성재 피드백)는 작업 화면을 Cursor·herdr 식으로 키우는 방향(여러 사람의 세션을 나란히 지켜보고, 남의 승인을 대신 누르고, 남의 진행을 세세히 따라가는 것)을 검토했다. 2026-10-15 성재는 그 방향에서 **팀 감시·대신 승인·남의 일 세밀 추적을 뺀다**고 정했다. 남는 질문은 「내가 맡긴 일이 어떻게 끝났나, 팀이 맡긴 일은 어떻게 끝났나」 하나이고, 그 답은 결과(PR·테스트·다음 할 일)이지 진행 스트림이 아니다.

### 지금 있는 것 [V]
- **사이드바 「에이전트·작업」 묶음의 작업 진입점이 다섯이다**(track/uxui `clients/web/src/features/sidebar/SidebarDestinations.tsx:96-162`): 「내 작업」(`MY_WORK_PATH`, 데스크탑 터미널 격자), 「팀 작업」(`TEAM_WORK_PATH`, 팀 보드), 「활동」(`/activity`, 워크스페이스 전체 에이전트 활동 줄, #3337), 「작업 콘솔」(`?view=console`, TC-1 #1758, 온라인 호스트가 있을 때만), 「작업 흐름」(`/workstreams`, ADR-0143, 서버가 실을 때만). 그 아래에 「이 기기」 실시간 세션 줄(최대 3개)이 붙는다.
- **팀 보드**(ADR-0194 D5, 실제 경로 `GET /v1/workspaces/{ws}/work-sessions/shared`)는 공유 L 세션·A 세션을 내고, `?include=runs`를 주면 **호스팅 에이전트의 `type=work` run**도 섞는다(ADR-0162 증보 3 D13, AT-4 구현 기록). 멘션 run과 관리형·BYOA 에이전트의 work run은 넣지 않는다(D13).
- **run의 진행·결과 사실**은 이미 서버에 있다: `phase`·`lease_state`·`latest_stage`·`last_event_at`(ADR-0200 D1·D2, `agent_runs.rs:842-845` 응답 DTO), 단계 원장, `output.artifacts`(PR URL·브랜치·줄 수·커밋 수, ADR-0162 증보 3 D12). 클라이언트는 `packages/momo-core/src/features/agents/runPhase.ts:195-241`에서 phase를 문구로 옮긴다. 경과 시간은 `created_at`·`claimed_at`·`finished_at`으로 계산된다.
- **승인 카드**(ADR-0186)는 채널과 인박스에 있고, #3829(#3819)로 한 번 누르면 결정된다. host 권한 승인은 소유자만 결정한다(ADR-0188 D3). 대신 승인은 없다.
- **run에는 요청자 열이 없다.** 요청자는 감사 행 `agent.work.queued`의 `actor_member_id`로 읽는다(ADR-0162 증보 3 AT-4 구현 기록). 멘션 run의 요청자는 트리거 메시지 작성자다(`agent_run.trigger_message_id` → `message.author_member_id`).

## 결정

### D1. 「작업」은 결과 중심의 한 화면이다
- 웹·데스크탑·폰 모두 **「작업」 화면 하나**다. 화면의 줄 하나는 「맡긴 일 하나」(D3)이고, 줄이 먼저 보여 주는 것은 **결과**다: 상태(ADR-0200 `phase`의 사람 문구), 결과 종류·PR 링크·테스트 수·다음 할 일(ADR-0162 증보 5 C1의 계약, 「에이전트 보고」 표시), 누가 맡겼나, 어느 에이전트가, 언제 끝났나·얼마나 걸렸나.
- 진행 스트림(단계·사고 과정·oort 호출 기록)은 줄을 **열었을 때** 기존 run 상세·채널 작업 패널(ADR-0200 D2 원장, 같은 날 증보의 `?include=tools`)에서 본다. 목록 자체는 실시간 진행판이 아니다.
- 승인을 기다리는 줄(`phase=awaiting_approval`)은 「승인 대기」로 보이고 **그 카드가 있는 자리로 연결**한다. 「작업」 화면이 승인 버튼을 따로 갖지 않는다(D5).

### D2. 「내 것 / 팀 전체」 필터 — 기본은 「내 것」
| 필터 | 들어오는 줄 | 근거 |
|---|---|---|
| **내 것** (기본) | 내가 맡긴 run(요청자 = 나) ∪ 내가 주인인 작업 세션(L·A) | 요청자는 `agent.work.queued` 감사 행 또는 트리거 메시지 작성자(맥락 [V]) |
| **팀 전체** | 내가 **활성 멤버인 채널**(미보관·`left_at IS NULL`)에 집이 있는 모든 줄 | ADR-0194 D3·D5, ADR-0162 증보 3 D13과 같은 가시성 SQL |
- 「팀 전체」의 「팀」은 워크스페이스 전체가 아니다. **내가 멤버인 채널**이다(성재 결재 원문 그대로). 내가 볼 수 없는 채널의 일은 줄도 숫자도 나오지 않는다(「공유되지 않은 세션 n개」 같은 숫자 금지, ADR-0194 D5 그대로).
- 「내 것」도 같은 가시성을 지킨다: 내가 맡긴 일이라도 그 채널을 떠났으면 줄이 나오지 않는다. 예외는 ADR-0194 D3의 「세션 주인은 공유 여부와 관계없이 자기 세션 카드」 하나다.
- 마지막으로 고른 필터는 **기기별 편의**로만 기억한다(localStorage, 읽기·쓰기 모두 try/catch). 기본값은 항상 「내 것」이다. `oort://work?view=team…` 링크(ADR-0194 D2)는 「팀 전체」로 연다.

### D3. 줄 = 어느 에이전트에게든 맡긴 일 (짧은 멘션 답은 뺀다)
줄의 출처는 셋이고, **에이전트 종류로 거르지 않는다**(그록봇 같은 호스팅 에이전트, 팀 AI(ADR-0201), 관리형·BYOA·개인 에이전트, 맥 세션).
1. **작업 세션**: 공유 L 세션·A 세션(맥 세션). ADR-0194 D5 그대로.
2. **`type=work` run**: 에이전트 종류와 무관하게 모두. (ADR-0162 증보 3 D13의 「관리형·BYOA work run은 v1에 넣지 않는다」를 이 ADR이 **넓힌다**.)
3. **맡긴 일이 된 멘션 run** — 다음 중 하나라도 참인 멘션 run(스레드 깨우기 run 포함, ADR-0162 증보 5 W1)이다 **[추정 — 「짧은 멘션 답」의 운영 정의]**:
   - 원장에 `stage` 행이 하나 이상 있다(에이전트가 단계를 보고했다),
   - `approval_requested` 행이 있다(승인 카드를 냈다 — 팀 AI 빠른 길의 카드도 여기로 들어온다),
   - `output.artifacts`가 있다(코드 결과를 보고했다),
   - 끝났으면 `finished_at − created_at ≥ 60초`, 아직이면 `now() − created_at ≥ 60초`(60초는 ADR-0162 증보 3 D14의 끝남 푸시 문턱과 같은 값).
   위 넷이 모두 거짓인 멘션 run = **짧은 멘션 답**이고 줄이 없다. 그 답은 이미 스레드의 메시지로 보인다. (ADR-0162 증보 3 D13·ADR-0200 「바뀌는 기존 결정」의 「mention run은 보드에 넣지 않는다」를 이 규칙으로 **대체**한다.)
- **중복 제거**: run에 연결된 작업 세션이 있으면 세션 줄이 대표다(AT-4 기록 그대로).
- 판정은 읽기 SQL이 한다(클라이언트 추정 없음). 줄마다 `source`(`session`·`run`)와 run 줄의 `trigger`(`work`·`mention`·`thread_reply`)를 낸다.

### D4. 읽기 계약 — 기존 보드 경로를 넓히고, 배포된 클라이언트를 깨지 않는다
- 새 목록 경로를 만들지 않는다. `GET /v1/workspaces/{ws}/work-sessions/shared`에 두 쿼리를 더한다:
  - `include=runs,jobs` — `jobs`는 D3의 2·3번(모든 에이전트의 work run + 맡긴 일이 된 멘션 run)으로 run 출처를 넓힌다. 기존 `include=runs`(호스팅 work run만)는 의미 그대로 남는다. `include` 값은 쉼표로 나눈 닫힌 집합이고 모르는 값은 400이다.
  - `who=mine|team` — 기본 `team`(기존 응답과 같은 집합, 배포된 클라이언트 불변). 새 「작업」 화면은 `who=mine`을 기본으로 보낸다.
- `include`가 없으면 응답은 지금과 바이트 수준으로 같다. 이미 배포된 클라이언트가 모든 행을 `sessionId`로 키 잡는 문제(AT-4 기록)와 모르는 열거값을 `WireShapeError`로 거부하는 문제(ADR-0200 doorbell 증보, #3830 선례) 때문이다. 새 필드(`trigger`, 결과 계약 필드)는 `include=jobs`를 준 응답에만 실린다.
- 구 서버는 `include=jobs`에 400을 낸다. 새 클라이언트는 400이면 `include=runs`로 한 번 물러서고(그 줄은 「호스팅 에이전트 작업만 보여요」 안내), 다시 묻지 않는다.
- 정렬·페이징은 기존 `(last_activity µs, id)` 커서 하나. 실시간은 기존 `work.run.updated` + ADR-0200 `agent.run.event` 프레임에 재조회(가시성은 조회가 다시 강제). 새 프레임 이름을 만들지 않는다. 다만 `work.run.updated`는 지금 **호스팅 에이전트의 run에서만** 나온다(AT-4 기록) — 출처를 넓히면 트리거 술어도 같이 넓혀야 한다(구현 슬라이스 E1의 red proof).

### D5. 팀 감시·대신 승인·남의 일 세밀 추적은 만들지 않는다
- **대신 승인 없음.** 다른 사람에게 온 승인(host 권한·spawn 승인, ADR-0188 D3)을 내가 누르는 길을 만들지 않는다. ADR-0188 D3의 「결정자 = 소유자」 불변식은 그대로다. 워크스페이스 행동 승인(ADR-0186)은 레지스트리의 `requiredRole`이 정한 사람이 그 카드에서 누른다 — 원래부터 「대신」이 아니라 그 권한자의 결정이다.
- **팀 감시 없음.** 남의 터미널·화면·실시간 세션 격자를 「작업」에서 보이지 않는다. 사람별 활동 타임라인, 「지금 누가 무엇을 하는지」 판을 만들지 않는다. 남의 줄은 D1의 결과 요약과 phase까지이고, 더 보려면 그 일의 채널에 들어가 기존 작업 패널을 연다(채널 멤버만, 기존 규칙).
- **세밀 추적 없음.** 남의 run의 단계·oort 호출을 「작업」 목록에 흘리지 않는다. 원장 자체의 가시성(채널 멤버)은 바꾸지 않는다.
- **승인 카드는 남는다.** ADR-0186 카드와 #3829의 한 번 클릭 결정은 채널·인박스에서 그대로다. 인박스(ADR-0199)와 「나에게 필요한 일」 수도 그대로다.

### D6. 사이드바 — 다섯 줄을 「작업」 한 줄로
- 「내 작업」·「팀 작업」·「활동」·「작업 콘솔」·「작업 흐름」 다섯 줄을 **「작업」 한 줄**로 바꾼다. 「작업」 줄은 지금 「내 작업」이 가진 「나에게 필요한 세션 수」 배지·점을 그대로 갖는다.
- 「이 기기」 실시간 세션 줄(내 것, 최대 3개)은 「작업」 아래에 그대로 둔다 — 내 기기의 응답 대기 신호이지 팀 감시가 아니다.
- **숨김 = 진입점만 뺀다. 코드는 남긴다.** `/activity`, `/workstreams`, `?view=console`, `/work?view=team` 라우트와 화면 코드는 지우지 않는다. 옛 메시지의 링크·딥링크는 계속 열린다(`/work?view=team`은 「작업」+「팀 전체」로 연다). 다시 꺼낼지는 별도 결정이다.
- **건드리지 않는 것**: 인박스·멤버·임시 보관함 줄, 「AI」·「에이전트」 줄, 승인 카드, 인박스.
- 데스크탑의 내 터미널 격자(지금의 「내 작업」 본문)는 「작업」 화면 안 「내 것」의 **이 기기 세션** 영역으로 들어간다(배치는 UXUI 이슈가 정한다). 사이드바 줄이 따로 있지 않다.
- 폰 탭바 「작업」은 이미 「팀 보드 한 열 + 내 것 필터」 모양이다(ADR-0194 D1). 같은 읽기 계약(D4)과 같은 필터 기본값(「내 것」)으로 맞춘다.

| A. 「내 작업」·「팀 작업」 두 화면 유지 + 활동 피드 | 성재 결재 「한 화면, 필터로 나눔」. 같은 줄을 두 곳에서 보는 비용과 진입점 다섯 개의 혼란(#3278 피드백)이 그대로다. |
| B. herdr식 팀 세션 감시판(여러 사람 터미널 격자) + 대신 승인 | 성재 결재로 뺌. 대신 승인은 ADR-0188 D3 불변식과 정면 충돌한다. |
| C. 「팀 전체」 = 워크스페이스 전체 | 내가 멤버가 아닌 채널의 제목·요청자 노출. 기존 가시성(ADR-0194 D3, ADR-0200 D3)과 어긋난다. |
| D. 멘션 run 전부를 줄로 | 짧은 답이 목록을 덮는다. 성재 결재가 「짧은 멘션 답은 제외」. |
| E. 새 목록 경로 `/work` | 같은 가시성·커서·이벤트를 두 벌 만든다. 기존 보드 경로에 `include`·`who`를 더하는 편이 배포된 클라이언트 호환도 쉽다(D4). |

## 불변식 대조
- Postgres = 원본, 단일 쓰기 경로: 이 ADR은 읽기만 넓힌다. 새 쓰기·새 테이블 없음.
- Centrifugo = 전송만: 새 프레임 이름 없음, 기존 프레임 + 재조회.
- 에이전트 = 1급 멤버, RLS FORCE + `SET LOCAL app.workspace_id`: 읽기 SQL은 기존 테넌트 tx와 채널 멤버십 술어.
- `schema_v0.sql` 불변, migration 없음.
- 공개 API 변경(보드 쿼리 `include=jobs`·`who`) → 이 Accepted가 구현 머지 조건(ADR-0100).

## 결재 기록 (2026-10-15, 성재 AskUserQuestion — 원문 인용)

1. 추적 범위 → 「팀 감시·대신 승인만 빼기 (추천)」 — herdr식 팀 감시·대신 승인·남의 일 세밀 추적을 빼고, ADR-0186 승인 카드(한 번 클릭, #3829)는 남긴다 (D5).
2. 화면 구성 → 「한 화면, 필터로 나눔 (추천)」 — 결과 중심 「작업」 한 화면, 「내 것 / 팀 전체」 필터(팀 = 내가 멤버인 채널, 기본 「내 것」) (D1·D2).
3. 줄의 범위 → 「모든 에이전트에게 맡긴 일 (추천)」 — 그록봇·팀 AI·개인 에이전트·맥 세션 모두, 짧은 멘션 답은 제외 (D3).
4. 사이드바 → 「「작업」 하나로 합치기 (추천)」 — 내 작업·팀 작업·활동·작업 콘솔·작업 흐름을 「작업」 하나로, 나머지 진입점은 숨기고 코드는 유지, 승인·인박스는 그대로 (D6).

같은 날 결재 중 이 화면에 들어가는 사실의 출처: 「oort 호출 + VM 개수 보고 (추천)」(ADR-0200 증보 2026-10-15), 「정해진 칸으로 보고 (추천)」(ADR-0162 증보 5 C1).

## 구현 슬라이스 (Accepted 후, 각각 한 이슈·한 PR)

- **E1 (engine) 보드 읽기 확장.** `include=jobs`·`who=mine|team`, D3 판정 SQL(멘션 run 네 조건), `trigger` 필드, `work.run.updated` 트리거 술어를 모든 에이전트 run으로. red proof: ① `include` 없는 응답이 기존과 같다(스냅샷), ② 59초·단계 없음·카드 없음·산출물 없음 멘션 run은 0줄이고 60초가 되면 1줄(문턱을 지우면 실패), ③ 관리형 에이전트의 `type=work` run이 나온다, ④ 채널 비멤버·다른 테넌트는 0줄, ⑤ `who=mine`은 남이 맡긴 run을 내지 않는다(요청자 술어를 빼면 실패), ⑥ 세션에 연결된 run은 한 줄, ⑦ 모르는 `include` 값은 400.
- **U1 (UXUI) 「작업」 화면·사이드바.** 다섯 줄 → 한 줄(라우트 유지), 필터(기본 「내 것」, 기기별 기억), 결과 칸(「에이전트 보고」 표시), 승인 대기 줄 → 카드 위치로, 구 서버 400 물러서기. 웹·데스크탑·폰 캡처, design-review Blocker 0·High 0. #3836(팀 AI 표면)과 같은 줄 모양을 쓴다.
