# ADR-0141: 세션 연속성 정책 — 침묵은 죽음이 아니다 + T3 유휴 자원 반환 3단

- Status: **Proposed** (2026-07-28, 기안 Fable — 성재 지시로 정책 위임분 포함)
- 관련: **ADR-0139 증보**(D1 상태 모델·D3 재부착/계보 분기·D4 T3 pause), ADR-0136(슬롯·크레딧), ADR-0125(D11 계보 재개)
- 이슈: #893(T2 결함), #870(데몬 재시작 시 사라진 PTY — 반대 국면)
- 발단: 성재(2026-07-28) — "iterm2에서 claude code 작업하다 노트북을 덮었다 열면 재개되는, 로컬 맥에서의 사용 패턴을 생각했어. 원격은 요청한 작업을 진행하면 그걸 기억하면서 idle로 있다가 다시 요청하면 재개하는 형태. **언제 idle이 리소스 반환이 되고 다른 사람들이 사용할 수 있게 할지 기준은 추천·적용해줘도 좋다.**"

## Context

### 두 티어의 사용 패턴이 다르다 (성재 모델)

- **T2 로컬**: 사용자가 도구를 *끈* 게 아니다. 랩탑을 덮었을 뿐이다. **로컬 터미널과 같아야 한다 — 덮었다 열면 그냥 이어진다.** 재개 의식(ceremony)이 없는 게 정상이다.
- **T3 원격**: 요청 → 수행 → **기억한 채 idle** → 다시 요청하면 재개. 켜둔 채 기다리는 게 기본값이고, 자원 반환은 그 위에 얹히는 운영 정책이다.

### 지금 코드가 두 모델을 다 어긴다 (실측)

1. **T2**: heartbeat 90초 단절(`Config.swift:72`)이면 sweep이 `orphaned`로 못박고, **되돌리는 전이가 없다**(`WorkSessionRoutes.swift:441,610,647`은 `running|idle`만 다룬다). 유일한 출구는 계보 재개(`:1443`)이고 그건 **새 세션**이다 — PTY도 미커밋 변경도 옮기지 않는다. **랩탑을 90초 덮으면 세션이 죽는다.**
2. **T3**: `paused`가 슬롯을 **그대로 점유**한다(`CloudUsageLedger.swift:63-88` — workspace `max_active`와 `per_member_soft_limit` 양쪽에서 `paused`를 occupied로 센다). 과금은 멈추지만(ADR-0139 D4) **팀원은 그 슬롯을 못 쓴다.** 반환 시점이 정의된 적이 없다.

### 비대칭 하나가 설계를 결정한다

- **T2의 침묵은 죽음의 증거가 아니다.** 랩탑이 자는 것과 데몬이 죽은 것은 원격에서 구분되지 않는다.
- **T3의 죽음은 적극적으로 증언된다.** provider가 404/410으로 "그 샌드박스 없다"고 답한다(ADR-0140 D4 `provider_missing`).

→ **증거 없이 파괴적 상태로 내리지 않는다**는 규칙 하나로 두 티어를 함께 설명할 수 있다.

## Decision

### D1. `orphaned`는 시간이 아니라 **사용자 행동**이 만든다

- **A (권고)**: heartbeat 단절 90초는 **`unreachable`**(중립·되돌릴 수 있음)까지만 만든다. 표시만 바뀌고 **아무것도 파괴하지 않는다**. 호스트가 돌아와 같은 세션의 PTY 보유를 서명 보고하면 `running|idle`로 **조용히 복귀**한다 — 사용자에게 재개 의식이 없다.
- **`orphaned`로의 강등은 "다른 호스트에서 이어받겠다"를 사용자가 선택하는 순간**에만 일어난다. 그 선택이 곧 "원래 호스트는 포기한다"는 선언이고, 그때부터 PTY·미커밋 변경 손실 고지가 정당해진다(ADR-0139 D3 유지).
- 기존 `resume_offer` 푸시(MOMO-519/520)는 그대로 쓰되 **판정이 아니라 제안**으로 의미가 바뀐다 — "이어받으시겠어요?"가 눌리면 그때 `orphaned`가 된다.
- **T3는 예외**: provider가 부재를 증언하면 시간과 무관하게 즉시 terminal(`provider_missing`). 죽음의 증거가 있는 유일한 경우다.
- B — grace를 90초에서 몇 시간으로 늘린다: 슬립은 덮이지만 **"침묵=죽음"이라는 잘못된 등식은 그대로**다. 더 긴 침묵 뒤의 복귀는 여전히 세션을 잃는다. **기각(미봉책).**
- C — 현행 유지 + 계보 재개를 빠르게: 성재 사용 패턴("덮었다 열면 이어진다")을 정면으로 어긴다. **기각.**

### D2. T3 유휴 자원 반환 3단 — 반환 전에 **작업을 먼저 안전하게** 만든다

| 단계 | 시점 | 반환하는 것 | 재개 체감 |
|---|---|---|---|
| **1. pause** | idle 진입 **즉시** | **compute·과금** (ADR-0139 D4, 기존) | 초 단위 |
| **2. hibernate** | paused **24시간** 경과(워크스페이스 설정) | **슬롯 + 스토리지** — 샌드박스 destroy | 수십 초(새 샌드박스 + workdir 복원) |
| **3. ended** | hibernate **7일** 경과 | 세션 자체 | 아카이브에서 새 세션으로 출발 |

- **24시간을 고른 이유**: 퇴근–출근(약 16시간)을 덮는 가장 작은 값이다. 12시간이면 "저녁에 멈추고 다음 날 오후에 재개"가 깨진다. pause 구간은 과금되지 않으므로(D4) 조기 반환을 압박하는 것은 **비용이 아니라 슬롯 공정성**이고, 그건 아래 D3가 따로 다룬다.
- **2단에 들어가기 전에 미커밋 변경을 보존한다** — 이게 없으면 자원 반환이 곧 작업 파기다.
  - **보존 방식: 사용자 원격에 WIP 커밋 + push**(`momo/wip/<session-id>` 네임스페이스 고정). 코드가 원래 사는 곳에 두므로 **새 저장 주장도, 새 시크릿 표면도 만들지 않는다**(`docs/security/README.ko.md`의 "실행 내용 미보관" 유지). ADR-0125 D11 계보 재개와 같은 문법이다.
  - **push할 원격이 없거나 실패하면 반환을 보류**하고 소유자에게 결정을 요청한다. **말없이 버리지 않는다.**
  - **알려진 부작용**: WIP push가 사용자 CI를 트리거할 수 있다. 네임스페이스를 고정해 제외 규칙을 쓸 수 있게 하고, **첫 발생 시 명시 고지**한다.
- 각 단계 전이는 소유자에게 id-only 푸시로 알린다(ADR-0120 유지). "자원을 반납했고, 요청하면 복원해서 재개한다"가 문장으로 보여야 한다.

### D3. 슬롯 압력 시 **가장 오래 쉰 것부터** 조기 회수

- 시간만으로는 공정하지 않다. 슬롯이 가득 찬 상태에서 새 요청이 오면, **paused 상태이면서 유휴가 가장 오래된 세션부터** 2단(hibernate)으로 내려 슬롯을 만든다.
- **최소 보호 시간 1시간** — 방금 쉬기 시작한 세션은 회수 대상이 아니다. "잠깐 커피 마시고 왔더니 남이 가져갔다"를 막는다.
- 회수는 **D2의 보존 절차를 그대로 지난다**(WIP push 실패 시 회수 보류 — 그러면 요청자에게 "슬롯이 비지 않았다"고 정직하게 답한다).
- 소유자에게 회수 사실을 푸시한다.

### D4. 데이터 분리는 **구조로** 보장한다

성재 조건("다만 데이터는 분리된 상태로")에 대해, 새로 만들 것은 없고 **이미 성립하는 근거를 명문화**한다.

- 반환된 자원을 다음 사용자가 받을 때는 **새 샌드박스**다 — destroy 후 재사용이 아니라 신규 프로비저닝이므로 파일시스템·메모리가 이어지지 않는다.
- 서버는 PTY 바이트를 **원래 나르지도 저장하지도 않는다**(ADR-0125 D10, ADR-0139 D2 유지).
- 원장·세션 메타는 워크스페이스 RLS FORCE 경계 안에 있다.
- WIP 아카이브는 **사용자 자신의 원격**에 있다 — momo가 새로 보관하는 사본이 없다.

## Consequences

- (+) 랩탑을 덮었다 여는 것이 **비사건**이 된다. 로컬 CLI 체감과 같아진다.
- (+) 파괴적 전이가 **전부 사용자 행동이나 provider 증언**을 요구한다 — 시간이 데이터를 지우지 않는다.
- (+) 슬롯 공정성이 시간(24h)과 압력(LRU) 두 축으로 다뤄져, 유휴 세션이 팀을 막지 않는다.
- (−) 상태가 하나 는다(`unreachable`) — 웹·macOS·iOS 표시와 문구가 모두 바뀐다. ADR-0139 D3의 "이어서 보기 vs 새 호스트에서 재개" 분기도 재작성.
- (−) WIP 자동 push는 사용자 저장소에 쓰는 **바깥 방향 행위**다. 네임스페이스·고지·설정으로 완화하지만 위험이 0은 아니다.
- (−) hibernate 재개는 수십 초가 걸린다 — "항상 즉시"가 아니게 되므로 UI가 이 차이를 정직하게 말해야 한다.
- (−) 2·3단 타이머와 LRU 회수가 sweep에 얹혀 sweep 책임이 커진다. ADR-0140 T-2의 세션 단위 트랜잭션 분할 이후에 얹어야 한다.

## 이행 (Accepted 시)

1. **#893 (T2, ADR-0140과 독립)** — `unreachable` 상태 + 복귀 전이 + `orphaned`를 사용자 행동으로 이동. #870(사라진 PTY 보고)과 **같은 배치**에서 설계해야 앞뒤가 맞는다.
2. **T3 3단 반환** — ADR-0140 **T-3(#891) 랜딩 후**. hibernate는 새 terminal이 아니라 **`t3_terminate`의 한 `reason`**으로 들어간다(정산 단일 문 유지).
3. **WIP 보존** — 2단·3단 공통 선행. 원격 없음/실패의 보류 경로가 red proof 대상.
4. 웹·macOS·iOS 표시 갱신은 1·2 랜딩 뒤 UXUI 트랙.
