## Context

- 채널 헤더의 「터미널」은 실제 터미널이 아니다. 다른 호스트의 작업 세션을 관전만 하는 도크다(`TerminalDock.tsx`). 그런데 관전할 바이트를 만드는 호스트가 지금은 없다. Swift 호스트는 #2165에서 삭제됐고, Rust `momo-workd`는 ACP만 말하며 셸을 거부한다.
- 데스크탑(Tauri)에는 PTY도 터미널 렌더도 없다. ADR-0114 D1(앱 내장 세션 매니저)·D6(SwiftTerm과 ctrl+` 서랍)은 Swift 시대의 결정이고, Tauri로 옮긴 뒤 다시 정한 적이 없다.
- 두 신뢰 모델이 「터미널」 한 단어에 섞여 있다. 0114(2026-07)는 사람 직접 조작과 에이전트 spawn을 한 세션 매니저에 두고 셸을 프로파일로 허용했다. 0188(2026-09)은 원격·에이전트 경로를 ACP만, 셸 금지, 결정자 = 소유자로 좁혔다. 성재가 원하는 「셸 + 하네스 선택 + 분할」을 workd로 보내면 0188 D6과 정면으로 부딪힌다.

## Options

| 선택지 | 내용 | 판단 |
|---|---|---|
| **A. 앱 프로세스 PTY, 원장 밖** | Tauri Rust 쪽이 PTY를 열고 xterm.js 칸에 그린다. 서버 컨트롤을 받지 않는다 | **채택.** 0188 불변식을 건드리지 않고 로컬 셸과 분할을 준다. 서버 변경 없이 M1이 선다 |
| B. workd 안의 PTY | 로컬 터미널도 workd가 열고 앱은 붙기만 한다 | 기각. 셸이 workd에 들어가면 0188 D6 「원격 셸 금지」를 설정으로 가르는 모양이 된다. 두 레인의 경계가 흐려진다 |
| C. 비샌드박스 helper 프로세스 | App Sandbox 배포판에서 PTY를 helper에 맡긴다(0114 보강 절) | 보류. 목표 A 동안 App Store로 데스크탑을 내지 않으므로(D1) 필요 없다. 스토어가 필요해지면 따로 ADR을 낸다 |
| D. 로컬 세션도 기본 원장 등록 | 모든 로컬 칸을 `work_session`으로 올린다 | 기각. raw가 새는 표면이 늘고, 등록 전 데스크탑(M1)에서는 `host_id`가 없어 불가능하다(0114 D8) |

## Decision

### D1. PTY는 데스크탑 앱 프로세스가 연다
- Tauri Rust 쪽이 `portable-pty` 계열(permissive) 라이브러리로 PTY를 열고, 앱 웹뷰의 xterm.js 칸이 그린다. 칸마다 headless 미러를 두어 앱 재시작 뒤 스크롤백을 복원한다.
- PTY 명령은 앱 웹뷰에서만 부른다. 서버 이벤트, 딥링크, workd는 PTY를 열 수 없다. 구현은 이것을 소스 시험으로 단정한다.
- **목표 A 동안 데스크탑은 공증 DMG로만 배포하고 Mac App Store에 내지 않는다**(Q7). 그래서 앱이 PTY를 직접 연다. 스토어 배포가 필요해지면 PTY를 비샌드박스 helper로 옮기는 ADR을 따로 낸다. ADR-0114의 「배포판 App Sandbox 경계」 절은 그때 다시 본다.

### D2. 로컬 레인은 비원장이 기본이고, 셸은 로컬에서만 허용한다
- 로컬 터미널(L 레인)은 앞에 앉은 사람이 직접 쓴다. 서버 컨트롤(`work.control.*`)을 받지 않고, 원격에서 spawn·input을 할 수 없다. 기본은 서버에 등록하지 않는다.
- 사람 직접 조작이므로 승인이 없다(0114 D5 「사람 직접 조작은 승인 불요」와 같다).
- **셸과 임의 CLI는 L 레인에서만 허용한다.** 에이전트 작업 레인(A 레인, workd·ACP)은 0188 D6 그대로 셸 금지, 모드 고정이다.
- 하네스는 기본 권한 모드로 띄운다. `--dangerously-skip-permissions` 같은 우회 플래그를 기본으로 켜지 않는다. 바꾸는 것은 사용자가 칸에서 명시적으로 한다.
- raw 출력은 로컬 화면에만 있다. 서버에 싣지 않는다.

### D3. 하네스 목록의 정본은 로컬 감지다
- L 칸의 하네스 목록은 이 기기의 PATH에서 찾은 CLI(`claude`, `codex`, `grok` 등)가 정본이다.
- 서버 `work_tool_profile`은 표시 이름과 아이콘 같은 **라벨**로만 쓴다. 워크스페이스 관리자의 표가 소유자의 맥에서 감지된 CLI를 막지 못한다.
- `work_tool_profile`이 정본인 곳은 A 레인뿐이다. 그것도 원격에서는 0188 D6에 따라 host 허용목록이 우선한다.

### D4. 「공유」 세션 종류를 두고, 서버가 컨트롤을 거부한다
- L 칸은 선택적으로 「공유」할 수 있다. 이름, 폴더 표시 이름(마지막 경로 요소), 상태만 올린다. 켜면 ADE 요약 줄과 폰 목록에 「성재 · 로컬 · 실행 중」으로 보인다. **기본은 끔이다.**
- 선행 조건: `work_session`은 `host_id`가 필수다(0114 D8). 그래서 공유는 데스크탑이 `work_host`로 등록된 뒤(0188 R1 등록 GUI)에야 된다. M1의 L 칸은 전부 등록하지 않는다.
- 공유된 L 세션은 **별도 종류로 기록한다**(예: `origin='local_pty'`). 컨트롤 생성 라우트는 그 종류의 세션에 대한 모든 `work.control.*` 생성을 **거부한다**. 호스트가 받고 무시하는 방식은 안 된다. 강제 없는 경계는 깨진다(0143 D3와 같은 이유).
- 폴더 전체 경로와 raw 바이트는 싣지 않는다(0188 §3 「서버에 폴더 경로 비저장」과 같은 방향).
- **요구 사항 — red proof:** 「공유 L 세션에 input 컨트롤 생성 → 거부」 conformance 시험이 있어야 한다. 거부 분기를 지우면 이 시험이 실패해야 한다. 이 시험 없이는 공유 기능을 머지하지 않는다(#2793).

### D5. 단축키 (Q4)
macOS 기준이다. Windows·Linux는 ⌘를 Ctrl로 읽는다.

| 동작 | 키 | 비고 |
|---|---|---|
| 터미널 도크 열고 닫기 | **⌃`** | `event.code === "Backquote"`로 판정한다. 한글 2벌식에서 같은 키가 `₩`를 내기 때문이다. ⌘`는 macOS 창 순환이라 쓰지 않는다 |
| 전체 화면 작업 공간 | ⌃⇧` | 도크를 격자로 키운다 |
| 새 세션 | ⌃⇧N (도크 포커스 중이면 ⌘T) | ⌘N은 새 창 관습이라 피한다 |
| 오른쪽으로 분할 / 아래로 분할 | ⌘D / ⌘⇧D | Orca 기본값, iTerm2 관습 |
| 칸 포커스 이동 | ⌘⌥←↑→↓(방향), ⌘] / ⌘[(순환) | |
| 칸 번호로 이동 | ⌃1..9 | ⌘1..9는 워크스페이스 전환에 남긴다 |
| 칸 최대화 토글 | ⌘⇧↵ | |
| 세션 점프 팔레트 | ⌘J | ⌘K(검색·이동)와 따로 둔다 |
| 칸 닫기 | ⌘W (실행 중이면 확인) | L 칸은 프로세스를 끝낸다. A 칸은 창만 닫고 세션은 계속된다. 문구로 구분한다 |
| 다음 「나를 기다림」으로 | ⌃⇧J | |

- 터미널에 포커스가 있으면 앱 단축키보다 터미널 입력이 먼저다. 위 표의 앱 키만 가로챈다. 이 목록은 설정에서 볼 수 있다.
- 도크 크기는 위 경계를 드래그한다. 크기와 격자 배치는 이 기기에 세션(worktree)마다 저장한다(ADR-0174).

### D6. 팀원 터미널 raw 관전은 목표 A 뒤로 미룬다 (Q3)
- 팀 관전은 큐레이션된 진행 뷰(ADR-0154 D2)로 먼저 한다.
- raw 관전은 workd에 PTY와 링버퍼를 다시 키우고 직결 불가 망의 중계(0125 D10)까지 풀어야 한다. 목표 A 뒤에 다시 정한다.
- 그때까지 관전 도크는 P0에서 정리한다(#2753).

### D7. 두 레인은 한 격자에 섞이고, 칸을 옮기지 않는다
- L 칸(xterm)과 A 칸(진행 뷰)이 같은 격자에 놓인다. 머리 문구와 아이콘으로 구분한다(`로컬` / `에이전트 · oort에 기록`). 색에만 기대지 않는다.
- 로컬 TUI에서 하던 일을 폰에서 이어받고 싶으면 같은 폴더·브랜치에서 A 세션을 새로 연다(0125 D11 계보 재개, 0154 D3 「인수」). PTY를 옮기지 않는다.
- 「나를 기다림」과 「끝남」은 기존 인박스와 OS 알림으로 합류한다. 토스트는 쓰지 않는다(ADR-0182).

## 업계 비교
- **Orca**(MIT): 칸마다 `node-pty` + xterm, OSC 제목과 hook으로 상태 점, 분할 단축키 ⌘D/⌘⇧D, 방향 포커스 이동은 없다. 하네스를 우회 플래그로 기본 실행한다. oort는 분할·상태 점 문법을 가져오고 우회 기본값은 따르지 않는다.
- **Claude Code 데스크탑**: Ctrl+`로 터미널을 토글하고 로컬 세션에서만 연다. oort의 ⌃`와 같다.
- **Conductor**: 같은 Tauri 스택에서 워크스페이스마다 worktree·터미널·diff를 둔다. 이 경험이 Tauri로 된다는 증거다.
- **Warp**: 상태가 바뀔 때만 알리는 에이전트 패널. oort는 토스트 대신 인박스와 OS 알림으로 보낸다.
- 공통점은 「로컬 터미널은 사람의 것」이다. 원격 조종이 필요한 일은 별도 레인(Orca SSH relay, Claude Remote Control)이 맡는다. oort는 그 레인을 0188 A 레인으로 둔다.

## Consequences
- (+) 서버 변경 없이 데스크탑만으로 로컬 워크벤치(M1)가 선다. R1 엔진 줄을 밀어내지 않는다.
- (+) 0188의 원격 불변식(셸 금지, 소유자 결정, 모드 고정)을 한 줄도 풀지 않는다.
- (+) 공유 세션의 입력 차단이 서버에서 강제되고 red proof로 잠긴다.
- (−) L 칸의 작업은 기본으로 원장에 남지 않는다. 감사가 필요한 작업은 A 레인을 쓰라고 안내한다.
- (−) App Store 배포는 PTY 위치 결정을 다시 요구한다(D1).
- 파생 이슈: #2772(PTY) · #2773(격자) · #2774(xterm 칸·도크·단축키) · #2775(새 세션·로컬 감지) · #2776(상태 점) · #2789(Remote Control 버튼) · #2793(공유 세션·red proof). P0 정리는 #2753.

## 증보 2026-09-26 — 온보딩 2.0: CLI 로그인 상태 확인 명령 실행 (D3)

- Status: **Accepted** (2026-09-26 성재 결재). 온보딩 2.0 제안서 Q4의 권장안이다. 결재 인용과 전체 결정은 ADR-0193에 있다.
- 기안: Opus 5.5 worker(#2805)

### D3-a. 감지는 두 상태 명령의 종료 코드까지 본다
- D3의 로컬 감지(PATH에서 CLI 찾기)에 더해, 데스크탑 셸은 아래 **두 명령만** 실행할 수 있다.
  - `claude auth status`
  - `codex login status`
- 판정은 **종료 코드만** 쓴다. 0이면 「CLI가 로그인됨이라고 알림」, 0이 아니면 「로그인 필요」, 실행 실패·시간 초과면 「확인 못 함」이다. Buzz도 같은 명령과 종료 코드 판정을 쓴다(`desktop/src-tauri/src/managed_agents/discovery.rs:153·186-187`, `readiness/cli_probe.rs:56-97`, Apache-2.0). 공식 문서도 종료 코드를 계약으로 적는다(Claude Code CLI reference: 로그인이면 0, 아니면 1).
- Buzz는 0이 아닐 때 stderr를 읽어 「설정 파일 오류」를 따로 가린다. oort는 stderr를 읽지 않으므로 설정 오류도 「로그인 필요」로 보인다. 사용자가 [터미널에서 로그인]으로 CLI를 열면 CLI가 스스로 오류를 알린다. 이 손실을 받아들인다.
- **stdout·stderr는 읽지 않는다.** 둘 다 버린다(`Stdio::null()`). `claude auth status`는 기본 출력이 JSON이고 계정 정보가 들어 있을 수 있기 때문이다. 명령 결과는 웹뷰에 세 값(로그인됨·로그인 필요·확인 못 함) 중 하나로만 넘긴다.
- **토큰과 자격 파일은 열지 않는다.** `~/.claude/`, `~/.codex/auth.json`, 키체인 항목, 환경 변수의 키를 읽지 않는다. Anthropic 법무 문서의 「자격·세션 토큰을 수집·저장·중개하지 않는다」를 지키는 선이다.
- 명령은 PATH에서 찾은 바이너리 절대 경로로, 셸 없이, 인자 고정으로 실행한다. 시간 제한을 둔다(값은 구현 이슈가 정한다). 웹뷰가 명령이나 인자를 넘길 수 없다. 서버 이벤트와 딥링크는 이 명령을 부를 수 없다(D1과 같은 경계).
- `detect.rs`의 「다른 앱을 구동하지 않는다」 계약에서 **이 두 줄만** 예외다. 다른 앱의 디버그 포트 조사, 로그인 명령 대행, 설치 대행은 여전히 표현할 수 없다.

### D3-b. 시험으로 잠근다
- 소스 시험이 허용목록이 **정확히 두 명령**임을 단정한다. 명령 하나를 더하면 시험이 실패해야 한다.
- 소스 시험이 셸 소스에 자격 파일 경로 문자열(`.claude/`, `auth.json`, `credentials` 등)이 없음을 단정한다.
- 시험이 stdout을 읽는 코드가 없음을 단정한다(예: 가짜 CLI가 토큰 같은 문자열을 출력하고 종료 코드 0을 내도 웹뷰로 가는 값에 그 문자열이 없음).
- 각 단정은 해당 코드를 되돌리면 실패하는 것을 PR에 red proof로 남긴다.
- 구현: #2813(OB2-7).

### D3-c. 로컬 git 읽기 명령 허용목록

작업 탭의 worktree 보기·로그 패널(W-MVP)과 공유 요약(D4-b)이 쓰는 git 숫자는 이 기기에서 읽는다. 데스크탑 셸(Tauri Rust)은 아래 **여덟 명령만** 실행할 수 있다. `<git>`은 PATH에서 한 번 찾은 git 바이너리의 절대 경로다.

모든 명령 앞에 붙는 고정 접두 인자(생략하지 않는다):

```
<git> --no-pager --no-optional-locks -c core.fsmonitor=false -c core.pager=cat -c color.ui=false
```

| # | 명령(접두 뒤, 인자 전부 고정) | 웹뷰로 넘기는 값 |
|---|---|---|
| G1 | `rev-parse --show-toplevel` | 최상위 폴더의 **마지막 경로 요소**(저장소 표시 이름). 전체 경로는 셸 안에만 둔다 |
| G2 | `branch --show-current` | 브랜치 이름. 빈 값이면 「분리된 HEAD」 |
| G3 | `worktree list --porcelain -z` | worktree마다 폴더의 마지막 경로 요소, 브랜치 이름, `detached`·`locked`·`prunable` 표지 |
| G4 | `rev-list --left-right --count @{upstream}...HEAD` | 두 정수(뒤·앞 커밋 수). upstream이 없으면 명령이 0이 아닌 코드로 끝나고, 값은 「기준점 없음」이다. 다른 기준점으로 다시 시도하지 않는다 |
| G5 | `log --no-color --format=%h%x00%ct%x00%(trailers:key=Co-Authored-By,valueonly,separator=%x2C) -n 50 @{upstream}..HEAD` | 커밋마다 짧은 해시, 커밋 시각(초), 공동 작성자 **이름**(이메일은 버린다). upstream이 없으면 G4와 같다 |
| G6 | `diff --numstat --no-ext-diff --no-textconv -z HEAD` | 파일마다 추가·삭제 줄 수와 저장소 기준 **상대 경로**, 합계. 이진 파일은 `-` 대신 「이진」 |
| G7 | `diff --numstat --no-ext-diff --no-textconv -z @{upstream}...HEAD` | G6과 같은 모양의 기준점 이후 합계와 파일별 숫자 |
| G8 | `status --porcelain=v1 -z --untracked-files=normal` | 수정·추가·삭제·추적 안 함 파일의 **개수** 넷. 경로는 넘기지 않는다 |

- **커밋 제목·본문, 파일 내용, diff 본문, 원격 URL은 웹뷰로도 넘기지 않는다.** 제안서 §3.5의 worktree 카드 「마지막 커밋 한 줄」은 이 증보로는 표시할 수 없다. 로컬에서 커밋 제목을 보여야 하면 이 표에 한 줄을 더하는 증보를 따로 낸다.
- **셸 없이 실행한다.** `sh -c`, `cmd /C`, 문자열 명령 줄 조립을 쓰지 않는다. 인자는 배열로 넘긴다.
- **웹뷰는 명령도 인자도 폴더도 넘기지 않는다.** 웹뷰가 넘기는 것은 명령 번호(G1~G8)와 칸 ID뿐이다. 실행 폴더(cwd)는 셸이 그 칸의 PTY에 기록해 둔 폴더에서 정한다. 서버 이벤트, 딥링크, workd는 이 명령을 부를 수 없다(D1과 같은 경계).
- **설정이 코드를 실행하는 길을 막는다.** 읽기 명령도 저장소 설정(`core.fsmonitor`, 외부 diff·textconv, pager)으로 임의 프로그램을 띄울 수 있다. 위 고정 접두·`--no-ext-diff --no-textconv`로 막는다. 환경은 `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `GIT_PAGER=cat`, `GIT_EXTERNAL_DIFF` 제거로 고정한다. 쓰기 명령(`fetch`, `gc`, `commit`, `checkout` 등)과 네트워크를 쓰는 명령은 목록에 없다.
- **stdout은 셸 안에서 파싱하고 stderr는 버린다.** 파싱 결과의 정해진 필드만 웹뷰로 넘긴다. stdout 원문을 넘기는 경로가 없다. D3-a의 두 로그인 명령은 여전히 stdout·stderr를 둘 다 버린다(그 규칙은 바뀌지 않는다).
- 명령마다 시간 제한과 stdout 바이트 상한을 둔다(값은 구현 이슈가 정한다). 넘으면 「확인 못 함」이다.
- **서버 호출은 0이다.** 결과는 이 기기의 웹뷰에만 간다. 서버로 가는 것은 D4-b가 허용한 합계 숫자뿐이고, 그것도 공유를 켠 세션에서만이다.
- `gh`(GitHub CLI)와 그 밖의 네트워크 명령은 이 목록에 없다. PR URL은 D4-b의 출처 규칙으로 들어온다.
- D3-a의 「`detect.rs`의 "다른 앱을 구동하지 않는다" 계약에서 이 두 줄만 예외다」는 이제 **「로그인 상태 두 줄(D3-a)과 git 읽기 여덟 줄(D3-c)만 예외다」**로 읽는다. 다른 앱의 디버그 포트 조사, 로그인·설치 대행, 쓰기 git 명령은 여전히 표현할 수 없다.

**시험으로 잠근다(red proof 필수).** 아래 단정마다 해당 코드를 되돌리거나 한 줄을 더하면 실패하는 것을 PR에 남긴다. 구현: T3(제안서 §8.4).
- 허용목록이 **정확히 여덟 명령**이고 인자가 위 표와 글자 그대로 같다. 명령이나 인자 하나를 더하면 실패한다. 이 목록은 D3-b의 로그인 상태 목록(정확히 두 명령)과 **별도 목록**이다. 두 시험은 각자의 목록을 세고, 한쪽 명령이 다른 쪽 목록으로 옮겨 가도 실패한다.
- 실행 코드에 셸 경유(`sh`, `-c` 명령 문자열, `cmd`)가 없다.
- 웹뷰 명령의 입력 타입에 명령 문자열·인자·경로 필드가 없다(명령 번호와 칸 ID뿐).
- 고정 접두 인자와 환경 고정이 모든 명령에 붙는다. 하나를 빼면 실패한다.
- 가짜 git이 stdout에 커밋 제목이나 토큰 같은 문자열을 섞어 내도 웹뷰로 가는 값에 그 문자열이 없다.
- 시간 제한 분기가 있다(멈춘 가짜 git으로 「확인 못 함」을 확인한다).

### D4-b. 공유 범위 S1과 출처 규칙

D4의 「이름 · 폴더 표시 이름 · 상태」를 아래 **S1**로 넓힌다(Q2). 공유의 기본값은 여전히 끔이고, 켜는 것은 주인이 칸에서 명시적으로 한다.

**S1 필드(이것 외에는 싣지 않는다).**

| 필드 | 출처 | 상한·형식 |
|---|---|---|
| 세션 이름 | 칸 라벨(주인이 정함) | 80자 |
| 저장소 표시 이름 | D3-c G1 | 100자, 경로 구분자 금지 |
| 브랜치 이름 | D3-c G2 | 200자 |
| 폴더 표시 이름 | 칸 폴더의 마지막 경로 요소(D4 그대로) | 100자 |
| 하네스 라벨 | 로컬 감지(D3) | 닫힌 목록 `claude`·`codex`·`grok`·`opencode`·`shell`·`other` |
| 파생 상태 | 칸 상태 판정(#2776·T8): 실행 중·나를 기다림·검토 대기·대기·조용함·끝남·멈춤 | 닫힌 목록. `work_session.status`와 별도 필드 |
| 단계 표지 | 하네스 구조 신호(아래 출처 규칙) | 최대 12개, 각 80자, 제어 문자·ANSI 제거 |
| diff 숫자 | D3-c G4·G7·G8 | 정수만: 추가·삭제 줄, 파일 수, 앞·뒤 커밋 수, 커밋 안 한 변경 수. **파일 이름은 싣지 않는다** |
| PR URL | 아래 출처 규칙 | 한 줄, `https`, `/pull/<번호>`로 끝남. 형식 검증은 ADR-0194 |
| 마지막 활동 시각 | 칸 이벤트 | 초 단위로 버림 |

- **싣지 않는 것(불변):** raw 바이트, 스크롤백, 명령 줄, 파일 내용, 파일 경로(마지막 요소 외), 파일 이름 목록, 환경 변수, 원격 저장소 URL, 권한 요청 본문, **커밋 제목**(Q2 — 고객명·내부 코드명이 섞일 수 있고, 서버에 가면 회수가 어렵다. 필요해지면 세션별 옵트인 증보로 연다).
- PR URL에는 GitHub의 `소유자/저장소`가 들어 있다. Q2가 PR URL을 S1에 넣었으므로 이 노출은 받아들인 것이다. 원격 URL 자체는 싣지 않는다.

**출처 규칙: 긁지 않는다(Q3).**
- L 세션의 요약은 **PTY 출력을 파싱하거나 모델로 요약해서 만들지 않는다.** 그렇게 하면 raw가 요약의 모양으로 기기 밖에 나간다(D2 우회).
- 허용 출처는 셋뿐이다.
  1. 하네스가 스스로 내는 구조 신호: Claude Code hook(Stop, Notification 등)과 statusLine, Codex `notify`, OSC 제목. 어떤 신호를 실제로 받을 수 있는지는 #2776 스파이크가 정한다.
  2. D3-c의 git 읽기 결과 숫자.
  3. 칸 생명주기: 시작, 종료 코드, 마지막 출력 **시각**(출력 내용은 아니다).
- PR URL도 이 셋에서만 온다: 하네스 구조 신호에 실린 URL, 또는 주인이 칸 메뉴에 직접 붙여 넣은 URL. `gh` 실행과 GitHub API 호출은 하지 않는다(Q6, ADR-0192 D7).
- 결과로 **셸 칸은 상태·생명주기·git 숫자만** 공유된다. hook을 내는 하네스 칸은 더 풍부하다. 이 차이를 카드 문구로 숨기지 않는다.
- A 레인(workd)은 이 규칙의 대상이 아니다. host가 사용자의 모델로 턴 요약을 만드는 경로는 ADR-0188 D4에 이미 결정돼 있다.

**집 채널(Q4·Q5).**
- `work_session`은 `channel_id`와 `root_message_id`가 필수다. 그래서 **공유를 켜는 순간 집 채널 하나를 고른다.** 기본값은 이 저장소(저장소 표시 이름)로 마지막에 공유한 채널이고, 처음이면 주인이 직접 고른다. 이 기본값 기억은 **이 기기에만** 둔다(ADR-0174). 서버는 저장소 → 채널 대응을 저장하지 않는다.
- 주인이 멤버이고 글을 쓸 수 있는 채널만 고를 수 있다. **워크스페이스 전체 공개는 없다.** 가시성은 집 채널 멤버십과 기존 채널 RLS만 따른다.
- 집 채널은 정해지면 바꾸지 않는다. 다른 채널에 알리고 싶으면 링크를 붙인다. 링크는 집 채널 멤버에게만 펼쳐진다(ADR-0194).
- 「채널에 공유」는 공유 켜기(아직 꺼져 있으면) + 집 채널 지정 + root 카드 게시를 한 번에 한다(Q5).
- 「링크 복사」는 공유가 꺼진 세션이면 「이 세션을 공유할까요? 팀은 이름·상태·worktree만 봅니다」를 먼저 묻는다. 거절하면 링크를 만들지 않는다. 주인만 여는 링크는 따로 두지 않는다(Q5).

**공유 해제와 보존 기한.**
- 해제(`shared:false`)하면 **같은 tx에서** S1 확장 필드를 지우고 outbox에 상태 전환 이벤트를 넣는다. 카드는 「공유가 꺼진 작업이에요」로 바뀐다. 세션 행과 root 메시지는 원장 규칙대로 남는다.
- 보존 기한: 세션이 끝나고(`ended_at`) **30일**이 지나면 S1 확장 필드를 지운다. 기존 sweep 경로에서 한다. 이름·상태 같은 D4의 기본 필드는 원장 규칙을 따른다.
- 집 채널이 지워지면 기존 FK(`ON DELETE CASCADE`)대로 세션 행과 확장 필드가 함께 지워진다.

**저장과 경계.**
- S1 확장 필드는 **새 테이블 `work_session_share`**(세션당 한 행, `workspace_id` 포함)에 둔다. 해제·보존 삭제가 행 삭제 하나로 끝나고, `work_session`의 원장 컬럼과 섞이지 않는다. `server/Migrations/`의 새 migration으로만 추가하고, RLS FORCE 정책 대상에 넣는다. Rust는 sqlx 런타임 쿼리를 쓴다. `work_session.tool` CHECK 확장(`grok` 등)도 같은 migration에서 한다(T10).
- 공유 페이로드는 host 서명(ADR-0125·0188 v2 서명) 경로로만 받는다. 서버가 **스키마로 검증**한다: 알려진 필드 외 거부, 필드별 상한 초과 거부, 닫힌 목록 밖 값 거부. 라우트는 ADR-0194.
- **D4의 서버측 컨트롤 거부는 그대로다.** 공유 L 세션(`origin='local_pty'`)에 대한 모든 `work.control.*` 생성을 컨트롤 생성 라우트가 거부하고, #2793의 red proof가 머지 조건이다. S1이 넓어져도 입력·멈춤·허락 경로는 생기지 않는다.

**시험(각각 되돌리면 실패하는 red proof).**
- 데스크탑 수집기 소스에 PTY 출력 → 공유 페이로드 경로가 없다. 가짜 PTY가 토큰 같은 문자열과 커밋 제목을 출력해도 페이로드에 없다(T9).
- 서버가 스키마 밖 필드, 상한 초과, 닫힌 목록 밖 값을 거부한다(T10).
- 해제하면 같은 tx에서 확장 행이 없어지고, 보존 sweep이 30일 지난 행을 지운다(T10).
- 공유 L 세션 컨트롤 생성 거부(#2793, D4에서 이미 요구).

### D3-d. 공식 CLI 구조화 출력에서 허용 필드만 읽는다 (Q1 2단계, Q5)
- 1단계(지금)는 사용자가 붙인 라벨만 보인다. D3-a 그대로다.
- 2단계에서 데스크탑 셸은 아래 출력을 **정해진 필드만 역직렬화**하고 나머지는 버린다. 원문은 로그·오류 메시지·웹뷰 어디에도 싣지 않는다.

| 출처 | 명령·메서드(고정) | 읽는 필드 | 버리는 것(예) |
|---|---|---|---|
| Claude | `claude auth status --json` | `loggedIn`, `authMethod`, `subscriptionType`, `email` | `orgId`, `orgName`, `configDirectory`, `projectsDirectory`, 그 밖 전부 |
| Codex | `codex app-server`의 `account/read` | `account.type`, `account.planType`, `account.email`, `requiresOpenaiAuth` | `WorkspaceRouting`(`chatgptAccountId` 등), 그 밖 전부 |
| Codex | `account/rateLimits/read`, 알림 `account/rateLimits/updated` | `rateLimits.primary`·`secondary`의 `usedPercent`·`windowDurationMins`·`resetsAt`, `rateLimits.planType` | `accountId`, `credits`, `rateLimitResetCredits`, `rateLimitUpsell`, `spendControl*`, `limitName` 등 |
| Grok | 없음 | — | 구독 CLI의 공식 상태·사용량 출처가 없다(Q7). 「준비 중」 줄과 「웹에서 확인」 링크만 둔다 |

- **이메일은 셸 안에서 가린다.** 웹뷰에는 앞 두 글자 + `…` + `@도메인`만 간다(예: `sj…@gmail.com`). 가리기 전 원문은 웹뷰로 넘기지 않는다.
- `claude auth status`의 **판정은 여전히 종료 코드가 먼저다**(D3-a). JSON이 깨졌거나 필드가 없으면 판정은 종료 코드로만 하고 플랜·이메일 자리는 비운다. stderr는 계속 버린다. D3-a의 「stdout을 읽지 않는다」는 이 명령에 한해 「허용 필드만 역직렬화하고 나머지는 버린다」로 바뀐다. `codex login status`는 종료 코드만 그대로다.
- `codex app-server`를 이 목적(계정 확인)으로 띄울 때 보낼 수 있는 요청은 `initialize`, `account/read`, `account/rateLimits/read` **셋뿐**이다. `account/login/*`, `account/logout`, `account/rateLimitResetCredit/consume`, `account/sendAddCreditsNudgeEmail`, 스레드·턴 메서드는 이 연결에서 보내지 않는다. 프로필 폴더(`CODEX_HOME`)를 가리켜 띄우고, 응답을 받으면 프로세스를 끝낸다. 상주 데몬(`app-server daemon`)은 쓰지 않는다.
- 값은 **이 기기의 웹뷰에만** 간다. 서버로 가는 것은 ADR-0191 D3의 쿼터 숫자뿐이고, 플랜·이메일은 서버에 싣지 않는다.
- 토큰과 자격 파일은 여전히 열지 않는다(D3-a, ADR-0191 D2).

### D3-e. 앱 명령 로컬 실행기 (Q4)
「테마 바꿔 줘」 같은 앱 명령을 사용자 자신의 구독으로 푸는 경로다(제안서 §4.3 (B)).

**조건(전부 지킨다).**
- **사용자가 요청할 때만 뜬다.** ⌘K 「AI에게 부탁」을 사용자가 보낸 순간 프로세스 하나를 띄우고, 결과를 받거나 시간 제한이 지나면 끝낸다. 백그라운드·예약·서버 이벤트·딥링크·에이전트 메시지는 실행기를 띄울 수 없다(D1과 같은 경계).
- **입력은 두 가지뿐이다.** 명령 레지스트리의 스키마(명령 id·인자 모양)와 사용자가 친 문장. 채널 메시지, 파일, 워크스페이스 데이터는 넣지 않는다.
- **도구를 쓰지 않는다.** 읽기 전용 샌드박스, 승인 요청 없음(`never`), 파일 쓰기·셸·네트워크 도구 없음으로 띄운다. 작업 폴더는 빈 임시 폴더다.
- **출력은 `{commandId, args}`로만 파싱한다.** 레지스트리에 있는 명령이고 인자가 스키마를 통과할 때만 `settings_preview` 카드(ADR-0186 D6)로 그린다. 아니면 버리고 「이해하지 못했어요」를 보인다. 원문 출력은 저장·로그하지 않는다.
- **결과는 이 기기에만 있다.** 카드는 로컬이고 메시지로 게시하지 않는다. 「적용」은 레지스트리 `run`이다. 서버 호출 0.
- 프로필은 「기본 AI」 개인 행에서 고른 이 기기의 프로필이다. 환경 변수 제거는 ADR-0191 D2와 같다.

**하네스별.**
- **Codex: 연다.** `codex app-server`를 프로필 `CODEX_HOME`으로 띄우고 요청은 `initialize`, `thread/start`, `turn/start`, `turn/interrupt`만 쓴다. OpenAI는 app-server를 「자기 제품 안의 깊은 통합(인증, 대화 기록, 승인, 스트리밍 이벤트)」용 프로토콜로 문서화했다(https://learn.chatgpt.com/docs/app-server).
- **Claude: 구독으로는 열지 않는다.** 앱이 `claude -p`(headless)를 띄워 사용자의 Pro·Max 로그인으로 앱 기능을 푸는 것은 Anthropic이 허용한 「수정 없는 바이너리에 자기 구독으로 로그인」 예외 밖이라고 판단한다. 근거와 인용은 ADR-0193 같은 날짜 증보의 「약관 판단」 절이다. Claude 프로필은 앱 명령 라우팅의 선택지에 나오지 않는다. Claude만 있는 사용자의 앱 명령은 폴백(팀 키, 제안서 §4.3 (C))으로 간다. Anthropic의 사전 승인을 받거나 문서가 바뀌면 새 증보로 다시 연다.
- **Grok: 없다**(Q7).

### D3-f. 프로필 로그인·로그아웃 실행 (#2816, Q2)
#2816의 로그인 모달과 AI 계정 화면의 「연결 해제」가 쓰는 명령이다. 앱은 **숨은 PTY**(L 레인 PTY와 같은 구현, 기본으로 화면에 칸을 그리지 않는다)에서 공식 바이너리를 수정 없이 실행한다.

| # | 명령(인자 고정) | 환경 | 쓰는 곳 |
|---|---|---|---|
| A1 | `claude auth login --claudeai` | `CLAUDE_CONFIG_DIR` = oort 프로필 폴더, 또는 설정하지 않음(이 맥의 기본 위치) | 로그인 모달, 다시 로그인 |
| A2 | `claude auth logout` | `CLAUDE_CONFIG_DIR` = **oort 프로필 폴더만** | 연결 해제 |
| A3 | `codex login` | `CODEX_HOME` = oort 프로필 폴더, 또는 설정하지 않음 | 로그인 모달(localhost 콜백) |
| A4 | `codex login --device-auth` | A3과 같다 | 브라우저 콜백이 안 되는 환경의 폴백 |
| A5 | `codex logout` | `CODEX_HOME` = **oort 프로필 폴더만** | 연결 해제 |

- `--console`(API 과금 로그인), `--sso`, `--email`, `--with-api-key`, `--with-access-token`, `-c` 설정 덮어쓰기는 넘기지 않는다. 키·토큰을 stdin으로 넣는 로그인은 이 경로에 없다.
- **웹뷰는 프로필 id만 넘긴다.** 경로는 셸이 정한다. 셸은 폴더가 `~/Library/Application Support/oort/profiles/<harness>/<label>/` 아래인지 확인하고, 아니면 거부한다(ADR-0191 D1). 기본 위치(`~/.claude`, `~/.codex`)는 A1·A3 로그인에만 쓰고, **로그아웃(A2·A5)에는 쓸 수 없다**. 사용자가 터미널에서 쓰던 로그인은 목록에서만 뺀다(Q2).
- 실행 환경은 ADR-0191 D2대로 `ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`CLAUDE_CODE_OAUTH_TOKEN`·`OPENAI_API_KEY` 등을 제거한다.
- **PTY 출력은 읽지 않는다.** 로그인 URL·코드·토큰을 파싱·저장·로그·전송하지 않는다. 출력은 사용자가 「터미널로 보기」를 펼칠 때만 그 화면에 보인다. 브라우저는 CLI가 스스로 연다.
- **코드 붙여 넣기:** CLI가 코드 입력을 요구하면 모달의 입력 칸 하나에 사용자가 붙인 문자열을 PTY stdin에 그대로 쓴다. 저장·로그·서버 전송이 없다.
- **완료 판정은 D3-a 상태 명령이다.** 로그인 뒤 상태 명령이 0이면 「연결됐어요」, 시간 제한·취소면 PTY를 끝내고 실패로 닫는다. 새로 만든 프로필 폴더는 실패·취소 때 지운다.
- **연결 해제 순서:** A2·A5 로그아웃 → 종료 코드 0 → 상태 명령이 0이 아님을 확인 → 그때만 프로필 폴더 삭제. 로그아웃이 실패하면 폴더를 지우지 않고 「터미널로 보기」를 준다. oort는 자격 파일이나 키체인 항목을 직접 지우지 않는다. 지우는 것은 공식 CLI다.
- 공식 로그아웃이 프로필별 키체인 항목까지 지우는지는 확인하지 못했다(제안서 §9). 연결 해제 구현(AA-4)은 실제 CLI로 로그아웃 뒤 해당 항목이 남지 않음을 확인해 PR에 적어야 머지한다. 남는다면 폴더를 지우지 않고 이 증보를 고친다.

### D3-g. 목록은 서로 별도이고, 시험으로 잠근다
- `detect.rs`의 「다른 앱을 구동하지 않는다」 계약의 예외는 이제 **D3-a 상태 두 줄, D3-c git 여덟 줄, D3-d 계정 확인(`claude auth status --json`, `codex app-server` 세 요청), D3-e Codex 실행기(네 요청), D3-f 로그인·로그아웃 다섯 줄**이다. 그 밖은 표현할 수 없다.
- 소스 시험(각각 되돌리거나 한 줄을 더하면 실패하는 red proof를 PR에 남긴다):
  - 목록마다 정확한 개수와 인자·메서드 이름. 한 목록의 항목이 다른 목록으로 옮겨 가도 실패한다.
  - 허용 필드 밖 값이 웹뷰로 가지 않는다: 가짜 CLI·가짜 app-server가 `orgName`, `accountId`, 토큰 같은 문자열을 섞어 내도 웹뷰 값에 없다. 이메일은 가려진 모양으로만 간다.
  - 로그아웃에 기본 위치나 프로필 루트 밖 경로를 주면 거부한다.
  - 로그인 PTY 출력이 파싱·로그·전송 경로에 닿지 않는다(가짜 CLI가 URL·코드·토큰 모양 문자열을 내도 어디에도 남지 않는다). 붙여 넣은 코드가 저장되지 않는다.
  - 실행기 출력이 레지스트리 밖 명령이거나 스키마 밖 인자면 카드가 그려지지 않는다. Claude 프로필이 실행기 선택지에 나오지 않는다.
  - 실행기를 띄우는 호출 지점이 ⌘K 사용자 제출 하나뿐이다.
  - 가짜 CLI로 로그인 성공·코드 입력·취소·시간 초과 흐름. 실제 계정 왕복은 owner 계정이 필요해 `runtime-unverified`로 적는다.
