## Context

- 채널 헤더의 「터미널」은 실제 터미널이 아니다. 다른 호스트의 작업 세션을 관전만 하는 도크다(`TerminalDock.tsx`). 그런데 관전할 바이트를 만드는 호스트가 지금은 없다. Swift 호스트는 #2165에서 삭제됐고, Rust `momo-workd`는 ACP만 말하며 셸을 거부한다.
- 데스크탑(Tauri)에는 PTY도 터미널 렌더도 없다. ADR-0114 D1(앱 내장 세션 매니저)·D6(SwiftTerm과 ctrl+` 서랍)은 Swift 시대의 결정이고, Tauri로 옮긴 뒤 다시 정한 적이 없다.
- 두 신뢰 모델이 「터미널」 한 단어에 섞여 있다. 0114(2026-07)는 사람 직접 조작과 에이전트 spawn을 한 세션 매니저에 두고 셸을 프로파일로 허용했다. 0188(2026-09)은 원격·에이전트 경로를 ACP만, 셸 금지, 결정자 = 소유자로 좁혔다. 성재가 원하는 「셸 + 하네스 선택 + 분할」을 workd로 보내면 0188 D6과 정면으로 부딪힌다.

## Options

| 선택지 | 내용 | 판단 |
|---|---|---|
| **A. 앱 프로세스 PTY, 원장 밖** | Tauri Rust 쪽이 PTY를 열고 xterm.js 칸에 그린다. 서버 컨트롤을 받지 않는다 | **채택.** 0188 불변식을 건드리지 않고 로컬 셸과 분할을 준다. 서버 변경 없이 M1이 선다 |
| B. workd 안의 PTY | 로컬 터미널도 workd가 열고 앱은 붙기만 한다 | 기각. 셸이 workd에 들어가면 0188 D6 「원격 셸 금지」를 설정으로 가르는 모양이 된다. 두 레인의 경계가 흐려진다 |
| C. 비샌드박스 helper 프로세스 | App Sandbox 배포판에서 PTY를 helper에 맡긴다(0114 보강 절) | 보류. 목표 A 동안 App Store로 데스크탑을 내지 않으므로(D1) 필요 없다. 스토어가 필요해지면 따로 ADR을 낸다 |
| D. 로컬 세션도 기본 원장 등록 | 모든 로컬 칸을 `work_session`으로 올린다 | 기각. raw가 새는 표면이 늘고, 등록 전 데스크탑(M1)에서는 `host_id`가 없어 불가능하다(0114 D8) |

## Decision

### D1. PTY는 데스크탑 앱 프로세스가 연다
- Tauri Rust 쪽이 `portable-pty` 계열(permissive) 라이브러리로 PTY를 열고, 앱 웹뷰의 xterm.js 칸이 그린다. 칸마다 headless 미러를 두어 앱 재시작 뒤 스크롤백을 복원한다.
- PTY 명령은 앱 웹뷰에서만 부른다. 서버 이벤트, 딥링크, workd는 PTY를 열 수 없다. 구현은 이것을 소스 시험으로 단정한다.
- **목표 A 동안 데스크탑은 공증 DMG로만 배포하고 Mac App Store에 내지 않는다**(Q7). 그래서 앱이 PTY를 직접 연다. 스토어 배포가 필요해지면 PTY를 비샌드박스 helper로 옮기는 ADR을 따로 낸다. ADR-0114의 「배포판 App Sandbox 경계」 절은 그때 다시 본다.

### D2. 로컬 레인은 비원장이 기본이고, 셸은 로컬에서만 허용한다
- 로컬 터미널(L 레인)은 앞에 앉은 사람이 직접 쓴다. 서버 컨트롤(`work.control.*`)을 받지 않고, 원격에서 spawn·input을 할 수 없다. 기본은 서버에 등록하지 않는다.
- 사람 직접 조작이므로 승인이 없다(0114 D5 「사람 직접 조작은 승인 불요」와 같다).
- **셸과 임의 CLI는 L 레인에서만 허용한다.** 에이전트 작업 레인(A 레인, workd·ACP)은 0188 D6 그대로 셸 금지, 모드 고정이다.
- 하네스는 기본 권한 모드로 띄운다. `--dangerously-skip-permissions` 같은 우회 플래그를 기본으로 켜지 않는다. 바꾸는 것은 사용자가 칸에서 명시적으로 한다.
- raw 출력은 로컬 화면에만 있다. 서버에 싣지 않는다.

### D3. 하네스 목록의 정본은 로컬 감지다
- L 칸의 하네스 목록은 이 기기의 PATH에서 찾은 CLI(`claude`, `codex`, `grok` 등)가 정본이다.
- 서버 `work_tool_profile`은 표시 이름과 아이콘 같은 **라벨**로만 쓴다. 워크스페이스 관리자의 표가 소유자의 맥에서 감지된 CLI를 막지 못한다.
- `work_tool_profile`이 정본인 곳은 A 레인뿐이다. 그것도 원격에서는 0188 D6에 따라 host 허용목록이 우선한다.

### D4. 「공유」 세션 종류를 두고, 서버가 컨트롤을 거부한다
- L 칸은 선택적으로 「공유」할 수 있다. 이름, 폴더 표시 이름(마지막 경로 요소), 상태만 올린다. 켜면 ADE 요약 줄과 폰 목록에 「성재 · 로컬 · 실행 중」으로 보인다. **기본은 끔이다.**
- 선행 조건: `work_session`은 `host_id`가 필수다(0114 D8). 그래서 공유는 데스크탑이 `work_host`로 등록된 뒤(0188 R1 등록 GUI)에야 된다. M1의 L 칸은 전부 등록하지 않는다.
- 공유된 L 세션은 **별도 종류로 기록한다**(예: `origin='local_pty'`). 컨트롤 생성 라우트는 그 종류의 세션에 대한 모든 `work.control.*` 생성을 **거부한다**. 호스트가 받고 무시하는 방식은 안 된다. 강제 없는 경계는 깨진다(0143 D3와 같은 이유).
- 폴더 전체 경로와 raw 바이트는 싣지 않는다(0188 §3 「서버에 폴더 경로 비저장」과 같은 방향).
- **요구 사항 — red proof:** 「공유 L 세션에 input 컨트롤 생성 → 거부」 conformance 시험이 있어야 한다. 거부 분기를 지우면 이 시험이 실패해야 한다. 이 시험 없이는 공유 기능을 머지하지 않는다(#2793).

### D5. 단축키 (Q4)
macOS 기준이다. Windows·Linux는 ⌘를 Ctrl로 읽는다.

| 동작 | 키 | 비고 |
|---|---|---|
| 터미널 도크 열고 닫기 | **⌃`** | `event.code === "Backquote"`로 판정한다. 한글 2벌식에서 같은 키가 `₩`를 내기 때문이다. ⌘`는 macOS 창 순환이라 쓰지 않는다 |
| 전체 화면 작업 공간 | ⌃⇧` | 도크를 격자로 키운다 |
| 새 세션 | ⌃⇧N (도크 포커스 중이면 ⌘T) | ⌘N은 새 창 관습이라 피한다 |
| 오른쪽으로 분할 / 아래로 분할 | ⌘D / ⌘⇧D | Orca 기본값, iTerm2 관습 |
| 칸 포커스 이동 | ⌘⌥←↑→↓(방향), ⌘] / ⌘[(순환) | |
| 칸 번호로 이동 | ⌃1..9 | ⌘1..9는 워크스페이스 전환에 남긴다 |
| 칸 최대화 토글 | ⌘⇧↵ | |
| 세션 점프 팔레트 | ⌘J | ⌘K(검색·이동)와 따로 둔다 |
| 칸 닫기 | ⌘W (실행 중이면 확인) | L 칸은 프로세스를 끝낸다. A 칸은 창만 닫고 세션은 계속된다. 문구로 구분한다 |
| 다음 「나를 기다림」으로 | ⌃⇧J | |

- 터미널에 포커스가 있으면 앱 단축키보다 터미널 입력이 먼저다. 위 표의 앱 키만 가로챈다. 이 목록은 설정에서 볼 수 있다.
- 도크 크기는 위 경계를 드래그한다. 크기와 격자 배치는 이 기기에 세션(worktree)마다 저장한다(ADR-0174).

### D6. 팀원 터미널 raw 관전은 목표 A 뒤로 미룬다 (Q3)
- 팀 관전은 큐레이션된 진행 뷰(ADR-0154 D2)로 먼저 한다.
- raw 관전은 workd에 PTY와 링버퍼를 다시 키우고 직결 불가 망의 중계(0125 D10)까지 풀어야 한다. 목표 A 뒤에 다시 정한다.
- 그때까지 관전 도크는 P0에서 정리한다(#2753).

### D7. 두 레인은 한 격자에 섞이고, 칸을 옮기지 않는다
- L 칸(xterm)과 A 칸(진행 뷰)이 같은 격자에 놓인다. 머리 문구와 아이콘으로 구분한다(`로컬` / `에이전트 · oort에 기록`). 색에만 기대지 않는다.
- 로컬 TUI에서 하던 일을 폰에서 이어받고 싶으면 같은 폴더·브랜치에서 A 세션을 새로 연다(0125 D11 계보 재개, 0154 D3 「인수」). PTY를 옮기지 않는다.
- 「나를 기다림」과 「끝남」은 기존 인박스와 OS 알림으로 합류한다. 토스트는 쓰지 않는다(ADR-0182).

## 업계 비교
- **Orca**(MIT): 칸마다 `node-pty` + xterm, OSC 제목과 hook으로 상태 점, 분할 단축키 ⌘D/⌘⇧D, 방향 포커스 이동은 없다. 하네스를 우회 플래그로 기본 실행한다. oort는 분할·상태 점 문법을 가져오고 우회 기본값은 따르지 않는다.
- **Claude Code 데스크탑**: Ctrl+`로 터미널을 토글하고 로컬 세션에서만 연다. oort의 ⌃`와 같다.
- **Conductor**: 같은 Tauri 스택에서 워크스페이스마다 worktree·터미널·diff를 둔다. 이 경험이 Tauri로 된다는 증거다.
- **Warp**: 상태가 바뀔 때만 알리는 에이전트 패널. oort는 토스트 대신 인박스와 OS 알림으로 보낸다.
- 공통점은 「로컬 터미널은 사람의 것」이다. 원격 조종이 필요한 일은 별도 레인(Orca SSH relay, Claude Remote Control)이 맡는다. oort는 그 레인을 0188 A 레인으로 둔다.

## Consequences
- (+) 서버 변경 없이 데스크탑만으로 로컬 워크벤치(M1)가 선다. R1 엔진 줄을 밀어내지 않는다.
- (+) 0188의 원격 불변식(셸 금지, 소유자 결정, 모드 고정)을 한 줄도 풀지 않는다.
- (+) 공유 세션의 입력 차단이 서버에서 강제되고 red proof로 잠긴다.
- (−) L 칸의 작업은 기본으로 원장에 남지 않는다. 감사가 필요한 작업은 A 레인을 쓰라고 안내한다.
- (−) App Store 배포는 PTY 위치 결정을 다시 요구한다(D1).
- 파생 이슈: #2772(PTY) · #2773(격자) · #2774(xterm 칸·도크·단축키) · #2775(새 세션·로컬 감지) · #2776(상태 점) · #2789(Remote Control 버튼) · #2793(공유 세션·red proof). P0 정리는 #2753.

## 증보 2026-09-26 — 온보딩 2.0: CLI 로그인 상태 확인 명령 실행 (D3)

- Status: **Accepted** (2026-09-26 성재 결재). 온보딩 2.0 제안서 Q4의 권장안이다. 결재 인용과 전체 결정은 ADR-0193에 있다.
- 기안: Opus 5.5 worker(#2805)

### D3-a. 감지는 두 상태 명령의 종료 코드까지 본다
- D3의 로컬 감지(PATH에서 CLI 찾기)에 더해, 데스크탑 셸은 아래 **두 명령만** 실행할 수 있다.
  - `claude auth status`
  - `codex login status`
- 판정은 **종료 코드만** 쓴다. 0이면 「CLI가 로그인됨이라고 알림」, 0이 아니면 「로그인 필요」, 실행 실패·시간 초과면 「확인 못 함」이다. Buzz도 같은 명령과 종료 코드 판정을 쓴다(`desktop/src-tauri/src/managed_agents/discovery.rs:153·186-187`, `readiness/cli_probe.rs:56-97`, Apache-2.0). 공식 문서도 종료 코드를 계약으로 적는다(Claude Code CLI reference: 로그인이면 0, 아니면 1).
- Buzz는 0이 아닐 때 stderr를 읽어 「설정 파일 오류」를 따로 가린다. oort는 stderr를 읽지 않으므로 설정 오류도 「로그인 필요」로 보인다. 사용자가 [터미널에서 로그인]으로 CLI를 열면 CLI가 스스로 오류를 알린다. 이 손실을 받아들인다.
- **stdout·stderr는 읽지 않는다.** 둘 다 버린다(`Stdio::null()`). `claude auth status`는 기본 출력이 JSON이고 계정 정보가 들어 있을 수 있기 때문이다. 명령 결과는 웹뷰에 세 값(로그인됨·로그인 필요·확인 못 함) 중 하나로만 넘긴다.
- **토큰과 자격 파일은 열지 않는다.** `~/.claude/`, `~/.codex/auth.json`, 키체인 항목, 환경 변수의 키를 읽지 않는다. Anthropic 법무 문서의 「자격·세션 토큰을 수집·저장·중개하지 않는다」를 지키는 선이다.
- 명령은 PATH에서 찾은 바이너리 절대 경로로, 셸 없이, 인자 고정으로 실행한다. 시간 제한을 둔다(값은 구현 이슈가 정한다). 웹뷰가 명령이나 인자를 넘길 수 없다. 서버 이벤트와 딥링크는 이 명령을 부를 수 없다(D1과 같은 경계).
- `detect.rs`의 「다른 앱을 구동하지 않는다」 계약에서 **이 두 줄만** 예외다. 다른 앱의 디버그 포트 조사, 로그인 명령 대행, 설치 대행은 여전히 표현할 수 없다.

### D3-b. 시험으로 잠근다
- 소스 시험이 허용목록이 **정확히 두 명령**임을 단정한다. 명령 하나를 더하면 시험이 실패해야 한다.
- 소스 시험이 셸 소스에 자격 파일 경로 문자열(`.claude/`, `auth.json`, `credentials` 등)이 없음을 단정한다.
- 시험이 stdout을 읽는 코드가 없음을 단정한다(예: 가짜 CLI가 토큰 같은 문자열을 출력하고 종료 코드 0을 내도 웹뷰로 가는 값에 그 문자열이 없음).
- 각 단정은 해당 코드를 되돌리면 실패하는 것을 PR에 red proof로 남긴다.
