# ADR-0148: 인용 답글 — `reply_to_id`를 깨운다 (스레드와 다른 장치다)

- Status: **Accepted** (2026-08-03 성재 승인 · 기안 Fable)
- 관련: ADR-0137 D5(v0 축 = 관전·승인·대화), ADR-0134(멘션 라우팅), UX 바이블 P-스레드 원칙
- 발단: 성재 실기기 피드백 — *"인용 느낌으로 답글 대신에 **해당 글에 대해 직접 인용 답글**을 다는 기능도 필요할 거 같아."*

## 실측 (이 결정의 출발점)

```
schema_v0.sql:176   reply_to_id uuid REFERENCES message(id)   -- direct reply target
```

- **스레드는 `root_id`로 구현돼 있다.** `reply_to_id`가 아니다.
- `reply_to_id`는 **컬럼도 있고 INSERT 바인딩도 있는데**(`momo-messaging/src/message.rs:390,406`) **모든 호출부가 `None`을 넣는다** — 서버 라우트 1곳, 에이전트 워커 3곳 등 확인된 전부. **이 컬럼에 non-null이 들어간 적이 한 번도 없다.**
- 즉 **스키마 변경 없이** 깨울 수 있다. 마이그레이션 불필요.

## 결정

**`reply_to_id`를 "이 메시지가 가리키는 메시지"로 깨운다. 스레드(`root_id`)와 나란히 쓰되, 절대 겹치지 않는다.**

두 장치의 의미를 여기서 확정한다.

| | `root_id` (스레드) | `reply_to_id` (인용) |
|---|---|---|
| 뜻 | **소속** — 이 메시지는 저 대화의 일부다 | **지목** — 이 메시지는 저 메시지를 가리킨다 |
| 어디 뜨나 | 채널 목록에서 접힘, 스레드 화면에서 펼침 | **채널 본류에 그대로 뜬다** |
| 개수 롤업 | 있다(「답글 N개」) | **없다** |
| 알림 | 스레드 구독자 | 인용당한 사람(멘션 규칙과 동일) |
| 중첩 | 한 단계(기존 규칙 유지) | **인용의 인용은 원본만 보여준다**(아래) |

**핵심 문장: 스레드는 대화를 옆으로 치우는 장치고, 인용은 대화를 본류에 두면서 맥락만 끌어오는 장치다.** 둘을 하나로 합치면 "옆으로 치우고 싶지 않은데 맥락은 필요한" 경우가 갈 곳이 없어진다 — 성재가 지적한 게 정확히 그 자리다.

## 규칙 (구현이 지킬 것)

1. **한 메시지가 둘 다 가질 수 있다.** 스레드 안에서 그 스레드의 특정 답글을 인용하는 건 자연스럽다. `root_id`와 `reply_to_id`는 배타가 아니다.
2. **인용 대상은 같은 채널 안에 있어야 한다.** 교차 채널 인용은 v0 범위 밖 — RLS·읽기권한·"내가 못 보는 메시지가 인용돼 보임" 문제를 한꺼번에 연다. 서버가 거부한다.
3. **인용 렌더는 스냅샷이 아니라 참조다.** 원본이 수정되면 인용도 따라 바뀌고, 삭제되면 **"삭제된 메시지"**로 남는다. 스냅샷으로 굳히면 삭제한 사람의 의사를 우회하는 사본이 생긴다.
4. **인용의 인용은 한 겹만 그린다.** 원본 안의 인용까지 펼치면 타임라인이 계단이 된다. 두 번째 겹은 "↳ 인용" 표시만.
5. **알림은 멘션과 같은 규칙을 탄다.** 인용당하는 건 이름이 불리는 것과 같다. 새 알림 종류를 만들지 않는다.
6. **에이전트도 인용할 수 있다** — 에이전트=member 무분기(하드 불변식). 에이전트가 "이 메시지에 답한다"를 표현할 때 `reply_to_id`가 정답이고, 지금 `None`을 박고 있는 워커 3곳이 바로 그 자리다.

## 불변식 대조

| 불변식 | 영향 |
|---|---|
| 단일 쓰기경로 | 없음 — 인용은 일반 메시지 INSERT의 한 컬럼일 뿐 |
| gapless `message.seq` | 없음 — 인용 답글도 그냥 메시지, seq 정상 소비 |
| RLS FORCE | **규칙 2가 여기서 나온다** — 같은 채널 제약이 격리를 유지한다 |
| 에이전트=member | 규칙 6이 무분기를 유지 |
| Centrifugo 전송전용 | 없음 |

**마이그레이션 없음.** 컬럼이 이미 있고 FK도 이미 걸려 있다.

## 되돌리기

`reply_to_id`를 다시 `None`으로 박고 렌더를 끄면 끝난다. 데이터는 남지만 무해하다(외래키가 이미 정합을 보장). **한 방향 문이 아니다.**

## 미결 (구현 배치가 판단해 PR에 적을 것)
- 인용 블록의 접기 임계(긴 원본을 몇 줄에서 자를 것인가). 폰과 웹이 달라도 되는지.
- 인용 대상이 **에이전트의 긴 출력**일 때 무엇을 보여줄 것인가(우리만 `detail.rows`를 전부 펼치는 문제와 얽힌다).
- 컴포저에서 인용을 **취소**하는 동작(성재가 "채팅창 닫는 UX가 미흡"이라 지적한 계열 — 들어가는 길만 있고 나오는 길이 없으면 안 된다).
