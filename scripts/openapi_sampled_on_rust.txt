# openapi_sampled_on_rust.txt — 스펙-Rust 이중 샘플 매니페스트 (SRV-B7 / #1042).
#
# 한 줄 = "METHOD /spec/path/{template}" — docs/api/openapi.yaml 이 쓰는 그 경로
# 템플릿 그대로. 여기 실린 연산은 scripts/verify_openapi_contract_rust.sh 가
# **Rust 배포본**(server-rust/Dockerfile 이미지 + infra/rust 컴포즈 부분집합)에
# 실제로 왕복시켜 응답 모양을 스펙과 대조한다.
#
# ── 왜 두 번째 매니페스트인가 ────────────────────────────────────────────────
# openapi 계약 게이트의 1차 패스는 e2e 컴포즈(swift:6.2)를 띄워 스펙 전 연산을
# 샘플한다. 그런데 스펙은 이제 Rust 배포본을 서술한다(#1040) — 즉 "스펙대로다"를
# Swift 로만 증명하면, 정본이 Rust 로 넘어간 경로에서는 게이트가 실제로는 아무것도
# 증명하지 않는다. 이 파일은 그 간극을 이름 붙여 닫는다: **여기 실린 경로는
# Rust 에서 실측됐다**가 게이트의 주장이 된다.
#
# ── 성장형 목록 (single direction: 늘어난다) ────────────────────────────────
# known-unsampled(scripts/openapi_known_unsampled.txt)가 "줄어들 수만 있는 부채
# 목록"인 것과 정확히 반대다. 이 목록은 **늘어날 수만 있다**. 이식이 진행돼 어떤
# 경로의 정본이 Rust 로 넘어가면 그때 여기에 한 줄을 추가하고, 그 줄은 다시
# 빠지지 않는다. 목록이 스펙 전 연산을 덮는 날 1차(Swift) 패스는 증명할 것이
# 남지 않고 — 그것이 이 파일이 Swift 패스를 잠식·최종 대체하는 방식이다.
#
# ── 등재의 효과: 모양 권위의 이전 ────────────────────────────────────────────
# 한 줄을 추가하면 그 연산의 **응답 모양에 대한 권위가 1차 패스에서 2차 패스로
# 넘어간다**. 1차(Swift) 패스는 그 연산을 여전히 호출하고 상태코드도 계속 단정하지만
# (Swift 가 거기서 500 을 내기 시작하면 여전히 1차에서 빨강이다), 응답 바디를
# 매니페스트에 기록하지 않고 스펙과 대조하지도 않는다.
#
# 왜 그래야 하나: #1040 이 스펙의 승인 스키마를 **배포된 와이어**(Rust, camelCase)로
# 맞춘 순간부터, Swift(snake_case)는 그 연산에서 구조적으로 스펙과 어긋난다. 그건
# 1차 패스가 잡아야 할 드리프트가 아니라, 1차 패스가 더는 그 연산의 권위가 아니라는
# 사실이다. 커버리지는 사라지지 않고 **이동한다** — 등재된 연산은 2차 패스가 스펙과
# 대조하므로 게이트 전체로 보면 여전히 전 연산이 검증된다.
#
# 2차 패스를 끄면(OPENAPI_GATE_RUST_PASS=0) 이 목록은 없는 것으로 취급된다.
# 아무도 샘플하지 않는 연산이 조용히 면제되는 상태는 만들지 않는다.
#
# ── 등재 기준 ────────────────────────────────────────────────────────────────
# ① server-rust 가 그 연산을 실제로 라우팅한다(bins/momo-server/src/lib.rs).
# ② infra/rust 컴포즈 부분집합(postgres+centrifugo+api)만으로 왕복이 성립한다 —
#    relay/agent-worker/외부 목이 있어야 성립하는 경로는 그 서비스가 부분집합에
#    합류할 때 함께 등재한다.
# ③ 등재와 동시에 verify_openapi_contract_rust.sh 에 실샘플이 있다. 목록과 샘플은
#    **양방향**으로 강제된다(등재됐는데 미샘플 = 실패, 샘플인데 미등재 = 실패).
#    "나중에 채우겠다"는 줄은 존재할 수 없다.
# ④ 그 실샘플은 **그 라우트가 실제로 요구하는 자격증명**으로 돈다. #1132/#1143 이
#    이 기준을 필요하게 만들었다: `POST …/work-controls` 는 agent bearer 전용이고
#    `…/ack` 은 요청자와 다른 자격증명 — 등록 호스트 소유자 **또는 서명 데몬** —
#    을 받는다. 사람 bearer 로 편하게 200 을 받아 등재하면 목록은 자라지만
#    「Rust 에서 실측됐다」가 가리키는 문장이 달라진다. 그래서 ack 은 서명 arm 으로
#    샘플한다(#1143 §① 이 연 그 경로).
#
# ── 등재 대상 밖: 스펙에 아예 없는 라우트 ────────────────────────────────────
# 이 파일은 **스펙 연산의 검증 권위를 옮기는** 목록이다. 그러므로 docs/api/openapi.yaml
# 에 아예 없는 라우트는 등재 대상이 아니다 — 옮길 권위 자체가 없기 때문이다. 그런
# 라우트는 커버리지 대상도 아니고 known-unsampled(부채) 대상도 아니다. 필요한 것은
# 등재가 아니라 **스펙 성문화**이고, 그게 끝난 뒤에야 여기 한 줄이 될 수 있다.
# (등재 시 스크립트가 스펙 실재를 먼저 검사하므로, 성문화 전에 넣으면 즉시 빨강이다.)
#
# 현재 확인된 스펙 갭 — 성문화 후 등재 가능:
#   * `/v1/provider/link` 계열(GET/PUT/DELETE/test) — #1050
#   * ephemeral typing(「작성 중」) 계열 — #1053
#   * 아래도 server-rust 가 라우팅하는데 스펙에 없어 등재 대상 밖이다 — 옮길 권위
#     자체가 없으므로 커버리지도 부채도 아니고, 필요한 것은 성문화다:
#       GET /v1/workspaces/{ws} · POST /v1/workspaces
#       POST|DELETE /v1/workspaces/{ws}/channels/{ch}/members[/{member}]
#       GET|POST /v1/workspaces/{ws}/invites · POST …/channels/{ch}/agent-runs
#       POST|GET|DELETE /v1/workspaces/{ws}/devices[/{device}]
#       GET …/work-sessions/{session}/reattach · GET …/usage/summary
#       POST /v1/agent-runs/{run}/approval-decisions
#       GET|PUT /v1/provider/work-host-engine · GET /v1/provider/quota-snapshots
#       POST /v1/centrifugo/subscribe · agent gateway 5 경로
#
# ── 등재 보류: attachments 3경로 (#1111 / ADR-0151) ──────────────────────────
# 스펙에 성문화돼 있고(:2991,3041,3080) server-rust 가 실제로 라우팅한다 —
# 즉 기준 ①은 만족한다. 막는 것은 **기준 ②**다.
#
#   createAttachmentUpload / completeAttachmentUpload / getAttachmentContent 는
#   전부 Drive 아카이브가 살아 있어야 왕복이 성립한다. 그런데 infra/rust 부분집합
#   에는 그 백엔드가 없다:
#     * 아카이브 미설정 = 세 경로 모두 503. 상태코드는 스펙에 있지만 성공 스키마를
#       대조할 바디가 없으므로 "왕복"이 아니다.
#     * stub 백엔드 = infra/rust 는 MOMO_ENV=staging(strict)이고, 거기서
#       MOMO_DRIVE_ARCHIVE_BACKEND=stub 은 **부팅 거부**다(config::DriveSettings::
#       boot_error). 게이트를 위해 그 거부를 풀면 인메모리 아카이브가 배포 환경에서
#       허용된다는 뜻이 되므로, 그 방향은 택하지 않는다.
#     * 실 Drive 서비스 계정 = 게이트 스택에 provider 자격증명을 넣는 일이라
#       ADR-0004 상 논외다.
#
#   따라서 이 세 연산의 모양 권위는 당분간 1차(Swift) 패스에 남는다 — 거기서는
#   이미 stub 아카이브로 왕복 샘플이 돌고 있다(verify_openapi_contract.sh:1007-1034).
#   등재 조건: 부분집합에 **Drive 목 서비스**가 합류하거나, S3 호환 백엔드(ADR-0151
#   에서 v1 로 유보)가 들어와 자격증명 없이 왕복이 성립할 때. 그때 relay/agent-worker
#   와 같은 규칙으로 세 줄을 함께 추가한다.
#
# ── 등재 보류: T3(momo Cloud) 4경로 — 부분집합이 스위치를 배선하지 않는다 ────
# `POST …/work-hosts/byoc/enrollments` · `POST …/work-hosts/cloud/register` ·
# `GET …/work-hosts/cloud/{provisionId}` · `POST /v1/admin/workspaces/{ws}/credits/topups`
# 는 전부 `MOMO_T3_ENABLED=1` 이 아니면 인증보다 **먼저** 503 이다
# (routes::shared::ready_t3 — ADR-0136 「T3 기본 비활성」). 그리고
# `infra/rust/docker-compose.rust.yml` 의 api 서비스는 그 키를 환경에 넣지 않는다
# (환경 목록: MOMO_ENV·DATABASE_URL·JWT_HMAC·CENT_*·MOMO_DRIVE_*·CORS·LOG_LEVEL).
# 즉 막는 것은 기준 ②이고, 여는 방법은 **배포 컴포즈에 게이트용 스위치를 넣는 것**
# 뿐이라 택하지 않는다 — 그건 이 패스가 「배포본을 그대로 실측한다」를 포기하는 일이다.
# (`register` 는 그 위에 enrollments 가 발급하는 1회용 bootstrap 토큰까지 필요하다.)
# 등재 조건: 부분집합이 T3 를 켜고 도는 프로필이 생기거나, 그 4경로가 T3 없이도
# 왕복하는 모양으로 바뀔 때. `POST …/work-hosts/cloud`(관리형 생성)는 애초에
# server-rust 가 라우팅하지 않으므로 기준 ① 부터 미달이다.
#
# ── 등재 보류: /v1/provider/link/chain 3경로 — 같은 이유(미배선) ─────────────
# GET|PUT|DELETE `/v1/provider/link/chain` 은 스펙에 있고 server-rust 가 라우팅한다.
# 막는 것은 둘 다 부분집합 배선이다: `PROVIDER_LINK_MASTER_KEY` 가 없으면 계열 전체가
# 503 이고, `PLATFORM_ADMIN_EMAILS` 가 비면 MOMO-583 게이트가 403 이다(이 서버의 로그인은
# `platform:read` 를 발급하지 않으므로 허용목록이 유일한 경로다). 위 api 서비스 환경
# 목록에 두 키가 다 없다. 게이트 편의로 배포 컴포즈에 조작기를 다는 대신, 보류로 둔다.
#
# ── 등재 보류: terminal-attach 2경로 — 앞절이 미이식 ─────────────────────────
# `POST …/work-sessions/{s}/terminal-attach` 와 `POST …/work-hosts/{h}/terminal-attach/validate`
# 는 세션에 **원격 PTY 바인딩**(`pty_id` + `attach_endpoint`)이 있어야 200 이고, 그 두 칸을
# 쓰는 것은 work-host 서명 `POST …/work-sessions` / `PATCH …/work-sessions/{s}` 인데 둘 다
# 미이식이다(work_host_auth 모듈 doc 의 「still-unported five」, routes::work_sessions::
# reject_unsupported_create 가 이름 붙여 400 으로 거절). 원장을 SQL 로 조작해 두 칸을
# 채우면 200 은 나오지만, 그건 이 서버가 만들 수 없는 상태를 게이트가 지어내는 것이라
# 「Rust 에서 실측됐다」가 거짓이 된다. 등재 조건: 그 서명 arm 두 개가 이식될 때.

# HAP-E6 해체 3연산 (ADR-0162 / #1367, 등재는 #1385). 위 다섯 줄과 같은 라우트
# 패밀리라 같은 자리에 산다 — 붙이는 lifecycle 이 하나이기 때문이다:
# pairing → confirm → proof(active) → disconnect → 아티팩트별 acknowledge →
# complete. 이 셋만은 「불러 보니 200 이더라」로 등재할 수 없다. disconnect 는
# 살아 있는 credential 을 회수하는 것이 존재 이유고 complete 는 매니페스트가
# 전부 resolve 된 뒤에만 열리므로, 앞 다섯 줄이 만든 **active 한 연결** 위에서만
# 왕복이 성립한다. 그래서 샘플러는 이 계열 전용 dedicated identity 를 하나 더
# 세워 거기서만 해체를 돌린다 — 감사 매트릭스가 쓰는 주 연결은 살려 둔다.
POST /v1/workspaces/{workspaceId}/hosted-agent-connections/{connectionId}/disconnect
POST /v1/workspaces/{workspaceId}/hosted-agent-connections/{connectionId}/disconnect/complete
POST /v1/workspaces/{workspaceId}/hosted-agent-connections/{connectionId}/cleanup-artifacts/{artifactId}/acknowledge

# ── work host 레지스트리 + work session 원장 (ADR-0125 / ADR-0114) ──────────
# heartbeat 는 bearer 가 아니라 Ed25519 서명 v1 으로 인증되는 PUBLIC 라우트다 —
# 등재는 그 서명 경로가 Rust 에서 실제로 검증된다는 주장이다.
POST /v1/workspaces/{workspaceId}/work-hosts
GET /v1/workspaces/{workspaceId}/work-hosts
DELETE /v1/workspaces/{workspaceId}/work-hosts/{workHostId}
POST /v1/workspaces/{workspaceId}/work-hosts/{workHostId}/heartbeat
POST /v1/workspaces/{workspaceId}/work-sessions
GET /v1/workspaces/{workspaceId}/work-sessions
PATCH /v1/workspaces/{workspaceId}/work-sessions/{workSessionId}
POST /v1/workspaces/{workspaceId}/work-sessions/{workSessionId}/resume

# ── work control 원장 + 서명 데몬 경로 (#1114 / #1132 이탈 6 / #1143) ───────
# 이 다섯 줄이 #1132 가 "실제로 왕복시키지 않은 5개"라며 미등재로 남긴 그 연산들이다.
# 이제 왕복한다: 사람이 도구를 미리 허가하고 → 에이전트가 **agent bearer**(scope
# `work:control`)로 spawn 을 요청해 카드 없이 dispatched 가 되고 → **데몬이 자기
# Ed25519 서명으로** 그 지시를 읽고(`pending-controls`) 자기 서명으로 「실행했다」를
# 보고한다(`ack`). ack 의 자격증명이 요청자와 다른 것이 이 계열의 요점이라
# (#1143 §①), 서명 arm 으로 샘플하지 않으면 등재해도 증명하는 바가 다르다.
POST /v1/workspaces/{workspaceId}/work-controls
POST /v1/workspaces/{workspaceId}/work-controls/{workControlId}/ack
GET /v1/workspaces/{workspaceId}/work-hosts/{workHostId}/pending-controls
GET /v1/workspaces/{workspaceId}/work-auto-approvals
PUT /v1/workspaces/{workspaceId}/work-auto-approvals/{tool}
DELETE /v1/workspaces/{workspaceId}/work-auto-approvals/{tool}
